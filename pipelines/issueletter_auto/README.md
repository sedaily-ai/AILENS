# issueletter_auto — 모아쓰기 레터 자동 발행

설계: `docs/product/모아쓰기레터/자동발행_설계.md`

하루 한 번(08시 KST) 최근 서울경제 기사에서 같은 사안을 다룬 기사 3건 이상을 묶어, 모아쓰기 레터 초안을 만들고 검증을 모두 통과하면 발행한다.
발행되면 서버(lens-cms-api)가 그 레터를 쓴 에디터를 구독한 구독자에게 메일을 보낸다.

| 파일 | 역할 |
|---|---|
| `run.py` | 진입점. 수집 → 이슈 묶기 → 초안 생성(최대 3회) → 검증 → 저장 → 검수 요청 → 발행 |
| `core.py` | 순수 검증 로직: 묶음 검증, 묶음 밖 링크 차단, 기사에 없는 수치 차단, 투자 권유 표현 차단, 에디터 지정 |
| `cluster_prompt.md`, `draft_prompt.txt` | 모델 프롬프트(초안은 마스터DB 템플릿 v2 기반) |
| `test_core.py`, `test_run.py` | 단위·흐름 테스트(모델·서버 호출은 가짜). `python3 -m pytest -q` |
| `provision.sh` 외 json | AWS 리소스 정의(기록용, **아직 실행하지 않음**) |

## 안전장치
- `ISSUELETTER_AUTO=1`일 때만 발행. 기본 0이면 초안을 저장하고 멈춘다(드라이런)
- 하루 최대 발행 수(`ISSUELETTER_MAX_PER_DAY`, 기본 1), 발행 시각 창 KST 06~18시
- 검증을 통과하지 못하면 서버에 저장조차 하지 않고 사유를 모델에게 돌려 최대 3회 다시 쓴다. 3회 모두 실패하면 중단
- 정치·젠더·세대·지역 갈등 소재, 이미 레터로 쓴 기사가 겹치는 묶음, 에디터를 정할 수 없는 주제는 제외

## 켜기 전에 확인할 것
1. v1.45 DDL, 에디터 시드, 서버 배포가 끝났는지
2. 드라이런(`ISSUELETTER_AUTO=0`)을 며칠 돌려 초안 품질과 보류 사유를 본다
3. 실제 구독자 발송(`LETTER_AUTO_SEND=1`)을 켤지 별도로 결정한다(이 스위치는 서버 쪽)
