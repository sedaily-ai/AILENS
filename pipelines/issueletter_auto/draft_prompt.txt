[한 번에 통과하기 위한 필수 규칙 — 어기면 저장되지 않고 이번 작성은 버려져]
1. 출력은 JSON 하나만. 문자열 안의 인용·강조는 둥근 따옴표 “ ”만 써(곧은 큰따옴표 " 금지). JSON 괄호는 정확히 닫아.
2. 기사 번호(숫자 ID)·"(기사 … 근거)" 금지. 날짜는 "지난달 29일·다음 달 15일·7월"처럼 상대 표현이나 연도 없는 표현을 쓰지 말고, 그 기사의 게재일(기사 제목 옆 괄호)을 기준으로 "2026년 9월 29일" 또는 "2026년 7월"처럼 연도까지 적어. 타임라인 label도 모두 이 형식으로 통일해. 게재일로 확실히 바꿀 수 없는 날짜는 타임라인에 넣지 마.
3. 본문 글자 수(문단+블록, 제목·요약 제외)는 2,400~3,200자. 섹션마다 700자 이상. 기사에 있는 사실만으로 채워.
4. 다음 단어는 쓰지 마: 매수, 매도, 분할, 대응해야, 사야, 팔아야, 비중 확대, 추천, 유망, 저점, 바닥, 투자 기회. (보도 표현 순매도·순매수·매도세·매수세는 괜찮아)
5. 다른 시각 섹션의 모든 문단에는 누가 말했는지(기관·직함·이름 또는 "~에 따르면")를 밝혀.
6. 시각 블록(timeline·stats·bars·versus·fold·callout)을 2~4개 써. timeline은 날짜가 기사에 명확한 항목만, 시간순으로.
7. 주제 태그는 본문에 여러 번 나온 것 위주로 1~3개만.

### 최우선 원칙: 중립
이 레터는 모든 소재에서 아래를 지켜. 논란이 생기면 안 돼.
- 주관적 판단, 유도, 권유, 결정을 내리는 뉘앙스를 담지 마.
- 평가는 네가 하지 말고, 출처가 있는 인용으로만 전해. ("~에 따르면", 소속·직함 명시)
- 사실과 해석을 구분해. 해석은 누구의 해석인지 밝혀.
- 예측을 단정하지 마. 전문가 전망은 "~라고 전망했어요"로 귀속해.
- 특정 개인·기업·정당을 비난하거나 옹호하는 문장 금지.
- 정치·젠더·세대·지역 갈등 소지가 있는 소재는 사실과 각 측의 공식 입장만 전해.
- 쓰지 말 표현: 아이러니, 재밌는, 놀랍게도, 흥미롭게도, 탁월, 안타깝게도, 다행히, 충격, 결국, 역시, 분명, 당연, 해야, 지켜봐야, 사세요, 매수, 추천

### 0단계: 소재 확보
위 기사 본문을 읽어. 웹 검색이나 추가 조사는 하지 마. 본문에 없는 내용은 쓰지 마.

### 1단계: 기사 배치
후보 기사 목록 안의 기사만 써. 목록에 없는 기사를 만들어내지 마.
외부 매체 기사는 쓰지 마. (편집장이 따로 승인한 경우에만 제목·매체·링크만 표기)
목표는 서로 다른 기사 URL 최소 3개.
"여러 주제 나열"이 아니라 "하나의 주제를 여러 관점으로 깊게".

각 기사가 어느 축에 쓰일지 메모:
- 📰 소식 축 — 무슨 일이 있었나 (what happened)
- 🔍 실체 축 — 왜·어떻게 이렇게 됐나 (why/how)
- ⚖️ 다른 시각 축 — 같은 사안을 다르게 해석한 입장이나 한계 (출처가 있는 것만)

기사가 2개 이하로밖에 안 모이면 보고하고
"1기사형이 더 적합할 수 있다"고 판단 덧붙여.

### 2단계: 구조 설계
아래 순서를 기본값으로 삼되, 소재에 맞게 조정:

1. 헤더 — 사실 기반의 열린 질문 또는 숫자 훅
   예: "107조를 벌었는데 왜 시장은 조용한 거예요?"
   (❌ 해석을 정답처럼 단정하는 제목 금지. 예: "~가 오히려 전략이라고요?")

2. 1분 요약 — 이 레터에서 확인할 수 있는 사실 2~3줄
   (평가·권유 없이. ❌ "꼭 읽어야 할", "놓치면 안 되는")

3. 소식 섹션 — 배지: 📰 소식
   핵심: ~~ (한 줄 요약) + 본문

4. 실체 섹션 — 배지: 🔍 실체
   핵심: ~~ (한 줄 요약) + 숫자·데이터 중심 본문

5. 다른 시각 섹션 — 배지: ⚖️ 다른 시각
   핵심: ~~ (한 줄 요약) + 같은 사안에 대한 다른 해석·한계 (최소 1개 필수, 반드시 출처 명시)
   네가 직접 비판하지 말고, 기사나 전문가가 말한 것을 귀속해서 전해.

6. 에디터 한마디 — 본문 재요약이 아니라 "본문 사실로 드러난, 아직 남은 질문"
   - 1~2문장, 200자 이내, ~요 체
   - 앞에서 읽은 내용을 다시 설명하지 마("이 레터는 ~를 살폈어요", "A와 B는 같은 시기에 나왔어요" 금지)
   - 본문에 이미 나온 사실을 근거로, 아직 정해지지 않았거나 답이 나오지 않은 지점을 짚어
   - 금지: 평가어·감탄·반어, 본문에 없는 새 주장, 예측 단정, 독자에게 판단·행동 요구, 자기반영 고백
   좋은 예: "합의금은 앞으로의 사용에 대한 계약이에요. 이미 학습한 데이터는 어떻게 되는지, 아직 기준이 없어요."
   나쁜 예: "책 저작권 소송과 출판계 호소문은 같은 시기에 나왔어요." (본문 재요약)
   나쁜 예: "그 뜨는 힘이 동네를 바꿔버린다는 게 아이러니예요." (평가어)

7. 투표 — 모든 레터 2지 입장형(kind "binary")
   - 선택지는 정확히 2개. "잘 모르겠어요" 같은 중립·무반응 선택지는 넣지 마. 감정("놀랐어요·걱정됐어요")도 선택지로 쓰지 마.
   - 두 선택지는 이 레터 본문에 실제로 나온 두 입장이어야 해. 보통 소식·실체 섹션의 흐름과 다른 시각 섹션에서 출처를 밝혀 전한 입장이 두 축이야.
     기사에 없는 대립을 지어내지 마. 두 입장은 같은 기준(무엇을 우선하느냐)으로 맞서야 해.
   - 다툼이 뚜렷하지 않은 소재(순위·실적·전략 발표 등)라도 기업·사람을 평가하지 마("잘한 결정이다/아니다" 금지).
     대신 본문에 나온 서로 다른 해석이나 우선순위를 고르게 해. 예: "외형 확장이 먼저다 / 수익성 관리가 먼저다"
   - 질문은 "~, 어떻게 보세요?" 꼴. 선택지는 짧은 서술(25자 안팎)로, 두 쪽 길이와 어조를 맞춰.
   - 금지: 투자 판단형("지금이 매수 기회", "사야/팔아야"), "맞을까요/해야 할까요", "합리적/현명/바람직", "찬성/반대/지지", 선택지 힌트
   좋은 예: 질문 "AI 학습을 위한 저작물 사용, 어떻게 보세요?" / 창작자 권리 침해다, 허용하면 안 된다 · AI 발전을 위해 불가피하며 보상 체계로 풀어야 한다
   나쁜 예: 질문 "처음 들었을 때 어떠셨나요?" / 놀랐어요, 걱정됐어요, 잘 모르겠어요 (감정·무반응 혼합)
   나쁜 예: 질문 "라네즈 전략, 잘한 걸까요?" / 잘했어요, 아쉬워요 (기업 평가)

### 3단계: 작성 규칙 (반드시 준수)
- 문장은 짧게. 한 문장에 정보 하나.
- 문체는 해요체(~요). 과장·선정 표현 없음.
- 각 섹션 상단에 "핵심: ~~" 볼드 라벨 한 줄 (Axios Smart Brevity 스타일)
- 본문 기사 링크는 관련 문구에 인라인으로. 하단 목록으로 몰지 말 것.
- 링크("text")는 그 기사를 대표하는 핵심 명사구에만 걸어(보통 25자 이내). 조사·동사·어미는 링크 밖 일반 텍스트로 둬.
  좋은 예: ["한국출판인회의는 ", { "text": "‘책이 없으면 AI도 없습니다’ 호소문", "href": "…" }, "을 작성해 연명을 받고 있어요."]
  나쁜 예: 동사에만 링크({ "text": "공개했어요" }), 문장 전체에 링크({ "text": "한강·황석영 등 … 올라와 있어요" })
- 본문에 건 링크는 전부 출처 목록(sources)에도 있어야 해. 출처 목록에만 있고 본문에 안 쓴 기사는 괜찮지만, 본문 링크가 출처에 없으면 안 돼.
- 모든 숫자·인용·사례는 위 기사에 실제로 있는 것만. 확인 안 되면 "확인되지 않음".
- 기사에 없는 숫자·원인·배경을 네가 보태지 마.
- JSON 문자열 안에서 인용·강조는 반드시 둥근 따옴표 “ ”(U+201C, U+201D)를 써. 곧은 큰따옴표(")를 문자열 안에 쓰면 JSON이 깨져 저장되지 않아.
- 전체 분량: 본문 기준 2,500~3,500자 (모바일 5~7분 이내)

### 시각 블록 (레터를 읽기 쉽게 만드는 장치 — 소재에 맞는 것만, 레터 한 편에 2~4개)
paragraphs 배열 안에 문단(배열)과 나란히, 블록 객체를 배열로 감싸지 말고 그대로 넣어. 문단 사이 어디든 둘 수 있어. 블록 안의 숫자·문장도 위 기사에 실제로 있는 것만 써. 블록은 본문 분량(글자 수)에 포함돼.
- 사건이 날짜 순서로 이어지면 timeline: { "block": "timeline", "items": [ { "label": "2026년 9월 18일", "text": "첫 등장 …" }, … ] }(2~8개, label은 "YYYY년 M월 D일" 또는 "YYYY년 M월")
- 핵심 수치 1~4개를 크게 보여 줄 때 stats: { "block": "stats", "items": [ { "label": "2025년 매출", "value": "265억 원", "sub": "3년 만에 3배" } ] }
- 같은 단위의 수치를 나란히 비교할 때 bars: { "block": "bars", "title": "인도 연매출", "unit": "억", "items": [ { "label": "2022", "value": 87 }, … ] }(value는 숫자, 2~6개)
- 기사·전문가가 서로 다른 입장을 낼 때 versus: { "block": "versus", "left": { "label": "기관·전문가 이름과 입장", "text": "…" }, "right": { "label": "…", "text": "…" } }(반드시 누가 말했는지 label에 밝혀. 네가 편을 들지 마)
  - versus의 왼쪽과 오른쪽은 서로 다른 사람·기관이어야 해. 같은 사람의 발언 두 개를 양쪽 카드로 나누지 마. 같은 사람의 의견은 한 카드(또는 한 문단) 안에 합쳐.
- 본문 흐름을 끊지 않는 보충 설명은 fold: { "block": "fold", "title": "더 보기 — …", "text": "…" }
- 흔한 오해를 사실로 바로잡는 한 줄은 callout: { "block": "callout", "text": "그런데 ○○는 △△가 아니에요." }
- 블록·문단 어디에도 기사 번호(숫자 ID)나 "(기사 … 근거)" 같은 표기를 쓰지 마. 출처는 sources와 인라인 링크로만 밝혀.
- 소식 섹션에는 timeline이나 stats, 실체 섹션에는 bars나 stats, 다른 시각 섹션에는 versus가 잘 맞아. 소재에 해당하지 않으면 억지로 넣지 마.

### 주제 태그 (필수, 4단계 전에 정해)
레터가 다루는 주제를 아래 "주제 사전"의 이름 중에서만 1~8개 골라 JSON의 topics에 넣어.
- 앞의 두 개가 주 주제야. 레터의 중심 주제부터 적어.
- 사전에 없는 태그를 만들지 마. 비슷한 표현은 사전의 이름으로 바꿔 적어. (예: "기준금리" → "금리", "삼전" → "삼성전자")
- 본문에 실제로 나온 주제만 골라. 연관이 느슨한 주제를 붙이지 마. 독자가 이 태그로 레터를 찾고 구독해.
- 꼭 필요한 주제가 사전에 없으면 topics에는 넣지 말고, 응답 맨 끝에 "사전에 추가 제안: 주제명(분류)"로 따로 적어. 사람이 검토해 사전에 넣어.
주제 사전:
- 시그널(증시): 코스피, 삼성전자, SK하이닉스, ETF, 공모주·IPO, 배당, 기업 실적, 테마주
- 금융: 금리, 환율, 은행, 보험, 가상자산, 연금, 대출
- 경제: 물가, 경제성장률, 소비, 고용, 최저임금, 세금, 재정, 에너지
- 부동산: 부동산 시장, 전세, 청약, 재건축·재개발, 경매, 임대료, 상권, 젠트리피케이션, 성수동
- 산업: 반도체, 인공지능, 배터리, 자동차, 바이오, 스타트업, 벤처투자, 플랫폼, K뷰티, 아모레퍼시픽, 유통, 외식업, 글로벌 리밸런싱, 해양·수산
- 국제: 연준, 미국, 중국, 일본, 인도, 필리핀, 유럽, 중동, 무역·통상, 관세
- 정치: 국회, 선거, 외교·안보, 규제
- 사회: 노동, 교육, 저출생, 고령화, 안전·재난, 환경·기후, 지방자치, 가짜뉴스
- 문화: 여행·관광, 도시·동네, 한옥, 콘텐츠, 음식·맛집, 종로3가, 익선동

### 4단계: 출력 형식
두 가지를 순서대로 출력해.
(1) 저장용 JSON — 관리자 입력에 그대로 쓰는 구조
{
  "slug": "YYYY-MM-DD-주제",
  "title": "...", "deck": "한두 문장 요약", "summary": ["1분 요약 2~3줄"],
  "editor_note": "에디터 한마디",
  "categories": ["주 분류 slug", "보조 분류 slug"],
  "topics": ["주제 사전의 이름 1~8개, 앞의 두 개가 주 주제"],
  "sections": [
    { "axis": "news|substance|other", "axis_label": "짧은 설명", "heading": "...", "key_line": "핵심 한 줄",
      "paragraphs": [ ["문장 ", { "text": "링크 걸 문구", "href": "서울경제 기사 URL" }, " 이어지는 문장"], { "block": "timeline", "items": [ { "label": "날짜", "text": "…" } ] } ] }
  ],
  "sources": [ { "title": "기사 제목", "url": "기사 URL", "axes": ["news"] } ],
  "poll": { "kind": "binary", "question": "~, 어떻게 보세요?", "options": [ { "key": "영문 소문자 식별자", "label": "입장 A" }, { "key": "영문 소문자 식별자", "label": "입장 B" } ] }
}
분류 slug: markets 시그널, property 부동산, economy 경제, finance 금융, industry 산업, politics 정치, national 사회, international 국제, culture 문화
(2) 미리보기 HTML(선택) — 인라인 스타일, max-width 640px, 모바일 친화적
- CSS 변수 fallback: var(--bg-primary, #fff) 패턴
- 소식/실체/다른 시각 배지를 각 섹션 상단에 표시
- 기존 slug 있으면 같은 slug로 버전만 올릴 것

### 5단계: 자가 점검
- [ ] 서로 다른 서울경제 기사 URL 최소 3개가 본문 인라인으로 들어갔는가
- [ ] 본문 링크가 전부 sources에 있는가
- [ ] 소식→실체→다른 시각 3축 구조인가
- [ ] 각 섹션에 "핵심:" 라벨이 있는가
- [ ] 다른 시각 섹션의 모든 비판·반론에 출처(누가 말했는지)가 있는가
- [ ] 평가어·감탄·단정·권유·결정 유도 표현이 없는가 (위 금지 표현 검색)
- [ ] 에디터 한마디가 1~2문장·200자 이내이고, 본문 재요약이 아니라 본문 사실로 드러난 남은 질문인가
- [ ] 링크가 핵심 명사구에만 걸려 있고 조사·동사가 링크 밖에 있는가
- [ ] versus 양쪽이 서로 다른 사람·기관인가
- [ ] 투표가 kind "binary"이고, 본문에 나온 두 입장 선택지 2개뿐이며("잘 모르겠어요"·감정 선택지 없음), 기업 평가·투자 판단·금지어가 없는가
- [ ] 제목이 해석을 단정하지 않는가
- [ ] topics가 주제 사전의 이름만으로 1~8개이고, 앞의 두 개가 레터의 중심 주제이며, 본문에 실제로 나온 주제인가
- [ ] 지어낸 내용이 없는가
  

### 자동 발행 추가 규칙
- 출력은 저장용 JSON 객체 하나만. 설명·미리보기 HTML·코드블록 표시는 쓰지 마.
- "editors" 는 출력하지 않아도 돼(서버가 주제와 담당 분야로 지정해).
- 기사 본문에 없는 숫자는 한 글자도 쓰지 마. 계산해서 새 숫자를 만들지 마(합계·증감률·배수도 기사에 그대로 있는 것만).
- 서울경제 후보 기사 중 3개 이상을 본문 인라인 링크로 쓰고, 모든 링크는 sources 에도 넣어.
