타임머신 지면데이터 설계

2026-11-03 · v0.1 초안 · timemachine-data · 개발단 결정 사항

타임머신에서 일자를 고르면 지면 1면 이미지와 1면 기사 데이터를 보여 주기 위한 개발단 설계. 서비스 경로는 사전 생성한 정적 파일(S3·CloudFront)을 권고하며, 2011-07-09 이전 텍스트만 기존 빅카인즈 경로를 유지함.

0범위와 전제

개발단 결정파일 형식 · 폴더·파일 구조 · 호출 방식 · 데이터 저장소 · 효율적 호출(캐시)
보유 데이터이미지 1960-08-01~2026-11-02, 16,254장·21.3GB(1978~87, 1991~93 없음) · 텍스트 네이버 2026-01-01~11-03, 250일·1,171건
수집 가능 범위네이버 텍스트는 2011-07-09 이후(표본 조회로 확인, 전수 미확인). 이전 구간은 네이버에 없음
기존 타임머신사용자 조회 시 Lambda가 빅카인즈를 호출하고 DynamoDB에 일자별 캐시. 1면은 면 번호가 있는 1994-01~1996-07, 2017-11-13~만 제공. 응답에 이미지 없음

1파일 형식

대상제안이유
이미지 원본jpg 그대로 보관(평균 1.3MB, 약 4,465×6,100px)재가공 원본. 웹에 직접 제공하기에는 큼
이미지 웹용WebP 2종: 목록·카드용 약 480px, 상세용 약 1,200px브라우저 지원 범위가 넓음. AVIF는 더 작으나 변환이 느려 제외. 변환 후 크기는 미측정(560px jpg 샘플 약 75KB만 실측)
일자별 데이터JSON 1개/일프런트가 바로 파싱. 기사 약 4~6건이라 작음(크기는 추정 1~2KB)
발행일 색인연 단위 JSON(calendar/YYYY.json)선택한 연도만 읽음. 전체 1개 파일보다 초기 로드가 작음. 지면 없는 날(일요일·휴간) 판별과 직전 발행일 대체에 사용
수집 원본CSV(naver_front_YYYY.csv)재생성 기준 정본. 서비스에는 노출하지 않음

2폴더·파일 구조

s3://<신규 버킷>/timemachine/v1/
├─ calendar/
│   └─ YYYY.json
├─ days/
│   └─ YYYY/MM/YYYYMMDD.json
├─ images/
│   ├─ thumb/YYYY/MM/YYYYMMDD.webp
│   └─ web/YYYY/MM/YYYYMMDD.webp
├─ original/YYYY/MM/YYYYMMDD.jpg   (비공개)
└─ raw/naver/naver_front_YYYY.csv  (비공개)
경로 규칙로컬 폴더(연도/월/YYYYMMDD.jpg)와 동일. 업로드 시 변환 불필요
버전 경로v1/. 형식이 바뀌면 v2/를 새로 만들어 구 클라이언트를 깨지 않음
공개 범위공개: calendar, days, images. 비공개: original, raw
객체 수일자 JSON·이미지 각 약 16,254개 규모(이미지 보유일 기준)

3호출 방식

일자 선택›calendar/YYYY.json›발행일 판별·직전 발행일 대체›days/…/YYYYMMDD.json›thumb → web 이미지
일자 구간텍스트이미지
2011-07-09 이후정적 JSON(CloudFront)정적 WebP
~ 2011-07-08기존 타임머신 API(빅카인즈, 1994-01~1996-07만 1면)정적 WebP(보유 구간)
이미지 없는 일자(1978~87, 1991~93 등)구간 규칙대로"이미지 없음" 표시, 직전·직후 발행일 안내는 미결정

한 번 선택 시 요청: 연도 색인(세션당 연도별 1회) + 일자 JSON 1회 + 썸네일 1회, 상세를 열 때 웹용 이미지 1회. 서버 계산과 외부 호출 없음. 판별은 프런트가 calendar로 처리해 기존 front_page_calendar.json의 Lambda 번들 방식을 대체할 수 있음(적용 시 기존 분기 조정 필요, 미검토).

4데이터 저장소

저장소용도판단
S3서비스 파일(JSON·WebP), 원본 jpg, 수집 CSV필수. 신규 버킷, 비용태깅 Service=lens 적용(2026-10-01 이후 신규 규칙). 월 저장비는 단가 기준 1달러 미만 추정(미확인)
CloudFrontS3 앞단 캐시·제공사이트용 배포는 config/resources.env에 있음. 이 데이터에 기존 배포를 쓸지 별도 배포를 둘지 미확인
DynamoDB기존 타임머신 일자 캐시2011-07 이전 빅카인즈 경로에서 계속 사용. 새 데이터는 넣지 않음
Aurora정본 DB서비스 경로에 불필요. 검색·분석이 필요해질 때 CSV를 적재(후속, 현재 제안 안 함)

5효율적 호출

수단내용
장기 캐시과거 일자 파일은 불변이므로 Cache-Control: public, max-age=31536000, immutable. 최근 며칠·오늘·올해 색인은 짧게(예: 1시간, 제안값)
사전 생성요청 시점에 네이버·빅카인즈를 호출하지 않음. 일 1회 배치가 전날 지면의 JSON·이미지를 추가하고 올해 색인만 갱신
무효화일 배치 후 당일 JSON과 올해 색인만 CDN 무효화. 과거 파일은 무효화 대상 아님
이미지 단계 로딩썸네일 먼저, 상세용은 열 때만. 원본은 서비스에서 사용하지 않음(확대는 웹용 1,200px)
미리 불러오기전후 일자 JSON 미리 요청은 선택. 필요 시 UX 확인 후 적용
오늘 처리당일 지면은 송고 전일 수 있어 장기 캐시하지 않음(기존 정책: 오늘 날짜는 저장하지 않음)

6미결정·확인 필요

#항목권고 / 상태
1서비스 조회 경로정적 파일(S3+CloudFront). 대안은 기존 DynamoDB 캐시에 사전 적재(코드 변경은 적으나 이미지는 어차피 S3 필요)
22011-07 이전 텍스트기존 빅카인즈 경로 유지 + 이미지 병행. 새 데이터로 대체하면 1994~1996 구간이 후퇴함
3기사 항목 범위현재 제목·링크·톱 여부만 있음. 기존 응답은 본문·기자명도 포함하므로 상세 수집 여부 결정 필요(2026년분 약 1,171건, 20분 내외 추정)
4원본 공개 여부비공개 권고. 확대는 1,200px 웹용으로 처리
5이미지 변환 크기미측정. 샘플 변환으로 확인 후 해상도·품질 확정
6AWS 계정·권한, CloudFront 구성미확인
