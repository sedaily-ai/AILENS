## 설명

기사 원문을 60~120초 짜리 세로/가로 영상 각본 + 렌더용 JSON으로 변환하는
프롬프트. 영상은 "변화와 대비"를 다룬다 — 무엇이 무엇으로 바뀌었나. 판단
기준: 이 정보를 눈으로 보면 더 잘 이해되는가. 글로 읽는 게 나은 정보는
영상에 넣지 않는다. 입력은 0단계(사실 추출)에서 만든 facts.json.

## 지침

전체 60~120초, 컷 8~12개, 나레이션 400~700자.

[컷1] 진입 (6~8초) — 질문 또는 상황. 3초 안에 주제가 잡혀야 함
[컷2] 문제 (8~12초) — 지금 무엇이 문제인지. 수치 1개
[컷3~6] 본론 (각 8~14초) — 변화·구조·비교 순차 제시. 컷당 정보 하나
[컷7~8] 반전/규모 (10~14초) — 예상과 다른 지점 또는 임팩트 수치
[컷9] 클로징 (8~10초) — 요약하지 않는다. 여운이 남는 한 문장 또는 질문으로
마무리. 미확정 사항이 있으면 이 컷 이전에 이미 명시해 둔다
[엔드카드] (3초)

**컷 타입 7종**

| type | 용도 | 화면 |
|---|---|---|
| opening | 진입 | 아이콘 + 타이틀 |
| stat | 단일 수치 | 큰 숫자 + 라벨 + 출처 |
| diagram | 흐름·구조 | 노드 + 커넥터 |
| chart | 추이·비교 | 막대 또는 꺾은선 |
| photo | 원문 사진 | 사진 전체 화면 + 자막 |
| highlight | 핵심 정보 | 박스 + 강조 텍스트 |
| closing | 마무리 | 정보 박스 |

**출력 형식 — 두 가지를 함께 출력한다**

(1) 각본 — 검수용
```
[컷N] 용도 / 초
type: 컷 타입
나레이션: (텍스트)
자막: (텍스트)
화면: (구성 설명)
```

(2) 렌더용 JSON
```json
{
  "title": "",
  "brand": "같은 뉴스, 네 가지 시선 | AILENS",
  "asOfDate": "",
  "cuts": [
    {
      "type": "stat",
      "duration": 10,
      "narration": "",
      "caption": "",
      "data": {}
    }
  ],
  "source": "자료: ",
  "disclaimer": ""
}
```

`asOfDate` — 이 영상이 다루는 사실의 기준 시점(예: "2027년도 예산안 기준", "2026.9.1 발표"). facts.json의 [기준일]을 그대로 쓴다. facts.json이 없거나 기준 시점을 특정하기 애매하면 빈 문자열로 둔다(첫 컷에 아무것도 안 뜨는 게 지어내는 것보다 낫다).

타입별 data 스키마:
```
// opening
{ "icon": "lucide 아이콘명" }

// stat
{ "value": 0, "unit": "", "label": "", "sourceNote": "" }

// diagram
{
  "nodes": [
    { "kind": "node", "icon": "", "label": "" },
    { "kind": "connector", "variant": "arrow" }
  ],
  "sourceNote": ""
}

// chart
{
  "chartType": "bar|line",
  "points": [{ "label": "", "value": 0 }],
  "unit": "",
  "sourceNote": ""
}

// photo — url은 비워서 출력한다(파이프라인이 실제 원문 사진 URL로
// 채운다 — 직접 쓰지 않는다). credit은 필요하면.
{ "url": "", "credit": "" }

// highlight — caption을 세그먼트 배열로
"caption": [
  { "text": "관건은 " },
  { "text": "매장 규모", "emphasis": true }
]

// closing
{}
```

### 절대 원칙 (모든 포맷 공통)

1. 각 포맷은 독립된 완결물이다. 하나만 봐도 이해돼야 한다.
2. 같은 사실을 다른 층위에서 다룬다. 같은 논리 전개를 반복하지 않는다.
3. 원문에 없는 것은 만들지 않는다.

### 시선 이동 · 신뢰도

- 원문에 있는 사실 중 독자와 가장 가까운 것을 전면 배치, 원문에 없는 인과·판단·전망 추가 금지
- 수치는 원문 그대로. 임의 반올림·가공 금지, 출처 최소 1회 명시
- 기사 출처와 사진 출처를 구분한다
- 기업·기관 주장은 주체 명시 (✗ "2030년까지 매출 6000억 달러 전망" → ✓ "엔비디아 자체 추정 2030년 매출 6000억 달러")
- 추정치와 확정치 구분 (✗ "301억 원 낭비했다" → ✓ "최대 301억 원을 절감하지 못했다")
- 수치에는 조건을 함께 쓴다 (기준 시점, 비교 대상, 모수)

### 비교 수치 (chart 컷 전용)

- chart 컷은 원문에 실제로 존재하는 두 개 이상의 비교 가능한 수치(전년 대비,
  평년 대비, 전후 대비 등)가 있을 때만 쓴다.
- 원문에 비교 가능한 실수치가 없으면 chart를 쓰지 않는다. highlight 또는
  diagram으로 대체한다 — 대비할 숫자가 없다고 숫자를 지어내지 않는다. 이건
  이 프롬프트에서 가장 자주 어긴 규칙이다: chart라는 형식 자체가 "두 지점"을
  요구하다 보니, 없으면 만들어서라도 채우려는 쪽으로 기울기 쉽다. 망설여지면
  chart를 포기한다.
- 비교 수치를 말할 때는 기준값을 먼저 제시하고 이번 값을 그 위에 얹는다
  (예: "평소엔 시간당 50mm만 와도 도로가 잠기는데, 이번엔 124mm였습니다" —
  기준 없이 결과 수치만 던지지 않는다).

### 원문 사진 (photo 컷 전용)

- photo 컷은 [원문 사진]이 "있음"으로 표시된 경우에만 쓴다. 표시가 없으면
  photo 컷 자체를 만들지 않는다(사진이 없는데 만들면 파이프라인이
  자동으로 highlight로 바꿔버린다 — 처음부터 안 만드는 게 낫다).
- 사진이 있어도, 그 사진이 담고 있을 법한 장면·인물·장소가 이 컷의
  나레이션과 구체적으로 이어지지 않으면 쓰지 않는다 — 사진 유무와
  무관하게 서사에 안 맞으면 포기한다(§비교 수치 원칙과 같은 태도).
- url은 이 프롬프트가 직접 채우지 않는다("파이프라인이 채움"으로 비워서
  출력) — 파이프라인이 이미 아는 실제 URL로 항상 덮어쓰기 때문에, 잘못된
  URL을 지어내 봤자 무의미하다.
- opening처럼 도입부에 쓸 수도, 본론 중 구체적 사례를 보여줄 때 쓸 수도
  있다 — 위치를 강제하지 않는다.

### 전환 브릿지

- 컷과 컷 사이 나레이션은 끊어진 사실 나열이 아니라, 앞 컷과 이어지는
  접속·전환 표현으로 시작한다 (예: "그런데", "여기서 반전은", "그렇다면",
  "이게 다가 아닙니다").
- 특히 컷3~6(본론) 구간은 각 컷을 독립된 사실 나열로 쓰지 않는다 — 앞 컷의
  정보가 다음 컷의 전제가 되도록 연결한다.

### 나레이션

- 컷당 1~2문장, 25~50자
- 자막과 나레이션은 다르게 쓴다
  - 나레이션: "D램 사용량은 16분의 1로 줄어듭니다"
  - 자막: "D램 1/16"
- 숫자는 읽는 방식 그대로

### 문장 어미 — "-습니다"로만 통일하지 않는다

가장 자주 어긴 규칙. "구어체 ~요체"라고만 지시하면 모델은 제일 안전한
"-습니다"로 도망간다 — 컷 9개를 전부 "-습니다"로 끝내면 실제 사람이 읽는
것 같지 않고 기계가 읽는 것처럼 들린다(TTS로 실제 들어보면 특히 두드러짐).

- 컷마다 다른 어미를 쓴다. 같은 어미가 연속 2컷을 넘기지 않는다
- 쓸 수 있는 어미 목록(이 중 최소 4종류 이상 섞어 쓴다):
  "-거든요", "-더라고요", "-잖아요", "-는데요", "-죠", "-고요", "-이에요/예요"
- "-습니다"는 완전히 금지가 아니라 "이번 컷은 무게감을 주고 싶다" 싶을 때
  한두 번만 의도적으로 쓴다 — 9컷짜리 각본에서 2번 넘게 쓰지 않는다
- 예시
  - ✗ (전부 같은 톤) "22% 늘었습니다." / "18% 늘었습니다." / "11%였습니다."
  - ✓ (섞은 톤) "22%나 늘었더라고요." / "대전도 18% 늘었거든요." / "제일 적게
    늘어난 서울도 11%였어요."

### 컷 구성 비율 — 인포그래픽 밀도

전체 8~12컷 중 stat·diagram·chart(정보를 시각적으로 보여주는 컷) 합이
최소 절반 이상이 되게 구성한다. opening·highlight·closing(텍스트 위주
컷)만 연달아 쓰면 화면이 단조로워진다 — 기자 피드백: "인포그래픽 비중이
낮아 화면이 단조롭게 느껴진다". 본론 구간(컷3~6)에서 특히, 서술로 넘어갈
수 있는 정보라도 원문에 수치·구조·비교 대상이 있으면 highlight 대신
stat/diagram/chart로 바꿀 수 있는지 먼저 검토한다(단, §비교 수치 원칙 —
없는 수치를 지어내면서까지 무리하게 바꾸지는 않는다).

### 비주얼 원칙

- 인물 캐릭터 없음. 아이콘·도식만
- 배경 딥네이비(#0F1A2E), 텍스트 화이트, 강조 앰버(#FFB020)
- 컷 하나에 요소 3개 이하
- 실제 로고·브랜드 이미지 금지 — 단, photo 컷은 예외다: 서울경제가 이미
  공개 발행한 원문 사진을 그대로 쓰는 것이라 "지어낸 그래픽"이 아니다
- 수치 컷에 출처·기준 시점 표기

### 소재별 처리

| 소재 | 처리 |
|---|---|
| 사건·피해 | 수법 설명 시 피해 결과 반드시 병기 |
| 시황·종목 | 주가 차트가 매수 유도로 읽히지 않게. 목표주가 표시 금지 |
| 기술·산업 | 구조 도해 중심. 성능 주장은 주체 명시 |

### 절대 하면 안 되는 것

- 원문에 없는 수치·발언·사실 생성
- chart 컷을 채우려고 대비 수치를 지어냄(원문에 비교 대상이 없으면 chart 자체를 포기)
- 기업·기관 주장을 중립적 사실처럼 서술
- 추정치를 확정치처럼 표기
- 투자·매수 유도로 읽힐 표현
- 피해자를 탓하는 구도

### 체크리스트

- 3초 안에 주제가 잡히는가
- 각 컷의 정보가 시각화할 가치가 있는가
- 컷 하나에 정보 하나인가
- 자막과 나레이션이 다른가
- 웹툰과 같은 정보를 반복하지 않는가
- 수치 컷에 출처·기준이 있는가
- chart 컷에 쓴 두 수치가 모두 원문에 실제로 있는가 (없으면 highlight/diagram으로 바꿨는가)
- 컷마다 앞 컷과 이어지는 전환 표현으로 시작하는가
- closing이 요약이 아니라 여운 또는 질문으로 끝나는가
- 문장 어미가 4종류 이상 섞여 있는가 ("-습니다"만 반복하지 않는가)
- 미확정 사항을 명시했는가
- JSON 스키마가 유효한가
- highlight의 caption이 세그먼트 배열인가
- diagram의 nodes에 kind가 있는가
- photo 컷을 썼다면 [원문 사진]이 "있음"이었고, 그 사진이 실제로 이 컷
  나레이션 내용과 맞는가
