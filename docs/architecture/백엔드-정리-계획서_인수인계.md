| 주의 | 공휴일이라 push·PR은 보류 중. 브랜치 `feat/seo-canonical-c`에 로컬 커밋이 쌓여 있음(PR #51은 열려 있고 머지 전) |

## 2. 현재 구조

| 구성 | 위치 | 실행 환경 | 역할 |
|---|---|---|---|
| 사이트 | `service/frontend` | ECS Fargate 1태스크(2GB) + ALB + CloudFront `E1QS7PY350VHF6` | Next.js SSR, ISR 5분 |
| 데이터 서버 | `service/lens-cms-api` | EC2 `i-0e3d04bdb01584833`(PM2·uvicorn 2워커·nginx) | Postgres 접근 단일 통로(공개·내부·관리 API) |
| 관리자 API | `admin/backend` | Lambda `sedaily-mbti-admin-api-dev`(VPC 내) | 로그인·웹툰·미디어·프롬프트 등 약 90라우트 + WebSocket |
| 관리자 화면 | `admin/frontend` | — | Next.js |
| 파이프라인 | `pipelines/` | ECS 일회성 작업(EventBridge cron) | mustknow_auto(하루 6회), frontpage_auto(07시) |
| 옛 Lambda | `service/backend` | Lambda 약 23개 | 대부분 폐기 대상(§5) |
| DB | Aurora PostgreSQL 16 `lens-postgres-migration-dev` | RDS | 정본. 마스터 계정 `lens_admin`(AWS 관리형 비밀번호로 되돌림), 앱 역할 `lens_service_app` |

문제점(구조): 실행 위치 기준으로 흩어져 있어 기능 하나 추가에 여러 곳을 같이 고친다(오늘 `candidate_seen` 추가 = DDL·서버·nginx·파이프라인 이미지·관리자 Lambda 5곳). DB 접근 서버는 단일 EC2·평문 HTTP·IP 하드코딩(`13.223.179.151`, `config/constants.py`·`admin/backend/shared/lens_cms_client.py`)이고 RAM 사용률 약 95%.

## 3. 목표 구조

```
backend/app/{content, editorial, ai_studio, automation, members, explore, platform}/
backend/migrations/   # 버전별 SQL(현재 docs/architecture/lens-erd-src)
frontend/  admin-frontend/  jobs/(pipelines)
```
- 도메인별 라우트 배치는 [라우트-도메인-맵](라우트-도메인-맵.md) 참조. 의존 방향: 각 도메인 → `content` → `platform`.
- 한 번에 옮기지 말고 서버 이전(§6)과 함께 단계적으로. MSA(서비스 분리)는 목표 아님 — 소규모 팀에서는 모듈형 모놀리스가 맞다고 판단.

## 5. 폐기·삭제 대상 (건건이 확인 후 진행)

| 대상 | 근거 | 선행 조건 |
|---|---|---|
| 질문 Lambda(`sedaily-mbti-question-dev`) | 서비스하지 않는 기능, 프론트 호출 제거 완료 | 호출 0 확인 후 삭제 |
| 브리핑·챗봇·웹소켓 Lambda(`briefing`, `chatbot`, `ws-*`) + EventBridge 규칙 | 프론트가 호출하지 않음(14일 chatbot 11·ws 5건) | EventBridge 규칙 먼저 끄고 관찰 |
| 기타 폐기 후보 Lambda 약 17개(`post`·`search`는 5분 워밍 핑만, `v2-*`, `voice-*` 등) | [Lambda 인벤토리](../worklog/2026-10/2026-10-09-웹툰영상-canonical-검색엔진점검.md) | `v2-quiz`는 호출 출처 불명(1,845건) → API Gateway 로그로 확인 후 |
| 관리자 "레터" 화면(`/admin/letters`, `routes/letters.py`, `repo/letters_repo.py`) | 읽기·쓰기 0건의 빈 `daily-letters` 테이블 | 프론트 페이지·네비 함께 제거 |
| DynamoDB 13개 테이블 | 14일 활동 기준: 죽은 것 8개, 쓰기 남은 것 5개 | 1주 관찰 → 온디맨드 백업/S3 내보내기 → 하나씩 삭제 |
| `daily_questions` 테이블 | 기능 폐기 | 다음 DDL 배치에서 DROP(89건은 백업 JSON 보관) |
| 사주 관련 AWS 리소스(S3 `ailens-mount/saju/`, CloudFront `/saju*`, Lambda, DynamoDB) | 저장소 폴더는 삭제함 | **요청에 따라 그대로 둠** — 건드리지 않음 |

| 3 | 분류 단일 출처화 | 분류 9개 목록이 프론트·`_NEW_CATEGORIES`·`pipelines/common/taxonomy.py`·`admin/frontend/src/lib/types.ts` 4곳에 복제됨 → `categories` 테이블 + API 하나로 | 하나 바꾸면 4곳 수정해야 하는 현재 구조가 사고 원인 |
| 4 | 스키마 마이그레이션 정식화 | 지금은 SQL 파일을 사람이 마스터 계정으로 직접 실행. 마이그레이션 도구 + `lens_migrator`(DDL 전용 역할) + 비밀번호를 사람이 만지지 않는 실행 경로(일회성 ECS 작업) | 오늘 비밀번호 전달 단계에서 가장 많이 막혔음 |
| 5 | 서버리스 정리 5b | 순서: `user`·`archive`(엔드포인트 이미 있음) → `question`(폐기) → `timeline`·`time-machine`·`s3-articles`(= explore 도메인 신설) → `article-collector`·`briefing`(크론) → `admin-api`(마지막) | 선행: 서버 단일 장애점·평문 HTTP·IP 하드코딩·메모리 95% 해소(EIP/HTTPS/이중화 또는 증설) |
| 6 | 코드 구조 재배치 | `lens-cms-api`를 도메인 폴더로 재배치(동작 불변) → 관리자 Lambda 이전 시 같은 앱 안으로 | 라우트 약 90개·WebSocket·S3·GPU 호출 이전이 가장 큼 |
| 7 | CloudFront·인프라(선택) | 404·5xx 에러 캐싱, ALB 헬스체크를 `/api/health`로, 오토스케일링·WAF는 **트래픽이 늘면** | 현재 트래픽이 거의 없어 비용만 증가 — 보류 결정 |

## 7. 알려진 이슈·함정

| 이슈 | 설명 | 조치 |
|---|---|---|
| nginx 설정 불일치 | 서버의 `lens-cms-api.conf`와 저장소 `service/lens-cms-api/nginx.conf`가 달랐음(선정 실험실 경로 등 누락). 오늘 서버에 맞춰 추가 | `deploy.sh`는 nginx를 배포하지 않음 → 새 경로는 수동 반영, 저장소와 서버를 항상 맞출 것 |
| 선정 실험실 기록 | `/internal/selection-runs`가 서버 nginx에 없어 그동안 기록이 막혔을 가능성 | 과거 기록 공백 확인 필요 |
| 관리자 테스트의 운영 쓰기 | `admin/backend/tests/conftest.py`가 운영 audit 테이블에 실제로 씀 | 로컬에서 함부로 실행 금지 |
| API Gateway 라우트 | 관리자 Lambda에 새 라우트 추가 시 코드만으로는 안 뚫림(`create-route` 별도) | 서버 이전하면 사라짐 |
| 이중 쓰기 위험 | 스위치 `ddb`↔`pg` 사이 기간에 두 곳에 나뉘어 써질 수 있음 | 전환 직후 `ddb_to_pg_v136.py seen --apply`로 증분 보정(재실행 안전) |
| 환경변수 갱신 | `update-function-configuration --environment`는 **전체 교체** | 기존 값을 읽어 병합 후 갱신(오늘 그렇게 함) |
| 공통 코드 | `service/backend/common/`을 admin·service가 함께 씀 | 이전 시 의존 확인 |

## 8. 운영 절차·규칙

| 주제 | 규칙 |
|---|---|
| 배포 | 프론트 `service/frontend/deploy.sh --no-wait` + CloudFront 무효화 · 서버 `service/lens-cms-api/deploy.sh`(SSM) · 관리자 `admin/backend/deploy-admin-api.sh` · 파이프라인은 이미지 빌드·push 후 태스크 정의 리비전 등록 |

| 비밀 | DB 마스터 비밀번호는 Secrets Manager `rds!cluster-…`(AWS 관리형). 내부 API 토큰은 SSM `/sedaily-mbti/admin/lens-cms-api-token`. 채팅·문서·로그에 값을 남기지 않음 |
| Bedrock | 베어 모델 ID 금지, application inference profile ARN 사용(비용 태그) — [비용태깅_규칙](비용태깅_규칙.md) |

| 기록 | 변경은 `db-changelog/postgres/vX.Y-*.md`와 worklog에 남김(왜·무엇·영향 범위) |
