# 라우트 → 도메인 맵 (2026-10-09, 모듈형 모놀리스 정리용)

현재 백엔드는 실행 위치 기준으로 흩어져 있다: `service/lens-cms-api`(FastAPI, EC2) 91개 라우트, `admin/backend`(Lambda) 약 90개 라우트, `service/backend`(Lambda 22개, 대부분 죽음), `pipelines/`(ECS 일회성 작업). 이 문서는 라우트를 **도메인별**로 다시 묶어, 나중에 백엔드 앱 하나(`backend/app/<도메인>/`)로 모을 때 어느 코드가 어디로 가는지의 기준으로 쓴다.
목표 구조와 이유는 대화 기록·`docs/worklog/2026-10/2026-10-09-웹툰영상-canonical-검색엔진점검.md` 참조. 이 문서는 구조 변경을 실행하지 않는다(서버리스 정리 5b 단계와 함께 진행).

## 목표 폴더 구조 (안)

```
backend/                    # 배포 단위 1개(FastAPI, 상시 서버)
  app/
    content/      # 공개 콘텐츠 읽기(글·기사·프롬프트 공개본)
    editorial/    # 편집·발행(관리자 기능) — posts · media · webtoon · video · selection · quiz
    ai_studio/    # 프롬프트·프롬프트랩·챗 스레드·비용
    automation/   # 자동 파이프라인용 내부 API(선정 이력·job·기사 수집)
    members/      # 회원·개인화·구독·커뮤니티·퀴즈 응답
    explore/      # 타임라인·타임머신·키워드 기사 검색
    platform/     # 인증·권한·감사로그·플래그·헬스
  migrations/     # 버전별 SQL(지금 docs/architecture/lens-erd-src)
frontend/  admin-frontend/  jobs/(pipelines)
```

각 도메인은 자기 테이블·라우트·로직만 갖고, 다른 도메인은 그 도메인이 내놓은 함수(인터페이스)로만 부른다.

## 폐기·삭제 대상 (도메인에 넣지 않음)

- 오늘의 질문 — `/internal/daily-questions/*`, `daily_questions`, question Lambda(2026-10-09 기능 삭제 확정, 프론트 코드 제거 완료)
- 챗봇·웹소켓·음성: `chatbot`, `ws-connect/message/disconnect`, `voice-tts/stt-*`, `search`, `post`, `v2-*`(posts·health·article·feed·subscribe·quiz·today-letters), `article`, `newsletter-subscribe`, `external-content`
- 관리자 레터 화면(`/admin/letters*`) — 읽기·쓰기 0건 빈 테이블

## 이전 순서(제안, 서버리스 정리 5b와 같음)

1. content·members·platform: 서버(`lens-cms-api`)에 이미 있다 → 폴더만 도메인별로 재배치(코드 이동, 동작 불변).
2. automation: 이미 서버에 있다. `article-collector`·`briefing` 크론을 서버/ECS 스케줄로 옮기는 일만 남음.
3. explore: 서버에 신설(대응 엔드포인트 없음).
4. editorial·ai_studio·platform(관리자): 관리자 Lambda를 서버 앱으로 이전(라우트 약 90개·WebSocket·S3·GPU 포함, 가장 큼, 마지막).

## 의존 방향(규칙)

`editorial`·`automation`·`members`·`explore` → `content`(글·기사 조회 인터페이스) → `platform`. `ai_studio`는 `editorial`이 호출한다. 도메인끼리 서로의 테이블을 직접 읽지 않는다(필요하면 상대 도메인 함수 호출). `platform`은 아무것도 모르는 최하위.
