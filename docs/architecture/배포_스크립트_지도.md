# 배포 스크립트 지도

갱신: 2026-10-02. "사용 여부"는 스크립트 수정일이 아니라 대상 리소스의 마지막
갱신·호출 기록으로 확인했다. 배포 대상 리소스 이름이 바뀌면 이 문서도 같이 고친다.

## 한눈에 보기

| 영역 | 스크립트 | 배포 대상 | 방식 |
|---|---|---|---|
| 서비스 프론트 | `service/frontend/deploy.sh` | ECS Fargate `sedaily-lens-frontend` | Docker 빌드 → ECR → 태스크 정의 → 롤링 |
| 서비스 백엔드(API) | `service/lens-cms-api/deploy.sh` | EC2 `i-0e3d04bdb01584833` (PM2) | tar → S3 → SSM → `pm2 restart` |
| 서비스 백엔드(옛 Lambda) | `service/backend/deploy.sh` | Lambda `sedaily-mbti-*-dev` | zip → `update-function-code` |
| CMS 프론트 | `admin/frontend/deploy-admin.sh` | S3 `sedaily-mbti-admin-frontend-dev` + CloudFront `E1MITYI58DB9UW` | build → S3 sync → invalidation |
| CMS 백엔드 | `admin/backend/deploy-admin-api.sh` | Lambda `sedaily-mbti-admin-api-dev` | zip → `update-function-code` |
| CMS 일괄 | `admin/deploy-all.sh [frontend\|backend]` | 위 CMS 두 스크립트 | 호출만 함. `deploy-frontend.sh`·`deploy-backend.sh`는 같은 래퍼 |
| 발행 파이프라인 | `pipelines/frontpage_auto/deploy.sh` | ECR `sedaily-lens-frontpage-auto` + 태스크 정의 | `mustknow_auto`도 같은 이미지를 쓴다 |

- 서비스 쪽은 일괄 배포 스크립트가 없다. 프론트와 백엔드를 각각 실행한다.
- 프론트 배포(`service/frontend/deploy.sh`)는 롤링이 끝나면 CloudFront(`E1QS7PY350VHF6`)에 `/*` 무효화를 자동으로 건다(2026-10-02).
  배포 직후 옛 빌드의 HTML·RSC 페이로드가 캐시에 남아 옛 폰트 참조가 계속 내려간 사고를 막으려는 것이다(월 1,000경로까지 무료).
- 이미지 최적화(`/_next/image`)는 CloudFront에 `/_next/image*` 전용 동작·캐시 정책(`AILens-NextImage`)이 있어야 동작한다.
  기본 캐시 정책이 쿼리스트링을 버리기 때문이다. 이미 적용돼 있고, 재현·복구는 `service/frontend/infrastructure/cloudfront-next-image.sh`.
  새 이미지 호스트를 쓰는 컴포넌트가 생기면 `next.config.ts`의 `images.remotePatterns`에 추가할 것.
- `provision*.sh`는 최초 구축 기록용이다. 재실행하는 스크립트가 아니다.
- 사주(`saju/frontend/deploy-saju.sh`)는 별도 앱이라 이 문서 범위 밖이다.

## 이름 주의

- `service/backend`는 **옛 Lambda API**다. 지금 서비스 백엔드는 `service/lens-cms-api`다.
  공개 API `/api/v2/posts*`는 CloudFront → EC2(`lens-cms-api-origin`)로 간다.
- 옛 Lambda도 아직 일부는 살아 있다(아래). 지우거나 방치하기 전에 호출 지표부터 확인할 것.

## 알아둘 점

- 두 배포 대상이 "상시 서버(EC2)"와 "이미지(Fargate)"로 나뉜다. 프론트를 Fargate로 둔 이유는
  규모가 아니라 9/4 EC2+PM2 배포 실패 3종(배포 신뢰성)이었다.
- `service/lens-cms-api/deploy.sh`는 서버의 `ecosystem.config.js`를 비밀값이 빠진 템플릿으로
  덮어쓴다. `pm2 restart`는 저장된 환경변수를 쓰므로 지금은 문제없지만, 서버 재부팅 후
  `pm2 start ecosystem.config.js`로 새로 올리면 DB 비밀번호·내부 토큰이 비어 있을 수 있다.
- 프론트 `deploy.sh`는 `--no-wait`(롤링 대기 생략)와 단계별 소요 시간 출력을 지원한다.
- 운영 인프라 설정(CLI로 직접 변경, 코드엔 없음): 프론트 대상 그룹 헬스체크 10초×2회, ECS
  서킷 브레이커 롤백 켬, EC2 nginx gzip·스왑 2GB·CloudWatch 에이전트
  (`service/lens-cms-api/cloudwatch-agent.json`). 경위는
  `docs/worklog/2026-10/2026-10-01-seo-rss-보강-배포속도-백엔드-안정화.md`.
