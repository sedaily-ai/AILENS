# architecture — 시스템 구조 정본

"지금 시스템이 실제로 어떻게 생겼는가"만 담는다. 왜 이렇게 됐는지(경위·결정
과정)는 여기가 아니라 `worklog/`에 있다 — 이 폴더는 결과만, 과거형이 아니라
항상 현재형으로 쓴다.

## 규칙

- **코드가 바뀌면 문서도 같이 고친다.** 이 폴더의 존재 이유가 "지금 진실"이라
  코드와 어긋나는 순간 가치가 없어진다.
- 날짜 접두 파일명은 되도록 안 쓴다 — 날짜가 붙으면 "그 시점 기록"처럼
  보여서 worklog와 혼동된다. 예외적으로 날짜가 필요하면(예: 버전 비교)
  본문에 "갱신: YYYY-MM-DD"를 명시.
- 특정 결정이 나중에 뒤집혀서 문서 내용이 더 이상 안 맞게 되면, 지우지
  말고 파일 맨 위에 경고를 붙이고 `archive/`로 옮긴다 — 그 문서가 왜
  틀리게 됐는지도 한 줄 남긴다(실제 사례: `archive/2026-08-07-rendering-
  strategy-decision.md`).
- 새 시스템 구성요소(파이프라인, 어드민 스택 등)를 만들면 여기 새 파일을
  추가하거나 기존 파일을 확장한다 — root `docs/README.md`의 "정본 문서
  빠른 링크" 표도 같이 갱신.
