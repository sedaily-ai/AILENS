# 2026-09-18 웹툰 이미지 모델 확장 + GPU/캐릭터락 경로 폐기 결정

작성: 문영광 + Claude Code
관련: `pipelines/common/webtoon_image.py`, `admin/backend/routes/webtoon_lab.py`,
`admin/frontend/src/lib/webtoonImageModels.ts`, IAM `AdminPromptTestBedrockInvoke`,
Bedrock application inference profile `lens-webtoon-image-sd35-large`/`lens-webtoon-image-sd-ultra`

## 배경

기존 컷 이미지 생성 경로는 SD1.5+IP-Adapter(GPU EC2) + Bedrock Stable Style
Transfer 하나뿐이었다. 사용자가 "스테이블 디퓨전은 모델이 1.5밖에 없는거냐"고
물은 뒤 "gpt 와 동일한 퀄리티로 나오면 제일 좋은뎅"이라고 요청 — AWS Bedrock에
있는 다른 모델을 조사하고 실제 품질을 검증하는 작업으로 이어졌다.

## 한 것

1. Bedrock에서 사용 가능한 텍스트→이미지 모델 조사 — SD3.5 Large,
   Stable Image Ultra 추가하기로 결정.
2. 비용 태깅 규칙에 맞춰 application inference profile 신규 생성
   (`lens-webtoon-image-sd35-large` → `stability.sd3-5-large-v1:0`,
   `lens-webtoon-image-sd-ultra` → `stability.stable-image-ultra-v1:1`,
   둘 다 us-west-2, `Service=atlas4`/`Project=Sedaily-LENS`/
   `Workload=webtoon-image` 태그), `sedaily-mbti-admin-api-dev-role`의
   `AdminPromptTestBedrockInvoke` 정책에 두 ARN 호출 권한 추가.
3. `webtoon_image.py`에 `generate_bedrock_sd35_image_bytes()`/
   `generate_bedrock_sd_ultra_image_bytes()` 추가, 트랜지언트 에러
   (`ServiceUnavailableException`/`ThrottlingException` 등) 2초 간격 3회
   재시도 로직, 네거티브 프롬프트에 고스트·블러·텍스트 뭉개짐 방지 문구 보강.
4. 실제 발행 프롬프트 기반 컷(법정 장면, 기자회견, 상징적 오브젝트 flat-lay
   등)으로 Stable Image Core/SD3.5 Large/Stable Image Ultra/Style Guide/
   OpenAI gpt-image-1 5개 모델을 나란히 비교 테스트.
5. 모델 제거 관련 사고 — 위 테스트에서 품질 문제(아래 "다음" 참고)를
   발견하고 SD3.5/Ultra를 목록에서 임의로 제거했다가 사용자 제지
   ("엥? 모델을 왜빼시나요...") — 원복하고 사과, 이후로는 모델 추가/제거
   같은 목록 변경은 명시적 확인 없이 하지 않기로.
6. "GPU 를 꼭 써야할까요? 인물을 고정할 필요도, 배경을 고정할 필요도 사실
   없거든" — 사용자가 GPU IP-Adapter 기반 인물·화풍 고정 아키텍처 자체가
   불필요하다고 판단, GPU 경로를 대체하는 방향으로 확정. 이어서
   "울트라로 하는걸로 하시죠. 모델 순서도... 울트라가 가장 위로 올라오도록"
   — Stable Image Ultra를 기본/1순위로 확정하고 `webtoonImageModels.ts`
   배열 맨 앞으로 승격.

## 결정

- Stable Image Ultra를 기본 선택 모델로 채택. 기존 `pipeline`(SD1.5+
  IP-Adapter)은 실제 프로덕션 파이프라인(`pipelines/webtoon/pipeline.py`)이
  아직 이 경로를 쓰고 있어 목록에는 "운영 중" 배지와 함께 남겨두되, 관리자
  실험 도구에서의 우선순위는 Ultra로 넘어갔다 — `pipeline.py` 자체의
  마이그레이션은 이번 스코프에 포함하지 않음.
- Nova Canvas는 LEGACY 모델 특유의 "30일 미사용 시 자동 차단" 제약에 걸려
  재활성화 방법이 없어 목록에서 제외 유지(코드는 남겨둠, 콘솔에서 풀리면
  다시 등록).
