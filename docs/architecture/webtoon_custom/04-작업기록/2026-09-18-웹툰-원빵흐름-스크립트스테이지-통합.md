# 2026-09-18 웹툰 스크립트 생성 "1단계/2단계" 구분 완전 제거 (단일 호출 통합)

작성: 문영광 + Claude Code
관련: `admin/backend/routes/prompts.py`, `admin/backend/routes/chat_ws.py`,
`admin/frontend/src/components/PromptChatLab/PromptChatLab.tsx`

## 배경

챗랩의 스크립트 생성은 원래 "1단계(스크립트) 결과 확인 → 사용자가 진행
선택 → 2단계(장면 연출) 진행"하는 human-in-the-loop 구조였다. 사용자가
"지금 원빵에 출력하는 방향으로 하기로 했는데요... json 으로 출력하는거
필요없고요.. 날것으로"라고 요청해 먼저 HITL 확인 게이트만 없앴다(1단계
직후 서버가 자동으로 2단계까지 이어 실행).

그런데도 코드 구조상 Bedrock 호출 자체는 여전히 두 번(`_build_step1_call`→
`_build_step2_call`) 나뉘어 있었다. 그 결과 화면에 "스크립트·장면 연출
작성 중"이 사실상 두 번 표시되고, 특히 2단계 원문 스트리밍 미리보기에
`camera_distance`/`camera_height`/`composition`/`background`처럼 사용자가
요청한 적 없는 필드가 나타났다("이렇게.. 연출장면 생성중?? 이런게 왜 또
뜨는거지? 그런거 필요없는데.. 프롬프트 입력된거 기반으로 출력만 하면
되는데"). 근본 원인을 짚어가던 중 사용자가 구조 자체에 문제를 제기했다 —
"스테이지 구분 자체가 왜 있어야하는거죠?? 그런거 필요없을텐데요".

## 조사

발행된 웹툰 프롬프트(`/api/v2/prompts/webtoon/published`, 105KB)를 직접
받아 확인한 결과: 22장("Stage 1 Script Output Format")은 스크립트 필드만
정의하고, 12/13/14장(Scene Design/Image Text Whitelist/Common Image Style)은
서술형 가이드일 뿐 출력 JSON 스키마를 전혀 정의하지 않는다. 즉 "2단계
출력 스키마"라는 개념 자체가 발행 프롬프트 어디에도 없었고, 코드 쪽
`_STAGE2_OUTPUT_FORMAT` 상수가 그 빈 자리를 강제로 메꾸며 매 호출마다
옛 4개 필드를 무조건 밀어넣고 있었던 게 직접 원인이었다.

## 한 것

1. `_build_step1_call`/`_build_step2_call`(Bedrock 2회 호출) →
   `_build_script_call()`(1회 호출)로 통합. 필요한 챕터(0~15, 22)를 한 번에
   전송하고, 22장 스크립트 스키마의 각 컷에 `camera`/`scene` 두 필드만
   코드에서 추가 요구 — 나머지 필드 구성은 프롬프트에 맡긴다.
   `_STAGE2_OUTPUT_FORMAT`/`_STEP1_INSTRUCTION`/`_STEP2_INSTRUCTION`/
   `_HITL_REMINDER` 상수 삭제.
2. `_merge_storyboard_cuts(script, scenes)`(두 결과를 컷 번호로 매칭) →
   `_normalize_cuts(script)`(단일 결과를 필드 이름만 정규화)로 단순화 —
   더 이상 매칭할 두 번째 딕셔너리가 없다.
3. `chat_ws.py::_run_article_flow`가 단일 호출로 스크립트+장면 연출을
   한 번에 받아 `storyboard` 메시지 하나로 push. `_run_step2_flow`,
   `confirm_step2` WS kind 분기 삭제(프론트도 이미 안 씀, 확인됨).
4. 프론트: `step1_chunk`/`step1_chunk_done`/`step2_chunk`/
   `step2_chunk_done`/`step1` 메시지 타입 5종 → `script_chunk`/
   `script_chunk_done` 2종으로 통합. `Step1Card` 컴포넌트와 `Step1Data`
   타입, 관련 저장/복원 로직 삭제.
5. 검증: 백엔드 `py_compile`+`pyflakes`, 프론트 `tsc --noEmit`+`eslint`+
   `npm run build` 클린 확인 후 `deploy-admin-api.sh`/`deploy-admin.sh`로
   각각 배포.

## 결정

- `camera`/`scene` 필드명은 유지 — 다운스트림(`compose_text.py`, 컷 이미지
  생성의 `translate_scene_to_photo_brief()`)이 이 이름을 그대로 소비하고
  있어서, 필드명을 `image_prompt` 등으로 바꾸는 건 다운스트림 파이프라인
  재배선이 필요한 더 큰 변경이라 이번 스코프에서 제외했다.
- `DumpNode`의 코드블럭 자동 감지(정규식 `image_prompt|animation_prompt`)는
  그대로 뒀다 — 지금 스키마(`camera`/`scene`, 짧은 한 문장)엔 안 걸려
  시각적으로 박스가 안 뜨지만, 이후 유사 이름의 필드가 다시 생기면 바로
  적용되는 범용 메커니즘으로 남겨둔다.
