# 의사결정 기록 — 왜 OpenAI가 아니라 AWS Bedrock 모델을 쓰는가, 왜 그중 Ultra인가

---

작성: 2026-09-20, 대화 내용 정리(사용자 원문 인용 포함). 테스트
정확한 횟수·AWS 크레딧 규모 등 구체 수치는 사용자 확인 후 보강 필요
(아래 "확인 필요" 표시 참고).

> **문제 발견**
> - 품질만 보면 OpenAI(gpt-image-1)가 가장 낫다는 걸 이미 실측으로
>   확인했음 — 정밀·상징적 지시(빈 연단, 문 개수 등)를 유일하게
>   정확히 따름([정리후보 F](../02-정리후보/06-죽은휴면모델옵션.md)
>   에서도 재확인)
> - 그런데 OpenAI는 이 서비스에서 **사업적으로 사용할 수 없다**
>   (2026-09-18 확정)
>
> **문제 정의**
> - 서울경제는 **AWS로부터 크레딧을 지원받는 관계**(AWS Jumpstart 등,
>   사용자 원문: "저희는 aws 에서 지원받는 크레딧을 사용할 수 있어서")
>   — 이 지원을 실제로 활용하려면 AWS Bedrock 안에 있는 모델을 써야
>   함
> - 즉 "가장 좋은 모델"이 아니라 **"지원받을 수 있는 범위 안에서 가장
>   좋은 모델"**을 골라야 하는 문제였음 — 그런데 그 범위 안의 어떤
>   모델이 실제로 쓸만한지 검증된 게 없었음
>
> **왜 그렇게 했는지**
> - AWS Bedrock에서 지원받을 수 있는 이미지 모델을 전부(Stable Image
>   Core, SD3.5 Large, Stable Image Ultra, Style Guide, Nova Canvas)
>   실사용 프롬프트로 비교 테스트함 — 법정 장면, 기자회견, 상징적
>   오브젝트 구성(예: "4개 상징 오브젝트 flat-lay", "문 3개 중 2개만
>   봉인") 등 실제 발행에 쓰일 법한 지시로 여러 차례 검증
>   *(정확한 테스트 라운드 수는 기록 안 됨 — 확인 필요)*
> - 그 결과 **Stable Image Ultra가 프롬프트에 적힌 내용을 다른 AWS
>   모델보다 가장 충실하게 반영**한다는 걸 확인함(다만 OpenAI 수준의
>   정밀도는 아님 — 빈 연단·문 개수류 초정밀 지시는 Ultra 포함 AWS
>   모델 전부 약함, [정리후보 F] 참고)
>
> **어떻게 달라졌는지**
> - Stable Image Ultra를 admin 실험 패널의 기본 모델로 채택
>   (2026-09-18)
> - 이 선택이 지금 설계하려는 구조("관리자가 작업한 프롬프트가 자동
>   파이프라인에 그대로 반영")와 맞아떨어지는 이유: 그 구조가 성립하려면
>   모델이 **프롬프트를 충실히 따라야** 한다는 전제가 필요한데, 실측상
>   Ultra가 AWS 지원 범위 안에서 그 전제를 가장 잘 지키는 모델이었기
>   때문 — 우연히 기본값이 된 게 아니라, 이번 구조의 요구사항과 선정
>   근거가 같은 방향을 가리켜서 채택함

## 모델별 기능 지원 표

2026-09-20 기준, `admin/backend/routes/webtoon/generate.py` 디스패치
로직 기준으로 정리(코드 대조).

**O/X는 "구조적으로 그 기능을 쓸 수 있는가"(가능 여부)만 나타낸다.**
가능한데 지금 코드에서 일부러 꺼둔 건 **O(꺼둠)**으로 따로 표시한다 —
"꺼둠"은 모델의 한계가 아니라 2026-09-20 "사용자 프롬프트로만 제어"
결정에 따른 선택이다. 지금 실제로 쓰고 있는 건 **✅ 사용 중**.

| 모델 | 인물 고정 | 화풍 참고이미지 | 프롬프트 충실도(실측) | 품질 검증(QA/재시도) | AWS 비용 귀속 태깅 | 현재 상태 |
|---|---|---|---|---|---|---|
| **pipeline**(GPU IP-Adapter+Style Transfer) | ✅ 사용 중 — 참조 사진으로 얼굴 고정 | ✅ 사용 중 — Style Transfer 단계 | 별도 비교 안 함(QA로 보완) | ✅ 사용 중 — 비전 판정+얼굴 수 검사 | O | 발행 파이프라인 현재 기본값(구 경로) |
| **Stable Image Core** | O(꺼둠) | X — 구조상 참조이미지 입력 자체가 없음 | 보통 — 정밀 지시 약함 | O(꺼둠) | O | admin 실험 옵션 |
| **SD3.5 Large** | O(꺼둠) | X — 구조상 없음 | 보통 — 정밀 지시 약함 | O(꺼둠) | O | admin 실험 옵션 |
| **Stable Image Ultra** | O(꺼둠) | X — 구조상 없음 | **AWS 모델 중 가장 높음** | O(꺼둠) | O | **✅ admin 현재 사용 모델**(2026-09-18) |
| **Style Guide** | O — 부분(역할매핑 텍스트만, 장문 묘사는 구조상 배제) | ✅ 사용 중 — 고정 참조이미지 1장 | 보통~약함(참고이미지 편향, [정리후보 C](../02-정리후보/03-styleguide참고이미지얽힘.md)) | O(꺼둠) | O | admin 실험 옵션, 구조 얽힘 |
| **Nova Canvas** | X — 참조이미지 컨디셔닝 자체가 없는 순수 text-to-image | X — 구조상 없음 | 미측정 | O(꺼둠, 모델 자체는 차단 중) | O | 접근 차단(LEGACY 모델, AWS 콘솔 재활성화 대기) |
| **OpenAI**(gpt-image-1) | X — 참조이미지 메커니즘 자체가 없음 | X — 구조상 없음 | **전체 중 가장 높음**(정밀 지시 전부 정확) | O(꺼둠, 사업상 미사용) | 해당 없음(AWS 아님) | **사업적으로 사용 불가**(2026-09-18 확정) |

- **"O(꺼둠)"** = 코드 구조상 가능하고 과거엔 실제로 켜져 있었지만, 2026-09-20
  "사용자 프롬프트로만 제어" 결정으로 지금은 의도적으로 안 씀. 모델
  자체의 한계가 아니다.
- **"X"** = 그 모델의 호출 방식 자체에 해당 메커니즘이 없어서, 켜고 끄는
  선택의 문제가 아니라 구조적으로 불가능.
- 지금 admin에서 실제로 쓰는 건 **Stable Image Ultra 하나**다 — 이 표의
  다른 행은 전부 "선택 가능한 대안"이지 "지금 같이 쓰이는 것"이 아니다.
