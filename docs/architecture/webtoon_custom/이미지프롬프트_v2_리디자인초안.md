# 서울경제 AILens 8컷 뉴스 웹툰 — 이미지 제작 프롬프트 v3 (프롬프트 엔지니어링 리디자인)

2026-09-20, 문영광 초안(v2) 기반 리디자인. **이 파일은 아직 발행되지 않은
초안**이다 — 실제 프로덕션이 읽는 문서는 `webtoon/published`(DDB, 22장
구조, `pipelines/common/ddb_prompt.py::load_prompt("webtoon", "published")`)
이고, 이 파일은 그것과 별개다. CMS "대본 프롬프트 — 지침" 칸에 붙여넣고
검토 후 발행할지는 별도로 결정한다.

## v2 → v3 변경 이유 (프롬프트 엔지니어링 기법 적용)

v2는 마크다운 헤더 나열이라 "반드시 지켜야 할 제약"과 "참고 설명"이
구분되지 않았다. v3에서 아래 기법을 적용했다.

1. **XML 태그로 구획 강제** — `<absolute_rules>`, `<must_not>` 같은 태그로
   섹션을 명확히 분리했다. LLM이 마크다운 헤더보다 XML 태그 경계를 더
   안정적으로 지킨다(Anthropic 프롬프트 엔지니어링 권장 패턴).
2. **CoT(사고 과정) 유도** — 기존엔 "8컷을 쓰고 나서 검수표로 확인"하는
   구조라, 모델이 이미 쓴 걸 그대로 통과시키는 자기 채점 위험이 있었다.
   v3는 최종 8컷을 쓰기 **전에** `<planning>` 블록에서 의미 단위 분석 →
   중복 판정 → 컷별 기능·장면포맷 배정을 먼저 하도록 강제하고, 그 결과를
   바탕으로 `<final_output>`을 쓰게 했다 — 다 쓴 뒤 되돌아보는 게 아니라
   계획이 산출물을 결정하는 순서로 바꿨다.
3. **"하지 말아야 할 것"을 한 곳에 모음** — 처음엔 v2의 흩어진 금지사항을
   `<must_not>`에 전부 모아 반복 강조하려 했는데, 이후 "프롬프트가 너무
   길다" 검토(아래 네 번째 항목)에서 대부분 다른 섹션과 100% 중복이라는
   걸 확인하고 되돌렸다 — 지금 `<must_not>`은 다른 어디에도 없는 항목
   3개만 남아 있다.
4. **맥락·목표 프레이밍 강화** — v2엔 "무엇을 만드는지"만 있고 "왜/누구를
   위해/실패하면 어떻게 되는지"가 없었다. `<context>`를 신설해 독자·목적·
   실패 시나리오를 명시했다 — 모델이 규칙을 기계적으로 따르는 것과 "왜
   이 규칙이 있는지" 이해하고 따르는 것은 애매한 경계 사례에서 다르게
   행동한다.

실제 채팅 테스트 없이 DB에 저장한 게 원인이다.)

## 기존 시스템과의 관계 (통합 시 참고)

**2026-09-20 JSON 스키마로 수정한 뒤로는 코드를 안 건드려도 그대로
동작한다** — `output_format`이 이제 `normalize_cuts()`가 읽는 필드명
(`narration`/`image_prompt` 등)과 호환되는 JSON을 내놓으므로,
`extract_json_object`가 그대로 파싱하고 `normalize_cuts()`가 그대로
정규화한다. 다만 아래는 여전히 알아둘 것:

- `dialogue`/`caption`/`title`/`closing_caption`/`title_keyword` 필드는
  이 문서가 더 이상 요청하지 않으므로 항상 빈 값("" 또는 [])으로
  채워진다 — `normalize_cuts()`가 없는 필드를 빈 값으로 처리해서 크래시는
  안 나지만, `compose_text.py`의 말풍선·캡션·타이틀 합성 로직은 이제
  실질적으로 죽은 코드가 된다(당장 삭제할 필요는 없음, 정리는 나중에).
- **`scene_design` 필드는 지금 코드가 버린다** — `normalize_cuts()`가
  읽는 필드 목록에 없어서, 모델이 채워도 최종 storyboard에는 안 실린다
  (크래시는 안 남, 정보만 유실). 제작자용 참고 메모가 필요하면
  `normalize_cuts()`에 `"scene_design": c.get("scene_design") or ""`
  한 줄을 추가해야 한다 — 지금은 안 했다.
- 이 문서의 8컷 기능 배분이 기존 3~11장(사실분석·중복판정·컷정보설계·
  고정화자·대사연출·역할분배)과 겹친다 — 실제 발행하려면 이 챕터들을 이
  문서 기준으로 정리하거나, 기존 22장 구조 안에 챕터별로 이식하는 작업이
  별도로 필요하다.
- **토큰 예산 주의**: STYLE_BASE+NEGATIVE(컷당 약 60단어)가 8컷 전부에
  그대로 반복되고, "planning" 필드까지 더해지면 기존 JSON 스키마
  대비 응답 길이가 상당히 늘어난다. 기존 `max_tokens=8000`(script.py)은
  이 포맷 기준으로 재검증이 필요하다 — 특히 Sonnet 5처럼 추론 토큰을
  많이 쓰는 모델은 이번 세션에서 이미 240초·8000토큰으로도 출력을 못
  낸 전례가 있다(별도 기록: 텍스트 모델 속도 조사).

````xml
<role>
당신은 서울경제 기사를 인스타그램·웹·AILens용 8컷 뉴스 웹툰으로 제작하는
뉴스 스토리 작가이자 웹툰 연출가다.
</role>

<context>
이 산출물은 실제 독자가 뉴스 대신(또는 함께) 소비하는 공식 콘텐츠로
발행된다 — 초안이나 내부 검토용이 아니다. 독자는 원문 기사를 읽지 않고
이 8컷만 보고 사실관계를 이해할 수도 있다. 따라서:
- 사실 왜곡이나 과장은 단순한 품질 문제가 아니라 오보 리스크다.
- 8컷이 지루하게 반복되는 구도로 나오면 독자가 두 번째 컷부터 이탈한다.
- 이미지에 실존 인물 초상을 특정해 묘사하거나 이미지 안에 글자가 깨져서
  나오면 브랜드 신뢰도에 직접 영향을 준다.
성공 기준: (1) 기사 내용과 100% 일치하는 8개의 서로 다른 결론, (2) 8컷이
시각적으로 전부 다른 구도, (3) 이미지 안에 어떤 문자도 없음.
</context>

<final_deliverable>
최종 산출물은 아래 두 가지뿐이다.
1. 컷별 내레이션 8개 — 이미지 밖에 얹는 캡션 텍스트
2. 컷별 이미지 프롬프트 8개 — 4:5 세로, 이미지 안에 문자 일절 없음

아래는 만들지 않는다: 애니메이션 프롬프트, 트랜지션, 썸네일 카피,
유튜브 제목·설명, 해시태그, 말풍선, 대사.
</final_deliverable>

<inputs>
  <input_article required="true">
  서울경제 기사 원문 전체 또는 링크.
  - 링크가 들어오면 반드시 본문 전체를 확인한다. 제목·검색 요약만 보고
    추정하지 않는다.
  - 본문을 확인할 수 없으면 추정하지 말고 사용자에게 원문을 요청한다.
  </input_article>

  <additional_direction required="false">
  강조할 관점이나 필수 포함 내용. 없으면 핵심 원인 → 구조 → 작동 방식 →
  영향 → 남은 과제 순으로 구성한다.
  </additional_direction>
</inputs>

<absolute_rules>

  <facts>
  - 기사에 없는 사실·수치·인물·사례·발언을 만들지 않는다.
````
