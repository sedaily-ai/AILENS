# 정리후보 A — 모델 디스패치 로직이 두 곳에 따로 있다

[← 정리후보](README.md)

---

> **문제 발견**
> - `admin/backend/routes/webtoon/generate.py::_generate_once()`는 5개
>   모델(pipeline/stable_image_core/sd35_large/sd_ultra/style_guide)을
>   전부 다루는 완성된 디스패치 로직을 갖고 있음
> - `pipelines/webtoon/pipeline.py`는 `IMAGE_PROVIDER` 코드 상수 하나로
>   GPU 경로 하나만 아는 완전히 별개의 if/elif 분기를 갖고 있음 — 두
>   구현이 코드를 한 줄도 공유하지 않음
>
> **문제 정의**
> - admin에서 아무리 다른 모델을 검증해도, 그 결과가 발행 파이프라인에
>   반영될 방법 자체가 없다 — 이게 [상위 README 목표](../README.md#목표)
>   ("설정값이 실시간으로 적용")가 막힌 근본 원인
> - 프롬프트 조립 함수(`build_background_prompt` 등)의 기본값을 admin
>   쪽만 바꾸고(2026-09-20, 캐릭터 고정 제거) 발행 파이프라인은 그대로
>   둔 비대칭 상태도 이 분리 때문에 생김
>
> **제안하는 방향**(미확정 — 사용자 검토 필요)
> - 발행 파이프라인이 admin의 `_generate_once()`(또는 그 후신)를 그대로
>   재사용하도록 합친다 — "모델 선택을 DB 설정값으로 뺀다"는
>   [상위 README 설계 목표]와 사실상 같은 작업일 가능성이 높다
> - 합치면 [정리후보 D](04-GPU경로결정미반영.md)(GPU 경로 결정 미반영)도
>   자연히 같이 풀린다
>
> **왜 그렇게 했는지 / 어떻게 달라졌는지**(2026-09-20, 진행 중)
> - Phase 1: `pipelines/common/webtoon_image.py`에 `generate_cut_image()`
>   신설 — admin의 `_generate_once()`/`_generate_composed_with_qa()`
>   본체를 여기로 옮겨 admin·발행 파이프라인 공유 정본으로 삼음
> - Phase 2: `admin/backend/routes/webtoon/generate.py`가
>   `generate_cut_image()`를 부르는 얇은 wrapper로 축소 — 배포 완료,
>   실험 패널 동작 확인
> - Phase 3(코드 완료, **배포는 아직**): `pipeline.py`(발행 파이프라인)도
>   `webtoon_image.generate_cut_image_to_file()`(파일쓰기+배치 재시도
>   래퍼 추가 신설) 한 호출로 전환 — `_generate_and_qa_cut`/
>   `_validate_and_detect`/개별 `build_*`/`generate_image_bedrock_*`
>   직접 호출 전부 제거. **이번 단계 목표는 리팩토링이지 모델 전환이
>   아니라서 `IMAGE_PROVIDER`는 그대로 유지**(정리후보 D 참고) — 로컬
>   모의 실행(fake generate_cut_image_to_file로 호출 인자 캡처)으로
>   `model="pipeline", retries=2, has_dialogue` 판정이 리팩토링 전과
>   동일함을 확인. ECS 재배포는 실제 무인 발행에 영향을 주므로 사용자
>   확인 후 진행 예정 — 배포되면 이 항목도 완료로 갱신
> - 이 통합으로 [정리후보 E](05-QA로직이중구현.md)(QA 로직 이중 구현)도
>   같이 해소됨 — `generate_cut_image()` 안에 QA/재시도가 한 곳에만 있음
> - **Phase 4(같은 날, 배포 완료)**: `IMAGE_PROVIDER`를
>   `"bedrock-sd-ultra"`로 전환해 admin·발행 파이프라인이 실제로 같은
>   모델(Stable Image Ultra)을 쓰도록 맞췄다 — 자세한 QA 정책·검증
>   결과는 [정리후보 D](04-GPU경로결정미반영.md) 참고. 이로써 이 항목
>   ("admin에서 검증해도 발행에 반영 안 됨")은 완전히 해소됨
