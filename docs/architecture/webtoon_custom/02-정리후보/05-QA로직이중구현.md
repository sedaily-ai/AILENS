# 정리후보 E — QA 로직이 admin과 발행 파이프라인에 각각 따로 구현돼 있다

[← 정리후보](README.md)

---

> **문제 발견**
> - admin `routes/webtoon/generate.py::_validate_and_detect()` vs 발행
>   `pipeline.py`의 `_generate_and_qa_cut()` — 별도 구현, docstring
>   상으로만 "같은 판정 기준"이라고 명시, 실제 코드 공유는 없음
>
> **문제 정의**
> - 판정 기준(`prompts.VALIDATE_SYSTEM`)은 정본을 공유하지만 호출
>   로직·재시도 로직 자체는 두 벌 — 한쪽만 고치면 조용히 갈라진다
> - 2026-09-20에 admin의 pipeline 외 4개 모델에서는 이 QA 자체를
>   제거했음(군중 등 사용자 프롬프트와 충돌하던 문제) — pipeline 모델
>   경로만 남아 발행 파이프라인과 비교 대상이 좁아진 상태
>
> **제안하는 방향**(미확정)
> - [정리후보 A](01-모델디스패치중복.md)가 풀려 두 경로가 합쳐지면 QA
>   호출부도 자연히 하나로 합칠 기회가 생김 — 별도로 먼저 합칠 필요는
>   낮음(위험 대비 이득이 A보다 작음)
>
> **왜 그렇게 했는지 / 어떻게 달라졌는지**(2026-09-20, [정리후보 A](01-모델디스패치중복.md) Phase 1~3으로 해소)
> - QA 판정(`_validate_and_detect_cut`)·재시도 1회 로직 전부
>   `common/webtoon_image.py::generate_cut_image()` 한 곳으로 통합 —
>   admin(`generate.py`)·발행(`pipeline.py`) 둘 다 이 함수를 호출하는
>   쪽으로 정리돼, 더 이상 두 벌의 QA 구현이 없다
> - `with_qa` 파라미터로 "model=='pipeline'일 때만 기본 QA"라는 admin의
>   2026-09-20 결정(나머지 4개 모델은 QA 없이 사용자 프롬프트 결과 그대로)이
>   발행 파이프라인에도 자동으로 동일 적용됨 — 별도 분기 불필요
