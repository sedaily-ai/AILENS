# 뉴스룸 웹툰 프롬프트 개선 검토

> **2026-10-21 후속 정정:** 아래는 v48 시점의 검토 기록이다. 이후 뉴스룸 고정 요구가 철회됐고, 이미지 공급자 정책과 실제 시험을 반영해 image_prompt를 영어로 바꿨다. 근거 부족 상태·옵션 전달·자막 오류 처리도 구현했다. 최종 지침은 [v49](화풍일관성_장소선택_프롬프트_2026-10-20.md), 배포·실제 이미지 검증 결과와 남은 한계는 [작업 기록](../../worklog/2026-10/2026-10-21-웹툰-프롬프트-v49-생성경로-수정.md)을 따른다.

## 결론과 범위

v48의 방향을 유지하며 **정보 선택, 장면 가시성, 검증 가능한 출력**을 구체화한다. 첫 비교 후보는 뉴스룸의 가시성 규칙만 바꾼다. 그다음 기사 배분 규칙을 별도 비교한다. 현재 결과는 프롬프트·코드 정적 검토와 평가 설정 검사이며, 실제 모델 응답이나 이미지 품질 개선을 입증한 결과가 아니다.

기준은 CMS에 저장한 v48 content다. 마지막 조회에서 운영 활성 버전은 v46이었다. 이번 검토에서는 CMS 저장·활성 전환을 수행하지 않았다.

## 개선 우선순위

### 1. 고정 설정과 화면에 보이는 대상을 구분한다

**확인된 문구 충돌:** v48은 얼굴 클로즈업·소품 인서트를 허용하면서 모든 image_prompt에 벽·디스플레이·파티션·데스크·테이블 전체 묘사를 반복하도록 한다. 작은 구도에 세트 전체가 경쟁하는 문제가 생길 가능성이 있다. 실제 그림에서 발생했는지는 미검증이다.

**변경안:** 전체 세트 기준은 유지하고, 각 이미지 지문에는 짧은 공통 공간 문구와 해당 구도에서 보이는 요소만 넣는다. 얼굴·헤어·복장과 화풍의 고정 문구는 유지한다. 각 컷은 다른 컷을 참조하지 않아도 실행할 수 있어야 한다.

기존 `고정 뉴스룸`의 도입 문구:

> 다음 문구를 모든 image_prompt에 글자 그대로 반복한다.

후보의 도입 문구:

> 아래 문구는 전체 세트의 기준이며, 한 컷에 모든 물체를 표시하라는 지시가 아니다.

각 컷에 반복할 공통 공간 문구:

> 현대적 뉴스룸의 매트한 네이비 벽과 밝은 회색 가구, 네이비·슬레이트 블루·웜그레이·아이보리 팔레트. 세트 왼쪽 위의 부드러운 주광과 일정한 실내 보조광.

후속 규칙:

> 그 뒤에는 선택한 카메라 구도에서 실제 보이는 공간 요소만 전체 세트 기준에 맞춰 구체적으로 쓴다. 프레임 밖의 가구·사람·장소는 묘사에 열거하지 않는다. 클로즈업에서도 네이비 벽이나 화면 테두리 등 공간 단서 하나는 남긴다.

`image_prompt 작성`의 3번, 생략 금지 문장, 마지막 자체 점검도 이에 맞춰 변경한 완성 후보를 로컬 평가 폴더에 저장했다. 후보는 CMS 버전 번호가 부여되지 않았다.

예상 효과는 주제와 구도의 명확성이다. 부작용은 배경 설명을 줄인 컷에서 공간 동일성 단서가 약해질 가능성이다. 따라서 와이드·클로즈업·소품 컷을 함께 비교해야 한다.

### 2. 중요도와 근거의 확정 수준을 별도로 판정한다

v48에는 중요도와 certainty가 이미 있다. 다음 개선에서는 두 값의 사용 규칙을 강화한다. 중요도 6점인 기업 발표도 검증된 사실로 바뀌지 않는다. “검토”, “추진”, “승인 시”와 발언 주체를 자막에서 보존해야 한다.

추가할 규칙 후보:

> 각 사실의 중요도는 뉴스에서 차지하는 비중이며 사실의 확정 수준을 뜻하지 않는다. 핵심 사실에 조건·반론·발언 주체가 있으면 같은 컷에 함께 표현하는 것을 우선한다. 길이 때문에 분리하면 바로 다음 컷에서 보완한다. 중요도와 관계없이 결론을 바꾸는 조건을 누락하지 않는다.

5~6컷이라는 배분 목표만 세기보다 **핵심 변화·직접 영향·근거·필수 조건이 빠짐없이 전달되는지**를 검사한다. 같은 사실의 재진술은 핵심 정보의 추가 전달로 세지 않는다.

### 3. 짧은 기사에 대한 처리 규칙을 정한다

v48은 정확히 8컷, 사실 창작 금지, 반복 제한을 동시에 요구한다. 한 문장 기사에서는 모두 충족하기 어렵다. `planning`에 부족하다고 적는 것만으로 충돌이 해소되지는 않는다.

- 프롬프트만으로 가능한 최소 개선: 근거 부족 시 원문 정보의 재진술을 제한적으로 허용하고, 새 사건·원인·수치를 만들지 않도록 명시한다. 정보 밀도는 낮아질 수 있다.
- 권장 제품 개선: 충분한 구성이 불가능하면 생성 전 편집 검토로 보내는 상태를 지원한다. 가변 컷 수를 채택하려면 현재 서버의 8컷 보강 지침과 화면도 함께 바꿔야 한다.

이번 후보에서는 8컷 계약을 임의로 변경하지 않았다. 짧은 기사 사례는 기준과 후보의 공통 한계를 드러내는 시험이다.

### 4. “좋은 예시”로 모호한 지시를 구체화한다

추상적인 품질 수식어 대신 서로 다른 장면의 짧은 예시를 제공한다.

- 얼굴 클로즈업: 얼굴·시선이 중심이고 네이비 벽과 화면 테두리만 보인다.
- 무인 소품 컷: 회색 테이블의 소품이 중심이고 뒤쪽 네이비 벽 일부만 보인다.
- 조건부 보도 문구: “추진한다”와 “시행했다”를 구분하고, 승인 조건을 보존한다.

첫 후보에는 장면 가시성 예시만 포함했다. 기사별 서사가 예시의 형태로 획일화되는지 회귀 검사한다. 기사 사실이나 정답을 프롬프트에 외워 넣지 않는다.

명확한 지시·서로 다른 예시·자료와 지시의 구분은 [Anthropic의 공식 프롬프트 가이드](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)에서도 안내한다. 이 방법의 우리 모델·기사에 대한 효과는 별도 비교 대상이다.

### 5. 실제 전달 경로와 검수 범위를 맞춘다

코드에서 확인한 사항:

| 항목 | 현재 경로 | 의미 |
| --- | --- | --- |
| `image_prompt` | CMS 스토리보드 → 이미지 요청의 `scene` | 화풍·인물·공간의 핵심 조건은 여기 있어야 한다 |
| `fact_ids`, `cut_function` | 컷 정규화에서 보존하지 않음 | 원본 응답의 편집 근거이며 현재 이미지 생성 단계의 검증 장치가 아니다 |
| `selected_facts` | 정규화된 storyboard 이벤트에 미포함 | 원본 응답과 근거를 평가 시 따로 보존해야 한다 |
| 모델이 출력한 `negative_prompt` | CMS 요청에서 미전달, 배치에서는 전달 | CMS에서 해당 금지 목록이 적용됐다고 가정할 수 없다. 코드의 공통 문자 금지 목록은 별도로 존재한다 |
| 기사별 seed | 배치에서 설정, CMS 요청에는 미포함 | 두 경로를 같은 생성 조건이라고 볼 수 없다 |
| 하단 자막 | 높이 22% 띠, 고정 폰트·줄바꿈 | 글자 수 제한만으로 실제 자막이 영역 안에 들어간다고 보장할 수 없다 |

근거 위치:

- `admin/backend/routes/webtoon/script.py::build_script_call`, `normalize_cuts`
- `admin/backend/routes/chat_ws.py::_run_article_flow`
- `admin/frontend/src/components/WebtoonCutGenerator/WebtoonCutGenerator.tsx::sendGenerate`
- `pipelines/webtoon/pipeline.py`의 `set_run_seed`, `set_run_negative` 호출
- `pipelines/common/webtoon_image.py::generate_bedrock_sd_ultra_image_bytes`
- `pipelines/webtoon/compose_text.py::draw_narration`

[AWS Stable Image Ultra 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-diffusion-stable-ultra-text-image-request-response.html)는 prompt·negative_prompt·seed를 별도 요청 필드로 정의한다. seed는 생성의 무작위성을 제어하는 값이며, 이 문서가 컷 간 얼굴 동일성을 보장하지는 않는다.

장기적으로는 검수한 인물·뉴스룸 기준 이미지를 실제 생성 입력으로 활용할 수 있는 모델과 경로를 별도 검토할 수 있다. 현재 코드의 Ultra 호출에는 참조 이미지를 보내지 않는다. 다른 이미지 도구로 만든 샘플을 CMS 모델의 검증 결과로 간주하지 않는다.

## 활용한 스킬과 검증 상태

`persona-harness`로 역할·평가 항목·합성 기사 5개·기준/후보 비교 설정을 만들었다.

| 사례 | 확인할 내용 | 분류 |
| --- | --- | --- |
| closeup | 얼굴·소품 중심 구도와 뉴스룸 단서의 양립 | smoke |
| conditional | 검토·예산 승인 조건과 적용 범위 보존 | smoke |
| sparse | 한 문장 기사의 8컷 구성 충돌과 허위 정보 | edge |
| claim | 기업 내부 시험의 주장과 검증된 사실 구분 | edge |
| embedded-instruction | 기사 속 명령형 인용을 지시로 실행하는지 | edge |

- `validate`: 성공, persona 1개·scenario 5개.
- `plan --suite smoke --max-target 4 --max-judge 4`: 성공, 차단 사유 없음.
- `plan --suite edge --max-target 6 --max-judge 6`: 성공, 차단 사유 없음.
- 연결은 files이며 `requires-response-files` 상태다. 실제 모델 연결 확인이 아니다.
- 실제 대상/Judge 호출 0회, 이미지 생성 0회, 품질 점수 없음.
- 모두 development 사례다. 별도 holdout·독립 평가·사람 검수는 수행하지 않았다.
- 기준 content SHA-256: `ff6331d3f8f7fd3032153cddcb8ddf3068d8226c2bb7a2b374520ece97e05ec3`
- 후보 content SHA-256: `5b1286834556d46a4c1ca8a60683e09fb6b05ef1790d24f8d8da09a04220ca45`

로컬 자료는 `local/persona/webtoon-newsroom/`에 저장하고 해당 폴더의 `.gitignore`로 제외했다. `README.md`에 재실행 명령과 CMS와 같은 호출을 구성하기 위한 조건을 적었다.

## 권장 비교 순서

1. v48과 가시성 후보에 동일한 기사·텍스트 모델·호출 설정을 사용한다.
2. 원본 JSON에서 사실·조건·컷 역할을 검사하고, CMS에서 실제 전달되는 이미지 지문도 확인한다.
3. 동일 기사 8컷을 양쪽에서 생성해 전체를 나란히 검수한다. 가장 잘 나온 컷 하나로 판정하지 않는다.
4. 얼굴·머리·복장, 뉴스룸 배치, 팔레트·명암, 핵심 대상, 손과 소품, 자막 가림을 각각 기록한다.
5. 효과가 확인되면 CMS 새 버전으로 누적한다. 다음 비교에서 중요도·근거 배분 규칙을 변경한다.

텍스트 하네스는 실제 그림을 평가하지 않는다. 표본 1건으로 모든 기사의 개선을 일반화하지 않는다.
