# 웹툰 합성 파이프라인 (현재 구조)

갱신: 2026-10-03 (파이프라인 개정 108 기준). 이 문서는 "지금 어떻게 동작하나"만 다룬다. 개발 과정과 판단 근거는 `docs/worklog/2026-10/2026-10-02-웹툰-합성-고도화-버전별-개발기록.md`.

## 1. 데이터 흐름

```
기사 원문
  → [스크립트] Bedrock Opus 5(inference profile) + CMS 웹툰 프롬프트(v34)
      출력 1_script.json: cuts[8](title, dialogue[{speaker,line,tone}], caption, narration, image_prompt),
                          core_question, card_title, key_numbers[2~3], negative_prompt, image_seed(코드가 추가)
  → [그림] Stable Image Ultra(Bedrock inference profile, us-west-2) 컷당 1장, 3:2, 기사별 seed 공통
  → [분석] (토글) Rekognition: 사람 상자·얼굴 상자·성별
  → [합성] compose_text.py(Pillow): 말풍선·제목·출처 박스·나레이션 띠 → 컷N.png (1824px)
  → [카드] (토글) 코드로 그린 핵심 정리 카드 컷9.png
  → [발행] WebP q90 업로드 → CMS(lens-cms-api) 글의 웹툰 lens(images/bullets/question) → 서비스 갤러리
```

## 2. 설정 위치 (재배포 없이 바뀌는 것)

| 설정 | 어디서 | 저장 | 읽는 곳 |
|---|---|---|---|
| 웹툰 생성 프롬프트 | CMS 프롬프트 화면(웹툰) | prompt `webtoon` | `ddb_prompt.load_prompt("webtoon")` |
| 이미지 모델·화풍·인물 | CMS 이미지 설정 | prompt `webtoon-image/published` 문서의 `## IMAGE_MODEL` 등 | `webtoon_image.get_*` |
| 말풍선 얼굴 회피 | CMS 이미지 설정 체크박스 | 같은 문서 `## BUBBLE_DETECT on/off` | `get_bubble_detect()` |
| 웹툰식 말풍선 | CMS 이미지 설정 체크박스 | 같은 문서 `## BUBBLE_STYLE on/off` | `get_bubble_style()` |

문서에 섹션이 없으면 꺼짐으로 읽는다. 읽기 실패도 꺼짐. 프론트의 `buildImagePromptDoc`(admin/frontend/src/lib/webtoonImagePromptDoc.ts)와 `webtoon_image.serialize_prompt_doc`/`parse_*`는 같은 포맷이어야 한다(한쪽만 고치면 발행이 깨진다).

테스트 카드·프로덕션 카드 컷 생성은 카드의 체크 상태(`cut.bubble_detect`, `cut.bubble_webtoon`)가 있으면 그것을, 없으면 발행 설정을 따른다.

## 3. 코드 지도

- `pipelines/webtoon/pipeline.py`: `run_article` — 스크립트, seed·negative 설정, 컷 루프(그림 → 감지 → 합성), 핵심 정리 카드, 세로 합치기. 합성 실패는 웹툰식 → 기본 스타일 순으로 폴백.
- `pipelines/webtoon/compose_text.py`: 합성 전부.
  - `compose(img_path, cut, faces, scale)`: 진입점. 배율(1.5) 적용, 말풍선 배치 정보(layout) 반환.
  - `cut` 키: `title`, `dialogue`, `caption`, `narration`, `closing_caption`, `detect`(Rekognition 결과), `bubble_style`("oval"), `bubble_margin`(true). 대사 항목의 `pos`/`tail`은 사람이 CMS에서 옮긴 위치(비율)로 자동 배치를 덮어쓴다.
  - `_plan_with_people`: 후보 자리 점수화(얼굴·머리 감점, 몸통 약한 감점, 풍선끼리 겹침 금지, 화자와 가까움, 위쪽, 꼬리 짧음, 질문이 위). 실패하면 None → 고정 배치.
  - `_tail_geometry`(사각형 풍선)·`_ellipse_tail`(타원·삐죽): 꼬리. 이음새는 흰 선으로 덮는다.
  - `_oval_bubble`, `_spiky_with_tail`, `_whisper_bubble`, `_thought_bubble`, `_handdrawn_bubble`: 모양.
  - `make_summary_card`: 핵심 정리 카드(이미지 모델 호출 없음).
  - 웹툰식(여백) 모드: 그림 위에 흰 여백을 붙이고(표지는 더 크게) 풍선을 거기에 두며, 나레이션은 그림 아래 검은 띠(핵심 숫자 파랑).
- `pipelines/common/webtoon_image.py`: Bedrock 호출(Ultra 프로파일 ARN), `set_run_seed`, `set_run_negative`, 설정 문서 파서.
- `pipelines/common/rekognition_people.py`: 사람·얼굴 감지. 실패하면 None.
- `pipelines/common/publish_utils.py`: 컷 → WebP 업로드, 컷9 카드 업로드(최소 컷 수 판정 제외).
- admin: `admin/backend/routes/webtoon/generate.py`(컷 생성 후 원본 `-bg.png` 보관, `handle_recompose`), `routes/media.py`(`handle_zip_download`), `admin/frontend/src/components/WebtoonCutGenerator/`(`BubbleEditorModal`, `WebtoonPreviewModal`, 컷 카드), `PromptChatLab/WebtoonImageSettingsPanel.tsx`(토글).
- 서비스: `service/frontend/src/shared/ui/WebtoonCutGallery.tsx`(컷마다 자기 비율).

## 4. 운영 메모

- 배포 순서: admin API → (새 라우트면 API Gateway `create-route`, 기존 연동 재사용) → admin 프론트 → 파이프라인 이미지(`bash pipelines/frontpage_auto/deploy.sh`, pipelines/ 에서 실행) → 서비스 프론트(갤러리 등).
- admin Lambda 배포 스크립트는 `compose_text.py`, `rekognition_people.py`, 글꼴 2종(`NotoSansKR-Bold.ttf`, `PretendardVariable.ttf`)을 zip 루트에 복사한다. 새 파일을 import하게 만들면 `deploy-admin-api.sh`에도 복사를 추가해야 한다(안 하면 admin API 전체가 콜드스타트에서 죽는다).
- 권한: 파이프라인 태스크 역할과 admin Lambda 역할에 `rekognition:DetectFaces`, `rekognition:DetectLabels`(인라인 정책 `WebtoonBubbleRekognition`).
- 비용태깅: 모델 호출은 항상 inference profile ARN(Ultra `lens-webtoon-image-sd-ultra`). 베어 모델 ID 금지.
- 비용: 이미지 컷당 약 $0.08(Ultra), Rekognition 컷당 약 $0.002, 합성·카드·나레이션은 0.
- 폴백 3단(웹툰식 합성): 한도 완화 재탐색 → 고정 배치 → 기본 스타일. 로그에 "웹툰식 합성 실패", "말풍선 자리 계산 실패"가 보이면 이유를 확인한다.

## 5. 복구·재생성 도구 (`pipelines/scripts/`)

- `repair_missing_formats.py [--apply] [--only webtoon|video] [--redo] <source_url>`: 빠진 포맷을 채우거나(`--redo`는 있는 웹툰도) 현재 프로덕션 설정으로 다시 만든다. 기존 글은 `repair_backup/`에 백업, 저장 후 레터·팟캐스트 동일 검증.
- `recompose_cut1.py [--apply] <source_url>`: 컷1 글자 합성만 다시(원본 그림 재사용).
- `repair_short_letters.py`: 레터 복구(웹툰과 무관, 같은 방식).

## 6. 알려진 한계

- 그림이 3:2로 나온다(프롬프트의 "4:5 vertical"과 어긋남). 4:5 전환은 합성·갤러리·기발행 컷 혼재를 같이 다뤄야 한다.
- 화풍·인물이 컷마다 달라진다(seed 공통은 약한 효과). Ultra는 image-to-image를 지원하지 않는다.
- 발행된 컷은 원본이 없어 CMS에서 말풍선을 고칠 수 없다.
- 한 기사의 특수 톤 한도(격앙2·속삭임2·생각1)는 프롬프트 규칙뿐이다(한 컷 안 두 대사 중복만 코드가 막는다).
- 목록·홈 썸네일은 3:2 중앙 크롭이라 웹툰식 표지의 여백이 일부 잘릴 수 있다.
