# AI LENS 개발 원칙 (2026-10-12)

기준 문서: 팀 공통 개발 원칙(AI ECHO 프로젝트에서 정리). 서버리스(Lambda + API Gateway) 항목은 참고만 하고, AI LENS 구조(FastAPI on EC2, ECS 파이프라인, Next on ECS)에 맞는 것만 적용함.
절차(브랜치·PR·배포)는 루트 `CLAUDE.md`, 비용 규칙은 `비용태깅_규칙.md`가 정본.

## 적용한 원칙과 이 저장소의 구현

| 원칙 | 이 저장소의 구현 | 확인 방법 |
|---|---|---|
| 정본 한 곳, 복사 금지(모델) | `pipelines/common/bedrock_models.py` 별칭→ARN. 코드에서 ARN 문자열 직접 기재 금지 | `pipelines/common/test_bedrock_models.py`(정책 JSON·관리자 모델 표와 정합) |
| 정본 한 곳, 복사 금지(리소스) | `config/resources.env`(계정·CloudFront·버킷·인스턴스 ID). 배포 스크립트는 source | `pipelines/scripts/check_resources_env.sh` |
| 오류를 삼키지 않음 | 폴백하는 `except` 는 원인 로그를 남김 | 코드 리뷰(PR 점검 항목) |
| 단일 책임 | 라우트는 `service/lens-cms-api/routes_*.py`(도메인별), 규칙은 `*_rules.py`, DB 접근은 `*_repo.py` | `tests/test_route_table.py` |
| 이름만으로 역할 파악 | `utils`·`common`·`temp` 신규 금지(기존 `pipelines/common`은 파이프라인 공용 모듈 폴더) | 리뷰 |
| 폴더당 파일 약 10개 | 초과 시 하위 폴더(예: `features/letter/components/{list,detail,dialog}`) | 리뷰 |
| 배포 번들 자급자족 | admin Lambda zip 은 pipelines 모듈을 flat 복사하므로 의존 모듈이 복사 목록에 있어야 함 | `pipelines/common/test_admin_bundle.py` |
| 비밀은 이름만 기재 | `.env.example` 에 변수 이름만, 값은 `.env.local`(git 제외) | 리뷰 |
| 확인한 것과 "미확인" 구분 | PR 본문 "검증" 항목에 기재 | PR 템플릿 관행 |

## 서버리스 항목(참고)

| 원칙 | AI LENS 해당 여부 |
|---|---|
| 얇은 핸들러, 초기화는 핸들러 밖, 상태는 DB | admin Lambda(`admin/backend`)에만 해당. lens-cms-api 는 상시 서버 |
| 30초 초과 작업은 비동기 | 파이프라인(ECS RunTask)과 admin 작업 job 이 이미 비동기 |
| 멱등성 | 파이프라인은 `already_published` 로 중복 발행 방지 |
| 실패 알림·DLQ | 미적용(후속 과제) |

## PR 전 점검
1. 바뀌는 이유가 하나인가
2. ARN·ID·이름을 복사하지 않고 정본(`bedrock_models.py`, `resources.env`)을 읽는가
3. 비밀·개인정보가 포함되지 않았는가
4. 입력 검증(서버)과 소유자 범위를 지켰는가
5. 코드 변경에 맞춰 문서·`.env.example`·정책 JSON 을 함께 고쳤는가
