# v1.29 — "오늘의 이슈, 4가지 시선"(lens 채널 지면 특별 코너) 빈 화면 버그 수정 (2026-09-09)

**왜**: 사용자가 홈페이지 스크린샷을 보내 "지면 1면" 등 4개 탭이 전부
"준비하고 있어요"로 비어있다고 신고. v1.25~v1.28 작업과는 무관하지만,
같은 세션에서 즉시 조사·수정.

## 진단

Explore 에이전트로 프론트엔드(`LensPreviewSection.tsx`)부터 역추적:
`GET /api/v2/posts?channel=lens` → `service/lens-cms-api/cms_posts_repo.py`
`list_published_posts()` → `cms_posts_shaping.py::shape_lens_summary()`가
`body_inline.paper_section`/`category`/`photo_image_url`, `display_order`
를 읽어 4탭에 배치한다.

**두 겹의 문제였다**:

1. **코드 버그**: `cms_posts_repo.py`의 "lens" 채널 SQL이 애초에
   `admin_extra` 컬럼을 SELECT하지 않았다 — `_row_to_post()`가 만드는
   `body_inline`엔 `body`/`images`/`lenses`만 있고 `paper_section`류
   필드 자체가 없어 항상 `None`이었다(v1.20/v1.21 lens 채널 컷오버
   당시부터 존재하던 갭, 오늘 처음 발견).
2. **데이터 갭**: 위 버그를 고쳐도 여전히 비어있었다 — `publications.
   admin_extra`가 대부분 `{}`였다. DynamoDB 원본(`sedaily-mbti-cms-posts-dev`,
   channel='lens', 913건)을 직접 확인한 결과 `body_inline.paper_section`
   에 실제 값("증권" 등)이 있었다 — v1.4/v1.12 마이그레이션 당시
   `admin_extra` 패턴 자체가 아직 없어서(v1.21에서 신설) 이 필드들이
   이관되지 않고 유실된 상태였다.

## 수정

`service/lens-cms-api/cms_posts_repo.py`:
- "lens" 채널 SQL 2곳(`list_published_posts`, `get_published_post_by_slug`)
  에 `admin_extra` SELECT 추가.
- `_apply_lens_admin_extra()` 헬퍼 신설 — `admin_extra.body_inline`의
  `category`/`paper_section`/`photo_image_url`과 `admin_extra`의
  `display_order`/`editor_id`를 `_row_to_post()` 결과에 병합.

## 백필

`sedaily-mbti-cms-posts-dev`(channel='lens', 913건) 전체 스캔 →
`admin_posts_repo.py::create()`와 동일한 모양(`editor_id`/`closing_line`/
`display_order`/`media_embed_url`/`created_by`/`body_inline` 전체)으로
`publications.admin_extra`에 백필 — 공개 읽기뿐 아니라 admin 편집 화면에서
이 글을 열어도 body_inline이 비어 보이지 않도록 전체 구조를 옮겼다.
이미 admin_extra가 채워진 행(라이브 컷오버 이후 실제 admin 작업 가능성)
은 덮어쓰지 않음.

결과: 874건 업데이트, 22건 slug 매칭 실패(마이너, 원인 미조사 — DynamoDB
쪽에만 있고 Postgres publications에 없는 소수 항목으로 추정), 17건은
이미 admin_extra가 있어 스킵(그중 1건 확인 결과 이전 세션의 v1.21 테스트
글로 이미 soft-delete 처리돼 있어 라이브에 영향 없음). paper_section이
실제로 채워진 행 509건(전체 51, 증권 185, 산업 217, 시그널 56).

## 검증

- 로컬 스크립트로 `list_published_posts('lens', ...)` 직접 호출 —
  수정 전 `category`/`paper_section`/`photo_image_url` 전부 None 확인,
  백필 후 실제 값 확인.
- EC2 배포 후 **실제 프로덕션 API** `https://ailens.sedaily.ai/api/v2/posts
  ?channel=lens&limit=1000` 직접 호출 — 4개 탭 전부 정상 카운트 확인
  (전체 51 / 증권 185 / 산업 217 / 시그널 56, 각각 최신 게시물의
  `paper_section`/`category`/`photo_image_url` 필드 정상 반환).

## 배포

lens-cms-api EC2 재배포 1회(`cms_posts_repo.py`만).

## 남은 항목

- DynamoDB-Postgres slug 매칭 실패 22건은 원인 미조사(낮은 우선순위,
  전체 913건 중 소수).
- 이 버그가 letters/webtoon/home_player 채널에도 존재하는지는 확인
  안 함 — `_BASE_SELECT`(이 채널들이 쓰는 쿼리)도 `admin_extra`를
  SELECT하지 않아 `body_inline.category`/`chart`/`section`/
  `series_title` 등이 똑같이 항상 None일 가능성이 있다(`cms_posts_
  shaping.py`의 `shape_letter`/`shape_webtoon`/`shape_home_player_item`
  전부 이 필드들을 읽음). 이번엔 사용자가 신고한 lens 채널만 정밀
  수정·검증했고, 다른 채널은 범위 밖으로 남겨둠 — 다음에 확인할 것.
