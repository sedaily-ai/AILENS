# v1.32 — 자동 콘텐츠 파이프라인 DynamoDB → Postgres 직접 발행 전환 (2026-09-10)

**왜**: 사용자가 "렌즈 파이프라인이 돌고 있나요? 9월 7일자가 마지막으로
돌고있는데?"라고 물어 조사한 결과, `frontpage_auto`/`mustknow_auto`(EventBridge
자동 실행 Fargate 파이프라인)는 정상 실행되며 하루 70~90건씩 콘텐츠를
만들고 있었지만 전부 DynamoDB에만 쓰고 있었다. 사이트 읽기(v1.20)·admin
쓰기(v1.21)는 Postgres로 전환됐는데 이 자동 파이프라인만 범위에서
빠져 있었던 것 — v1.4 이관 스냅샷 이후(2026-09-07 01:05 UTC) 파이프라인이
만든 글이 DynamoDB에 고립돼 사이트에 전혀 반영되지 않고 있었다.

세션 워크로그에 설계·구현 경위 전체가 있다:
`docs/worklog/2026-09/2026-09-10-파이프라인-postgres-직접발행-전환.md`.
이 문서는 db-changelog 관례에 맞춘 요약 + 실측 수치.

## 수정

- 두 파이프라인이 `service/lens-cms-api`의 기존 내부 HTTP API(admin
  콘솔과 동일 경로, `POST /admin/posts`+`/status`)를 통해 Postgres에
  직접 발행 — 직접 DB 접속 대신 "Postgres 접근을 이 서버 하나로
  집중"하는 기존 원칙을 그대로 따랐다.
- 형제 채널(webtoon/video/home_player) 별도 publications 행 생성 제거
  — v1.30에서 이미 확인된 설계(channel=video/webtoon 조회가 lens 번들의
  rendition만 보고 걸러준다는 것)와 맞춤.
- `publications.source_url`에 btree 인덱스 신설(중복 발행 체크용, 기존엔
  없었음).
- 배포 중 발견·수정한 IAM 권한 갭 3건(GPU EC2/SSM 제어, Bedrock 이미지
  스타일 모델, Bedrock cross-region 라우팅) — 자동 파이프라인이 실제로
  실행돼본 적 없던 웹툰 GPU 생성 경로에서 전부 처음 드러남.
- 부수 발견·수정: 홈페이지 카드가 웹툰 컷을 썸네일로 잘못 쓰는 문제,
  같은 글이 카드 2번 중복 표시되는 문제, lens 글이 `/letters/{slug}`로
  정적 생성·사이트맵·RSS에 노출되던 문제 — 전부 `channel=letters` 조회가
  letter 포맷 rendition 있는 모든 글(=거의 모든 lens 글)을 같이 돌려주는
  기존 설계를 letters 전용 소비처들이 모르고 있던 것이 원인(v1.30과 같은
  클래스의 버그).
- **9/7~9/10 사이 DynamoDB에만 고립됐던 244건 백필** — 새로 만든 발행
  경로(HTTP API)로 재사용, source_url 완전일치로 중복 스킵. 216건 신규
  생성, 28건은 이미 있어 스킵, 실패 0건. 원본 `published_at`을 보존하도록
  후속 SQL로 보정(공개 읽기 경로가 `admin_publish_date`가 아니라
  `published_at`에서 표시 날짜를 뽑아, 그냥 두면 "오늘 발행"으로 잘못
  보였을 것).

## 검증

- `aws ecs run-task`로 frontpage_auto 수동 1회 실행 — 지면 1면 후보 4건
  전부 `{"published": 4, "published_no_video": 0, "skipped_duplicate": 0,
  "failed": 0}`로 완주. DB 확인 결과 게시물당 publications 1행 + rendition
  4개(형제 행 중복 없음).
- mustknow_auto 정기 스케줄(06:00 UTC)이 새 이미지로 자동 실행되는 것
  확인 — **이 문서 작성 시점 기준 아직 실행 중**(장시간 실행, 다음
  섹션 참조).
- 244건 백필 후 총 발행 게시물 995건 → 1,220건, 최신 발행일 2026-09-10
  (더 이상 "9월 7일이 마지막"이 아님).

## 남은 항목

- **mustknow_auto 이번 정기 실행의 완주 확인** — 이 문서 작성 시점
  기준 여전히 실행 중. 끝나면 이 섹션에 최종 발행 건수·웹툰 성공률을
  추가할 것(과거 기록을 고치는 대신 이어 쓰는 방식 — README 새 항목
  추가 규칙 §4).
- Rekognition(`DetectFaces`) 권한 갭 — 웹툰 컷 QA의 얼굴 인식 검증이
  권한 부족으로 매번 폴백(균등분할)한다. 발행 자체는 안 끊기는
  비차단 이슈라 사용자 확인 후 보류 중.
