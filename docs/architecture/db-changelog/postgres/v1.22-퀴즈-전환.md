## 사전 조사 — daily-letters는 제외

원래 다음 후보였던 "오늘의 레터"(`sedaily-mbti-daily-letters-dev`)를
조사한 결과 **죽은 레거시**로 확인해 마이그레이션 대상에서 제외했다:
- 실데이터 0건(2026-09-08 테이블 인벤토리 실측)
- 쓰기 파이프라인(Editor Pick)이 2026-08-05에 이미 폐기됨(2026-08-04
  RDS 삭제로 매일 조용히 실패 중이던 걸 발견해 폐기)
- 유일한 소비자였던 프론트엔드 `today-letters` 호출 자체가 2026-09-03
  삭제됨("죽은 fetch를 지우고 빈 응답을 로컬에서 바로 구성") — 콘텐츠는
  이미 cms-posts의 letters/lens 채널로 완전히 흡수됨
- admin `/letters` 화면은 남아있지만 "새로 쓰는 건 콘텐츠 메뉴에서" 라고
  스스로 명시(레거시 콘텐츠 수정/삭제 전용)

## 스키마 확장

원본 `quizzes` 스키마(id/quiz_date/position/question/created_by_type/
editor_no/run_id/is_reviewed/created_at)에는 admin의 draft/published
워크플로 자체가 없었다(응답을 저장 안 한다는 제품 결정과는 별개 문제).
cms-posts(v1.21)와 같은 패턴으로 확장:

- `status VARCHAR(16) DEFAULT 'draft' CHECK IN ('draft','published')`
- `published_at TIMESTAMPTZ`, `deleted_at TIMESTAMPTZ`, `updated_at
  TIMESTAMPTZ`(원본에 없었음)
- `admin_post_id UUID UNIQUE` — admin CmsQuiz 문서 원래 id(uuid) 보존
- `admin_extra JSONB` — term(원본 필드명, question과 의미 유사)/
  explain(정답 설명, 원본 스키마에 컬럼 자체가 없었음)/created_by

`lens_service_app`에 quizzes/quiz_options INSERT/UPDATE/DELETE +
시퀀스 USAGE 권한 부여(cms-posts와 마찬가지로 SELECT만 있었음).

## 정답 저장 방식 변경

DynamoDB는 오답 3개(`options`)만 저장하고 정답은 `term` 자체였다
(별도 정답 필드 없음). 관계형 `quiz_options`는 그렇게 암묵적으로 둘 수
없어 **정답도 명시적 행**(`position=1, is_correct=TRUE, content=term`)
으로 저장하고 이어서 오답 3개를 `is_correct=FALSE`로 저장 — 공개 조회는
`is_correct=FALSE`인 것만 뽑아 기존과 동일한 `options` 배열을 재구성한다.

- `service/lens-cms-api/quiz_repo.py`(신규) — create/get/list_quiz/
  update/set_status/soft_delete(admin 쓰기) + list_published_quizzes

- `service/lens-cms-api/main.py` — `/admin/quizzes*`(내부 API, 토큰

- `admin/backend/repo/quiz_repo.py` — DynamoDB(boto3) 전부 제거, HTTP
  클라이언트로 교체(posts_repo.py/v1.21과 동일 패턴). 함수 시그니처
  무변경 — `routes/quiz.py` 무수정.
- `service/backend/clients/quiz_questions_ddb_client.py` — 마찬가지로
  HTTP 클라이언트로 교체, `handlers/quiz_public.py` 무수정(같은 이름
  파일이 그대로 import됨).

## 발견·수정한 버그

`UNIQUE(quiz_date, position)` 제약이 `deleted_at`(soft-delete)과 무관하게
걸리는 하드 제약이라, "다음 position"을 `deleted_at IS NULL` 필터로
계산하면 이미 소프트 삭제된 행과 충돌해 `UniqueViolation`이 났다 —
실측 중 발견, 필터 없이 전체 행 기준으로 계산하도록 수정.

## 검증

- `quiz_repo.py` 단위 스크립트: create→get→list→update→publish→
  공개조회→delete 전체 사이클 확인.
- 새 서버 HTTP 엔드포인트 직접 테스트(공개 200, admin CRUD 200).
- **실제 admin API Gateway 경유 e2e**: JWT 발급 → `POST /admin/quiz`
  (201, 라우트가 `/admin/quiz` 단수임을 처음엔 착각해 404 한 번 겪음)
  → `POST /admin/quiz/{id}/publish`(200) → 즉시 `GET /api/quiz/today`
  (같은 API Gateway 경유)로 조회 시 방금 쓴 내용 확인 — **admin
  발행이 지연 없이 공개 API에 반영된다.**
- admin/backend 테스트: `test_quiz_routes.py` 28/28 통과(repo를
  monkeypatch하는 구조라 무수정으로 통과).
