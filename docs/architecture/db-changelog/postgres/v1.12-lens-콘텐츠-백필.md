# v1.12 — 'lens' 채널 lenses[] 콘텐츠 백필 (2026-09-09)

**왜**: v1.10에서 발견한 알려진 한계 — 'lens' 채널의 `body_inline.lenses[]`
(v1.4 이관 시 미이관) 해소.

**대상 확인**: 전체 `publications` 986건 중 렌디션이 0개인 것 **50건**
(913건이 아니었던 이유: 대부분의 'lens' 채널 그룹은 v1.4에서 같은
source_url을 공유하는 webtoon/video/home_player 형제 row를 통해 이미
렌디션을 받았음. 진짜 백필이 필요한 건 형제 row 없이 lens 하나만 있던
50건뿐).

**실행 중 추가로 발견한 것 — `lenses[].label`이 두 가지 다른 의미로
쓰이고 있었다**:
- **포맷 라벨**("레터"/"웹툰"/"팟캐스트"/"영상", 2건): v1.10에서 확인한
  원래 가정과 일치 — 포맷별 렌디션(webtoon_panels/media_assets/
  rendition_blocks)으로 정확히 분해.
- **분석 관점 라벨**("시선 ① — 원인이 궁금한 사람" 등, 48건, 더 이른
  시기 발행분): 4개 미디어 포맷이 아니라 **같은 주제를 보는 4가지
  분석 관점**(각각 `question`+`bullets` 텍스트)이었다. 미디어 포맷
  개념이 아니라서 letter 렌디션 하나에 4개 텍스트 블록으로 합쳐
  보존(2026-09-09 결정, 데이터 유실 감수 방침 하 최선 노력 보존 — 완벽한
  구조적 표현은 아님을 명시).

**결과**:

| 대상 | 결과 |
|---|---|
| 포맷 라벨 방식 | renditions 8건 (webtoon_panels 16, media_assets 4) |
| 관점 라벨 방식 | renditions 48건, rendition_blocks 192건(4개씩) |
| **렌디션 0개 publications** | 50 → **0** |

전체 `publications` 986건 전부 최소 1개 렌디션을 가진 상태로 확정.

**한계**: "관점 라벨" 방식으로 백필된 48건은 원래 UI 의도(4가지 관점
카드)를 정확히 재현하지 못한다 — 하나의 letter 렌디션 안에 4개 텍스트
블록으로 뭉쳐뒀을 뿐, 프론트가 원래처럼 "4가지 시선" 카드 UI로 렌더링
하려면 별도 구조가 필요하다. 지금은 콘텐츠 손실 없이 텍스트만 보존한
상태.
