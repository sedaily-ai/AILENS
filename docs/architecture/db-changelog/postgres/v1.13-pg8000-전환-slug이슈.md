# v1.13 — 드라이버를 pg8000으로 교체 + slug 유일성 이슈 발견 (2026-09-09)

**왜**: v1.10/v1.11에서 남긴 한계 — Lambda 배포 패키지에 `psycopg2-binary`가
없어 `CMS_DB_BACKEND=postgres`를 켜면 ImportError가 나는 문제를 해소.

## 해결: psycopg2 대신 pg8000 사용

`service/backend/deploy.sh`의 pip install 목록을 확인해보니 **pg8000이
이미 있었다**(`pg8000==1.31.2` — 순수 Python 드라이버, C 확장 빌드 문제가
없어 `--platform manylinux2014_x86_64 --only-binary=:all:` 크로스 빌드가
그대로 통한다. 과거 `pgvector_client.py`/`admin/backend/shared/pg_client.py`가
쓰던 것과 동일). `cms_posts_pg_client.py`를 psycopg2에서 pg8000으로
재작성 — **deploy.sh 변경 전혀 불필요**, 이미 배포 가능한 상태.

pg8000 관련 확인 사항(psycopg2와 다른 점, 실측):
- paramstyle이 `format`(위치 기반 `%s`) — named param(`%(name)s`) 미지원,
  전부 위치 기반으로 재작성.
- dict cursor가 없어 `cur.description` 기반 zip 헬퍼(`_dictfetchall`/
  `_dictfetchone`) 직접 작성.
- `jsonb_agg` 결과는 **자동으로 Python list/dict로 파싱됨**(json.loads
  불필요) — 실측 확인.

기존 테스트(`test_cms_posts_public.py`, `test_cms_posts_ddb_client.py`)
16개 재확인 통과.

## 새로 발견한 이슈 — publications.slug 유일성이 원본 slug 다양성을 잃음

pg8000 전환 테스트 중 `get_published_post_by_slug()`가 포맷 구분 없이
아무 렌디션이나 가져오는 걸 발견해 조사하다가, **형제 채널(같은
source_url)이 서로 다른 slug를 쓴다**는 걸 확인했다(예:
`...-video` vs `...-podcast`). v1.4 마이그레이션은 그룹당
`publications.slug` 하나만(우선순위 채널 기준) 남기고 나머지 채널의
고유 slug는 버렸다 — 원본 스키마의 `UNIQUE(slug)` 제약과 "발행물 하나에
형식콘텐츠 여러 개"라는 설계 의도상 불가피한 선택이었지만, 그 결과
**개별 채널 slug로 들어오는 기존 URL(북마크·검색엔진 색인)이 새 스키마
에서 그대로 해석되지 않는다.**

원본 스키마엔 정확히 이런 상황을 위한 `publication_slug_history`
테이블이 이미 있다(현재 미사용, 0건) — 다음 후속 작업으로 버려진
채널별 slug를 여기 채워 넣고 `get_published_post_by_slug()`가 실패 시
이 테이블로 폴백하도록 확장하면 해결 가능. 이번 세션에서는 발견만
하고 수정하지 않음(범위가 커서 별도 작업으로 분리).
