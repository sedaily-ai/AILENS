# v1.36 — DynamoDB 잔여 데이터 이관: candidate_seen · admin_jobs · daily_questions (2026-10-09)

**왜**: 글·회원·퀴즈·구독자·기사·커뮤니티는 v1.20~v1.35에서 Postgres로 옮겨졌지만, 2026-10-09 점검(DynamoDB 최근 14일 쓰기 활동 + 호출 코드 추적)에서 DynamoDB에 아직 쓰는 곳 5개가 남아 있었다. 사용자 방침("DynamoDB는 조인·쿼리·관리가 어렵다 — RDB로 다 옮기는 게 맞다")에 따라 남은 보조 데이터를 정식으로 설계해 옮긴다. 설계는 개념→논리→물리→확장성 순서로 `lens-erd-src/16-ddb-잔여-이관-설계.md`에 정리했다.

## 조사 요약

| `sedaily-lens-mustknow-seen-dev` (11,359건, TTL 없음) | ECS `mustknow_auto`(하루 6회). 후보마다 `get_item`/`put_item` | → `candidate_seen` |

## 스키마 변경

`lens-erd-src/lens_schema_v1.36_2026-10-09.sql` — 3개 테이블(멱등, 롤백 SQL 포함).

- `candidate_seen(pipeline, article_key, seen_at, tab, score, reasoning, is_manual, excluded_from_general, reason, detail jsonb, PK(pipeline, article_key))` + `(pipeline, seen_at DESC)`
- `admin_jobs(id, kind, job_id, status CHECK pending/running/done/error, payload, result, error, created_at, updated_at, finished_at, expires_at, UNIQUE(kind, job_id))` + 진행 중 부분 인덱스·`expires_at` 인덱스
- `daily_questions(question_date PK, questions jsonb, question_count, model, generated_at, created_at)`
- GRANT: `lens_service_app`에 테이블·시퀀스 권한(시퀀스 USAGE·SELECT 포함 — v1.24 RETURNING 사고 반영)

## 실행 — 마스터 계정 필요 (사용자 직접 실행)

`lens_service_app`에는 DDL 권한이 없다(v1.33~v1.35와 같은 절차: SSM 릴레이 또는 로컬 psql, 비밀번호는 세션에 노출하지 않는다). SQL 파일 맨 아래에 검증 쿼리와 롤백 SQL이 있다.

## 구현 (코드 완료·미배포, 2026-10-09)

- **lens-cms-api**: `candidate_seen_repo.py`·`admin_jobs_repo.py`·`daily_questions_repo.py` + `main.py` `/internal/candidate-seen{,/exists,/bulk,/count}`·`/internal/admin-jobs[/{kind}/{job_id}]`·`/internal/daily-questions/{date}` + `nginx.conf` location 3개. 단위 테스트 12개(`tests/test_v136_repos.py`, 가짜 커서). nginx.conf 는 `deploy.sh` 에 포함되지 않으므로 서버에 따로 반영한다.
- **호출자(전부 환경변수 스위치, 기본 ddb)**:
  - `pipelines/mustknow_auto/run.py` — `SEEN_BACKEND=pg` 이면 `_PgSeenTable`(DynamoDB Table 의 get_item/put_item 어댑터, 후보 일괄 prefetch)이 `common/lens_cms_client.py` 의 `seen_exists`/`seen_mark` 를 호출.
  - `admin/backend/routes/webtoon/jobs.py`·`routes/prompts.py` — `JOBS_BACKEND=pg` 이면 `repo/admin_jobs_repo.py`(옛 평평한 항목 모양으로 되돌려 호출부 변경 없음).
  - `service/backend/handlers/user/question.py` — `QUESTIONS_BACKEND=pg` 이면 `clients/pg/daily_questions.py`.
- **이관 스크립트**: `pipelines/scripts/ddb_to_pg_v136.py {seen|questions|jobs}` — 드라이런 기본, 백업 JSON, `--apply`. 드라이런으로 질문 89건·job 765건(최근 30일 764건)이 확인됐다.
- 브리핑·챗봇·웹소켓은 이관하지 않고 폐기 대상(별도 확인).

## 적용 순서 (사용자 확인이 필요한 단계 표시)

1. **DDL 실행(마스터 계정, 사용자)** → 검증 쿼리로 `\d+`·권한 확인
2. `service/lens-cms-api/deploy.sh` + 서버 nginx.conf 반영(location 3개) + `nginx -t` 후 reload
3. 이관 스크립트 `seen`·`questions`·`jobs` 를 드라이런 → `--apply`
4. 스위치 전환(`SEEN_BACKEND`·`JOBS_BACKEND`·`QUESTIONS_BACKEND` = pg): ECS 태스크 정의 환경변수, admin-api·question Lambda 환경변수(question Lambda 는 `LENS_CMS_API_TOKEN` 이미 있음)
5. 1주 관찰 → DynamoDB 쓰기 0 확인 → 온디맨드 백업·S3 내보내기 → 테이블 삭제

## 코드 정리 (같은 날)

- `admin/backend/shared/ddb_client.py`: 사용처 없는 accessor(prompts·posts·quiz·subscribers) 제거. 남은 것은 `config_table`(`JOBS_BACKEND=ddb` 복귀 경로)와 `letters_table`.
- 통합 테스트·데모 스크립트의 운영 DynamoDB 테이블 기본값 제거(`TEST-ONLY-set-…` — 환경변수를 주지 않으면 존재하지 않는 테이블이라 실패한다). 2026-10-04 운영 `articles` 테이블에 `test_integ_*` 잔재와 쓰기 7,770 WCU가 남은 사고 방지.
- 발견: 관리자 "레터" 화면(`/admin/letters`, `routes/letters.py`, `repo/letters_repo.py`)은 읽기·쓰기 0건·0 아이템인 `daily-letters` 테이블을 본다 → 폐기 후보(admin 프론트 페이지·라우트 함께, 별도 확인).
- 참고: `admin/backend/tests`는 `conftest.py` 주석대로 운영 audit 테이블에 실제로 쓰므로 로컬에서 함부로 실행하지 않는다(이번엔 수집 단계 오류로 실행되지 않음, `elevenlabs_tts` 모듈 경로 문제는 기존 환경 이슈).
