# v1.35 — 선정 실험실(selection_runs/selection_articles) 테이블 신설 (2026-09-28)

**왜**: mustknow_auto "일반" 카테고리 선정 결과(오늘의 흐름 파악·선정
기사·배제 사유)를 날짜별로 모아 팀원이 적절/애매/부적절로 채점하는
admin 화면("선정 실험실", `/selection-lab`)을 정식 기능으로 승격 —
"팀원이 루틴하게 할거라"는 사용자 요청. 지금까지는 목업 데이터였고,
사용자가 직접 "하드코딩 하는게 아니고 db 랑 연결하면 되는거 아닌가요?
매일 쌓아야하는데.."로 지적해 이번 버전에서 실제 저장으로 전환한다.

## 스키마

`prompt_lab_docs`/`prompt_lab_files`(v1.15 계열)와 동일 원칙 — 실험용
저장 계층이라 `publications`처럼 무겁게 설계하지 않는다. 회차(run) 1개
= 파이프라인 1회 호출(하루에 여러 번 돎, `_GENERAL_DAILY_CAP=20`에
도달할 때까지) — 날짜 화면은 그 날짜의 모든 회차를 합쳐서 보여준다.

```sql
CREATE TABLE selection_runs (
    id                  SERIAL PRIMARY KEY,
    run_date            DATE NOT NULL,
    category            VARCHAR(32) NOT NULL DEFAULT 'general',
    today_context       TEXT,
    candidates_total    INT,
    excluded_count      INT,
    excluded_reasons    JSONB,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX selection_runs_date_category_idx
    ON selection_runs (category, run_date DESC, created_at);

CREATE TABLE selection_articles (
    id          SERIAL PRIMARY KEY,
    run_id      INT NOT NULL REFERENCES selection_runs(id) ON DELETE CASCADE,
    article_key VARCHAR(255) NOT NULL,
    title       TEXT NOT NULL,
    category    VARCHAR(64),
    reason      TEXT,
    verdict     VARCHAR(16),
    note        TEXT,
    scored_by   VARCHAR(64),
    scored_at   TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX selection_articles_run_id_idx ON selection_articles (run_id);
```

`verdict`는 `'ok' | 'unclear' | 'bad' | NULL`(체크 제약 대신 애플리케이션
레벨 검증 — `service/lens-cms-api/selection_repo.py::_VALID_VERDICTS`,
다른 상태값 테이블들과 동일 패턴).

## 실행 — 마스터 계정 필요 (사용자 직접 실행)

`lens_service_app`(앱 DB 역할)엔 DDL 권한이 없다(v1.15/`prompt_lab_repo.py`
docstring과 동일 원칙 — `CREATE TABLE IF NOT EXISTS`도 스키마 CREATE
권한을 먼저 검사해 항상 permission denied). 위 SQL을 마스터 계정으로
직접 실행해야 한다 — v1.33/v1.34와 동일 절차(SSM 릴레이 또는 로컬
psql, 비밀번호는 세션에 노출하지 않고 사용자가 직접 실행).
