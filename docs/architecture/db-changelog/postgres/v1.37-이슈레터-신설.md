# v1.37 — 이슈 레터(모아쓰기 레터) 테이블 7개 신설 (2026-10-09, DDL 적용·API 배포 완료, 프론트·관리자 화면 전)

**왜**: 기사 한 건을 4형식으로 보여주던 기존 구조와 달리, 하나의 이슈를 소식·실체·다른 시각 세 관점으로 읽는 "레터" 탭을 만든다(기획 `docs/product/모아쓰기레터/`). 화면은 목업으로 확정했고, 저장·발행·투표를 받칠 테이블이 필요하다.

## 스키마 변경
`lens-erd-src/lens_schema_v1.37_2026-10-09.sql` — `issue_letters`, `issue_letter_categories`, `issue_letter_sections`, `issue_letter_sources`, `issue_letter_polls`, `issue_letter_poll_options`, `issue_letter_votes`. 설계·API·전환 순서는 `lens-erd-src/17-이슈레터-설계.md`.

## 핵심 제약
- 발행본은 호수·발행 시각·검수자 필수(CHECK)
- 출처는 자사 기사 FK 또는 외부(제목·매체·URL+편집장 승인) 중 하나만
- 투표는 레터당 한 사람 한 표(PK), 식별자는 해시만 저장, 앱 역할은 SELECT/INSERT만

## 검증 (2026-10-09, 로컬 Postgres 16 컨테이너)
- 스텁(editors·categories·articles) 위에서 DDL 적용 → 재적용 오류 없음(멱등)
- 위반 케이스 전부 거부 확인: 호수 없는 발행, 주 분류 2개, 외부 출처 승인 없음, 자사·외부 동시, 잘못된 axes, 없는 선택지 투표, 중복 투표
- 정상 케이스 통과: 발행, 자사 출처, 승인된 외부 출처, 투표 집계

## 실행 기록 (2026-10-09)
- DDL: 사용자가 EC2에서 마스터 계정으로 실행(파이썬 psycopg2, 비밀번호는 getpass). 권한 조회 결과 7개 테이블 모두 기대와 일치(`issue_letter_votes`는 INSERT·SELECT만, `issue_letters`는 DELETE 없음).
- API 코드(미배포): `service/lens-cms-api/issue_letters_repo.py` + `main.py` 라우트 11개(`/api/v2/issue-letters*` 공개 4, `/admin/issue-letters*` 관리 7) + `nginx.conf` location 2개 + `tests/test_issue_letters.py`(21개, 가짜 커서).
- 실제 DB 검증: 로컬 Postgres 16에 DDL을 적용하고 **앱 역할(lens_service_app) 권한으로** create → submit → 자기 승인 거부 → 금융+binary 투표 거부 → 발행(호수 1) → 목록·분류 필터 → 상세 → 투표·중복 → 수정 거부 → 내림 → 후보 검색을 끝까지 실행해 통과. 저장된 투표 식별자는 64자 해시.

## 배포 기록 (2026-10-09 저녁)
1. `service/lens-cms-api/deploy.sh` — 헬스 200
2. 솔트: root PM2 환경에 `VOTE_HASH_SALT`(서버에서 무작위 생성, 출력·저장 안 함) + `pm2 save`. PM2는 root 소유라 사용자 세션에서는 `sudo -i`가 필요
3. nginx: location 2개 추가(백업 `lens-cms-api.conf.bak.v137`, `nginx -t` 후 reload)
4. CloudFront `E1QS7PY350VHF6`: `/api/v2/issue-letters*` 동작 추가(기존 `/api/v2/posts*`와 같은 설정 — CachingDisabled + AllViewer, EC2-lens-cms-api 오리진). `/admin/issue-letters`는 CloudFront에 열지 않음(관리자 Lambda가 서버를 직접 호출)
- 확인: 외부 `https://ailens.sedaily.ai/api/v2/issue-letters` → `{"letters":[]}` 200, 없는 상세 404, 기존 posts·홈 200, 외부 `/admin/issue-letters` 404
- 주의: 인스턴스 메모리 사용률이 92%대라(배포 직후 측정) 레터 데이터가 늘기 전에 확인 필요

## (참고) 배포 때 필요했던 것
1. `VOTE_HASH_SALT` 환경변수(서버 PM2). 비어 있으면 투표가 500으로 거부된다
2. 서버 nginx conf에 location 2개 반영(`/api/v2/issue-letters`, `/admin/issue-letters` — `deploy.sh`는 nginx.conf를 올리지 않는다)
3. CloudFront(`E1QS7PY350VHF6`)에 `/api/v2/issue-letters*` behavior 추가(공개 읽기·투표용, 투표 헤더 `X-Voter-Id` 전달)
4. `service/lens-cms-api/deploy.sh`
5. 관리자 Lambda에서 `/admin/issue-letters*` 프록시 + 로그인한 편집자 정보(`actor.employee_no`, `actor.role`)를 본문에 실어 보내는 코드(관리자 화면 단계)

## 알려진 한계
- 투표 식별자는 클라이언트가 보낸 `X-Voter-Id`를 서버가 해시한다. 익명은 쿠키 id라 지우면 중복 가능(Q6에서 수용한 한계, 투표수가 의미를 가지면 속도 제한 추가).
- 호수 채번은 `LOCK TABLE ... SHARE ROW EXCLUSIVE` 안에서 `MAX+1`. 발행이 드문 쓰기라 허용.
