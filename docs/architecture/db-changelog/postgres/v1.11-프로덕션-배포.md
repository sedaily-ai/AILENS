# v1.11 — 프로덕션 배포 (2026-09-09)

**왜**: v1.10에서 작성한 `CMS_DB_BACKEND` feature-flag 코드를 실제 라이브
Lambda에 배포. 사용자가 직접 `./deploy.sh api`를 실행(Claude Code 자동
모드 분류기가 실제 프로덕션 배포 명령을 반복 차단해, 사전 점검(마지막
배포 시각 확인, 워킹트리 클린 확인)까지만 하고 실제 실행은 사용자에게
넘김).

**배포 전 확인한 것**:
- 대상 Lambda(`sedaily-mbti-v2-posts-dev`) 마지막 배포: 2026-09-07 —
  이번 배포로 덮어써질 더 최신 배포가 없음을 확인.
- `git status`로 워킹트리 클린 확인 — 의도치 않은 변경 섞임 없음.

**결과**: 22개 Lambda 함수 전부 업데이트 성공, 0건 스킵. 배포 직후
헬스체크(`GET /api/v2/posts?channel=letters&limit=1`) 200 확인. 배포
후 실측: `channel=lens` 200(3.82초), `channel=webtoon` 200(1.80초) —
`CMS_DB_BACKEND` 미설정 상태라 여전히 기존 DynamoDB 경로로 서빙 중임을
확인(설계대로 동작 변화 없음).

**지금 상태**: 코드는 라이브에 있지만 `CMS_DB_BACKEND=postgres`는
어디에도 설정하지 않았다 — Postgres 경로는 아직 한 번도 실행된 적
없는 dormant 상태. 이 환경변수를 실제로 켜는 것이 이 이관 프로젝트의
진짜 마지막 스위치이며, 별도의 명시적 결정이 필요하다(v1.10에 적어둔
알려진 한계 — lens 채널 lenses[] 미이관, psycopg2 Lambda 패키징 필요,
DynamoDB 원본과의 데이터 최신성 격차 — 를 먼저 해결해야 안전하게 켤 수
있다).
