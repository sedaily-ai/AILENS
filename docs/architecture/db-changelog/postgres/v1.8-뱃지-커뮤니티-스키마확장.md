# v1.8 — 뱃지·커뮤니티 게시판 스키마 확장 (2026-09-09)

**왜**: 계획 단계(Explore 에이전트 조사)에서 발견한 원본 스키마의 2가지
공백 — 실제로 쓰이는 기능인데 `lens_schema_2026-08-26.sql`에 자리가
없던 뱃지·커뮤니티 게시판을 확정해 스키마에 반영. 원본 파일은 수정하지
않고 `lens-erd-src`와 별개로 이 db-changelog 항목으로만 기록(원본 DDL은
"기준 파일"로 그대로 둔다는 원칙 유지).

**적용한 스키마**:
```sql
ALTER TABLE users ADD COLUMN badges TEXT[] NOT NULL DEFAULT '{}';

CREATE TABLE community_posts (
    id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    user_name VARCHAR(64), user_avatar TEXT,
    archived_sentence TEXT NOT NULL, user_comment TEXT,
    article_no VARCHAR(32) REFERENCES articles(article_no) ON DELETE SET NULL,
    tags TEXT[] NOT NULL DEFAULT '{}',
    upvotes INTEGER NOT NULL DEFAULT 0, comment_count INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE community_comments (
    id BIGSERIAL PRIMARY KEY,
    post_id BIGINT NOT NULL REFERENCES community_posts(id) ON DELETE CASCADE,
    user_id VARCHAR(64) NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    user_name VARCHAR(64), user_avatar TEXT,
    content TEXT NOT NULL, likes INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```
설계 원칙: `user_archives.content`(원본 스키마가 이미 쓰는 "작성 당시
스냅샷을 의도적으로 비정규화" 패턴)를 그대로 따라 `user_name`/`user_avatar`를
매번 `users` 조인 없이 저장. 폐기된 `user_mbti` 필드는 제외.

**데이터 이관 결과**:

| 항목 | 결과 |
|---|---|
| `users.badges` | 3명(11명 중) — `reader_10`/`first_login`/`weekly_5`/`reader_50`/`streak_7` 등 |
| `community_posts` | **0건** |
| `community_comments` | **0건** |

**커뮤니티 게시판 실사용 데이터 0건인 이유**: `sedaily-mbti-engagement-dev`
전체를 스캔한 결과 `pk='COMMUNITY_POSTS'` 게시글은 1건, 댓글은 2건뿐이었고,
그 게시글의 `user_id`는 `"test_user_1"`, `article_id`는 `"test123"`으로
**명백한 테스트 픽스처**였다(직접 열어서 확인 — 추측 아님). 실제 프로덕션
사용자가 이 기능을 쓴 기록이 없다. 그 외 engagement 테이블에 섞여 있던
`ARTICLE#`/`USER#`/`QUIZ#`/`STATS#` 패턴들도 대부분 `test-`/`mock-` 접두가
붙은 테스트 데이터였다.

**결론**: 스키마는 준비됐지만(향후 실사용 대비), 이관할 실데이터가
없었다 — "이관 실패"가 아니라 "원래 실사용 데이터가 없었다"는 사실
확인.
