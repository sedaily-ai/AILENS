# v1.6 — articles 본문 백필 + 이미지·관련기사 이관 (2026-09-08)

**왜**: v1.4에서 `articles`는 메타데이터만 이관하고 본문(`body`)은 S3에
있어 후속 작업으로 남겨뒀다. 이번에 그 후속 작업을 실행.

**한 것 — 시행착오 포함**:

1. `articles.body` 백필 1차 시도: DynamoDB `s3_body_uri` 필드 값으로
   S3에서 `content_ko`를 가져오는 방식으로 18,114건 중 4,232건(23%)만
   성공, 나머지 13,882건은 `NoSuchKey`.
2. 원인 확인: 실패한 항목들은 `s3_body_uri` 필드 자체가 **DynamoDB에
   없었다**(NULL). 해당 아이템을 직접 열어보니 `content_ko`가 DynamoDB
   항목 안에 **직접** 들어있었다 — S3를 안 쓰던 "레거시 모드"로 저장된
   기사들이었다(`dynamodb_client.py` docstring이 언급한 이원화 저장
   방식과 일치).
3. 2차 백필: 나머지 13,882건을 DynamoDB `GetItem`으로 직접 조회해
   `content_ko`를 가져옴 — **13,882건 전부 성공**, 결측 0건.
4. `article_images`(23,733건), `article_related_news`(69,200건) 이관 —
   DynamoDB `images`/`related_news` 리스트 필드를 그대로 분해.

## 결과

| 테이블 | 건수 |
|---|---|
| `articles.body` 채워짐 | 18,114 / 18,114 (100%) |
| `article_images` | 23,733 |
| `article_related_news` | 69,200 |

## 검증

- FK orphan(`article_images`/`article_related_news` → `articles`): **0건**
- 샘플 3건 무작위 대조: article_no/title/본문 길이 정상

## 제외한 것

- `article_categories`: `articles.category` 값(경제/사회/정치/국제/문화/
  스포츠/IT_과학 — 전통 신문 섹션)이 `categories` 테이블에 시드된 AI LENS
  자체 분류(증시/부동산/산업/금융·정책/국제/재테크/문화)와 **다른 체계**임을
  확인. 두 값을 임의로 매핑하면 편집 판단을 제가 대신하는 것이라 보류 —
  실제 매핑표는 에디터 확인 필요. 참고로 `category` 없는 6,482건은
  v1.4에서 이미 제외된 6,482건과 동일한 레코드임을 확인(같은 결측 집합).
