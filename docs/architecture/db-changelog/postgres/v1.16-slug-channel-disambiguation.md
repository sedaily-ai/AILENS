# v1.16 — get_published_post_by_slug의 channel 기반 포맷 disambiguation (2026-09-09)

**왜**: v1.13에서 남긴 두 번째 미해결 항목 — 한 발행물(publications)에
형제 채널 렌디션이 여러 개 있을 수 있는데 `get_published_post_by_slug()`가
포맷 구분 없이 `ORDER BY r.id LIMIT 1`로 아무 렌디션이나 반환하던 문제.
"프론트엔드가 실제로 채널별 slug를 URL에 쓰는지 확인 필요"가 전제조건
이었다.

## 조사: 프론트엔드가 단건 조회마다 항상 ?channel=을 보낸다

`service/frontend/src/app/(content)/`의 `webtoon/[slug]`, `video/[slug]`,
`lens/[slug]`, `letters/[id]` 각각이 `shared/lib/api/cmsPostsApi.ts`의
전용 fetch 함수(`fetchWebtoonBySlug`/`fetchVideoBySlug`/`fetchLensBySlug`/
`fetchCmsPostBySlug`)를 통해 `GET /api/v2/posts/{slug}?channel=X`를
호출한다는 것을 확인. 채널 간 slug를 섞어 쓰는 곳은 없었다(과거
`lensMediaFeed.ts`가 webtoon/video 카드를 lens slug로 연결했다가
"클릭하면 엉뚱한 lens 페이지로 감" 문제로 2026-08-23 삭제된 전례
확인 — cmsPostsApi.ts:78-81, WebtoonPreviewSection.tsx:87-92).

**결론**: 지금 이 문제는 라이브 트래픽에 영향 없음(`CMS_DB_BACKEND`
dormant + DynamoDB는 slug 자체가 아이템별 고유라 원래 disambiguation이
불필요). 다만 `CMS_DB_BACKEND=postgres`를 켜는 순간부터는 프론트가
보내는 `?channel=`을 백엔드가 완전히 무시하고 있어(핸들러가 애초에
읽지도 않음) 잠재 버그였다 — 컷오버 전에 지금 고쳐두는 게 안전.

## 수정

- `cms_posts_pg_client.py::get_published_post_by_slug(slug, channel=None)` —
  channel을 포맷으로 매핑(`_CHANNEL_TO_FORMAT`)해 해당 포맷의 렌디션으로
  필터링. 매칭 렌디션이 없으면(드묾 — v1.12로 전체 publications가 최소
  1개 렌디션 보유) 기존과 동일한 임의 선택으로 폴백 — 실패해도 404가
  아니라 이전 동작 그대로 유지.
- `cms_posts_ddb_client.py::get_published_post_by_slug`에도 동일 시그니처
  `channel=None` 추가(인터페이스 호환, DynamoDB에서는 no-op — slug가
  이미 아이템별 고유라 채널 구분이 원래 불필요).
- `handlers/cms_posts_public.py` — 단건 조회 시 `qs.get("channel")`을
  클라이언트 호출에 실제로 전달하도록 배선.
- **범위 밖**(그대로 유지): 'lens' 채널은 포맷이 아니라 4개 포맷을
  한 응답에 조합해야 하는 별도 UI(FormatPicker)라 이 필터링 대상이
  아님 — v1.12에서 이미 문서화된 "완벽한 구조 재현 아님" 한계 그대로.

## 검증

dev DB against pg8000, 같은 group(웹툰+영상+홈플레이어 3개 렌디션 보유)
기준:
- `channel=None` → 임의 선택(home_player, 기존과 동일 — 회귀 없음)
- `channel='home_player'` → home_player 정확히 반환
- `channel='video'` → video 정확히 반환
- `channel='webtoon'` → webtoon 정확히 반환
- `channel='letters'`(이 그룹엔 letter 렌디션 없음) → 정상적으로 임의
  선택 폴백(크래시 없음)
- publication_slug_history 폴백 슬롱(`...-video`) + `channel='video'` →
  정확히 video 렌디션, 캐노니컬 slug로 응답 — 의도한 조합 정상 동작
- 테스트 스위트: 기존 mock 시그니처(`lambda slug: ...`)가 새 `channel`
  kwarg와 안 맞아 2건 실패 발견 → `tests/test_cms_posts_public.py`의
  fake를 `lambda slug, channel=None: ...`로 수정 후 104 passed(기존
  무관 에러 6건 동일)

## 배포

22개 Lambda 함수 전부 업데이트 성공. 배포 전 확인: 대상 Lambda 마지막
배포 시각이 v1.15와 일치(`2026-09-08T22:55:30Z`) — 그 사이 다른 배포
없음 확인, 워킹트리 클린 확인. 배포 후: LastModified
`2026-09-08T23:10:35Z`로 갱신 확인, 실 API `channel=lens` 200(4.07초),
`channel=webtoon` 200(1.84초) — `CMS_DB_BACKEND` 미설정 상태 그대로라
여전히 기존 DynamoDB 경로로 정상 서빙 중.

## 남은 미해결

- 'lens' 채널의 4-포맷 통합 응답(FormatPicker가 기대하는 구조)은
  여전히 재설계 필요 — v1.12 문서화된 한계, 이번 범위 밖.
- `CMS_DB_BACKEND=postgres`는 여전히 어디에도 설정 안 됨 — Postgres
  경로는 계속 dormant.
