# 2026-09-07 — CMS 목록 조회 channel GSI 이관 (성능 사고와 실제 개선)

**왜**: 발행글이 쌓일수록 모든 목록 조회가 느려지는 구조적 문제 — GSI가
채널 구분 없이 발행글 전체를 읽은 뒤 애플리케이션에서 필터링하고 있었다.

**한 것**: `channel-publish_date-index` 신규 GSI 생성 + 기존 3,551건 백필,
`CMS_LIST_INDEX_MODE` 환경변수로 즉시 롤백 가능한 컷오버.

**비포/애프터 (실측)**:

| 지표 | 이관 전 | 이관 후 | 개선율 |
|---|---|---|---|
| `channel=lens` 응답 | 9.8초 | 6.0~6.2초 | ~40% |
| webtoon 목록 응답 | 8~10초 | 2.9~4.4초 | 60~70% |
| webtoon 페이로드 | 3.2MB | 604KB | ~81% |

**부수 사고**: IAM 정책에 신규 GSI ARN을 빠뜨려 전체 목록 API 500 사고 발생
→ env 스위치 덕에 즉시 롤백. (이게 나중에 "AI로 DB 작업할 때 사람 승인
필요" 원칙의 실증 사례가 됨.)

**이 프로젝트에서 갖는 의미**: 이 시점 실측이
[postgres 트랙 v1.0](../postgres/v1.0-논리물리-설계-확정.md)의 물리 설계가
참조하는 "실제 DynamoDB 접근 패턴"의 원천 데이터다 — 채널+발행일 범위
조회 패턴이 여기서 처음 정량적으로 확인됐다.
