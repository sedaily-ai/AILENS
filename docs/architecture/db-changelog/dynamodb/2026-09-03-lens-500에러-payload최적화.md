# 2026-09-03 — lens 500 에러 + payload 최적화

**문제**: `95fc976`(09-03) lens 채널 `limit=300` 근처에서 500 에러 발생.
근본 원인은 DynamoDB가 아니라 **Lambda 응답 6MB 한도** — 목록 응답이
너무 커서 Lambda 자체가 응답을 못 돌려주는 상황이었다.

**조치**: `shape_lens_summary()` 도입 — 목록 조회 응답에서 항목당 크기를
90% 감소(본문·패널 등 상세 필드 제외, 요약 필드만 반환).

**연관 조치**: `f9f67fb`(09-03) SSG→ISR 재설계로 `webtoon/series/[slug]`
무제한 정적생성 제거 — 배포 타르볼 832MB→320MB.

**이 이력에서 갖는 의미**: DynamoDB 자체 용량 문제가 아니라 "필요 이상으로
큰 응답을 그대로 돌려주는" 애플리케이션 레이어 문제라는 점에서
[2026-09-07 GSI 이관](2026-09-07-channel-gsi-이관.md)과 같은 계열의 원인 —
`docs/architecture/lens-erd-src/13-physical-design.md`의 "목록 API는 무거운
필드를 SELECT에서 제외한 shaper가 기본" 원칙이 이 사고에서 나온 교훈을
Postgres 물리 설계에 그대로 반영한 것이다.
