## 0. AI LENS 개발자가 알아야 할 것

이 레포에서 하는 일이 이 탭 숫자에 그대로 반영된다. 네 가지만 기억하면 된다.

| 이 레포에서 | 탭에 생기는 일 | 할 일 |
|---|---|---|
| 리소스·Bedrock 프로파일에 `Service` 태그를 붙인다 | 붙은 비용만 탭에 들어간다. 베어 모델 ID 호출(미태깅)은 **안 잡힌다** | [`비용태깅_규칙.md`](비용태깅_규칙.md) §3 |
| 새 모델을 쓰기 시작한다(예: Opus 5.5) | 자동으로 `기타 Bedrock`(Z열)에 들어간다. 누락은 없다 | 전용 열이 필요하면 아래 §8 |
| AI LENS에 **새 `Service` 값**을 쓴다 | 정본 코드 `DEFAULT_TAGS`에 없으면 그 비용이 탭에서 **조용히 사라진다** | AI-dashboard `pipeline/push_lens_cost_to_sheets.py`의 `DEFAULT_TAGS`에 추가 요청 |
| **태그를 붙일 수 없는 AWS 서비스**를 쓴다(예: Polly — 요청에 태그 슬롯이 없다) | 미태깅으로만 청구돼 탭에 **안 잡힌다**. 현재 `Amazon Polly`만 서비스명으로 귀속해 `Amazon Polly`칸(AD열)에 넣는다 | 태그를 붙이려 하지 않는다([`비용태깅_규칙.md`](비용태깅_규칙.md) §7). 다른 서비스가 필요하면 정본 코드 `UNTAGGED_TO_LENS`에 서비스명 추가 요청 |

---

AWS 청구 → BillingON → 마스터DB `LENS` 탭으로 AI LENS 주차별 비용이 흘러가는 경로와 각 단계의 규칙을 적은 문서다.
탭의 칸 구성과 일상 운영(수동 실행·장애 대응)은
[`lens-sheet.md`](https://github.com/sedaily-ai/AI-dashboard/blob/main/docs/guides/lens-sheet.md)(AI-dashboard)에 있고,
이 문서는 **파이프라인이 안에서 무엇을 하는지**를 다룬다. 코드를 고치거나 숫자가 왜 그렇게 나왔는지 추적할 때 읽는다.

## 1. 흐름

```text
AWS 리소스·Bedrock application inference profile
  └ 비용할당 태그 user:Service = atlas4 | lens | mbti
        │  AWS 청구 데이터 (적재 T+1~3일)
        ▼
BillingON (이테크 MSP 포털) listCostExplorer
  groupBy=Tag · tagName=user:Service · tagListType=tag · granuality=D
        │  {태그값: {AWS 서비스명: {useDt: USD}}}
        │  태그를 못 붙이는 Amazon Polly 는 태그값 `Not Applicable`(미태깅) 아래로 온다
        ▼
push_lens_cost_to_sheets.py
  ① 주차 결정 ─ ② 인증·조회 ─ ③ 주차 집계 ─ ④ 칸 분류
  ⑤ 시트 구조 검증 ─ ⑥ 변경 계획 ─ ⑦ 비교 출력 / 일괄 기입
        │  입력칸 11개 + 메모 1개 × 주차
        ▼
마스터DB LENS 탭 ── 시트 수식이 소계·총비용·증감·누적을 계산
```

한 번 실행할 때 BillingON 조회는 **한 번**, 시트 쓰기도 **한 번**(일괄 요청)이다.
②~⑥ 중 하나라도 실패하면 아무 칸도 쓰지 않고 종료 코드 1로 끝난다.

| 경로 | 명령 | 대상 주차 | 쓰기 |

## 3. 단계별 동작

### ① 주차 결정 — `parse_weeks()` · `last_completed_week()`

- 주차는 **목~수**. 시트 1주차 = 2026-08-06. 주간 보고서 번호와는 `LENS N주차 = W(N+35)`.
- 인자 형식: `10`(LENS 주차) · `W45`(보고서 주차) · `3-9`(범위) · `3,5,7`(목록).
- 인자가 없으면 **오늘(KST) 기준 마지막으로 끝난 주차와 그 전 주** 두 개를 고른다. 수요일 당일은 그 주가
  아직 진행 중이므로 한 주 더 뒤로 간다. 예: 10/16(금) 실행 → 10주차(10/08~14)와 9주차.
- 1주차 이전을 고르면 오류.

### ② 인증·조회 — `fetch_nested()`

1. `getRsaKey.do` → RSA 공개키 → API 키를 PKCS#1 v1.5로 암호화 → `getToken.do` → JWT
2. `getAuthorities.do` → `customerIdx`·`groupId`·`accountId` (환경변수 `BILLINGON_ACCOUNT_ID`가 없으면 첫 authority)
3. `listCostExplorer.do` 한 번 — 기간은 **첫 대상 주차 시작일 ~ 마지막 대상 주차 종료일**, 일 단위,
   `groupBy=Tag` + `tagListType=tag`(태그값이 최상위, AWS 서비스가 하위)
4. `nested_service_matrix()`로 `{태그값: {서비스: {일자: 금액}}}`로 펼친 뒤 `pick_nested()`로 필요한 것만 남긴다:
   대상 태그(`DEFAULT_TAGS`) 전부, 그리고 미태깅(`Not Applicable`) 줄 중 `UNTAGGED_TO_LENS`에 적힌 서비스(현재
   `Amazon Polly`)뿐이다. 미태깅에는 Kiro 좌석·다른 팀 호출·베어 모델 ID 호출이 섞여 있어 나머지는 여기서 버리고,
   뒤 단계(집계·`--json` 출력)는 그것을 보지 못한다.

HTTP 재시도(3회)·응답 디코딩·`resultCd` 검사는 `billingon_client.py`가 한다. 인증 흐름 상세는 그 파일 머리말.

### ③ 주차 집계 — `week_breakdown()`

- 그 주 7일(`useDt` 기준)의 금액을 **태그를 가리지 않고 서비스별로 합친다.**
  같은 서비스가 `atlas4`와 `lens`에 나뉘어 있어도 한 줄이 된다.
- BillingON `useDt`는 UTC 날짜다. KST 주차와 9시간 어긋나는 것은 COST 탭·금요일 보고와 같은 규약이라
  보정하지 않는다.
- 0원 서비스는 내역에서 뺀다.
- **미태깅 귀속**: `Not Applicable` 아래 서비스 중 이름이 `UNTAGGED_TO_LENS`와 **정확히 같은** 줄(Amazon Polly)의
  그 주 금액을 같은 서비스별 합계에 더한다. 태그 몫과 겹치지 않는 별개 청구 줄이라(한 청구 줄은 하나의 태그값만
  가진다) 이중계상이 아니다. 나중에 Polly 일부가 태그되어 `lens` 아래에도 나타나면 두 몫이 같은 칸에 더해진다.
- 결과: 칸별 금액(`slots`, 소수 둘째 자리 반올림), 총액(`total` = 태그 몫 + 귀속분), 태그별 합(`by_tag`, 태그 몫만),
  미태깅 귀속분(`attributed`, 서비스별), 서비스별 금액(`by_service`), 칸별 소속 서비스(`members`).

### ④ 칸 분류 — `classify()`

위에서부터 처음 맞는 규칙 하나만 적용한다. **모든 서비스가 정확히 한 칸에 들어가므로** 칸 합계 = 태그 합계다.

| 순서 | 규칙 (BillingON 서비스명) | 칸 |
|---|---|---|
| 1 | `Stable Image Ultra`·`Stable Image Core`로 시작 | 웹툰 이미지 (L) |
| 2 | `Claude Opus 5 (`로 시작 | Claude Opus 5 (P) |
| 3 | `Claude Sonnet 4.6`으로 시작 | Claude Sonnet 4.6 (T) |
| 4 | `Claude Sonnet 5 (`로 시작 | Claude Sonnet 5 (X) |
| 5 | 이름에 `Bedrock` 포함 | 기타 Bedrock (Z) |
| 6 | `Amazon Polly` (정확히 일치) | Amazon Polly (AD) |
| 7 | `Amazon Elastic Compute Cloud` / `Amazon Virtual Private Cloud` / `Amazon Relational Database Service` / `Amazon Elastic Container Service` (정확히 일치) | EC2 (AF) / VPC (AG) / RDS (AH) / ECS (AI) |
| 8 | 그 밖의 전부 | 인프라 기타 (AJ) |

`Opus 5 (`·`Sonnet 5 (`처럼 **괄호까지 붙여 비교하는 이유**: `Claude Opus 5.5`·`Claude Sonnet 5.5`가 이미 청구에
나온다. 접두어만 보면 5.5가 5 칸에 섞인다. 5.5는 규칙 5에 걸려 기타 Bedrock으로 간다.

분류는 **서비스 이름만** 본다. 태그 아래에서 왔든 미태깅 귀속분이든 같은 규칙이다 — `UNTAGGED_TO_LENS`에 Polly 아닌
서비스를 더하면 전용 칸이 없는 한 인프라 기타(AJ)로 들어간다.

### ⑤ 시트 구조 검증 — `resolve_columns()` · `find_week_rows()`

시트를 `A1:CF60` 범위로 두 번 읽는다(계산값 `UNFORMATTED_VALUE`, 수식 `FORMULA`).

**열 찾기** — 열 문자를 코드에 적지 않고 헤더로 찾는다. 그래서 열을 삽입해도 깨지지 않는다.
- 2행 그룹명은 병합 셀이라 첫 칸에만 값이 있다. 이름 있는 칸부터 다음 이름 칸 직전까지를 한 그룹으로 본다.
- 그룹명의 괄호 앞부분이 `SLOTS[*].group`과 **정확히 같고**, 3행 하위 이름이 `SLOTS[*].sub`와 정확히 같은 칸을 찾는다.
  예: 그룹 `Claude Sonnet 5 (기사 선정)` + 하위 `COST($)` → X열.
- 슬롯마다 **정확히 한 칸**이어야 한다. 0개나 2개 이상이면 중단한다.

**행 찾기** — B열 라벨 `N주차`가 정확히 하나이고, 그 행 C열 시작일(시트 날짜 일련번호)이 계산한 시작일과
같아야 한다. 행이 밀렸거나 앵커가 바뀌면 중단한다. 22주차(12/31~) 이후는 시트에 행이 없어 중단한다.

### ⑥ 변경 계획 — `plan_updates()`

- 총액이 0인 주차는 **통째로 건너뛴다**(값·메모 모두 그대로).
- 대상 칸 11개를 모두 쓴다. 그 주 0원인 칸도 `0`을 쓴다 — 빈칸은 "모름", 0은 "실청구 0"이라 뜻이 다르다.
  (Polly 증감 AE 같은 증감 열은 수식 칸이라 쓰지 않는다.)
- 대상 칸에 수식(`=`로 시작)이 있으면 중단한다. 입력칸이 아니라는 뜻이다.
- 메모(AM)는 비어 있거나 `[자동]`으로 시작할 때만 쓴다. 사람 메모는 `--overwrite-memo`가 있을 때만 바꾸고,
  없으면 경고만 출력한다.
- 메모 형식: `[자동] BillingON 실청구 Service=atlas4+lens+mbti + 미태깅 Amazon Polly 귀속 · 수집 YYYY-MM-DD HH:MM KST · 확정|잠정(…)`

### ⑦ 비교 출력·기입 — `format_diff()` · `batch_update`

- 주차마다 칸별 `이전값 → 새값 (차이)`, 바뀌는 칸에 `*`, 총비용(E열, 수식) 이전값 → 새 합계(태그 + 미태깅 귀속),
  기타 Bedrock·인프라 기타에 묶인 서비스 이름을 출력한다. 주차 제목 줄에는 태그별 합과 `미태깅 귀속 {서비스: 금액}`이
  나온다. Actions에서는 이 출력이 run Summary에 붙는다.
- `--json 경로`를 주면 ③의 주차별 결과 전체를 저장한다(서비스별 금액 추적용).
- `--apply`면 모든 주차의 변경을 **한 번의 `batch_update`**(`USER_ENTERED`)로 보낸다. 칸 서식(파란 바탕 등)은 유지된다.

## 4. 잠정 → 확정

BillingON은 청구가 며칠 늦게 쌓인다. 그래서 한 주차는 **두 번 기입되고 두 번째 값이 최종**이다.

```text
10주차 (10/08 목 ~ 10/14 수)
  10/16 금 07:40  1차 기입  ─ 마지막 1~2일이 덜 쌓인 상태  → 메모 "잠정"
  10/23 금 07:40  2차 기입  ─ 같은 칸을 덮어씀             → 메모 "확정"
```

판정 함수는 `is_settled()`: **UTC 오늘 ≥ 주 종료일 + 4일**이면 확정(`SETTLE_DAYS=3`).
금요일 실행 시점에 지난주는 종료 후 2일이라 잠정, 그 전 주는 9일이라 확정이 된다.

2026-10-12 백필 때 9주차 Opus 5가 10/09 보고 시점 $198.80에서 $213.11로 늘어 있었다. 늦게 쌓이는 금액이
이 정도 된다는 실측이다.

## 5. 데이터 계약

### 입력 — BillingON 응답(`costDataList`)

```text
[{ dataset: "<계정>__atlas4",                    ← 태그값 (계정 접두는 billingon_client 가 제거)
   dataList: [{useDt: "2026-10-01", costSum: …}],  ← 태그 합계(이 파이프라인은 안 씀)
   subDataList: [{ dataset: "Claude Opus 5 (Amazon Bedrock Edition)",
                   dataList: [{useDt, costSum}] }, …] }, …]
```

태그 없이 청구된 비용은 같은 모양으로 `dataset: "<계정>__Not Applicable"` 아래에 온다.
이 파이프라인은 그 아래 `subDataList` 중 `dataset`이 `Amazon Polly`인 것만 쓴다.

### 출력 — `--json`

```json
{
  "tags": ["atlas4", "lens", "mbti"],
  "collected_at": "2026-10-12T19:15:00+09:00",
  "weeks": [{
    "week": 9, "dashboard_week": 44, "start": "2026-10-01", "end": "2026-10-07",
    "slots": {"image": 306.46, "opus5": 213.11, "sonnet46": 7.46, "sonnet5": 4.49, "bedrock_other": 0.0,
              "polly": 13.13,
              "ec2": 13.89, "vpc": 11.92, "rds": 12.37, "ecs": 5.63, "infra_other": 7.34},
    "total": 595.8,
    "by_tag": {"atlas4": 581.69, "lens": 0.58, "mbti": 0.4},
    "attributed": {"Amazon Polly": 13.13},
    "by_service": {"Stable Image Ultra (Amazon Bedrock Edition)": 306.46, "…": 0},
    "members": {"image": ["Stable Image Ultra (Amazon Bedrock Edition)"], "…": []}
  }]
}
```

형태 예시다. `polly`·`attributed` 값은 2026-10-16 BillingON 실값(W44)이고, 나머지는 2026-10-12 실행 결과다.
`total` = `by_tag` 합 + `attributed` 합.

### 시트 — 반드시 있어야 하는 것

| 위치 | 값 |
|---|---|
| 2행 그룹명(괄호 앞) | `합계` · `웹툰 이미지` · `Claude Opus 5` · `Claude Sonnet 4.6` · `Claude Sonnet 5` · `기타 Bedrock` · `Amazon Polly` · `인프라` · `비고` |
| 3행 하위 이름 | 각 그룹 안에 `COST($)` 하나, `인프라` 아래 `EC2`·`VPC`·`RDS`·`ECS`·`기타`, `비고` 아래 `메모`, `합계` 아래 `총비용 COST($)` |
| E열 수식 | `Bedrock 소계 + Amazon Polly + 인프라 소계`를 더한다 (코드는 수식을 읽지 않는다 — 어긋나면 `--diff`의 총비용 줄에서 보인다) |
| B열 | `1주차` ~ `21주차` 라벨이 하나씩 |
| C열 | 각 주차 시작일 (C5 = 2026-08-06, 이후 +7일) |
| 입력칸 | 수식이 없을 것 |

이 중 하나가 바뀌면 파이프라인은 쓰지 않고 멈춘다. 의도한 변경이면 코드 `SLOTS`를 맞춘다.

## 6. 불변식과 그것을 지키는 테스트

| 불변식 | 테스트 |

**멱등성** — 같은 BillingON 응답이면 몇 번을 돌려도 같은 칸에 같은 값이 들어간다(덮어쓰기). 메모의 수집 시각만 바뀐다.

## 7. 다른 파이프라인과의 관계

| 워크플로 | 시각(금, KST) | 쓰는 곳 | 관계 |
|---|---|---|---|
| `weekly-billingon.yml` | 06:47 | 마스터DB NOVA·COST 탭, 주간 비용 보고서 | 같은 주차 규약(목~수, UTC 일자). 서로 의존하지 않는다 |
| `weekly-atlas-kpi.yml` | 07:20 | `data/weekly/W{N}.atlas.json` | 무관 |
| `lens-sheet-weekly.yml` | 07:40 | 마스터DB LENS 탭 | 이 문서 |

**주간 비용 보고서와 이 탭의 금액이 다를 수 있다.** 이유는 세 가지다.
1. 보고서(`canonical_cost.py`)는 청구 태그마다 줄을 따로 둔다 — `atlas4`는 "Atlas-4 (AI LENS 전체)",
   `lens`는 "AI LENS", `mbti`는 "MBTI". 이 탭은 셋을 합친 값이다. 보고서에서 비교하려면 세 줄을 더한다.
2. 보고서는 금요일 아침 1회 값으로 고정되고, 이 탭은 다음 주에 확정치로 다시 쓴다.
3. 이 탭의 총비용은 **미태깅 Polly를 포함**한다. 보고서는 태그 비용만 세므로 그 주 Polly(AD열)만큼 이 탭이 크다.
   보고서와 맞춰 볼 때는 `E − AD`를 비교한다.

## 8. 확장하기

**새 모델에 전용 칸을 줄 때** (예: Claude Opus 5.5)
1. 시트에 그룹(2행)·하위 `COST($)`(3행) 열을 추가하고, 증감·소계(`AB`)·누적(26행) 수식에 그 열을 넣는다
2. 코드 `SLOTS`에 `Slot("opus55", "Claude Opus 5.5", "COST($)", "Claude Opus 5.5")` 추가
3. `classify()`에서 **`Bedrock` 포함 규칙(5번)보다 위에** 규칙 추가
4. `test_classify`에 케이스 추가, `GROUP_ROW`·`SUB_ROW` 테스트 헤더에도 열 추가
5. `--diff`로 확인 후 머지

**새 `Service` 값을 AI LENS에 쓰기 시작할 때** — `DEFAULT_TAGS`에 추가하고
`test_default_tags_cover_every_lens_tag_era`를 갱신한다. 빠뜨리면 그 값의 비용이 탭에서 조용히 사라진다.

**태그를 붙일 수 없는 서비스를 LENS가 쓰기 시작할 때** (예: Polly처럼 요청에 태그 슬롯이 없는 서비스)
1. 그 서비스가 BillingON에서 실제로 `Not Applicable` 아래에 오는지, 정확한 서비스명이 무엇인지 본다 —
   `data/weekly/W{N}.json`의 `cost_matrix["Not Applicable"]`. (이 스크립트는 귀속 대상만 남기므로 출력에는 새 후보가 안 보인다)
2. 같은 계정의 다른 서비스(ENG·NOVA 등)도 쓰는지 CloudTrail로 확인한다. 쓴다면 귀속은 상한이다 — 시트 안내(`lens-sheet.md` §2)에 적는다
3. 코드 `UNTAGGED_TO_LENS`에 **서비스명을 정확히** 추가한다. 전용 칸이 없으면 `인프라 기타`로 들어간다. 전용 칸이 필요하면 위
   "새 모델에 전용 칸" 절차를 따른다
4. `test_untagged_attribution_list_is_polly_only`와 `lens-sheet.md` §2를 함께 고친다 — 이 목록은 비용 정의다

**시트 구조를 바꾸는 변경은 시트를 먼저, 코드를 나중에** — 코드는 헤더로 칸을 찾고 못 찾으면 아무것도 쓰지 않고 멈춘다.
새 칸을 요구하는 코드가 먼저 배포되면 다음 금요일 실행이 헤더 오류로 실패한다(텔레그램 알림). 시트만 먼저 바뀌는 것은
안전하다(옛 코드는 새 칸을 모르고 무시한다).

**21주차(12/30) 이후** — 시트에 행을 추가하고 기존 행 수식을 복사한 뒤 26행 누적 합계 범위를 늘린다.
코드 수정은 필요 없다(`find_week_rows`가 라벨로 찾는다). 읽기 범위 `A1:CF60`을 넘으면 `last_row`도 늘린다.

**BillingON에 없는 칸(호출 수·발행 건수·트래픽)** — 이 스크립트에 넣지 말고 원천별 수집기를 따로 둔다.
원천 하나가 실패해도 비용 기입은 계속돼야 하기 때문이다(ATLAS 탭이 같은 방식).
