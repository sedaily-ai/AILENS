## 배경

PRISM 자동 제작 영상이 바로 공개되는 구조라, 숫자·날짜 오류가 사람 확인 없이 유튜브·데일리모션에
나간다(이전 worklog 2026-11-05 PRISM 매일 자동제작의 "다음" 항목으로 남아 있던 품질 이슈).
최근 자동제작 29편(10/27~11/5)을 받아 각본과 원문을 대조해 실제 오류를 먼저 찾았다. 결과:

- **단위/배율 오역이 실재**했다. 10/28 SK하이닉스 공매도 원문 `1조 5234억 원`이 대본에서 `4.2 billion won`으로,
  11/3 부동산 평당가 원문 `1590만 원`이 `15 million won`으로 왜곡됐다(29편 중 2건).
- 날짜는 생각보다 안전했다 — 방송 날짜·요일은 prism_batch가 `[RECORDING DATE]`·`[WEEKDAY]`를 코드로
  계산해 넣어 정확했다. 다만 대본 본문의 상대 날짜(`yesterday` 등)는 검수가 전혀 없었다.
- 기존 `style_issues`의 숫자 대조는 콤마·한글 단위(만/억/조)를 못 읽어 `7만 7451`·`2159억` 같은 정상값도
  원문에서 못 찾아 노이즈만 냈다.

## 한 것

- `generate_script.py` **`date_issues()`** 신설 — [오류] 녹화일/달력과 어긋나는 방송 날짜·요일,
  [확인] 원문에 근거 없는 절대 날짜·특정 과거 상대 날짜(`yesterday`/`last month` 등). `this year` 같은
  현재 시점은 노이즈라 제외.
- `generate_script.py` **`number_issues()`** 신설 — 원문 한글 금액(조/억/만)을 원 단위로 환산해
  대본의 `N trillion/billion/million won`과 ±5% 대조. 미매칭 시 가장 가까운 원문 금액·배율을 **힌트로만**
  붙여 [확인] 플래그.
- `prism_batch.py` — 렌더 직전 두 검수를 돌려 상태(`date_flags`/`number_flags`)·로그에 기록.
- `prism_notify.py` — 슬랙 완료 알림에 편별 `🔎검수 N건` 뱃지 + 하단 상세 블록 추가.
- `test_date_issues.py` — 단위 테스트 15개(정상 변환 통과·실제 오역 포착·오탐 방지), 전부 통과.
- PR #218 생성 → main의 PR #217(`demote_incomplete_stats`)과 prism_batch.py import 충돌 → 두 기능 합쳐 해결 → 머지.
- 영상 서버 배포(현지님 실행) — `sedaily-lens-frontpage-auto` ECR 이미지 재빌드. 11/7 09:00 자동제작부터 적용.

## 결정

- **렌더를 막지 않고 "확인 요청"으로만 남긴다.** PRISM은 바로 공개라, 확실한 오류도 슬랙·로그로 사람이 보게
  하고 영상 자체는 나간다. 없는 사실을 지어내 재요청하지 않는다는 `validate_script` 철학과 동일.
- **배율(10/100/1000배)은 자동 판정하지 않고 힌트로만 쓴다.** 각본 금액이 원문의 어느 항목과 대응하는지
  코드가 알 수 없어(기사에 금액이 여럿) 틀린 매칭으로 재요청하면 값을 오히려 망칠 수 있다. "확인"으로만.
- 샘플을 먼저 뜯어 실제 오류를 확인한 뒤 규칙을 짰다 — 추측으로 짜면 안 나는 패턴을 방어하게 된다.
