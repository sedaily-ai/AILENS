# 2026-11-26 PRISM·지면 영상 유튜브 썸네일 자동 생성

작성: Claude Code
관련: 브랜치 `feat/prism-thumbnail`, 작업 정의 `sedaily-lens-video-lab:34`(이미지 `video-lab-thumb-20261126b`), `pipelines/video/prism_thumbnail.py`

## 배경

PRISM·지면 자동 영상의 유튜브 썸네일이 영상 첫 장면(글자만 있는 검은 화면)으로 나가고 있었다. 마케팅 쪽 요청으로, 기사 사진 위에 큰 문구(예: "KOSPI / 10,000?", "K-HIKING")를 얹은 썸네일을 영상마다 자동으로 만들어 가로 영상·쇼츠 모두에 지정한다.

## 한 것

- `prism_thumbnail.py` 새 파일
  - 후보 사진: 입력 txt의 기사 번호 → daily-xml(녹화일~3일 전)에서 기사에 붙은 사진 **전부**(기사당 0~7장, 최대 14장).
  - AI(`prism_scene` 프로파일, Haiku 5.5)가 후보 사진을 **직접 보고** 사진 1장 + 문구(kicker·headline·tag)를 고른다.
  - 코드 검사: 문구 숫자는 대본에 **숫자 하나 전체로** 있어야(반올림·일부 일치 금지), 숫자를 영어 단어로 쓰면 안 됨, 태그·사진 속 인물 이름은 대본에 있어야. 어긋나면 이유를 붙여 2번까지 다시 요청, 그래도 안 되면 만들지 않음.
  - 그리기(Pillow, Anton 글꼴): Rekognition으로 얼굴·사람·물체 상자를 찾고, 글자 덩어리를 117자리 × 크기 5단계 × 사진 배치 5가지로 시험해 가장 덜 가리는 곳에 놓는다. 어두운 바탕은 글자 주변에만, 얼굴 자리는 빼고 깐다.
  - 쇼츠 탭은 세로 썸네일 위아래를 약 8%씩 잘라 보여 준다(화면 260×388 실측) → 세로판은 위아래 11% 띠 밖에만 글자.
  - 같은 날 사진·문구 겹침 방지: `media/prism-thumb/<YYYYMMDD>/<job_id>.json`(사진 모양 지문·문구). 영상 서버 역할에 `s3:ListBucket`이 없어 그날 목록 `media/prism-auto/<YYYYMMDD>.json`의 job_id로 하나씩 읽는다.
- `prism_batch.py`: 가로 영상 업로드 직후 썸네일을 만들어 가로에 지정, 쇼츠 업로드 직후 세로판 지정. 모듈 불러오기·만들기·지정 어느 것이 실패해도 영상 공개·편 완료에는 영향 없음(상태 파일에 `thumbnail`/`thumbnail_error`/`shorts_thumbnail` 기록).
- `youtube_upload.py`: `set_thumbnail()`(thumbnails.set). 기존 `youtube.upload` 권한으로 가로·쇼츠 모두 된다(11/25 실측).
- `public/fonts/Anton-Regular.ttf`(SIL OFL, `Anton-OFL.txt` 동봉).
- 11/24 영상 12편(가로+쇼츠 24개)에 손으로 먼저 적용해 모양을 확인했다.
- 배포: Docker 없이 ECR API로 `video-lab-paper-20261119` 위에 층 하나를 얹어 `video-lab-thumb-20261126b` → 작업 정의 34(11/26 09:14 KST). 30·32는 서버 안 시험용, 31·33은 29와 같은 내용(시험 중 운영 유지용).

## 결정

- 타사(연합·AP 등) 사진도 쓴다(요청자 결정).
- 얼굴 찾기가 실패하면 썸네일을 만들지 않는다 — 글자가 얼굴을 가릴 수 있어서.
- 인물 사진은 대본에 나오는 그 사람일 때만 — 다른 기사 인물 얼굴 옆에 상관없는 문구가 붙는 사고(시험 중 실제 발생)를 막으려고.
- AI가 사진 설명만 보고 고르게 했더니 눈 감은 사진·그래프를 골라서, 사진을 직접 보여 주는 방식으로 바꿨다(편당 몇 원 수준).
