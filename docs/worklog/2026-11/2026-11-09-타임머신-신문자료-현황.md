# 타임머신 신문 자료 현황

## 배경
생일 선택 전에 1면 사진과 기사 제공 여부를 확인하고, 자료가 쌓일 때 날짜별 현황과 연도별 집계를 갱신한다.

## 한 것
- 생일 입력 화면의 날짜별 상태 미리보기와 결과 화면의 사진·기사 상태를 구현했다. API 오류와 미확인을 자료 없음으로 확정하지 않는다.
- 사진과 기사 현황을 병렬 조회하고 사진이 먼저 확인되면 선택일 기준임을 명시해 먼저 표시한다. 날짜 선택이 400ms 안정된 뒤 자료를 조회하고, 사진이 있으면 결과 화면에 들어가기 전 이미지 원본을 브라우저 캐시에 미리 받는다. 대체 날짜 안내에는 두 줄 높이를 미리 확보해 문구가 생겨도 패널이 늘어나지 않게 했다. 미리보기와 결과 상태를 사진·기사 아이콘과 구분선, 상태별 색상으로 정리했다. 자료가 없는 경우와 조회 실패의 문구를 구분한다.
- ‘전체 보기’ 대화상자에서 연도별 사진·1면 기사 목록 개수와 비율을 확인할 수 있게 했다. 미확인은 자료 없음과 분리하고, 10년 단위로 접고 펼치게 했다. 이 화면 변경은 로컬에만 반영했으며 배포하지 않았다.
- 공유 카드 사진 로딩이 실패한 경우에만 기사 제목으로 카드를 만들었다는 안내를 추가했다. 지연·실패·성공을 로컬 브라우저에서 확인했다.
- 이미지 목록과 네이버 연도 자료로 날짜별 현황을 만들고 연도별 집계를 생성했다. 빅카인즈 1면은 전수 확인하지 않아 미확인으로 둔다.
- 기존 AWS Lambda와 권한을 갱신하고 1960~2026년 현황 67개와 집계 파일의 공개 조회를 확인했다. 네이버 수집은 꺼진 채다.
- 이미지 수집 규칙을 KST 13:10·14:10·15:10으로 바꾸고, 이미 당일 이미지와 e-Paper 기록이 있으면 외부 요청을 생략한다. 기존 누락 감시는 매시간 유지한다.
- 매일 13:25 전체 연도를 대조해 과거 S3 추가분도 다음 갱신에 반영하고, 14:25·15:25에는 올해 현황을 재확인하도록 갱신해 Lambda에 배포했다. EventBridge가 활성 상태이고 매시간 25분 실행하며, Lambda 상태와 `Service=lens` 태그를 확인했다. 동일한 현황 파일은 다시 쓰지 않는다. 새 전체 대조의 첫 정기 실행은 다음 13:25에 확인해야 한다.
- 이미지 사전 캐시를 포함한 프론트엔드 ECS 롤링 배포를 마쳤고 운영 스모크 30건이 통과했다. CloudFront 무효화를 요청했다. 로컬에서 ALB 직접 접속은 000이었으나 공개 사이트 스모크는 정상 응답했다.

## 결정
- e-Paper 기록과 화면용 1면 기사 제공은 별도로 판정한다. 미확인은 없음으로 간주하지 않는다.
- 연도별 현황과 집계의 캐시 시간은 10분이다. 과거 수동 업로드는 다음 전체 대조 또는 연도 지정 재처리에 반영한다.

## 다음
- 최초 정기 실행 및 실패 알림의 실제 동작을 운영 로그에서 확인한다. 발행되지 않은 명절은 누락 알림이 울릴 수 있다.

## 추가 작업: 날짜별 현황과 캐시 사전 정리
- 로컬에서 v2 현황을 추가해 S3 사진·e-Paper 기록, 기존 네이버 목록, 기존 빅카인즈 1면 달력과 비공개 조회 캐시를 출처별로 구분하도록 했다. e-Paper 기록만으로 1면 기사 보유를 추정하지 않는다.
- 기존 DynamoDB 캐시는 API를 다시 부르지 않고 시간당 최대 50일씩 읽어 현황에 반영하는 경로를 추가했다. 빅카인즈 백필은 시간당 최대 2일이며 오류 시 중지한다. 두 기능은 각각 환경 변수로 활성화하며 현재 운영 반영 여부는 별도로 확인해야 한다.
- 다이얼 사진 상태를 400ms 지연 없이 표시하고, 새 현황에 이미 있는 기사 상태를 먼저 보여준다. 최근 30일의 오래된 조회 캐시는 6시간 이후 재조회한다.
- 빅카인즈 API 한도·계약은 아직 확인하지 못했다. 사용자에게 문의했으나 모른다는 답변을 받았다. 대량 자동 조회를 켜기 전에 조건 확인과 소량 검증이 필요하다.

## 운영 반영 및 확인 (21:26 KST)
- 기사 조회 Lambda에 최근 30일 캐시 6시간 재확인 코드를 배포했고, 코드 해시와 1996-06-01 기존 캐시 응답(200, `cached=true`)을 확인했다.
- 일일 현황 Lambda에 v2 현황 및 DynamoDB 기존 캐시 순환 색인을 배포했다. 역할에는 새 inline 정책 `TimemachineAvailabilityV2`를 추가했고 기사 캐시 키만 BatchGet 가능함을 IAM 시뮬레이션으로 확인했다. 1960~2026년 v2 파일 67개 생성과 공개 조회를 확인했다.
- `BIGKINDS_CACHE_TABLE`을 설정해 기존 캐시를 매시간 최대 600일씩 색인한다. 수동 색인 후 21:25 정기 실행으로 진행일이 1991-10-13에서 1993-06-04로 바뀌는 것을 확인했다. 전체 범위 끝에서는 처음으로 순환한다.
- 프런트 ECS 롤링 배포와 30개 주소 스모크가 통과했다. 운영 화면에서 1996-06-01 사진·1면 기사 상태가 모두 표시되는 것을 확인했다. 직접 ALB 접근은 000이나 공개 주소 스모크는 성공했다.
- BigKinds 실제 1990-01-02 소량 조회는 약 20초 후 502였고 운영 로그에서 `tools.kinds.or.kr` 뉴스 검색 읽기 시간 초과를 확인했다. 루트 URL은 200이었다. API 호출 한도도 미확인이므로 `BIGKINDS_BACKFILL_TARGET`은 설정하지 않았고 신규 기사 백필은 실행되지 않는다. 네이버 자동 수집도 꺼진 상태다.
- 검증: 수집기 unittest 106개, 기사 조회 pytest 57개, 프런트 vitest 39개, 관련 ESLint·TypeScript 통과. 로컬 Next 빌드는 성공했지만 빌드 환경 DNS 제한으로 외부 뉴스 API 연결은 실패했다. 운영 Docker 빌드·스모크는 성공했다.
