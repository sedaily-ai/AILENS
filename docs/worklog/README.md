# worklog — 작업 기록

날짜·주제가 있는 모든 작업 기록을 모아두는 곳. 진행 중인 세션 기록,
완료된 구현 계획(plan), 기능 설계 스펙(design)을 전부 여기 하나에 둔다
(2026-08-22 이전엔 `history/`·`superpowers/`로 나뉘어 있었으나 실익 없이
헷갈리기만 해서 통합했다 — 경위: `2026-08/2026-08-22-docs-reorganization.md`).

## 규칙

- 경로: `YYYY-MM/YYYY-MM-DD-주제.md`
- 계획 문서는 `-plan`, 설계 스펙은 `-design` 접미사(둘 다 없으면 일반 작업기록)
- 같은 날 같은 주제를 이어서 하면 새 파일 대신 기존 파일에 덧붙인다
- 새 파일은 `_TEMPLATE.md`를 복사해서 시작 — 형식보다 내용, 배경/한 것/결정/다음 4섹션만 지키면 됨
- **여기 있는 글은 그 시점의 기록이라 나중에 틀린 내용이 될 수 있다 — 정상이다.**
  worklog는 "지금 맞는 말"을 담는 곳이 아니라 "그때 무슨 일이 있었는지"를
  담는 곳. 현재 진실은 `architecture/`·`product/`가 담당.
- 완전히 폐기된 기능·아키텍처를 다루는 오래된 기록은 지우지 않는다 — 그건
  `archive/` 대상이 아니라 그냥 worklog로 남는다(무슨 일이 있었는지 기록은
  계속 유효하므로).

## 이 파일만 읽고 옛날 기록 찾는 법

파일명이 전부 `YYYY-MM-DD-주제`라 `ls YYYY-MM/ | grep 주제` 또는
저장소 전체에서 `grep -rl 키워드 docs/worklog/`로 찾는 게 제일 빠르다.
