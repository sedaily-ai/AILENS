# 2026-10-21 Bedrock 웹툰 이미지 모델 계정 조회

## 배경

사용자가 회사 AWS `default` 계정에 직접 접근하여 웹툰 인물 일관성을 개선할 후보를 조사하도록 요청했다. Bedrock만 사용하며 외부 직접 API는 후보에서 제외한다.

## 한 것

- AWS CLI `default` 프로파일의 STS 조회로 저장소 기준 계정과 일치함을 확인했다. 기본 리전은 us-east-1이며 이미지 모델은 us-west-2도 조회했다.
- `list-foundation-models` 결과: us-west-2의 SD 3.5 Large는 ACTIVE, 입력 TEXT/IMAGE다. Ultra와 Core는 ACTIVE, 입력 TEXT다.
- `list-inference-profiles --type-equals APPLICATION` 결과: 기존 웹툰 Core, SD 3.5 Large, Ultra, Style Guide, Style Transfer, Remove Background 프로파일이 ACTIVE다. ACTIVE는 실제 생성 성공을 의미하지 않는다.
- `get-foundation-model-availability` 결과: SD 3.5 Large, Style Guide, Style Transfer(us-west-2), Control Structure, Inpaint, Conservative Upscale, Nova Canvas(us-east-1)의 authorizationStatus=AUTHORIZED, agreement/entitlement/region availability=AVAILABLE을 확인했다. 운영 Lambda 역할의 호출 권한과 실제 출력 품질은 별도 검증 대상이다.
- `list-tags-for-resource` 결과: SD 3.5 Large, Style Guide, Style Transfer의 기존 웹툰 프로파일은 아직 Service=atlas4다. 현재 비용 규칙에 따라 실제 시험 전 Service=lens로 정정하고 재조회해야 한다. 이번 조회에서는 변경하지 않았다.
- 현재 `pipelines/common/webtoon_image.py::generate_bedrock_sd35_image_bytes`는 mode=text-to-image만 전달하고 image/strength를 받지 않는다. 공식 문서의 image-to-image 기능은 아직 CMS 호출 경로에 연결되지 않았다.
- Nova Canvas는 코드상 512x512 텍스트 생성 경로다. 과거 Legacy/해상도 오류에 관한 주석이 있지만 이번 availability 응답은 AVAILABLE이다. 과거 주석으로 현재 이용 불가나 해상도 제한을 확정하지 않는다.
- Style Guide와 GPU 합성 경로는 `admin/backend/routes/webtoon/generate.py` 주석상 2026-09-25 사용자 결정으로 제거됐다. 프로파일이 남아 있다는 이유로 운영 기능을 자동 복구하지 않는다.
- 유료 이미지 추론, 모델 구독, 프로파일 변경, 운영 코드 수정 및 배포는 수행하지 않았다.

## 결정

- 첫 시험 후보는 기존 프로파일과 CMS 선택지가 있는 Bedrock SD 3.5 Large의 image-to-image다. 현재 참조 이미지를 사용해 얼굴 유지와 포즈 변경 사이의 균형을 확인한다. 품질 우위는 미확정이다.
- Style Guide/Transfer는 화풍 보조 후보이며 얼굴 정체성 고정 기능으로 취급하지 않는다. Control Structure는 구조 제어이며 독립적인 얼굴 고정 기능이 아니다.
- Inpaint는 국소 수정, Conservative Upscale은 채택된 컷의 확대 품질 보조 후보로 둔다. 얼굴이 달라진 결과를 업스케일로 해결하려 하지 않는다.
- Ultra의 기존 생성물은 비교 기준으로 보존한다. GPT Image 직접 API는 사용하지 않는다.

## 다음

- 기존 기준 이미지와 정면/측면/배경 변화 조건으로 소량 시험한다. 얼굴 유지와 자세 변화를 별개로 평가하고 원본 해상도·시간·재시도 포함 비용을 기록한다.
- 품질이 통과한 뒤 CMS 참조 이미지 전달 기능의 수정 범위를 확정한다.

## 후속 실행 — 승인된 SD 3.5 Large 참조 이미지 시험

사용자의 "진행하세요"에 따라 실제 Bedrock API 시험을 수행했다.

### 실행 및 검증

- `image_sd35_large` 정본 프로파일의 Service 태그만 atlas4에서 lens로 정정했다. CLI 변경 성공 후 재조회했고, 각 생성 직전 ACTIVE·기반 모델·Service=lens를 확인했다. Style Guide/Transfer 프로파일은 이번에 사용하지 않아 변경하지 않았다.
- 기존 `local/persona/webtoon-reference-3cut-20261021/master.png`를 모든 요청에 독립적으로 전달했다. 원본은 1536×1024이며 이전 내장 이미지 도구 생성물이다. 정확한 원본 모델은 알 수 없다. 이번 신규 생성은 모두 Bedrock SD 3.5 Large다.
- `output/imagegen/webtoon-sd35-reference-20261021/run.py`는 제품에 연결하지 않은 시험 스크립트다. 정본 `profile_arn('image_sd35_large')`를 사용하며, 한 작업당 추론 1회·자동 재시도 없음·시작 기록으로 중복 방지를 적용했다.
- 정면/측면/야외 3컷: strength=0.60, seed=20261021, 같은 원본. 구도 미반영을 확인하고 측면의 strength만 0.85로 바꾼 비교 1회를 추가했다.
- 4회 모두 정상 응답, 각 1장 반환, 원본 출력 1254×836. 반환 이미지 해시·크기를 검증했다. 측면 비교는 요청의 strength 이외 모든 필드가 동일함을 검사했다.
- 각 CLI 추론 시간: 정면 16.155초, 측면 10.809초, 야외 10.438초, 측면 추가 24.047초. 기본 3컷 37.402초, 추가 포함 61.449초. 시간은 CLI 시작부터 응답 저장까지이며 사전 조회·검수 시간은 제외한다.
- AWS 공식 가격 페이지의 SD 3.5 Large 가격 키를 공식 공개 가격 JSON의 Oregon 요율과 연결해 장당 USD 0.08을 확인했다. 3장 USD 0.24, 추가 포함 USD 0.32의 공시 단가 추정이다. 실청구 확정 아님. `price-evidence.json`에 매핑·게시 시점·요율을 저장했다.
- 모든 생성 결과, 기준 이미지, 기존 Ultra 결과 비교, 실제 프롬프트, 원본 100%/200% 확대 및 얼굴 픽셀 비교를 `review.html`에 저장했다. HTML의 로컬 링크도 존재 여부를 검사했다.

### 시각 검수 및 결정

- strength 0.60: 세 출력끼리는 얼굴과 복장이 비교적 비슷하고 야외 배경도 반영된다. 그러나 원본보다 눈이 커지고 턱이 좁아졌으며 귀걸이·목걸이·금색 단추가 추가된다. 측면/3분의4 구도 지시는 반영되지 않고 원본의 정면·손 자세가 반복된다. 측면 요청 결과에는 배경 가짜 글자도 생겼다.
- strength 0.85: 자세가 바뀌지만 완전한 측면은 아니며, 얼굴·머리 길이·옷·선화가 달라졌다. 두 강도 모두 인물 동일성과 자유로운 구도 변경을 함께 통과하지 못했다.
- 200% 확대는 표시 확대이며 새로운 디테일이 생기지 않는다. 약 1MP 원본을 확대해도 깨지지 않는 고해상도 결과로 보고하지 않는다.
- **CMS 적용 보류**. 얼굴 유지/포즈 변화가 미달이므로 Style Transfer나 업스케일을 추가 호출해 비용을 늘리지 않았다. 이번 결과로 SD 3.5가 항상 실패한다거나 Ultra보다 보편적으로 우수/열등하다고 일반화하지 않는다(한 seed·한 참조·소수 사례).
- 운영 프롬프트 버전·활성 상태·제품 코드·배포는 변경하지 않았다. 기존 Ultra 결과와는 입력 방식과 프롬프트도 달라 모델만의 통제 비교가 아니다.
- 다음 후보는 원하는 구도를 먼저 확보한 뒤 필요한 부위를 편집하는 Bedrock 작업 흐름이다. 얼굴 동일성 보존은 별도로 검증해야 하며 현재 성공이 확인된 대안은 없다.

## 후속 개선 — Bedrock 부분 편집과 확대 시험

### 배경

사용자의 "개선 진행해" 요청에 따라 얼굴 보존과 포즈·표정 변경을 함께 확인했다. Inpaint에는 별도 얼굴 참조 입력이 없으므로 기존 기준 컷의 머리를 보호하고 편집 마스크 안을 변경하는 소량 시험으로 한정했다.

### 한 것

- `lens-webtoon-image-inpaint`, `lens-webtoon-image-conservative-upscale` application inference profile을 us-west-2에 생성했다. 생성 시 Service=lens 및 공통 태그를 지정하고 매 호출 직전 ACTIVE·기반 모델·태그를 재조회했다. IAM 정책은 변경하지 않았다. 실제 ARN과 태그는 각 `*.started.json`에 보존했다.
- 모델 ARN 사본을 실행 코드에 하드코딩하지 않고 프로파일 이름으로 조회한 뒤 정본 `profile_arn()`의 임시 환경변수 별칭을 사용했다.
- `output/imagegen/webtoon-bedrock-inpaint-20261021/trial.py`로 Inpaint 4회 실행: 넓은 몸 편집, 야외 변경, 좁은 팔 편집, 입 모양 편집. 각각 36.343 / 23.106 / 25.711 / 31.234초, 모두 1536×1024 1장 반환. 총 116.394초.
- 넓은 몸 마스크는 의상 변경과 동작 미반영으로 제외했다. 팔 마스크를 좁히고 프롬프트를 짧게 바꾸자 화면을 가리키는 동작이 반영됐다. 다만 요청한 태블릿과 펼친 손은 미반영이다. 두 요소를 동시에 바꾼 실험이므로 개선을 한 요소의 효과로 단정하지 않는다.
- 입 주변 마스크는 말하는 입으로 바뀌었다. 입술·치아가 주변보다 세밀해 보여 추가 시각 검수 대상이다. 야외 컷은 얼굴이 비슷하지만 몸·배경 선화, 의상 및 머리 뒤 뉴스룸 잔여 영역이 어긋나 제외했다.
- Inpaint 원본 출력은 마스크 밖에도 픽셀 변화가 있었다. `protect.py`의 전체 비편집 영역 원본 복원은 사각 경계를 만들었으므로 팔/야외 후보에 채택하지 않았다. 실패한 결과도 파일로 보존했다.
- `refine.py`로 원본 얼굴 내부만 합성했다. 완전 불투명 영역 22,320픽셀의 원본 일치를 검사하고 경계만 안쪽으로 혼합했다. 나머지는 Bedrock 원본 출력이다. 입 편집은 입 밖 원본 복원이 시각적으로 가능했다. 이 검사는 새 각도 얼굴 생성의 정체성 점수나 얼굴 전체 일치 판정이 아니다.
- Conservative Upscale은 공식 문서 범위의 creativity=0.1을 실제 API가 거부했다(2.561초, ValidationException, 실제 범위 0.2~0.5). 0.2로 정정하고 얼굴 내부 보존 후보를 1248×832로 축소 입력했으나 34.860초 후 InternalServerException. 동일 입력·설정 1회 재시도도 30.915초 후 같은 오류여서 추가 호출을 중단했다. 확대 이미지 0장, 고해상도 품질 미검증.
- 전체 시도 7회, 성공 생성 4장, CLI 추론 호출 대기 합계 184.730초. AWS 공식 Oregon 단가 기준 성공한 Inpaint 4장 추정 $0.28. 실패한 업스케일 3회 청구 여부는 미확인이라 총 실청구액으로 표현하지 않는다. 정상 upscale 공시 단가는 $0.40이며 이번에는 정상 반환이 없다.
- 요청·응답 기록, 마스크, 원본 및 후처리 이미지, 100%/200% 얼굴 비교와 `review.html`을 저장했다. 반환 이미지 해시, 크기, 보존 픽셀 일치, HTML 로컬 링크 존재 여부를 검사했다. 제품 코드·활성 프롬프트·CMS HTTP API는 이번 시험에서 변경하거나 호출하지 않았다.

### 결정

- 현재 소량 시험에서 개선이 확인된 범위는 **동일 머리 각도에서 팔 동작·입 모양을 부분 편집하는 것**이다. 자유로운 측면 구도, 다인물·8컷 자동 일관성은 해결됐다고 보고하지 않는다.
- CMS 기본 생성 경로로 승격하지 않는다. 부분 편집은 참조 이미지·마스크·후처리·이력 관리가 필요하므로 프롬프트 버전 추가만으로 적용되지 않는다. 적용한다면 공통 `pipelines/common/webtoon_image.py` 경로와 CMS 요청 계약을 함께 확장해야 한다. 과거 삭제된 합성 기능은 복구하지 않았다.
- 기사별 기준 인물·장소·색감을 선택하고 기사 안에서 유지하는 설계가 적절하다. 모든 기사에 동일 인물·뉴스룸을 강제하는 결론은 아니다.

### 다음

- 시각 검수를 통과한 정면 설명 컷에 한정해 참조 이미지와 편집 마스크 저장 기능의 적용 범위를 결정한다. 현재 마스크 좌표는 해당 기준 이미지에만 유효하므로 다른 인물에 그대로 적용하지 않는다.
- 자유로운 머리 각도·다인물 변경은 별도 검증이 필요하다. 동일 이미지 반복 생성이나 확대만으로 해결됐다고 판정하지 않는다.
- Conservative Upscale은 두 차례 내부 오류로 이번 시험에서 사용할 수 없었다. 다른 정상 입력·서비스 상태가 확인되기 전 무조건 재시도하는 운영 로직을 추가하지 않는다.

근거: [AWS Stability Image Services](https://docs.aws.amazon.com/bedrock/latest/userguide/stable-image-services.html), [AWS Bedrock 가격](https://aws.amazon.com/bedrock/pricing/). 문서상 creativity 범위와 실제 API 오류의 차이는 원문 응답 기록에 남겼다.

## 후속 개선 — 가상 아나운서 2인과 대화·내레이션 혼합 3컷

### 배경

사용자가 기사에 맞는 2명의 전문가 또는 아나운서를 정하고, 한눈에 구분되는 외형과 실제 질문·답변 및 내레이션을 섞은 시안을 요청했다. 앞서 제안한 3컷 시험을 승인한 범위에서 진행했다.
