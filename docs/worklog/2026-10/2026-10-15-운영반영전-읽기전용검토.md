- 리소스 정본 `config/resources.env`의 기존 CMS 서버를 사용했다. AWS 계정·SSM Online 상태를 먼저 확인했다.

### 5. 적용 시 보존·중단·복구 경계

- 계획의 UPDATE 대상에는 slug/source_url/발행 상태/이미지 URL/음성·영상 파일 URL/계정 테이블이 없다. 웹툰 URL·순서는 사전 비교하고 캡션만 정정한다.
- 적용 코드가 단일 `get_cursor()` 안에서 실행되고 예외 시 rollback하는 구조는 확인했다. **실제 운영 쓰기·오류 주입으로 원자성을 시험한 것은 아니다.**
- 백업은 publications 원본과 계획이다. 자식 테이블의 전체 행·ID·위치·타입을 포함하는 완전한 복구 백업은 아니다. 실제 적용 전에는 해당 자식 행과 추가된 블록을 원상 복원할 기준까지 함께 남기는 편이 적절하다. 기존 백업만으로 완전 복구가 검증됐다고 판정하지 않는다.
- 본문 정정 4건은 `completion_repo.metadata()`의 body hash를 바꾼다. 이미 열린 읽기 세션은 완료 요청 때 `activity_repo.py`의 `409 CONTENT_CHANGED`를 받을 수 있다. 계정 행 삭제와는 별개로 다시 열기·기존 완료 기록 유지 시나리오를 확인해야 한다. 이번에는 계정·완료 데이터를 조회하거나 변경하지 않았다.
- 직접 SQL 정정은 관리자 revalidation webhook을 호출하지 않는다. Next의 300초 TTL·큰 목록 메모 캐시를 고려해 운영 반영 계획에 캐시 갱신 또는 만료·재검증 순서를 명시해야 한다. 캐시 무효화도 이번에는 실행하지 않았다.
- 대본·캡션 텍스트의 정정은 이미 생성된 음성 발화·이미지 픽셀·영상 자막을 바꾸지 않는다. 실제 미디어에 오류가 있는지는 별도 검수 범위다.

### 8. B01–B03 로컬 수정·재검증

사용자가 세 보완 사항의 구현을 요청해 기존 경로 안에서 수정했다. 이 후속 작업의 기준은 `2bcb516e`에 아래 미커밋 변경을 더한 스냅샷이다. 위의 읽기 전용 검토 결과와 후속 수정 결과를 구분한다.

| ID | 수정 | 재검증·상태 |
|---|---|---|
| B01 | `cms_posts_repo.list_published_posts('lens')`가 유효한 keywords를 함께 전달하도록 보완. 본문·미디어는 목록에 추가하지 않음 | **로컬 RESOLVED.** 실제 로컬 SQL 조회→repo→shaper 테스트에서 각 기사 용어 보존·잘못된 용어 제외·무거운 필드 제외 확인. 내부 브라우저 `/words`까지 실제 경로로 연결해 EPC 표시·검색·빈 결과·검색 초기화 확인 |
| B02 | 서비스의 전역 DB 풀 대신 도구 전용 연결 사용. 기본 연결 옵션부터 `default_transaction_read_only=on`, `readonly=True`, `REPEATABLE READ` 적용. 기본 조회에는 행 잠금 없음. 원본·문단·대본·캡션을 모두 사전 검사하고 성공 시에도 rollback | **로컬 RESOLVED.** PostgreSQL이 기본 모드의 UPDATE를 실제 거부. 검사 전후 테이블과 문단 시퀀스 값 동일. 투영만 변경된 경우·누락/실패 렌디션·본문 아닌 블록도 거부 |
| B03 | 패키지 allowlist에 `seed/2026-10-15-audit-corrections.json` 하나를 명시적으로 추가 | **로컬 RESOLVED.** 실제 tar 생성 후 스크립트와 정정 JSON 포함 확인. JSON 바이트 SHA가 원본과 같고 기존 정본 5개+정정안 1개 이외의 seed JSON은 없음 |

적용 모드는 기사 5건 전체의 원본과 투영을 먼저 검사·잠그고, 그 다음 백업을 배타 생성하고 변경하도록 분리했다. 백업에는 이제 원본 publications뿐 아니라 렌디션과 문단·대본·패널 전체 조회 행도 포함한다. `--apply`의 계획 SHA·신규 백업 필수 조건과 단일 트랜잭션은 유지했다. 접속 환경변수 네 가지를 모두 요구하고 `LENS_PG_PORT`도 지정할 수 있어 로컬 테스트가 운영 기본 주소로 연결되지 않는다.

실제 운영 적용 모드는 실행하지 않았다. 전용 임시 PostgreSQL **17.11**, `127.0.0.1:55439`, `lens_corrections_test`에서만 기사 5건의 수정 전 값을 합성 적재하고 테스트했다. 이전 운영 확인은 PostgreSQL 16.14였으므로 이번 로컬 검증을 운영 실행 검증으로 확대하지 않는다. 초기 샌드박스의 공유 메모리 제한을 확인한 뒤 로컬 클러스터 초기화 권한으로 실행했으며, 운영 AWS 명령은 실행하지 않았다.

검증 명령과 결과:

```bash
LENS_CORRECTIONS_TEST_PORT=55439 PYTHONPATH=service/lens-cms-api /tmp/lens-pr-venv/bin/python -m pytest service/lens-cms-api/tests/test_publication_corrections.py service/lens-cms-api/tests/test_publication_corrections_db.py service/lens-cms-api/tests/test_words_summary.py service/lens-cms-api/tests/test_correction_release.py -q
```

- **20개 테스트 통과**: 기존 순수 변환 8개·summary 1개, 신규 PostgreSQL 통합 10개·릴리스 1개. 통합 테스트는 전용 포트 환경변수를 명시해야 실행되며 이번 실행에서는 skip 없이 모두 통과했다. 일반 실행에서 이 환경변수가 없으면 DB 테스트 10개는 의도적으로 skip된다.
- 기본 CLI 검사 뒤 백업 파일이 만들어지지 않고, 전체 대상 행·문단 시퀀스가 그대로임을 확인했다. 기본 연결에서 UPDATE 거부도 실제 PostgreSQL 오류로 확인했다.
- 원본 JSON을 바꾸지 않고 자식 문단·대본·캡션만 바꾸거나 렌디션 상태/형식을 바꾸면 기본 검사와 적용 전 검사에서 모두 거부했다. 적용 전 거부 시 백업·부분 수정이 없음을 확인했다.
- 로컬 적용 테스트에서 5건의 JSON과 투영, 기존 블록 ID, 렌디션·URL·상태 보존 및 백업 권한 0600을 확인했다. 중간에 주입한 오류는 테이블 변경 전체를 rollback했다. PostgreSQL 시퀀스의 apply 실패 후 번호 간격은 트랜잭션 밖 동작이므로 테이블 원자성과 구분했다.
- 변경한 제품 코드·신규 테스트 5개 파일의 pyflakes와 `git diff --check` 통과.
- 실제 로컬 repo+PostgreSQL+shaper를 HTTP API로 연결해 프런트엔드를 빌드했다. `npm run build --workspace service/frontend` 성공, 내장 TypeScript 검사 통과, 정적 페이지 **62개** 생성. fixture가 일부 API 목록을 비워 반환하므로 이전 운영 자료 기반 빌드와 페이지 개수를 비교하지 않는다. tracing/turbopack 루트·middleware 폐기 예정 경고는 남아 있다.
- 내부 브라우저에서 로컬 DB 5건에 같은 EPC를 넣은 표본을 확인했다. 응답의 중복 용어가 화면에서는 1개로 모이고 “설계·조달·시공” 설명과 출처 링크가 표시됐다. 실제 SQL→새 repo→shaper를 사용했으며 keywords를 브라우저 fixture에 직접 주입하지 않았다. 출처 문서 전체의 동작은 이번 범위에 포함하지 않았다.
- 콘솔 error 0건, 스크린샷 촬영·저장 없음. 프런트엔드 소스는 바꾸지 않았고 기존 lint 0/0·135개 프런트 테스트 결과는 이전 스냅샷 근거로 유지하며 이번에 다시 실행한 것으로 세지 않았다.
- 독립 리뷰어가 최종 5개 파일의 SHA와 실제 호출·직렬화·저장·패키지 경로를 확인했다. 이번 요청 범위에서 추가 확정 결함은 발견하지 못했다. 실제 동시 편집 두 세션의 잠금 경쟁은 실행하지 않았으며, 운영 캐시·열린 읽기 세션·미디어 검수 경계는 앞선 검토대로 남아 있다.

## 결정

- 운영 read-only 대조 당시 정정안의 값 충돌은 발견되지 않았으나 B01–B03 때문에 반영을 보류했다. 후속 요청으로 **B01–B03은 로컬 수정·재검증 완료**했다. 운영 적용·전체 운영 준비 완료를 뜻하지 않는다.
- 최초 검토에서는 제품 코드를 변경하지 않았고, 후속 작업에서만 관련 코드·테스트를 수정했다. 운영 데이터·계정 데이터·캐시·서비스 설정은 변경하지 않았다. 재검증 당시에는 미커밋 상태였으며, 이후 사용자 요청으로 보완 코드 3개·테스트 2개·이 보고서만 추가 로컬 커밋 대상으로 확정했다. 배포·push는 수행하지 않는다.
- 기존 사용자 작업 기록 `2026-10-15-나의LENS-배포준비.md`는 그대로 보존했다. 원래 해시 `fa6a2bb2c54f3da9344680d72876eed960f93a826070f195ef7bd8cb125cd8f5`를 확인한다.
- 다이어트 후보는 20건 모두 원장에 남겼다. D08·D09·D18의 오류 수정과 겹친 부분을 구분했으며 일괄 삭제·축소하지 않았다.
