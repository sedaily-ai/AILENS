CMS/API/프론트 각 단계 뒤 health·공개/개인 계약을 확인하고 실패하면 다음 단위를 멈추는 계획이 필요하다. 기사 정정 뒤에는 원본/공개 투영·단어장·투표·열린 읽기 세션과 캐시를 별도로 확인한다. 이 상세 실행 준비는 우선순위 2–6 범위다.

**이번에 포함하지 않을 것:** 기존 미커밋 `나의LENS-배포준비` 내용, 앞선 미커밋 우선순위 보고서와 이 보고서의 자동 커밋, 관리자 웹/API, 모바일 앱 빌드/스토어 배포, 파이프라인 이미지, 콘텐츠 메타데이터 공급/새 SQL 적용, worker timer 활성화/실발송, 추가 다이어트 삭제. 모바일 개선은 Git 통합에서 보존하되 모바일 배포를 수행한다는 뜻은 아니다.

### 8. 범위·근거·검증 한계

- 원격 compare와 raw diff, 로컬 경로/해시, AWS ECS/ECR/Lambda/Gateway 조회 및 CMS 디스크 해시를 대조했다. 원격 전체 모바일 기능·모든 75개 코드의 정확성을 새로 전수 리뷰한 것은 아니다.
- 실제 Cognito 인증/개인 API·DB 데이터·계정 설정·기사 현재 값은 읽거나 쓰지 않았다. 공개 페이지 GET 외 사용자 흐름은 재실행하지 않았고 스크린샷은 없다.
- SSM은 승인된 기존 서버에서 해시 계산·프로세스 경로 조회만 수행했다. AWS Run Command 자체의 명령·로그 기록은 생기지만 제품 파일/설정/DB/프로세스 상태 변경은 없다.
- 처음 Gateway 기본 페이지만 읽은 결과는 불완전해 전체 페이지 157개 조회로 대체했다. ECR index를 단일 manifest로 가정한 초기 조회와 리다이렉트 400은 근거에서 제외하고 ARM64 child/config/provenance 조회를 완료한 결과만 사용했다. 레지스트리 인증 헤더는 다른 호스트 리다이렉트에서 제거했고 인증값은 저장·출력하지 않았다.
- 상세 임시 근거는 `/tmp/ailens-priority1-review/`의 `baseline.json`, `remote-comparison.json`, `local-paths.json`, `aws-metadata.json`, `operating-more.json`(Gateway/공개 응답), `image-metadata.json`, `image-provenance.json`, `cms-operating-hashes.json`, `cms-code-comparison.json`, `lambda-code-comparison.json`에 있다. 운영 Lambda ZIP은 이 임시 디렉터리에 권한 0600으로만 저장했다. 비밀 환경 값·ECR 인증값·Lambda 다운로드 서명 URL은 결과에 남기지 않았다.

## 결정

우선순위 1의 **버전·반영 범위 대조는 완료**했다. 원격/로컬 파일 직접 충돌은 없고 CMS/Lambda의 확인한 제품 파일은 공통 기준과 일치한다. 프론트는 실행 image digest와 공개 표본의 미반영을 확인했으나 Git SHA 출처는 확정할 수 없다. 따라서 ‘모든 운영 소스가 특정 Git 커밋과 일치’ 또는 ‘지금 배포 가능’으로 결론 내리지 않는다.

권장안은 **격리 통합 브랜치에서 두 이력 보존 → 최종 diff/산출물 검증 → 별도 승인된 CMS·계정 API·프론트 반영**이다. 기사 데이터 5건은 별도 사전 검사/백업/승인 단위로 유지한다. 함수·라우트 신규 생성, DB 재마이그레이션, worker·실발송 활성화를 이번 변경에 끼워 넣지 않는다.
