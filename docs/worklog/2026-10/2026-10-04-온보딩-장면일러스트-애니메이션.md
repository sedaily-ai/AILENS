## 사이클 1 — 장면(1단계) 아이콘 → 동작하는 인물

### 문제 발견
- 초안 장면 아이콘 4종: 선 몇 개짜리 정지 그림 — 사용자 지적: "움직이는 것처럼", "사람이 걷고, 눕고, 지하철이 움직이고", "좀 더 퀄리티 높게 / 더 사실적이고 동작이 유연하게"
- 1차 개선(선 몇 개를 SMIL로 흔듦) 후에도 "걷는다"가 읽히지 않음 — 점심·침대 장면은 움직임 부족 지적

### 문제 정의
- 동작의 설득력 부족 원인 = 포즈 구조 부재(걷기의 접촉·낮아짐·교차·올라감 4포즈, 상하 흔들림, 무릎 굽힘, 팔 엇박자·지연)

### Why
- 선택지가 "내 상황"을 알아보게 하는 핵심 장치 → 그림이 상황을 읽히지 못하면 질문 1의 목적(알아보기) 실패

### How
- 리서치: 걷기 사이클 4포즈 + 겹침 동작 원칙 / 웹 애니메이션 도구 비교(Lottie·Rive·CSS·JS)
- 선택: 중첩 `<g transform>` 순기구학(FK) + 2관절 역기구학(IK) + `requestAnimationFrame`으로 각도 갱신
- 선택 이유: Lottie는 After Effects, Rive는 Rive 에디터가 필요해 코드만으로 제작 불가 / 손이 손잡이·폰에 닿는 동작은 IK로 해결
- 버린 대안: SMIL만 사용(회전 중심·연동 동작 한계로 부자연스러움)
- 그림체: 얼굴 없는 면 채색 + 얇은 외곽선, 파란색(`#5b8def`)은 움직임·소리·빛에만 사용(AI 티 나는 인물 일러스트 회피)
- 장면별 동작: 점심 = 폰 쓸기·고개 들기·숨쉬기·시계 / 지하철 = 차체 흔들림 + 손잡이 지연 흔들림(0.35초) + 발 고정 / 걷기 = 발 미끄러짐 없는 지면 속도(보폭 역산, 52.6/1.05초) + 배경 시차 / 침대 = 숨쉬는 이불·팔 처짐(9초 주기)·뒤척임(7초 주기)·별똥별 7개(주기 2.3~4.3초, 어긋나게)
- 접근성: 움직임 줄이기(`prefers-reduced-motion`) 시 한 프레임 정지 그림 — SMIL은 미디어쿼리 미적용이라 애니메이션 요소 자체를 미렌더
- 사용자 수정 반영: 침대 장면 "움직임 덜하다" → 창 확대(26×24 → 46×32), 별똥별·뒤척임 추가

### 검증
- 시간차 캡처(0.3~0.9초 간격 3~12프레임)로 장면별 위치·자세 변화 확인
- 한계: 지하철 장면에서 팔이 머리를 가리는 프레임 존재 / 얼굴 부재로 표정 표현 불가 / 컵 드는 동작은 팔이 닿지 않아 제외

### 판정

## 사이클 2 — 선택지(2단계) 아이콘 → "눈이 먼저 가는 곳" 화면

### 문제 발견
- 초안 2단계 아이콘: 막대·글줄·삼각형·헤드폰 정지 아이콘 — 사용자 지적: "1단계처럼 구체적으로 디자인", "그림 부분이 설명과 안 맞음", "영상이 등산 같다"(산 풍경 때문)
- "그림과 사진" 선택지에 해당하는 웹툰 장면 부재

### 문제 정의
- 선택지 이름(글·그림과 사진·소리·영상)과 그림이 실제 AI LENS 포맷의 모습과 불일치

### How
- 컨셉: 뉴스 화면 한 장 안에서 해당 요소만 파랗게 살아 움직임
- 글 = 파란 형광펜이 줄을 따라 읽음(읽은 줄 진하게) / 소리 = 앨범 회전 + 이퀄라이저 9개 + 진행바 / 영상 = 실제 영상처럼 네이비 화면에서 큰 숫자 → 막대그래프 → 도넛 컷 전환 + 말하는 자막 / 그림과 사진 = 실제 웹툰처럼 일러스트 컷 + 검은 자막 띠 + 사진 컷(뷰파인더·셔터 플래시), 컷이 위로 넘어감
- 엔진 공유: `useRig`(MomentArt) 재사용, 임의 속성(선 그리기 등) 갱신용 `A()` 추가
- 선택지 5개 → 4개(숫자와 표 제거)

### 검증
- 6~12프레임 연속 캡처로 컷 전환·플래시·도넛 채움 확인 / 웹툰 마지막 구간 하단 공백 발견 → 컷 5개로 연장해 해소(12프레임 내내 공백 0)
