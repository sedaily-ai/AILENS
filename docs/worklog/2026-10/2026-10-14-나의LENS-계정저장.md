# 나의 LENS 첫 백엔드 개발 묶음

## 배경

프론트 로그인 제한만으로 개인 자료 API의 소유권을 보호하거나 관심·레터 저장을 계정 간 동기화할 수 없었다. 기존 개인 Lambda → 내부 FastAPI → PostgreSQL 구조를 유지해 첫 계정 저장 흐름을 구현한다.

## 한 것

- 서랍 GET 인증과 JWT 필수 클레임 검증을 보완하고 요청 user_id를 검증한 sub로 덮어쓴다.
- 공통 콘텐츠 resolver를 추가해 publication/issue_letter 및 stable ID/명시적 slug를 구분한다. 문장 응답에 content_key/href를 제공한다.
- 계정 관심·읽을 시간의 revision 저장과 레터 북마크의 멱등 저장·해제·페이지 조회 API를 구현한다.
- v1.48 계정 설정·북마크 SQL과 로컬 개인 API shim을 추가한다.
- 레터 목록·상세·대시보드를 비동기 계정 저장에 연결하고 실패·충돌·계정 전환을 처리한다.
- 실행 계획과 구현 상태·로컬 실행·운영 연결 후속 사항을 제품 문서에 남긴다.

## 결정

- 운영 DB·배포·AWS 리소스·커밋·push는 이번 요청 범위에서 제외한다.
- 로그인 전 공용 브라우저 자료를 계정에 자동으로 합치지 않으며 원본을 보존한다.
- 계정 팔로우·자료 가져오기·서버 추천·리워드·알림은 다음 묶음으로 분리한다.

## 다음

- 운영 반영 요청 시 기존 schema/권한을 인수하고 신규 API 라우팅·마이그레이션·배포 순서를 적용한다.
- 다음 개발 묶음은 서버 이용 신호와 추천·개인 대시보드 집계다.
