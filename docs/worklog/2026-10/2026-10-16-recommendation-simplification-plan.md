# 관심사 설정 제거·추천 단순화 실행 계획

> 승인된 방향을 현재 세션에서 직접 구현한다.

**목표:** 수동 관심사 설정을 없애고 뉴스는 최근 열람 분야, 레터는 팔로우 에디터와 최신순으로 고른다. 기존 이메일 구독과 읽을 시간은 유지한다.

**구조:** 기존 계정·추천 API를 사용한다. 읽을 시간 PUT은 `minutes`, `revision`만 보내며 서버가 기존 관심 데이터를 보존한다. 과거 전체 설정 요청은 호환한다. 저장 문장 단어는 해당 문장의 관련 글 요청에서만 사용한다. 형식 선호는 통계만 제공한다.

**스택:** Next.js 16 / React 19 / Python / PostgreSQL. 새 의존성·DB 마이그레이션 없음.

## 작업

1. 설정 저장 계약에 시간만 변경하는 요청을 허용한다. 기존 관심과 동시 수정 revision 검사를 유지하고 저장 회귀 테스트를 추가한다.
2. 공통 추천에서 수동 관심·키워드·전역 문장·형식 점수를 제거한다. 뉴스는 열람 분야, 레터는 실제 팔로우 저자를 확인하고 최신순으로 고른다. 입력이 없으면 최신 목록을 사용한다. 시간 제한은 레터 합계에 적용한다.
3. 홈·레터 목록·알림의 관심사 UI와 호출을 제거한다. 시간 설정은 독립 훅으로 저장한다. 신규 이메일 구독에는 에디터만 보내며 기존 구독 발송 코드는 보존한다.
4. 소비자가 없어진 기기 관심 피드·프론트 중복 추천 함수를 삭제한다. 문장 관련 글·구독 배달·콘텐츠 주제 탐색은 유지한다.
5. Python 관련 테스트와 pyflakes, 프론트 테스트·타입 검사·lint·빌드를 실행한다. 미검증 환경 경계는 작업 기록에 명시한다.

## 집중 검토

- 시간 변경이 기존 관심/이메일 구독을 지우지 않는지, revision 충돌이 보존되는지.
- 다른 계정 데이터 노출과 인증 실패 후 기기 저장으로 우회하지 않는지.
- 전역 추천에 수동 관심·문장·형식이 더 이상 개입하지 않는지.
- 팔로우가 없을 때만 최신 레터를 쓰고, 예산과 중복 제거가 적용되는지.
- 문장 관련 글은 해당 문장만 사용하고 새 뉴스가 없으면 빈 목록인지.
