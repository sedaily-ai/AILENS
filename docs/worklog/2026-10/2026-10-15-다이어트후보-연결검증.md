# 2026-10-15 다이어트 후보의 프론트와 백엔드 연결 검증

> 과거 조사·검증 시점의 기록입니다. 현재 통합 범위·배포 상태·미완료 항목은 [2026-10-16-사용자웹-잔여통합-PR준비](2026-10-16-사용자웹-잔여통합-PR준비.md)을 기준으로 확인합니다. 본문의 과거 계획은 이번 실행 지시가 아닙니다.

**후속 로컬 구현:** 사용자 승인으로 우선순위 1–7을 수정·재검증했다. 아래 1–7절은 구현 전 조사이며, 구현 결과·검증 범위는 8절에 기록했다. 이후 요청된 로컬 커밋 범위는 제품 소스 11개·관련 테스트 1개·이 보고서이며, 기존 별도 작업 기록은 제외한다. push·배포·운영 저장값 변경은 없다.

## 배경

사용자 요청에 따라 기존 D01–D20을 화면→API→저장·집계·외부 호출까지 다시 추적했다. 우선순위는 **프론트만으로 중복과 복잡도를 줄일 수 있고 기존 기능·저장값을 보존하는 안**을 앞에 둔다. 기준은 로컬 `main`의 `be7cad7c7a626af3f07fd6c36f6d717c718c3280`이다. 운영 화면은 같은 날 내부 브라우저에서 읽기 전용으로 표본 재확인했다. 이 보고서만 추가하며 제품 코드·데이터·설정은 변경하지 않는다.

결론은 **프론트 우선 정리 7건**, **추가 비용 개선 후보 1건**, 나머지는 조건부 검토·보류·오류 분리다. 사용자 수·이용률이 낮다는 이유로 확정한 삭제 대상은 없다. 기존 20건을 모두 불필요한 기능으로 분류했던 해석은 철회한다.

### 4. 추가 발견 N01 대시보드 조회를 탭별로 늦추기

UI 정리와 구분한 **성능·조회 비용 후보**다. 프론트에서 시작할 수 있지만 기존 집계 API의 계약까지 확인해야 하므로 위 7건 다음 별도 묶음으로 권한다.

- [MyLensPage.tsx:64](../../../service/frontend/src/widgets/MyLensPage/MyLensPage.tsx#L64)에서 탭 분기 전에 shelf·archive·interests·follow·letters·server 훅을 모두 마운트한다. 설정·기록 탭에서도 서랍 문장 최대 200개, 저장 레터 목록, 팔로우, 공개 레터 목록의 로더가 활성화될 수 있다. 탭별 `<section>`을 숨기는 것만으로 훅은 멈추지 않는다.
- [useDashboardArchive.ts:36](../../../service/frontend/src/widgets/MyLensPage/lib/news/useDashboardArchive.ts#L36)는 전체 문장 목록을 호출하지만 홈은 `server.data.recent_sentences`로 다시 대체한다. 전체 문장을 쓰는 서랍 탭에만 로더를 두는 안은 명확한 후보이다. 인증 owner·삭제 후 갱신·검색·관련 글 동작은 유지해야 한다.
- [useLetterShelf.ts:55](../../../service/frontend/src/features/letter/lib/useLetterShelf.ts#L55)는 저장 레터 전체를 가져오고, [useDashboardLetters.ts:19](../../../service/frontend/src/widgets/MyLensPage/lib/useDashboardLetters.ts#L19)는 공개 목록과 필요시 저장된 레터 상세를 복원한다. 설정 탭에서 이 목록이 필요한지 분리할 수 있다. 한도 밖 저장 레터 복원·완료 필터는 제거 대상이 아니다.
- [useServerDashboard.ts:18](../../../service/frontend/src/widgets/MyLensPage/lib/useServerDashboard.ts#L18)는 탭을 인자로 받지 않고 focus/pageshow 및 변경 이벤트에 집계를 다시 읽는다. [get_dashboard](../../../service/backend/services/user/dashboard_summary.py#L23)의 정상 응답 경로에는 입력 1회+뉴스/레터 후보 각각 1회+저장 레터 1회+리워드 1회+알림 1회, **내부 HTTP 요청 6회**가 있다. 후보 계산 요청은 POST지만 조회 연산이다. 이는 소스에서 센 정상 경로이며 이번에 측정한 운영 요청 수나 SQL 실행 횟수가 아니다.
- 설정 화면의 `useNotifications`는 알림 상태를 별도로 조회한다. 집계 응답에도 같은 알림 조회가 있으므로 상태 공유·재조회 경계를 검토할 여지가 있다. 동의 철회·기기 해제·다른 창 변경의 최신성 보장은 유지해야 한다.
- 추천: **먼저 프론트의 불필요한 로더를 탭 진입 시 마운트**하고, 그 뒤 집계 응답을 탭별로 나눌 필요를 판단한다. 카드만 숨겨 얻는 효과, 프론트 요청 감소, 서버 집계 축소를 구분해 측정한다. 실제 네트워크 요청 수·응답 크기·지연·DB 부하는 아직 측정하지 않았으므로 절감률은 미산정이다.

내부 브라우저는 `/tmp/ailens-diet-qa/app/service/frontend`의 임시 복사본에서 확인했다. 변경한 제품 소스 11개의 바이트가 저장소와 모두 같은 것을 대조했다. 실제 로그인·저장 데이터를 사용하지 않도록 복사본에서만 Amplify 로더를 합성 계정으로 대체하고, 분석 스크립트 제외 및 동일 출처 로컬 API 프록시를 적용했다. 저장소의 인증·API 클라이언트·Next 설정은 변경하지 않았다. 브라우저의 최종 **21개 확인 항목이 모두 통과**했다.

- 비활성 시간 설정 접힘과 활성 상태의 기본 펼침. 기존 14:35·런던·주 3회·금요일을 확인하고 시간대 편집 후 접기·재열기·변경 취소를 검증.

- 현재 목록 에디터와 전체 에디터 전환, 준서 0편 화면, 소개 음성·메일·팔로우 진입점, 직접 `/letter/editors/junseo` 진입과 선택 표시 유지. 음성 완주·메일 발송·실제 팔로우 저장을 검증한 것은 아니다.

## 결정

- 프론트 우선 7건을 작업 제안으로 추렸다. 구현·삭제 승인을 받은 것으로 해석하지 않는다. UI 단순화와 API·DB·배치 폐기를 구분한다.
- D09·D11·D19는 다이어트에서 제외하고 오류 복구·검증으로 분리했다. D15는 소개 근거 검수, D20은 UI 중복과 접근성 오류로 나눴다. D04·D05·D07·D08·D13은 조건부, D10·D16·D17·D18은 보류다.
- 추가 N01은 호출 경로로 뒷받침되는 비용 개선 후보지만 운영 성능 측정은 아직 없다. 7건의 단순 UI 정리보다 회귀 범위가 크므로 별도 작업으로 둔다.
- 코드·설정·테스트·운영 데이터 수정, 기존 파일 삭제, 커밋·push·배포를 수행하지 않았다. 제품 소스·자산 1,089개 파일의 조사 종료 기준 SHA를 재대조해 변경 없음을 확인했고, 기존 별도 작업 기록의 SHA도 유지됐다. 보고서의 로컬 근거 링크 50개는 경로 존재·행 범위를 확인했다. 임시 브라우저 탭을 닫고 기존 탭은 나의 LENS 홈으로 복원했다. 이번 결과는 새 보고서만 추가한다.
- 위 문단은 최초 조사 시점의 상태다. 후속 승인으로 **1–7은 8절대로 로컬 수정·검증 완료**했으며 구현 종료 시점에는 미커밋으로 남겼다. 이후 사용자의 커밋 요청에 따라 제품 소스 11개·관련 테스트 1개·이 보고서만 로컬 커밋 대상으로 확정했다. 기존 별도 배포 준비 기록은 제외하며 push·배포는 수행하지 않는다. N01 조회 최적화와 E01–E04 별도 오류·검수 항목은 수정하지 않았다.
