# 2026-10-20 모바일 홈 에디터 대화형 재설계

작성: 사용자 + Claude Code
관련: PR #143·#144, 계획 `~/.claude/plans/snuggly-splashing-wozniak.md`, `docs/architecture/apps-mobile-홈-설계.md`

## 배경

웹 홈을 그대로 옮긴 앱 홈은 매일 다시 열 이유가 약했다. 방향("에이전틱·초개인화 뉴스·시사 플랫폼")과 사용자가 말한 가치(관심 분야를 차곡차곡 읽고·남기고·이해하고, 내 성향을 확인) 기준으로 홈을 "내 에디터와 대화하며 오늘의 소식을 이해하는 곳"으로 다시 설계했다.

## 한 것

- 문제 재정의(Why 5): 홈이 복잡한 이유는 UI가 아니라 "읽고 나서 남는 것·돌아올 이유가 없음". 가치 루프 = 이해 → 남김 → 쌓임 → 확신. 습관 루프(트리거·행동·가변 보상·투자)와 3 Horizons(H1 출시 70·H2 성장 20·H3 실험 10)로 범위 구분.
- 조사: 뉴스 앱 습관 설계·듀오링고 스트릭·Hooked 모델(근거 약함 표기), 링글(Unmute) 코드(선제 푸시 구조·학습 상태·스트릭), 서버 현황(챗봇·daily_questions·푸시·읽은 기록 API).
- 홈 구성: 내 에디터 대화 카드(시간·상황 인사 말풍선, 자기소개 음성) → 추천 질문(제자리 아코디언: 핵심 정리·용어·더 자세히·이 소식 전체 읽기·다른 형식으로 이어가기) → 내 관심 → 이어서 볼까요? → 지금은 이렇게 볼까요?(형식 캐러셀) → 오늘의 지면(압축) → 방금 올라온 소식 3건 → 그날로 떠나요.
- 질문·풀이는 기사 필드만 사용(`lenses[]`의 웹툰 `question`, 레터 `bullets`·`keywords`). 최근 60건 중 54건에서 구성 가능. 생성 문장 없음.
- 에디터 8명 데이터를 웹 `features/letter/data/editors.ts`에서 `packages/domain/src/letters/editors.ts`로 공용화(웹은 재수출, 레터 테스트 23건 통과). 에디터 담당 분야·주제어와 읽은 글로 질문 선정(`questions.ts`), 에디터 성향 3종 말투(`editorVoice.ts`).
- 하단 탭 3개(듣기 탭 제거), 로고는 홈에만, 항상 떠 있던 오디오 바 제거(재생 중에만 미니 플레이어).
- 순수 로직 검증: 질문 선정 20건, 진행 계산 5건, P2 11건.

## 결정

- 질문·풀이는 생성형이 아니라 기사 필드만 사용(사실성·비용). 웹 챗봇(`/api/chat`)은 인증·요청 제한이 없어 재사용 금지, 자유 대화는 H3로 보류.
- 2026-10-19 "읽기 요약 제거" 결정에 대해: 한때 홈에 진행 카드·이번 주 7칸을 되살렸으나(번복) 이후 대화형 홈에서 다시 내리고 연속 일수 칩만 남김. 푸시(에디터가 먼저 말 걸기)는 2026-10-20 기능 다이어트로 서버가 삭제된 상태라 별도 결정 전까지 제외.
- 호칭은 쓰지 않음(구글 로그인에 이름이 없음).
