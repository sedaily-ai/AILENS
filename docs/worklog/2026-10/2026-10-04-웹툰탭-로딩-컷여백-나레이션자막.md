## 사이클 1 — 탭 로딩 지연

### 문제 발견
- 사용자 지적: 웹툰 탭 로딩 느림
- 실측(운영, 1.6Mbps · CPU 4배 감속): 탭 클릭 후 첫 컷 표시까지 약 1,990ms
- 원인(측정): ① 탭이 숨겨진 동안 이미지 요청 미시작 ② 컷 7장(장당 약 50KB, 총 약 370KB) 동시 수신으로 대역폭 분할 → 첫 컷 지연 ③ 컷 자리 비율 3:2 vs 실제 약 1824×1752(≈1:1) → 이미지 표시 시 레이아웃 이동
- 서버 응답(TTFB) 10~40ms로 정상 — 병목은 서버가 아닌 수신 순서

### 문제 정의
- 숨은 탭의 지연 요청 + 우선순위 없는 일괄 수신 + 자리 비율 불일치

### How
- 앞 2컷 고우선순위, 나머지 저우선순위로 분리
- 탭 숨김 상태에서 로드 완료 후 idle에 앞 2컷 사전 수신, 사전 수신 전 클릭 시 화면 진입 즉시 고우선순위 승격
- 자리 비율을 실제 값에 맞춤
- 버린 대안: 이미지 품질 85→80(약 10% 용량 감소 예상) — 말풍선 글자가 이미지에 포함돼 화질 민감, 보류
- SEO 영향 없음: 이미지는 모두 HTML에 유지

### 검증
- 로컬 동일 조건: 첫 2컷 표시 약 1,990ms(운영 현재) → 약 730~900ms
- 한계: 로컬 개발 서버 대 운영 CloudFront 조건 상이로 정확한 수치 비교 아님, 실기기 체감 미확인

### 판정
- 채택 · 프론트 배포 완료

## 사이클 2 — 컷 사이 여백

### 문제 발견
- 사용자 요청: 컷 사이 흰 여백 증가(이후 "더 늘려", "약간 줄여" 두 차례 미세 조정)
- 기존: 컷 이미지에 박힌 흰 띠(말풍선 자리)만 존재, 컷마다 편차

### How
- 코드로 일정한 흰 간격 부여: 화면 폭 비례 `clamp(56px, 12vw, 140px)`(최종값, 초기 40~104px에서 사용자 조정)
- 이미지 내부 흰 띠와 합쳐지는 컷 존재, 기존 발행분에도 즉시 적용

### 판정
- 적용 완료 · 배포 완료(사용자 직접 관찰 기반 조정이라 가설/검증 생략)

## 사이클 3 — 나레이션을 이미지에서 분리

### 문제 발견
- 사용자 요청: 검정 자막 띠 위치를 흰 여백 쪽으로 이동
- 기존 구조: 나레이션이 이미지에 검정 띠로 구워짐 → 텍스트 수정·서체·표시 방식 변경 불가

### 문제 정의
- 텍스트가 이미지에 종속 → 사이트 표시 계층에서 제어 불가

### How
- 선택(B안): 합성 시 검정 띠를 굽지 않고, 나레이션을 컷 아래 흰 여백에 굵은 진한 글씨 가운데 정렬로 표시
- 숫자·단위는 서울경제 파랑 `#5b8def`(예: 18곳, 9월 30일) — 기존 띠 안 숫자 강조 규칙 계승, 글자 크기 18~25px(화면 폭 비례)
- 시험 합성 컷 높이 134px 감소
- 구분 장치: 컷별 마커 파일 `컷N.textcaption` → `images[].text_caption` — 새 방식으로 합성된 컷만 표시, 합성 실패(기본 스타일 대체) 컷은 표시 없음 → 글자 이중 표시·누락 방지
- 영향 범위: 이미 발행된 웹툰은 이미지에 띠가 박혀 있어 변화 없음(재생성 시 비용 발생이라 별도 결정 대상)
- 배포 순서 근거: 프론트가 표시 필드를 먼저 읽을 수 있어야 하므로 프론트 → 파이프라인 이미지

### 판정
- 프론트 배포 완료 / 파이프라인 이미지 배포 완료(실제 적용은 다음 자동 실행부터)
- 미검증: 새 방식으로 합성된 실제 웹툰의 라이브 실행
- 잔여: CMS 웹툰 실험 화면 미리보기(`admin/backend/routes/webtoon/generate.py`)는 미수정 → 시험 이미지에 옛 검정 띠 잔존
