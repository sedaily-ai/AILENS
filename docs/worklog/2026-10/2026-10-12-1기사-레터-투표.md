# 1기사 레터 투표 기능 (2026-10-12)

## 문제 발견
- 1기사 레터 본문의 "🗳️ 투표" 칸이 보기 문구를 글자 목록으로만 보여 주고 선택·저장·집계가 없었다(스크린샷 확인). 투표 API는 모아쓰기 레터(`issue_letters`)에만 있었다.
- 같은 화면에서 마지막 보기에 출처 줄이 붙어 보였다("④ 잘 모르겠어요 -- 자료: 서울경제신문(2026년 10월 10일), …"): 압축 프롬프트(v34) 표기를 파서가 못 읽은 결과(수정 완료, 기존 글은 화면에서 잘라 내도록 처리).

## 문제 정의
- 1기사 글은 본문이 텍스트라 투표 정의 테이블이 없다. 보기는 본문에서 읽어 번호(o1~o9)로만 저장하면 된다.

## 추가: 투표 다시 선택 (같은 날)
- 요구: 투표한 뒤에도 다른 보기를 눌러 바꿀 수 있게. 기존은 한 번 투표하면 고정("투표는 바꾸지도 지우지도 않는다", v1.37 설계).
- 결정: 한 기기 한 표는 유지, 보기 변경만 허용(삭제는 계속 불가).
- 변경: 서버 `INSERT … ON CONFLICT DO UPDATE`(1기사·모아쓰기 둘 다, 같은 보기를 다시 누르면 변화 없음, 409 응답 폐지, 응답에 `changed`). DDL v1.47: `post_votes`·`issue_letter_votes`에 UPDATE 권한. 화면: 투표 후에도 다른 보기 활성, 눌렀을 때 낙관적 갱신(이전 보기 -1·새 보기 +1로 막대와 숫자가 곧바로 옮겨 감, 실패하면 되돌림), 막대는 transition 하나로 첫 차오름과 변경을 모두 처리, 숫자는 직전 값에서 새 값으로.
- 순서 주의: UPDATE 권한이 없는 상태로 서버를 배포하면 첫 투표도 실패한다(ON CONFLICT DO UPDATE 는 권한을 요구). 그래서 DDL v1.47 적용 → 서버·프론트 배포 순서.
- 테스트: 서버 113개 통과(보기 변경 포함), 프론트 낙관적 계산 vitest 3개.

## 추가: 레터 탭 성능·노출 점검 (같은 날)
- 점검: 날짜 없이 `/letter/<slug>`·`/letter/editors/<id>`가 `cache-control: private, no-store`(매 요청 서버 렌더, CDN 미캐시). 홈·카테고리·레터 목록은 ISR로 CDN 캐시.
- 원인: 동적 파라미터 라우트에 `generateStaticParams`가 없어 Next가 라우트를 동적으로 처리(지난 지면 라우트에 같은 이유가 주석으로 기록돼 있었음).
- 조치: 두 라우트에 `generateStaticParams`(빈 배열)와 `dynamicParams` 추가. 링크 미리 받기(`LinkPrefetcher`)의 한가할 때 받기에 `/letter/<slug>`·`/letter/editors/<id>`를 포함(손가락 닿음·호버 즉시 받기는 원래 모든 내부 링크). 푸터 콘텐츠 링크와 전체 메뉴 하단 링크에 레터 추가. 헤더 검색 아이콘을 햄버거 막대+돋보기를 합친 아이콘으로(서울경제 sedaily.com "통합검색 & 사이트맵" 아이콘 구조, 누르면 전체 메뉴+검색 패널).
- 확인: 배포 후 레터 상세 두 번째 요청부터 `x-cache: Hit from cloudfront`, 응답 시작 시간 약 0.02~0.03초(캐시 적중).
- 남은 일: 사이트맵·llms.txt·구조화 데이터에 레터 포함은 노출(noindex 해제) 결정 때 함께. 정식 오픈 전이라 보류.
