#### time-machine만 워밍 대상으로 등록(2026-10-22 정리, 실행하지 않음)

- **배포(`./deploy.sh time-machine`) 뒤에만 실행한다.** 지금 배포된 옛 코드는 `{"warmup": true}` 입력을 400으로 돌려보낸다. 새 코드(`lambda_handler`)는 `warmup`이나 `source: aws.events`를 받으면 DynamoDB·빅카인즈 세션·달력만 준비하고 `{"status": "warm"}`으로 돌아간다(빅카인즈 호출 없음, 로그 `warmup`).
- 2026-10-22 읽기 전용 조회로 본 지금 상태
  - 규칙 `sedaily-mbti-lambda-warming`: `rate(5 minutes)`, ENABLED, 기본 이벤트 버스, 태그 `Service=atlas4`·`Project=Sedaily-LENS`·`Environment=dev` 등.
  - 대상 3개: `sedaily-mbti-post-dev`·`sedaily-mbti-search-dev`·`sedaily-mbti-v2-feed-dev`. Id는 함수 이름과 같고, Input은 모두 `{"warmup":true}`다.
  - 기존 대상의 권한 Sid는 `lambda-warming-permission`(principal `events.amazonaws.com`, SourceArn 규칙 ARN)이다. time-machine 함수의 리소스 정책에는 API Gateway 권한(`apigw-time-machine`) 하나뿐이라 같은 Sid를 새로 넣을 수 있다.
- 등록 — 권한을 먼저 넣고 대상을 넣는다. `put-targets`는 적은 대상만 더하거나 고치고, 기존 세 대상은 그대로 둔다.

  ```bash
  aws lambda add-permission \
    --function-name sedaily-mbti-time-machine-dev \
    --statement-id lambda-warming-permission \
    --action lambda:InvokeFunction \
    --principal events.amazonaws.com \
    --source-arn arn:aws:events:us-east-1:887078546492:rule/sedaily-mbti-lambda-warming \
    --region us-east-1

  aws events put-targets \
    --rule sedaily-mbti-lambda-warming \
    --targets '[{"Id":"sedaily-mbti-time-machine-dev","Arn":"arn:aws:lambda:us-east-1:887078546492:function:sedaily-mbti-time-machine-dev","Input":"{\"warmup\":true}"}]' \
    --region us-east-1
  # 기대 출력: "FailedEntryCount": 0
  ```

- 확인

  ```bash
  aws events list-targets-by-rule --rule sedaily-mbti-lambda-warming --region us-east-1 --query 'Targets[].[Id,Input]' --output text
  # post·search·v2-feed·time-machine 네 줄, Input 모두 {"warmup":true}
  aws lambda get-policy --function-name sedaily-mbti-time-machine-dev --region us-east-1 --query Policy --output text
  # Sid lambda-warming-permission(events.amazonaws.com, SourceArn = 규칙 ARN)과 apigw-time-machine
  aws logs tail /aws/lambda/sedaily-mbti-time-machine-dev --since 15m --filter-pattern warmup
  # 5분마다 'warmup' 한 줄. 400 응답이나 'warmup 준비 실패'가 보이면 아래 되돌리기
  ```

- 되돌리기 — 대상을 먼저 빼고 권한을 지운다(기존 세 대상은 건드리지 않는다).

  ```bash

  aws lambda remove-permission --function-name sedaily-mbti-time-machine-dev --statement-id lambda-warming-permission --region us-east-1
  ```

- 비용 태깅 판단: 새 AWS 리소스를 만들지 않는다. 이미 있는 규칙(`Service=atlas4` 태그)에 대상을 하나 더하고, 이미 있는 함수에 리소스 정책 문장을 하나 더할 뿐이다. 둘 다 태그를 붙이는 자리가 아니라 [`비용태깅_규칙.md`](../../architecture/비용태깅_규칙.md)의 생성 전 태깅 대상이 아니다. 늘어나는 비용은 time-machine 함수 호출(5분마다, 하루 288회)이고, 그 함수에는 이미 `Service=atlas4`·`Project=Sedaily-LENS`·`Environment=dev` 태그가 있어 그대로 귀속된다(2026-10-22 조회). ## 그날 신문 카드를 면 번호 없는 시기에도(2026-10-22)

- 1990~1993년생·1996.8~2017.11.12생(kind day)은 '그날 신문 카드' 버튼 두 곳과 영수증의 그날 서울경제 제목을 못 봤다. `shareableFront`가 진짜 1면(kind front)만 받던 '1면 카드' 시절 조건이 남아 있었다.
- 카드 이름이 '그날 신문 카드', 출처가 '출처 빅카인즈 보관본'이라 그 이유가 없어져 조건을 `(kind front 또는 day) && shown_date === date`로 바꿨다(사용자 승인 A안). 일요일·명절로 다른 날 신문을 대신 보여 주는 경우는 여전히 넣지 않고, 카드·영수증 문구는 그대로다.
