## 배경

결과 화면의 "그날의 서울경제 1면"이 처음 조회하는 날짜에서 서버 2.4~20.5초(중앙값 6.9초, 오후 15~20초) 걸렸다. 캐시가 있는 날은 0.6초다. 2026-10-21 사용자가 권장안 A·B·C·E를 한 번에 진행하기로 승인했다(D 메모리, F 장면 순서·문구, G~K CloudFront·API Gateway 캐시·정적 파일·프로비저닝 동시성은 하지 않음).

같은 날 18:33 KST 무렵부터 빅카인즈 검색 API가 응답하지 않았다(`tools.kinds.or.kr` 루트는 정상, 원인 미확인). 무응답이 이어지면 캐시가 없는 생일은 20초 뒤 502가 된다(이번 변경과 무관, 배포된 Lambda도 같음).

## 한 것

반영된 것(브랜치에 있음, 배포 전):

- **C** 빅카인즈 연결(`requests.Session`) 재사용, 그날 기사와 이슈 순위 동시 조회. 기사가 없으면 순위 결과는 버린다. 버린 순위 요청은 Lambda당 한 자리만 쥐고, 동시 요청은 Session을 따로 빌린다.
- **A 서버 소수정** ① 거슬러 간 날(일요일→토요일 등)의 자기 신문 캐시를 재사용 ② 30일 지난 날짜의 0건 결과를 10년 보관 ③ 1990~1993 그날 기사에서 이슈 순위 조회 생략(실호출 13일 모두 `no_match`).
- **B 코드** Lambda가 `{"warmup": true}`·EventBridge 이벤트를 받으면 DynamoDB·SSM 키·달력만 준비하고 바로 돌아간다(빅카인즈 호출 없음). `setup-lambda-warming.sh` 목록에 `sedaily-mbti-time-machine-dev` 추가. 스크립트는 실행하지 않았다.
- **E** 프런트가 같은 날짜 요청을 한 Promise로 공유하고(StrictMode 두 번 실행·미리 요청·결과 화면을 하나로), "타임머신 타기"를 누른 직후에만 미리 요청한다. 실패는 기억하지 않아 "다시 불러오기"가 새로 묻는다.

## 다음

### 1. 배포(사용자) — 빅카인즈가 회복된 뒤

빅카인즈가 무응답인 동안 배포하면 바뀐 점을 확인할 수 없다. 회복을 확인한 뒤 순서대로 한다.

```bash
cd service/backend
./deploy.sh time-machine          # sedaily-mbti-time-machine-dev 하나만 갱신
# 워밍 등록은 배포 뒤에 — 옛 코드는 warmup 입력을 400으로 돌려보낸다.
# time-machine만 넣으려면 아래 「time-machine만 워밍 대상으로 등록」 명령을 쓴다.
# ./setup-lambda-warming.sh       # 그대로 돌리면 article-dev도 대상에 들어간다
```

- zip은 `service/backend`만 담는다(`deployment/package.py`). 작업 트리의 다른 세션 변경(admin/·pipelines/)은 들어가지 않는다.
- 워밍 스크립트는 기존 규칙 `sedaily-mbti-lambda-warming`(5분, `Service=atlas4` 태그 있음)을 다시 설정한다. 새 리소스는 만들지 않는다. 2026-10-21 현재 규칙 대상은 post·search·v2-feed이고, 스크립트를 돌리면 목록의 article-dev와 time-machine-dev가 대상에 더해진다(v2-feed는 남는다). **`./setup-lambda-warming.sh`를 그대로 돌리면 article-dev도 워밍 대상에 들어간다.** time-machine만 넣고 싶으면 스크립트 대신 아래 명령으로 그 함수 하나만 `add-permission`·`put-targets` 한다.

#### time-machine만 워밍 대상으로 등록(2026-10-22 정리, 실행하지 않음)

- **배포(`./deploy.sh time-machine`) 뒤에만 실행한다.** 지금 배포된 옛 코드는 `{"warmup": true}` 입력을 400으로 돌려보낸다. 새 코드(`lambda_handler`)는 `warmup`이나 `source: aws.events`를 받으면 DynamoDB·빅카인즈 세션·달력만 준비하고 `{"status": "warm"}`으로 돌아간다(빅카인즈 호출 없음, 로그 `warmup`).
- 2026-10-22 읽기 전용 조회로 본 지금 상태
  - 규칙 `sedaily-mbti-lambda-warming`: `rate(5 minutes)`, ENABLED, 기본 이벤트 버스, 태그 `Service=atlas4`·`Project=Sedaily-LENS`·`Environment=dev` 등.
  - 대상 3개: `sedaily-mbti-post-dev`·`sedaily-mbti-search-dev`·`sedaily-mbti-v2-feed-dev`. Id는 함수 이름과 같고, Input은 모두 `{"warmup":true}`다.
  - 기존 대상의 권한 Sid는 `lambda-warming-permission`(principal `events.amazonaws.com`, SourceArn 규칙 ARN)이다. time-machine 함수의 리소스 정책에는 API Gateway 권한(`apigw-time-machine`) 하나뿐이라 같은 Sid를 새로 넣을 수 있다.
- 등록 — 권한을 먼저 넣고 대상을 넣는다. `put-targets`는 적은 대상만 더하거나 고치고, 기존 세 대상은 그대로 둔다.

  ```bash
  aws lambda add-permission \
    --function-name sedaily-mbti-time-machine-dev \
    --statement-id lambda-warming-permission \
    --action lambda:InvokeFunction \
    --principal events.amazonaws.com \
    --source-arn arn:aws:events:us-east-1:887078546492:rule/sedaily-mbti-lambda-warming \
    --region us-east-1

  aws events put-targets \
    --rule sedaily-mbti-lambda-warming \
    --targets '[{"Id":"sedaily-mbti-time-machine-dev","Arn":"arn:aws:lambda:us-east-1:887078546492:function:sedaily-mbti-time-machine-dev","Input":"{\"warmup\":true}"}]' \
    --region us-east-1
  # 기대 출력: "FailedEntryCount": 0
  ```

- 확인

  ```bash
  aws events list-targets-by-rule --rule sedaily-mbti-lambda-warming --region us-east-1 --query 'Targets[].[Id,Input]' --output text
  # post·search·v2-feed·time-machine 네 줄, Input 모두 {"warmup":true}
  aws lambda get-policy --function-name sedaily-mbti-time-machine-dev --region us-east-1 --query Policy --output text
  # Sid lambda-warming-permission(events.amazonaws.com, SourceArn = 규칙 ARN)과 apigw-time-machine
  aws logs tail /aws/lambda/sedaily-mbti-time-machine-dev --since 15m --filter-pattern warmup
  # 5분마다 'warmup' 한 줄. 400 응답이나 'warmup 준비 실패'가 보이면 아래 되돌리기
  ```

- 되돌리기 — 대상을 먼저 빼고 권한을 지운다(기존 세 대상은 건드리지 않는다).

  ```bash
  aws events remove-targets --rule sedaily-mbti-lambda-warming --ids sedaily-mbti-time-machine-dev --region us-east-1
  aws lambda remove-permission --function-name sedaily-mbti-time-machine-dev --statement-id lambda-warming-permission --region us-east-1
  ```

- 비용 태깅 판단: 새 AWS 리소스를 만들지 않는다. 이미 있는 규칙(`Service=atlas4` 태그)에 대상을 하나 더하고, 이미 있는 함수에 리소스 정책 문장을 하나 더할 뿐이다. 둘 다 태그를 붙이는 자리가 아니라 [`비용태깅_규칙.md`](../../architecture/비용태깅_규칙.md)의 생성 전 태깅 대상이 아니다. 늘어나는 비용은 time-machine 함수 호출(5분마다, 하루 288회)이고, 그 함수에는 이미 `Service=atlas4`·`Project=Sedaily-LENS`·`Environment=dev` 태그가 있어 그대로 귀속된다(2026-10-22 조회). Bedrock 호출은 없다.
- 확인: 캐시 없는 날짜 1~2개를 골라(아래 GetItem이 빈 결과인 날) 한 번씩만 부른다. 빅카인즈를 실제로 부르는 호출이다.

  ```bash
  D=2001-04-17   # 예시 — 먼저 캐시가 없는지 본다
  aws dynamodb get-item --region us-east-1 --table-name sedaily-mbti-articles-dev \
    --key "{\"news_id\":{\"S\":\"timemachine_frontv2_$D\"}}" --projection-expression news_id
  curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' \
    "https://chzwwtjtgk.execute-api.us-east-1.amazonaws.com/dev/time-machine?front=$D"
  aws logs tail /aws/lambda/sedaily-mbti-time-machine-dev --since 15m --filter-pattern warmup
  ```
