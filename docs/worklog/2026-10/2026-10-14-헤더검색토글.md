# 공통 헤더와 레터 UI 추가 다듬기

관련: `feat/uiux-global-polish` → `main`

## 배경

- 공통 UI·기사 화면 다듬기 이후 사용자가 헤더 검색 X 토글, 선택 탭 표시, 넓은 화면의 지면 탭 줄바꿈, 레터 북마크 크기를 추가로 요청했다.
- 최종 요청은 작업 기록·커밋·push·일반 PR 생성이다. 검증 문서와 화면 증거는 커밋에서 제외하고 배포하지 않는다.

## 한 것

- 아래 본문 폭을 유지하며 헤더를 최대 1320px와 같은 좌우 여백에 맞췄다. 카테고리·최신 뉴스에서도 공통 상단 메뉴를 유지하고 현재 탭은 파란색·볼드로 표시한다. 아래 부탭의 선택선은 유지했다.
- 검색이 열리면 같은 위치에 X를 제공하고 다시 클릭하면 닫는다. HTML dialog의 포커스·Escape·배경 닫기를 유지하며 폭 변경 시 X 위치를 맞춘다. 스크롤 잠금을 문서 루트에 적용해 스크롤 중 헤더가 밀리는 문제도 수정했다.
- 지면 탭은 넓은 화면에서 글자 길이에 맞는 폭으로 한 줄을 유지하고, 480px 이하에서는 지면명/1면의 균등한 두 줄을 사용한다.
- 레터 목록·상세 북마크 SVG를 16px에서 22px로 키웠다. 기존 44px 클릭 영역, 버튼 위치, 아이콘 모양·색, 저장·해제 기능은 유지했다.
- 모바일 메뉴 폭, 데스크톱 푸터, 웹툰·완독·형식 이동·공유·듣기 수정은 [전날 작업 기록](2026-10-13-uiux-반응형점검.md)에 이어서 기록했다.
- 최종 제품 코드와 기존 검증 대상의 콘텐츠 해시를 대조했다. 동일한 최종 코드의 프로덕션 빌드·타입 검사를 재사용하고 변경 22파일 ESLint, 기존 테스트 68개, 레터 파서 테스트 12개, diff check를 PR 준비 단계에서 확인했다.
- 공용 헤더 16화면에서 1920→320→1920px 축소·확대, 검색·키보드·링크·스크롤 잠금/복원을 확인했다. 홈·지난 지면의 네 탭과 480/481px 경계, 레터 목록·상세 저장/해제·새로고침을 별도로 확인했다.

## 결정

- 제품 코드 22파일과 작업 기록 2파일만 커밋 대상으로 삼는다. 검증 문서·스크린샷·trace·측정 스크립트는 저장소 밖에 보관한다.
- 하네스의 외부 통신·콘솔 게이트와 목록의 복수 버튼 선택자 실패는 전체 합격으로 표현하지 않는다. 해당 기능은 첫 버튼을 명시한 독립 브라우저 검사에서 통과했고, 실패 증거도 저장소 밖에 보존한다.
- 실제 단말 Safari/Chrome, 운영 인증·구독·계정 동기화, 모든 콘텐츠 조합은 미검증이다. 북마크 백엔드·API 계약·저장 로직은 이번 PR에서 변경하지 않았다.
- PR 준비 시 origin/main은 e2bd63ea(PR #100 API 클라이언트 공용화)였다. 현재 작업 기준 fca2e9e9와 비교해 UI 수정 파일은 겹치지 않았다. 기존 브랜치 이력을 유지하며 이 PR에 다른 작업을 섞지 않는다.

## 다음

- 공통 탐색과 기사·레터 UI 변경을 일반 PR로 리뷰한다. 운영 배포는 사용자 요청 전까지 진행하지 않는다.
