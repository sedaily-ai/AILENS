# 2026-10-02 기사 상세 UI 개편 · 모바일 성능 · SEO 정본 통합

작성: Claude Code (요청: 문영광)
관련: 프론트 ECS 개정 41→43, CloudFront E1QS7PY350VHF6(`/_next/image*` 동작 추가), 파이프라인 `sedaily-lens-frontpage-auto` 개정 94, `service/frontend/infrastructure/cloudfront-next-image.sh`

## 배경

구글 검색 노출이 약하다는 문제의식에서 시작해 기사 상세 UI를 에듀테크 느낌으로 다듬고, Search Console 자료(색인 4,120건 / 3개월 클릭 153·노출 4,159 / 모바일 노출 비중 14%)와 모바일 실측(홈 LCP 약 49초, 폰트 4.3MB, 홈 이미지 7.3MB)을 근거로 성능·SEO 구조를 고쳤다.

## 한 것

- UI: 용어 풀이(문장 선택 팝오버, 런타임 AI 비용 0), 용어 흰 카드 툴팁, 챕터 헤더(`02 / 06` 알약+질문 면), 상단 진행 바 챕터 단위 칸, 따옴표·금액 자동 강조(`renderInline.tsx`), 타이포 값 조정(행간 1.8, 본문 #191919, 강조 600), 스케치 톤(손으로 그은 구분선·밑줄·체크, 모서리 불규칙), 읽기 강조색 서울경제 CI 파랑(`READING_ACCENT #5b8def`), 형식 탭 sticky 해제, 맨 위로 버튼, 웹툰 탭 몰입형(레일 숨김·컷 920px·틈 없이·상단 칸 진행·레터로 잇기 버튼), 웹툰 대사 전문은 sr-only로 DOM 유지.
- 웹툰 파이프라인: `compose_text.py`에 배율 도입(1.5배 합성, 1.0 배율은 원본과 픽셀 동일 검증), 컷 WebP q90 업로드(컷당 2.2MB→약 0.3MB). 다음 `mustknow-auto` 실행(08:00 KST)부터 적용.
- 성능: Pretendard 가변 동적 서브셋(폰트 4.3MB→약 1MB), 이미지 최적화(`/_next/image`, 홈 이미지 7.3MB→0.86MB), CloudFront에 `/_next/image*` 전용 캐시 정책·동작 추가, `deploy.sh`에 CloudFront `/*` 무효화 추가·ALB 직접 헬스체크 시간 초과로 exit 28 나던 문제 수정.
- SEO: 웹툰·영상·오디오 페이지 canonical을 같은 기사(lens) 페이지로 통합(`shared/lib/seo/lensCanonical.ts`), 사이트맵에서 `/webtoon|video|listen/{id}` 제외(URL 3,754→1,754), 이미지 사이트맵이 비어 있던 버그 수정(lens 항목에 images 537건), 영상 정보는 lens 항목 videos로 이전, 2페이지 이후 목록 noindex,follow, 옛 `/lens/{slug}`를 한 번의 308로(예전엔 308→307 2단 이동).

### 추가(2026-10-02 새벽)

- robots.txt: 24개 검색 봇 그룹의 `Disallow: /_next/` 제거. 구글은 가장 긴 규칙을 우선해 `Allow: /`를 이겨 JS·CSS·폰트·이미지 변환(`/_next/image`)이 막혀 있었다(Search Console "robots.txt에 의해 차단됨" 폰트 11건). 파이썬 `robotparser`는 첫 일치 규칙을 따라 "허용"으로 오판하므로 구글식 판정기로 확인.
- 웹툰 페이지 정본 복원(정정): "panels가 비어 있는 얇은 페이지"라는 근거는 목록 API가 응답 경량화로 panels를 비워 내려주는 것을 오해한 것. 단건 조회엔 컷 8장이 오고 서버 HTML에도 컷이 있으며 검색 실적(클릭 29)도 있었다. 웹툰·영상은 자기 정본·사이트맵, 오디오만 기사로 통합. 사이트맵 3,754개(기사 1,754 + 웹툰 1,000 + 영상 1,000).
- 레터 장애: 2026-10-01 12:00 KST 실행이 발행한 4건이 레터 1문단(리드 한 줄)뿐이었다(최근 240건 중 4건, 나머지는 13문단). 같은 시간대 lens-cms-api가 시간 초과·404를 내 프롬프트 로드가 파일 폴백(컨테이너에 없음)으로 떨어졌고, 아무 검사 없이 발행됐다. 파이프라인에 레터 6문단 미만 재생성(최대 2회)·발행 보류와 프롬프트 로드 3회 재시도 추가(개정 95). `scripts/repair_short_letters.py`로 4건을 13문단으로 복구(다른 포맷·필드 동일 검증, 백업 보관). 국고채 글은 웹툰 컷·영상이 없는 채라 별도 복구가 필요(미처리).
- PR #43(`cms/multi-format-prompt-lab` → main, 202개 파일)으로 저장소를 배포 상태와 맞춤.

## 결정

- 손글씨 폰트(Gaegu)는 시험 후 제외 — "유아틱하다"는 피드백. 손맛은 선과 모서리에만.
- 커스텀 `loader`는 쓰지 않는다 — 내장 `/_next/image`가 꺼져 404. 기본 로더 + remotePatterns 3곳.
- 배포 순서는 CloudFront 설정 → 프론트. 기본 캐시 정책이 쿼리스트링을 버려, 순서가 바뀌면 이미지가 전부 깨진다.
- 영상·오디오 3.7MB 선로딩 문제로 보고했던 것은 측정 오류(Range 요청의 content-length 합산). 실제 232KB라 코드 변경 없음. 실제 바이트는 CDP `Network.dataReceived`로 잴 것.
- 덧붙인 보강 텍스트(IssueContextSection)를 줄여 중복을 해소하려던 시도는 되돌림 — 기사 페이지 HTML이 4형식의 글을 전부 담고 있어 중복 비율이 오히려 올랐다(웹툰 78→88%). 중복의 근본은 "한 페이지에 4형식 전문 + 형식별 페이지" 구조.
- 기사 페이지의 숨은 영상 탭을 클릭 시 로드로 바꾸는 건 하지 않음 — Search Console 영상 색인 926건 오류는 구글의 보고일 뿐 실해가 없고, 영상·오디오 선로딩은 실측 232KB로 작다(처음 3.7MB로 보고한 건 Range 요청 content-length 합산 오류).
- 보류: JSON-LD image 16:9·4:3·1:1 3종(크롭 URL 필요), `/timeline/{날짜}` 730개 사이트맵 정리, 읽어주기(음성 합성).
