## 사이클 1 — 7단계 위저드를 질문 2개로

### 문제 발견
- 홈 헤더 카피 "당신의 일상에 맞춘 뉴스를 준비했어요" 직후 독자 질문 발생 예상: "내 일상이 뭔지?" — 출처: 사용자 의견(데이터 아님)
- 기존 `/start` 구조: 목표 → 포맷 → 체험 → 관심분야 → 결과 → 구독 → 완료 = 7단계
- 사용자 직접 지적: "어려우면 이탈", "간단하고 직관적이어야" (스크린샷 기준 체험 단계 = 카드 46장 슬라이더, 빈 화면 + 진행바 6칸)
- 기존 진입 경로: 피드 상단 12.5px 회색 텍스트 링크 1줄 + 닫기 버튼(발견성 낮음)
- 기존 완료율·이탈 단계 지표: 미측정(기준선 없음)

### 문제 정의
- 독자가 자기 상황을 직접 정의해야 하는 질문 구조 + 결과 전 단계 과다(7) → 결과 도달 전 이탈 우려
- 판단 근거는 구조 비교와 사용자 피드백이며 실측 이탈률은 없음

### Why
- 홈이 "일상에 맞춘 뉴스"를 약속한 직후 첫 경험이 7단계 설문이면 약속과 경험의 불일치 발생
- 포맷(레터·웹툰·팟캐스트·영상) 4종 존재 이유가 "같은 기사를 상황별로 다르게" — 온보딩이 이 제안을 1분 안에 체험시키는 유일한 경로
- 미착수 시 손실: 포맷 다양성이 사용자에게 선택 근거 없이 노출 유지

### How
- 선택: 일상을 묻지 않고 "하루의 틈" 장면 4개 중 1개 선택(알아보는 방식) → 선택 즉시 결과 + 기사 체험
- 장면 4개: 점심 먹고 남은 10분 / 퇴근길 지하철 / 출근길 걸으며 / 자기 전 침대
- 참고 자료에서 가져온 관점: KOSAC 기획서(상황 해시태그 장면 방식), 카피 플랫폼(특성→혜택→컨셉), 발상법(상황 설정 우선)
- 버린 대안: ① 인물 페르소나(이름·나이) — "나는 이 사람이 아닌데" 위험 ② MBTI 직접 질문 — 질문 증가·"모르겠다" 이탈 ③ 복수 선택 + 다음 버튼 — 클릭 수 증가
- 쉬워지는 것: 클릭 2회로 기사 도달 / 어려워지는 것: 장면 4개로 커버 못 하는 사용자 존재
- 사전 부검("실패했다면 왜"): 장면→포맷 매핑이 틀림 / 장면에 해당하는 사람 부재 → 대응: "나중에 할게요" 항상 노출 + 포맷 칩으로 직접 변경 가능
- 제거: 목표 질문·관심분야·구독·완료 단계, 5초 자동 진행 타이머, 46장 체험 슬라이더, 상단 배너(`DiscoveryBanner`)
- 진입: 홈 헤더 부제 아래 링크("내 일상이 뭔지 모르겠다면, 하루를 같이 떠올려볼까요 →")

### 가설 / 검증
- 정량 실험 미실행 — 기준선 부재로 성공 기준 수치 미확정(초안: 완료율 기존 대비 1.5배 이상, 선택 직후 기사 열람률 50% 이상)
- 반증 조건: 완료율만 상승하고 열람이 불변 → 장면 카피 수정(재실험) / 둘 다 불변 → 기존 위저드 복귀
- 측정 방법(구현 완료): 이벤트 `onboarding_moment_select` · `onboarding_glance_select` · `onboarding_result` · `onboarding_result_tab` · `onboarding_result_slide` · `onboarding_result_stats_toggle` · `format_step_click`(source=onboarding)

### 판정
- 적용 완료 · 프론트 배포 완료(ECS 롤링 300s, CloudFront 무효화 Completed, `/start` 200 확인)
- 효과 판정은 지표 수집 후

## 사이클 2 — 인지 유형 질문(질문 2) 추가

### 문제 발견
- 상황만 묻는 구조에서는 같은 상황의 사용자 간 선호 차이 포착 불가 — 출처: 사용자 의견("같은 상황 속에서 무엇이 먼저 눈에 띄는지")
- AI LENS 컨셉 = 인지 유형 방식(정보를 어떤 형태로 먼저 보는지) → 온보딩 데이터가 컨셉 검증 자산이 될 가능성

### 문제 정의
- 질문 1(상황)은 "언제", 질문 2(눈이 먼저 가는 곳)는 "무엇을" — 포맷 결정에는 둘 다 필요
- 상황 제약(걷기=눈 사용 불가, 점심=소리 불가)과 선호 충돌 시 처리 규칙 필요

### Why
- 질문 1개 추가 비용(클릭 +1) 대비 얻는 것: 16조합(상황 4 × 선택지 4) 데이터 + 상황 제약 반영 결과
- 질문 3(MBTI 직접 입력)은 보류 — 사용자 결정: "선택하게 하는 게 아니라 녹이는 것"

### How
- 선택지: 처음 5개(글·그림·소리·영상·숫자와 표) → 4개로 축소 — 사용자 의견("4가지가 깔끔")
- 숫자와 표 선택지 삭제 — 통계·차트 컷을 가장 많이 보여 주는 영상 설명에 흡수("움직이는 화면과 그래프")
- 순서: 글 → 그림과 사진 → 소리 → 영상(기사 형식 순서와 일치)
- 포맷 결정 규칙(가설): 글→레터 / 그림과 사진→웹툰 / 소리→팟캐스트 / 영상→영상
- 상황 제약: 걷기(레터·웹툰·영상 차단) → 팟캐스트 대체 / 점심(팟캐스트 차단) → 레터 대체 / 대체 시 사유를 결과 문구에 표기
- 구현: `lib/moments.ts` `resolveFormat` — 대체 여부 이벤트 `adjusted` 로 계측

### 가설 / 검증
- 핵심 검증 지표(미실행): 선택한 유형 vs 2주 뒤 실제 최다 소비 포맷의 일치율
- 생략 사유: 배포 직후 수집 시작 단계
