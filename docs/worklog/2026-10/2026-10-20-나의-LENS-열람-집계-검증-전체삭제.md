# 2026-10-20 나의 LENS 열람 집계 검증과 전체 삭제

## 배경

사용자는 최근 90일 분야 편수가 실제로 계산되는지 검증하고, 오류가 있으면 수정하며, 확인 절차를 거치는 열람 기록 전체 삭제 기능을 요청했다.

## 확인한 집계 경로

- 기사 `useLensFormatTabs`와 레터 `LetterDetailView`가 `useNewsReadingSignal`을 호출한다.
- 로그인한 사용자는 콘텐츠 식별자 확인 → 열람 세션 생성 → 화면에 보인 시간 보고 순서로 저장한다. 숨긴 탭과 화면 밖 콘텐츠의 시간은 제외한다.
- CMS `activity_repo.accept_event`가 클라이언트 표시 시간과 서버 경과 시간을 검증한다. 둘 다 10초 이상이면 `user_content_views`에 계정·콘텐츠별 최근 열람을 저장한다.
- `recommendation_repo.inputs`는 최근 90일의 `user_content_views`와 기존 `user_readings`를 합쳐 콘텐츠 키 중복을 제거하고 분야별 `count(DISTINCT content_key)`를 계산한다.
- 계정 API `recommendations.profile`은 분야별 편수 순서의 상위 5개를 제공하고, 웹은 `distinct_contents`를 표시한다. 한 글이 여러 분야에 속한 레터라면 각 분야에 포함될 수 있다.
- 실제 PostgreSQL 테스트에서 열람 보고 → 편수 증가, 같은 글 재열람·기존 기록과의 중복 제거, 90일 제외, 다른 계정 분리를 확인했다. 운영 로그인 계정의 화면 숫자와 DB를 직접 대조한 검증은 아니다.

## 한 것

- `useReadingSignals.ts`: 계정 열람의 서버 저장이 실패해도 브라우저 캐시가 먼저 저장되던 경로를 수정했다. 서버의 `viewed=true` 응답 후에만 계정 캐시를 남긴다. 비로그인 브라우저 기록은 기존 기준을 유지한다.
- 계정 API와 CMS에 `DELETE /activity/history`를 연결했다. 공개 경로는 `/api/v2/me/activity/history`이며 인증 사용자만 대상으로 한다. 요청 본문은 `{"confirm":true}`만 허용한다.
- CMS `clear_history`는 계정 잠금과 한 트랜잭션으로 모든 기간의 열람·기존 읽기 기록·세션·이벤트를 삭제한다. 세션 삭제를 막는 예전 완료/리워드 원장 FK도 정리한다. 기존 세션 재전송은 404가 되어 기록을 다시 만들 수 없다.
- 북마크, 저장 문장, 팔로우, 관심 설정은 유지한다. 부분 실패 시 모두 롤백된다.
- 분야 목록 아래 `열람 기록 전체 삭제` 버튼과 네이티브 확인창을 추가했다. 삭제 범위·복구 불가·보존 항목을 설명하고, 취소 버튼에 초기 포커스를 둔다. 처리 중 중복 클릭과 창 닫기를 막고 실패 메시지를 표시한다.
- 서버 삭제 확인 후 해당 계정의 브라우저 기록을 지우고, 다른 탭의 기존 측정도 중단한다. 대시보드 변경 이벤트로 집계와 추천을 다시 조회한다.
- 배포 선행 권한 검사에 `user_readings`의 SELECT/DELETE 권한을 추가했다. DB 구조 변경은 없다.
