# 2026-10-14 CMS 영상 다시 만들기 — 기사 하나의 영상을 프롬프트로 내용·디자인까지 고쳐 교체

작성: Claude Code
관련: 브랜치 `feat/cms-video-prompting` (PR), 사용 안내 [`docs/backoffice/영상_다시_만들기_사용법.md`](../../backoffice/영상_다시_만들기_사용법.md)

## 배경

- 자동 발행 영상 중 이상하게 나온 1~2건을 사람이 고칠 방법이 없었다. 영상 탭(프롬프트 실험실)은 시험만 되고, 4가지 시선 편집 화면의 [저장]은 화면에 없는 필드(영상 썸네일·대본·원문 사진 등)를 지운다.
- 영상 디자인은 렌더 템플릿(`pipelines/video/src`)에 고정돼 프롬프트로 바꿀 수 없었다. AI는 각본 내용만 정하고, 렌더러는 정해진 JSON만 읽는다.
- 전달받은 종이 질감 템플릿(Remotion, 고정 각본 1편용)을 사이트 각본으로 쓸 수 있게 해 달라는 요청.

## 한 것

- **렌더 템플릿** (`pipelines/video`)
    - 각본 스키마(`src/lib/schema.ts`)에 선택 항목 추가: 최상위 `design`(theme·paper·spot·endCard), 컷별 `style`(layout·paper·transition·emStyle·kicker·sub·note·tag·stamp·holdSeconds), diagram 노드 `sub`. 목록 밖 값은 `.catch`로 그 항목만 버린다.
    - 종이 질감 컴포지션 `NewsVideo-Paper` 추가(`src/paper/`). 전달받은 템플릿 부품을 옮기고, 사이트 각본 → 종이 화면 변환(`convert.ts`), 컷마다 나레이션 음성 재생, 컷 길이 = TTS 길이 + holdSeconds. 글꼴은 각본 글자에 맞는 Google Fonts 조각만 종이 컴포지션에서 불러온다(기본 렌더에는 영향 없음).
    - 고정 각본 기준이던 글자·도장·막대 크기를 글자 폭(한글 1, 숫자 0.62 …)으로 계산해 칸 안에 맞춤. 막대 5~6개, 긴 자막, 긴 도장 글자 대응.
    - `render.ts`·`render-lambda.ts`가 `design.theme === "paper"`면 종이 컴포지션(가로형 고정)을 고른다(`compositionFor`). 기본 각본은 기존 그대로.
    - `render_from_script.py`에 `--photo-url`/`--photo-credit`(photo 컷용 원문 사진).
- **CMS 서버** (`admin/backend`)
    - `routes/video_remake.py` 신설, `chat_ws.py`에 WS kind `remake_load`·`remake_script`·`remake_apply` 추가, `render_video`에 원문 사진 전달.
    - 수작업 프롬프트는 별도 이름 `video-remake/published`. 저장 전에는 `video/published` + 디자인 안내로 시작한다.
    - 원문: 기사 XML 공개 API(`/s3-articles?date=` → `/s3-article/{news_id}`) → lens-cms-api `/api/v2/articles/{no}` → 직접 붙여넣기 순. lens-cms-api 기사 표에는 자동 발행 기사 원문이 대부분 없다(영문 서비스용 일부만 수집, 10-14 확인).
    - 교체: `posts_repo.update(…, channel="video")`(lens-cms-api 채널 단위 저장)로 video_url·thumbnail_url·transcript만 갱신 + revalidate.
- **CMS 화면** (`admin/frontend`)
    - `components/VideoRemakePanel.tsx` 신설, 4가지 시선 편집 화면(`lens/edit`)에 [영상 다시 만들기] 버튼. 원문 → 수작업 프롬프트 저장 → 각본 생성·수정 → 렌더·미리보기 → 교체.
- **시험(로컬)**: 실제 기사(CES 2027)로 원문 조회 → Bedrock 각본(디자인 항목 포함) → Polly 음성 → 종이 질감 렌더 성공(23초, 1920×1080, 이 PC 약 5분).
- **배포(10-14)**
    1. 롤백 기록: ECR latest `sha256:31ea9a44…`(10-12), admin Lambda CodeSha256 `vXLO0hgZ…`, 렌더 서버 틀 백업 `s3://remotionlambda-useast1-criescup5q/sites-backup/ailens-video-lab-20261014/`(332개 파일).
    2. 렌더 서버 틀: `npx remotion lambda sites create src/index.ts --site-name=ailens-video-lab` (주소 그대로).
    3. 콘텐츠 공장 이미지: 빌드 후 push → ECR latest `sha256:2eb1f64b…`(11:35). 12:00 mustknow 회차가 새 이미지로 정상(발행 5, 영상 누락 0, 실패 0).
    4. CMS 서버: `deploy-admin-api.sh` → CodeSha256 `pUCHMso2…`(12:31). 배포본에 새 파일 포함 확인.
    5. CMS 화면: `deploy-admin.sh`. 첫 배포는 `.env.local` 없이 빌드돼 API 주소가 비어 대시보드가 `<!DOCTYPE … is not valid JSON` 오류 → `.env.local` 만들고 재배포해 복구.
- **운영 영상 프롬프트**: 프롬프트 실험실에서 §7 디자인 지정(type과 layout 구분, 허용 조합표, 값 목록, 자연어 변환 규칙, 완성 예시), 검수용 `[디자인 메모]`, 체크리스트 디자인 항목을 넣은 버전을 v44로 프로덕션 적용(편집자 요청이 없으면 디자인 항목을 쓰지 않는다).

## 결정

- **디자인 값은 각본(JSON) 안에 둔다.** 공장 검사(`fix_script`)는 모르는 키를 지우지 않고, 스키마만 열면 CMS→공장→렌더 서버로 따로 값을 넘길 장치가 필요 없다. 별도 `--theme` 인자 방식은 버렸다.
- **수작업 프롬프트를 메인과 분리**(`video-remake`). 기사 하나 고치려다 자동 발행 프롬프트를 발행하는 사고를 구조적으로 막는다.
- **WebSocket 프레임 한도(32KB)** 때문에 프롬프트·원문은 소켓에 싣지 않고 서버가 읽는다. 프롬프트는 먼저 저장해야 각본 생성에 쓰인다.
- **영상 교체는 채널 단위 저장**만 쓴다. 편집 화면 [저장]의 필드 유실 문제는 이번 범위 밖으로 남겼다.
- **새 AWS 리소스·권한 없음.** S3 복사 대신 렌더 결과(`media/video-lab/{job}.mp4`)를 그대로 쓴다. 버킷 수명 주기는 "덮어쓴 이전 버전 90일 후 삭제"뿐이라 현재 객체는 남는다.
- 첫 컷의 1면 레이아웃 등 종이 질감 연출은 각본에 없는 정보(카드 설명, 손글씨 등)가 필요해, 프롬프트(§7)로 AI가 채우게 했다. 원본 템플릿처럼 기사마다 코드를 짜는 방식은 자동 발행에 맞지 않아 버렸다.
