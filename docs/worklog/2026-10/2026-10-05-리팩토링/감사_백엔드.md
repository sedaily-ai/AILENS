## 8. 배포/설정

- deploy.sh: `((SUCCESS_COUNT++))`, `((FAIL_COUNT++))`를 `set -e` 하에서 사용 — 값이 0일 때 종료 코드 1. 이 머신의 bash(3.2)에서는 재현되지 않았으나 bash 4/5(Linux CI 등)에서는 첫 증가에서 스크립트가 중단될 수 있음(이식성 위험, 낮음~중간). 함수 목록의 `ws-*`, `voice-*`, `timeline`, `quiz` 등은 핸들러 22개와 대응하는 이름이 있음. 존재하지 않는 모듈을 가리키는 함수는 없으나 폐기된 AWS 쪽 함수(newsletter-subscribe 등)가 코드 목록에서 빠진 채 AWS에는 남아 있을 수 있음(주석에 이미 기록됨).
- deploy.sh pip 목록에서 boto3/botocore는 버전 미고정, requirements.txt에는 opensearch-py/requests-aws4auth/fastapi 등 Lambda에 불필요하거나 죽은 의존성이 남음(opensearch-py, requests-aws4auth는 사용 0).
- deploy.bat: 사실상 깨진 옛 스크립트 — pydantic/pydantic-settings/redis 설치, 존재하지 않는 MBTI_TRANSFORM_PROMPT.md 복사(실패), common/·newsletter/ 미복사(zip에 필수 모듈 누락 시 ImportError), time-machine 함수 한 개만 갱신. 실행 시 장애 위험.
- setup-briefing-lambda.sh: IAM role `sedaily-mbti-lambda-role`(다른 스크립트·코드는 `sedaily-mbti-lambda-execution-dev`) 불일치, 핸들러 경로는 유효. setup-timeline-lambda.sh: 계정 ID·role ARN·API ID 하드코딩. setup-lambda-warming.sh: warmup 이벤트(`{"warmup":true}`)를 search/article/post에 보내는데 warmup 분기를 가진 것은 post_handler와 question_handler뿐 — search/article은 워밍 호출이 실제 요청 경로로 흘러감(워밍 대상 중 2/3는 효과 없거나 에러 로그 유발 가능, 동작 관찰 사항).
- deploy.sh의 메모리/타임아웃/VPC 설정 로직 없음(CLAUDE.md도 인정) — 수동 콘솔 변경값이 문서화되지 않음.
- infrastructure/: provision_pgvector.sh, provision_opensearch.sh 등 삭제된 리소스용 스크립트 잔존.
