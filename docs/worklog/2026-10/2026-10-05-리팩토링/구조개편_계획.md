원칙: 이동·이름 변경만 한다(내용 변경 없음). 한 단계 한 커밋. git mv로 이력 보존. 각 단계마다 단위 테스트 187개, pyflakes, 전 모듈 import 확인.

## 백엔드 (service/backend)
- 단계 1: clients를 저장소 종류별로 — `pg/`(articles, cms_posts, community, newsletter_subscribers, personal), `ddb/`(cms_posts, daily_letters, dynamodb), `s3/`(article_body, xml_articles)
- 단계 2: services를 도메인별로 — `articles/`, `chat/`, `content/`, `timeline/`, `user/`, `market/`
- 단계 3: handlers를 도메인별로 — `articles/`, `chat/`(voice·websocket 포함), `content/`, `timeline/`, `user/`, `system/`. 파일명에서 중복되는 `_handler` 접미사 제거
  - Lambda 핸들러 문자열이 AWS 설정에 박혀 있어(예: `handlers.article_handler.lambda_handler`) 파일 이동은 배포 설정 변경을 동반한다. deploy.sh가 새 경로로 `--handler`를 갱신하고, 전환 순간 오류를 없애려고 패키징 때 옛 경로 shim을 자동 생성해 같은 zip에 넣는다(저장소에는 shim을 두지 않는다)
- 보류: common/·core/·utils/ 세 공용 폴더 통합(import가 전 코드에 퍼져 있어 별도 단계)
