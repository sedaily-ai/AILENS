# 나의 LENS 대시보드 구현과 백엔드 개발 인계

작성일: 2026-10-14 · 작업 브랜치: feat/my-lens-dashboard

## 배경

뉴스·레터 이용 분야와 키워드, 직접 고른 관심사, 담은 문장과 저장 레터를 연결하는 개인 대시보드를 구성한다. 기존 내 서랍의 저장·삭제·주소를 유지하고, 기획을 모르는 백엔드 개발자가 기존 프로젝트 구조에서 후속 기능을 구현할 수 있도록 인계한다.

## 한 것

- 밝은 LENS 톤의 `/my-lens`를 추가하고 홈·내 서랍·읽기 기록/리워드·관심사/알림을 실제 URL 메뉴로 분리했다.
- 로그인 사용자 메뉴의 내 서랍 진입을 ‘나의 LENS’로 통합했다. 기존 `/?tab=archive` 주소와 문장 저장·삭제는 유지한다.
- 뉴스·레터 상세의 visible 체류 기반 약한 관심 신호를 계정/브라우저 scope로 저장하고, 분야·등록 키워드·선택 관심·문장 단어를 뉴스 추천 근거로 연결했다.
- 기존 관심 레터 피드의 추천 이유와 목록을 병합했다. 읽을 시간 0/5/10분의 묶음, 저장/미열람 필터, 최신 목록 밖 저장 레터 복원, 팔로우 에디터를 연결했다.
- 홈에서 담은 문장 최대 3개를 요약하고 내 서랍의 검색·복사·삭제·원문 및 문장별 관련 뉴스로 연결했다. 저장·삭제 후 관련 화면 갱신 이벤트를 공유한다.
- 관심 설정을 선택 요약·9개 분야·분야별 주제/전체 검색으로 정리했다. 기존 선택 보존·합계40개 제한·취소·저장 실패 상태를 처리했다.
- 주간 스탬프 오른쪽 요약과 주·월·연 조회 UI, 배지 조건 및 명시적인 달성 예시를 추가했다. 실제 리워드와 구분한다.
- 개인화 푸시 유형·관심 근거·빈도·시간·시간대·주간 요일·중지 설정을 브라우저 초안으로 구성했다. 실제 동의·구독·발송과 구분한다.
- 불필요한 장식 기호·하단 레터 전용 링크·다른 읽기 방식 안내를 제거하고 선택창 화살표·펼치기·보조 호버를 정리했다. 데이터에 포함된 이모지와 기능/리워드 아이콘은 보존한다.
- 후속 요청에 따라 개발 중 비로그인 진입 예외를 종료했다. AuthContext 확인 전에 개인 화면의 훅을 마운트하지 않고 비로그인은 로그인으로 이동한다. 기존 복귀 기능으로 탭·쿼리·해시를 유지하며 로그아웃 시 화면을 내린다.
- 최신 화면과 기존 Lambda→service→repository→내부 CMS API→PostgreSQL을 대조해 제품 인수인계, API 계약, 데이터/코드 배치·원자 처리 설계를 작성했다.
- 서버 개인 서랍 GET의 무인증 user_id 전달 가능 경로와 CMS 응답 id=slug/읽기 FK 차이를 선행 보완 항목으로 명시했다. 기존 읽기 통계·배지를 새 리워드 원장과 구분했다.

## 결정

- 대시보드 진입은 로그인 필수다. 로그인 화면 제한과 서버 인증·계정 동기화 완료를 구분한다.
- 추천은 우선 분야·단어 일치다. 현재 축약 뉴스 목록에는 등록 용어가 없어 후보는 제목·요약의 단어 일치만 활용한다. 본문 등록 용어와 의미 분석·확인된 후속 관계는 서버 연결 범위로 표시한다.
- 레터 저장·팔로우와 알림 초안은 아직 브라우저 범위다. 공용 로컬 자료를 다른 계정에 자동 귀속하지 않는다.
- 약한 열람·기존70% 열람 표시를 보상 완료로 승격하지 않는다. 예시 스탬프·배지와 실제 발송은 현재 미연동 상태로 표시한다.
- 백엔드는 기존 레이어를 재사용한다. 신규 API·테이블·파일은 구현 제안이며 유효 완료·동일 이슈·알림 품질/후속 관계·보존 정책은 별도로 확정한다.
- 기존 서버·DB·AWS·실제 발송과 배포는 이번 대시보드 작업에서 변경하지 않는다.
- 업로드에는 변경 내용과 인계 문서를 포함하고, 화면 캡처·실행 로그·검증 보고서와 상세 검증 기록은 제외한다.
