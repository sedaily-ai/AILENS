# 2026-10-27 생일 타임머신 ECOS 키 교체
작성: 이도연 + Kiro
관련: [`docs/product/birthday-assets/자료갱신_키교체.md`](../../product/birthday-assets/자료갱신_키교체.md), 스크립트 `service/backend/scripts/build_birthday_assets.py`

## 배경
생일 타임머신 100만 원 장면 자료를 받는 ECOS 키(SSM v1)는 비영리로 신청한 키라 사용자가 ECOS에서 폐기했다. 그 뒤로는 월 갱신 스크립트를 돌릴 수 없었다. 영리 키를 새로 받아 SSM에 넣었다.

## 한 것
- 사용자가 `read -rs` 명령으로 새 키를 SSM `us-east-1 /sedaily-mbti/ecos-api-key`에 넣었다(`--overwrite`). 키 값은 채팅·로그·문서 어디에도 남기지 않았다.
- 메타데이터 확인: Version 2, LastModifiedDate 2026-10-27 15:11 KST, KeyId `alias/aws/ssm`, 태그 5개(`Project`·`Environment`·`Service`·`CostCenter`·`ServiceName`) 유지.
- 동작 확인: `build_birthday_assets.py --until 2026-10-20`을 1회 실행(ECOS 호출 6번). 6개 계열 모두 받아짐, `files=64`. 연도 파일은 커밋된 값과 점 하나도 다르지 않았고 `latest.json`은 `generatedAt`만 바뀌었다. 생성 파일은 `git restore`로 되돌렸다.
- 키 교체 문서의 현재 상태·키 위치 표를 v2 기준으로 고쳤다.

## 결정
- 코드와 커밋된 자료가 바뀌지 않아 웹 배포는 하지 않는다. 웹은 정적 JSON만 읽고 ECOS를 부르는 웹·Lambda 코드가 없다.
- 기존 파라미터의 값만 바꾼 일이라 새 AWS 리소스가 아니고, 비용 태그 작업도 없다.
