# 2026-10-12 환각 점검 기사 19건 비공개와 Next.js 보안 업데이트 배포

작성: 이민서 + Claude Code
관련: PR #74(Next.js 16.3.8), PR #64(운영 런북), `docs/worklog/2026-10/2026-10-07-개선계획/06-오류개선-QA-리팩토링.md`(게이트 G2)

## 배경

- 10/9 환각 표본 점검에서 중대 오류가 있는 기사 19건이 나왔다. 발행 기사 100건을 원문과 AI로 대조한 1차 판정이다. 원문에 없는 인용 같은 오류 문장이 사이트에 그대로 공개돼 있었다.
- 10/11 보안 자체 점검의 고위험 2건 중 1건이 웹 프레임워크 보안 업데이트다. 운영 서비스 웹의 Next.js 16.2.2는 공개 보안 공지(치명 등급 포함) 대상이었다.

## 한 것

- **기사 19건 비공개**(10/12 03:21, 사용자 실행)
  - CMS API로 19건을 published에서 draft로 바꾸고, 사이트 캐시 재검증(`/api/revalidate`)을 1회 요청했다.
  - 같은 원문으로 발행된 글이 둘인 1건은 점검한 글만 내렸다.
  - 확인: 19건 주소가 모두 404다. 홈·RSS·feed·llms.txt·사이트맵 4개에서도 빠졌다.
  - 원본 JSON 19건과 일괄 전환·복구 스크립트는 저장소 밖 보고서 작업 폴더에 있다. 기사 제목과 오류 내용은 공개 저장소에 적지 않는다.
- **Next.js 16.3.8 배포**(PR #74)
  - 최신 main(3a65d2d4, PR #73까지) 위로 다시 올려 검증했다.
    - tsc·eslint 오류 0건, vitest 75건, 블록 테스트 12건, 운영 빌드를 통과했다.
    - 로컬 운영 모드 스모크 30건을 통과했다. 레터, 비교 카드 PNG, 위젯 조회, 이미지 최적화(webp)도 정상이었다.
  - 배포 전 드리프트 대조:
    - 운영 사이트맵(core·월별 표본), 홈 링크, 특수 경로를 합친 1,123개 경로의 상태 코드와 리다이렉트를 운영과 로컬 main 빌드에서 비교했다. 차이는 0건이다.
    - 주요 화면 6개의 보이는 문구와 메타 태그도 비교했다. `/about`만 달랐는데, CloudFront에 10/11 13시 캐시가 남아 있던 것이다(age 약 14.8시간, `s-maxage` 1년). 코드 차이는 아니다.
  - 배포: main 339fc2d6에서 `service/frontend/deploy.sh`로 배포했다(03:53~03:58). ECS 태스크 정의 rev 104, 이미지 digest `sha256:09b9c2170db714e879f9d25840e687381a390fe67cdc774d540f84d8839d2d2c`.
    - 운영 스모크 30건을 통과했다. 레터, 비교 카드 PNG, 위젯 조회·스크립트, 이미지 최적화(webp)도 정상이었다.
    - 운영 클라이언트 번들에서 16.3.8을 확인했다.
    - 헤드리스 브라우저로 7개 화면을 열어 콘솔 오류 0건을 확인했다. GA·Clarity 요청은 막고 열었다.
    - 배포 직후 CloudFront 전체 무효화로 `/about`도 새 화면으로 바뀌었다.
  - 롤백용 이전 이미지: rev 103, digest `sha256:ccfa7c786ea2dbda45adf5ad66e4dca13eb15b4583f12bebf03f4e92f0faf132`.

## 결정

- 19건은 고치지 않고 비공개로 내렸다. 사람 확인 전 AI 판정이라 지우지 않고 draft로 두어 되돌릴 수 있게 했다.
- 비용 태그: 새 태스크 정의에는 main의 `tags-ecs.json`대로 `Service=atlas4`가 붙었다.
  - 규칙상 10/1 이후 신규 리소스는 `lens`다. 다만 AI LENS 전체 원복이 아직이라 이번 배포에서만 따로 바꾸지 않았다.
  - 작업 디렉터리를 main과 다르게 만들어 배포하지 않는다는 원칙도 지켰다.
