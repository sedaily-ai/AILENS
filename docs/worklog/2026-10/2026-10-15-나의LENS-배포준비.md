# 2026-10-15 나의 LENS 배포 준비

> 과거 조사·검증 시점의 기록입니다. 현재 통합 범위·배포 상태·미완료 항목은 [2026-10-16-사용자웹-잔여통합-PR준비](2026-10-16-사용자웹-잔여통합-PR준비.md)을 기준으로 확인합니다. 본문의 과거 계획은 이번 실행 지시가 아닙니다.

관련: fix/dashboard-schema-array-types · [배포 실행 명령](../../product/나의LENS/배포실행_명령.md)

## 배경

운영 실행 직전에 멈추는 범위에서 나의 LENS의 계정 API·CMS·프론트·worker 배포 준비를 이어갔다. 기존 미커밋 타입·잠금 권한 v1.55 보완을 유지했다.

## 한 것

- 계정 API 전용 Lambda 대상·신규 dashboard/Gateway/CORS 연결, Python 3.11/x86_64/실제 환경변수 preflight, 코드·경로·CORS 백업/복구를 준비했다. 기존 배포 카운터의 set -e 조기 종료도 수정했다.
- worker를 소스 번들과 systemd oneshot/timer로 공급한다. 기본 dry_run을 강제하고 처리 오류는 실패 종료 코드로 표시한다.
- CMS 릴리스에 v1.48~55 SQL을 포함하고 별도 적용 CLI와 앱 역할·타입·함수 보안 검사를 준비했다. 기존 PM2 환경 파일 보존, 서버 환경 공급, DB preflight 실패 전 코드 보존, health 실패 후 중단을 연결했다.
- 파이프라인 완성 파일의 실측 길이 공급, 편집 확인한 보상/후속/작성자/직접 재생 metadata 관리 CLI를 구현했다. 기본 rollback으로 확인하고 별도 적용한다.
- 출시 UI의 모의 기기/후보/처리 시각은 개발 빌드에만 남겼다. 실제 발송 구성·구독을 표시하고 archive 개인 오류·쓰기 응답도 private/no-store로 통일했다.
- AWS/SSM/DB/PM2 대체 검증, 실제 타입을 재구성한 로컬 DB의 SQL 재실행·권한 검사, CMS 전체 208개 회귀와 공개 계정/worker 41개, 프론트 123개 검사, 타입·lint·pyflakes·쉘 구문·격리 프로덕션 빌드를 확인했다. 임시 자료·백업·로그는 /tmp에만 둔다.

## 결정

- 운영 DB 변경·AWS 변경·배포·실제 푸시·커밋·push·PR을 실행하지 않았다. 실행 명령과 preflight/복구 경로를 제공하는 상태로 멈춘다.
- 앱 역할에 편집 관계 쓰기 권한을 추가하지 않는다. 수동 관리 자료는 별도 승인된 편집 역할이 명시적으로 입력한다.
- 실제 AWS·Cognito·기기·자료량/성능을 로컬 검사 통과로 대체하지 않는다. 격리 빌드는 외부 fetch 차단·글꼴 fixture 조건이며 최종 ARM64 Docker/운영 콘텐츠 인수는 별도다.

## 다음

- 사용자가 실행할 때 실제 비밀·기존 DB 버전/복원·IAM/네트워크·Cognito를 preflight/인수로 확인한다. 실패하면 다음 적용 단위를 중단한다.
- 실제 기기 수신과 worker unknown 관제·운영 알람을 확인한 뒤에만 별도 실발송 활성화를 검토한다.


### 후속 인수 보완

- Gateway 두 함수의 invoke 정책·환경 일치·태그·목록 조회를 첫 변경 전에 검사한다. 코드 ZIP 다운로드 중 실패한 파일을 복구 백업으로 잘못 재사용하지 않도록 임시 파일로 받은 뒤 교체한다.
- DB 첫 DDL 전 실제 앱 연결·선행 테이블/권한/타입을 검사하며 별도 --baseline 명령으로도 실행한다.
- 프론트 신규 task의 Service 태그를 lens로 맞췄다. 기존 실행 이미지 digest를 고정한 롤백 정의를 보존하고 새 task도 digest로 등록한다. 이전 ARN이 latest를 가리키는 복구 오류를 방지한다.
- 공개 JWT handler → 실제 CMS router → 전용 로컬 DB의 계정/추천/완료/리워드/알림 통합 회귀 2개를 추가해 확인했다. 검증 전용 소켓·자격증명은 운영에 사용하지 않는다.

- 후속 최종 검사: CMS 전체 210개, 프론트 123개, 공개 연결 통합 2개, 배포 도구 12개, SQL/메타데이터 도구 8개, 이미지 정의 2개를 확인했다. SSM/PM2 실패 중단과 프론트 읽기 전용 preflight의 서비스/digest/롤링 불일치도 대체 검사했다. 실제 운영 명령은 실행하지 않았다.


### Git·PR 인계 준비

- 배포 담당자가 읽을 문서 순서와 실제 운영 입력·권한 차단 범위를 실행 문서에 추가하고 공개 API README에 account 대상을 반영했다.
- PR 전 독립 검토에서 프론트 latest 재조회 동시성 및 원격 비밀 백업 생성 권한 문제를 확인해 고유 release 태그와 원격 umask 077로 수정했다.
- 운영 DB·AWS 적용과 실제 푸시는 계속 미실행이다. /tmp 검증 환경은 인계되지 않으며 담당자가 실제 비밀과 권한을 준비한다.

- 추가로 Lambda handler 설정 변경 완료 waiter를 넣어 비동기 갱신 중 다음 preflight가 실패하지 않도록 했다. 이번 재검증은 프론트 123개·tsc·변경 파일 eslint, 공개 계정/worker·미디어 43개, 배포 도구 12개·DB 도구 8개·이미지 도구 2개, pyflakes·shell 구문·diff check 통과다. CMS 전체 210개와 격리 빌드 근거는 앞선 동일 구현 검사에서 재사용했고 이번 턴에서는 운영/DB 전체를 재실행하지 않았다.
- 독립 리뷰 후 최종 재검토에서 위 3건의 수정 유효성을 확인했고 추가 확정 결함은 보고되지 않았다. 실제 AWS·SSM 사용자/PM2·ARM64 실행·운영 DB/Cognito는 미검증으로 유지한다. 이는 운영 무결함 판정이 아니다.

### 배포 전 재검증 (후속 세션)

운영 읽기 전용 조회와 로컬 재현으로 배포를 막는 결함 3건을 확인했다. 수정·배포·운영 변경은 하지 않았다.

- 공개 dashboard handler가 stage 접두사를 처리하지 않는다. 운영 HTTP API(stage=dev)는 경로에 `/dev`를 붙여 보낸다(archive Lambda 운영 로그 실측: `GET /dev/api/archive`). `handlers/user/dashboard.py`의 `startswith('/api/v2/me/')` 비교 때문에 인증 뒤 모든 계정 API가 404가 된다. 같은 모양의 이벤트로 재현했다(stage 없음 200, `/dev` 포함 404). 기존 테스트 이벤트에는 stage가 없다.
- `service/backend/deploy.sh`에 새로 넣은 `umask 077` 때문에 pip 의존성과 shim이 600/700 권한으로 zip에 들어간다(로컬 재현: `jwt/__init__.py -rw-------`). Lambda는 644/755가 필요하다. `all`/`api`도 같은 zip을 쓰므로 전 함수에 영향이 간다.
- 운영 archive Lambda 환경에는 `LENS_CMS_API_URL`과 `COGNITO_*`가 없다(키 이름만 조회). 지금은 코드 기본값으로 동작하지만 `account_gateway.py preflight`가 명시 값을 요구하므로 3단계에서 멈춘다.
- 그 밖에 확인한 것:
  - `useServerDashboard`: focus나 저장 이벤트가 생길 때마다 대시보드 전체가 로딩 상태로 바뀐다.
  - 신규 CSS: 11·12px 글자와 하드코딩 색이 들어 있다.
  - env 템플릿: `AWS_PROFILE=`, `PGPORT=`를 빈 값으로 두면 실패한다.
  - `layout.tsx`: 서비스워커를 전역으로 해제한다. 실발송 전 차단 요인이다.
- 운영 상태:
  - dashboard 함수와 `/api/v2/me` 라우트는 아직 없다.
  - CORS 설정이 이미 있어서 병합해도 안전하다.
  - archive 통합은 payload 2.0이다.
  - 프론트 마지막 배포는 10-14 21:09(:115, latest)다. 그 이후 모바일 작업에서 바뀐 웹·공유 패키지 25개 파일도 다음 프론트 배포에 함께 실린다.
- 로컬 재검증:
  - 프론트: tsc 통과, vitest 123개 통과. eslint 오류 20건은 모두 기능 범위 밖의 기존 파일이다.
  - 공개 계정·배포 도구: 64개 통과.
  - CMS: 143개 통과. DB가 필요한 75개는 Docker 미실행으로 건너뛰었다.
- 7cdf68b0은 PR #110으로 main에 머지됐다. `배포준비_이어가기.md`의 "미커밋" 서술은 지난 상태다.

다음: 차단 1·2번을 수정하고 회귀 테스트를 추가한다. archive 환경변수 보완은 운영 설정 변경이라 승인 뒤 진행한다. 그다음 최신 main에서 배포 순서를 진행한다.
