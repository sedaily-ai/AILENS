# 2026-10-20 저장한 기사(기사 저장 버튼 + 내 서랍)

작성: 이도연 + Kiro
관련: 브랜치 `feat/saved-articles`(PR2, PR1 `feat/feature-diet` 위에 쌓음 — [기능 다이어트 작업 기록](2026-10-19-기능-다이어트.md)), SQL `docs/architecture/lens-erd-src/lens_schema_v1.57_2026-10-20.sql`

## 배경

기능 다이어트에서 기사 오디오·비디오, 홈 하단 플레이어의 북마크를 지웠다. 이 북마크는 브라우저에만 남고 다시 볼 화면도 없었다. 대신 기사 자체를 계정에 저장해, 나의 LENS 내 서랍에서 '담은 문장'·'저장한 레터'와 나란히 다시 보게 한다.

## 한 것

- DB v1.57 `user_article_bookmarks`
  - 구조: `(user_id, publication_id)` PK, `saved_at`. users·publications FK는 ON DELETE CASCADE
  - 인덱스: 최신 저장순(user_id, saved_at DESC, publication_id DESC), 기사 실삭제용(publication_id)
  - `lens_service_app` 권한을 준다. 역할이 없으면 WARNING을 남긴다.
  - `SET LOCAL lock_timeout='5s'`. 다시 적용해도 된다(테스트에서 두 번 적용).
  - 배포 묶음(`package_release`)과 점검(`account_schema`)이 v1.48~57을 다룬다.
- CMS(`dashboard_repo.py`, `routes_dashboard.py`)
  - 내부 경로: `GET /internal/personal/lens/article-bookmarks`, `GET·PUT·DELETE /…/article-bookmarks/{id}`
  - 저장 규칙은 레터 북마크와 같다.
    - 새로 저장할 수 있는 기사: 공개 중이고, 목록 카드로 보여 줄 형식이 있는 기사(`load_cards`). 아니면 404
    - 다시 저장해도 처음 저장 시각을 유지한다. 해제는 언제든 된다.
    - 비공개로 바뀐 기사는 `available:false`로 남아 해제만 할 수 있다.
  - 커서 서명에 목록 종류(`kind`)를 넣어 레터 커서와 섞이지 않게 했다.
  - 저장하는 사이 기사가 지워지면(FK 위반) 404로 돌려준다.
- 계정 API(`services/user/dashboard.py`, `handlers/user/dashboard.py`)
  - `/api/v2/me/article-bookmarks`는 `limit`(1~200)·`cursor`만 받는다. `/{id}`는 숫자 ID만 받는다.
  - CMS가 아직 옛 판이라 FastAPI 기본 404를 주면 503이 아닌 404로 넘긴다.
  - Gateway는 이미 `ANY /api/v2/me/{proxy+}`이고 CORS에 DELETE가 있어 바꿀 것이 없다(`deployment/account_gateway.py` 확인).
  - `account_smoke.py --after-cms`: CMS 배포 뒤 목록 200과 DELETE CORS를 확인한다.
- 웹
  - `entities/user`: `articleBookmarksApi`, `useArticleBookmark`(계정별 상태, 로그인 확인 중 대기, 404면 저장할 수 없는 기사로 보고 버튼 숨김)
  - 기사 화면(`ArticleSaveButton.tsx`, `ArticleToolRail.tsx`, `LensViewClient.tsx`)
    - 좁은 화면 도구 줄과 넓은 화면 왼쪽 레일에 '저장'/'저장됨' 버튼을 둔다(aria-pressed, 처리 중 aria-disabled).
    - 상태 조회는 한 번만 하고 두 버튼이 함께 쓴다.
    - 로그인 전에는 돌아올 주소를 남기고 로그인 화면으로 보낸다.
    - 결과는 화면 아래 안내로 알린다: "기사를 저장했어요. 나의 LENS 내 서랍에서 다시 볼 수 있어요." 등
  - 넓은 화면 웹툰 탭: 레일에 저장·공유만 남겨 보이게 했다. 측정상 그림과 72px 떨어져 있다.
  - 내 서랍(`DrawerPanel.tsx`, `DashboardArticle.tsx`, `useArticleShelf.ts`)
    - '저장한 기사' 칩을 더했다. `?kind=articles`로 바로 열 수 있다.
    - 제목·요약 검색, 저장 해제, 로딩·실패·로그인·빈 상태 안내를 넣었다.
    - 공개가 끝난 기사는 "더 이상 볼 수 없는 기사"로 남는다.

## 결정

- 레터 북마크와 같은 모양·규칙을 쓴다(새 경로 대신 같은 패턴). 플레이어 북마크의 브라우저 저장값은 옮기지 않는다(브라우저 값 자동 이전 금지 규칙).
- 저장 가능 기준을 목록 카드 기준(공개 + 볼 수 있는 형식)에 맞췄다. 저장하자마자 '볼 수 없는 기사'로 나오지 않게 하려는 것이다.
- 웹툰 탭은 원래 "그림에 집중"하려고 레일을 숨겼다. 위쪽 도구 줄을 보이게 해 봤지만 버렸다. 탭을 바꿀 때 본문이 58px 밀리고 글자 크기 설정이 레일과 엇갈렸기 때문이다. 대신 레일을 저장·공유 두 개로만 줄였다.
