# 그날로 떠나요 — 생일 시세 타임머신 구현

## 배경

원본 HTML 기획안의 7묶음·18항목을 유지하며 생일 시세 시범판을 LENS에 통합했다.

## 한 것

- 홈 진입과 `/birthday-market` 전용 페이지, 생일 다이얼·숫자 입력·선택 성별, 항목별 상세와 출처를 구현했다.
- 확보된 CPI·GNI·환율 일부 값, 최저임금·연금 규칙과 기존 경제 사건을 연결했다. 생일은 브라우저 메모리에만 두고 연도 공유 링크와 AI LENS 공유 이미지를 제공한다.
- 금액·배율은 기본색, 증감률만 증가 빨강·감소 파랑·0% 중립색으로 통일했다.
- 기능 코드는 `service/frontend/src/features/news-feed/components/birthday/`, 전용 페이지는 `service/frontend/src/widgets/BirthdayMarketPage/`에 있다. 운영 배포는 회의 후로 보류하며 push·PR은 수행하지 않는다. 이번 기능은 별도 기능 브랜치에 커밋한다.

## 검증과 결정

- 기존 생일 기능 테스트 13개, TypeScript·ESLint·프로덕션 빌드 통과. Chromium PC·모바일과 공유 PNG 저장 확인. 초기 빌드에는 외부 기사 조회 네트워크 제한 경고가 있었으며, 아래 최종 검증에서는 외부 응답까지 확인했다. 운영 배포 검증과는 구분한다.
- 1988년 예시 기준 확보 범위에서 작동 4개·부분 연결 4개·자료 대기 10개. 자동 갱신·이용권·정식 출시 완료를 의미하지 않는다. 출생아 수·기대수명은 미연결, 월별 CPI는 두 시점만 보유한다.
- 사용자 요청으로 회의·분석·초기 계획·상세 검증 기록과 초기 독립 시범판을 저장소 밖으로 이동했다. 보관 위치: /Users/ldy/Desktop/LENS 타임머신 기획 및 자료 조사/2026-10-18_구현자료
- 기존 제품 문서와 서비스 실행·유지보수에 필요한 코드·테스트·데이터는 저장소에 유지했다.

## 다음

회의에서 필수 작동 항목·원자료 확보 담당·일정·이용 조건·결측 대체 규칙을 확정한다. 자료 확보·교차 검증·갱신 절차·편집 검수 후 공개 범위를 결정한다. 실물 Safari 검증은 남아 있다.

## 날짜 상한 수정·자료 정리·기능 커밋

- 사용자 승인으로 외부 보관함의 미사용 history.png, 재생성 slide-messages.json, 통합 전 독립 시범판 9개 파일을 삭제했다. 회의 완성본·조사·기획·상세 검증 기록은 보존했고 목록·링크를 정리했다. Git 밖 파일이므로 삭제는 서비스 커밋에 포함되지 않는다.
- 입력 상한은 자료 기준일과 분리해 공용 kstTodayStr의 한국 시간 오늘을 사용한다. 숫자 입력·다이얼·입력 오류 안내·연도 공유 검증·첫돌 여부에 적용했다. 열린 화면은 30초 주기와 포커스/가시성 변경 시 상한을 갱신하며, 통계 자료 기준일·고정 비교값은 그대로다.
- 정적 HTML과 hydration은 같은 날짜 스냅샷으로 시작한 후 브라우저의 현재 날짜로 갱신한다.
- 전체 프론트엔드 테스트 38파일·176개(생일 기능 15개), 전체 TypeScript, 변경 파일 ESLint, 프로덕션 빌드 65개 정적 페이지 생성 통과. 외부 기사 응답도 받았으며 기존 Next 설정·middleware·2MB 초과 캐시 경고는 남는다.
- Chromium 미국 시간대에서 KST 자정 전 미래 날짜 거부→자정 후 허용, 다음 날 거부, 2027년 1월 1일 다이얼 상한을 확인했다. 모바일 390px 가로 넘침 없음, 홈→전용 페이지·18항목·연도 공유 흐름도 확인했다. 시각을 강제 변경한 첫 실행에서 latency 속성 오류가 한 차례 관찰됐으나 정상 흐름 및 재확인에서는 재현되지 않았고 원인은 확정하지 않았다.
- 원격 main과 현재 기준 커밋이 55f86a65로 같은 것을 확인하고 feat/birthday-market-timemachine 브랜치를 만들었다. 생일 기능 관련 37개 파일만 포함하며, 다른 작업인 사이트 기능 다이어트 worklog는 제외한다. 운영 배포는 회의 후 결정한다.
