## 2. 타임라인 전체 리팩토링 (같은 날, 로컬만·미배포)

### 문제 발견
- 운영에서 `/timeline/{날짜}`가 모든 날짜에 500: ISR 페이지(revalidate + generateStaticParams)에서 서버 fetch가 `no-store`라 "Page changed from static to dynamic at runtime" 오류(운영 로그 확인). sitemap에 이 주소가 730일치 들어 있어 검색 로봇도 500을 받고 있었다. 로컬 dev 서버에서는 이 충돌이 안 걸려 가려졌다.
- 항상 비어 있는 "그날의 이슈" 보기가 화면에 노출됨(백엔드 mode=issues가 빈 값만 반환).
- 같은 기능이 두 벌: 홈 구역은 `/s3-articles`+`/time-machine`, `/timeline`은 `/api/timeline`+`/time-machine`. 날짜 유틸·구간 경계(2026-02-01)·fetch 함수 이름이 중복.
- 홈 구역 파일 884줄에 상태·폴링·렌더·스켈레톤이 한 파일, 미사용 백업 사본 897줄.
- 백엔드: S3 XML을 요청마다 통째로 받아 파싱(캐시 없음), 0건 날짜는 빅카인즈를 매번 재호출, DynamoDB `expires_at`을 문자열로 저장해 TTL이 동작하지 않음, 오류 시 내부 예외 문자열 노출, 같은 검증 코드 두 핸들러에 복제.

## 8. 연대기 탐험 고도화 — 기사 비중 곡선 + 겹침 없는 사건 주석 (로컬만·미배포)

- 요청(사용자): 더 디테일하고 고급스럽게, 겹치는 라벨 없이, 더 화려하고 세련되게, 라이브러리 리서치, 1차원적인 차트 말고, AI 티 나는 이모지 금지.
- 리서치 결론: 라벨 겹침 회피는 d3 계열(d3-force, d3-annotation)이 정석이고, React 환경에서는 시각 요소를 직접 그리고 계산만 d3에 맡기는 방식(visx 철학)이 가장 가볍고 디자인 통제가 쉽다. 번들 크기는 D3 약 90KB · visx 약 49KB · ECharts 약 100~170KB. 채택: `d3-scale` · `d3-shape` · `d3-array`(계산만, 트리셰이킹), 차트는 React SVG로 직접 구현. 차트 라이브러리는 쓰지 않음(주석 시계열은 프리셋 차트로 원하는 모양이 안 나옴).
