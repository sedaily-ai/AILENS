# 이용 기록 달력과 오른쪽 영역 정리

관련: `style/dashboard-disclosure-records` → `main`

## 배경

- 월간 달력의 달성 표시가 흐리고 ‘읽기’라는 이름 때문에 웹툰·듣기·영상도 포함되는지 알기 어렵다는 피드백을 반영했다.
- 기록 탭에도 다른 세 탭처럼 오른쪽 영역을 두되 주간 스탬프를 중복 표시하지 않도록 요청받았다.

## 한 것

- 탭 이름을 ‘이용 기록·리워드’, 기간 기록 제목을 ‘나의 뉴스 이용 기록’, 월간 제목을 ‘월간 활동 달력’으로 변경했다. 읽기·웹툰·듣기·영상의 완료 기록을 포함한다고 명시했다.
- 실제 집계의 `read_days`가 완료한 날짜 수인 것을 `reading_records_repo.py`에서 확인하고 표시 이름을 ‘완료한 날’로 맞췄다. API·집계·스탬프 지급 조건은 변경하지 않았다.
- 스탬프 달성일은 진한 파란색 셀·달성 문구·완료 편수로, 스탬프 없는 완료일은 옅은 파란색과 완료 문구로 구분했다. 오늘은 외곽선과 `aria-current=date`로, 수집 전과 미래는 기존 의미를 유지해 구분했다. 범례와 월 스탬프 달성 일수를 추가했다.
- 기록 탭의 단일 열 예외를 제거하고 공통 좌우 배치를 사용한다. 오른쪽에 기존 ‘한 문장, 다음 이야기’ 안내와 ‘내가 팔로우한 에디터’를 표시하며 주간 스탬프는 이 탭에서만 제외한다.
- 기록 탭에서도 기존 계정 팔로우 조회 훅을 활성화했다. 에디터 목록은 로딩·조회 실패·빈 목록을 구분한다. 좁은 화면에서는 기존 반응형 규칙대로 오른쪽 영역이 본문 아래에 배치된다.

### 검증

- `npx tsc --noEmit --project service/frontend/tsconfig.json`, `npm run lint --workspace service/frontend`, `npm test --workspace service/frontend`의 기존 34개 파일·172개 테스트와 `git diff --check` 통과.
- 운영 공개 API URL을 지정한 `npm run build --workspace service/frontend` 성공. 샌드박스 DNS 제한으로 정적 생성 중 운영 데이터 조회는 대체 처리가 실행됐다.
- 임시 로컬 화면에서 실제 MyLensPage·ReadingPeriodView·제품 CSS를 사용하고 인증·Next 탐색·계정 조회 훅은 모의 처리했다. 네 탭의 데스크톱 좌우 배치, 기록 탭 스탬프 중복 없음, 팔로우 조회 활성화와 실제 목록 렌더를 확인했다.
- 320·390·768·1024·1440px 가로 넘침 없음과 달성 강조를 확인했다. 31일 렌더, 오늘·미래·수집 전·완료 전용 상태, 이전 달·이번 달 이동, 주·월·연 전환, 팔로우 로딩·실패·빈 목록도 확인했다. 검증 화면의 날짜·에디터는 모의 데이터이며 제품에 포함하지 않았다.
- PR 준비 시 제품 변경을 전체 자체 검토하고 필수 검사를 다시 통과했다. 최종 제품 스냅샷과 재사용한 브라우저 근거는 [펼치기 디자인 작업 기록](2026-10-16-사용자웹-펼치기-디자인.md)의 ‘PR 준비와 최종 검증’에 남겼다.

## 결정

- 파란색뿐 아니라 달성·완료 문구와 접근성 이름으로 상태를 구분한다.
- 기존 오른쪽 영역과 조회 훅을 재사용하며 새 API와 의존성은 추가하지 않는다. 기존 펼치기 개선 변경은 유지한다.
