# 2026-10-09 모듈 C 에이전트 설계서·PoC와 모듈 E 보도사진 라벨링 PoC

작성: 이민서 + Claude Code
관련: `2026-10-08-결과보고서-용역완료보고서-초안.md`, 과업지시서 2.4.6·2.4.7, `docs/architecture/비용태깅_규칙.md`

## 배경

결과보고서 초안에 미달성 성과지표 2개가 남아 있었다. 하나는 "독자 뉴스 에이전트 설계서 1건"이고, 다른 하나는 모듈 E의 "샘플 데이터 기술 검증"이다(본지 위젯은 별도).
두 항목을 실제로 수행해 근거 있는 결과로 채웠다.

## 한 것

- Bedrock application inference profile 3개를 만들었다: `lens-poc-opus-5-5`, `lens-poc-sonnet-5-5`, `lens-poc-haiku-4-5`.
  - 10/1 이후 규칙에 따라 `Service=lens`를 붙였고, 7개 태그 키를 재조회로 확인했다.
- **모듈 C:** 에이전트 설계서를 작성했다(기능 정의·대화 시나리오·아키텍처·도구 명세 7종·메모리·폴백·평가 체계).
  - Opus 5.5로 ReAct 루프 PoC를 돌렸다. 도구 4종을 썼고, 대상은 공개 API 기사 1,000건이다.
  - 평가 시나리오는 12건으로, 성공 6·실패 대응 3·환각 회귀 3이다.
  - 결과는 11/12 통과다. 미통과는 H2다: 1990년 날짜 질문에 도구를 부르지 않고 확인되지 않은 외부 서비스를 안내했다 → `timeline_lookup` 도구 필요.
  - 자동 점검 규칙이 1차 실행에서 "없었습니다" 같은 표현을 놓쳐, 정상 답변 2건을 미통과로 판정했다. 표현 목록을 보완해 저장된 로그로 재판정했다. 설계서 8.4에 이 사실을 적었다.
- **모듈 E:** AI LENS 게재 보도사진 40장(분야별 무작위)에 Rekognition DetectLabels와 Claude Opus 5.5·Sonnet 5.5·Haiku 4.5를 동일 프롬프트로 적용했다.

| 항목 | Opus 5.5 | Sonnet 5.5 | Haiku 4.5 | Rekognition |
|---|---|---|---|---|
| 사진 대조 '정확' | 39/40 | 37/40 | 15/40 | 0/40(영어 일반 라벨) |
| 평균 응답 | 12.7초 | 4.0초 | 3.3초 | 0.8초 |
| 장당 비용(추정) | 약 19원 | 약 10원 | 약 4원 | 약 1원 |

- 권고안은 Sonnet 5.5 배치 전량 + Opus 5.5 재검토 10%다. 64만 장 기준 약 373만 원이다.
- 저장 스키마(PostgreSQL `photo_labels`)와 검색·필터 시제품(HTML 안에서 동작)을 보고서에 넣었다.
- 결과보고서·용역완료보고서 HWP를 다시 생성했다. 빨간 자리표시가 결과보고서 12→7, 완료보고서 5→2로 줄었다.
- 최종 폴더에 3번(설계서)·4번(PoC 보고서) PDF·HTML을 추가했다.
- 비용은 Claude 약 $1.6, Rekognition $0.04다. Rekognition은 태그 슬롯이 없어 미태깅이다.

## 결정

- 사진별 판정은 Claude Code가 사진과 라벨을 대조해 매겼다. 보고서 판정표에는 '담당자 확인' 칸을 비워 두어, 사람 검수 표본을 나중에 채울 수 있게 했다.
- 뉴스 분야는 사진 라벨이 아니라 기사 메타데이터에서 가져온다. 사진만으로 본 분야 일치율은 48~57%였는데, 같은 사진이 여러 분야 기사에 쓰이기 때문이다.
- Haiku 4.5는 아카이브 라벨용으로 권하지 않는다. 글자 오독·과잉 추정이 잦았다(예: 접종 일정표를 정년 개정표로, 없는 법안명 생성).
