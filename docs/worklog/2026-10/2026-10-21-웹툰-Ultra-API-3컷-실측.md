# 웹툰 Stable Image Ultra API 3컷 실측

## 배경

사용자는 CMS용 실제 API로 정면·측면·야외의 같은 세 장면을 생성하고 품질·시간·비용을 확인하도록 승인했으며, 모델을 Stable Image Ultra로 명시했다. 앞선 내장 이미지 도구의 결과는 Ultra 결과가 아니므로 분리한다.

## 실행 범위

- 모델: `stability.stable-image-ultra-v1:1`, AWS Bedrock us-west-2.
- `bedrock_models.profile_arn("image_sd_ultra")`로 기존 CMS application inference profile을 조회했다. 추론 전 실제 태그 `Service=lens`와 ACTIVE 상태를 재확인했다.
- CMS 공용 함수 `pipelines/common/webtoon_image.py::generate_bedrock_sd_ultra_image_bytes`를 직접 실행했다. 측정용 클라이언트 래퍼로 요청·응답 메타데이터를 기록했으며 제품 코드는 변경하지 않았다.
- 실제 공급자 API 시험이다. CMS HTTP 라우트·인증·화면·기사 스크립트 생성·자막 합성·발행 전체를 실행한 시험은 아니다.
- 공통 seed `20261021`, PNG, 요청 aspect ratio `3:2`. 반환 원본은 모두 `1216×832`이며 요청 비율과 정확히 일치하는 1.5 비율은 아니다.
- 최종 이미지에 리터칭·선명화·업스케일을 하지 않았다. 비교용 썸네일과 확대 검사 파일만 별도로 만들었다.
- 최초 잘못 선택한 OpenAI 시험은 `images.edit` 호출 직전 중단했다. 모델 목록 조회만 했고 OpenAI 이미지 생성 호출은 0회다.
- 활성 프롬프트, CMS 설정, 배포 상태, AWS 태그는 이번 시험에서 변경하지 않았다. 커밋·push도 수행하지 않았다.

산출물: `output/imagegen/webtoon-ultra-api-3cut-20261021/`. 폴더 내부 `.gitignore`로 생성 파일을 Git에서 제외한다.

## 비용

[AWS 공식 Bedrock 요금 페이지](https://aws.amazon.com/bedrock/pricing/)의 Stable Image Ultra 항목과 해당 페이지의 [공개 가격 데이터](https://b0.p.awsstatic.com/pricing/2.0/meteredUnitMaps/bedrockfoundationmodels/USD/current/bedrockfoundationmodels.json)를 연결해 확인했다.

- Oregon, 이미지당 **$0.14**. 공개 가격 데이터 발행일 2026-10-12.
- 최종 3컷 공시 단가 예상: **$0.42**.
- 최초 동일 이미지 3회까지 포함한 총 6회 생성 예상: **$0.84**.
- 참조 입력 검증 실패 2회는 생성 이미지를 반환하지 않았다. 실패 요청의 실제 청구 여부는 확인하지 않았다.
- 청구서·Cost Explorer로 확정한 금액이 아니다. 세금·네트워크 비용 등은 위 생성 예상액에 포함하지 않았다.
- `official-price-evidence.json`에 HTML의 모델명→가격 키 연결과 Oregon 요금·발행일을 보존했다. 응답에는 최종 청구 금액이 포함되지 않는다.

## CMS 적용 방향

1. **Ultra 모델 유지, 컷별 독립 생성.** 한 장에 8컷을 넣어 자르면 이번에 관측한 약 1MP 원본 픽셀을 나눠 쓰게 되므로 확대 품질 요구와 맞지 않는다. 컷별 원본을 보존한 뒤 세로 합성본을 만든다.
2. **기사별 화풍·인물 설명을 짧게 고정하고, 컷별 구도·행동·장소를 앞부분에 넣는다.** 장문의 공통 규칙 뒤에 장면을 쌓는 방식은 이번 실제 출력에서 실패했다. 장소는 기사에 따라 바꾸되 반복 장소의 색·주요 구조를 짧게 공유한다.
3. **프롬프트 버전으로 먼저 검증한다.** 웹툰 같은 선화·명암을 앞쪽에 짧게 명시한 Ultra 전용 후보가 필요하다. 이번 장면 우선 후보는 화풍·정체성 측면에서 아직 미완료다. 생성 조건을 보관하되 현 운영 버전을 바로 교체하지 않는다.
4. **최종 전송 문자열을 함께 확인한다.** 공용 `build_background_prompt`가 STYLE·camera·characters·scene·CRITICAL을 결합한다. 이번 시험은 그 조립 뒤 단계인 이미지 생성 함수에 직접 최종 prompt를 전달했으므로, 같은 문안을 CMS 버전에 저장하는 것만으로 동일 요청이 나간다고 볼 수 없다. 활성 설정과 실제 전송 요청에서 긴 접두부가 재도입되는지 확인해야 한다. 조립 순서 자체 수정은 별도 코드 변경·배포 대상이다.
5. **동일 seed는 인물 고정 장치로 취급하지 않는다.** 이번 시험은 같은 seed에서도 얼굴·장신구가 달라졌다. 선택 컷 재생성과 원본 비교가 필요하다. 텍스트만으로 정확한 얼굴 고정을 보장하는 문구를 제품에 넣지 않는다.
6. **확대 요구를 실제 원본 크기로 안내한다.** 이번 출력은 1216×832다. 업스케일 도입은 별도 품질·가격 시험이 필요하며, 확대만으로 새로운 원본 디테일이 생기는 것으로 설명하지 않는다.

## 후속: 화풍 문구만 바꾼 비교

### 배경

사용자가 이번 Ultra 결과가 기존 웹툰보다 실사에 가까운 이유를 질문했다. 앞선 시험은 모델·참조 입력·프롬프트를 함께 변경해 모델 적합성을 판정하기 어려웠다. 같은 Ultra에서 화풍만 바꾸는 비교를 제안했고 사용자가 진행을 승인했다. `brainstorming` 스킬의 승인된 소규모 시험으로 수행했으며 CMS 제품 코드나 활성 버전 변경은 범위에 넣지 않았다.

### 한 것

산출물: `output/imagegen/webtoon-ultra-style-ab-20261021/`.

- 직전 `compact` 3컷과 실제 요청을 기준으로 재사용했다. 기준 이미지를 다시 생성하지 않았다.
- 모델 프로파일·장면 문구·인물 문구·seed `20261021`·negative·종횡비·출력 형식을 고정했다.
- 정면에서 **같은 위치의 화풍 문장만** 교체해 생성했다. 선화·면 음영이 강화돼 같은 변경을 측면·야외에도 적용했다.
- 별도로 정면에서 교체한 화풍 문장을 맨 앞으로 옮긴 순서 시험을 1회 했다. 이 시험을 문구 교체 효과와 혼합하지 않는다.
- 실제 전송 body를 기존과 비교하는 assertion으로 `prompt` 외 필드 동일, 화풍 문장을 제거한 나머지 텍스트 동일을 확인했다.
- 매 실행 전 application profile의 ACTIVE 상태와 `Service=lens`를 조회했다. 전 호출 CMS 공용 Ultra 함수 사용, 호출당 1회 제한, 성공 4회·재시도 0회.
- 이전 임시 가상환경이 없어 새 임시 환경에 boto3·Pillow를 설치했다. 프로젝트 의존성은 변경하지 않았다.

기존 문장:

```text
Korean news webtoon, fine ink, cel shading, navy-ivory palette, soft upper-left daylight.
```


교체 문장은 진단용 후보이며 CMS에 발행하지 않았다. 문장 길이와 구체성이 함께 달라졌으므로 특정 단어 하나의 효과로 해석하지 않는다.

4개 원본 및 정면 얼굴 200% 검사를 직접 확인했다. PNG 크기·SHA-256, 요청의 통제 조건, HTML의 로컬 자산 참조 검사를 통과했다. 비교·크롭 외 이미지 보정은 하지 않았다. 원본 해상도는 변하지 않아 확대 품질 개선 시험으로 해석하지 않는다.

### 결정

- **Ultra가 만화적 표현을 생성할 수 있다는 실제 사례를 확보했다.** 이번 반실사 결과를 모델 특성만으로 설명하거나, Ultra가 웹툰에 원천적으로 부적합하다고 결론 내릴 수 없다.
- **요구하는 웹툰을 안정적으로 생산할 수 있는지는 여전히 미확인이다.** 같은 화풍 문장을 적용해도 정면·측면·야외의 표현 방식과 인물 연속성이 달라졌다. 단순히 `webtoon`을 넣는 것보다 구체적인 선화·면 색·명암 지시가 유효해 보이지만, 이것만으로 운영 품질은 충족하지 않는다.
- **화풍 문구를 무조건 맨 앞에 두는 규칙은 채택하지 않는다.** 순서 시험에서도 구도·불필요한 요소 문제가 있었고 단일 정면 사례뿐이다.
- negative에 금지한 요소가 여전히 등장했다. negative는 보장 장치가 아니다.
- 이번 시험의 범위는 한 seed와 세 장면이다. 기준 이미지는 이전 실행을 재사용했으며 서비스 내부 모델 빌드가 동일한지는 확인할 수 없었다. 통계적 성공률이나 모든 기사에서의 재현성을 주장하지 않는다.
- CMS 활성 프롬프트·제품 코드·배포 상태는 그대로 두었다. 운영 반영을 승인할 결과가 아니다.

### 다음

다음 후보는 인물과 배경에 같은 선화·채색을 적용하는 지시, 인물 앞을 가리는 구조물 방지, 생성 이미지의 테두리 방지를 분리해서 검증해야 한다. 화풍을 바꿔도 인물 동일성·구도·추가 요소가 유지되는지 별도 seed와 실제 기사에서 확인한 뒤 CMS 버전 후보를 확정한다. 한 번에 규칙을 여러 개 추가해 다시 원인을 구분할 수 없게 만드는 방식은 피한다.

비교 페이지 `review.html`에는 이전/수정 3쌍, 순서 시험, 정확한 변경 문구, 원본·200% 확대와 다운로드를 담았다. `before-after.jpg`는 전체 3쌍, `front-before-after.jpg`는 정면 1쌍, `metrics.json`과 각 `.request.json`/`.response.json`은 측정 근거다.

## 후속: 얼굴 일관성 및 나머지 조건 조정

### 배경

사용자가 컷별 얼굴 변화부터 조정하고 구도·배경·테두리 등 나머지 문제도 조정하도록 요청했다. 동일한 Ultra와 seed에서 고정 얼굴 묘사, 문안 순서·길이, 배경 단순화와 negative를 조정해 검증했다. 이전의 화풍 단일 변수 시험과 달리 이번은 여러 조건을 조정하는 개선 탐색이다.

- 이 시험은 한 여성 진행자·한 seed·세 장면이다. 얼굴 인상의 유사함은 육안 관찰이며 정량 동일인 판정이 아니다. 단어 수를 내부 토큰 한계로 해석하지 않는다.

### 결정

**해결 완료로 처리하지 않는다.** 얼굴이 비슷해지는 후보는 있었지만 얼굴 동일성·요청한 구도·장소·웹툰 화풍·금지 요소가 한 세트에서 동시에 통과하지 않았다. 서로 다른 단계에서 잘 나온 컷만 골라 하나의 성공 세트처럼 제시하지 않았다.

현재 Bedrock Ultra의 텍스트 입력만으로 각 컷을 다시 생성하는 방식에서는 이번 조정으로 얼굴 고정을 보장할 수 없었다. 추가 수식어·negative·동일 seed를 얼굴 고정 기능이라고 표현하지 않는다. 이 결과가 가능한 모든 프롬프트의 실패를 증명하는 것은 아니지만, 같은 접근으로 자동 운영 품질을 보장할 근거는 확보하지 못했다.

CMS 활성 프롬프트·제품 코드·배포·기존 버전은 변경하지 않았다. 검증에 실패한 후보를 새 운영 후보 버전으로 올리지 않았다. 이번 작업의 실제 변경은 세 단계 시험 문안과 실행·검토 산출물이며 CMS 운영 수정과 구분한다.

### 다음

얼굴 동일성이 필수 조건이면 **검수한 캐릭터 이미지 자산을 재사용하는 구성**이 대안이다. Ultra로 캐릭터와 배경을 만들되 컷마다 얼굴을 새로 생성하지 않고 동일 자산을 합성하면, 재사용하는 이미지의 얼굴 픽셀은 유지할 수 있다. 대신 포즈와 시점이 준비된 자산 범위로 제한되고, 캐릭터 분리·배경 합성·레이아웃·자산 관리 기능이 필요하다. 이는 아직 구현·품질 검증하지 않은 별도 CMS 작업이며, 현재 프롬프트 수정만으로 완료했다고 보고하지 않는다.

검토 페이지 `review.html`은 이전 3컷과 이번 세 단계 9컷을 구분해서 보여주고 실제 요청 문안·원본 다운로드·200% 표시를 제공한다. `all-rounds.jpg`는 4행 비교, `metrics.json`은 호출 시간·비용 추정·검증 한계를 기록한다.
