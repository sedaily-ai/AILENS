작성: 이도연 + Kiro
관련: PR #139(1면 조회 기본 경로, 2026-10-20 main 병합 `bb8ac0c4`)의 후속. 최신 `main`에서 새 브랜치 `feat/birthday-front-fallback`을 만들어 진행한다. Lambda `sedaily-mbti-time-machine-dev`

> 실행: 작업 1→6 순서로, 단계마다 체크박스(`- [ ]`)를 채운다. 작업마다 커밋하고, push·PR 생성·배포는 따로 확인받는다.

**목표:** 생년월일을 넣으면 그날 실제 서울경제 1면을 보여 준다. 그날 신문이 없으면 직전 발행일 1면으로, 면 기록이 없는 시기면 그날 실제 서울경제 기사로 대신한다.

**구조:** 사용자가 조회할 때 빅카인즈에서 가져와 기존 DynamoDB 캐시에 요청 날짜 단위로 저장한다. 면 번호가 있는 시기의 "1면 없는 날" 목록만 미리 한 번 수집해 JSON으로 Lambda에 함께 싣는다. 서버는 그 목록으로 거슬러 찾을 날을 바로 고르고, 목록 밖 날짜(수집 이후 등)는 본문 없는 가벼운 조회로 확인한다.

**기술:** Python 3.11 Lambda(`requests`, `boto3`)·pytest, Next.js 16·TypeScript·vitest.

**근거:** `docs/worklog/2026-10/2026-10-19-내생일타임머신-기획안v3-개편.md`의 "생일 1면 실제 기사 가능성 실측(2026-10-20)"(빅카인즈 149회 실측).

## 전역 제약

- 기사 제목·본문은 빅카인즈 원문만 쓴다. AI 생성문은 쓰지 않는다.
- 서버 로그에 요청 날짜와 보여 준 날짜를 남기지 않는다.
- 새 AWS 리소스는 없다. 키는 SSM `/sedaily-mbti/bigkinds-api-key`.
- Lambda 제한시간 30초 → 1면 탐색 예산 `FRONT_SEARCH_BUDGET_SECONDS = 20`(구현 때 15에서 바꿈 — 호출마다 남은 시간만 기다리게 해서 20초로도 30초 안에 끝난다).
- 거슬러 찾기 `FRONT_LOOKBACK_DAYS = 10`(생일 포함 11일), 그날 기사 `FRONT_DAY_ARTICLES = 4`.
- 면 번호 시기: 1994-01-01~1996-07-31(`published`), 2017-11-13~(`sent`). 일요일 휴간 규칙은 1996-09-29부터.
- 캐시 키: `timemachine_frontv2_{date}`(응답 형식이 바뀌어 접두사 변경), 결과 없음은 `timemachine_frontv2_none_{date}`(6시간). 오늘 날짜는 저장하지 않는다.
- UI: 터치 44px, 글자 13px 이상, 간격 4px 배수, `birthdayStory.module.css`의 기존 클래스만 쓴다. 강조색은 #1d4ed8 하나.
- 생일 기능 코드는 `features/news-feed/components/birthday` 안에 둔다(기능 간 import 금지).
- 대체한 1면과 "그날 서울경제"는 공유 카드에 넣지 않는다. 카드 문구가 "내가 태어난 날 서울경제 1면"이라 사실과 어긋난다. 이때는 생일 영수증만 고를 수 있다.

## 응답 형식 — `GET /time-machine?front=YYYY-MM-DD`

```json
{ "date": "2024-10-13", "shown_date": "2024-10-12", "kind": "front", "reason": "sunday", "articles": [], "cached": false }
```

- `kind`: `front`(1면) · `day`(그날 서울경제, 면 기록이 없는 시기) · `none`(11일 안에 없음)
- `reason`: `null`(생일 당일) · `sunday` · `no_paper` · `archive_missing`(`kind`가 `none`일 때)
- `shown_date`: `kind`가 `none`이면 `null`
- `articles` 항목은 지금과 같다: `news_id, title, content, byline, category, original_link`
