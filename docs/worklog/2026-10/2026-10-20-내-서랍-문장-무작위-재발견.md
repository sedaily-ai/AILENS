# 내 서랍 문장 무작위 재발견

## 배경

홈 오른쪽 ‘내 서랍에서 다시 발견’은 최근 저장 문장 3개를 고정 표시했다. 재진입 시 다른 저장 문장을 볼 수 있도록 랜덤 또는 순환 구조로 바꿔 달라는 요청을 반영했다.

## 한 것

- CMS `recommendation_repo.inputs`가 계정의 전체 저장 문장에서 `ORDER BY random() LIMIT 3`으로 후보를 뽑는다. 오래된 문장도 선택될 수 있다. API 응답 키 `recent_sentences`는 호환을 위해 유지한다.
- `drawerModel.pickDiscoverySentence`는 직전 ID를 제외한 후보 중 한 문장을 고른다. 후보가 하나면 그 문장을 사용하고 없으면 빈 상태다.
- `useServerDashboard`는 새 응답을 받았을 때 선택한 한 문장만 화면에 전달한다. `lens-archive-discovery:v1:<계정 ID>` 키로 직전 문장 ID만 localStorage에 기억한다. 빈 목록이면 키를 지우고 조회 실패·취소 응답은 기록하지 않는다.
- `ArchiveDiscovery`는 한 문장만 표시한다. 0개일 때 안내와 원문·서랍 링크는 유지한다. 타이머 없이 재진입·새로고침·기존 대시보드 갱신 이벤트에서 다시 선택한다. 단순 리렌더링으로는 바뀌지 않는다.
- 단위 테스트 14개(문장 선택·기존 원문 링크·대시보드 어댑터), 전용 loopback PostgreSQL 기반 테스트 15개 통과. 저장 문장 0/2/42개, 오래된 문장 선택, 계정 분리, 중복 없는 후보와 원문 주소를 확인했다. SQL 난수는 고정 seed로 검증했다.
- 실제 대시보드 훅과 재발견 컴포넌트를 Chrome에 연결해 0개·1개·2개 교대·재진입·한 문장 표시·일반 리렌더 안정성·오래된 후보·계정 분리·조회 실패·저장소 차단·빈 목록의 키 정리를 검증했다. API는 로컬 샘플 응답을 사용했다.
- 프로덕션 빌드, 타입 검사, 변경 파일 ESLint, `git diff --check` 통과. 빌드 중 외부 API DNS 경고가 있었으나 완료됐다.
- 이번 작업의 임시 PostgreSQL 컨테이너 `lens-rediscovery-check-20261020`과 볼륨을 제거했다.

## 결정

- 전체 보관 문장에서 뽑아 최근 문장에만 노출이 쏠리지 않게 한다. API의 소유자 필터를 유지한다.
- 다른 후보가 있으면 직전 문장만 제외한다. 모든 문장을 다 보기 전까지 중복을 금지하는 방식은 아니다.
- localStorage가 차단되면 랜덤 표시는 계속 가능하지만 재방문 간 직전 문장 제외는 보장하지 않는다.
- 내 서랍 전체 목록의 최신 저장순 정렬은 유지한다.

## 다음

- 로컬 변경이며 배포하지 않았다. 전체 보관 문장을 후보로 쓰려면 프론트엔드와 CMS 변경을 함께 배포해야 한다.
