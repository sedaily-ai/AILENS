Codex 내부 브라우저에서 임시 앱 `http://127.0.0.1:4328`을 직접 조작했다. 기존 QA 복사본 `/tmp/ailens-diet-qa/app`을 사용했고, 변경된 제품 소스 7개와 테스트 1개의 바이트가 저장소와 동일한지 대조했다. 임시 앱의 인증 로더·분석 스크립트 제외·동일 출처 API 프록시·오류 주입 스크립트·hydration 확인 컴포넌트는 검증 경계이며 최종 제품 변경에 포함하지 않는다.

기본 브라우저 폭이 작업 도중 변경되어 실제 DOM 기준 **469×954**의 좁은 화면에서 카테고리·공유 오류 안내를 확인했고, 데스크톱 전용 계정 메뉴 검증은 명시적으로 **1280×900**을 설정해 확인했다. 두 크기 모두 실측했다. 네이티브 모바일·터치 검증이나 픽셀·색 대비 평가로 확대하지 않는다. 스크린샷 API는 호출하지 않았고 이미지 파일로 화면을 저장하지 않았다.

### 검증 중 확인한 환경 제약

- 임시 앱의 Turbopack은 저장소 밖 node_modules 심볼릭 링크 때문에 시작하지 못해 webpack 개발 서버로 전환했다.
- 초기 webpack 실행 위치가 프론트 디렉터리가 아니어서 카드 글꼴 경로 오류가 발생했다. 실행 디렉터리를 바로잡은 뒤 정상 PNG에서 공유 취소·실패·재시도 시나리오를 다시 확인했다. 제품 카드 렌더러를 고친 것이 아니다.
- 일부 첫 조작은 hydration·비동기 이동 전에 실행됐다. 실제 URL·선택 옵션·준비 표시를 확인한 후 다시 실행한 결과만 통과 근거로 쓴다. 서버 HTML은 기존 기본 목록이고 URL 필터는 hydration 뒤 복원되므로, JavaScript 실행 전의 필터 반영을 보장하지 않는다.
- 초기 QA 스크립트의 html 속성 주입으로 hydration 경고가 발생해 해당 사전 속성 주입을 제거했다. 개발 모드의 스크립트 경고·기존 이미지 LCP 경고를 포함해 전체 콘솔 로그를 오류·경고 0건이라고 주장하지 않는다.
- QA public 심볼릭 링크를 분리해 오류 주입 파일은 임시 앱에만 남겼고, 임시 접근성·콘솔 관찰 파일도 저장소 밖으로 옮겼다.
