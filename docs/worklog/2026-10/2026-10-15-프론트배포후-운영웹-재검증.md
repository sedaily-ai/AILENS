# 프론트 배포 후 운영 사용자 웹 재검증

## 배경

- 사용자가 프론트 배포를 완료한 뒤 로그인, 나의 LENS 네 탭, 필터 복원, 공유, 미디어 전환의 운영 재검증을 요청했다.
- 대상: https://ailens.sedaily.ai 사용자 웹. 관리자 웹은 제외했다.
- 사용자는 자동 프로필 동기화 및 열람·재생·완료·스탬프 기록만 허용했다. 설정·북마크·동의·팔로우·저장 문장의 저장/삭제는 실행하지 않았다.
- 코드와 운영 데이터의 수동 수정, 커밋·push·배포 없이 검증했다. 스크린샷을 촬영하거나 저장하지 않았다.
- 로컬 기준 HEAD: `dfa088f467323396ef506d9dcba20ba6f0dd20fc`(PR #118 병합). 운영 화면의 동작을 확인한 것이며 실행 중인 서버 이미지의 커밋 동일성까지 증명하는 검사는 아니다.

## 한 것

### 방식과 확인 범위

내부 브라우저의 실제 로그인 세션에서 UI를 조작하고 접근성 트리, 렌더링된 문구, 선택 상태, URL, 미디어 재생 상태를 읽었다. frontend-harness의 점검 기준을 적용하되 스크린샷을 생성하는 자동 실행은 사용하지 않았다. 화면 픽셀·반응형 전수 검사나 음질 평가는 이번 결과에 포함하지 않는다.

### 검증 경계

- 링크 복사 직후 브라우저 도구의 clipboard 읽기는 이전 값을 반환했지만, 실제 입력창 붙여넣기는 현재 기사의 정확한 URL이었다. 최종 판정은 실제 붙여넣기에 근거하며 사이트 복사 오류로 집계하지 않았다.
- 사이트 탭의 캡처된 error 콘솔 로그는 최종 조회에서 빈 배열이었다. 이것이 모든 네트워크 요청의 성공을 뜻하지는 않는다.
- 브라우저 제어 도구 자체의 외부 텔레메트리 403 오류는 사용자 웹 오류로 분류하지 않았다. 선택자 중복/제목 불일치로 발생한 자동화 대기 오류 역시 사이트 결함으로 집계하지 않았다.
- 기존 로그인 유지·세션 복원 확인과 신규 로그인 전체 흐름 검증은 구분했다. 외부 SNS의 실제 게시 및 OS 공유 완료는 미검증이다.
- 정상 이용에 따라 자동 기록 요청이 발생할 수 있다. 운영 DB를 직접 조회해 각 기록의 저장 완료 여부까지 대조하지 않았다.

## 결정

- 요청한 핵심 흐름은 위 범위에서 확인했다. 내 서랍 조회 실패 1건과 시간 표시 불일치 1건 때문에 ‘전부 이상 없음’으로 판정하지 않는다.
- 관리자 웹 접근, 제품 코드 수정, 계정 설정·저장 항목 변경, 스크린샷 촬영/저장, 커밋·push·배포는 하지 않는다.
- 기존 별도 작업 기록은 그대로 보존하고 이번 검증 결과만 이 문서에 기록한다.
