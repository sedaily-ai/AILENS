## 배경

1차 배포 뒤 저장소를 다시 훑어 찾은 추가 후보 16건(1차 작업 기록 '다음') 중 C·I·J·L·M·N·P를 먼저 정리했다. 기준은 1차와 같다: 쓰는 곳이 없으면 코드를 지우고 DB 데이터는 남긴다. 도연님 기준으로, 지운 것 중 쓰는 곳이 있던 것은 되돌렸다.

## 결정

- C는 취소(도연님). 최신 글 레일은 지우지 않는다.
- I는 공유만 맞춘다(I-1). 글자 크기를 기사 공용 부품으로 바꾸면 버튼이 44px보다 작아지고, 레터 '작게'가 14.9px로 본문 최소 16px보다 작아진다.
- 되돌리기 기준(도연님): 지운 것 중 쓰는 곳이 있으면 되돌린다. M·N은 웹·관리자·모바일·파이프라인 어디에서도 부르지 않아 유지, P는 `InteractiveBlock`만 되돌렸다.
- 서버 `/etc/lens-cms-api.env`의 `LENS_PUSH_ENCRYPTION_KEY`는 지우지 않는다. 남겨 둔 기기 정보가 이 키로 암호화돼 있다.

## 다음

- 배포 순서: 웹 → 계정 API → CMS. DB·관리자 변경은 없다. 되돌릴 때는 CMS 먼저, 그다음 계정 API.
  - CMS `deploy.sh`는 옛 워커 타이머·유닛이 남아 있으면 멈춘다. 10-15 운영 배포 때 워커(배포실행_명령 '6. worker 정기 모의 처리')는 보류됐으므로 타이머는 없을 가능성이 높다 [추정]. 멈추면 아래를 실행한 뒤 다시 배포한다.

    ```bash
    sudo systemctl disable --now lens-notification-worker.timer lens-notification-worker.service
    sudo rm -f /etc/systemd/system/lens-notification-worker.timer /etc/systemd/system/lens-notification-worker.service
    sudo systemctl daemon-reload
    sudo systemctl reset-failed lens-notification-worker.service lens-notification-worker.timer
    systemctl list-unit-files 'lens-notification-worker*' --no-pager   # 0개면 끝
    ```

  - (선택) `deploy.sh`는 묶음을 기존 폴더 위에 풀기 때문에 옛 워커 파일이 서버에 남는다. 불러오는 곳이 없어 해는 없다. 지우려면 새 CMS가 정상인 것을 확인한 뒤 `/opt/lens-cms-api`에서 `ls`로 확인하고 `notification-worker`(폴더)·`notification-worker.service`·`notification-worker.timer`와 워커 전용 모듈 6개(`*.py`)를 지운다.
