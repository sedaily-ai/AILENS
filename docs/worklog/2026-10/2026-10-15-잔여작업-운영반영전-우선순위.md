### 4. 기사 정정 잔여 사항

정정 JSON SHA256은 `b9bf023108fa70c41cb0c779d0d05e84fcd82f684802219e29633136dde7e198`로 기존과 같다. 기사 20101714/20101638/20101715/20101767/20099924, 총 5건·13필드다. 기존 실제 DB 대조는 **2026-10-15 19:36:02 KST** 스냅샷에서 before 13/13·공개 투영 6/6 일치한 결과다. 지금도 동일하다고 재확인한 것은 아니다.

도구는 기본 접속부터 read-only+REPEATABLE READ이고 기본 검사 종료 시 rollback한다. 적용 시에만 전체 대상 검증·행 잠금→원본/자식 백업 배타 생성→단일 트랜잭션 정정 순서다. B 보완으로 백업에 자식 행은 포함됐지만 완전한 복구 실행을 자동 제공하지는 않는다. 실패 시 테이블 rollback과 시퀀스 번호 간격은 구분한다.

R03의 전체 콘텐츠 사실 검수·이미지 픽셀·음성 발화·영상 프레임 검수는 완료되지 않았다. 이번 정정은 텍스트/대본/캡션이며 실제 녹음·이미지·영상 자산을 바꾸지 않는다. 우선 5건에서 잘못된 내용이 실제 미디어에 남는지 확인하고 자산 수정이 필요하면 별도 작업으로 정한다.

### 5. 이전 인계에서 남은 별도 작업

- **콘텐츠 메타데이터 공급:** 실측 미디어 길이·직접 재생 URL, 이슈 레터 보상 그룹, 승인 후속 관계·실제 작성자 확인이 남았다. 관리 도구·파이프라인 공급 코드는 준비 기록이 있으나 실제 공급은 미완료다. 준비되지 않은 기능은 기존 대기/빈 결과를 유지한다. 정정 JSON 5건과 별도 업무이며, 파이프라인 이미지 갱신도 별도 단위다.
- **알림 worker:** 기존 운영 기록은 서버 메모리 검토 전 정기 실행 보류다. 이 상태를 현재 서버 실측으로 재확인하지 않았다. dry_run 정기 처리·lease/unknown·관제와 실기기 인수는 남았다. 현재 layout의 서비스워커 전역 unregister도 실푸시 활성화 전에 별도로 해결·검증할 대상이다. 이번 화면/조회 개선의 선행 작업으로 worker나 live를 켤 이유는 없다.
- **실발송·실기기:** 동의한 테스트 기기의 HTTPS/권한/service worker scope/VAPID/실수신·클릭·410/429/5xx·unknown 처리 인수가 남았다. provider accepted와 실제 수신은 구분한다. 별도 요청 전까지 발송 비활성을 유지한다.
- **다이어트 조건부:** D04 형식 안내, D05 MBTI 예시, D07 비교 카드 범위, D08 추가 종료 안내, D13 구독·팔로우·알림의 명칭/흐름 정리는 근거·설계가 필요한 선택 작업이다. D07 중복 복사와 D08 동일 요약 등 이미 수정된 부분은 제외한다.

앞서 명시적으로 요청한 구현 5묶음은 로컬 커밋 완료다. 운영 반영 준비는 **최신 원격과의 통합·실제 배포 상태 비교부터 검토**해야 한다. 이후 기사 정정/복구, 배포 계약, 최종 산출물, 실계정·브라우저 인수를 순서대로 확인한다. 독립 최종 통합 리뷰·운영 인수가 완료됐거나 배포 가능하다고 판정하지 않는다.

기존 초기 DB/계정 API/프론트 배포는 이전 운영 기록에서 완료된 것으로 구분하며, 이 5개 후속 커밋의 운영 반영은 이번에 확인되지 않았다. 과거 문서의 미착수 항목을 그대로 재실행하지 않는다. worker 실발송·콘텐츠 메타데이터·조건부 다이어트는 별도 범위다.

## 다음

1. 원격 추가 변경과 로컬 5개 커밋의 통합·검증 방법, 실제 운영 코드와의 차이를 먼저 검토한다. 현재 작업 트리/이력은 변경하지 않았다.
2. 최신 기사 값 read-only 대조와 복구 계획, 최종 빌드·패키지 검증 및 실계정 인수 환경을 준비한다. 운영 쓰기·캐시 무효화·배포·push는 별도 요청 전까지 실행하지 않는다.
3. 이 보고서도 커밋하지 않았다. 기존 별도 작업 기록·제품 코드·정정 JSON은 보존했다. 스크린샷은 촬영·저장하지 않았다.
