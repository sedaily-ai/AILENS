# 06. 오류 개선 · QA · 리팩토링

결론: 가장 먼저 볼 오류는 검색 405(검색이 실패 중일 가능성)와 SSR의 이미지 경로 조회 3,210건. 품질 게이트는 점검기가 이미 있어 파이프라인 편입이 가장 빠른 개선. QA는 발행 직후 자동 리포트 + 주 1회 샘플 점검으로 간헐 진행.

운영 로그 7일(2026-09-30~10-07) 분석. 주의: CloudWatch 로그에는 옛 로그가 다시 수집된 구간이 있어 메시지 안의 날짜로 현재 여부를 확인.

## 2. 품질 게이트 파이프라인 편입

현재 파이프라인에 있는 검증: 레터 최소 6문단(미만 시 최대 2회 재생성), 영상 `validate_script`, 웹툰 최소 컷 수, 선정 JSON 검증, 중복 검사 2종. **없는 것**: 숫자 원문 대조, 팟캐스트 길이·형식, 웹툰 스키마 엄격 검증, 이미지 내용 QA, 레터 `[용어]`·`[핵심 요약]` 검증, 발행 전 사람 승인(draft 직후 곧바로 published).

| 게이트 | 입력 | 판정 | 실패 시 |
|---|---|---|---|
| G1 분량 예산 | 레터 본문 칸별 글자 수 | 칸별 예산·합계 범위 (`regen_letters.py::check_template` 재사용) | 피드백 붙여 재생성(최대 N회), 계속 실패하면 최선 결과 + 경고 플래그 |
| G2 숫자 대조 | 본문·요약의 숫자 vs 원문·팩트시트 | 원문에 없는 숫자 0건 | 재생성 → 실패 시 발행 보류 |
| G3 형식 파싱 | 레터 파서(제목·리드·소제목·핵심 요약·용어), 웹툰 JSON, 팟캐스트 구조 | 필수 요소 존재 | 재생성 → 보류 |
| G4 비어 있는 요소 | `[핵심 요약]`·`[용어]` | 비어 있으면 경고 | 경고만 |
| G5 발행 전 승인(선택) | 전수 또는 샘플 | 사람 확인 | 도입 여부 결정 필요 |

설계 원칙: 게이트 결과(통과·재시도 횟수·사유)를 글 메타에 기록해 일별 합격률 집계. 재시도는 비용을 늘리므로 상한 필수.

## 3. QA 체계 (간헐 진행)

| 주기 | 항목 | 방법 | 산출물 |
|---|---|---|---|
| 발행 직후 | 분량·숫자·링크·파싱 | 자동 리포트(게이트 결과 집계) | 일별 리포트 |
| 일 1회 | 운영 스모크 28건 | `service/frontend/scripts/smoke.sh` | 통과/실패 |
| 주 1회 | 샘플 20편 점검표 | 레터 구조·이미지 일관성·음성·모바일 렌더 | 점검표 |
| 주 1회 | CMS CRUD 스모크 7단계 | 05 문서 4절 (스테이징·로컬) | 결과 기록 |
| 릴리스 전 | 체크리스트 | 모바일·데스크톱·OG·링크·접근성 | 체크리스트 |
| 모델·프롬프트 변경 시 | 골든 세트 회귀 | 기사 10건 재생성 비교 + 블라인드 비교 | 비교표 |

관측 알람(02 문서 I5)과 연결: 발행 실패율·5xx·게이트 불합격률 임계 초과 시 알림.

## 4. 리팩토링 우선순위

| 순위 | 작업 | 근거 | 난이도 |
|---|---|---|---|
| 1 | 모델·프로파일 상수 단일 설정 | 4곳 분산(letters·podcast·video·webtoon), 모델 전환 비용 | 하 |
| 2 | 품질 게이트 모듈화(`pipelines/common/quality_gates.py`) | G1~G4를 레터·팟캐스트·웹툰이 공유 | 중 |
| 3 | 이미지 호출 어댑터화 | 공급자 교체(Bedrock ↔ 직접 API) 대비 | 중 |
| 4 | 시험·파이프라인 입력 조립 공유 모듈 | 프롬프트 랩 L2 | 중~상 |
| 5 | admin 테스트 복구: 실패 2건·수집 오류 1건 | 모킹 시그니처 불일치, `elevenlabs_tts` import | 하 |
| 6 | 프론트 테스트 신설(CMS) | 테스트 0건 | 중 |
| 7 | 이관 후 잔존 코드 정리 | DynamoDB 이름·상수, 미사용 Lambda 소스 | 하 |
| 8 | 문서 정정 | `CLAUDE.md` 상단 dev/dev2 안내가 현 체크아웃과 어긋남(원격은 이미 정본 `AILENS`), ERD README | 하 |
| 9 | IaC 도입 | CloudFormation·Terraform 없음 | 상 |

원칙: 리팩토링 커밋은 Before/After 수치·원칙·검증을 포함(`feedback_refactor_commit_documentation`). 모델 전환·삭제 같은 운영 변경은 리팩토링과 분리해 커밋.

## 5. 일정(제안)

| 주 | 작업 |
|---|---|
| 1주 | E1 확인·수정 · E2 원인 추적 · 게이트 G1·G3 편입 · 상수 단일화 · admin 테스트 복구 |
| 2주 | 게이트 G2·G4 편입 · 품질 리포트 자동화 · 스모크 자동화 · E3·E4 정리 |
| 3주 이후 | 이미지 어댑터 · 프롬프트 랩 L1~L4 · 프론트 테스트 · IaC 검토 |

완료 기준: 게이트 통과율 90% 이상, 운영 5xx 일 10건 이하, 검색 405 0건, 스모크 일 1회 자동 통과.
