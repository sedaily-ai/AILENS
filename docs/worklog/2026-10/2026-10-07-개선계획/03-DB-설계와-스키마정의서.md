# 03. DB 설계와 스키마 정의서

결론: Aurora CPU 100%의 원인 후보는 쿼리 패턴(N+1·풀스캔·캐스팅·목록 집계)이고, 스키마 문서는 코드가 쓰는 테이블 9개가 ERD에 없고 현행 스냅샷이 없는 상태. 쿼리 개선 → 캐시 → ACU 산정 순서로 진행하고, 스키마 문서는 현행 스냅샷 확보부터 시작.

조사는 코드·문서 기준이며 실DB와 대조하지 않음(추정 포함). 실DB 대조는 승인 후 읽기 접속으로 진행.

## 1. 현황

| 항목 | 값 | 출처 |
|---|---|---|
| 엔진 | Aurora PostgreSQL 16.14 Serverless v2, 0.5–2 ACU, 인스턴스 1, 단일 AZ | 측정 |
| 보호 | 백업 1일 · 미암호화 · 퍼블릭 접근 가능 · 삭제 보호 꺼짐 | 측정 |
| 부하 | ACU 일 평균 0.5 / 시간 최대 2.0(상한), CPU 일 평균 21% / 시간 최대 100%, 연결 평균 4·최대 20 | 측정 |
| 지연 | 읽기 평균 0.9ms · 쓰기 0.3ms | 측정 |
| 규모 | 볼륨 0.3 GB | 측정 |
| 연결 풀 | 워커당 최대 10, 부족 시 대기 후 PoolError | 코드 |
| 정본 이관 | 2026-09-09 DynamoDB → Aurora (글·구독자·개인화·기사·퀴즈·프롬프트) | 문서 |

## 2. CPU·ACU 상한 원인 후보 (추정, 우선순위순)

| 순위 | 후보 | 근거 (파일:라인) |
|---|---|---|
| 높음 | 기사 목록·검색 N+1: 기사 N건 × (이미지 + 관련기사 쿼리) = 2N+1, 본문 전체 SELECT 후 응답엔 `body[:200]`만 사용 | `articles_repo.py:88-92, 102, 126, 150, 192, 20-26, 200` |
| 높음 | `ILIKE '%kw%'` + `count(*)` + OFFSET 페이지네이션: 요청마다 풀스캔 2회 | `articles_repo.py:117, 176-189` |
| 높음 | 목록마다 `jsonb_agg` 서브쿼리 2개를 행마다 실행, 캐시 없음 | `cms_posts_repo.py:96-114, 212-219` |
| 중간 | 날짜 캐스팅 필터: `published_at::date = %s` 등은 인덱스를 못 쓰는 것으로 추정 | `articles_repo.py:83, 171-173` · `cms_posts_repo.py:204, 215` |
| 중간 | admin 목록 `SELECT *`로 통짜 JSONB 읽은 뒤 Python에서 제거 | `admin_posts_repo.py:296, 346-350` |
| 중간 | 연결 풀 포화 | `db.py:22-23, 37-52` |
| 중간 | 매일 23시(KST) 기사 수집 크론: 존재 확인 + 본문 포함 해시 조회 후 기사당 DELETE+INSERT | `articles_repo.py:220-247, 251-306` |

확인 필요: 시간별 CPU 100% 시각과 크론·발행 시각의 상관(CloudWatch 시간대 대조 미수행). 발행 시각은 하루 7회(07:00 KST + 08·12·15·18·21·23시 KST).

## 3. 쿼리 개선 작업

| ID | 작업 | 산출물 | 검증 |
|---|---|---|---|
| D1 | 기사 목록 N+1 제거: 이미지·관련기사를 `IN` 배치 1회 조회, 목록 SELECT에서 `body` 제외 | `articles_repo.py` 수정 | 쿼리 수 2N+1 → 3, 응답 동일성 |
| D2 | 날짜 조건을 범위 조건(`>= d AND < d+1`)으로 교체 + 인덱스 확인 | repo 수정 | `EXPLAIN`으로 인덱스 사용 확인 |
| D3 | 검색 인덱스: pg_bigm `gin_bigm_ops` 인덱스 존재·사용 확인 (changelog v1.3은 생성 기록, 실DB 미검증) | 확인 결과 | `EXPLAIN` |
| D4 | 목록 `jsonb_agg` 정리, admin 목록은 필요한 컬럼만 SELECT | repo 수정 | 응답 크기·시간 |
| D5 | 연결 풀 점검: 워커 수 × 풀 크기와 Aurora 최대 연결 | 설정 확정 | PoolError 로그 0 |
| D6 | 목록 응답 캐시(02 문서 4절) | 캐시 정책 | EC2·Aurora 부하 감소 |

개선 후 1주간 시간별 최대 ACU·CPU를 재측정해 상한 원인이 해소되었는지 판정.

## 4. ACU·스펙 산정

| 단계 | 설정 | 근거 |
|---|---|---|
| 현재 | 0.5–2 | 시간별 최대 상한 도달 |
| 쿼리 개선 전(임시) | 0.5–4 | 상한 해소, 스케일 시만 과금 |
| 쿼리 개선·캐시 후 | 재측정 값 기준 | CPU가 낮아지면 상한을 4에서 유지 또는 축소 |
| 트래픽 ×3 / ×10 / ×30 | 최대 12 / 40 / 120 (비례 산정) | 읽기 복제본·RDS Proxy 병행(×10 이상) |
| 최소 ACU | 0.5 (월 약 $44), 상시 부하가 생기면 상향 | 비용 하한 |

Aurora 비용은 인프라 23만원 중 최대 항목. 최소 ACU를 올리면 고정비가 늘므로 쿼리·캐시 개선이 선행.

## 6. 스키마 문서 현황

| 점검 | 결과 |
|---|---|
| 정본 DDL | `ERD/lens_schema_2026-08-26.sql` 1개(50개 테이블·뷰 1·확장 3). 이후 변경은 changelog md 코드블록에만 흩어짐 |
| 코드가 쓰는데 ERD에 없는 테이블 9개 | `prompt_lab_docs/files/threads/thread_messages` · `community_posts/comments/post_votes` · `thresholds` · `admin_login_lockout` · `selection_runs/selection_articles` (일부는 changelog v1.8·v1.28·v1.35에만 DDL) |
| 문서에 없는 컬럼 | `publications.admin_post_id/admin_channel/admin_publish_date/admin_extra`, `articles.raw_category` |
| 불일치 | 원본 SQL `source_url UNIQUE`는 v1.21에서 제거됨 · 원본 SQL·ERD는 tsvector/GIN, 코드는 ILIKE(v1.3은 pg_bigm으로 전환 기록) |
| 문서 낡음 | ERD README "아직 프로덕션 미반영" · HTML 재렌더 미반영(9/8 이후) · 테이블 수 50 vs 실제 59개 이상 |
| 이력 누락 | v1.35(9/28) 이후 변경에 버전 파일 없음, `prompt_lab_*` 생성 기록 없음 |
| 마이그레이션 | 도구 없음. 마스터 계정 수동 실행 후 changelog에 복붙. 앱 역할은 DDL 권한 없음, 롤백·적용 이력 없음 |
| 문서에는 있으나 코드가 안 쓰는 테이블 | 약 25개(`view_events`·`chat_*`·`embeddings`·`newsletter_sends` 등). 미구현인지 다른 경로 사용인지 미확인 |

## 7. 표준 문서 체계 (제안)

| 산출물 | 위치(제안) | 내용 |
|---|---|---|
| 현행 스키마 스냅샷 | `ERD/current_schema.sql` | `pg_dump -s` 결과, 변경마다 갱신 |
| 마이그레이션 파일 | `ERD/migrations/NNNN_*.sql` | changelog의 DDL 코드블록을 파일화, 롤백 DDL 포함 |
| 데이터 사전 | `ERD/16-data-dictionary.md` | `information_schema` 자동 생성 + 설명·코드값·개인정보 등급 수기. 컬럼 단위 타입·NULL·기본값·설명 |
| 변경 이력 | `db-changelog/postgres/vX.Y-*.md` | 상단 필수 블록: 적용일·환경·실행 DDL·롤백 DDL·영향 repo 파일·검증 쿼리 |
| 적용 이력 | DB `schema_migrations` 테이블 | 도구 도입(Alembic/Flyway) 검토 시 대체 |
| 정책 표 | 데이터 사전 부록 | FK ON DELETE 정책 · 인덱스↔쿼리 매핑 · 보존·파티션 · 역할·권한 매트릭스 · 코드값(status·format·channel↔format) |
| ERD | `.mmd` + HTML 재렌더 | 변경 PR 체크리스트에 포함 |

문서 헤더 필수 항목: 버전 · 갱신일 · 적용 환경(dev/prod) · 소유자.
