### 기능·저장값 재검증

- 홈의 추천 카드 1개·저장 카드 1개·5분 설정 유지. 아직 안 읽은 레터 필터에서 완료된 합성 레터가 제외되고 전체로 돌아오면 다시 표시된다.
- 합성 북마크 해제→빈 목록→재저장→1개 복원, 읽을 시간 5→10→5 저장과 재집계를 확인했다.
- 홈→서랍 전환과 서랍 직접 진입 모두 문장 1개·저장 레터 1개를 표시했다. 직접 선택한 문장의 관련 뉴스 1개와 서랍 검색·검색 해제도 유지된다.
- 기록 탭의 열람·저장 개수 각각 1편, 월·연 전환을 확인했다. 기록 탭에서 북마크/문장 변경 이벤트를 보내면 집계만 재조회하고 전체 북마크·문장·팔로우·공개 레터를 요청하지 않는다.
- 설정 탭에서 UTC 초안을 만든 뒤 focus 재조회에도 초안 유지, 변경 취소 시 런던 복원, UTC 저장→런던 재저장을 확인했다. 새로고침 뒤에도 원래 시각 14:35·Europe/London을 표시한다.
- 최종 fixture 조회로 알림 12개 설정 필드, 관심사 7개, 읽을 시간 5, 동의·기기 1개, 북마크·문장 1개와 원래 팔로우 없음 상태를 대조했다. 실제 동의 변경·기기 삭제 요청은 없었다. 합성 환경에서 저장을 왕복해 알림 revision은 7→9, 관심 설정 revision은 4→6으로 증가했다.
- 집계 전체에 503을 주입해도 기록 탭의 저장 개수는 전체 북마크 조회로 1편을 표시한다. 집계 재시도 후 열람·저장 개수 모두 복구된다.
- 서랍·저장 레터 조회 503 각각의 안내·재시도·기존 데이터 복구를 확인했다. 문장 삭제 확인 취소는 1개를 유지했고 실제 합성 문장 삭제 후 홈 요약도 비워졌다. 이후 fixture 문장을 원래 값으로 복원했다.
- 합성 팔로우를 변경한 뒤 focus로 재조회해 에디터 링크가 갱신됨을 확인하고 원래 상태로 복원했다.
- 서랍 API를 700ms 지연시키고 서랍→설정으로 이동했다. 서랍 요청은 약 541ms에 본문 0바이트로 취소됐고 설정 화면에는 이전 문장이나 오류 안내가 남지 않았다.
- 401 주입 시 개인 카드를 내리고 `/login`으로 이동했다. 실패 주입을 모두 해제한 뒤 정상 설정 화면과 복원된 값으로 다시 확인했다.

## 결정

N01은 프론트 조회 활성화 조건과 백엔드 선택적 탭 집계까지 로컬에서 구현·재검증했다. 기존 클라이언트는 tab 인자 없이 기존 전체 계약을 유지하고, 이전 백엔드도 새 쿼리를 무시하면 기존 전체 응답으로 기능이 유지된다. 미조회 영역은 명시적으로 unavailable이며, 값이 필요한 오류 경로의 대체 조회는 보존한다.

변경은 프론트 제품 소스 7개·테스트 1개, 백엔드 제품 소스 1개·테스트 1개와 이 보고서다. 기존 별도 작업 기록의 SHA256 `fa6a2bb2c54f3da9344680d72876eed960f93a826070f195ef7bd8cb125cd8f5`를 유지한다. 임시 내부 브라우저 탭과 API/Next 서버를 종료했다. 구현·검증 종료 시점에는 HEAD가 기준 커밋 그대로이고 Git index는 비어 있었으며, 커밋·push·배포는 하지 않았다. 후속 커밋 요청에 따라 위 소스 8개·테스트 2개와 이 보고서만 로컬 커밋 대상으로 확정했다. 기존 별도 작업 기록은 제외하고 push·배포는 수행하지 않는다.
