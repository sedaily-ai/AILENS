# 2026-10-23 웹툰 CMS JSON 오류와 실시간 연결 전송 실패 진단

관련: `admin/backend/routes/chat_ws.py`, `pipelines/common/json_extract.py`, `admin/frontend/src/lib/useAdminChatSocket.ts`

## 배경

웹툰 CMS에서 코인세 기사 입력 후 `Bedrock 응답에서 JSON을 찾지 못했습니다`가 표시됐다. 프로그램 문제인지 다른 작업의 동시 실행 영향인지 확인했다.

## 한 것

- 현재 체크아웃 `bb3272b8`의 응답 처리 코드를 확인하고, CloudWatch `/aws/lambda/sedaily-mbti-admin-api-dev`를 읽기 전용으로 조회했다.
- 2026-10-23 10:14:32 KST의 요청 `4fcd054d-59e8-4292-98ad-73179a18de78`에서 스크린샷 기사와 일치하는 코인세 응답을 찾았다. 실제 선택 모델은 `opus-5`였다.
- 해당 요청은 `ws connection gone` 로그 다음 약 16ms 뒤 JSON 파싱에 실패했다. 실행 시간은 약 36.88초였고 Lambda 타임아웃으로 종료되지 않았다. Bedrock 응답 앞부분에는 `layout`, `selected_facts`, `cuts` 등 JSON 내용이 있었다.
- 09:59:21, 10:00:08 KST의 임금 격차 기사 요청 두 건에서도 같은 연결 ID에 `ws connection gone` 다음 JSON 파싱 실패가 기록됐다.
- 09:30~10:20 KST의 해당 Lambda 로그에서 `ThrottlingException`, `TooManyRequestsException`, `ServiceUnavailableException`, `ModelStreamErrorException`, `modelStreamErrorException`, `throttlingException`, `Task timed out`을 검색했으며 결과는 0건이었다. 계정 전체의 부하나 다른 작업 전체를 검사한 것은 아니다.
- `_make_push`는 WebSocket 전송의 `GoneException`에 `False`를 반환한다. `_stream_json_completion`은 청크 전송이 한 번 실패하면 응답 수신을 중단하고, 이미 받은 부분만 반환한다. 호출부는 그 반환값을 완성된 JSON처럼 파싱한다.
- 실제 `_stream_json_completion` 함수를 AST로 분리해 가짜 Bedrock 스트림으로 실행했다. 정상 전송에서는 `{"cuts":[{"cut":1}]}` 파싱이 성공했고, 첫 청크 전송 실패에서는 `{"cuts":[`만 반환돼 신고와 동일한 오류를 재현했다. 이 재현에서 외부 API 및 Bedrock 호출은 0회다.
- [AWS 공식 안내](https://repost.aws/knowledge-center/410-gone-api-gateway)에서 `GoneException`이 연결 상태·연결 ID 관련 오류임을 확인했다.

## 결정

- 프로그램이 WebSocket 전송 실패를 응답 수신 중단으로 처리하고, 부분 응답을 JSON 오류로 표시하는 결함은 코드와 로컬 재현으로 확인했다. 운영 로그의 순서도 이 경로와 부합한다.
- 동시 실행 때문에 Bedrock 호출 제한에 걸렸다는 근거는 확인되지 않았다. 작업을 중지할 필요가 있다는 판단은 하지 않는다.
- 연결 전송 실패의 최초 원인(브라우저, 네트워크, API Gateway 등)은 미확정이다. 운영 로그는 응답 앞 2,000자만 남기고 종료 사유·전체 길이를 기록하지 않아, 전체 응답이나 모든 오류 가능성을 확정할 수 없다.
- 최초 요청의 범위는 원인 진단이었다. 해당 단계에서는 애플리케이션 코드·운영 프롬프트·인프라 변경, 배포, 커밋·push를 수행하지 않았다. 이후 사용자 요청에 따른 수정·배포는 아래 후속 기록을 따른다.

## 다음

- 임시로 입력 원문을 보관한 뒤 CMS를 새로고침해 새 연결에서 재시도할 수 있다. 근본 해결을 보장하는 조치는 아니다.

- 연결 실패 원인을 더 좁히려면 API Gateway 실행 로그와 브라우저 종료 코드, 응답 종료 사유를 연계한다. 현재 로그만으로 사용자 행동이나 특정 동시 작업을 원인으로 단정하지 않는다.
