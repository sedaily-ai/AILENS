# 웹툰 참조 이미지 3컷 시험과 CMS 적용 방향

> 후속 정정: 사용자가 Stable Image Ultra 사용을 명시했다. 아래 GPT Image 참조 모드 제안은 현재 적용안에서 제외한다. Bedrock Ultra는 실제 API에서 image-to-image를 거부했으며, 내장 도구의 1536×1024 결과를 Ultra 품질로 볼 수 없다. 현재 모델에 대한 측정과 적용 방향은 [Ultra API 3컷 실측](2026-10-21-웹툰-Ultra-API-3컷-실측.md)을 따른다. 아래 내용은 당시 시험 이력이다.

## 배경

사용자는 기사별 기준 이미지를 정하고 컷별 고해상도로 생성하는 방식의 3컷 시험을 요청했다. 확인 대상은 정면·측면·다른 장소에서도 유지되는 인물 일관성, 확대 품질, CMS 적용 방향이다. 이번 범위는 시각 시험과 적용 방향 정리이며 CMS 기능 구현·배포는 포함하지 않는다.

## 한 것

### 생성 조건과 자료

- `imagegen` 스킬의 기본 내장 `image_gen` 경로를 사용했다. CLI·CMS API·Bedrock 호출은 하지 않았다.
- 내장 도구가 모델 ID·버전·API 비용을 공개하지 않아 특정 API 모델로 생성했다고 기록하지 않는다. 모델별 품질 또는 비용 비교 결과로 사용할 수 없다.
- 가상의 성인 여성 진행자 한 명과 뉴스룸을 담은 기준 이미지 1장을 먼저 만들었다. 기존 제공 레퍼런스의 선화·성인 비율·네이비 계열 방향을 문장으로 반영했으며, 원본 스크린샷 자체를 도구에 참조 파일로 전달한 시험은 아니다.
- 매 컷에서 원래 기준 이미지 파일을 직접 전달했다. 이전 컷을 연쇄적으로 참조하지 않았다.
- 컷 1은 정면 설명, 컷 2는 측면, 컷 3은 야외 버스 정류장이다. 시각적 변화에 집중한 시험으로, 기사 선정·사실 추출 모델은 호출하지 않았다.
- 최초 측면 컷이 약간 정면으로 돌아와 있어, 한쪽 눈만 보이는 옆모습과 얼굴 클로즈업으로 지시를 좁혀 1회 수정했다. 최종 3컷 외에 기준 1장·폐기하지 않은 최초 측면 1장으로 **총 5회 생성**했다.
- 원본은 기준·최종 3컷·최초 측면 모두 **1536×1024 PNG**다. 보간 확대, 선명화, 얼굴 보정으로 원본 품질을 바꾸지 않았다.

로컬 산출물 폴더: `local/persona/webtoon-reference-3cut-20261021/`. 생성물을 프로젝트 폴더로 복사했으며 폴더 내부 `.gitignore`로 대용량 시험 파일을 Git에서 제외했다.

| 파일 | 용도 |
|---|---|
| `master.png`, `master-prompt.txt` | 기준 이미지와 생성 지시 |
| `cut-1.png`, `cut-2.png`, `cut-3.png` | 최종 정면·측면·야외 컷 |
| `cut-2-initial.png` | 수정 전 측면 컷 |
| `prompts.json`, `cut-2-retry.json` | 실제 컷 생성 지시와 수정 지시 |
| `manifest.json` | 파일 크기·해상도·SHA-256·원본 경로 |
| `comparison.jpg` | 기준과 최종 3컷 전체 비교 |
| `face-100pct.png`, `face-200pct.png` | 얼굴 부분의 원본 픽셀·200% 확대 검사 |
| `review.html` | 로컬 비교·확대 보기. 768/1536/3072px 표시 크기 선택, 원본 다운로드 |

확대 검사 자료만 잘라내기·배치·nearest-neighbor 확대를 사용했다. 200% 파일은 원본 픽셀을 드러내는 검사 자료이며 고해상도 복원 결과가 아니다. 측면 최종은 더 가까운 구도라 같은 320×320 픽셀 영역에서 얼굴이 더 크게 보인다. 다른 컷의 얼굴 크기를 인위적으로 맞추지 않았다.

### 육안 검토 결과

| 항목 | 관찰과 판정 |
|---|---|
| 인물 일관성 | 최종 3컷에서 같은 캐릭터로 읽힌다. 눈·머리 색, 단발 길이, 가르마, 전체 얼굴 인상이 이어진다. 눈매·턱선·머리카락 곡선의 세부 차이는 남는다. 정량 유사도 점수를 산출하지 않았다. |
| 의상·화풍 | 네이비 재킷·아이보리 셔츠·깨끗한 선화·명암 표현이 유지된다. 야외 컷도 같은 표현 방식이다. |
| 원본 품질 | 얼굴과 머리카락의 원본 크기·200% 검사 이미지를 직접 확인했다. 100%에서 눈·머리카락·옷깃 선이 읽히며 큰 블록형 압축 손상은 보이지 않는다. 최종 측면 수정본도 직접 확인했다. |
| 확대 한계 | 원본 200%에서는 픽셀 계단과 일부 부드러운 표현이 드러난다. 4K 원본이나 무제한 확대 품질을 확보한 시험이 아니다. |
| 무문자·인원 | 최종 3컷 육안 검토에서 가짜 글자·추가 인물·안경·장신구가 보이지 않는다. OCR 또는 자동 판별 점수는 산출하지 않았다. |
| 구도 지시 | 최초 측면은 엄격한 옆모습 지시에 미달해 1회 수정했다. 수정본은 측면에 더 가깝고 얼굴을 크게 보여주지만, 200% 검사에서 반대쪽 눈 일부가 남아 정확한 90도·한쪽 눈만 보이기 조건은 부분 통과다. |
| 자막 영역 | 컷 1의 손 일부가 하단 22% 영역과 겹친다. 공간 확보 지시만으로 후합성 안전 영역을 보장할 수 없다. |
| 장소 | 뉴스룸의 창문·네이비 벽·디스플레이·책상 단서가 이어진다. 정확한 3D 구조 일치나 야외 장소 재등장 연속성은 검증하지 않았다. |

최종 판단은 **시각적 가능성 확인, CMS 실험 모드 연동을 추진할 근거 확보**다. 운영 품질 승인이나 모든 기사에서의 재현성 확인으로 간주하지 않는다. 앞선 Ultra 8컷과는 모델·구도·장면 복잡도가 달라, 이번 개선을 참조 입력 하나의 효과로 분리해 입증한 A/B 시험은 아니다.

가로 768 이미지 픽셀로 출력하는 화면을 기준으로 2배 너비인 1536px까지는 원본에 담긴 샘플을 사용할 수 있다. 이는 CSS 768px에서 모든 기기의 2배 확대가 선명하다는 보장이 아니다. 레티나 화면의 기기 픽셀 비율·브라우저 배율·이미지 재압축·실제 게시 레이아웃은 별도 확인해야 한다.

### 확인한 CMS 코드

- `admin/backend/openai_image.py::generate_image_bytes`: 현재 `/v1/images/generations`, 기본 `gpt-image-1`, 기본 세로 `1024x1536`, 90초 타임아웃, 이미지 참조 입력 없음.
- `admin/backend/routes/webtoon/generate.py::_generate_composed`: `openai_dalle3`라는 기존 선택 키가 위 어댑터를 호출한다. 이 이름만 보고 실제 DALL-E 3 호출로 해석하면 안 된다.
- `pipelines/common/webtoon_image.py`: 현재 Ultra 생성 요청은 텍스트·negative·seed·종횡비 등이며 참조 이미지 파일을 전달하지 않는다.
- `admin/frontend/src/components/WebtoonCutGenerator/WebtoonCutGenerator.tsx`: 테스트별 컷 생성·재생성 UI가 있어 새 전체 화면을 만드는 대신 참조 세트 선택을 붙일 수 있다.
- `admin/backend/routes/webtoon/jobs.py`: 생성 작업 기록이 있으므로 실제 참조 버전·모델·결과 크기 등을 이력으로 남기는 연결 지점으로 검토한다.

## 결정

### 권장 CMS 최소 적용 범위

1. **기사별 기준 이미지 세트**
   - 기사 또는 챗랩 세션에 기준 이미지를 등록·생성하고 버전으로 확정한다.
   - 이번 시험은 인물·화풍·뉴스룸이 한 이미지에 합쳐진 형태다. 인물·장소·화풍을 별도 이미지로 나누어 함께 전달하는 방식은 다음 API 시험에서 확인한다.
   - 다른 기사에서는 새 기준을 선택한다. 전 기사에 동일 인물·배경을 강제하지 않는다.

2. **참조를 실제로 전달하는 별도 생성 모드**
   - 텍스트에 파일명만 쓰는 방식이 아니라 서버가 이미지 바이트 또는 공급자가 지원하는 파일 참조를 전달한다.
   - 기존 `openai_dalle3` 키의 동작을 몰래 바꾸지 않고, 명시적인 참조 생성 모드와 실제 공급자 모델 ID를 구분한다.
   - GPT Image의 참조 이미지 입력·편집 경로를 첫 통합 후보로 삼되, 사용할 계정의 접근 권한·모델·크기·가격은 실제 API 연결 시 확인한다. 내장 도구의 결과와 동일 모델·품질이라고 가정하지 않는다.
   - CMS와 발행 경로가 동일 어댑터를 소비하도록 구성한다. 챗랩만 동작하고 발행에서는 참조가 사라지는 구현을 피한다.

3. **기사 기준 버전과 컷 이력 연결**
   - 기사/세션 ID, 기준 세트 버전, 원본 파일 해시, 컷별 사용 참조, 프롬프트 버전, 공급자·모델·출력 옵션, 결과 원본 크기·작업 ID·시도를 함께 기록한다.
   - 기준 이미지 교체 시 과거 결과의 참조 정보를 덮어쓰지 않는다. 참조 누락·권한 오류는 명시적으로 실패시키고 텍스트 전용 생성으로 조용히 전환하지 않는다.
   - 외부 임의 URL을 서버가 가져오게 하기보다 해당 기사에서 접근 가능한 업로드 자산을 검증해 사용한다.

4. **확대 비교와 선택 컷 수정**
   - 기존 컷 생성 UI에 기준 이미지와 원본 크기 비교를 추가한다.
   - 초기에는 편집자 선택으로 문제가 있는 컷만 수정한다. 무제한 자동 재생성은 넣지 않는다.
   - 원본 파일을 보존하고 미리보기 썸네일과 구분한다. 큰 크기를 요청해도 응답이 작으면 실제 크기를 표시한다.

5. **자막과 최종 출력**
   - 얼굴·손을 덮지 않는 별도 하단 자막 영역을 우선 시안으로 비교한다. 이는 제품 레이아웃 변경 제안이며 아직 적용하지 않았다.
   - 기존 겹침 자막을 유지할 때는 컷별 위치 조절과 실제 합성 미리보기가 필요하다.
   - 최종 개별 컷과 세로 합성본을 모두 제공한다. 원본을 키웠다는 이유만으로 품질 통과 처리하지 않는다.

### 단계별 적용

- **첫 단계:** 챗랩에서 기준 이미지 선택·실제 API 참조 생성·원본 보존·선택 컷 수정까지 연결한다.
- **다음 검증:** 같은 기준과 장면으로 API 3컷을 재현하고, 다인물·8컷 전체·실제 기사·게시 화면 확대를 검사한다. 참조 해제/사용의 동일 모델 비교도 여기서 진행할 수 있다.
- **이후:** 재생성 횟수·소요 시간·실제 비용을 근거로 기본 모델·출력 크기·확대 지원 범위를 결정하고 발행 경로에 확대한다.

참조 이미지 입력과 편집은 [OpenAI 공식 이미지 생성 가이드](https://developers.openai.com/api/docs/guides/image-generation)에 문서화돼 있다. 같은 문서가 반복 캐릭터 일관성과 정확한 구도 제어의 한계도 명시하므로, 참조 입력만으로 검수를 제거하지 않는다.

## 다음

이번에 완료한 것은 3컷 시각 시험, 원본·확대 증거 보존, CMS 적용 방향 정리다. CMS 참조 기능 코드·배포·실제 API 키/모델 접근 시험은 하지 않았다. 기존 운영 모델·활성 프롬프트·AWS 태그를 변경하지 않았다. 커밋·push도 수행하지 않았다.
