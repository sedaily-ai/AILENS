## 결정

- 관련 변경만 한 목적의 커밋과 PR로 묶는다. 이전 PR 이력을 수정하거나 기본 브랜치에 직접 push하지 않는다.
- 배포 순서는 DB 권한 선행 확인 → CMS API → 공개 계정 API → 프런트엔드다. 백엔드가 준비되기 전에 새 삭제 버튼을 노출하지 않는다.
- 운영 권한과 실제 배포 결과는 미확인으로 남긴다. 로컬 검증을 운영 반영 완료로 표현하지 않는다.
