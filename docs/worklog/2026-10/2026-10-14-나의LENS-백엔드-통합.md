# 2026-10-14 나의 LENS 계정 백엔드와 웹 연결 통합

관련: `feat/my-lens-account-storage` · [현재 구현 문서](../../product/나의LENS/README.md) · [운영 적용 단계](../../product/나의LENS/운영적용_남은단계.md)

## 배경

브라우저 중심이었던 나의 LENS의 관심·저장·추천·읽기 기록을 로그인 계정에 연결한다. 여러 개발 묶음과 후속 오류 수정을 하나의 변경 범위로 정리하고, 백엔드 담당자가 현재 계약과 운영 적용 조건을 함께 인수할 수 있게 한다.

## 한 것

- 기존 Python Lambda → 내부 FastAPI → PostgreSQL 구조에서 검증된 Cognito sub로 개인 API의 소유자를 결정하고 서랍 조회 인증을 보완했다.
- publication/issue_letter의 안정적인 콘텐츠 ID를 해석하고, 계정 관심·읽을 시간·레터 북마크·에디터 팔로우를 저장한다.
- 유효 이용 신호·직접 선택한 관심·저장 문장으로 뉴스/레터를 추천하고 개인 홈의 자료를 집계한다.
- 콘텐츠 완료 판정, 한국 시간 기준 주·월·연 기록, 중복을 제한하는 스탬프·주간 배지를 구현한다.
- 실제 이용한 읽기·웹툰·듣기·영상 형식을 계정별로 분석하고, 제공되는 형식 안에서 추천·알림 후보와 기사 링크에 반영한다.
- 알림 worker의 요청 모드를 계획·lease·송신까지 묶고 dry_run에서 provider 호출을 차단한다.
- 개인화 알림 설정·별도 수신 동의·암호화 기기 구독·후보와 전달 원장·oneshot worker·웹 기기 연결을 구현한다.
- 레터 저장·해제의 로그인 필수 정책, 서버 완료 읽음 필터, 사용자 선택 브라우저 북마크 가져오기를 웹 목록·상세·대시보드에 연결한다.
- 빈/미래/비공개 콘텐츠, 기존 서랍 원문 연결, 계정 전환·조회 실패·설정 충돌, 알림 후보 누락·계획 순서·lease 및 가져오기 재시도를 보완한다.
- 일부 형식만 제공하는 기사의 탭·본문·분량·계측을 실제 format에 맞추고 존재하는 형식 사이에서만 이동한다.
- 기존 읽기 이력의 articles 별칭을 유지해 기존 프로필·읽기 기록 API의 조회/저장 계약을 보존한다.
- v1.48~v1.54 SQL, 최신 API·기능 구현 문서, 작업별 기록과 운영 적용 순서를 정리했다.

## 결정

- 현재 웹 대시보드와 신규 계정 API를 변경 범위로 묶는다. 기존 모바일 앱의 브라우저/기기 저장 방식을 신규 API로 이관하는 작업은 포함하지 않는다. 기존 인증된 문장 API의 응답 필드는 유지하고 안정 ID·주소만 추가한다.
- 과거 공용 브라우저 데이터는 원본을 유지하며 자동 병합하지 않는다. 가져오기는 사용자가 선택한 레터 북마크만 처리하고 관심·읽음·팔로우·알림 동의를 생성하지 않는다.
- 기능의 회귀 테스트 소스는 변경 코드와 함께 유지한다. 검증 로그·화면 캡처·실행 결과 보고서는 커밋과 PR 본문에서 제외한다.
- 이번 공유 범위는 작업 기록·커밋·작업 브랜치 push·PR 생성이다. 운영 DB·배포·실제 푸시 발송은 수행하지 않는다.
- 리워드는 완료 기록과 중복 방지 규칙을 사용한다. 의미 유사도 추천·품질 평가와 메타데이터/편집 관계 공급 자동화는 별도 작업이다.
