**목표:** 스무 살 생일(서른 살 생일 전이면 태어난 날)에 100만 원을 정기예금·달러·서울 아파트·금 한 돈에 뒀다면 지금 어떻게 됐는지를, 이용 근거가 확인된 한국은행 ECOS 공식 통계(금은 세계은행 Pink Sheet, CC BY 4.0)로만 계산해 고정 순서로 보여 주고, 칸 목록 아래에 같은 기간 물가를 한 줄로 적는다. 투자 권유로 읽히지 않게 1등 강조·정렬은 하지 않는다.

**구조:** 로컬 수집 스크립트가 ECOS 원자료를 받아 기준일 연도별 정적 JSON과 `latest.json`을 만든다(`service/frontend/public/data/birthday-assets/`, 같은 출처 정적 파일). 웹은 기준일 연도 파일과 `latest.json` 두 개만 받아 기기 안에서 계산한다. 서버에는 연도만 드러나고(공유 링크에도 이미 들어 있는 값) 생일 날짜는 가지 않는다. 1단계는 새 AWS 리소스를 만들지 않는다. 최신값 갱신은 스크립트를 다시 돌리고 웹을 배포하는 월 1회 수동 절차다.

**기술:** Python 3 스크립트(`requests`, `boto3`, `openpyxl`, `uv run --no-project`로 실행)·pytest, Next.js 16·TypeScript·vitest.

## 전역 제약

- 이용 근거(약관·라이선스 URL과 해당 문구)를 작업 0에서 기록한 출처만 수집한다(스크립트 `SOURCES`의 `allowed`). 근거가 없는 항목은 수집하지 않고 화면에도 보이지 않는다. "준비 중"으로 이름만 남기지 않는다.
- 값은 스크립트가 원자료에서 만든 것만 넣는다. 손으로 넣은 값, 추정치, AI가 만든 값은 쓰지 않는다. 생성 JSON도 손으로 고치지 않는다.
- 생일 날짜는 서버로 보내지 않는다. 요청 주소에는 기준일 연도만 담는다.
- ECOS 인증키는 수집 스크립트에서만 쓴다. 웹 코드와 JSON에는 넣지 않는다. 보관은 SSM SecureString `us-east-1 /sedaily-mbti/ecos-api-key`이고 출력·로그·파일에 남기지 않는다(요청 예외 메시지에서도 가린다).
- 표시
  - 기본은 "100만 원 → 지금 N만 원(±N%)"이고 배수는 막대 옆에 쓴다(`ASSET_STAKE = 1_000_000`).
  - 물가는 칸이 아니라 칸 목록 아래 한 줄: "같은 기간 물가는 N배 올랐어요."(1배로 반올림되면 "N% 올랐어요"·"거의 그대로예요"). 영수증에는 넣지 않는다.
  - 증감은 색이 아니라 ▲/▼(낭독 제외)와 부호 있는 %(감소는 U+2212 −)로 쓴다. 글자색은 같다.
  - 실제 단가가 있는 항목만 단가 줄을 덧붙인다(1달러, 금 1돈).
  - 서울 아파트는 지수라서 배수만 쓴다("서울 아파트값 N배"). 원 금액·"1채" 표현을 쓰지 않는다.
  - 출처 줄에 "한국은행 ECOS" 제공, 작성기관(한국은행·국가데이터처·한국부동산원), 칸별 "지금" 기준 시점을 적는다. 금 칸이 보이면 "세계은행 Pink Sheet(CC BY 4.0)"를 장면 출처 줄과 하단 출처 줄에 함께 적는다(CC BY 4.0 출처·라이선스 표시). 세금·수수료는 빼고 계산했고 투자 권유가 아니라고 밝힌다.
- 휴일이면 직전 영업일 종가를 쓴다(`onOrBefore`, 메모 "휴일이라 직전 영업일 종가로 계산했어요.").
- UI(`.kiro/steering/ui-ux-principles.md`): 375px 우선, 터치 44px, 글자 13px 이상(본문 16px), 간격 4px 배수, `birthdayStory.module.css`의 기존 클래스만 쓴다(새 CSS 값 없음). 강조색은 #1d4ed8 하나.

- 칸은 기준일에 따라 1~4개다: 2006년 이후 네 칸, 1996~2005년 세 칸(정기예금·달러·금), 1964-05-04~1995년 두 칸(달러·금). 기준월이 금값 마지막 달보다 뒤면(지금은 2026-10부터) 금 칸이 빠진다. 칸을 억지로 채우지 않는다. 물가 줄은 1965-01 이후 기준일에만 붙는다(1964-05-04~12-31은 달러 한 칸뿐).
- 현금 칸은 2026-10-21에 뺐다(사용자 승인). 막대가 늘 1배라 비교할 게 없었고, 영수증의 "현금 그대로 100만 원"은 누구에게나 같은 값이었으며, 1080×1920 영수증에 금 한 돈 줄 자리가 필요했다. 물가는 다른 칸을 읽는 기준이라 칸과 같은 기간으로 한 줄 남긴다(1억 원 장면은 태어난 해 기준이라 기간이 다르다).
- 2단계(이용 근거를 확보한 뒤): 삼성전자·SK하이닉스·코스피는 사내 시세 계약 범위 또는 KRX 계약, 비트코인은 두나무 영리 이용 허락, 원 단위 서울 아파트는 국토교통부 실거래가 API 활용신청 뒤 다시 설계한다.
- 기준일(`assetBase`)
  - 서른 살 생일(`anniversary(date, 30)`, 2월 29일은 기존 규칙대로 말일)이 오늘 이전(당일 포함)이면 스무 살 생일(`anniversary(date, 20)`), 아직이면 태어난 날이다. 비교 기간이 늘 10년 이상(또는 태어난 뒤 전체)이 된다.
  - 2026-10-21에 고쳤다(사용자 승인). 처음엔 스무 살 생일이 지나면 스무 살 생일이라 21살은 1년 치만 비교돼 의미가 없었다. 서른 살 경계가 1996년생이라 태어난 날 기준인 사람(1996년 10월 이후 출생)은 정기예금 기록(1996-01~)이 늘 있다. 대가로 2006년 전에 태어난 서른 살 전(지금 20~29살)은 서울 아파트 칸(2006-01~)이 빠진다.
  - 연도만 공유된 결과(`mode === 'year'`)는 그해 1월 1일 기준이라, 서른 살이 되는 해의 1월 1일부터 스무 살이 된 해의 1월 1일이 된다(1990년생 → 2010-01-01, 1997년생 → 1997-01-01).
  - 기준일이 1964-05-04(원/달러 기록 시작)보다 앞서면 칸을 만들지 않고 파일도 요청하지 않으며 한 줄로 안내한다.

## 파일 형식

공통: 점은 `[시점, 값]`, 시점 오름차순. 일별 `YYYY-MM-DD`(KST), 월별 `YYYY-MM`. 연도 파일은 한 줄 JSON, `latest.json`은 들여쓰기 1.

연도 파일 `{YYYY}.json`(YYYY = 기준일 연도). 허용되지 않은 출처의 키는 없고, 자료 시작 전 연도는 빈 배열이다. 생성 시각은 넣지 않는다(매달 갱신 때 지난 해 파일이 바뀌지 않게).

```json
{ "year": 2010,
  "cpi": [["2010-01", 85.351], …],
  "deposit": [["2010-01", 2.380262319], …],
  "usdkrw": { "daily": [["2009-12-16", 1164.9], …, ["2010-12-30", 1134.8]], "monthly": [["2010-01", 1138.82], …] },
  "apartment": [["2010-01", 41.3], …] }
```

- `deposit`은 금리가 발표된 달의 월초 누적지수 I(m): I(1996-01) = 1, I(m+1) = I(m) × (1 + r_m ÷ 1200), 각 값 소수 10자리. 금리가 빠진 달이 있으면 스크립트가 멈춘다.
- `usdkrw.daily`는 전년 마지막 10영업일을 함께 넣는다(1월 1일·연초 휴일 기준일의 직전 영업일).

`latest.json`:

```json
{ "generatedAt": "2026-10-21T13:40:20+09:00", "until": "2026-10-20",
  "sources": { "cpi": "…(한국은행 ECOS 901Y009)", "deposit": "…(121Y002)", "usdkrw": "…(731Y003·731Y004)", "apartment": "…(901Y089)" },
  "last": { "cpi": "2026-09", "deposit_rate": "2026-08", "usdkrw_daily": "2026-10-20", "usdkrw_monthly": "2026-09", "apartment": "2026-07" },
  "cpi": ["2026-09", 120.43], "deposit": ["2026-09", 3.5601204401],
  "usdkrw": { "daily": ["2026-10-20", 1328.1], "monthly": ["2026-09", 1359.0] }, "apartment": ["2026-07", 101.9] }
```

- `last`는 원계열별 마지막 시점(예금은 마지막 금리 달, 금은 엑셀의 마지막 금값 달). 금은 `gold: { usd, usdkrw }`(두 계열 공통 최신월)로 들어간다(2026-10-21 켬).

## 검토 초점

1. 기준일이 1월 1일이거나 연초 휴일이면 직전 영업일이 전년도에 있다 → 연도 파일에 전년 마지막 10영업일(`test_year_file_includes_previous_year_tail`, 프런트 `달러: 1990-03-02부터는 …` 테스트의 1월 1일 경우).
2. 기준월의 월별 자료가 아직 발표되지 않았다(이번 달 기준일의 물가·아파트, 마지막 금리 달 뒤의 예금) → 그 칸만 빼고 나머지는 보여 준다(`정기예금: … 금리가 없는 달은 칸이 없다`, `서울 아파트: … 미발표 달은 칸이 없다`).
3. 연도 파일 요청이 실패한다(네트워크, 배포 직후 캐시) → 자산 장면만 오류와 "다시 불러오기"를 보이고 다른 장면은 그대로다(Playwright 오류 → 복구 경우).
4. 스무 살 생일이 기준일인 사용자에게 "태어난 날"이라고 말하면 사실과 다르다 → 장면 제목·lead·영수증 소제목이 기준일 종류(스무 살·태어난 날)와 연도 공유 여부를 따른다(`100만 원 묶음 소제목은 기준일 종류에 따라 바뀐다`, Playwright 2010-08-20·연도 공유 경우).
5. 1배 미만(손실) 칸을 색으로만 구분하면 색각 이상 사용자가 놓친다 → ▲/▼ + 부호 %(1977-12-24 기준 달러 ▼ −28%로 확인).
