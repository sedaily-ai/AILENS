# 뉴스 웹툰 기사별 연출 프롬프트 개선 및 운영 반영

## 배경

사용자가 운영 프롬프트 증가 여부와 품질 평가 후 개선을 요청했다. 확인 시 대본 활성 v61, 최신 저장 v62, 이미지 활성 v29였다. v61은 반복 인물 금지·자막 단독·8종 장면 강제를 포함했고, 앞서 합의한 최대 2인과 대화·내레이션 혼합 기준과 달랐다.

## 한 것

- 대본 **v63**, 이미지 설정 **v30**을 비활성으로 저장한 뒤 검수 후 활성화했다. 기존 버전은 삭제하지 않았다. 활성화 직전 활성 내용·버전과 편집 초안 변경 여부를 확인했다. 내부 조회·공개 소비 API·편집 초안의 지침 일치를 확인했다.
- 대본 정본: `docs/architecture/webtoon_custom/뉴스웹툰_기사별연출_운영프롬프트_2026-10-23.md`. 이미지 설정 정본: `docs/architecture/webtoon_custom/뉴스웹툰_기사별연출_이미지설정_2026-10-23.md`.
- 기사별 scene_led/presenter_led 선택, 최대 두 성인·기사 안의 외형 유지, 실제 질문·답변과 내레이션 혼합, 이름·소개 없음, 장소 수·장면 종류 강제 해제, 원문 연속 인용·확정 수준·인과관계 분리, 근거 부족 시 needs_article 계약을 정리했다.
- 실제 CMS는 완성형 image_prompt에 별도 STYLE/캐릭터 설정을 자동으로 덧붙이지 않는다. 각 이미지 지문에 화풍·외형·장소가 독립적으로 포함되게 했다. 현재 요청 비율 3:2와 맞췄다. 이미지 설정은 sd_ultra 유지, BUBBLE_STYLE=on, BUBBLE_DETECT=off다.
- 실제 운영 Lambda에서 읽은 관련 7개 파일이 로컬과 동일함을 확인했다. 제품 코드·Lambda·프런트·ECS는 배포하지 않았다. 프롬프트 반영 당시 Git 작업은 하지 않았고, 이후 사용자 요청으로 아래 기록용 PR을 준비했다.
- 테스트 전에 Sonnet 5·Ultra 프로파일의 Service=lens를 확인했다. 기본 CMS 채팅 모델 Opus 5 프로파일은 atlas4여서 기존 사용자 승인·10월 정책에 따라 Service만 lens로 변경하고 재조회했다. 태그 갱신 응답이 빈 본문이라 로컬 도구 JSON 파서가 오류를 냈지만 쓰기는 성공했고, 중복 쓰기 없이 조회로 확인했다.

### 실제 검증과 제외한 결과

- 검증 기사는 합성 자료(주택 임대차 통계·위성 공동 발사 계획·도서관 보수·짧은 버스 기사)다. 실제 보도나 콘텐츠로 발행하지 않았다.
- 텍스트 실제 호출 총 13회, 기록된 입력 101,034·출력 85,215토큰. 초기 3회 시험 도구에서 운영의 thinking=disabled 설정을 빠뜨렸고, 긴 기사 2건은 max_tokens로 잘렸다. 이 결과를 통과로 쓰지 않았다. 이후 운영 설정·JSON 추출기를 맞춰 시험했다.
- 중간 후보에서 자막 70자 초과, 인물 문자열의 중첩 객체, 단독 질문·내레이션 반복, 잘못된 인과 연결·조건 확정화가 나타나 규칙을 보완했다. Sonnet의 형식 통과를 사실 정확성 통과로 간주하지 않았다.
- 최종 후보를 CMS 기본 Opus 5로 실행: 62.728초, 8컷, 대화 6컷, 정보 중심 2컷. 원문 인용·사실 ID 연결·70자 서버 제한·35자 대사·영어 화풍·고정 외형 문자열 검사를 통과했다. 최종 image_prompt는 636~791자다.
- 장면 중심 8컷은 자막 길이 보완 후보를 Sonnet 5로 시험해 서버 계약을 통과했다(47.323초). 짧은 기사도 needs_article와 빈 cuts를 반환해 실제 서버 검증 함수에서 보류됨을 확인했다(7.108초). 이 두 결과를 최종 후보의 동일 모델·동일 버전 전수 검증으로 확대하지 않는다.
- 테스트 호출은 실제 운영과 동일한 대본 조립 함수·모델 옵션·파서·검증 함수 및 이미지 공통 생성/합성 함수를 사용한 로컬 실행이다. 실제 Bedrock API를 호출했지만 CMS 로그인·웹소켓·저장 전체 UI를 거친 종단 시험은 아니다. 기존 pytest 실행은 설치된 pytest가 없어 실행되지 않았다. 제품 코드 변경은 없다.
- Ultra 호출 총 7회. 처음 3회는 서로 다른 프롬프트와 같은 seed에서 동일 SHA의 분할 초상이 나와 제외했다. 같은 seed의 장면 우선 시험 1회는 공유 공간으로 바뀌었으나 안경 누락·불필요한 로고가 있어 최종본으로 쓰지 않았다. 내부 토큰 잘림 등 원인은 확인하지 않았다.
- 화풍·외형을 줄이고 컷별 장소·동작을 앞에 배치한 최종 후보의 1·4·8컷은 CMS 기본값인 임의 seed로 생성했다. 원본 1216×832, 생성 왕복 시간 12.749, 12.65, 13.402초. 세 원본 SHA가 모두 다르고 공유 공간·서로 다른 자세가 나왔다. 기존 합성 함수로 대화·내레이션을 붙인 결과는 1216×1171이다. 얼굴 복사나 수동 그림 보정은 하지 않았다.
- 3컷 시각 검수에서 갈색 단발/안경/남색·코럴 의상과 은회색 머리/안경/청록·아이보리 의상을 구분할 수 있었다. 얼굴의 나이감·윤곽, 벽·책상 형태와 소품은 달라지고 8컷 배경은 단순화됐다. 정확한 동일 인물·공간, 8컷 전체 품질, 확대 무손실로 보고하지 않는다.
- 검수 페이지: `output/imagegen/webtoon-prompt-improvement-20261023/review.html`. 모든 요청·응답·이전 내용·활성 영수증·태그·관찰은 Git 제외 디렉터리 `local/persona/webtoon-improvement-20261023/`에 보존했다. 최종 검수 페이지에는 합성 시험 자료·모델·후보별 검증 범위를 표시했다.

### 팀 공유용 기록 정리

사용자가 앞선 웹툰 작업을 팀이 확인할 수 있도록 PR 기록을 요청했다. 이번 PR은 운영에 반영한 프롬프트 본문과 검증 자료를 보존한다. 제품 코드·운영 프롬프트 값을 다시 바꾸는 작업은 포함하지 않는다.

- [검증 자료와 실제 3컷](../../evaluation/webtoon/2026-10-23-prompt-quality/README.md): 합성 기사, 8컷 대본, 이미지 원본·한국어 합성본, 실제 이미지 요청, 생성 시간·사용량, 활성화 영수증·해시를 보존한다.
- [설계 기록](2026-10-23-웹툰-기사별연출-design.md)과 [완료된 실행 계획](2026-10-23-웹툰-기사별연출-plan.md)은 저장소 문서 규칙에 따라 worklog에 둔다. 원 작업의 로컬 `docs/superpowers/` 파일은 원래 작업 폴더에 보존하고 PR에서는 중복 게재하지 않는다.
- 현재 작업 폴더의 별도 CMS 연결 오류 수정은 독립 작업이므로 이 PR에 포함하지 않았다.

#### PR 준비 검증

- 원자료 27개의 SHA256·바이트 크기, 운영 정본 2개의 활성화 당시 해시, PNG 6개의 디코딩·크기를 대조했다.
- 저장된 설명형·장면형 대본 2건에 기존 `validate_storyboard`·`cut_metadata`를 다시 실행했다. 짧은 기사 1건의 보류 응답도 검증했다. 새 추론을 실행한 결과는 아니다.
- 최종 대본의 영어 화풍 문장·인물 문자열·대사 길이, 3개 실제 이미지 요청의 대본 지문 포함·seed 미지정을 확인했다. 기록된 13회 텍스트 토큰 합계를 다시 계산했다.
- staging된 파일이 모두 docs 아래인지, 추가한 Markdown 링크가 존재하는지, 비밀값 패턴이 없는지 검사했다. `git diff --cached --check`를 통과했다. 현재 pre-commit 필터는 제품 Python·프런트 코드에만 적용되므로 문서·JSON·PNG 변경은 해당하지 않는다.
- 실행: 임시 로컬 보존 검사 `verify-webtoon-pr-record.py`를 작업 환경의 Pillow 포함 Python으로 실행했다. [결과 영수증](../../evaluation/webtoon/2026-10-23-prompt-quality/record-verification.json)에 검증 범위를 보존했다. 테스트 기사 생성 때 실행하지 못한 pytest를 이번에 통과했다고 표시하지 않는다.
- 이미지 1·4·8컷을 다시 열어 위 시각 관찰을 대조했다. 4컷 노트·손동작 차이와 8컷 종이의 글자 같은 무늬도 잔여 한계로 기록했다.

## 결정

새 프롬프트와 기존 CMS 기능으로 적용한다. Ultra를 유지하고 모든 컷에 같은 seed를 강제로 넣지 않는다. 중요도·원문 조건·기사별 연출을 지침으로 개선하되 모델 출력의 사실 검수와 인물·배경 검수는 계속 필요하다. 연속성이 필요한 경우 같은 기사 안의 고정 외형·공간 설명을 사용한다. 배경·인물 묘사만으로 완전한 동일성을 보장한다고 설명하지 않는다.

## 다음

실제 기사에서 주체 누락·핵심 정보 누락·인과관계·계획 시제, 인물 얼굴·안경·복장·공간과 소품을 편집 검수한다. 최종 3컷 외의 모든 컷과 다양한 기사에서 성공률을 측정한 것은 아니다. 문제가 재현되면 해당 원본·대본·모델·프롬프트 버전으로 수정 범위를 좁힌다.

작업 종료 시 다른 작업에서 작성된 `2026-10-23-웹툰-CMS-JSON오류-연결진단.md`를 확인했다. WebSocket 전송 실패 후 부분 응답을 JSON으로 파싱하는 별도 코드 문제의 진단이며 이 작업에서는 해당 파일이나 코드를 수정하지 않았다. 이번 공개 프롬프트 값 검증·Bedrock 직접 검증으로 CMS 웹소켓 오류까지 해결됐다고 보고하지 않는다.
