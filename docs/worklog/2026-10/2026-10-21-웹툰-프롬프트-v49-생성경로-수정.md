# 웹툰 프롬프트 v49와 CMS 생성 경로 수정

## 배경

사용자는 뉴스 중요도에 따른 컷 구성, 선택적 대화, 높은 이미지 품질, 인물·배경·화풍 일관성을 요청했다. 뉴스룸 고정은 필수가 아니라고 정정했으므로 화풍과 인물 묘사를 고정하고 기사에 필요한 장소를 선택하는 방향으로 바꿨다. 기존 버전에 덧붙이는 방식으로 저장하며 활성 프롬프트는 유지한다.

기존 v48의 뉴스룸 고정 지침과 당시 검토 문서는 이력으로 보존한다. 당시 검토에서 한국어 image_prompt를 코드에 맞추는 방향은 공급자의 언어 정책을 충분히 반영하지 못했다. 실제 테스트에서 한국어 이미지 요청 2개가 `Filter reason: prompt`로 거부됐고 영어 요청은 성공했다. 언어만이 필터 원인이라고 단정할 수는 없지만, [Stability 공식 지원 언어 정책](https://kb.stability.ai/knowledge-base/supported-prompt-languages)에 맞춰 이미지용 프롬프트는 영어, 독자용 문구는 한국어로 수정했다.

## 한 것

### 프롬프트와 CMS 버전

- [최종 지침](../../architecture/webtoon_custom/화풍일관성_장소선택_프롬프트_2026-10-20.md)을 CMS `webtoon/published` **v49**로 저장했다.
- 표시 이름: **화풍·인물 일관성 · 장소 선택 · 기사 근거 검증**.
- 저장 시각: `2026-10-20T15:30:38.019985+00:00` (한국 시간 10월 21일).
- 저장·재조회 결과 본문과 sections가 일치했다. 활성 **v46** 및 활성 본문은 유지됐다.
- 저장 본문 SHA-256: `f26c5a69803f628ce3bfba0112a22a297503d136360a303c744c5c073dd14650` (파일 끝 공백 제거 기준).
- 중요도 1~6점과 확정 수준을 분리했다. 핵심 조건·반론은 점수와 무관하게 보존하며, 근거가 부족하면 8컷을 억지로 채우지 않는다.
- 사실 ID와 원문 직접 인용, 컷별 정보 역할을 연결했다. 설명 자막을 기본으로 하고 대화는 명시 요청 때만 사용한다.
- 동일한 짧은 화풍 문장·등장 인물 외형을 각 영어 이미지 프롬프트에 반복한다. 장소별 구조·광원은 정의하고 실제 보이는 요소만 컷에 넣는다.
- 생성 모델에 글자를 그리게 하지 않고 한국어 narration을 후합성한다. 모든 컷의 자막 형식과 하단 영역을 통일한다.

### 코드

| 경로 | 수정 이유·동작 |
|---|---|
| `pipelines/common/webtoon_contract.py` | CMS·배치의 출력 보강을 공유하고 근거 부족, 컷 개수·번호, 직접 인용, 메타데이터·이미지 옵션을 검증한다. |
| `admin/backend/routes/webtoon/script.py`, `routes/chat_ws.py` | 정규화 전 검증하고 사실·장소·이미지 옵션이 컷에 남도록 한다. |
| `admin/backend/routes/prompts.py` | JSON만 반환하도록 보강해 코드 펜스 관련 형식 충돌을 제거한다. |
| `admin/frontend/src/lib/types.ts`, `components/WebtoonCutGenerator/WebtoonCutGenerator.tsx` | 두 이미지 생성 진입점 모두 negative_prompt와 image_seed를 서버로 전달한다. |
| `admin/backend/routes/webtoon/generate.py`, `pipelines/common/webtoon_image.py` | 요청별 옵션을 Stability 호출까지 전달하고 순화 재시도에도 보존한다. 빈 CMS 옵션은 배치 전역값을 상속하지 않는다. |
| `pipelines/webtoon/compose_text.py` | 실제 글자 크기를 측정해 하단 22%에 맞추고, 배치 불가능하면 원문을 자르지 않고 오류를 낸다. |
| `pipelines/webtoon/pipeline.py` | 공유 계약·메타데이터와 자막 넘침 오류 처리를 반영했다. 배치 실행 이미지 배포는 별도다. |
| `admin/backend/deploy-admin-api.sh` | 새 공유 계약 모듈을 Lambda 패키지에 포함한다. |

이미지 공급자의 negative_prompt·seed 필드는 [Bedrock Stable Image Ultra 요청 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-diffusion-stable-ultra-text-image-request-response.html)를 기준으로 했다. 동일 seed는 동일 인물의 얼굴을 보장하는 장치가 아니다.

### 비용 태그

사용자가 권장안으로 변경하도록 승인한 뒤 `webtoon_script_sonnet5`, `image_sd_ultra` 프로파일의 `Service=atlas4`를 `Service=lens`로 변경하고 재조회했다. 다른 태그는 보존했다. 이 두 프로파일의 application inference profile ARN으로만 실제 시험을 수행했다. 전체 프로파일 이관을 수행한 것은 아니다.

### 실제 생성 시험

실제 뉴스로 오인하지 않도록 가상의 해솔시 버스 정책 기사로 시험했다. 4개 외곽 노선 배차 간격 검토, 예산 심의 조건, 예산 미집행, 조건부 시범 운영, 기존 차량 재배치 검토, 조사 지표, 요금 조정 제외, 설명회 일정 미정 등 구별되는 사실을 포함했다.

CMS 스크립트 조립 함수·상수·정규화와 공유 이미지 생성 함수를 사용했다. 텍스트 호출은 선택 모델 Sonnet 5의 비스트리밍 Converse였다. CMS 기본 모델 전체나 로그인한 브라우저의 스트리밍 흐름을 시험한 것은 아니다. 이미지 모델은 Stable Image Ultra다.

1. 초기 텍스트 응답의 떨어진 원문을 `...`로 이어 붙인 인용이 검증에서 실패했다. 연속 직접 인용 규칙과 인과관계·중복 컷 검사를 강화했다.
2. 수정 응답에서 8컷·원문 인용·근거 연결·자막 길이를 통과했다. 짧은 도서관 휴관 기사에서는 `needs_article`, `cuts=[]`가 나왔고 이미지 생성을 보류했다.
3. 한국어 이미지 요청 2개는 필터 거부됐다. 영어로 전환한 뒤 생성은 성공했으나 긴 화풍 설명에서 분할 화면·복제 인물이 나타났다.
4. 장면 우선 문장과 짧은 화풍 우선 문장을 소수 진단 이미지로 비교했다. 이 진단용 프롬프트는 직접 작성한 것이며 텍스트 모델 산출물의 자동 평가 점수로 취급하지 않는다.
5. 최종 지침으로 텍스트 모델을 다시 호출했다. 8컷 전체의 원문 인용·사실 연결·70자 이내 한국어 자막·영어 이미지 프롬프트를 확인했다. 텍스트 사용량은 입력 10,144 / 출력 6,545 토큰이었다.
6. 최종 8컷을 실제 생성하고 한국어 자막을 합성했다. 옵션 전달을 확인하기 위해 시험 seed `20261021`을 공통 적용했다. v49의 기본 seed는 null이다. 8개 모두 생성·합성에 성공했다.

로컬 시험 자료는 Git에서 제외된 `local/persona/webtoon-newsroom/`에 있다. 최종 응답·요청·컷별 원본·합성본은 `runtime-20261021-final/`, 전체 비교 이미지는 `contact-sheet.jpg`다. 실제 응답을 저장했으며 persona-harness의 자동 judge 점수나 통계적 A/B 우월성은 산출하지 않았다.

## 결정

**코드 전달·생성 계약 검증은 통과했지만, 시각적 일관성은 완전 통과로 판정하지 않는다.**

최종 8컷을 직접 확인한 결과:

- 전체 네이비 계열 색조와 설명 자막 형식은 이어졌다.
- 컷 6에 금지한 안경이 나타났고, 컷 2·6·7의 남성 얼굴과 머리 모양에 차이가 있다.
- 같은 장소로 지정한 컷 3·4의 버스 정류장 구조와 벤치가 달라졌다.
- 컷 4의 수채화 같은 표현, 컷 7의 배경 생략 등 화풍·공간 지시 이탈이 있다.
- 화면·버스·달력에 가짜 글자와 숫자가 남았다. 공급자 negative_prompt에 전달해도 완전히 제거되지 않았다.

따라서 v49는 **비활성 검토용**으로 저장했다. 자동 운영은 v46을 유지한다. 프롬프트 변경만으로 운영 적용되는 구조와 별개로, 이번 옵션 누락·자막·검증 수정에는 CMS 코드 배포가 필요했고 완료했다.

## 다음

- 모든 컷의 동일 인물·공간을 엄격하게 유지하려면 고정 캐릭터·장소 참조 이미지를 실제 요청에 넣는 생성 경로가 필요하다. 현재 Ultra 경로는 컷별 텍스트 입력이며 이번에 참조 입력 경로를 추가하지 않았다.
- v49를 운영에 활성화하기 전에 실제 기사와 사용할 텍스트 모델에서 시각 결과를 검수해야 한다. 생성 성공만으로 이미지 품질 통과로 판정하지 않는다.
- 배치 소스는 공유 계약을 반영했지만 ECS 이미지 재빌드·배포는 수행하지 않았다. 자동 발행 경로에 적용할 때 해당 배포가 필요하다.
- 커밋·push·PR·운영 프롬프트 활성화는 수행하지 않았다.
