# 리팩토링 1·2단계: 모델 ARN과 운영 리소스 값의 정본 단일화 (2026-10-12)

작성: 문영광 + Claude Code
관련: PR #77(모델 레지스트리), #79(리소스 정본), #89(남은 스크립트), 기준 문서 `docs/architecture/개발원칙.md`

## 문제 발견
- Bedrock 프로파일 ARN이 파이프라인 .py 15곳, 정책 JSON 약 34곳에 복사돼 있었다. 모델 교체(10/11 Sonnet 5 전환)마다 약 10개 파일을 건드렸고, 10/12 권한 누락 사고의 직접 원인이 됐다([제목생성-권한누락-폴백](2026-10-12-제목생성-권한누락-폴백.md)).
- 계정 ID, CloudFront ID, 버킷, 인스턴스 ID가 배포 스크립트마다 리터럴로 복사돼 있었다(8/6 dev·dev2 덮어쓰기 사고와 같은 유형의 위험).

## 문제 정의
- 값이 두 곳 이상이면 어긋나고, 어긋남은 오류 없이 폴백으로 가려진다. 정본 한 곳과 어긋남을 잡는 검사가 필요했다.

## 판정
- 1·2단계 목적 달성(정합 검사 가동). 단 `task-policy.json`을 운영 기준으로 덮으면서 옛 항목(GPU 락 테이블, ipadapter S3, 배경 제거용 Stability 프로파일)이 빠졌다. 운영 역할에 원래 없던 권한이라 동작 영향은 없다고 추정하나, 해당 기능 코드가 남아 있는지는 미확인.
- admin `routes/prompts.py`의 ARN은 별도 배포 단위(Lambda zip)라 레지스트리를 import하지 못하고 테스트로만 묶었다.
