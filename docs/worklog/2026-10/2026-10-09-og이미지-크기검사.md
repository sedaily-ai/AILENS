# 2026-10-09 og:image 크기 검사 — 폭 1200px 미만 대표 이미지 제거

작성: 문영광 + Claude Code
관련: 브랜치 `perf/og-image-size-guard`(커밋 `c9a20eb`), 이전 기록 `2026-10-04-검색노출-SEO점검과-개선.md` §2·§6
데이터: `2026-10-09-og이미지-크기검사_data/`(전수 측정 CSV 2개 + 측정 스크립트)

## 1. 문제 발견

- Search Console(3개월): 클릭 237 · 노출 6.96천 · CTR 3.4% · 평균 순위 6.6
- 하루 14~18건 발행 대비 노출이 적고, 10/3 전후 노출만 급등(약 1.5천) — 클릭은 같은 속도로 늘지 않음
- 기사 1건 HTML 점검 중 og:image가 386×93(13KB)으로 나가는 것을 발견

## 2. 문제 정의

- 대표 이미지(og:image·JSON-LD image)가 Discover·뉴스 카드 권장 조건(폭 1200px 이상)을 못 채우는 기사가 있음
- 전수 측정(기사 URL 2,560건 중 2,556건 측정, 2026-10-09 실측)

| 폭 | 건수 | 비율 |
|---|---|---|
| 1200px 이상 | 1,530 | 59.9% |
| 800~1199 | 433 | 16.9% |
| 600~799 | 378 | 14.8% |
| 600 미만 | 215 | 8.4% |

- 카테고리별 1200px 미만: 증시 56% · 뉴스 40% · 산업 36% · 금융 34% · 국제 25% · 문화 15% · 부동산 13%
- 월별: 8월 49% · 9월 38% · 10월 34%

## 3. Why — 원인

- 본지 피드의 `<image href>`(`pipelines/discovery/pipeline.py:115`)를 크기 확인 없이 `photo_image_url`로 저장
- 프론트 `pickShareImages`(`app/(economy)/_shared/lensArticlePageShared.tsx`)가 사진이 있으면 무조건 1순위로 사용 → 배너·도표형 대표 사진이 그대로 노출
- 기본 커버(`public/lens/default-cover.webp`)는 실제 960×960인데 1200×800으로 선언 중이었음
- 앞서 짚었던 `letters/[id]/page.tsx`는 라이브 기사 경로가 아님(정정). 라이브는 `(economy)/{카테고리}/…/[slug]` → `buildLensArticleMetadata`

## 4. How — 변경

- 후보(본지 사진 → 웹툰 컷)의 앞 256KB만 읽어 크기를 재고, 폭 1200px 이상·가로세로비 3 이하인 첫 이미지를 선택(`shareImage.ts`, JPEG·PNG·WebP 판독)
- 모두 미달이면 `/og-image.png`(1200×630), 측정 실패면 기존 동작(첫 후보)
- og:image:width/height·JSON-LD image에는 잰 값만 기재
- 순수 함수 테스트 12건 추가

검토 후 버린 안: CMS 글에 `og_image_url` 필드 추가
- 프론트·백엔드 조회 2곳·저장 층·파이프라인·기존 2,560건 보정 스크립트까지 5개 층을 건드리고 백엔드 배포 순서가 필요
- 렌더 시 측정은 프론트 한 파일로 끝나고 기존 기사에 배포 즉시 적용 → 먼저 이 안으로 감
- 필요해지면 필드 방식으로 확장(렌더 시 추가 요청 제거 목적)

## 6. 가설(반증 가능)

- H1 규칙 동작: 배포 후 같은 2,560건 재측정에서 og:image 폭 1200px 미만 비율 40% → 3% 이하(측정 실패 폴백 분만 허용). 3% 초과면 규칙 결함
- H2 노출: 배포 후 4주(~2026-11-06) 일평균 노출이 직전 4주보다 늘고 CTR 3.4% 이상 유지. 단 10/1 개편·본지 링크 등 교란 요인이 커서 이 변경만의 효과로 판정하지 않음, 방향성 참고용
- H3 지연: 캐시 미스 상세 페이지 TTFB 증가가 p95 +500ms 이내. 초과하면 필드 방식(`og_image_url`)으로 전환
- 역효과 위험
  - 폴백 약 373건이 같은 이미지 → 공유 미리보기 차별성 저하(제목 얹은 카드 자동 생성이 후속 후보)
  - 웹툰 컷은 가로세로비 0.93~1.5라 정사각형에 가까워 1.91:1 카드에서 위아래가 잘릴 수 있음
  - 개발 이름 버킷 URL 의존이 늘어남(CloudFront 도메인 이전 시 치환 대상 증가)

| 시각(KST) | 오류 | 원인 | 조치 |

- 방문자 영향 범위는 ALB 지표로 분리하지 못함(평소 트래픽이 5분에 수십~백여 건, 같은 시간대에 내 요청이 섞임)
- 잔여 위험: 색인 대기 4,712건을 Google이 크롤링하기 시작하면 캐시 없는 기사가 한꺼번에 렌더되어 같은 OOM이 날 수 있음(이번 변경과 별개로 존재하던 구조일 가능성)
