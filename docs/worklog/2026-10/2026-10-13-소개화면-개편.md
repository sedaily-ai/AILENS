# 2026-10-13 소개 화면 개편과 구독·이메일 정합성 개선

작성: Peter
관련: 브랜치 `feat/onboarding-redesign`, 화면 `/onboarding`

## 배경

기존 소개 화면은 메일 구독만 설명하고, 확인되지 않은 매일 아침 발송을 약속했다. 같은 기사를 읽기·웹툰·팟캐스트·영상으로 보는 방식과 주요 기능을 소개하는 화면으로 개편했다. 이후 구독 흐름을 확인하면서 기존 main에도 있던 발송 상태·기사 링크·날짜 문제를 발견해 관련 백엔드 보정과 이메일 디자인까지 범위를 확장했다.

## 한 것

- 공용 헤더 → 히어로 → 발행 기사 4형식 비교 → 기능 목록 → 제작 방식 → 메일 신청 순서로 구성했다. 예전 소개 섹션과 미사용 `ScrollReveal`을 제거했다.
- 비교 카드와 오늘 1면 선택 로직을 `shared/lib/content`로 옮겨 소개 화면·기존 카드·`/start`에서 재사용한다. 기존 선택 동작은 유지했다.
- 사이트에서 쓰던 색상·글자 크기에 CSS 토큰을 추가했다. 1024px 이상에서는 본문 최대 폭을 760px로 넓히고, 구독 입력창과 버튼의 양쪽 끝을 본문에 맞췄다. 모바일·태블릿은 기존 폭을 유지했다.
- `#newsletter` 이동 시 고정 헤더에 가리지 않도록 여백을 주고, 제목 줄바꿈을 정리했다. 개인정보 링크 이름을 ‘개인정보처리방침 보기’로 명확히 했다.
- 이메일 형식·수신 동의·기사 로딩 상태에 따라 신청 버튼을 활성화하고, 필요한 행동부터 안내한다. 브라우저 저장소 접근 실패가 구독 저장 성공을 실패로 바꾸지 않도록 처리했다.
- `NewsletterCTA`에서 실제 기사 요약·정본 경로·발행일을 전달하고, 메일로 받을 기사의 제목과 날짜를 화면에 표시한다. 비교 카드와 메일 기사가 다를 수 있음을 안내한다.
- 구독 저장과 메일 발송 결과를 구분한다. `sent`만 발송 성공으로 처리하며 `dry_run`·`error`·`no_letter`는 해당 상태를 알린다. 예시 레터(mock)는 실제 구독자에게 보내지 않도록 차단했다.
- 메일 링크는 정본 기사 경로를 우선하고 기존 레터 ID 링크도 유지한다. ID가 없을 때 날짜로 잘못된 상세 링크를 만들지 않는다. 날짜는 전달된 발행일을 우선하고 없으면 한국 시간을 쓴다.
- 기존 발송 역할의 `ses:SendEmail` 권한을 쓰도록 SESv2 요청을 Raw에서 Simple로 변경했다. AWS 리소스·IAM 정책·구독 DB 구조는 바꾸지 않았다.
- 이메일을 흰 배경·명조 제목·파란 버튼·담백한 해요체로 개편했다. 이메일용 표 레이아웃과 인라인 스타일, 본문 수신거부 링크와 `List-Unsubscribe` 헤더를 사용한다. POST 처리가 없는 원클릭 해지 헤더는 보내지 않는다.
- 기존 전체 메뉴의 ‘서비스 소개’ 링크를 `/about`에서 `/onboarding`으로 바로잡았다. 새 헤더 탭은 추가하지 않았다.

## 결정

- 발송 시각이나 정기 발송을 약속하지 않고 ‘최근 발행 기사 요약과 전체 기사 링크’로 설명한다.
- 실제 발송할 요약을 불러오지 못하면 구독 신청을 막는다. 화면을 활성화하려고 예시 콘텐츠로 대체하지 않는다.
- 이메일 공통 렌더러와 발송 모듈을 쓰는 기존 구독 경로에도 보정이 적용된다. 별도 `/letter` 서비스, `/start`의 선택 흐름, 발행 파이프라인은 개편 대상이 아니다.
- 배포는 승인 뒤 진행한다. 프론트와 백엔드를 따로 배포할 경우 새 응답 상태와 기사 링크가 일치하도록 백엔드 반영을 먼저 확인한다.
- 상세 검증 로그·스크린샷·개인 테스트 주소는 worklog와 저장소에 넣지 않는다. 실행 결과와 미확인 범위는 PR 본문에 기재한다.

## 다음

- 화면·메일 디자인과 관련 백엔드 보정 범위를 검토하고 승인 후 배포한다.
- 배포 후 실제 신청으로 구독 저장, SES 발송, 받은편지함 도착, 기사 링크와 해지를 확인한다. 수정 코드의 운영 실수신은 아직 확인하지 않았다.
- 홈의 새 소개 탭 또는 추가 진입 동선은 개편 승인 뒤 별도 작업으로 정한다.
