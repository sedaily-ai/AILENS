1. **대상 5건의 편집 구간 확보:** 관리자 저장·재생성/일괄 작업 등 해당 기사에 쓰는 경로를 확인한다. 기존에 열려 있던 편집 화면과 처리 중 요청까지 정리하고, 완료 후 새로 읽어 편집을 재개하는 절차를 정한다. 이는 이번에 편집을 중단하거나 연락을 보냈다는 뜻이 아니다.
2. **실행 자료 고정:** 최종 코드 SHA·정정 JSON SHA·DB/역할/버전·대상 publication ID·원본/투영 해시·원래 updated_at을 작업 식별자에 연결한다. 최신 before를 다시 확인하며 하나라도 다르면 중단한다. 예전 해시로 값을 강제 덮어쓰지 않는다.
3. **지속되는 백업:** 디스크의 작업별 디렉터리 0700·파일 0600·배타 생성을 사용한다. 위 전체 관련 145행에 대응하는 원본/자식 ID·순서·타입·URL·내용·관련 제약 정보를 저장하고 작업·계획·도구 SHA 및 생성 시각을 manifest에 기록하는 안을 권한다. 행 수는 미래에도 145로 고정하지 않고 실행 당시 값을 사용한다. 계정 테이블은 포함하지 않는다.
4. **내구성과 복원 가능성 확인:** JSON 역직렬화·필수 키/타입·대상 ID·개수·내용 해시를 검사한다. DB 변경 전에 파일/디렉터리 동기화를 포함한 내구성 경로를 구현·시험하고, 승인된 비공개 보관처의 독립 사본을 확인한다. 같은 서버 디스크 한 사본을 전체 재해 복구라고 부르지 않는다. 이번에는 백업/독립 사본을 생성하지 않았다.

### 6. 복구 절차 — 아직 구현·실행하지 않은 계획

**커밋 전 실패:** 연결·권한·before·투영·잠금/직렬화·백업·SQL 중 하나라도 실패하면 현재 트랜잭션 전체 rollback을 확인한다. 백업 파일이 생겼어도 적용 성공 증거로 쓰지 않는다. 불완전/실패 백업은 덮어쓰지 말고 실패 상태로 분리해 보관한다. 새 시도는 전체 사전 검사와 새 작업/백업 이름으로 시작한다. 시퀀스 번호 간격은 되돌리지 않는다.

**커밋 결과 불명:** 연결이 끊겼거나 성공 출력만 유실되면 즉시 재적용/역정정하지 않는다. 새 read-only 연결로 13개 원본·6개 투영·실제 행 ID를 비교해 전체 before / 전체 after / 그 밖의 상태로 분류한다. before면 미반영 검토, after면 이미 반영된 실행의 검증으로 이어가며 혼합 상태는 외부 편집 가능성을 포함해 중단·조사한다. 백업 파일 존재만으로 커밋 여부를 결정하지 않는다.

**커밋 후 조건부 역정정:**

1. 편집 구간을 다시 확보하고 백업·영수증 SHA와 대상 DB/ID를 검증한다. 신규 문단 ID 영수증이 없거나 대상 ID가 달라졌으면 자동 삭제하지 않는다.
2. 단일 트랜잭션에서 정방향과 같은 순서로 publications→대상 renditions→기존 자식 행을 잠근다. 현재 내용·updated_at·ID·순서·미디어 URL이 적용 직후 영수증과 같은지 검사한다. 후속 편집이 있으면 과거 백업으로 덮어쓰지 않고 복구 계획을 다시 검토한다.
3. 승인된 13개 필드만 역변환한다. publications를 삭제하거나 admin_extra 전체를 무조건 과거 값으로 덮어쓰지 않는다. 기존 문단 53개는 **원래 ID에 내용만** 복원하고 대본·캡션도 원래 ID를 사용한다.
4. 산업 기사 `rendition_id=18044`에 추가된 7행은 **영수증으로 특정한 ID+소속+위치+내용이 모두 일치할 때만** 삭제한다. `position>=8` 같은 넓은 조건이나 렌디션 삭제/재생성은 쓰지 않는다. 보존할 기존 문단 ID는 32479–32486이다. 이 ID들은 이번 스냅샷 기준이므로 실제 실행 영수증이 우선한다.
5. before 13/13·투영 6/6과 전체 관련 범위의 비대상 필드/ID/URL 보존을 검사한 후 한 번만 commit한다. 하나라도 다르면 전체 rollback한다. 복구 행의 updated_at은 새 복구 시각으로 기록하는 안을 권하며 원래 시각은 감사 자료로 보관한다. 논리 내용 복원과 과거 시각까지의 바이트 완전 동일을 혼동하지 않는다.
6. 새 read-only 조회와 공개 목록·상세·단어장·투표·미디어 텍스트, 캐시 갱신/만료 후 화면을 확인한다. body hash가 다시 바뀌는 열린 읽기 세션의 재진입과 기존 완료 기록 보존도 검증한다. 캐시 무효화·실계정 쓰기 등 실제 조작은 별도 승인 범위다.

복구 도구는 DB/ID/계획/영수증 검증, 기본 read-only 미리보기, 명시적 복구 실행, 전체 트랜잭션·원본 ID 보존을 갖춘 작은 전용 도구로 준비하는 안이 적절하다. 지금 정정 JSON의 before/after를 뒤집어 기존 적용 CLI에 넣으면 문단 감소 금지에 걸리고 신규 행 제거도 지원되지 않으므로 복구 수단으로 제시하지 않는다.

### 7. 동시 편집 위험의 코드 근거

현재 정정 도구는 적용 때 `REPEATABLE READ` 안에서 부모/자식에 `FOR UPDATE`를 요청하고 모든 before를 다시 비교한다. 하지만 이 보호는 **정정 트랜잭션 이후의 오래된 관리자 저장**까지 거절하는 버전 검사가 아니다.

운영 `admin_posts_repo.py`, `routes_admin_posts.py`, `db.py`의 파일 SHA는 현재 로컬과 모두 같았다. 실제 관리자 경로의 [초기 SELECT](../../../service/lens-cms-api/admin_posts_repo.py#L469)와 [최종 UPDATE](../../../service/lens-cms-api/admin_posts_repo.py#L532)는 예상 updated_at/버전을 비교하지 않는다. [한 포맷 저장](../../../service/lens-cms-api/admin_posts_repo.py#L363)도 처음 읽은 admin_extra를 구성한 뒤 `WHERE id`로 기록한다. 일반 본문 저장은 렌디션을 삭제·재생성할 수 있다. 프론트→admin Lambda→CMS 전달 경로에서도 예상 버전/If-Match를 전달·검증하는 처리를 확인하지 못했다.

추가 read-only SELECT에서 해당 접속의 기본/실제 격리 수준이 모두 **READ COMMITTED**, read_only가 on임을 확인했다. 시각 **21:32:44.969764 KST**, SSM `1ff5f279-ad20-44b2-951b-8879260cecd3`, Success / 0이다. 관리자 `db.py` 풀은 자체 격리 수준을 지정하지 않는다. 실제 실행 중인 풀의 모든 세션 설정을 조사한 것은 아니므로 세션별 커스텀 설정까지 동일하다고 확대하지 않는다.

구체적인 위험 순서는 다음과 같다. READ COMMITTED의 관리자 요청 B가 옛 admin_extra를 먼저 읽고, 정정 A가 JSON·투영을 갱신한 다음 commit한다. B가 뒤늦게 옛 JSON 기반 UPDATE를 실행하면 A의 정정이 덮일 수 있다. 포맷별 저장이라면 다른 포맷의 JSON까지 옛 값으로 돌아가면서 해당 투영과 불일치할 여지도 있다. 이 경합은 운영에서 재현하지 않았다. 아래 C06/C07에서 실제 두 세션으로 반증해야 한다.

최소 운영 방안은 **5건에 한정한 모든 writer의 짧은 편집 중지·진행 요청 정리·적용 후 새로고침**이다. 지속적인 근본 대응은 관리자 저장에 예상 버전과 DB의 조건부 UPDATE를 연결해 충돌을 명시적으로 거절하는 별도 변경이다. 이번에는 어느 방안도 적용하지 않았다.

### 8. 동시 편집·장애·복원 시험 계획

전용 **로컬 PostgreSQL 16 계열**과 합성 5건으로 수행한다. 운영 SELECT에서 확인한 unique/FK/CASCADE·컬럼 타입·기본 격리를 재현하고 실제 DB 두 세션 A/B를 사용한다. 기존 검증의 PostgreSQL 17.11 결과를 이 경합/복원 시험의 통과로 대체하지 않는다. sleep 의존 대신 barrier로 ‘읽음/잠금 획득/commit’을 조절하고 서로 다른 backup 경로를 사용한다. 정정 코드는 실제 도구를, 편집 경로는 실제 관리자 repo의 트랜잭션을 연결한다.

| ID | A/B 또는 오류 주입 | 통과·판정 기준 |
|---|---|---|
| C01 | B가 대상 필드 편집 후 commit → A 시작 | A가 before 불일치로 중단. B 변경 유지, A 백업/부분 수정 없음 |
| C02 | 원본 JSON은 그대로 두고 B가 문단·대본·캡션만 변경 | 기본 검사·적용 직전 검사 모두 투영 불일치 거절 |
| C03 | B가 비대상 필드만 먼저 바꾼 뒤 A 시작 | 대상 before가 같으면 최신 비대상 필드 보존. 옛 사전 검사 스냅샷으로 덮어쓰지 않음 |
| C04 | B가 같은 부모/자식 잠금을 5초 이상 보유 | A lock_timeout 경로와 전체 rollback 확인. 진행 중 다른 기사 영향은 제한적이어야 함 |
| C05 | A의 RR snapshot 뒤 B가 같은 행 변경·commit → A 잠금 | 직렬화 실패(40001) 등으로 중단, 5건 부분 수정 없음. 새 승인 기준 없이 자동 반복하지 않음 |
| C06 | A가 잠근 동안 B가 옛 JSON을 읽고 저장 대기, A commit 후 B 저장 | **현 코드의 덮어쓰기 위험을 반증하는 시험.** 잠금 대기 성공만으로 통과 처리하지 않음. 편집 중지/버전 검사 방안 적용 뒤 같은 순서에서 오래된 쓰기가 수행되지 않는지 별도 확인 |
| C07 | A가 최종 commit한 뒤 오래 열린 편집 화면의 payload 저장 | 정정이 되돌아갈 수 있는 현 경로 기록. 재개 시 강제 새로 읽기 또는 예상 버전 거절이 작동해야 실행 준비 통과 |
| C08 | A 잠금 중 B가 대상 child 삽입/삭제·렌디션 재생성 | FK·부모/자식 잠금·CASCADE의 실제 대기/오류를 관측. 원본-투영 불일치·ID 유실을 허용하지 않음 |
| C09 | 같은 정정 두 개 동시 실행·역순 잠금 교차 | 한 실행만 반영, 다른 실행의 before/직렬화/교착(40P01) 중단과 전체 rollback. 고정 작업 순서·전체 재검사 유지 |
| C10 | 두 번째 정정 필드 이후 오류·세션 종료 | 테이블 전체는 before 유지. sequence 간격은 실패로 간주하지 않고 별도 기록 |
| C11 | 백업 이름 중복·권한 거부·용량 부족·JSON 기록/fsync 오류 | DB 변경 전 중단, 기존 백업 불변, 불완전 파일을 성공 백업으로 표시하지 않음. fsync 주입 시험은 내구성 보완 후 가능 |
| C12 | commit 직후 응답 유실 | 새 읽기 전용 대조로 before/after/혼합 판정. 무조건 재실행·역정정 금지 |
| C13 | 정상 적용 → 영수증 생성 → 복구 → 재조회 | 13필드·6투영 복원, 신규 문단 7개만 제거, 기존 ID/URL/비대상 내용 유지, updated_at 정책 확인. 복구 도구 준비 후 실행 |
| C14 | 정상 적용 후 B 편집·ID 교체 → 복구 시도 | 영수증/updated_at/ID 불일치로 복구 전량 중단. B 변경을 보존 |
| C15 | A 적용/복구 동안 관계없는 다른 기사 B 편집 | 해당 기사의 값·행 수는 시험 기대대로 유지. 불필요한 전체 테이블 잠금/광역 되돌림 없음 |

각 시험은 두 세션의 SQLSTATE·적용 단계·before/after 해시·백업 존재/권한/해시·신규 행 ID를 기록한다. 최종 확인은 세 번째 새 연결에서 수행한다. C06/C07의 현 코드 위험, 미구현 복구·내구성 처리를 숨긴 채 테스트 기대값만 ‘성공’으로 두지 않는다.

PostgreSQL의 RR 갱신 충돌·시퀀스 비트랜잭션 동작과 행 잠금/교착의 판정은 [PostgreSQL 16 격리 문서](https://www.postgresql.org/docs/16/transaction-iso.html#XACT-REPEATABLE-READ), [명시적 잠금 문서](https://www.postgresql.org/docs/16/explicit-locking.html#LOCKING-ROWS)를 기준으로 삼았다. 이번 실측은 읽기 전용이고 위 쓰기 경합 결과는 아직 얻지 않았다.

## 결정

**최신 값 대조는 통과했다.** 대상 5건·13필드·투영 6묶음에 현재 정정안과의 충돌은 없으며 모두 미정정 상태다. 다만 적용 직전 새 스냅샷에서도 다시 확인해야 한다.

**운영 적용 준비 완료 판정은 보류한다.** 남은 준비는 (1) 백업 내구성·적용 후 신규 ID 영수증, (2) 조건부 복구 도구와 PG16 적용→복원 연습, (3) 동시 편집 두 세션 시험 및 5건 writer/오래된 편집 화면 통제다. 최신 before 일치와 과거 20개 정정 테스트 통과만으로 이 항목들을 완료 처리하지 않는다.
