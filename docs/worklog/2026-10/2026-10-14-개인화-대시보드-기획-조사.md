# 2026-10-14 개인화 대시보드 기획 조사

## 배경

사용자가 관심사·소비 패턴 분석, 맞춤 대시보드, 추천, 리워드, 푸시 알림의 기능 기획을 요청했다. 실제 개발 및 구현은 제외한다.

## 한 것

- 루트 CLAUDE.md와 문서 배치 규칙, 4format-persona-system.md를 읽었다. 기존 기획은 레터·웹툰·팟캐스트·영상의 소비 맥락을 구분한다. 현재 구현 및 데이터 수집 상태는 조사하지 않았다.
- Lesser School 공개 소개 페이지에서 맞춤 학습, 개인별 분석·성장 피드백, 복습 기능 안내를 확인했다: https://www.lesser.school/
- DIG 공개 메인에서 오늘의 레터, 뉴스 Pick, 인기 Top 5, 퀴즈·포인트 안내, 활동 배지 UI를 확인했다: https://dig.mk.co.kr/
- 공개 안내 확인에 한정하며 로그인 후 개인화 동작, 추천 알고리즘, 포인트 지급·교환 정책은 검증하지 않았다.
- 추가 조사: 롱블랙의 읽기 스탬프·샷과 제휴 혜택(https://longblack.co/about/selection), Headway의 목표·이용 이력 기반 추천과 짧은 학습(https://makeheadway.com/faq/), Readwise의 하이라이트 Daily Review(https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights), Inoreader의 키워드 모니터링 피드(https://www.inoreader.com/help/pro/monitoring-feeds/how-do-i-create-a-monitoring-feed), Ground News의 읽기 습관 대시보드(https://ground.news/ground-rebrand)를 공식 공개 자료로 확인했다.
- 후속 요청에 따라 [개인화 대시보드 통합 기획안 v0.1](2026-10-14-개인화-대시보드-통합기획-design.md)을 작성했다. 기존 다섯 기능, 대시보드·이용 흐름, 추천·기록·리워드·알림 연결, 예외 정책과 성과 검토를 통합했다. 모든 정책값은 제안이며 구현하지 않았다.
- 후속 로컬 코드 조사에서 로그인 메뉴의 ‘내 서랍’, 문장 조회·삭제와 키워드 기반 추천, 레터의 브라우저 저장·읽음·에디터 팔로우, 상황별 포맷 온보딩을 확인했다. 운영 로그인 화면·실제 API 성공 여부는 검증하지 않았다. 통합안 §15에 근거와 재사용 후보를 기록했다.
- 사용자 요청으로 대화에서 검토하는 ‘나의 LENS’ 와이어프레임을 만들었다. 작업 전용 시각화 경로의 `my-lens-wireframe.html`에 저장했으며 서비스 소스에는 추가하지 않았다. LENS의 흰 바탕·파란 강조색, 내 서랍의 문장 중심 구성을 참고해 추천·후속 소식과 보조 개인 기록 영역을 구성했다. 모바일·첫 방문 상태, 포맷·시간·알림 전환은 시안 내부에서만 동작하며 실제 API·저장·발송은 없다.
- 로컬 미리보기에서 1024·390·320px 브라우저 폭의 가로 넘침 없음, 포맷/시간에 따른 표시 변경, 알림 전환, 첫 방문 시 개인 기록 숨김을 확인했다. 브라우저 오류는 없었다. 개발·배포용 검증을 실행한 것은 아니다.

## 결정

- 확정된 제품 결정은 없다. 뉴스 독자의 탐색 부담 감소와 지속적인 소비를 목표로 하는 기획 초안을 대화로 제안한다.
- 직접 선택한 관심사와 행동 신호를 함께 활용하는 방향을 추천한다. 보상과 알림은 추천의 유용성을 검토한 후 확장하는 후보로 둔다.
- 추가 제안은 관심 주제·이용 목적·가용 시간을 반영한 오늘의 콘텐츠 묶음, 읽기 기록, 저장 내용 재발견이다. 롱블랙·Headway·Readwise를 우선 벤치마크로 제안하며, 효과가 검증되거나 방향이 확정된 것은 아니다.
- 코드·설정·인프라 변경, 서비스 호출, 커밋·배포는 수행하지 않는다.
- 사용자가 ‘내 서랍’을 화면 구성 참고로 지정했으며, 실제 내 서랍은 교체하지 말라고 명시했다. 기존 화면을 유지하고 유사한 콘텐츠 중심 구성의 별도 맞춤 뉴스 화면을 제안한다. 리워드·퀴즈는 보조 기능으로 우선순위를 낮추는 검토 의견을 추가했다.
