# 2026-10-11 운영 매뉴얼·런북 작성과 보안 자체 점검(REQ-011)

작성: 이민서 + Claude Code
관련: `docs/ops/운영-런북.md`(신규), 요구사항정의서 REQ-011, 과업지시서 4.1·4.2

## 배경

- 결과보고서·용역완료보고서를 10/14까지 마감해야 한다. 그런데 과업지시서 산출물 가운데 운영 런북과 보안 점검(REQ-011)이 비어 있었다.
- 10/4 요구사항 부합 점검에서도 REQ-011은 '취약점 점검 미실시'로 남아 있었다.

## 한 것

- **운영 매뉴얼·런북**(`docs/ops/운영-런북.md`)
  - 담은 내용: 배포·롤백·모니터링·사고 대응·비밀정보 관리·정기 점검표.
  - 근거: 저장소의 배포 스크립트·설정 파일·worklog만 썼다. 항목마다 근거 파일 경로를 달았다.
  - 저장소에 절차가 없는 곳은 '저장소에 정해진 절차 없음'으로 적었다. 예: CMS API·Lambda·관리자 화면 롤백, DB 복원, 드리프트 비교 스크립트.
  - 알람 현황은 2026-10-11 AWS 조회 결과다.
    - 이름에 mbti·lens가 든 알람은 8개다.
    - 실제로 동작하는 것은 CMS API 서버 자동 복구 1개뿐이다.
    - 5개는 폐기한 자원을 보고 있고, 그 알림 주제에는 구독자가 없다.
- **보안 자체 점검**(읽기 전용, 설정 변경 없음)
  - 범위: 의존성 취약점(npm audit, pip-audit), 비밀정보 노출(detect-secrets, 전체 커밋 이력 정규식 검사), TLS·HTTP→HTTPS·보안 헤더, 관리자 API 인증, AWS 접근 통제 설정(보안 그룹·DB·S3·CloudFront·API Gateway·Lambda·ECS), 알람.
  - 결과: 고위험 2건, 중위험 7건, 저위험 4건. 공개 저장소 전체 이력에서 실제 키 노출은 0건이다.
  - 세부 내용(취약 지점)은 공개 저장소에 적지 않는다. 담당자에게 따로 공유한다.

## 결정

- 런북은 저장소에 근거가 있는 절차만 적는다. 실행 기록이 없는 절차(ECS 이미지 digest 고정 롤백)는 그 사실을 함께 적는다.
- 보안 점검 상세는 10/4 점검과 같이 내부로만 공유한다. 이 기록에는 범위와 건수만 남긴다.
