# 공유 버튼의 링크 복사 메시지

관련: `fix/share-copy-feedback` → `main`

## 배경

카카오톡·인스타그램 기사 공유 버튼은 직접 공유 대신 기사 URL을 복사한다. 사용자는 체크 표시만으로는 실제 동작을 알기 어려워 “링크 복사” 메시지 표시를 요청했다.

## 한 것

- `service/frontend/src/shared/ui/article/ArticleShareButtons.tsx`에 복사 성공 상태 메시지를 추가했다. 카카오톡·인스타그램·체인 모양 링크 버튼의 복사 성공 시 기존 체크 표시와 함께 화면 하단에 “링크 복사”를 2초간 표시한다.
- 최초 버튼 행 아래 메시지는 모바일 글자 크기 도구 영역과 겹쳐 잘 보이지 않았다. `createPortal`로 본문 스타일과 분리해 화면 하단에 어두운 배경의 알림으로 표시하도록 수정했다. 메시지는 `role="status"`로 전달한다. 다른 공유 버튼의 동작은 그대로다.
- 로컬 브라우저에서 상단 인스타그램·본문 하단 카카오톡 클릭 후 알림 표시 및 시간이 지난 뒤 알림 제거를 확인했다.
- 추가 요청에 따라 체인 모양 링크 복사 버튼에도 같은 알림을 적용하고, 로컬 브라우저에서 클릭 후 표시를 확인했다.
- `npx tsc --noEmit`, 해당 파일 ESLint, `git diff --check` 통과.
- 최초 빌드는 Google Fonts 네트워크 접근 제한으로 실패했다. 네트워크 허용 후 `npm run build` 통과. 기존 Next.js 경고와 2MB 초과 응답 캐시 경고는 남아 있다.

## 결정

- 단일 공유 컴포넌트의 표시 변경이므로 기본 자체 검증을 적용했다. 백엔드·인증·저장 데이터·SNS 공유 URL에는 변경이 없다.
- 최종 코드 SHA-256은 `52102181df07b3daf11de05ac97a7522e12996c282ff698b578933473cc6f06a`다. 마지막 링크 버튼 추가 뒤 실행한 타입 검사·파일 ESLint·빌드와 실제 클릭 결과를 동일한 코드의 근거로 재사용했다.
- 복사 성공 이후에만 알림을 표시하고 기존 2초 상태 초기화로 제거한다. 변경 전 체크 표시만 나오던 동작과 변경 후 실제 알림 표시를 브라우저에서 구별했다. 클립보드 권한 실패 안내는 기존 구현 그대로이며 실패 재현, 전체 브라우저 콘솔 감사, 실제 단말 Safari 검증은 수행하지 않았다.
- 원격 `origin/main`과 로컬 기준은 `eaca2b995f4048a3260b3936ed98e33ba3b170e1`로 일치했다. 공유 버튼 코드와 이 기록만 커밋하며 대시보드 문서와 브라우저 산출물은 제외한다.
