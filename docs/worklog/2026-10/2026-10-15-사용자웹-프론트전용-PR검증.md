# 사용자 웹 프론트 전용 변경 분리와 PR 검증

## 배경

사용자 요청에 따라 프론트 배포만 필요한 기존 변경을 별도 브랜치 `fix/user-web-frontend-audit`로 분리했다. fetch로 확인한 최신 원격 `main`은 `47ae257b280ead3c81ad09cf4e666a0596ac7457`이다. 이 원격 커밋을 기준으로 시작했고, 로컬 구현 기준 `a845952e`에서 허용한 프론트 파일만 가져왔다. 기존 로컬 커밋 전체를 cherry-pick하지 않았다. 관련 파일의 원격 변경과 직접 겹치는 경로는 없었다.

## 한 것

### 반영 범위

- F01~F06, F10~F11, F17~F18, F20~F21의 프론트 수정: 최신 글 표시·빈 분류, 형식별 이동, 미디어 안내·정지, 요약·조사, 레터 개요·타임라인, 개인정보 안내·게임 제목.
- 프론트 린트 오류 20건·경고 4건 수정. CloudFront 파일에는 전역 진입점의 미사용 경고를 제한하는 주석만 있으며 함수 동작 변경·별도 인프라 배포가 필요하지 않다.
- 화면 정리 1~7: 중복 공유·문의·관심사 진입, 설명과 고급 설정 노출, 스탬프 요약, 에디터 선택 표시를 정리하고 기존 기능·저장값을 보존한다.
- E01~E04: URL 필터·페이지 복원, 계정 메뉴 접근성, 스타일 예시 안내, 공유 오류·취소 구분과 이미지 응답 검사.
- N01 중 프론트: 탭별 조회·이벤트 구독 활성화, 저장된 관심 설정을 읽은 뒤 집계, 불필요한 요청 제거, 이전 요청 취소 및 오류 시 대체 조회.
- 제품·테스트 변경 55개 파일은 모두 `service/frontend/` 아래다. 이 보고서 외 기존 별도 작업 기록 4개는 포함하지 않는다.

### N01 기존 API 호환성

수정하지 않은 원격 기준의 `service/backend/services/user/dashboard.py`와 `dashboard_summary.py`를 로컬에서 직접 실행했다. 저장 계층만 합성 데이터로 대체하고 외부 저장 요청은 차단했다. `tab` 없음과 `home/archive/records/settings` 4개 값을 각각 전달했을 때 모두 정상 전체 응답을 반환했다. 생성 시각만 제외한 응답 값은 같았고, 각 호출의 내부 저장소 요청은 기존대로 6회였다. 기존 API는 추가 `tab`을 무시하며 필수 `minutes` 계약은 바뀌지 않는다.

내부 브라우저에서 이 기존 dispatch·집계 코드를 사용하는 합성 API와 새 프론트를 연결해 네 탭의 표시를 확인했다. 이번 PR의 효과는 클라이언트 요청 감소다. 탭별 서버 내부 집계 생략이나 운영 지연·비용 절감까지 완료했다고 주장하지 않는다.

### 실행 검증

- Node `v24.21.0`, npm `11.17.0`에서 공용 domain/api-client/auth 패키지를 현재 원격 소스로 빌드했다. 패키지 소스·매니페스트·lockfile은 변경하지 않았다.
- `npm run lint --workspace service/frontend -- --max-warnings 0`: 오류·경고 0건으로 통과.
- `npm test --workspace service/frontend`: 31개 파일·138개 테스트 통과. F19 테스트는 제외되어 이전 전체 묶음의 139개와 구분한다.
- `npx tsc --noEmit --project service/frontend/tsconfig.json`: 통과.
- `NEXT_PUBLIC_CMS_API_URL=http://127.0.0.1:4359 NEXT_PUBLIC_API_URL=http://127.0.0.1:4359/account NEXT_TELEMETRY_DISABLED=1 npm run build --workspace service/frontend`: 성공, 정적 페이지 62개 생성. 실제 저장소의 제품 소스를 로컬 합성 API로 빌드했다. 첫 시도는 샌드박스의 loopback 연결 제한으로 빈 데이터 fallback을 사용했으므로 인수 근거에서 제외하고, 연결 허용 후 재실행한 결과를 채택했다. 최종 실행에 fetch 실패는 없었다.
- 기존 Next.js tracing/turbopack root 불일치·middleware 폐기 예정 경고는 남아 있다. 이번 PR에서 설정을 변경하지 않았다.
- `git diff --check`: 통과. 55개 프론트 파일이 허용한 원본 구현과 바이트 단위로 같고, 기존 별도 기록 4개의 SHA-256이 보존됐음을 확인했다.

### 내부 브라우저와 독립 리뷰

내부 브라우저 `127.0.0.1:4358`에서 아래를 확인했다. 스크린샷은 촬영·저장하지 않았다. QA 복사본은 실제 제품 소스와 대조했고, 인증 로더·분석 스크립트 제외·동일 출처 API 프록시만 격리된 복사본에서 사용했다. 브라우저의 직접 교차 출처 loopback 요청 제약은 이 QA 프록시로 우회했으며 제품 설정은 변경하지 않았다. 기사 자료는 정정안을 덮어쓰지 않은 기존 공개 스냅샷이고 계정·추가 목록만 합성 데이터다.

| 항목 | 확인 결과 |
|---|---|
| 나의 LENS 네 탭 | 추천·저장 레터·서랍 문장·기록·알림 표시. 저장 레터 1개, 문장 1개, 열람 1편, 스탬프 1일과 기존 London 14:35 설정 유지 |
| 집계 실패·복구 | 합성 API에 503을 주입했을 때 기록 탭이 전체 북마크를 대체 조회해 저장 1편 유지. 실패 해제 후 재시도로 열람·저장 개수 복구 |
| 카테고리 | 국내증시·50개·2페이지를 URL에 기록하고 새로고침 후 hydration이 끝나면 동일 값·2페이지 복원. 뒤로가기에서 직전 URL 유지 |
| 정적 안내 | 스타일 카드가 예시임을 명시하고 내용 보존. 개인정보의 Google 안내·개정일, 문의의 공통 이메일·전화 표시 확인 |
| 기사·공유·미디어 | 원래 기사 상세와 핵심 요약·최신 기사 표시, 링크 복사 후 `복사됨` 피드백, 영상 탭 선택 확인. 기사 화면의 문서 폭과 viewport 모두 614px로 가로 넘침 없음 |

독립 리뷰어는 동일한 최종 프론트 diff·신규 파일·인접 호출자를 읽고 N01의 기존 API 계약, 계정별 화면 재생성, owner·abort 보호, 재진입·오류 복구와 형식·URL 계약을 검토했다. 관련 테스트 5개 파일·17개도 통과했다(전체 138개에 중복 합산하지 않음). 재현 조건이 확정된 신규 결함은 발견되지 않았다. 이는 운영·모든 브라우저에서 무결점이라는 판정이 아니다.

## 결정

- F19 단어장의 프론트 2개 파일, 모든 백엔드·CMS·기사 정정 JSON/도구·DB 변경은 이번 PR에서 제외한다. 실제 저장값·저장 키·형식을 변경하지 않는다.
- 관리 도구 소스와 배포는 이번 범위에 포함하지 않는다. 원격 base와 비교한 제품 변경은 `service/frontend/`에만 한정한다.
- 실제 Cognito/운영 DB, 운영 API의 현재 배포 상태, OS 공유 시트·실제 SNS 게시, 모든 미디어 실재생과 전체 반응형 전수 시험은 이번 실행 범위가 아니다. 기존 로컬 상세 회귀 기록과 이번 분리본 검증을 구분한다.
- ARM64 Docker 이미지·운영 환경값 빌드와 배포 후 확인은 배포 단계에서 수행할 범위다. 이번 로컬 빌드 산출물을 운영에 올리지 않는다.
- 요청된 Git 단계는 이 프론트 변경과 보고서의 커밋·전용 브랜치 일반 push·PR 생성까지다. 병합·리뷰 요청·배포·운영 데이터 수정은 수행하지 않는다.
