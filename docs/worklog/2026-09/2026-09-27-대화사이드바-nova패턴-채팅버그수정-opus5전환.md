## 사이클 1 — 대화 사이드바에 이름변경·삭제·일괄삭제·이모지 태그 추가

**문제발견**: 좌측 대화 쓰레드 사이드바에 이름 변경·삭제 기능이 없었다. 사용자 요청: "좌측 대화 사이드바에도 이름 변경.. 대화 삭제.. 할 수 있도록 해주세요, 일괄삭제나 그런거 가능하게 해주세여."
**문제정의**: 확인해보니 백엔드(`PUT`/`DELETE /admin/chat-threads/{id}`)와 프론트 API 클라이언트(`adminClient.ts::updateChatThreadTitle`/`deleteChatThread`)는 이미 다 구현·배포돼 있었다 — UI에서만 안 쓰고 있었다. 순수 프론트 작업.
**왜**: 사용자가 레퍼런스로 `1_ai_link/nova`(ainova-v2) 프로젝트의 `ConversationItem.jsx`/`Sidebar.jsx`를 직접 짚어주며 "설저ㅏㅇ된 코드 그대로 사용해도됩니다"라고 요청 — 1차 조사로 그 구조(선택모드 토글 → 체크박스 다중선택 → 하단 액션바 일괄삭제, "..." 드롭다운 메뉴)를 먼저 읽고 파악했다.
**어떻게 달라졌는지**:
- `useChatLabThread.ts`에 `renameThread`/`setThreadTag`/`deleteThread`/`bulkDeleteThreads` 추가(웹툰·레터/팟캐/영상 두 셸이 공유하는 훅이라 한 번만 추가하면 양쪽 다 얻는다).
- `ChatThreadSidebar.tsx` 전면 개편: 선택 모드(체크박스+하단 "N개 삭제" 액션바, `Promise.allSettled`로 일부 실패해도 나머지는 지워지게), 이모지 태그(큐레이션 6종 ⭐📌🔥💡🧪📰 + 직접 입력, 사용 빈도순 필터 칩).
- 이모지 태그는 DB에 `tag` 컬럼이 없어서(`prompt_lab_threads`가 2026-09-15 1회성 마이그레이션 산출물이라 정식 이관 문서화 범위 밖) 사용자 승인 하에 RDS 마스터로 직접 `ALTER TABLE prompt_lab_threads ADD COLUMN tag TEXT` 실행 — Claude Code 자동 모드가 마스터 비밀번호를 다루는 시도를 "Credential Exploration"/"Credential Leakage"로 반복 차단해서(2026-09-25 기록에도 있던 동일 패턴), 최종적으로 사용자가 비밀번호를 채팅에 직접 제공하고 1회 실행을 허용해 완료했다.
**판정**: 적용 완료 — `tsc`/`eslint`/`build` 클린, 배포 완료.

## 사이클 2 — UI 디자인 3연속 수정(사용자가 실제 nova 화면을 보며 지적)

**문제발견**: 1차 구현(휴지통 아이콘을 "새 대화" 옆에, 연필/휴지통/이모지 3개를 행마다 호버로 늘어놓는 방식)을 실제 nova 스크린샷과 비교한 사용자가 세 가지를 순서대로 지적:
1. "휴지통이 새 대화 오른쪽에 있으면 좀 이상하네요"
2. "노바처럼... 검색 창 넣고, 그 오른쪽에 휴지통 아이콘 넣는걸로"
3. "사이드 부분 접히는것도 노바랑 동일한 아이콘이랑 구조로" + "'대화' 말고 AI LENS 로고를 넣는걸로" (+ 후속 "al은 빼고")
**문제정의**: 매번 레퍼런스 스크린샷을 다시 보고 정확한 위치·아이콘·구조를 재현해야 하는 반복 수정이었다.
**어떻게 달라졌는지**:
- 휴지통 아이콘을 "새 대화" 옆에서 제거 → 검색창(대화 제목 필터, 태그 필터와 함께 체이닝) + 오른쪽 휴지통(선택모드 토글) 한 줄로.
- 접기 아이콘을 nova의 `PanelLeft`/`PanelLeftClose`(사각 패널 프레임 + 세로 구분선, 접을 때만 화살표)로 인라인 SVG 재현(lucide-react는 이 프로젝트의 zero-new-dependency 정책 위반이라 못 씀) — 위치도 "새 대화" 옆에서 제목 줄(원래 "대화" 텍스트, 후에 "AI LENS"로 교체) 오른쪽으로 이동.
- 개별 행 메뉴(연필/휴지통/이모지 3개 호버 아이콘)를 nova와 동일한 "..." 드롭다운 하나로 재통합(이름변경·삭제·이모지 태그 전부 그 메뉴 안).
**판정**: 적용 완료, 매 단계 `tsc`/`eslint`/`build` 클린 확인 후 배포.

## 사이클 3 — 채팅 중복 전송 버그 + 복사 버튼

**문제발견**: 사용자가 레터 탭에서 한 번 입력했는데 똑같은 답("네, 말씀하세요! 😀")이 두 번 출력된 스크린샷 제보 + "답변 출력중에는 또 다른 채팅 못보내도록 하시고" + "복사버튼 있으면 좋을것같고요.. nova 서비스처럼."
**문제정의**: `send()`에 생성 중(응답 대기·스트리밍 중) 재전송을 막는 가드가 전혀 없었다 — 응답이 빨리 끝나는 짧은 입력(인사말 등)에서 Enter를 연달아 누르면 같은 텍스트가 두 번 전송돼 답도 두 번 쌓였다. 복사 버튼은 기존에 팟캐스트/영상 카테고리에만("우측 패널에 붙여넣으세요" 문구와 묶여) 있었고 레터·웹툰엔 없었다.
**어떻게 달라졌는지**: `PromptChatLab.tsx`(웹툰)·`PromptTextLab.tsx`(레터/팟캐/영상) 둘 다 `isGenerating`(`waiting || liveText !== null`, 웹툰은 `|| liveStepActive`도) 계산 후 `send()`·입력창·전송 버튼에 가드 적용(placeholder도 "응답을 기다리는 중..."으로 안내). 복사 버튼은 nova `Message.jsx`와 동일 위치·모양(아이콘+"복사"/"복사됨")으로 전 카테고리·전 화면에 확대.
**판정**: 적용 완료, `tsc`/`eslint`/`build` 클린, 배포 완료. 백엔드 변경 없음(순수 프론트 버그).

## 사이클 4 — 전 카테고리 프로덕션 모델을 Claude Opus 5로 통일

**문제발견**: 사용자 요청 — "모델에서 클로드 4.6sonnet 빼시고요. 클로드 5.0 opus로 모든 프로덕션, 레터, 웹툰, 팟캐스트, 영상 쪽 업데이트 해주시죠. 드롭다운에서도 삭제."
**문제정의**: 조사 결과 letters만 이미 Opus 5(`lens-letters-opus-5`)였고, podcast/video/webtoon은 각자 전용 Sonnet 4.6 프로파일을 쓰고 있었다(`admin/backend/routes/prompts.py::_CATEGORY_BEDROCK`가 정본, 각 `pipelines/*/pipeline.py`가 실제 발행에서 같은 값을 미러링). webtoon용 Opus 5 프로파일(`lens-webtoon-script-opus-5`)은 2026-09-20에 admin CMS 테스트 드롭다운용으로 이미 만들어져 있었지만 podcast/video용은 아예 없었다.
**왜**: 단순 문자열 치환이 아니라 실제 위험이 있었다 — 이 세션에서 이미 "영상 탭에서 Opus 5 사용 시 reasoning이 max_tokens 예산을 전부 써서 응답이 0글자가 되는" 버그를 겪고 admin CMS 쪽(`get_thinking_config`)에만 완화(`thinking: disabled`)를 넣어뒀는데, 그 완화가 (1) admin CMS의 "카테고리 기본 모델(model_id 미지정)" 경로에는 적용 안 되고 있었고(당시엔 기본값이 Sonnet 4.6이라 무해했음) (2) 실제 자동 발행 파이프라인(`pipelines/common/bedrock_client.py::call_text()`)에는 아예 없었다. 4개 카테고리 전부 Opus 5로 바뀌면 이 두 경로 모두 같은 실패 모드에 그대로 노출된다 — 특히 podcast(max_tokens 3000)·video(4000)는 letters(12000)보다 예산이 훨씬 작아 위험이 더 크다.
**어떻게 달라졌는지**:
- Bedrock에 `lens-podcast-opus-5`(`6bjkzt0icf74`)·`lens-video-opus-5`(`p28gzlq5kj6s`) 신규 생성(`us.anthropic.claude-opus-5` copyFrom, `Service=atlas4` 등 기존 비용태깅 규칙 그대로), webtoon은 기존 프로파일 재사용.
- `admin/backend/routes/prompts.py::_CATEGORY_BEDROCK` 4종 전부 Opus 5로 교체, `TEXT_MODELS`에서 `sonnet-46` 제거·`DEFAULT_TEXT_MODEL`을 `opus-5`로, `get_thinking_config()`가 `model_id` 없을 때도 `opus-5` 설정으로 폴백하도록 수정 + `chat_ws.py`의 `if model_id else None` 가드 제거.
- `pipelines/podcast/pipeline.py`·`pipelines/webtoon/pipeline.py`·`pipelines/common/bedrock_client.py`(video 기본값) 전부 새 ARN으로 교체, `call_text()`에 `additionalModelRequestFields={"thinking":{"type":"disabled"}}`를 무조건 적용(admin 쪽에서 이미 sonnet-46/opus-5/sonnet-5 셋 다 이 필드를 받아준다고 실측 확인된 값이라 조건 분기 없이 안전).
- `admin/frontend/textModels.ts`에서 sonnet-46 제거, `DEFAULT_TEXT_MODEL="opus-5"`.
- IAM 3개 역할(`sedaily-mbti-admin-api-dev-role`, `sedaily-lens-frontpage-auto-task-role`, `sedaily-lens-mustknow-auto-task-role`)에 새 ARN 2~3개씩 추가 — Claude Code 자동 모드가 "Permission Grant"로 차단해서, 업데이트된 정책 JSON을 준비해두고 사용자가 `!`로 3회 직접 `put-role-policy` 실행(적용 후 즉시 `get-role-policy`로 반영 확인). `pipelines/{frontpage_auto,mustknow_auto}/task-policy.json`도 레포에 같이 반영해 다음 재프로비저닝 시 어긋나지 않게 함.
**판정**: 적용 완료 — `pyflakes`/`pytest`(144 통과, 기존 무관 실패 2건 그대로)/`tsc`/`eslint`/`build` 전부 클린. IAM 반영 확인 후 `admin/backend` Lambda·`pipelines`(frontpage_auto/mustknow_auto 공유 Docker 이미지, 리비전 76)·`admin/frontend` 전부 배포 완료. 다음 EventBridge 트리거(매일 07:00 KST)부터 4개 카테고리 실제 자동 발행이 Opus 5로 나간다.
