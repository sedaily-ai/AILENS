## Before / After (구체적 예시)

**Before** — 영상 첫 화면(OpeningCut)엔 아이콘 + 제목만 있고 이 정보가
언제 기준인지 표시할 방법이 스키마에 아예 없었다. 시청자가 나중에
다시 보면 "이게 최근 얘기인가?" 판단할 수 없음.

**After** — 스키마에 `asOfDate` 추가, 모델이 0단계 공용 팩트시트의
[기준일]을 그대로 채워 첫 컷에 한 줄로 노출:
```json
{ "title": "...", "brand": "...", "asOfDate": "2027년도 예산안 기준", "cuts": [...] }
```
화면에는 제목 아래 작게 "2027년도 예산안 기준" 표시(muted 톤, BrandTag와
같은 절제된 스타일 — 화면을 잠식하지 않으면서도 한 번은 명확히 보임).

**인포그래픽 비중** — Before는 정해진 비율 규칙이 없어 opening/highlight/
closing(텍스트 위주 컷)만 연달아 나올 수 있었다. After는 프롬프트에
"stat·diagram·chart 합이 전체 컷의 최소 절반 이상" 규칙을 명시 — 예를
들어 9컷짜리 영상이면 최소 4~5컷은 숫자·도식·차트로 시각화되게 강제.

### Remotion 버전 고정 (`Remotion-인수인계-가이드.pdf` 참고)

사용자가 공유한 Remotion 인수인계 가이드 PDF를 근거로 코드를 점검함.
5장 "절대 하면 안 되는 것"(CSS transition/animation, Math.random(),
setTimeout, 원시 `<img>/<video>` 태그, 절대 경로 등) 위반은 전부 없었음
— 클린. 그런데 11장 "버전 관리 정책"에서 실제 위반을 발견:

**Before**: `package.json`의 `remotion`·`@remotion/*` 패키지 전부
`^4.0.513`처럼 캐럿이 붙어있었고, Dockerfile은 `npm install`을 씀.
가이드가 정확히 경고하는 조합 — "Remotion은 거의 매일 릴리스되므로,
캐럿+`npm install`이면 다음 이미지 재빌드 때 패키지 간 버전이 갈라져
설치될 위험." 지금 당장은 lockfile상 전부 4.0.513으로 일치해서
안전했지만, 다음 재빌드부터 위험해지는 잠복 문제였음.

**After**: `package.json`에서 캐럿 제거(`--save-exact`로 고정), lockfile
재동기화. Dockerfile은 `npm install` → `npm ci`로 전환(lockfile을 절대
기준으로 강제, 어긋나면 설치 자체가 실패해 조용한 버전 이탈을 막음).
실제로 이 Dockerfile 변경으로 이미지가 정상 빌드되는 것까지 확인(리비전
25 배포 성공).

### 영상 톤앤매너 개편 — 3단계로 진화

사용자가 "품질적으로 좀 더 트렌디하고 깔끔하게" 요청 → 시도해보고
방향을 계속 좁혀나감:

1. **1차: 다크 네이비 배경에 미묘한 그라디언트만 추가** — 완전 단색이던
   배경(`#0F1A2E`)에 방사형 글로우+비네트 추가. 색상 자체는 안 바꿈.
2. **2차: "화이트 배경 에듀테크 스타일"로 요청 변경** — 전체 팔레트를
   화이트 캔버스 기준으로 재설계. 브랜드 앰버(`#FFB020`)는 유지하되
   배경 화이트, 아이콘·카드 배경은 앰버 파스텔 칩, 텍스트는 순검정
   대신 데운 잉크 톤(`#1C1B17`)으로. 이 과정에서 하드코딩 버그 하나
   발견·수정: `CaptionBar.tsx`가 "어두운 배경 + `COLORS.text`(흰 글자)"
   조합을 하드코딩하고 있어서, 배경이 화이트가 되면 어두운 칩 위에
   어두운 글자가 겹쳐 안 보이게 될 뻔했다 — 칩 자체를 배경 테마와
   무관한 고정 다크 잉크색으로 분리.
3. **3차: "유튜브 지식 채널 애프터이펙트 느낌"으로 요청 변경** — 실제
   mp4로 렌더링해서 확인해보니, **숫자 카운트업(`useCountUp`)과 차트
   라인 드로잉(`CHART_LINE_DRAW_SECONDS`)이 이미 코드에 구현·정상
   작동 중**이었다(정지 이미지만 봐서 이번 세션 내내 몰랐던 것). 여기에
   3가지를 추가:
   - `GrainOverlay.tsx` 신설 — SVG `feTurbulence` 기반 정적 필름 그레인.
     `Math.random()`이 아니라 결정론적 노이즈라 Remotion의 "순수 함수"
     규칙(가이드 5장)을 그대로 지킨다.
   - `BackgroundAtmosphere.tsx` 신설 — 배경 그라디언트 중심점을 영상
     전체 길이에 걸쳐 아주 느리게 이동시키는 패럴랙스. `interpolate()`
     기반(CSS animation 금지 규칙 준수).
   - `animation.ts`의 spring 감쇠비 재조정 — 기존
     `damping:200/stiffness:260/mass:0.9` 조합의 감쇠비(ζ)가 약 6.5로
     심하게 과감쇠 상태라, 스프링을 쓰고 있었는데도 오버슈트가 전혀
     없었다(사실상 ease-out과 구분 안 됨). 텍스트 슬라이드(ζ≈0.75, 절제된
     탄력)와 아이콘 스케일업(ζ≈0.5, 확실한 바운스)을 다른 감쇠비로 분리.

### 검증 방법

`npx remotion still`로 정지 프레임을 여러 컷 타입(오프닝/통계/라인차트)
에서 뽑아 색상·대비를 확인했고, `npx remotion render --frames=<범위>`로
실제 mp4를 짧게 렌더링한 뒤 ffmpeg로 프레임을 추출해 카운트업 애니메이션
("8,561건" → "10,037건"으로 실제 올라가는 것)이 정상 작동함을 직접
확인. 그레인·패럴랙스·바운스처럼 "움직여야 보이는" 요소는 정지 이미지
비교로는 판단 불가능하다는 걸 깨닫고, 최종적으론 mp4 파일 자체를 Finder로
열어 재생 확인하는 방식으로 전환.
