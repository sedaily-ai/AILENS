## 배경

사용자가 홈 "오늘의 이슈, 4가지 시선"의 형식 타일을 클릭했는데 페이지가
안 넘어가는 것처럼 느껴진다고 스크린샷으로 지적하며 시작됐다. 원인을
추적하다 발행 파이프라인의 캐시 무효화 타이밍 버그와, 별개로 지난 세션에
"레포 밖 이슈"로 잘못 스코프됐던 메타디스크립션 붙음 버그의 진짜 원인을
찾았다. 이어서 사용자가 "페이지속도·메타디스크립션·GEO/AEO 체크"를
요청해 감사를 돌렸고, 그 결과로 홈 페이로드 축소 작업을 했다. 그 다음
"온보딩 페이지 디자인 통일"을 요청받아 `/start` 7단계 플로우를 전면
재작업했고, 마지막으로 "이번에 만진 것 중 태깅 작업은 다 됐나" 질문에
답하다가 `frontpage_auto`가 애초에 태그가 하나도 없었다는 걸 발견해 고쳤다.

## 한 것

### 1. lens 상세페이지 "이슈를 찾을 수 없어요" — 캐시 지연 발행
- `pipelines/frontpage_auto/run.py`, `pipelines/mustknow_auto/run.py`
  (main() 정규 실행 + manual_backfill 포함): revalidate 웹훅을 후보
  전체 처리가 끝난 뒤 1회 호출하던 것을, 기사 하나가 발행 성공할
  때마다 즉시 호출하도록 변경. 뒤에 남은 후보의 영상 생성이 안 끝나면
  이미 DB엔 써진 앞선 기사도 그 사이 SSR 캐시가 안 갱신돼 사용자가
  클릭해도 "이슈를 찾을 수 없어요"로 뜨는 문제였다.
- `pipelines/discovery/pipeline.py`: `_strip_html()`이 `<br/>` 등 HTML
  태그를 빈 문자열로 지워서 원문 subTitle의 줄바꿈 자리가 사라지고
  문장이 그대로 붙어버리던 버그 수정(태그를 공백으로 치환 후 공백
  정리). 실제 원본 XML에서 `<br/>` 3개로 구분된 4줄짜리 subTitle이
  한 줄로 붙는 걸 재현·검증했다. lens/video/letters 메타디스크립션
  전부 이 필드(`service/backend/services/cms_posts_shaping.py:220`의
  `context = post.get("subtitle")`)를 거쳐가고 있었다.
  **주의**: 이미 발행된 글의 subtitle 값 자체는 소급 안 됨 — 새로
  발행되는 글부터만 정상.

### 2. 홈 페이로드 축소
- `service/frontend/src/shared/lib/api/cmsPostsApi.ts`에
  `toLensPreviewSummaries()` 신설, `service/frontend/src/app/page.tsx`가
  홈 히어로("오늘의 이슈" LensPreviewSection)에 내려주는 lens 데이터에서
  안 쓰는 4포맷 전체 본문(bullets/paragraphs/transcript 등)을 제거.
  Lighthouse 실측 홈 HTML 6.7MB → 배포 후 실측 5.43MB.
- `service/frontend/src/app/sitemap.ts`: video/listen 채널에 Google
  비디오 sitemap 확장 필드(`videos`) 추가(웹툰의 `images`와 대칭).

### 3. 온보딩(`/start`) 재설계
- `OnboardingHeader.tsx` 신설 — 7단계 공용 헤더(세그먼트 진행바 항상
  표시, 뒤로가기, 스킵). `onboardingButton.ts` 신설 — 공용 주요 액션
  버튼 스타일(포맷 정해진 화면은 그 포맷 accent 배경).
  `LetterStoryCards.tsx` 신설 — 레터 포맷 체험 화면을 문장 단위
  스토리 카드(자동 전환 4.2s·좌우 탐색·타이머 바)로 교체, 실제 CMS
  문단만 사용.
- `OnboardingFlow.tsx`: 이동 이력(history 스택) 기반 뒤로가기 추가.
  "건너뛰기"의 의미를 "그 질문만 스킵"에서 "온보딩 전체 종료, 홈으로"로
  통일(사용자가 실사용 중 지적).
- `ConditionalFooter.tsx`/`AnnouncementBar.tsx`: `/start`를 games·
  timeline과 같은 완전 몰입형 라우트로 분류해 전역 푸터·공지배너 숨김
  — 불필요한 스크롤 제거.
- 색·타이포·레이아웃 통일: `#3182F6`(온보딩 로컬 하드코딩) →
  `LENS_ACCENT`, 보조 회색 3종 → 1종, 컨테이너 폭 420/440/680 → 420
  (체험 화면만 구조상 680 유지), 결과 화면의 방사형 그라데이션 배경·
  accent색 카드 글로우 제거(중립 회색 그림자로 교체).

### 4. frontpage_auto 비용태깅 구멍
- `frontpage_auto/tags-ecs.json` 신설, `eventbridge-runtask-policy.json`에
  `ecs:TagResource` 권한 추가, `eventbridge-target.json`에
  `PropagateTags: TASK_DEFINITION` 추가, `deploy.sh`가
  `register-task-definition`에 `--tags` 전달하도록 수정, `provision.sh`도
  같은 패턴으로 갱신(기록 문서 정합성 — 재실행 스크립트 아님).
- 라이브 리소스에 직접 적용: IAM 정책 갱신, EventBridge 타겟 갱신, 태그
  포함 새 태스크 정의 리비전(30) 등록, 로그그룹·EventBridge 규칙·ECR·
  ECS 클러스터·IAM 역할 3개 소급 태깅 — 전부 `list-tags`로 확인 완료.

## 결정

- 레터 스토리 카드의 문장 분할·전환 방식은 3가지 안(스토리형 카드/
  숫자 모션 카드/타이핑 리빌)을 제시하고 사용자가 "스토리형 카드"를
  선택한 뒤 구현했다.
- "건너뛰기" 의미 변경도 3가지 안(전체 종료/처음 3단계만/X 버튼 별도)
  중 사용자가 "건너뛰기 = 전체 종료"를 선택.
- 이미 발행된 과거 글의 subtitle 붙음은 이번엔 백필하지 않음(사용자가
  물어봤을 때 필요하면 별도 요청하기로).
- frontpage_auto 태깅은 "다음 배포부터만 반영" 정도로 끝낼 수도 있었지만,
  실제 컴퓨트 비용(Fargate 태스크)까지 태깅되려면 PropagateTags·
  ecs:TagResource가 함께 있어야 한다는 걸 mustknow_auto의 기존 주석에서
  발견해 같이 고쳤다 — 절반만 고치면 또 새는 상태였을 것.

  팀 확인 필요.
