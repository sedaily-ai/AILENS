# 2026-09-18 웹툰 챗랩 실시간 스트리밍 UI 개선

작성: 문영광 + Claude Code
관련: `admin/frontend/src/components/PromptChatLab/PromptChatLab.tsx`,
참고 포팅 대상: `1_ai_link/nova/ainova-v2/dev/nova/frontend/src/features/chat/hooks/useSmoothStreaming.js`

## 배경

스크립트·장면 연출 생성 중 원문 미리보기를 붙인 뒤, 여러 라운드에 걸쳐
스트리밍 표현이 부자연스럽다는 지적이 이어졌다 — "전체 출력을 하고나서..
보정을 하네요(실시간으로 안 됨)", "버벅이면서.. 뚝뚝 끊기는 느낌",
"타이핑 하듯이.. 타닥타닥타닥 나와야 하는데.. 지금은 쭉 한번에 끊기듯이",
"스크롤 하고 싶은데 계속 아래쪽으로 이동", 마지막으로 "다 쓰고 나서
보정은 제가 원하는게 아닙니다"(필드 단위로 완성 시점을 맞춰야 한다는 뜻).

## 한 것 (순서대로)

1. **구조화 렌더 도입** — `JSON.stringify(data.script, null, 2)` 원문 노출을
   `DumpNode`(키:값 나열, `image_prompt`/`animation_prompt`류 필드만 자동
   코드블럭 박스)로 교체. 스트리밍 미리보기와 완성 카드가 같은 컴포넌트를
   쓰게 해서 "완성 시 디자인이 바뀌는" 문제 자체를 없앴다.
2. **최선-복구 파서** — `tryParsePartialJson()` 신설: 끝이 안 닫힌 문자열
   (홀수 따옴표), 값 없이 남은 키, 안 닫힌 `{`/`[`를 스택으로 추적해 강제로
   닫아 매 청크마다 다시 파싱 — 반쪽 JSON도 그 순간까지 들어온 필드만큼
   `DumpNode`로 그린다. 초기 버전은 "값 없이 키만 남은" 케이스에서 실패했고,
   해당 키째로 버리는 정규식 보정을 추가해 로컬 5개 샘플 전부 통과하도록
   수정.
3. **타이핑 리빌 포팅** — nova(`ainova-v2`)의 `useSmoothStreaming.js` 패턴을
   그대로 이식. 서버 원문은 `fullTextRef`에 즉시 누적(네트워크 속도와 무관),
   `requestAnimationFrame` 루프가 `cps = max(25, backlog * 2.2)` 공식으로
   밀린 양에 비례한 속도로 한 글자씩 드러낸다 — 드러난 prefix만 매 프레임
   `tryParsePartialJson`으로 재파싱.
4. **성능/스크롤 버그 수정** — 리빌 인덱스 계산(매 프레임)과 실제
   `setLiveParsed()`(리렌더 트리거)를 분리, 후자는 90ms 간격으로만 실행
   (`RENDER_INTERVAL_MS`, 완료 시 강제 1회 렌더하는 `justCaughtUp` 예외
   있음) — 코드블럭 포함 트리 전체를 초당 60번 리렌더하던 버벅임 해결.
   자동 스크롤도 `[messages]`(smooth)와 `[liveText, liveParsed]`(auto,
   즉시)로 분리하고 `isNearBottomRef`/`handleListScroll`(바닥에서
   120px 이내일 때만)을 추가 — 스트리밍 중 사용자가 위로 스크롤해도
   다음 프레임에 도로 끌려 내려가던 문제 해결.
5. **필드 단위 코드블럭 타이밍** — `computeInProgressPath()` 신설: 스트리밍
   원문을 문자 단위로 스캔하며 "지금 값이 자라고 있는 자리"의 JSON 경로
   (예: `["cuts", 1, "scene"]`)를 실시간 추적하는 미니 상태 머신. 값
   문자열의 닫는 따옴표가 나오면 그 즉시(콤마를 기다리지 않고) 그 필드를
   "완성"으로 처리한다. `DumpNode`에 `path`/`inProgressPath` prop을 추가해,
   지금 이 경로와 일치하는 필드만 평문 유지하고 그 외(이미 값이 닫힌 필드)는
   즉시 코드블럭으로 확정 — 응답 전체가 끝나길 기다리지 않는다.

## 결정

- 코드블럭 감지는 필드 "이름" 기준(정규식) 그대로 유지하고, 감지된 필드
  중에서도 "지금 진행 중인 것"만 예외 처리하는 방식을 택했다 — 필드 값
  내용을 분석해 완성 여부를 판단하는 방식보다 훨씬 가볍고, JSON 자체가
  구조를 이미 갖고 있어 정확도도 충분하다고 판단.
- 스캐너 로직(`computeInProgressPath`)은 로컬 Node 스크립트로 7개 케이스
  (진행 중 필드, 방금 닫힌 값, 완전히 닫힌 JSON, 빈 배열 경계 케이스 등)
  단위 테스트 후 반영.
