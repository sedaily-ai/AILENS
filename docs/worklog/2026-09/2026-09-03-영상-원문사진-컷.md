# 2026-09-03 영상 포맷에 원문 사진(photo) 컷 추가

작성: Claude Code
관련: `8a5bb2e`(main 머지 커밋)

## 배경

기자 피드백 6번(영상): "인포그래픽·픽토그램 확대"(완료·검증됨)와 "기사에
사용된 원문 사진이 들어가면 좋을 것 같음" 중 원문 사진 항목이 이전
라운드에서 "Remotion 컷 타입 신설 + CMS 사진 배선 필요"로 별도 라운드
분리 결정됐던 것을 이번에 처리했다.

조사 결과 데이터는 이미 CMS까지 와 있었다 — `pipelines/discovery/
pipeline.py`가 원문 XML의 `<image href=...>`를 이미 `photo_url`로 파싱해
`mustknow_auto`/`frontpage_auto`가 영상 채널 CMS 레코드의
`cover_image_url` 폴백으로 쓰고 있었다. 다만 영상 각본 생성
(`generate_script.py`)에는 이 값이 전혀 전달되지 않고 있었다 — 유일한
진짜 공백.

## 한 것

- `discovery/pipeline.py`: `image` 엘리먼트에서 `caption_title`/
  `caption_content`도 같이 캡처(`photo_caption`) — `clients/
  s3_xml_client.py`의 `_parse_image()`와 같은 속성명.
- `generate_script.py`: `photo_url`/`photo_caption` kwarg 추가. LLM에는
  원문 뒤에 `[원문 사진]\n있음 — {caption}` 한 줄만 이어붙여 "있다/이런
  캡션"만 알려주고, 실제 URL 문자열은 절대 주지 않는다 — `fix_script()`
  (기존 아이콘 화이트리스트 후처리와 같은 함수)가 `type: "photo"` 컷을
  만나면 파이프라인이 이미 아는 실제 URL로 항상 덮어쓴다. LLM이
  `photo_url` 없이 photo 컷을 만들면 `highlight`로 안전 강등.
- `schema.ts`: `photoCutSchema` 추가(`data: {url, credit?}`),
  discriminated union에 편입.
- `PhotoCut.tsx`(신규): 다른 컷과 달리 `CutLayout`을 안 쓰고 직접 짰다
  — Remotion `<Img>` 풀블리드 배경 위에 상/하 다크 스크림 오버레이,
  기존 `BrandTag`/`CaptionBar` 재사용, `credit`은 우하단 작은 텍스트로.
  이 프로젝트 최초의 원격 이미지 렌더라 로컬 렌더 1회 + 프레임 캡처로
  실제 확인(원격 URL 로딩·오버레이·캡션·credit 전부 정상).
- `CutRenderer.tsx`: `'photo'` case 추가(기존 exhaustive-check `never`
  패턴이 있어 타입 누락 시 컴파일 에러로 바로 드러남).
- `mustknow_auto/run.py`·`frontpage_auto/run.py`: `_generate_video()`
  호출부에 `article["photo_url"]`/`["photo_caption"]` 배선(두 파일 동일
  패턴 복제 — 오늘 letters 수정 때와 같은 기존 관례).
- DDB `PROMPT#video/published` v6→v7: 컷 타입 6종→7종(photo 추가),
  data 스키마 블록에 `// photo` 추가, "원문 사진" 신설 섹션(있을 때만·
  서사에 구체적으로 맞을 때만 사용, url은 프롬프트가 직접 안 채움),
  "비주얼 원칙"의 "실제 로고·브랜드 이미지 금지"에 photo 컷 예외 명시
  (AI가 지어내는 그래픽에만 적용되는 규칙이었지, 서울경제가 이미 공개
  발행한 원문 사진과는 애초에 무관 — "정책 반전"이 아니라 새 컷 타입
  하나를 추가한 것). 폴백 파일(`service/backend/prompts/video/
  published.md`, 8/20 수준으로 낡아있던 것도 이번에 같이 v7로 동기화).

## 검증

- `discovery/pipeline.py`·`generate_script.py`·`mustknow_auto/run.py`·
  `frontpage_auto/run.py` 4개 `python3 -m py_compile` 통과.
- `fix_script()`의 photo 주입/강등 로직을 합성 데이터 3케이스(URL
  있음/없음/photo 컷 아닌 경우)로 직접 호출해 단위 테스트하듯 확인 —
  전부 통과.
- `pipelines/video`에서 `npx tsc --noEmit` 통과.
- 실제 S3 이미지 URL(그 순간 라이브였던 다른 기사의 video 썸네일 —
  진짜 원문 사진은 아니지만 렌더 경로 검증엔 충분)로 합성 `script.json`을
  만들어 `npm run render`로 로컬 렌더 1회, `ffmpeg`로 photo 컷 프레임을
  캡처해 육안 확인 — 원격 `<Img>` 로딩·그라디언트 오버레이·캡션 칩·
  credit 텍스트 전부 정상 렌더됨을 확인.

## 결정

- photo 컷의 URL은 LLM이 직접 쓰지 않는다 — 잘못 베낄(hallucination)
  위험을 원천 차단하기 위해 파이프라인이 후처리로 항상 덮어쓴다. 기존
  아이콘 화이트리스트 패턴과 같은 원칙.
- 사진이 없는 기사(대다수일 수 있음)는 photo 컷이 그냥 안 나온다 —
  `asOfDate` 생략 패턴과 동일, 별도 처리 불필요.
- "기승전결(기=관계자 멘트로 시작)" 항목은 이번 라운드에서 안 건드림
  — 현재 구조(진입→문제→본론→반전→클로징)가 이미 유사한 아크를 갖고
  있어 재검토는 필요하면 별도로.
