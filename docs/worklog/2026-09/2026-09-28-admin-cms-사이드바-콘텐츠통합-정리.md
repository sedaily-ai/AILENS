관련: `admin/frontend/src/components/Sidebar.tsx`, `admin/frontend/src/app/(authenticated)/posts/page.tsx`, `admin/frontend/src/components/PostForm/{LensMode.tsx,VideoMode.tsx}`, S3 `sedaily-mbti-admin-frontend-dev` + CloudFront `E1MITYI58DB9UW`

## 배경

"탭이 많은데 깔끔하게 정리할 수 있을까요?" 요청으로 시작. 대화로 구조를
먼저 짚어본 뒤(플로우 설명 → 사용자 확인) 진행 — 코드 먼저 손대지 않았다.

## 한 것

**콘텐츠 목록 통합(글 관리 = 유일한 목록 화면)**
- 이전엔 웹툰/영상/4가지 시선이 각자 사이드바 메뉴 + 목록을 가졌는데,
  실측 확인 결과 셋 다 `listPosts(channel=...)`만 다른 사실상 동일한
  페이지였고, 지금은 자동 파이프라인이 항상 4종(레터/웹툰/팟캐스트/영상)을
  한 번에 묶어(`is_lens_bundle`) 발행하므로 채널별로 쪼개볼 이유가 없어졌다.
- `posts/page.tsx`: 웹툰/영상 채널 제외 필터 제거(실측으로 현재 데이터가
  전부 `channels:["lens"]`라 이 필터는 이미 no-op였음도 확인) +
  `editHref`를 `is_lens_bundle` 여부로 분기해 번들 글은 `/lens/edit`(4탭
  편집기)로, 일반 레터는 `/posts/edit`로 가게 수정 — 이전엔 번들 글을
  클릭하면 레터 전용 편집기가 열려 웹툰/영상/팟캐스트 내용이 아예 안
  보이는 실제 버그였음.
- 사이드바에서 웹툰/영상/4가지 시선 메뉴 제거. `/webtoon`, `/video`,
  `/lens` 라우트 자체는 남김(되돌리기 쉽게, 기존 관례).

**실사용 없는 메뉴 정리**
- 실측: 퀴즈 발행 0건, 뉴스레터 구독자 5명(최근 12일 신규 없음), 팟캐스트는
  콘텐츠 목록 자체가 없는 플레이스홀더. 사용자 확인 후 사이드바에서 3개
  전부 제거(라우트는 유지).
- 최종 사이드바: "콘텐츠"(글 관리/홈 플레이어) + "운영"(대시보드/비용/
  스케줄·플래그/설정) 2그룹 6항목.

**미디어 미리보기 추가**
- `/lens/edit`의 팟캐스트·영상 탭이 링크 입력창만 있고 실제 재생 불가 —
  자동 파이프라인이 채우는 media_url/video_url이 YouTube가 아니라 S3
  mp3/mp4 직링크라 기존 YouTube 썸네일 로직으로는 아무것도 안 떴음.
  YouTube면 iframe 임베드, 아니면 `<audio>`/`<video>` 네이티브 태그로
  직접 재생하도록 `LensMode.tsx`에 `MediaPreview` 추가, `VideoMode.tsx`
  (`/video/edit`)도 동일 패턴으로 맞춤.

## 결정

- 팟캐스트는 콘텐츠 목록 통합 대상에서 제외 — 웹툰/영상/4가지 시선과 달리
  자체 콘텐츠 목록이 원래 없었음(프롬프트 편집 전용). 이후 실사용 확인
  단계에서 이것도 결국 메뉴에서 뺐다.
- 삭제 대신 "라우트 유지 + 메뉴만 제거" 원칙 그대로 적용 — 이번 정리
  전체(웹툰/영상/4가지시선/팟캐스트/퀴즈/뉴스레터)에 일관되게.
