# 프롬프트 랩 사이드바 UX — 대화 목록 정리 + 양옆 리사이즈 (2026-09-25)

## 문제 발견

- 사용자 스크린샷 지적: 대화가 많은 스레드(실사용 50개)에서 "전체 대화 보기" 버튼이 목록과 같은 스크롤 흐름 안에 있어 화면 하단에 다른 UI(새 대화 아이콘)와 겹쳐 잘려 보임
- "우측 프로덕션 적용 프롬프트 사이드 부분도 모두" 양옆으로 드래그해서 폭을 조절하고 싶다는 요청 — 가운데 칸(음성/이미지 생성 패널)엔 이미 있는 기능인데 좌측 대화 목록·우측 설정 패널엔 없었음

## 문제 정의

- `ChatThreadSidebar.tsx`가 `VISIBLE_COUNT=8`로 고정해 목록을 자르고 넘치는 건 별도 모달로 봐야 했음(2026-09-21 결정) — 지금은 그 결정을 재검토하는 상황
- `PromptChatLab.tsx`/`PromptTextLab.tsx`의 우측 "설정"(발행 프롬프트) 패널은 `w-[380px]`로 고정, 가운데 음성/이미지 생성 패널(`imagePanelWidth`/`mediaPanelWidth`)만 이미 드래그 리사이즈가 있었음 — 세 칼럼 중 하나만 조절 가능한 비일관 상태

## 왜 그렇게 했는지

- 목록 표시 방식은 사용자와 함께 실시간으로 네 가지를 순서대로 검토: ①스크롤 없이 개수 고정 → ②스크롤 → ③`overflow-hidden`(항목이 경계에서 애매하게 잘림 발견) → ④버튼 실측 높이로 정확한 개수 계산(코드 완성) → 결국 "어렵게 하지 말고 스크롤 두고 전체 대화 보기는 삭제"로 최종 결정. 대화 목록은 title/시각만 담은 가벼운 요약이라(이미 다 불러온 상태) 스크롤이 추가 백엔드 호출을 만들지 않는다는 점을 확인해 성능 걱정 없이 단순한 쪽으로 확정
- 리사이즈는 이미 검증된 자체 패턴(`imagePanelWidth`/`handleImagePanelResizeStart`, `mediaPanelWidth`/`handleMediaPanelResizeStart` — 둘 다 마우스 드래그 + `Math.min/max`로 폭 clamp)을 그대로 복제 — 새 훅이나 라이브러리를 추가하지 않고 이미 이 코드베이스에 있는 것과 똑같은 모양으로 통일
- 좌측 대화 목록(`ChatThreadSidebar.tsx`)은 `PromptChatLab.tsx`/`PromptTextLab.tsx` 둘 다 공유하는 컴포넌트라 폭 상태를 부모가 아니라 컴포넌트 자신이 들고 있게 함(중복 방지)

## 어떻게 달라졌는지

| | 이전 | 이후 |
|---|---|---|
| 대화 목록 표시 | 8개 고정 캡 + "전체 대화" 모달 | 스크롤로 전부 표시, 모달 제거(추가 백엔드 호출 없음 확인) |
| 좌측 대화 목록 폭 | 고정 220px | 드래그 조절(160~400px) |
| 우측 설정 패널 폭(웹툰/레터·팟캐·영상 공통) | 고정 380px | 드래그 조절(300~640px) |
| 3칼럼 리사이즈 일관성 | 가운데 칸만 가능 | 좌·중·우 전부 가능 |

- `tsc --noEmit`, `eslint`, 프로덕션 빌드(22라우트) 전부 클린 확인 후 배포 완료

## 결정

- "전체 대화 보기" 모달(`AllThreadsModal`)은 완전히 삭제 — 스크롤로 전체를 이미 볼 수 있어 중복 UI였음
- 리사이즈 폭 상태는 세션 간 저장(localStorage) 없이 매 진입 시 기본값(220/380px)으로 시작 — 기존 가운데 칸 리사이즈도 저장 안 하던 것과 동일하게 맞춤(비일관 방지)
