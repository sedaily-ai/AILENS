# 영상 랩 렌더 속도 3배 단축 — Fargate vCPU + 동시성 + TTS 병렬화 (2026-09-24)

## 문제 발견

- "동영상 생성이 더 빨라지면 생성할 맛 날 것 같다"는 요청으로 조사 착수
- 완료된 실제 렌더 1건(9컷, 1684프레임, horizontal)의 CloudWatch 로그를 직접 분석 — 전체 476초 중 TTS 순차 처리 58초, 나머지 ~418초가 렌더링+인코딩

## 문제 정의

- `@remotion/renderer`(설치 버전 4.0.513) 소스를 직접 읽어 확인: 렌더 동시성 기본값이 `round(min(8, max(1, 코어수/2)))` — 감지된 코어의 **절반만** 사용
- video-lab Fargate 태스크가 2 vCPU라 2/2=1 → 사실상 싱글스레드로 프레임을 하나씩 렌더링하고 있었음(56초 분량 영상 렌더에 7분 넘게 걸린 이유)
- 컨테이너 CPU 감지 자체는 `os.availableParallelism()`으로 cgroup을 정확히 읽는 버전이라 오감지 문제가 아님(GitHub `remotion-dev/remotion#4300`은 별도 프로젝트의 구버전 이슈, 우리 설치본엔 해당 수정이 이미 반영돼 있음을 소스 대조로 확인)
- TTS 9컷도 `resolveAudio.ts`에서 `for`+`await` 순차 루프로 처리돼 58초가 그대로 더해지고 있었음

## 왜 그렇게 했는지

- Remotion 공식 문서(서버 렌더링 방식 비교)를 리서치 — Remotion이 자체적으로 "Remotion Lambda가 속도·비용·성숙도 종합 최선"이라 권장. 단일 머신(Fargate) 방식은 코어 수라는 물리적 한계를 못 벗어나지만, Lambda는 프레임 구간을 수십 개 함수에 병렬 분산하는 구조(공식 예시: 600프레임을 30개 함수로 분산 시 20프레임 분 시간+스티칭 10~20초)
- 이번엔 Remotion Lambda 마이그레이션을 적용하지 않음 — 신규 Lambda 함수 배포+사이트 번들 S3 업로드+호출부 전면 교체가 필요한 진짜 아키텍처 변경이라, 지금 구조 그대로 적용 가능한 저위험 조치부터 먼저 처리하고 마이그레이션은 별도 기획으로 분리
- `renderMedia()`에 `concurrency: '100%'`를 명시해 "절반만 쓰는" 기본값을 오버라이드 — 코드 소스(`get-concurrency.js`)로 100%가 감지된 코어 수 그대로 적용됨을 확인한 뒤 반영
- TTS는 무제한 `Promise.all` 대신 동시 4개로 제한한 워커 풀 방식 채택 — Polly는 여유 있으나 ElevenLabs(요금제별 동시 요청 한도)가 있어 더 낮은 공통분모에 맞춤

## 어떻게 달라졌는지

| | 이전 | 이후 |
|---|---|---|
| Fargate 태스크 | 2 vCPU / 4GB | 8 vCPU / 16GB(리비전 3) |
| 렌더 동시성 | 1(코어수/2, 소수점 내림) | `concurrency: '100%'` 명시로 최대 8 |
| TTS 처리 | 9컷 순차(`for`+`await`) | 워커 풀 동시 4개 |
| 전체 렌더 시간(동일 입력 재검증) | 476초 | **160초** |

- 검증 방법: 이전에 476초 걸렸던 동일 입력 스크립트(S3 원본 그대로 재사용, `job_id=5b89aa039e7a4475`)를 그대로 재렌더해 직접 비교
- TTS 완료 순서가 `[1][3][4][2][5][6][8][9][7]`로 확인돼 병렬 처리가 실제로 걸렸음을 실증(순차였다면 1→9 고정 순서)
- 프레임 수 1661(vs 1684, TTS 길이 미세 차이로 거의 동일), 인코딩 100% 정상 완료 확인
- 공유 이미지(`sedaily-lens-frontpage-auto:latest`) 재빌드·푸시로 frontpage_auto 리비전 68도 동시 갱신됐으나, 수정 파일이 전부 `pipelines/video/` 안쪽이라 frontpage_auto/mustknow_auto 실행 로직 자체는 무변경

## 결정

- 인프라 크기(vCPU) 조정까지만 이번에 적용 — Remotion Lambda는 설정 변경이 아닌 아키텍처 도입이라 별도 기획 필요, 사용자 확인 후 착수하기로 함
