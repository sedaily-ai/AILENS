## 배경

기존 `/onboarding`은 5단계 질문형 온보딩(welcome/motivation/context/result/letter)이
"부담스럽다"는 피드백으로 폐기되고 소개용 스크롤 랜딩(about page)으로 대체된
상태였다. 그런데 최근 받은 실제 피드백은 "독자들이 자기 유형에 맞는 기사를
찾아가는 게 없다"는 것 — 5단계 질문 자체가 문제가 아니라 **질문을 먼저
시키는 순서**와 **결과(result) 리빌이 없다는 것**이 문제였다는 재해석.

듀오링고/말해보카/링글 온보딩 패턴(가입을 맨 뒤로 미루고, 콘텐츠 체험 →
취향 파악 → 결과 리빌까지 비회원 상태로 진행 → 결과를 "잃고 싶지 않아서"
구독하게 만드는 구조)을 참고해 7단계 플로우로 재설계했다.

  InterestStep 관심분야 → ResultStep 결과리빌 → SubscribeStep 이메일구독 →

  재사용.

- `subscribe.py`(Phase 2) — 구독 시 선택한 `format`/`interests`를 옵셔널로

  미완료 조건부 노출로 만들었다가, 로그인 상태에서 확인하던 사용자 눈엔
  안 보여 "안 뜬다"는 오해를 사서 로그인 여부 무관 상시 노출로 변경. 배치도
  처음엔 `NewsFeedTab` 바깥 별도 maxWidth로 떠서 실제 피드 그리드
  (`maxWidth:1320` 2열)와 안 맞았다 — `topBanner` prop(기존 `sidebar` prop과
  같은 패턴)으로 그리드 안, 히어로 캐러셀 바로 위로 재배치.
- 백엔드 Lambda 23개 배포(`service/backend/deploy.sh api`), 프론트 EC2 배포
  (`service/frontend/deploy.sh`) — 여러 차례(배너 반복 수정 때마다).

## 결정

- FSD 경계 위반 1건 남김 — `ConsumeStep.tsx`가 `LensFormatPanel`을
  `app/(content)/lens/[slug]/components/`에서 직접 import(`features → app`
  역방향 의존, eslint `boundaries/dependencies` warning). 제대로 고치려면
  `LensFormatPanel`을 `shared/ui/`로 옮겨야 하는데 기존 프로덕션 페이지를
  건드리는 작업이라 이번 스코프에서 보류.
- STEP 7(배송 시간 설정) — 와이어프레임엔 "7시/8시/9시" 피커가 있었지만,
  실제 파이프라인(frontpage_auto 07:00 고정, mustknow_auto 6회 고정 배치)이
  유저별 임의 발송 시각을 지원 안 해서 드롭. 대신 확인 화면 +
  `/lens/[slug]?v=N` 딥링크로 "오늘 것부터 먼저 보기" CTA만 남김.
- Google OAuth 가입은 신규/기존 구분 신호가 없어 `/start` 라우팅 대상에서
  제외(계속 `/`로 감) — 이메일 가입만 처리.
