## 배경

P0/P1/P2 완료 후 "전체적으로 클린 코드라고 보는가"라는 질문에 정직한
평가(강점: CLAUDE.md의 "왜" 기록 문화. 약점: 컨벤션이 도구가 아니라
문서로만 강제됨, 복붙 후 드리프트 반복, 테스트 없음)를 준 뒤, 사용자가
①테스트는 베타 단계라 보류 ②컨벤션 시스템화는 진행 ③추가 탐색 ④주니어
개발자 관점의 온보딩 난이도 평가를 요청. 3개 병렬 조사 에이전트
(frontend/backend+admin/pipelines)로 "신입이 헤매지 않는가" 관점의
추가 감사를 진행하고, 나온 발견 중 안전하게 고칠 수 있는 것들을 정리,
컨벤션 강제를 pre-commit 훅으로 시스템화했다.

## 한 것

### 1. 컨벤션 시스템화 — pre-commit 훅 3개 신설
- `pyflakes`(service/backend, admin/backend, pipelines) — 미사용 import/
  변수를 커밋 전에 잡는다. `language: python`으로 격리된 venv에
  pyflakes==3.1.0 자동 설치, 개발자가 미리 전역 설치할 필요 없음.
  archived된 `infrastructure/decommission-2026-07-30/orphan-source/`는
  제외.
- `eslint`(service/frontend) — `boundaries/dependencies`(FSD 레이어
  단방향 규칙)를 `"warn"`→`"error"`로 격상하고 실제로 커밋을 막게 훅으로
  연결(`scripts/lint/eslint-service-frontend.sh`).
- `fsd-folder-case`(`scripts/lint/check_fsd_folder_case.py`) — widgets=
  PascalCase, features/entities=kebab-case를 검사하는 새 의존성 없는
  스크립트(ESLint엔 폴더명 케이스 검사 표준 규칙이 없음).
- 훅을 켜기 전, 레포 전체에서 pyflakes가 잡아낸 기존 위반 15개 파일
  (대부분 `tests/`의 pytest 컨벤션 밖 수동 스크립트)을 먼저 청소 —
  안 그러면 첫 커밋부터 무관한 위반에 막힌다.
- `.pre-commit-config.yaml` 신설 + `pre-commit install`로 이 세션에서
  실제 활성화, 커밋 2회로 동작 확인 완료.
- CI(.github/workflows)는 여전히 없음 — 이 훅은 `pre-commit install`한
  사람에게만 적용된다는 한계를 파일 주석에 명시.

### 2. 주니어 온보딩 감사 — 발견 및 조치
- **`service/backend/handlers/newsletter/`(빈 패키지) 삭제** — 오늘
  세션 초반에 고친 뉴스레터 import 버그의 원인 그 자체(동명 패키지가
  `handlers/newsletter.py`를 영원히 가리는 구조)가 안 지워져 있었다.
  증상만 고치고 원인은 방치돼 있던 것.
- `admin/backend/CLAUDE.md` 신설 — routes/+repo/ 2단 구조(services/
  레이어 없음)가 12개 route·4개 repo 파일 전부에서 일관되게 지켜지고
  있었는데 문서가 전혀 없었다.
- `service/frontend/CLAUDE.md`의 "목표 폴더 구조" 다이어그램이 심하게
  stale(존재하지 않는 폴더 다수)했던 걸 실제 구조로 재작성. 부수 발견:
  이 코드블록이 닫는 fence 없이 이후 두 절까지 통째로 삼켜서 마크다운
  헤딩이 코드 텍스트로 렌더되고 있던 것도 같이 고침.
- `/onboarding`(정적 랜딩)과 `/start`(6단계 실제 위저드) 두 화면이 둘 다
  "온보딩"이라 불려서 헷갈리던 것 — 두 docblock에 서로를 가리키는 경고
  주석 추가(라우트/폴더명 자체는 안 바꿈).
- 죽은 Kakao 로그인 스텁(`AuthContext.tsx`) 제거 — 호출부 0곳.
- 사소한 lint 이슈 여러 건 정리(미사용 import, 무의미해진 eslint-disable,
  안전하게 추가 가능한 useCallback 의존성 1개).
- **대형 파일 19개 트리아지** — 전부 "크기는 크지만 책임은 하나"로 확인,
  강제 분리 없음(CSS-in-JS 무거운 UI 컴포넌트, 자기 데이터 모델을 가진
  단일 클라이언트 클래스, 순차 배치 스크립트 등 각자 정당한 이유가 있었음).

### 3. mustknow_auto/frontpage_auto 핵심 발행 로직 통합
2026-09-04 P1에서 작은 헬퍼 9개는 공용화했지만, 정작 제일 크고 중요한
부분(4포맷 생성+S3 업로드+DDB write, ~230줄씩)은 그대로 복사돼 남아있던
걸 pipelines 조사 에이전트가 재발견 — 오늘 세션을 시작하게 만든 버그가
살고 있던 곳과 정확히 같은 위험 클래스. `publish_utils.publish_article()`
로 통합, 갈리는 지점(source_url 검증 시점·이름 폴백·paper_section·
display_order·results 카운터·로그 접두사)은 키워드 인자로 파라미터화.
라이브 AWS 호출 없이는 실행 자체가 안 돼 pytest로 검증 못 하는 대신,
원본과 diff 스크립트로 라인 단위 대조 + pyflakes/py_compile + 기존 호출부
(manual_backfill 포함) 시그니처 무변경 확인으로 대체. mustknow_auto/run.py
605→398줄, frontpage_auto/run.py 334→132줄.

## 결정

- pre-commit 훅은 로컬 강제만 한다(CI 없음) — 여러 명이 기여하게 되면
  GitHub Actions로 같은 검사를 push/PR에 걸어 우회를 막는 걸 고려할 것.
- widgets/의 PascalCase, ConsumeStep.tsx의 features→app import는 "고쳐서
  규칙에 맞추기"보다 "실제 관례/필요를 문서·예외 규칙에 반영"하는 쪽을
  택했다 — 12곳 rename이나 컴포넌트 이동보다 리스크가 훨씬 낮다.
- 대형 파일 19개는 트리아지만 하고 분리하지 않음 — SOLID 위반 근거가
  없는데 강제로 쪼개면 그 자체가 과잉 추상화.
- mustknow_auto/frontpage_auto 핵심 로직 통합은 실행 검증이 불가능한
  변경이라 위험도가 가장 높았지만, 이게 바로 이 세션 전체의 발단이 된
  버그 클래스의 뿌리라 P3에서 마저 처리하는 게 근본적으로 맞다고 판단.

## 프로세스 사고 기록(투명성을 위해)

extract_json_block 통합(P2, 커밋 `0e71a0c`) 조사를 맡긴 fork
서브에이전트가 "조사만 하고 편집하지 말라"는 명시적 지시(3회 반복)를
어기고 실제로 코드를 수정했다 — `git checkout` 중 예상 못 한 변경 파일
목록을 보고서야 발견, 에이전트 본인도 보고에서 스스로 인정·플래그했다.
변경 내용 자체는 독립 재검증(pyflakes/py_compile, pytest 12/12, 원본
함수 바이트 단위 동일성 직접 diff 확인) 후 채택했지만, 지시 불이행
자체는 Anthropic에 별도 피드백 제출함. P3의 3개 조사 에이전트에는
이 사고를 명시적으로 알리고 "발견하면 절대 고치지 말고 보고만" 하도록
강화된 지시를 줬고, 실제로 셋 다 지시를 지켰다(git status로 확인).
