# 프롬프트 실험 4탭 UI 통합 + 모델 드롭다운 6종 확장 (2026-09-24)

## 문제 발견

- "4개 탭 UI/UX 정돈 작업은 된건가요"라는 확인 질문으로 현황 점검 착수
- 채팅 스레드 상태(메시지/스레드 목록/appendMessage/openThread) 로직이 `PromptChatLab.tsx`(웹툰)·`PromptTextLab.tsx`(레터/팟캐/영상) 두 파일에 거의 그대로 중복
- 모델 드롭다운이 실제 Bedrock 계정 보유 모델과 어긋나 있고(Opus 5.1을 있는 것처럼 표기), 활성 탭 기본값이 진입 페이지마다 달라 일관성 없음

## 문제 정의

- 공통·비공통 컴포넌트 감사 결과: 공통(`PromptSectionsPanel`/`ChatThreadSidebar`/`VersionPreviewModal`/`CollapsibleSection`/`textModels.ts`)은 이미 분리돼 있었으나, 채팅 스레드 상태만 유일하게 복붙 상태로 남아있었음
- `aws bedrock list-foundation-models` 직접 조회 결과 Opus 5.1은 계정에 존재하지 않음(착오), 반면 Opus 5.5/Sonnet 5/GPT-6 Astra·Sol은 실재하나 드롭다운에 없었음

## 왜 그렇게 했는지

- 새 상태관리 라이브러리 대신 `useChatLabThread.ts` 훅 하나로 중복 로직을 추출 — 백엔드는 이미 라우트 하나(`routes/chat_threads.py`)가 category 파라미터로 4포맷을 전부 처리하고 있어 프론트 리팩토링만으로 충분하다고 판단
- 모델 드롭다운은 베어 모델 ID 대신 application inference profile 경유 원칙(비용태깅 규칙)을 신규 3종에도 동일 적용 — 새 예외를 만들지 않음
- 활성 탭 기본값은 페이지별 분기를 없애고 "letters" 단일값으로 통일 — "어느 페이지에서 열었냐"에 따라 첫 탭이 달라지던 동작을 의도적으로 제거

## 어떻게 달라졌는지

| | 이전 | 이후 |
|---|---|---|
| 채팅 스레드 상태 | `PromptChatLab.tsx`/`PromptTextLab.tsx` 2곳 중복 | `useChatLabThread.ts` 단일 훅 |
| 텍스트 모델 드롭다운 | 3종(sonnet-46/opus-5/sonnet-5), Opus 5.1 존재 여부 미확인 | 6종(+opus-5-5/gpt-6-astra/gpt-6-sol), 전량 실제 호출로 존재 확인 |
| 활성 탭 기본값 | 진입 페이지별 상이 | "letters" 고정, `?format=` 쿼리 동기화 |
| 프로덕션 모델 표시 | 드롭다운에 하드코딩된 "프로덕션 기본값(레터)" 옵션 | `GET /admin/prompts/{category}/current-model` 신설, 헤더 배지로 실시간 표시 — 프로덕션 모델 변경 시 프론트 재배포 불필요 |

- 웹툰 탭 헤더의 중복 "목록으로" 버튼(바깥 셸 닫기 버튼과 중복) 제거
