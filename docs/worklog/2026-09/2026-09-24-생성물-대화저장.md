# 생성물(컷 이미지·음성·영상)을 대화 스레드에 저장 (2026-09-24)

## 문제 발견

- "대화 나갔다 오면, 생성했던 음성·영상·웹툰이 사라지는데... 대화들은 살아있는데, 나머지들도 다 남으면 좋지"라는 지적 — 채팅 텍스트는 서버 스레드로 저장되는데 그 대화에서 만든 결과물은 다른 대화를 열었다 돌아오면 사라진 것처럼 보임

## 문제 정의

- 스레드 저장은 완전 자유형 JSONB라 신규 백엔드 작업은 불필요함을 먼저 확인
- 웹툰 컷 이미지는 생성 즉시 이미 저장되고 있었으나(`imagePreview` 메시지, `cut_image` 이벤트 시점 append), 그 데이터가 채팅 말풍선 렌더링에만 쓰이고 실제 사용자가 보는 우측 그리드(`WebtoonCutGenerator.tsx`의 `slots`)로는 전혀 복원되지 않던 것이 진짜 원인 — "저장이 안 됨"이 아니라 "저장은 되는데 복원 배선이 없음"
- `slots`가 `cuts` prop 변경(=대화 전환) 시 리셋되지 않는 역방향 버그도 동시 존재 — 다른 대화의 이미지가 새 대화 화면에 남아 보임
- 팟캐스트(`VoicePreviewGenerator.tsx`)·영상(`VideoCardGenerator.tsx`)은 스레드와 아예 무관하게 설계돼 있었고, 영상 카드가 쓰던 localStorage도 전역 키 1개라 여러 대화가 혼재

## 왜 그렇게 했는지

- 채팅 말풍선(`appendMessage`)과 별도로 `useChatLabThread.ts::persistArtifact()`를 신설 — 팟캐/영상 카드 완료 결과를 말풍선으로 노출하면 어색한 텍스트 말풍선이 끼어들기 때문에, 로컬 `messages`는 안 건드리고 서버에만 조용히 append하는 경로를 분리
- threadId가 없으면(채팅을 한 번도 안 한 상태) 저장하지 않고 무시 — 이미 그렇게 동작하던 웹툰 컷 이미지 저장과 같은 전제를 그대로 따름, `ensureThread()`는 "첫 사용자 메시지" 전제라 생성기 카드가 임의 호출하기엔 부적합하다고 판단해 새로 만들지 않음
- 복원 로직 초안은 `useEffect`+`setState`로 작성했으나 `react-hooks/set-state-in-effect` 규칙(및 `admin/frontend/CLAUDE.md` "근본 수정 우선" 원칙)에 저촉 — `WebtoonCutGenerator.tsx`가 이미 쓰던 "렌더 중 prop 비교로 그 자리에서 state 동기화" 패턴으로 전면 재작성

## 어떻게 달라졌는지

| | 이전 | 이후 |
|---|---|---|
| 웹툰 컷 이미지 | 서버 저장은 됨, 그리드 복원 배선 없음 + 대화 전환 시 리셋 안 됨 | `restoredCutImages` 수집 + `threadId`/`restoredImages` prop 연결, 전환 시 8칸 리셋 후 재적재하는 로직 하나로 복원·리셋 동시 해결 |
| 팟캐 음성 카드 | 스레드 무관, 저장 없음 | `audio_ready` 시점 `persistArtifact`로 저장, `restoredAudioCards` 복원 |
| 영상 카드 | 스레드 무관, localStorage 전역 키 1개 | 렌더 종료(done/error) 시점에 오디오+영상 결과 한 번에 저장(append-only 특성상 분할 저장 시 복원 중복 방지), localStorage 키를 `threadId`별로 분리 |
| 데이터 스키마 | — | `types.ts::ChatThreadMessage`에 `audioPreview`/`videoPreview` optional 필드 추가 |

- 검증: tsc/eslint 전체 소스 트리 + 프로덕션 빌드 25개 라우트 통과, 관리자 프론트엔드 배포 완료

## 결정

- 채팅 말풍선 인라인 카드 렌더러(웹툰 `CutImagePreview`급)는 범위 제외 — 요청은 "사라지지 않게"였지 "예쁘게 보이게"가 아니었음, 저장 데이터는 이미 있어 렌더러만 추가하면 되는 구조로 남김
- 영상 렌더 "진행 중" 상태는 서버 미저장(완료 결과만) — 동일 브라우저 새로고침 대비는 기존 localStorage로 충분, 타 기기 이어보기는 범위 밖
