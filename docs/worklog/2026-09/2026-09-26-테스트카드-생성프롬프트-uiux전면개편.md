# 2026-09-26 테스트 카드 "생성 프롬프트" UI/UX 전면 개편 + 버전 이름 기능

작성: 문영광 + Claude Code
관련: `admin/frontend/src/components/{CustomSelect.tsx,PromptChatLab/{PromptVersionReference,VersionSwitcher,CollapsibleSection,PromptChatLab,PromptTextLab}.tsx}`, `admin/backend/{routes/prompts.py,repo/prompts_repo.py,handler.py}`, `service/lens-cms-api/{main.py,prompts_repo.py}`, `admin/frontend/src/lib/{formatDate.ts,promptLabSections.ts,types.ts,adminClient.ts}`

세션 하나로 이어진 대화지만 실제로는 독립된 지적이 8~9번 연쇄돼서 한 컴포넌트가 계속 다시 그려진 과정이다 — 사이클 단위로 쪼갠다.

---

## 사이클 1 — 카드 자체가 너무 복잡함 (진입점)

**문제발견**: 테스트 카드를 펼치지 않으면 어떤 버전이 쓰이는지 전혀 안 보였고, 펼쳐도 "버전 불러오기" 드롭다운이 "생성 프롬프트" 토글과 별도 위치에 있어 조회·전환에 클릭이 여러 번 필요했다.
**근거**: 사용자 직접 조작 후 지적 — "테스트 카드 컴포넌트 UI/UX가 너무 복잡한거 아닌가요? ... 어떻게 클릭 클릭을 하고 시선들이 움직일려나?"
**문제정의**: "자주 훑어보는 정보(지금 몇 버전)"와 "가끔 하는 작업(편집·커밋)"이 한 레벨에 섞여 있었다.
**Why**: 테스트 카드가 웹툰/팟캐스트/영상 3곳에서 반복되는 핵심 UI라, 여기서 생긴 혼동은 화면 3개로 그대로 복제된다.
**How**: 점진적 공개(progressive disclosure) 원칙 적용 — "조회·전환"(버전 드롭다운, 활성화 배지)은 `CollapsibleSection`의 항상-보이는 헤더로, "편집·커밋"(설명/지침/파일, 버전 저장/적용/삭제)은 펼쳤을 때만 보이는 본문으로 분리. `CollapsibleSection.tsx`에 `badge`(오른쪽 끝, 상태 표시)와 별개로 `titleExtra`(제목 옆, 왼쪽 무리 — 컨트롤용) 슬롯을 신설.
**판정**: 적용 완료.

## 사이클 2 — 드롭다운 위치·클리핑·시인성

**문제발견**: 드롭다운이 오른쪽 끝에 있었고("우측에있어요"), 열면 화면 밖으로 잘렸고("드롭다운열면 화면에 잘리는데"), 트리거가 그냥 텍스트처럼 보여 클릭 가능한 컨트롤인지 구분이 안 갔다("선택 이라고 나와있는데... 박스? 색상이라도").
**Why**: 셋 다 "이게 조작 가능한 UI라는 신호가 없다"는 같은 근본 원인이라 한 번에 고쳤다.
**How**:
- 위치: `titleExtra`로 제목 옆(왼쪽)으로 이동.
- 클리핑: 원인은 `overflow-y-auto` 컨테이너가 CSS 스펙상 `overflow-x`도 자동으로 `auto`가 되는 것 — `CustomSelect.tsx`를 `position:absolute` 자식 렌더에서 `createPortal(document.body) + position:fixed` 방식으로 전면 재작성, `getBoundingClientRect()` 기반 좌표 계산 + `alignRight` prop.
- 시인성: `boxed` prop 추가 — 트리거에 테두리+배경(칩 모양)을 입힘.
**판정**: 적용 완료.

## 사이클 3 — "커밋 범위"가 안 보임 + 저장 결과 불투명

**문제발견**: 설명/지침/파일을 고치고 "버전 저장"을 누르는 게 하나의 묶음이라는 게 시각적으로 안 느껴졌고("경계? 가 있으면 더 안정적이지 않을려나"), 저장 버튼을 눌렀을 때 몇 번 버전으로 남는지 미리 알 수 없었다("어떤 버전이름으로 저장이 되는거죠? 그걸 모르겠네").
**How**: 편집 영역(설명/지침/파일) + 커밋 영역(저장/적용/삭제 버튼 + 상태 문구) 전체를 `ui-card` 테두리 박스 하나로 묶음. 저장 버튼에 `nextVersionPreview`(= `MAX(모든 버전)+1`, 서버 채번 규칙과 동일하게 프론트에서 미리 계산) 표시 — **단, 이 표시는 사이클 8에서 다시 제거됨(아래 참고)**.
**판정**: 1차 적용 → 이후 사이클에서 방향 수정.

## 사이클 4 — 버전 삭제 + 생성 시각 + 타임존 버그

**문제발견**: 버전을 지울 방법이 없었고("버전을 삭제하는 방법도 있어야"), 생성 시각이 없었는데 추가하고 보니 실제 한국 시간보다 9시간 이른 값이 찍혔다.
**근거**: 사용자가 스크린샷과 실제 벽시계 시각을 직접 대조해서 발견("지금. 한국 시간 기준 맞나요??").
**Why**: 타임존 버그는 방치하면 "언제 저장됐는지" 판단 자체가 틀어져 버전 관리 신뢰도를 깎는다.
**How**:
- 삭제: 3계층 전부 신설 — `service/lens-cms-api/prompts_repo.py::delete_version()`(활성 버전은 `{"deleted": False}`로 거부) → `main.py DELETE /internal/admin/prompts/.../versions/{version}` → `admin/backend` 프록시(`repo/prompts_repo.py::delete_version`, `routes/prompts.py::handle_delete_version`) → `DELETE /admin/prompts/.../versions/{version}` 등록.
- 타임존: `lib/formatDate.ts::formatKstDateTime()` 신설 — UTC 인스턴트에 9시간을 더해 `getUTCFullYear` 등으로 읽는 방식(브라우저 로컬 타임존 변환은 의도적으로 안 씀 — 한국 전용 관리자 도구라 뷰어 타임존에 관계없이 결정적이어야 함). 기존 `formatDateTime`을 sed로 일괄 치환.
**판정**: 적용 완료 — pytest 12/12, pyflakes clean.

## 사이클 5 — 드롭다운 정보 위계 (전문가 디자인 리뷰 요청)

**문제발견**: 버전 번호·상태 배지·날짜가 한 줄에 다 욱여넣어져 구분이 안 갔다.
**근거**: 사용자가 "UI/UX 전문 디자이너라면 어떻게 보실까?"로 자가 비평 요청.
**How**: `CustomSelect.tsx::Option<T>`에 `badge`(색 있는 필), `sublabel`(둘째 줄, 옅은 색 — 날짜), `pinned`(프로덕션 항목을 맨 위 고정 + 구분선 + 배경 톤) 신설. 선택된 항목엔 체크 아이콘 추가.
**판정**: 적용 완료.

## 사이클 6 — 버전 이름(별명) 도입 + 표시/수정 UX (가장 오래 이어진 사이클)

**문제발견 → 문제정의**: "버전 번호만으론 뭘 실험한 버전인지 기억이 안 난다" — 자유 텍스트 이름을 붙일 수 있어야 함("사용자가 직접 버전 네이밍을 입력하고 저장할 수 있도록").
**Why**: 번호는 채번 순서일 뿐 의미가 없고, 실험이 쌓일수록 "이게 무슨 실험이었지"를 번호만으로 추적하기 어려워진다.
**How (버려진 대안 포함)**:
- 새 DB 컬럼 추가는 이 프로젝트 DB 역할에 `ALTER TABLE` 권한이 없어 수동 마이그레이션이 필요 — 대신 이미 있는 `prompt_versions.sections` JSONB에 `label` 키로 얹는 방식 채택(스키마 변경 0건).
- 저장 시(`handleSaveVersion`): `sections`에 `label` 조건부 포함.
- 조회(`get_prompt_history`): `sections->>'label' AS label`로 같이 반환.
- **이름 위치**: 처음엔 커밋 버튼 옆(맨 아래)에 뒀다가, 사용자 지적으로 카드 맨 위(설명보다 먼저)로 이동 — "보통 제목을 먼저 위에서 쓰고 세부적인건 아래에서 하는 로직이니까". 입력칸도 일반 박스에서 밑줄만 있는 "제목처럼 보이는" 스타일로 변경.
- **이름 자체 수정(사후 rename)**: "버전 저장"은 항상 새 번호를 만드는 동작이라 기존 버전 이름만 고치는 덴 못 씀 — 별도 `rename_version()` 3계층 신설(`service/lens-cms-api` → `admin/backend` → `PATCH /admin/prompts/{category}/{name}/versions/{version}/label`). 카드 제목 입력칸 옆 "이름 저장" 버튼(내용이 로드된 이름과 다를 때만 노출) + **드롭다운 안 연필 아이콘**(그 버전을 먼저 "불러오기" 안 해도 목록에서 바로 수정) 두 경로 다 지원.
- **연필 아이콘 세부 UX 반복**: 1차는 편집 시작하면 기존 텍스트가 사라지고 빈칸이 됐다 → 사용자 지적("edit 아이콘 누르면... 기존 버전 네이밍이 아예 사라지고 다시 쓰게 되네요"). 2차는 "v17"을 고정 프리픽스(수정 불가)로 만들었다 → 사용자가 "v17도 수정 가능해야 한다"고 재지적. 최종: 고정 프리픽스 없이 완전 자유 텍스트 입력이되, 시작값을 빈칸이 아니라 "이름이 있으면 그 이름, 없으면 번호 표시(v17)"로 채워서 아무것도 안 사라진 채로 바로 고칠 수 있게 함.
**판정**: 적용 완료, 배포 완료(2026-09-26 저녁).

## 사이클 7 — 테스트/프로덕션 카드 헤더에 버전 노출

**문제발견**: 테스트 1/테스트 2로만 구분돼 있어 카드를 펼치지 않으면 어느 카드가 무슨 버전을 쓰는지 몰랐다.
**How**: `PromptVersionReference.tsx`에 `onActiveInfoChange` 콜백 신설 — 카드 내부 로드 상태(`savedVersion`/`versionLabel`)가 바뀔 때마다 부모에게 알림(ref로 콜백을 감싸 무한 루프 방지, `react-hooks/set-state-in-effect` 회피를 위해 ref 갱신도 별도 effect로 분리). 부모(`WebtoonCutGenerator.tsx`/`VoicePreviewGenerator.tsx`/`VideoCardGenerator.tsx`)가 `Record<testId, info>`로 모아 "테스트 N" 헤더 옆 배지로 렌더 — 채팅이 실제로 쓰는 버전이면 액센트색, 아니면 회색. 프로덕션 카드 헤더에도 `v{scriptServerVersion}` 배지 추가(`PromptChatLab.tsx`/`PromptTextLab.tsx`).
**판정**: 적용 완료.

## 사이클 8 — "버전 저장 → v19" 미리보기 제거 (사이클 3 뒤집기)

**문제발견**: 이름 기능이 자리잡은 뒤 다시 보니, 저장 버튼에 아직 일어나지도 않은 결과 번호("→ v19")를 항상 노출하는 게 불필요한 내부 구현 디테일로 느껴짐.
**근거**: "v19, v18 -> v19 이런것 조차도 없도록... 없어야하는데요."
**Why**: 이름이 사람이 보는 실제 식별자가 된 이상, 자동 채번 숫자를 버튼 전면에 내세울 이유가 없어짐 — 사이클 3의 판단을 뒤집는 결정.
**How**: 버튼 문구를 무조건 "버전 저장"으로 고정(hover 툴팁에만 번호 남김).
**판정**: 적용 완료, 배포 완료.

## 사이클 9 — 버전 드롭다운 → 좌측 사이드바 전면 재설계

**문제발견**: "생성 프롬프트" 카드의 버전 드롭다운(CustomSelect 팝업)이 "뭔가 유의미한 디자인으로 안 보이더라"는 지적 — 버전을 하나하나 열어서 훑어보기 번거롭고, 그 버전에 뭐가 들어있는지 빠르게 파악하기 어려움.
**How**: 팝업 드롭다운을 없애고 채팅 스레드 사이드바 느낌의 상시 펼침 목록으로 교체 — 왼쪽 폭 고정 목록(설명/지침/파일 영역과 같은 박스 안, 넘치면 내부 스크롤), 클릭 한 번으로 그 버전 내용이 오른쪽에 뜬다("훑어보기"+"불러오기" 통합). 버전 활성화(채팅이 쓸 버전)도 각 행 왼쪽 위 점으로 직접 전환 가능하게 추가 — "불러오기 → 활성화" 2클릭을 1클릭으로 줄임.
**후속 반복**(사용자가 스크린샷 보며 연달아 지적):
- "버전저장, 휴지통, 제목 수정 부분 다 필요없다 — 사이드바에서 전부 컨트롤해야" → 우측 패널의 저장/삭제/이름수정 버튼을 전부 제거, 사이드바로 완전 이관: 목록 맨 위 "+ 새 버전"(=기존 "버전 저장"과 동일 동작, 위치만 이동), 각 행의 연필(이름 수정)·휴지통(삭제). 우측은 순수 설명/지침/파일 편집 영역만 남음.
- "v18 '2313' · 지금 프로덕션과 같음..." 상태 문구도 "의미없다" → 제거(사이드바의 체크 표시·프로덕션 태그·날짜로 이미 같은 정보가 보임).
- 이름 수정 아이콘을 눌렀을 때 기존 이름이 사라지고 빈칸으로 시작 → 기존 이름(또는 이름이 없으면 "v17" 번호 표시)으로 채워진 채 시작하도록 수정, 완전 자유 텍스트 편집(고정 프리픽스 아님) 확정.
**판정**: 적용 완료, 배포 완료.

## 사이클 10 — "프로덕션에 적용" 테스트 카드 레벨 통합 (웹툰→팟캐스트/영상 전체)

**문제발견**: "생성 프롬프트"와 "이미지 생성 — 컷"(웹툰) 안에 "프로덕션에 적용" 버튼이 각각 따로 있어 "따로따로 하지 말라고 했는데"라는 재지적. 조사해보니 podcast/video는 카드 레벨에 버튼이 하나뿐이었지만 그마저 "값만 채우고 발행은 별도 버튼을 또 눌러야" 하는 반쪽짜리였다 — 세 화면 모두 결국 "테스트 카드에서 한 번에 끝나지 않는다"는 같은 문제.
**Why**: 지금 안 고치면 사이클 9에서 PromptVersionReference의 "프로덕션에 적용" 버튼을 뗀 것 때문에(사이드바 이관 작업) 웹툰/팟캐스트/영상 전부 프롬프트 버전을 활성화할 방법 자체가 없어지는 회귀가 생긴 상태였음 — 우선순위 최상위.
**How**:
- `PromptVersionReference.tsx`를 `forwardRef`로 바꿔 `activateIfNeeded()`(로드된 버전이 프로덕션과 다르면 활성화)를 노출.
- `WebtoonImageSettingsPanel`/`PodcastVoiceSettingsPanel`/`VideoRenderSettingsPanel` 셋 다 `applyFromTest`(값만 채움) 옆에 `applyAndPublish`(override 값으로 changed·confirm 가드를 건너뛰고 바로 발행)를 추가 — 세 패널이 정확히 같은 패턴을 쓰도록 통일.

## 사이클 11 — 프로덕션 카드가 활성화 직후 예전 내용을 계속 보여주던 버그

**문제발견**: 테스트 카드에서 "프로덕션에 적용"으로 v18을 활성화했는데, 상단 "프로덕션" 카드의 "생성 프롬프트" 섹션은 여전히 예전(활성화 전) 지침 내용(10,220자)을 그대로 보여줬다. 사용자 질문: "프롬프트 부분이 왜 프로덕션이랑 동일하지 않은가? DB에서 끌어당기지 않은건가?"
**문제정의**: 백엔드(`main.py::internal_activate_prompt_version`)는 버전 활성화 시 `prompt_lab_docs`(프로덕션 카드가 읽는 별도 저장소)까지 같이 동기화하도록 이미 짜여 있었다 — DB 자체는 맞다. 문제는 프론트: `PromptSectionsPanel.tsx`가 `prompt_lab_docs`를 마운트 시 딱 한 번만 읽고 그 이후로는 절대 다시 안 읽어서, 이미 화면에 떠 있던 컴포넌트는 DB가 바뀐 사실 자체를 몰랐다.
**How**: `PromptSectionsPanel`의 fetch 로직을 재사용 가능한 `loadDoc()`으로 빼고(`loadTokenRef`로 오래된 응답이 새 응답을 덮어쓰지 않게 토큰 가드), `PromptSectionsPanelHandle`에 `refresh()`를 추가로 노출. 부모(`PromptChatLab.tsx`/`PromptTextLab.tsx`)에서 테스트 카드가 보고하는 `onServerVersionChange`를 새 wrapper(`handleScriptVersionActivatedFromTest`)로 받아 버전 번호 갱신과 동시에 `scriptPanelRef.current?.refresh()`를 호출 — 활성화 직후 프로덕션 카드가 즉시 최신 DB 내용으로 다시 그려진다. 웹툰(`PromptChatLab.tsx`)·레터/팟캐스트/영상(`PromptTextLab.tsx`) 전부 동일하게 적용.
**판정**: 적용 완료, tsc/eslint/build 클린.

## 사이클 12 — 프로덕션 카드를 테스트 카드와 완전히 같은 구조로 통합(이중 저장소 제거)

**문제발견**: 사이클 11의 스테일니스 버그를 조사하던 중 근본 구조 자체가 문제라는 게 드러났다 — 이 화면엔 프롬프트를 다루는 저장소가 사실 두 개였다: ① `prompt_versions`(진짜 버전 이력, 테스트 카드의 `PromptVersionReference`가 읽음) ② `prompt_lab_docs`(별도 "초안" 저장소, 프로덕션 카드의 `PromptSectionsPanel`+`VersionSwitcher`가 읽고 씀). 실측(DB 직접 조회)으로 확인: 프로덕션 카드가 "v18"이라고 배지에는 정확히 표시하면서, 그 아래 본문은 ②에 남아있던 완전히 다른(더 예전) 버전의 내용을 보여주고 있었다 — 배지와 본문이 서로 다른 소스에서 오니 구조적으로 어긋날 수밖에 없었다. 사용자 확인 질문: "프로덕션 부분 카드도.. 테스트 카드랑 동일한 구조가 되도록 하면 어떤가요?"
**문제정의**: 저장소가 두 개인 한, 아무리 새로고침 트리거를 잘 심어도(사이클 11) 둘이 어긋나는 경우의 수 자체가 없어지지 않는다 — 근본 해법은 저장소를 하나로 합치는 것.
**Why**: 지금 안 고치면 "테스트 카드에서 활성화했는데 프로덕션 카드엔 안 보인다"는 혼동이 계속 반복된다(이번 세션에서만 세 번째 재현). 그리고 이번 사고(사이클 11에서 되돌릴 수 없는 편집 중 콘텐츠 554자를 실수로 날릴 뻔한 것)도 "저장소가 둘이라 뭐가 진짜인지 헷갈렸던" 데서 시작됐다.
**How**: `PromptChatLab.tsx`(웹툰)·`PromptTextLab.tsx`(레터/팟캐스트/영상) 양쪽에서 프로덕션 카드의 "생성 프롬프트 — 설명·지침·파일" 섹션을 통째로 걷어내고, 테스트 카드와 똑같은 `<PromptVersionReference>`를 그대로 렌더한다 — 왼쪽 사이드바로 버전 훑어보기/불러오기, "+ 새 버전", 연필(이름 수정)·휴지통(삭제) 전부 테스트 카드와 100% 동일 컴포넌트. 프로덕션 카드 전용으로 `activateIfNeeded()`를 부르는 "프로덕션에 적용" 버튼만 카드 배지에 추가(테스트 카드처럼). `scriptServerVersion`(지금 활성 버전 번호)은 더 이상 `PromptSectionsPanel`이 보고해주지 않으므로 `listPrompts()`로 직접 가볍게 조회하도록 바꿨다.
**결과 — 완전히 죽은 컴포넌트 4개 삭제**: `PromptSectionsPanel.tsx`/`VersionSwitcher.tsx`/`SettingsPublishBar.tsx`/`VersionPreviewModal.tsx` — 전부 프로덕션 카드 전용이었고 다른 곳에서 안 쓰여서(grep으로 전수 확인) 통째로 지웠다. `prompt_lab_docs`/`prompt_lab_files` 백엔드 테이블·라우트는 이번엔 안 건드렸다(더 이상 프론트에서 안 쓰지만, DB/백엔드 정리는 별도 판단 필요).
**판정**: 적용 완료 — tsc/eslint(전체 src/ 대상)/build 전부 클린.

## 사이클 13 — "프로덕션에 적용"이 조용히 아무 일도 안 하던 race condition

**문제발견**: 사이클 12로 바꾼 직후, 사용자가 "v15를 누르고 프로덕션에 적용을 눌렀거든요? ... 적용이 안된느낌"이라고 리포트. DB를 직접 조회해 확인 — active_version은 여전히 18, 진짜로 아무 일도 안 일어났다(로컬 개발 서버라서가 아님 — 이 세션 내내 로컬 dev는 실제 배포된 백엔드/DB를 그대로 호출한다).
**문제정의**: 사이드바에서 버전을 클릭하면 `loadVersion()`이 비동기로 `savedVersion`을 나중에 채우는데, 바로 이어서 "프로덕션에 적용" 버튼이 `activateIfNeeded()`를 부르면 그 순간 아직 옛 `savedVersion`(심지어 아직 `null`일 수도 있음)을 읽어 "적용할 버전이 없다"며 조용히 종료했다 — 에러도 안 남아서 사용자는 원인을 알 길이 없는 silent no-op이었다. 부수적으로 이 컴포넌트의 마운트 effect도 같은 계열 버그였다: 마운트되는 순간 부모의 `serverVersion`이 아직 `null`이면(프로덕션 카드는 자기 활성 버전을 별도 API로 늦게 가져옴) 다시는 재시도를 안 해서 `savedVersion`이 계속 `null`로 남는 경우가 있었다.
**How**: 지금 불러오는 중인 요청을 `pendingLoadRef`에 저장해두고 `activateIfNeeded()`가 그걸 먼저 기다린 뒤, `savedVersionRef`(항상 최신값을 반영하는 ref)로 판단하도록 바꿨다 — 클로저가 오래된 값을 들고 있던 근본 원인을 없앴다. 마운트 effect는 `hasLoadedOnceRef`로 "아직 한 번도 초기 로드를 못 한 경우"에만 동작하되 `serverVersion`이 바뀔 때마다 재시도하도록 deps를 `[]`→`[category, name, serverVersion]`로 바꿨다(사용자가 사이드바로 이미 다른 버전을 골랐으면 `loadVersion()`도 `hasLoadedOnceRef`를 세워 나중에 덮어쓰지 않게 함).
**판정**: 적용 완료, tsc/eslint/build 클린. 실제 클릭 시나리오는 브라우저에서 재확인 필요.

## 사이클 14 — 웹툰 컷 프롬프트 일괄 채우기

**문제발견**: 스토리보드가 만든 컷별 `image_prompt`를 8칸에 하나하나 복사·붙여넣기 해야 해서 번거로웠다. 사용자 요청: "이미지 컷별로 하나하나 복붙해서... 넣기가 귀찮은데... 일괄적으로 붙여넣어지거나 채워지게 하면 좀 효율적일 것 같아요."

**판정**: 적용 완료, tsc/eslint/build 클린.

## 사이클 15 — "프로덕션에 적용" 전 검토 모달 + 적용 이력

**문제발견**: "프로덕션에 적용"이 `window.confirm` 한 줄만 띄우고 바로 실제 자동 생성 파이프라인에 반영돼서, 뭐가 적용되는지 미리 확인할 방법도, 나중에 언제·누가 적용했는지 돌아볼 방법도 없었다. 사용자 요청: "현재 설정한 것들... 최종적으로 검토를 하도록 하고... 해당 테스트에서 출력된 결과도 같이 보면서 검토하도록... 중앙 모달 창 띄우고요... 프로덕션에 적용한 이력들도 남아야 해요, 몇시 몇분 날짜에 했는지."
**문제정의**: 확인 하나(검토 없이 즉시 실행)와 기록 없음(적용 이력 조회 불가) 두 가지가 묶인 요청 — 검토 모달과 이력 조회 API를 같이 만들어야 한다.
**Why**: 실제 자동 생성 파이프라인(웹툰/팟캐스트/영상)에 즉시 반영되는 되돌리기 어려운 조작이라, 클릭 한 번보다 한 단계 더 확인할 여지를 두는 게 안전하고, 사고 발생 시(사이클 11~12의 이중 저장소 사고 참고) "언제 뭘 적용했는지" 되짚을 기록이 있어야 한다.
**How**:
- **이력 저장(신규 인프라 없이 재사용)**: `admin/backend/routes/prompts.py::handle_activate_version`이 이미 매 활성화마다 `audit.log("prompt-activate", {...})`를 남기고 있었다(기존 감사 로그 인프라) — 새 테이블 없이 이 로그를 필터링하는 조회 하나만 추가하면 됐다. `service/lens-cms-api/audit_repo.py::list_prompt_activation_history()` 신설(action='prompt-activate' AND detail->>'prompt'=카테고리/이름, 최신순) → `main.py`에 `GET /internal/admin/prompts/{category}/{name}/activation-history` 신설 → `admin/backend/repo/prompts_repo.py::get_activation_history()` → `routes/prompts.py::handle_get_activation_history()` → `handler.py`에 `GET /admin/prompts/{category}/{name}/activation-history` 등록(pyflakes/pytest 12/12 클린) → `adminClient.ts::getPromptActivationHistory()`.
- **검토 모달**: `PromptChatLab/ApplyReviewModal.tsx` 신설 — 웹툰/팟캐스트/영상 3곳이 공용으로 쓰는 컴포넌트. `settingsSummary`/`resultPreview`는 호출부가 자기 사정(프롬프트 버전+이미지 모델 / +음성 설정 / +포맷)에 맞게 JSX로 넘기고, 모달 자체는 확인/취소 버튼·적용 중 스피너·"최근 적용 이력" 목록(`getPromptActivationHistory` 호출, KST 포맷) 공통 부분만 책임진다.
- **3곳 배선**: `WebtoonCutGenerator.tsx`/`VoicePreviewGenerator.tsx`/`VideoCardGenerator.tsx`의 "프로덕션에 적용" 버튼을 `window.confirm` 직접 호출 대신 `reviewTestId`/`reviewSlotId`/`reviewCardId` state로 모달을 열도록 바꿨다. 결과 미리보기는 각 화면 성격대로: 웹툰=완료된 컷 이미지 그리드, 팟캐스트=오디오 플레이어, 영상=영상(렌더 전이면 오디오로 폴백) — 아직 아무 결과도 없으면 "프롬프트·설정만 반영됩니다" 안내로 대체.
**결과**: tsc/eslint(대상 파일 전체)/build 클린(25개 라우트 정상 생성). `aws apigatewayv2 create-route`로 새 라우트(`GET /admin/prompts/{category}/{name}/activation-history`) 등록, `service/lens-cms-api` `./deploy.sh` 배포(헬스체크 200, 신규 엔드포인트 실제 EC2에서 v15 활성화 이력 정상 반환 확인), 로컬 `local_server.py` 재기동(신규 라우트로 로컬 검증 완료), `admin/backend` `./deploy-admin-api.sh` 배포 후 API Gateway를 통해 401(인증 필요, 404 아님)로 라우트 정상 반영 확인.
**판정**: 백엔드+프론트+배포 전 구간 적용 완료. 브라우저에서 실제 클릭 시나리오(모달 열기→결과 미리보기→적용→이력 갱신 확인)는 재확인 필요.
