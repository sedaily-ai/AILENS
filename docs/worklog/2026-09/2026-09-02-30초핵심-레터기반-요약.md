# 2026-09-02 "30초 핵심"이 웹툰 캡션 대신 레터 전용 요약을 쓰도록 수정

관련: 브랜치 `fix/core-summary-from-letter`(머지됨, main `cea1bf3`),
DDB `PROMPT#letters/published` v3→v4

## 배경

기자가 발행된 기사 1건("반도체 호황 올라탄 821조 슈퍼 예산...")을 4포맷
전부 검수한 피드백 문서를 받음(`~/Downloads/AI렌즈_기자_관점_구성_피드백.docx`).
가장 구체적인 지적: 기사 상세페이지 상단 "30초 핵심" 카드의 "빚 106조 원
늘어요, 어떻게 가능하죠?"라는 문장이 질문만 던지고 답이 없어서, 독자가
원문을 안 보면 이해할 수 없음.

## 한 것

- 근본 원인 파악: "30초 핵심"은 전용 요약이 아니라 **웹툰 컷 캡션을
  재활용**한 것이었다 — `lensSamples.ts`의 `coreSummaryBullets()`가 포맷
  순서(팟캐스트→영상→웹툰→레터)로 `bullets` 필드를 뒤지는데, 실제
  생성기(`frontpage_auto`/`mustknow_auto`의 `run.py`)는 레터·팟캐스트·
  영상엔 전부 `bullets: []`만 넣고 웹툰만 컷 캡션을 채워서, 이 카드는
  사실상 항상 웹툰 캡션이었다. 캡션은 그림과 함께 볼 때 뜻이 완결되는
  텍스트라 그림 없이 카드로 떼어놓으면 맥락이 빠진다 — 기자가 지적한
  현상과 정확히 일치.
- 레터 프롬프트(DDB `PROMPT#letters/published`, v3→v4)에 `[핵심 요약]`
  블록 신설 — 3~4문장, 6하원칙(무슨 일 → 왜 가능한가/문제인가 → 앞으로
  뭘 볼지) 순서, 각 문장이 비교 기준(시점·모수)을 포함해 단독으로 완결
  되도록, 질문형 금지. `handle_update`(admin 프롬프트 저장 API)와 완전히
  동일한 DDB 스키마로 직접 write(`v#4` put + `LATEST.active_version` update).
- `pipelines/{frontpage_auto,mustknow_auto}/run.py` — `_parse_letters()`가
  `[핵심 요약]` 블록에서 멈추도록 수정(안 그러면 본문 문단에 섞임) + 새
  함수 `_parse_letter_summary_bullets()` 추가. 레터 항목의 `bullets`를
  더 이상 `[]`로 하드코딩하지 않고 이 함수 결과로 채움.
- `lensSamples.ts` — `SUMMARY_BULLET_FORMAT_ORDER`를 `[2,3,1,0]`→
  `[0,2,3,1]`로 변경(레터 최우선, 웹툰은 레터가 비었을 때만 폴백).
- 파서 유닛 검증(샘플 마크다운으로 `_parse_letter_summary_bullets`/
  `_parse_letters` 둘 다 오염 없이 정확히 분리되는지 확인) + `tsc`/lint 클린.
- 배포: 파이프라인 Docker 이미지(`sedaily-lens-frontpage-auto` 리비전 18,
  mustknow_auto도 같은 이미지 공유) + 프론트 EC2.

## 결정

- 기자 피드백의 나머지 항목(공통 팩트시트, 팟캐스트·영상 기준일 표기,
  웹툰 컷 간 캐릭터 일관성, 영상 인포그래픽 비중)은 사용자가 "차근차근
  하나씩" 요청한 대로 **이번 스코프에 안 넣음** — Step 1(이 항목)만 처리.
- 이미 발행된 "반도체 호황..." 기사 자체는 소급 수정 안 함 — 옛 프롬프트로
  만들어진 과거 발행분은 그대로 두고, 이 변경은 앞으로 발행되는 기사부터
  적용.
- `_parse_letters()`/`_parse_letter_summary_bullets()`를 `common/`으로
  공용화하지 않고 두 파일에 각각 복제 — 이미 그렇게 돼 있던 기존 코드
  관행(`_parse_letters` 자체가 이미 두 파일에 복제돼 있었음) 그대로 따름.
