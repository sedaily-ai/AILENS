# 2026-09-28 자동 발행 파이프라인 — 웹툰·영상 버그 수정 + 백필

작성: 문영광 + Claude Code
관련: `pipelines/{webtoon/pipeline.py,video/generate_script.py,common/{bedrock_client.py,publish_utils.py},webtoon/compose_text.py}`, `admin/backend/routes/prompts.py`, `service/frontend/src/features/news-feed/components/LensPreviewSection.tsx`, `service/frontend/src/app/(content)/lens/[slug]/components/LensFormatPanel.tsx`, ECS `sedaily-lens-frontpage-auto` 리비전 78~83, 웹툰 prompt `webtoon/published` v20

## 배경

"웹툰 생성 안된게 있는 것 같은데 오늘 자 거에?", "지면 1면에 9/23 기사가 아직 있네요"
등 사용자 리포트로 시작 — 전날(2026-09-27) 레터/팟캐스트/영상/웹툰 전 카테고리를
Opus 5로 전환한 뒤, 자동 파이프라인(mustknow_auto/frontpage_auto)에서 웹툰·영상이
광범위하게 "없이 발행"되고 있었다. 오늘 지면 1면 섹션이 며칠째 갱신 안 되는
문제도 같이 확인됐다.

## 한 것

**웹툰 100% 실패 — 확정 원인 2건, 순차 수정+재배포**
- `pipeline.py:165`의 고정 `temperature=0.7`이 Opus 5에서
  `ValidationException(temperature is deprecated for this model)`로 매번 실패
  → 제거(`bedrock_client.call_text`가 None이면 아예 안 넘김).
- `call_json(..., max_tokens=8000)`이 Opus 5의 길어진 영/한 이중
  image_prompt로는 8컷을 못 채우고 응답이 멀티바이트 문자 중간에서 잘림 →
  `16000`으로 상향(자동 발행 파이프라인 + `admin/backend/routes/prompts.py`의
  admin 실험 도구, 둘 다 패리티 유지).

**영상 실패 — 확정 원인 2건**
- `generate_script.py::validate_script()`가 `cuts`가 비어있거나
  `brand`/`source`가 없어도 통과시켜서(빈 배열은 for 루프가 그냥 스킵), 빈
  스크립트가 script.json으로 저장된 뒤 한참 뒤 render.ts의 Zod 스키마에서야
  죽었다 → 최상위 필드 검증 추가, 기존 재요청 경로를 타게 함.
- `stat` 컷의 `data.value`가 `"16~30"` 같은 범위 문자열로 오면 렌더가
  깨짐 → `fix_script()`에 안전한 숫자 코어스(콤마·공백만 벗기고, 범위처럼
  숫자가 둘 이상 섞이면 손대지 않음) 추가. **1차 구현에 버그 있었음** —
  비숫자 문자를 전부 지우는 순진한 regex라 "16~30" → 1630(없는 숫자)으로
  잘못 변환하는 걸 배포 전 로컬 재현으로 잡아 재수정(실제 배포 안 됨).
  `validate_script()`에도 같은 검사 추가해 코어스 실패 시 재요청 경로로.

**웹툰 "전부 아니면 무" 정책 완화**
- `publish_utils.py`: 8컷 중 1컷이라도 이미지 생성 실패(컨텐츠 필터 등)하면
  업로드 루프가 없는 파일을 열려다 `FileNotFoundError`로 죽고, 이미 성공한
  나머지 컷까지 전부 버려지던 것 확인(실사례: "갤런당 50마일..." 기사, 7/8
  성공했는데 전부 폐기). 실패한 컷만 건너뛰고, 남은 컷이
  `N_CUTS-2`(=6/8) 이상이면 그대로 발행하도록 완화.

**웹툰 이미지 내 텍스트 겹침 버그**
- `compose_text.py`: 캡션 박스(좌하단, 흰 배경)와 내레이션 밴드(하단 전체,
  회색 반투명)가 같은 컷에 있으면 둘 다 독립적으로 "화면 맨 밑" 기준 좌표로
  그려져 겹침. narration/closing_caption을 먼저 그리고 그 상단 y좌표를
  받아 caption을 그 위로 띄우도록 수정 — 로컬 PIL 렌더 테스트로 겹침 해소
  확인 후 배포.

**지면 1면(전체 탭)이 9/23 기사에 멈춰있던 문제**
- 원인: `display_order`가 "그날 회차 안에서만" 0부터 다시 매겨지는 값인데
  `LensPreviewSection.tsx`가 이걸 전체 기간 통틀어 전역 오름차순 정렬 —
  과거 어느 날 우연히 0을 받은 글이 영구히 1등 자리를 차지. 날짜를
  1순위(최신순)로, 같은 날짜 안에서만 `display_order`로 정렬하도록 수정.

**백필 (이미 발행된 게시물의 결손 보완)**
- 오늘(KST) 발행된 웹툰 빈 게시물 14건 확인 후 전부 재생성해서 채워넣음
  (1건은 컨텐츠 필터로 1차 실패, 재시도로 8/8 성공). 전부 공개 API로
  8컷 게재 확인.
- 지면 1면 기사 1건("음원 저작권료가...") 영상 결손 확인 후 재생성해서
  채워넣음 — `video_url` 공개 API로 확인.
- "갤런당 50마일..." 기사(컷7 실패로 7컷 전부 폐기됐던 건) 정책 완화 후
  재생성 → 7/8컷 게재 확인.

**웹툰 프롬프트 v20 적용 + 최근 10건 일괄 재생성**
- 사용자가 CMS에서 웹툰 프롬프트 v20을 저장했다고 알려왔는데, 실측 확인
  결과 **저장만 됐고 프로덕션엔 미적용**(active_version이 여전히 v15)이었다
  — `POST /internal/admin/prompts/webtoon/published/activate`로 v20 적용,
  적용 후 active_version=20 재확인.
- 적용 시점 기준 최근 발행 10건(오늘 KST)의 웹툰을 전부 v20으로
  재생성 — 9건 1차 성공, 1건("농지 신고 포상금...")은 Bedrock 응답 JSON
  파싱 실패로 스크립트 생성 자체가 안 됐다가 재시도로 8/8컷 성공. 최종
  10/10 전부 공개 API로 패널 게재 확인.
- v20 적용 이후 자동 파이프라인이 새로 발행한 글(백필 대상이 아니었던
  "편의점에서 립밤...", "대웅제약..." 등)도 별도 조치 없이 이미 v20
  기준으로 생성된 것 확인(발행 시각이 v20 적용 이후라 자동 반영).

**웹툰 "대사로 읽기" 자막 줄바꿈**
- `LensFormatPanel.tsx`의 "대사로 읽기" 목록이 `cut.caption`을 가공 없이
  그대로 렌더해서, 한 컷 캡션에 문장이 여럿 있으면(원문 내레이션이
  마침표로만 이어붙는 경우가 흔함) 한 줄로 쭉 이어져 보였다 — 문장 종결
  부호(`.`/`!`/`?`) 뒤에서 끊어 문장 단위로 나누는 `splitSentences()` 추가,
  각 문장을 `display:block` span으로 렌더. 종결 부호 뒤에 공백이 있든
  없든(원본 캡션 표기가 혼재) 둘 다 처리하도록 부호 기준으로 split.

## 결정

- 웹툰 "부분 성공" 임계값은 `N_CUTS-2`(현재 6/8)로 — 사용자 확인 후 채택.
  이보다 적으면 기존처럼 전체 폐기(부실한 웹툰보다 pending이 낫다는 원칙
  유지).
- 과거에 이미 발행된, 아직 겹침 버그가 남아있는 이미지는 자동으로
  재생성하지 않음 — 새로 생성되는 컷부터만 적용(요청 시 개별 백필).

## 다음

- 겹침 버그가 있는 과거 발행 이미지들 — 필요하면 개별 백필.
- 영상 렌더 실패(스키마 위반 외의 사유, 예: Bedrock JSON 파싱 실패)는
  비결정적으로 재발 가능 — 재시도 외 근본 대응은 아직 없음. 웹툰 스크립트
  생성도 같은 유형의 실패(오늘 "농지 신고 포상금..." 건)가 있었음 —
  마찬가지로 재시도 외 근본 대응 없음.
- v20 이전(v15)으로 발행된 과거 웹툰들은 이번 백필 대상(오늘 발행 10건)
  밖이라 그대로 남아있음 — 필요하면 범위를 넓혀 추가 백필.
- 프롬프트 버전을 저장(v20 등)하는 것과 "프로덕션에 적용"하는 것은
  별개 동작이라는 점을 admin 화면에서 더 명확히 드러낼지 검토 — 오늘
  실제로 이 차이 때문에 "버전은 저장됐는데 반영이 안 됨" 상황이 발생.
