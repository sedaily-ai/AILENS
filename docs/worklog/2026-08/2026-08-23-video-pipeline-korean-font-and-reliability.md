# 2026-08-23 영상 파이프라인 한글 폰트 근본 원인 수정 + 웹툰 2단계 신뢰성 개선

작성: Claude Code
관련: pipelines/video, pipelines/webtoon

## 배경

사용자가 "영상에 글자가 깨져서 나오는데 왜 그러지?"라고 지적 — 최신 발행
2건의 영상에서 브랜드 태그·통계 박스 라벨 등 일부 한글 텍스트가 네모
박스로 나왔다(같은 영상 안의 다른 한글 캡션은 정상 렌더되는 들쭉날쭉한
증상). 조사 도중 웹툰 2단계(장면 연출) JSON 파싱 실패의 근본 원인도
같이 짚었다.

## 한 것

### 1. 영상 렌더 한글 깨짐 — 폰트를 실제로 로드한 적이 없었다
- `styles/tokens.ts`의 `FONT_FAMILY`가 `'Pretendard'`를 1순위로 쓰는데,
  프로젝트 어디에도 `@font-face`나 실제 폰트 파일이 없어서 한 번도 로드된
  적이 없었다. 폴백 목록(`-apple-system`, `'Apple SD Gothic Neo'`,
  `'Malgun Gothic'`)도 전부 macOS/Windows 전용이라 헤드리스 Linux
  (Fargate) Chromium엔 하나도 없음 — 결국 마지막 `sans-serif` 제네릭에
  우연히 걸리는 글리프만 렌더돼, 렌더 환경/단어마다 되고 안 되고가 갈리는
  증상이었다.
- Noto Sans KR(Google Fonts, 400/500/600/700/800 5개 웨이트 — 웹툰 컷
  텍스트 합성 때 쓴 것과 같은 출처)을 `public/fonts/`에 실제로 번들.
  `src/lib/fonts.ts`(신규)가 `FontFace` API + Remotion
  `delayRender`/`continueRender`로 렌더 시작 전 로드를 보장. `FONT_FAMILY`
  1순위를 `'Noto Sans KR'`로 교체.
- 로컬 `remotion still` 렌더로 검증 — 정확히 깨졌던 필드 패턴("같은
  뉴스, 네 가지 시선 | AILENS")이 정상 렌더됨을 스크린샷으로 확인.
- 이미 깨진 채로 발행됐던 영상 2건(총량제의 덫, 은행 상반기)을 로컬에서
  스크립트부터 재생성해서 같은 S3 키에 덮어씀 — DDB는 그대로라 별도
  반영 작업 없이 즉시 새 영상으로 교체됨.
- 같은 요청으로, 영상이 아예 없던 기존 lens 글 2건(카카오 인적분할,
  교육교부금)도 처음부터 영상을 새로 만들어 채워 넣음 — lens 글의
  video 포맷 + 독립 video 채널 글 둘 다 갱신.

### 2. 웹툰 2단계(장면 연출) JSON 파싱 실패 원인 대응
- 사용자 질문("2단계가 왜 실패하나요")에 답하며 재조사 — `call_json()`의
  `max_tokens=2000`이 1·2단계 공통인데, 2단계는 8컷 각각의 카메라+장면
  묘사를 전부 써야 해서 1단계(대사/캡션)보다 원래 더 길다. 응답이 문장
  중간에 잘리면 닫는 `}`가 없어 4단계 JSON 폴백 전부 실패한다는 게 유력한
  원인 — video 파이프라인이 비슷한 분량(8~9컷)에 `max_tokens=4000`을
  쓰는 것과 대조.
- `max_tokens`을 2000→4000으로 확대. 확신을 못 했던 이유는 실패한 원문
  응답을 어디에도 안 남겨서였다 — `call_json()`이 파싱 실패 시 원문을
  로컬 파일(컨테이너 생애주기 안에서만 유효)과 CloudWatch로 남는 stdout
  (2000자 컷) 둘 다에 남기도록 수정, 다음에 또 실패하면 바로 원인 확인
  가능.
- 영상 재생성 과정에서 **커넥터 variant 자동 보정 부재**도 발견 —
  `schema.ts`의 `connector.variant`는 `'arrow'` 하나만 허용하는데,
  Claude가 가끔 `'divider'`/`'cross'` 같은 지원 안 하는 값을 써서 렌더가
  스키마 검증 단계에서 통째로 실패했다(자동 파이프라인에서도 조용히
  같은 이유로 영상이 빠졌을 수 있음). 기존 아이콘 화이트리스트 보정과
  같은 패턴으로 `fix_script()`에 커넥터 variant 보정 추가.

## 결정

- 이미 깨진 영상은 재생성해서 같은 S3 키에 덮어쓰는 방식을 택함(DDB
  URL은 그대로 유지) — 새 슬러그를 만들지 않아 렌즈 페이지·독립 채널
  글 양쪽 다 자동으로 고쳐진 영상을 가리키게 됨.
