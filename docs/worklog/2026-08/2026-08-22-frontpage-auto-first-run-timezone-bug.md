## 배경

어제(8/21) 저녁에 EventBridge(매일 07:00 KST) → Fargate 태스크로 지면
1면 자동 발행 파이프라인을 구축·검증 완료했다. 오늘 오전 10시 30분,
사용자가 "지금 아침입니다.. 8월 22일 10시 30분... 자동화 돌았나요"라고
확인 요청 — 실제로 트리거는 정확히 07:01 KST에 발동됐지만, 처리
결과를 보니 뭔가 잘못돼 있었다.

## 한 것

### 1. 타임존 버그 발견

CloudWatch 로그(`/ecs/sedaily-mbti-frontpage-auto`)를 확인해보니
2026-08-21T22:01:34 UTC(=2026-08-22 07:01 KST, 정확히 스케줄대로)에
태스크가 실행됐지만, 로그에 `지면 20260821 후보 탐색`이라고 찍혀
있었다 — 오늘(8/22) 지면이 아니라 **어제(8/21) 지면**을 다시 조회한
것. 5건 전부 "이미 발행됨, 스킵"으로 끝나 겉보기엔 정상 종료(exit 0,
에러 없음)였지만 실제로는 아무 일도 안 한 것이었다.

**원인**: `run.py`의 `main()`이 `today = datetime.now().strftime
("%Y%m%d")`로 "오늘"을 계산했는데, Fargate 컨테이너의 시스템 시간대는
UTC다. 07:00 KST는 22:00 UTC(전날)라서, 이 시각의 `datetime.now()`
(타임존 미지정 → 시스템 로컬 = UTC)는 아직 전날 날짜를 반환한다 —
"매일 아침 7시 지면"을 노리고 만든 스케줄인데, 정작 그 실행 시점의
UTC 날짜는 KST 기준 "오늘"보다 하루 이르다는 걸 놓쳤다. 로그가
"정상 종료"로 보여서 더 위험한 종류의 버그였다(크래시했으면 바로
알았을 텐데, 조용히 아무 일도 안 하고 성공한 것처럼 끝났다).

### 2. 실제 영향 확인

`discovery/pipeline.py`를 오늘 날짜(20260822)로 직접 돌려 검증 —
진짜 오늘 지면 1면 후보 5건이 있었다(상법개정 후유증[시그널]·현대차
전면파업·삼성전자 주주환원·교육교부금 폐지·카카오 인적분할). 자동화가
이걸 완전히 놓쳤을 뻔했다.

### 3. 수정

`run.py`에 고정 오프셋 KST 상수 도입(`timezone(timedelta(hours=9))`)
— 한국은 서머타임이 없어 IANA tzdata(zoneinfo) 의존 없이 안전하게
처리 가능. `main()`의 `today` 계산과, DDB에 쓰는 `publish_date`/slug
날짜 접두사(기존엔 `datetime.now(timezone.utc)`로 별도 계산해서 지면
날짜와 다른 값이 될 수 있었음)까지 전부 이 KST 기준으로 통일 —
`process_article()`에 `today_kst` 파라미터를 추가해 discovery가 조회한
바로 그 날짜를 DDB에도 그대로 쓰도록 스레딩.

### 4. 당일 수동 복구 실행

수정된 코드로 로컬에서 실제 발행 재실행(사용자 승인 후 진행,
`AWS_PROFILE=yeonggwang python3 run.py`) — 10:47~11:51 KST, 약 64분
소요(기사 5건 × 레터/팟캐스트/웹툰 8컷/영상). 결과:
`{"published": 1, "published_no_video": 4, "skipped_duplicate": 0,
"failed": 0}` — 삼성전자 주주환원 기사만 영상까지 4/4 포맷 완전
성공, 나머지 4건은 영상 각본의 실제 수치 누락(`validate_script()`가
의도대로 잡아냄)으로 3/4 포맷만 발행하고 `needs_video: true`로 표시.

라이브 확인: DDB에 오늘(`publish_date="2026-08-22"`) 5건 전부
`paper_section="전체"`로 존재, `display_order` 0~4가 discovery가 매긴
지면 우선순위(TOP 배치 기사가 0번)와 정확히 일치. `/?tab=feed` 200.

## 결정

- Fargate 태스크 정의에 `TZ=Asia/Seoul` 환경변수를 추가하는 대신
  코드에서 명시적으로 KST를 계산하는 쪽을 택했다 — 컨테이너 시스템
  시간대에 암묵적으로 의존하면 나중에 이미지 베이스를 바꾸거나 다른
  환경(로컬 개발 등)에서 실행할 때 또 같은 종류의 버그가 재발할 수
  있다. 코드 안에 명시하면 실행 환경과 무관하게 항상 옳다.
