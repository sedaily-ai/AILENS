## 배경

국장님 지시 — 4가지 시선(원인/공감/실무/숫자)을 지금처럼 텍스트로만 보여주지
말고, 한 유형은 레터(텍스트)·한 유형은 카드뉴스·한 유형은 팟캐스트·한 유형은
영상으로 서로 다른 출력 포맷으로 보여주는 구조를 잡으라는 요청. 회의 전
컨셉을 눈으로 보여주기 위한 목업 요청.

## 한 것

- `lensPerspectives.ts`에 `LensFormat`(`letter | cardnews | podcast | video`)과
  인덱스 기준 `lensFormatAt(i)` 헬퍼 추가 — 시선 순서(원인→공감→실무→숫자)에
  1:1로 포맷을 고정 매핑.
- `LensViewClient.tsx`의 시선 패널 렌더링을 포맷별로 분기:
  - `letter`(원인) — 기존 질문+불릿 텍스트 렌더 그대로, 변경 없음.
  - `cardnews`(공감) — 표지 카드(사진+질문) + 불릿마다 한 칸씩, 가로 스크롤
    카드덱 목업.
  - `podcast`(실무) — 재생 버튼·진행바(정적 장식) + 불릿을 챕터 목록으로.
  - `video`(숫자) — 기사 사진을 썸네일로 재사용한 재생 버튼 오버레이 +
    불릿을 타임라인 목록으로.
- 실제 서비스 코드베이스 조사 중 발견한 사실도 같이 정리(회의에서 공유 필요):
  - 카드뉴스는 이 프론트엔드에 라우트/컴포넌트가 전혀 없음(완전 신규).
  - 팟캐스트는 `shared/lib/podcastApi.ts`(Bedrock-Haiku+Polly)가 이미 있지만
    UI 소비처가 없고, 레터 상세의 미니 플레이어는 오늘 이미 제거됨("대부분
    오디오 없어 빈 회색 카드로 보임").
  - 영상·텍스트(레터)는 이미 라이브(`/video`, `/letters`, CMS 수동 업로드 기반).

### 데모 데이터 — 원문 전체 기준으로 재작성

`DEV_FORMAT_OVERRIDES`(`lens.id` 슬러그 키, `NODE_ENV==='development'`
전용, `DEV_EXACT_PHOTOS`와 같은 패턴)를 신설해 아래를 전부 원문(김태영
기자, 08/14 06:40)의 사실만으로 다시 씀 — CMS 4렌즈 불릿(이미 한 번
압축된 짧은 문장)만 재활용하던 걸 원문 기준으로 되돌려 밀도를 올림:
- `summary` — 상단 "30초 핵심" 3줄(신설 섹션, 시선 선택 위에 노출)
- `letter` — 문단 3개(27시간·84%·34%·53%·20종 라인업)
- `cardnews` — 카드 3장을 물량 숫자에서 "누가 타나"(선택지) 축으로 전면
  교체(아래 사유)
- `podcast` — 챕터 4개(3주간·제주 제외·70% 할인·얼리버드·본부장 코멘트)
- `video` — 타임라인 5개(900여대·500+300 분할·1000대 누적·59%·53%·14%)
- `bridge` — 포맷 끝마다 다음 시선으로 넘어가는 한 줄(레터→카드뉴스→
  팟캐스트→영상), 오버라이드 없는 기사는 `다음 시선 — {다음 persona
  full}`로 자동 생성

### 콘텐츠 품질 재검토 — 카드뉴스가 페르소나와 안 맞음

AI LINK/AI LENS 편집장 프롬프트(사용자 제공)의 "네 관점이 같은 사실의
말바꾸기가 아닌가" 체크리스트로 자체 점검하다가 발견: 카드뉴스(공감,
"그래서 누가 어떻게 됐을까")가 물량·일정 숫자(800+100대, 500+300 분할,
1000대 누적)만 나열해 사실상 "숫자" 페르소나 내용과 중복이었음. 카드뉴스를
"그래서 누가 이 차를 타게 될까"(예산별 선택지: 블랙라벨 프리미엄 vs
EV3·아이오닉9 실속형 vs 20종 라인업)로 전면 교체해 영상과 사실 중복 해소.

### 디자인 2차 개정 — 카드뉴스 시각 처리

1차: tint 채움 → 흰 카드 + `LENS_CARD_SHADOW`(공용 톤), persona 색은 작은
배지로 축소("카드 반복의 함정" 원칙 적용).
2차(같은 원칙에 다시 걸림): 본문 카드 3장을 persona 색 풀블리드 블록으로
바꿨다가 "균일한 색 블록 반복 = 위계 없음"이라는 같은 함정에 다시 걸림
(사용자: "토스라면 이렇게 했을까"). 흰 카드로 재복귀, 대신 원본 카피의
"훅 — 설명" em-dash 구조를 파싱해 레터 질문과 같은 세리프 큰 글자(훅) +
작은 회색 캡션(설명) 2단 위계 적용, persona 색은 아이콘 배지 하나에만.

### 카드뉴스 UX 전면 교체 — 필름스트립 → 인스타 스타일 캐러셀

"가로 스크롤로 4장을 한 번에 보여주는 게 촌스럽다, 인스타처럼 화살표로
한 장씩 넘기면 안 되냐" 지적. `/design` 스킬로 방향(표지·카드2 활성 상태
2종)을 먼저 스케치해 승인받은 뒤 반영:
- 새 컴포넌트 `CardnewsCarousel`(파일 내 로컬, `useState`로 카드 인덱스
  보유 — 시선 패널이 한 번에 하나만 보여 인스턴스도 사실상 하나) 신설.
- 카드 1장(240px, 4:5)만 크게 표시, 좌우 화살표 버튼(끝에서 비활성화) +
  터치 스와이프(가로 이동 32px 이상 시 전환).
- 상단 진행바를 인스타 스토리 세그먼트 스타일로(표지=사진 위 흰 세그먼트,
  본문 카드=흰 배경 위 persona 색 세그먼트, 지난/현재 칸은 채움).
- 기존 가로 스크롤 필름스트립 코드(`format === 'cardnews'` 100줄+)를
  `<CardnewsCarousel />` 호출 한 줄로 교체.

## 이어서 (같은 날) — 클릭 피드백 제거 + 프로덕션 노출 전환 + 배포

### 타일 선택 배경색·클릭 플래시 제거

스크린샷 지적 두 건, 순서대로 처리:
1. "유형 누르면 뜨는 배경색"(선택된 페르소나 타일 자체가 `p.tint`로 통째
   채워지던 것) 제거 — 테두리+그림자+체크 3중 표시만 남기고 `background:
   '#fff'` 고정.
2. 이어서 확인해보니 클릭 직후 **패널 전체**(포맷 카드 포함 아래 콘텐츠
   블록)를 0.9초간 persona 색으로 물들였다 빼는 클릭 피드백 효과
   (`justSelectedIdx` state, 커밋 `2c54f50`에서 같은 날 앞서 추가된 것)가
   따로 있었다 — 스크린샷의 넓은 초록 배경 원인이 이것. `justSelectedIdx`
   state·`setTimeout` 로직·`section` 배경 스타일 전부 제거.

### 프로덕션 노출 전환

데모 콘텐츠(`DEV_FORMAT_OVERRIDES` → 이 시점에 `ARTICLE_FORMAT_SAMPLES`로
개명)와 테슬라 사진 exact-match가 전부 `NODE_ENV === 'development'`에서만
켜지도록 짜여 있어(원래 안전장치) 배포해도 프로덕션엔 안 보였다. "국장님
회의에서 실제 URL로 보여줄 것" 확인 후 요청으로 게이트 제거:
- `articleFormatSample`/`articleSummarySample`/`articleBridgeSample`
  (개명 전 `devFormatOverride` 등) 3개 함수 + `cardnewsHeadline` 계산부의
  `NODE_ENV` 체크 전부 제거. 식별자도 `DEV_` 접두어를 떼 `ARTICLE_FORMAT_
  SAMPLES` 등으로 리네임(더 이상 dev 전용이 아니라 이름이 오해를 줬음).
- `pickLensPhoto()`의 사진 폴백은 둘로 나뉘어 있었다 — `DEV_EXACT_PHOTOS`
  (기사별로 정확히 지정한 사진, 이 데모 기사 전용)는 게이트 제거해 dev/prod
  둘 다 노출, `DEV_SAMPLE_PHOTOS`(무작위 매칭)는 실제 발행 글에 엉뚱한
  사진이 붙을 위험이 있어 dev 전용으로 그대로 남김 — 두 폴백을 다르게
  취급한 것이 이번 변경의 핵심 판단.
- 이 변경은 `lens.id`(기사 slug) 키로 스코프가 좁혀져 있어 테슬라 기사
  1건에만 실질적 영향 — 다른 발행 기사는 전과 동일하게 CMS 데이터만 씀.
