## 결론 먼저

오늘부로 레터의 웹 발행이 정상화됐다. 레터 생성은 이미 매일 자동으로 돌고 있었고,
끊겨 있던 것은 웹 딥링크(정적 페이지)와 안전장치였다. 남은 결정은 3개 — 프롬프트
버전 선택, 재시도 크론 승인, 매일 자동 배포 방식.

팩트:

  7/24부터 매일 4편씩 자동 적재. 결손 0일.

- 웹 레터 딥링크(/letters/{id} 정적 페이지)는 7/30 배포분에서 멈춤 —
  7/31 이후 레터는 직접 진입 시 빈 껍데기.

분석:

  수동"인 상태였다. 병목은 프론트 재빌드가 매일 돌지 않는 것 하나.
- 분량 문제는 프롬프트 계보가 갈라진 결과다. 5월에 만든 v3 프롬프트(레터당

  프롬프트를 새로 썼다.

## 결정 요청 3건

1. 레터 프롬프트 — 현행 압축형(950~1,000자) vs v3 에세이형(3,083~4,429자).
   실물 비교 (같은 기사, 프롬프트만 다름):
   - 현행: https://ailens.sedaily.ai/letters/view?id=nt-2026-08-03 (nf/st/sf 동일 형식)
   - v3:   https://ailens.sedaily.ai/letters/view?id=nt-2026-07-01 (nf/st/sf 동일 형식)
   트레이드오프: v3는 편지다운 밀도·체류시간 유리 / 생성비 일 $0.1 → $0.35,
   모바일 스크롤 길이 증가.
2. 재시도 크론 승인 — EventBridge 3개 룰의 발화 시각만 수정(신규 리소스 없음) +
   editor-pick env 1개 + 코드 배포. 지면이 늦는 날 레터 결손·구본 고착을 막는다.
   평시 추가 비용 $0.
3. 매일 자동 배포 방식 — 레터 딥링크가 매일 최신이 되려면 프론트 재빌드가 매일 필요.
   후보: (a) EventBridge → CodeBuild (관리형, 회사 계정 안에서 완결),
   (b) 로컬 crontab + deploy.sh (즉시 가능, 맥북 켜져 있어야 함).
   당장은 수동 deploy.sh 1회/일로 운영 가능.
