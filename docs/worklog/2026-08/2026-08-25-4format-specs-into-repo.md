# 2026-08-25 4포맷 프롬프트 스펙을 레포로 편입 + 없던 2종 재구성

작성: 이민서 + Claude Code
관련: `docs/product/4format-pipeline/`, PR #26(FACT_IDS 트레일러 처리),
`docs/archive/2026-08-10-뉴스웹툰-파이프라인-README.md`

## 배경

4포맷 파이프라인 프롬프트 스펙 8종이 마스터DB 에만 있고 이 레포에 없었다.
버전 관리도, 코드와의 연결도 없는 상태였다. 게다가 실제로 손에 있는 건
`03_LETTER`·`04_PODCAST`·`05_VIDEO`·`06_WEBTOON` 네 개뿐이고,
**파이프라인의 시작(`02_EXTRACT`)과 끝(`07_VERIFY`)이 없었다.**

`grep -r 'facts.json'` 을 `pipelines/`·`docs/` 전체에 돌려도 결과가 0이다 —
0단계와 검증은 문서도 구현도 아예 없다.

## 한 것

### 1. 없던 2종 재구성

- `02_EXTRACT.md` — 원문 → facts.json
- `07_VERIFY.md` — 커버리지·사실 검증 게이트

지어내지 않고 네 스펙이 facts.json 에 대해 요구하는 것에서 역산했다.
결정적 근거는 `06_WEBTOON` 출력 스키마의 `"fact_ids": [8]`
("이 컷이 담은 facts.json의 id 배열") — 사실이 정수 id 를 갖는다는 게 여기서
확정된다. 두 문서 모두 §7 에 **필드별 근거 출처표**를 달고, 추정이 섞인
곳을 따로 명시했다.

특히 `comparisons` 는 `4format-persona-system.md` §4 의 라운드1 사고
(영상이 원문에 없는 "2025: 100 → 2026: 150" 을 생성)에서 나왔다. 빈 배열이
"아직 안 찾음"이 아니라 **"원문에 대비 수치가 없음"의 확정 신호**가 되게
정의해서, 영상이 차트 컷을 스킵할 근거를 만들었다. 07_VERIFY 의 C5 가 이걸
기계적으로 검사한다.

### 2. 나머지 3종에 fact_ids 출력 추가

07_VERIFY 기준("core 사실이 최소 2개 포맷에")은 각 포맷이 자기가 담은
사실을 보고해야 성립하는데, **웹툰만 보고하고 있었다.**

- `03`·`04` — 코드블록 바깥 마지막 줄 `FACT_IDS: [1, 3, 4]`
- `05` — 이미 JSON 이라 컷마다 `"fact_ids": []`

### 3. 그 트레일러를 견디는 코드 (PR #26)

스펙만 바꾸면 프로덕션이 깨진다는 걸 확인했다 — 레터는 `_parse_letters` 에
본문 종료 조건이 없어 트레일러가 발행 문단이 되고, 팟캐스트는
`strip_code_fence` 결과가 그대로 ElevenLabs 로 가서 소리 내어 읽는다.
`common/text_utils.py` 에 `extract_fact_ids()` 를 넣고 소비 지점 5곳을
정리했다(`_parse_letters` 가 mustknow_auto·frontpage_auto 두 곳에 복사돼 있다).

### 4. 레포 편입

`docs/README.md` 배치 규칙에 맞춰 나눴다.

| 옮긴 것 | 간 곳 | 근거 |
|---|---|---|
| 스펙 6종 | `docs/product/4format-pipeline/` | "날짜 없이 주제명, 계속 참조되는 정본" |
| 작업 지시서 | `docs/worklog/2026-08/2026-08-20-...md` | "날짜가 붙은 계획 산출물은 전부 worklog" |

## 결정

- **`docs/prompts/` 같은 최상위 폴더를 새로 만들지 않았다.** `docs/README.md`
  가 "최상위 폴더 7개, 각각 서로 겹치지 않는 질문 하나씩"으로 못 박아서,
  `product/` 하위로 넣었다. `4format-persona-system.md`(왜 이 형태인가)와
  나란히 놓이는 게 맞기도 하다 — 이건 "무엇을 어떻게".
- **뉴스웹툰_파이프라인의 `.py` 6종은 옮기지 않았다.** `pipelines/webtoon/`
  과 대조해보니 4개는 동일하고 `pipeline.py`(237줄)·`prompts.py`(170줄)는
  다르다 — 마스터DB 사본이 **2026-08-23 Bedrock 이관 전 버전**이다. 살아있는
  코드 옆에 낡은 사본을 두면 나중에 누가 틀린 쪽을 고친다. README 만
  `archive/` 로 옮기고 경고를 붙였다.
- **재구성본을 원본인 척 두지 않았다.** 두 문서 다 맨 위에 재구성 배너,
  맨 아래 근거표. 원본이 나오면 원본이 정본이다.
- `00_CONTEXT`·`01_COMMON` 은 **복원하지 않았다.** 02·07 과 달리 내용을
  추정할 근거가 없다. 지금은 네 포맷이 전부 "01_COMMON 준수"를 전제하는데
  그 문서를 아무도 읽을 수 없는 상태 — 마스터DB 회수가 맞다.

3. 0단계(facts.json 생성)를 파이프라인에 실제로 연결. 지금은 각 포맷이 원문을
   따로 받아서, 네 포맷이 같은 사실을 담는다는 보장이 없다.
4. 07_VERIFY 를 게이트로 붙이기. C1~C5(기계 검사)는 LLM 없이 코드로 가능하다.
