# 타임머신 신문 자료 사전 수집 및 빠른 표시 계획

**목표:** 기존 사진·기사와 새로 확인한 자료를 날짜별로 정리하고, 빅카인즈 과거 자료를 제한된 양씩 수집해 날짜 선택 시 빠르게 표시한다.

**기준:** 2026-11-09 사용자 요청과 이 대화. 네이버 기존 수집분은 활용하고 추가 자동 수집은 끈다. 사용자가 이후 배포를 요청했다. 실행 결과는 아래 운영 상태와 worklog를 따른다.

## 계획 작성 당시 확인된 구조와 한계

- `timemachine-data/collect/availability.py`는 S3 이미지와 네이버 인덱스를 확인한다. 빅카인즈와 e-Paper 기사 기록은 현황에 포함하지 않는다.
- `BirthdayAvailability.tsx`는 사진 현황 연도 파일을 읽고, 기사와 대체 날짜는 `loadFrontScene`을 통해 조회한다. 사진 판정은 먼저 보여줄 수 있으나 기사 조회는 캐시가 없으면 빅카인즈 응답을 기다린다.
- 빅카인즈 응답은 `service/backend/handlers/timeline/time_machine.py`의 DynamoDB 캐시에 저장된다. 캐시된 결과가 모두 해당 날짜의 원본은 아니다: 다른 날짜로 대체한 결과도 있으므로 요청 날짜와 표시 날짜를 반드시 구분한다.
- e-Paper JSON은 기사 제목·위치 등을 담지만 기사 원문 링크로 변환 가능한지는 미확인이다. 현황에는 기록 보유 여부를 별도 표시하고 화면용 1면 기사로 무조건 간주하지 않는다.
- 계획 작성 당시 운영 AWS 직접 연결에 실패했다. 이후 확인·배포 결과는 아래 운영 상태와 worklog에 기록했다.

## 데이터 구조와 판정

- 기존 `availability/v1/YYYY.json`은 호환성을 유지한다. 신규 `availability/v2/YYYY.json`은 날짜별로 사진, 빅카인즈 1면, 빅카인즈 그날 기사, 네이버 1면, e-Paper 기록의 상태를 각각 `available`, `unavailable`, `unknown`으로 둔다. 출처별 확인 시각과 유효기간을 기록한다. 요약만 저장하고 기사 본문·이미지 자체는 담지 않는다.
- `unavailable`은 해당 출처의 조회 성공과 0건 등 부재가 확인된 경우만 기록한다. 오류·미조회·면 번호가 없어 판별할 수 없는 경우는 `unknown`이다. 날짜별 현황과 대체 신문 날짜를 구분한다.
- 기사 결과는 기존 응답 계약과 링크를 보존하는 버전별 날짜 파일에 분리한다. 공개 S3에 빅카인즈 원문을 넣기 전 API 이용 조건 및 저장·공개 권한을 확인한다. 허용 범위가 불명확하면 기존 비공개 DynamoDB 캐시만 사용하고 공개 파일에는 보유 상태만 기록한다.
- 대체 결과는 요청 날짜, 실제 표시 날짜, 사유를 함께 저장한다. 이 결과만으로 요청일에 기사가 있다고 기록하지 않는다. 발행 중단·일요일·미래 날짜·면 번호가 없는 기간의 규칙을 기존 구현과 일치시킨다.

## 작업 1: 보유 자료와 기존 캐시 정리

**대상:** `timemachine-data/collect/availability.py`, `timemachine-data/collect/daily_handler.py`, 신규 현황 변환 모듈, `service/backend/handlers/timeline/time_machine.py`.

- [ ] S3의 `img/YYYY/MM/YYYYMMDD.jpg`, `epaper/YYYY/MM/YYYYMMDD.json`, 기존 네이버 `index/v1/YYYY.json`을 날짜별로 검증해 v2 현황을 작성한다. 잘못된 키와 읽기 실패는 부재로 기록하지 않는다.
- [ ] DynamoDB의 기존 타임머신 캐시를 페이지 단위로 읽는 재개 가능한 일회성 도구를 만든다. 만료 여부, 결과 종류, 요청일과 표시일을 검사해 확인 가능한 사실만 반영한다. 기존 캐시에서 이미 대체된 날짜의 부재를 추측하지 않는다.
- [ ] 빅카인즈의 기존 정적 `front_page_calendar.json`은 확인 구간과 unknown 목록을 검증한 뒤 별도 출처로 가져온다. 기사 내용은 이 파일에 없음을 유지한다.
- [ ] 날짜 중복, 조건부 쓰기 충돌과 중단 후 재시작을 처리한다. 기존 v1 파일과 원본 데이터는 유지한다.

## 작업 2: 빅카인즈 단계적 수집

**대상:** `service/backend/services/timeline/bigkinds_search.py`, `service/backend/handlers/timeline/time_machine.py`, 신규 배치 작업 및 AWS 설정.

- [ ] 먼저 빅카인즈 API의 호출 한도, 기사 저장·공개 조건, 기존 운영 키의 사용량과 S3/DynamoDB 비용을 확인한다. 확인 전에는 대량 조회를 실행하지 않는다.
- [ ] 미확인 날짜를 체크포인트에 기록하고, 1면 구분이 가능한 기간과 그날 기사만 가능한 기간을 기존 `FRONT_PAGE_ERAS` 기준으로 처리한다. 조회 성공·0건·오류를 구분하고 기사와 현황을 각각 저장한다.
- [ ] 초기 설정은 하루 최대 50개 날짜, 동시 요청 1개, 요청 간 최소 1초로 시작한다. 날짜당 실제 API 호출 수를 별도로 세고 확인된 API 한도가 더 엄격하면 그 한도를 우선한다. 이는 초기 설정이지 공급자 허용량을 확인한 값이 아니다.
- [ ] 429·403 및 한도 초과는 즉시 중단하고 다음 실행에서 재개한다. 일시 오류는 지수 대기 후 최대 3회 시도하고 실패 날짜는 `unknown`으로 남긴다. 진행량·호출 수·실패 수·마지막 성공 시각을 기록한다.
- [ ] 기존 사용자 조회가 성공하면 동일한 저장 경로에 결과를 반영한다. 저장 실패가 조회 응답을 막지 않도록 하며 중복 쓰기를 안전하게 처리한다.

## 작업 3: 매일 갱신과 사진 속도

**대상:** `timemachine-data/collect/daily_handler.py`, `timemachine-data/collect/lambda_handler.py`, `service/frontend/src/features/news-feed/components/birthday/BirthdayAvailability.tsx`, `BirthdayFrontPage.tsx`.

- [ ] 기존 e-Paper 수집 이후 사진과 기록을 현황에 반영하고, 최근 30일 빅카인즈의 미확인·임시 결과를 정해진 일일 호출 예산 안에서 다시 확인한다. 과거 S3 이미지 추가분도 기존 전체 연도 대조에 반영한다.
- [ ] 연도 현황은 브라우저에서 재사용하고 날짜 선택 즉시 사진 상태를 표시한다. 기사 조회는 독립적으로 진행해 사진 상태를 지연시키지 않는다. 실패·미확인은 실제 부재와 구분해 표시한다.
- [ ] 원본을 유지하면서 표시용 축소 이미지를 별도 키에 생성하고, 결과 화면에서 축소본을 먼저 보여준다. 확대 시 원본을 불러오고 축소본이 없으면 원본으로 대체한다. 포맷·크기·캐시 정책은 실제 원본 표본과 모바일 화면에서 품질 및 전송량을 측정해 결정한다.
- [ ] 선택일과 가까운 날짜의 현황 및 이미지는 제한적으로 미리 받되, 빠른 다이얼 조작에서 불필요한 다운로드와 이전 응답의 덮어쓰기를 막는다.
- [ ] S3 현황과 브라우저 캐시의 갱신 시점을 명시하고, 새로 업로드된 사진이 오래된 `unavailable` 때문에 계속 숨겨지지 않도록 갱신·만료 정책을 적용한다.

## 작업 4: 검증과 운영 준비

- [ ] 성공·0건·오류·타임아웃·429, 면 정보 없음, 일요일 대체, 날짜 변경 중 응답 역전, 오래된 캐시와 새 사진 업로드를 자동 검사한다.
- [ ] 기존 네이버 저장분이 보이고 네이버 신규 요청은 발생하지 않는지, e-Paper 기록이 기사 링크로 잘못 표시되지 않는지 확인한다.
- [ ] 로컬 또는 격리된 환경에서 사진 상태 표시와 기사 표시를 각각 측정한다. 캐시 적중·미적중, 전송량, 오류율 및 대량 날짜 전환을 비교한다. 속도 개선은 실측 결과로 보고한다.
- [ ] 운영 배포 전 Lambda·EventBridge 활성 상태, 권한, 알람 전달 경로, 실제 수집 범위와 기존 객체를 확인한다. 신규 AWS 리소스가 필요하면 `Service=lens`를 생성 시 태그하고 재조회한다.
- [ ] 배포·백필 실행은 사용자의 배포 지시 이후 수행한다. 먼저 소량 실행해 결과·비용·호출량을 확인한 후 일일 배치를 켠다. 실패 시 배치를 끄고 기존 조회 경로로 되돌릴 수 있게 한다.

- EventBridge `sedaily-lens-timemachine-newspaper-daily-hourly`: ENABLED, `cron(25 * * * ? *)`(매시간 25분).
- EventBridge `sedaily-lens-timemachine-newspaper-capture-hourly`: ENABLED, `cron(10 4-6 * * ? *)`(KST 13:10·14:10·15:10).

- 빅카인즈 FAQ는 기사 다운로드 본문의 제공 제한 및 기사 본문 인용에 관한 조건을 설명한다. 이 설명만으로 서울경제의 별도 계약과 API 응답의 저장·공개 권한이나 호출 한도를 확정할 수 없으므로 확인 전 공개 S3에 본문을 복제하지 않는다: https://www.bigkinds.or.kr/news/faqList.do
