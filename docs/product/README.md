# product — 프로덕트 정의

"서비스가 무엇을 해야 하는가, 왜 이렇게 만들었는가"를 담는다.
`architecture/`가 "지금 어떻게 동작하는가"(엔지니어 관점)라면, 여기는
"왜 이런 선택을 했는가"(기획 관점)다. 콘텐츠 **품질을 어떻게 재는가**는
성격이 달라서 `evaluation/`으로 따로 뺐다(2026-08-22) — 여기는 순수
제품 정의만.

## 규칙

- 날짜 없이 주제명으로 — 계속 참조되는 정본이라 "언제 쓴 글"보다 "지금
  맞는 정의"가 중요하다.
- 특정 시점에 확정된 설계 산출물(리포트 PDF 등 — "그날 결정된 것"에
  가까운 문서)은 여기가 아니라 `worklog/YYYY-MM/YYYY-MM-DD-주제.md`가
  맞는 자리. 예: 뉴스 선별 파이프라인 설계 리포트는
  `worklog/2026-08/2026-08-22-news-selection-pipeline-design.pdf`에 있다.
- 서비스 방향이 바뀌어 문서 내용이 안 맞게 되면 `architecture/`와 같은
  규칙 — 지우지 말고 경고 붙여서 `archive/`로.
