# 모아쓰기 레터 자동 발행 설계 (2026-10-11)

## 1. 목표와 원칙
- 목표: 사람 개입 없이 매일 모아쓰기 레터를 생성·검증·발행하고, 구독한 에디터의 구독자에게 발송한다
- 원칙 1: 완전 자동이되, **모든 검증을 통과한 것만** 발행한다. 막히면 발행하지 않고 사유를 남긴다(보류)
- 원칙 2: 서울경제 기사 안에서만, 기사에 있는 사실만 쓴다(지어내기 금지). 검증을 모델 한 번에 맡기지 않는다
- 원칙 3: 중립 원칙은 기존 서버 발행 규칙(금지어, 투표, 출처·인라인 링크)이 마지막 관문이다
- 원칙 4: 발행 상한과 안전 스위치를 둔다(하루 최대 편수, 환경변수로 즉시 정지)

## 2. 파이프라인
| 단계 | 동작 | 막히면 |
|---|---|---|
| 1. 기사 수집 | 최근 N일의 서울경제 기사(S3 일일 XML)를 읽는다 | 기사 없음 → 종료 |
| 2. 이슈 묶기 | 제목·리드로 같은 사안을 다룬 기사끼리 묶는다(모델). 3건 이상 묶이는 이슈만 후보. 이미 레터로 쓴 사안과 겹치면 제외 | 후보 없음 → 그날 발행 없음 |
| 3. 이슈 선정 | 후보 중 가장 큰 이슈 1개(하루 편수 상한 이내). 정치·젠더·세대·지역 갈등 소지가 큰 소재는 제외 | 선정 없음 → 종료 |
| 4. 후보 확보 | 묶음의 기사를 보관 기사로 저장 | 3건 미만 → 중단 |
| 5. 초안 생성 | 프롬프트 v2 + 주제 사전 + 에디터 목록으로 JSON 생성(`lens-letters-opus-5`, 기존 비용 태그 프로파일) | 형식 오류 시 1회 재시도, 이후 중단 |
| 6. 서버 저장·검증 | 기존 저장 API가 형식·출처·중립 규칙을 검증한다 | 위반 → 사유 기록, 최대 2회 수정 재생성 후 중단 |
| 7. 사실 대조 | 별도 호출로 초안의 숫자·인용·고유명사를 기사 본문과 대조한다. 기사에 없는 값이 하나라도 있으면 보류 | 불일치 → 보류 |
| 8. 발행·발송 | 검수 요청 → 발행(서버가 구독한 에디터 구독자에게 자동 발송) | 실패 → 기록 |

## 3. 안전장치
- 하루 최대 발행 수(기본 1편), 시각 창(KST 06~18시) 밖에는 발행하지 않는다
- 스위치: `ISSUELETTER_AUTO=1` 일 때만 실제 발행. 아니면 초안 저장까지만(드라이런)
- 모든 실행은 `issue_letter_auto_runs`(DDB 또는 CloudWatch 로그)에 단계별 결과를 남긴다
- 같은 이슈를 다시 쓰지 않도록, 사용한 기사 번호를 기록하고 겹치면 제외한다
- 보류·중단은 CloudWatch 알람 + 관리자 화면 "자동 발행 보류 목록"에서 확인한다

## 4. 구현 위치
- `pipelines/issueletter_auto/` : `run.py`(엔트리), `cluster.py`(이슈 묶기), `draft.py`(초안 생성·재시도), `verify.py`(사실 대조), 프롬프트 파일
- 재사용: `pipelines/discovery`(기사 수집), `pipelines/common/bedrock_client.py`, `lens_cms_client.py`
- 서버(`lens-cms-api`): 저장·검증·발행·발송(이미 구현). 자동 발행용 토큰 경로는 기존 내부 토큰 사용
- 배포: 기존 `mustknow_auto`와 같은 ECS 태스크 + EventBridge 구조(승인 후 생성)

## 5. 승인이 필요한 일(실행 전 확인)
1. ECS 태스크 정의, EventBridge 규칙, IAM 정책 생성 (AWS 리소스 생성)
2. `ISSUELETTER_AUTO=1` 켜기(실제 발행)
3. 운영 DB에서 에디터 시드 입력과 DDL v1.45

## 6. 위험과 완화
| 위험 | 완화 |
|---|---|
| 지어낸 숫자·인용 | 7단계 사실 대조 + 서버의 출처·링크 규칙. 불일치 시 보류 |
| 논란 소재 발행 | 3단계 제외 규칙 + 서버 금지어 규칙. 정치·젠더·세대·지역 갈등 소지 소재는 선정에서 제외 |
| 같은 이슈 반복 | 사용 기사 기록으로 중복 제외 |
| 잘못된 에디터 지정 | 에디터 담당 분야와 레터 주제의 겹침으로 지정, 겹침이 없으면 보류 |
| 비용 증가 | 하루 편수 상한, 재시도 횟수 상한, 호출 수와 토큰 로그 |
| 모델 오작동 | 스위치로 즉시 정지, 검증 통과율을 매주 점검 |
