# 페르소나 찾아가는 온보딩 설계 (2026-10-12)

기반: `에디터_개인화_기획.md`(상황·과업 틀), 홍예린 페르소나 제안서(2026-10-08), `구독_UX_행동정의.md`

## 1. 문제 정의
- 제안서의 페르소나는 "독자가 자기 유형을 아는 것"이 전제. 실제 독자는 입장 시점에 자기 상황을 말하지 않음
- 현재 온보딩은 구독 다이얼로그 안에만 있음 → 구독하지 않는 독자는 개인화 신호가 0
- 질문으로 묻기 전에, 행동(읽기·저장·팔로우)에서 먼저 추정하고 확인만 받는 구조가 필요

## 2. 원칙
1. 묻기보다 관찰: 행동 신호 먼저, 질문은 마지막
2. 추정은 독자에게 보여주고 고치게 함("이런 레터를 보여드려요 · 바꾸기")
3. 이유는 사실만(관심 주제 겹침, 팔로우한 에디터). "당신은 ~한 사람" 단정 금지
4. 직업·소득·직무 수집 금지, 응답 없어도 동일 서비스(PIPA 최소수집)
5. 정치·논란성 주제는 개인화 제외, 일부 고정 편성은 시작값 20~30%(가설)

## 3. 단계 (점진적 프로파일링)
| 단계 | 시점 | 신호 | 화면 | 저장 |
|---|---|---|---|---|
| 0 | 첫 방문 | 없음 | 전체 최신순 | 없음 |
| 1 | 레터 2편 읽음 또는 저장 1회 | 읽은 주제·에디터 | 목록 상단 한 줄 제안: "금리·부동산 레터를 자주 보셨어요. 관련 에디터 팔로우할까요?" | localStorage |
| 2 | 팔로우 1명 이상 | 팔로우 에디터 | 카드에 "팔로우한 ○○ 에디터가 쓴 레터예요" (적용됨) | localStorage, 구독 시 서버 |
| 3 | 구독 다이얼로그 | 상황 1개·과업 복수(건너뛰기 가능) | 기존 SITUATIONS 6·NEEDS 4 | 서버 reason_text |
| 4 | 구독 후 30일 | 클릭·열람 패턴 | 월 1회 "받는 주제 점검" 메일 한 줄 | 서버 |

## 4. 진입점
| 위치 | 문구(안) | 단계 |
|---|---|---|
| 목록 상단 제안 줄 | "자주 보신 주제 ○○ · 에디터 보기" | 1 |
| 상세 하단 | "이 레터를 쓴 ○○ 에디터 팔로우" | 1→2 |
| 구독 다이얼로그 | 상황·과업 칩 | 3 |
| 메일 하단 | "받는 주제 바꾸기" | 4 |

## 5. 데이터
| 항목 | 위치 | 비고 |
|---|---|---|
| 팔로우 에디터 | localStorage `lens-letter-editors` | 구현됨 |
| 관심 주제·이유 | 서버 interests(`reason_text`) | 구현됨 |
| 읽음·저장 | localStorage 책장 | 구현됨 |
| 상황·과업 | 구독 시 서버 | 구현됨(구독 경로) |
| 추정 신호(읽은 주제 집계) | 클라이언트 계산, 저장 안 함 | 단계 1 신규 |

## 6. 측정
| 이벤트 | 파라미터 | 목적 |
|---|---|---|
| letter_card_click | slug, position, reason_type(none/followed_editor/interest_topic), followed_count, surface | 이유 표시가 클릭에 주는 영향 |
| letter_sub_* | 기존 | 구독 퍼널 |
| (예정) onboarding_suggest_shown/accepted/dismissed | step | 단계 1 제안 수용률 |

## 7. 가설과 반증 기준
| 가설 | 반증 기준 |
|---|---|
| H1 이유가 붙은 카드의 클릭률이 이유 없는 카드보다 높다 | 2주 후 reason_type 간 CTR 차이가 없거나 낮음 → 이유 문구 폐기 |
| H2 단계 1 제안 수용률 10% 이상 | 5% 미만 → 제안 위치·문구 변경 또는 폐기 |
| H3 팔로우한 독자의 7일 재방문율이 미팔로우보다 높다 | 차이 없음 → 팔로우를 핵심 목표로 두지 않음 |
| 위험: 필터 버블 | 팔로우 카드 외 레터 클릭 비중이 급감하면 고정 편성 비율 상향 |

수치는 현재 사이트 트래픽이 작아 방향 확인용. 통계적 확정은 불가(미확인).

## 8. 구현 순서
1. 완료: 카드 이유(팔로우 에디터) 표시, letter_card_click 측정
2. 단계 1 제안 줄(읽음 집계 → 에디터 제안) — 결정 후 착수
3. 제안서 B(이 일이 닿는 사람 필드), C(관심사 추가 제안) — 에디터 방식으로 대체 매핑 합의 후
