# 레터 북마크 — 로그인 필수·계정 저장과 대시보드 연결

기준일: 2026-10-14. **로그인한 계정만 레터를 저장·해제할 수 있도록 로컬 구현했다.** 목록·상세·나의 LENS는 같은 계정 API를 사용한다. 운영 DB 마이그레이션·API Gateway 연결·배포는 수행하지 않았다.

이 문서는 이전 브라우저 저장 허용·slug 기반 API 제안을 현재 구현으로 교체한다. [계정 저장 구현 상태](../나의LENS/계정저장_구현상태.md), [백엔드 리뷰 보완](../나의LENS/백엔드_리뷰_보완.md)을 함께 따른다.

## 사용자 흐름과 정책

1. 공개 레터 목록·본문은 로그인 없이 읽을 수 있다.
2. 비로그인 상태에서 북마크를 누르면 ‘로그인이 필요해요’ 안내를 연다. 신규 저장·해제 요청과 브라우저 북마크 쓰기는 실행하지 않는다. 안내를 닫으면 기존 화면과 저장 상태를 유지한다.
3. ‘로그인하기’는 기존 `/login`을 사용한다. 현재 pathname·query·hash를 안전한 내부 복귀 주소로 기억한다. 기존 이메일 로그인·소셜 콜백의 복귀 처리를 재사용한다.
4. 로그인 후 원래 화면으로 돌아오면 저장 버튼을 다시 눌러야 한다. 로그인만으로 저장하거나 이전 클릭을 자동 실행하지 않는다.
5. 로그인 계정은 공개 API의 Cognito ID token 검증을 거쳐 서버에 저장한다. 저장 성공이 확정된 뒤 목록·상세·대시보드의 북마크 상태를 재조회한다. 실패를 브라우저 저장으로 대체하지 않는다.
6. 나의 LENS 홈의 ‘다시 펼쳐볼 레터’와 ‘내 서랍 → 저장한 레터’에서 같은 계정 북마크를 표시하고 해제할 수 있다. 서버가 반환한 최근 저장순을 유지하며 홈은 처음 3편과 펼치기를 제공한다.
7. 계정 변경·로그아웃 때 이전 계정 자료를 숨기고 요청을 취소한다. 401·세션 없음이면 다시 로그인하도록 안내하며 대시보드는 개인 화면을 내린다.

레터 저장의 로그인 필수 정책은 나의 LENS 진입 제한과 별도로 저장 훅에서도 검사한다. 공개 콘텐츠 열람·메일 구독·글자 크기·브라우저 읽음 표시에는 새 로그인 제한을 확대하지 않는다.

## 기존 브라우저 데이터 보존

| 데이터 | 현재 처리 |
|---|---|
| `lens-letter-saved` | 기존 slug 배열을 삭제하거나 덮어쓰지 않는다. 비로그인 공개 레터 목록에서 기존 저장 상태와 저장 필터를 조회할 수 있다. 저장·해제 클릭은 로그인 안내만 연다. |
| 로그인 계정 북마크 | 서버 `user_letter_bookmarks`만 읽고 쓴다. 기존 공용 브라우저 키를 A/B 계정 캐시로 사용하지 않는다. |
| `lens-letter-read` | 비로그인 브라우저 읽음 표시를 유지한다. 로그인 상태에서는 `lens-letter-read:account:SUB`를 사용한다. 서버 완료·보상 기록과 별개다. |
| `lens-letter-font` | 기존 글자 크기 설정을 유지한다. |

**사용자 선택 북마크 가져오기를 로컬 구현했다.** 자동 업로드·삭제를 하지 않는다. 내 서랍에서 사용자가 체크한 목록만 `/api/v2/me/imports/bookmarks`로 반영하며 원본을 보존한다. 계정별 선택 목록 처리 이력으로 같은 목록 재시도 시 이후 해제 항목이 복원되지 않게 한다. v1.54에서는 UUID별 입력을 묶고, 응답 손실 후 같은 UUID로 재시도한다. 새 UUID의 명시 재요청은 이전 거부 항목만 현재 공개 상태로 재검사한다. 상세 계약은 [형식 선호·계정 연결](../나의LENS/형식선호·계정연결_구현상태.md)을 따른다.

## 현재 공개 API 계약

기존 `API_URL` origin의 공개 handler → 내부 CMS FastAPI → PostgreSQL 구조를 따른다. 프론트는 기존 `authFetch`로 Cognito ID token을 보낸다. 계정 owner는 검증된 `sub`이며 body/query의 user_id나 `X-Voter-Id`로 지정할 수 없다. 개인 응답은 `Cache-Control: private, no-store`다.

| API | 현재 역할 |
|---|---|
| GET `/api/v2/me/letter-bookmarks` | 현재 계정의 목록. limit 1~200, cursor 페이지네이션, 제목 검색 q. read=all/unread/completed를 지원하며 서버 완료 기록을 기준으로 한다. `items`, `count`, `total`, `next_cursor` 반환. 프론트는 cursor를 끝까지 조회한다. |
| GET `/api/v2/me/content/resolve?kind=issue_letter&key_type=slug&key=…` | UI slug를 stable ID와 정식 주소로 해석한다. 숫자 slug도 ID로 추정하지 않는다. |
| PUT `/api/v2/me/letter-bookmarks/{letter_id}` | stable issue_letter ID로 저장 상태를 지정한다. 반복 PUT은 중복 생성·saved_at 변경 없이 성공한다. |
| DELETE `/api/v2/me/letter-bookmarks/{letter_id}` | 본인 저장을 해제한다. 이미 해제된 경우도 성공한다. 비공개 저장 항목은 보유 ID로 해제할 수 있다. |

목록 예시:

```json
{
  "items": [{
    "letter_id": "42",
    "saved_at": "2026-10-14T03:00:00+00:00",
    "version": 1,
    "content": {
      "content_key": "issue_letter:42",
      "kind": "issue_letter",
      "available": true,
      "completed": false,
      "slug": "example-letter",
      "title": "예시 레터",
      "summary": "예시 요약",
      "read_minutes": 3,
      "published_at": "2026-10-14T00:00:00+00:00",
      "href": "/letter/example-letter",
      "categories": ["finance"]
    }
  }],
  "count": 1,
  "total": 1,
  "next_cursor": null
}
```

PUT/DELETE 응답은 `letter_id`, `saved`, `saved_at`, `version`이다. 인증 없음·유효하지 않은 토큰은 401, 계정 이용 불가는 403, 잘못된 ID/cursor는 400이다. 서버 장애는 실패로 표시하고 기존 저장 상태를 유지한다. 저장 가능한 원문은 발행 시각이 도래한 공개·미삭제 레터다. 기존 저장 원문이 비공개·soft delete되면 제목·본문 대신 `available:false`를 반환한다. hard delete는 FK CASCADE로 북마크도 제거한다.

## DB와 인증 경계

신규 테이블의 정본은 `docs/architecture/lens-erd-src/lens_schema_v1.48_2026-10-14.sql`이다. 이번 로그인 UI 수정은 새 SQL을 추가하지 않는다.

- `user_letter_bookmarks`: `user_id VARCHAR(64)`, `issue_letter_id BIGINT`, `saved_at TIMESTAMPTZ`, `version BIGINT`.
- 복합 PK `(user_id, issue_letter_id)`, users/issue_letters FK, 계정별 최근 저장순 인덱스.
- slug는 화면 주소이며 저장 정본은 안정적인 issue_letter ID다.
- 내부 `/internal/personal/lens/*` 호출은 `X-Internal-Token` 필수다. 브라우저에 내부 토큰·DB 접속 정보를 넣지 않는다.
- 기존 문장 서랍 `user_archives`와 공개 기기 관심 API는 레터 북마크 저장소·인증 수단으로 사용하지 않는다.

## UI 표시와 갱신

- 비로그인: ‘레터를 저장하려면 로그인해 주세요.’ 기존 저장이 있으면 조회만 가능하고 계정 저장과 별개임을 덧붙인다.
- 로그인: 계정 저장 안내와 기존 브라우저 북마크 자동 병합 없음 안내.
- 변경 중: 진행 상태를 표시하고 같은 항목의 중복 저장 요청을 막는다.
- 실패: 오류·다시 불러오기를 제공하며 서버 성공 전 저장 성공·저장 분석 이벤트를 표시하지 않는다.
- 비공개 원문: 이용 불가 안내와 ID 기반 해제 버튼을 제공한다.
- 저장 확정: `lens-account-bookmarks-changed` 이벤트로 같은 화면 훅과 홈 집계를 갱신한다. 다른 탭은 revision storage 이벤트, 포커스 복귀·pageshow에서 서버 상태를 다시 읽는다. 실시간 기기 간 push 동기화를 제공한다고 표현하지 않는다.

## 운영 반영 전 남은 범위

- v1.48 이후 대시보드 SQL의 적용 순서·실제 기존 스키마·DB 역할 권한 인수.
- 내부 CMS 및 공개 Lambda/API Gateway의 신규 계정 경로 연결 후 프론트 전환.
- 실제 Cognito 로그인·만료·두 기기 계정 조회 인수. 현재 로컬 검증은 합성 계정·로컬 서명키와 격리 DB를 사용한다.
- 선택적 북마크 가져오기·서버 완료 읽음 필터는 로컬 구현했다. 기존 브라우저 자료가 자동으로 계정 자료가 되는 것은 아니다.

운영 DB 변경·배포·실제 알림 발송은 이 작업 범위에 포함하지 않는다.
