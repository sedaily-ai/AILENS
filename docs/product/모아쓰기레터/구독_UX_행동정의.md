# 레터 메일 구독 — 사용자 행동 정의 (2026-10-11)

## 1. 목적과 원칙
- 목적: 관심 에디터의 새 레터를 메일로 받게 하되, 신청 단계에서 이탈하지 않고 신뢰를 잃지 않는 것
- 원칙 1: 입력은 이메일 하나가 핵심. 주기·시각은 기본값(매일, 오전 8시)이 있어 건드리지 않아도 신청 가능
- 원칙 2: 동의는 미리 체크하지 않음. 거부해도 레터 읽기에는 제약 없음
- 원칙 3: 약속을 신청 화면에 먼저 보임 — 구독한 에디터의 레터가 올라올 때만, 한 통에 한 편, 언제든 수신거부
- 원칙 4: 신청 직후 "메일 확인"까지 안내. 확인 전에는 아무 메일도 보내지 않음
- 원칙 5: 어두운 패턴 금지 — 숨은 체크, 수신거부 방해, 반복 팝업 없음

## 2. 사용자 유형과 진입
| 유형 | 상태 | 진입 경로 | 기대 행동 |
|---|---|---|---|
| 처음 방문자 | 에디터를 모름 | 레터 탭 → 에디터 선택줄 | 에디터를 눌러 소개를 보고 판단 |
| 관심 있는 독자 | 에디터를 정함 | 소개 카드의 "메일로 구독" | 이메일 입력 → 신청 |
| 여러 에디터 팔로우 독자 | 팔로우 2명 이상 | "내 에디터" 바의 "메일로 받기" | 한 번에 합쳐 구독 |
| 메일 수신 독자 | 구독 중 | 메일의 "신청 확인하기" / "수신거부" | 확인 또는 해지 |

## 3. 신청 흐름 (정상)
| 단계 | 사용자 행동 | 화면 반응 | 이탈 방지 장치 |
|---|---|---|---|
| 1. 시작 | "메일로 구독" 클릭 | 중앙 대화상자, 이메일 입력칸에 자동 포커스 | 대화상자라 목록 위치를 잃지 않음, Esc·배경·× 로 즉시 닫기 |
| 2. 이해 | 약속 3줄 확인 | 담당 분야를 한 줄로 안내 | 무엇을 받는지 먼저 보임 |
| 3. 입력 | 이메일 입력 | 칸을 벗어날 때만 형식 오류 표시(입력 중에는 경고 없음) | 입력 중 오류로 방해하지 않음 |
| 4. 선택(선택 사항) | 주기(매일/매주 월요일), 시각(오전 8시/낮 12시/오후 6시) | 큰 터치 영역의 선택 버튼 | 기본값 있음, 드롭다운 없음 |
| 5. 동의 | 필수 동의 체크 | "자세히"로 수집 항목·목적을 펼침 | 한 줄 요약 + 필요할 때만 상세 |
| 6. 제출 | "구독 신청하기" | 이메일 형식 + 동의가 충족될 때만 활성, 제출 중 "신청하는 중…" | 중복 클릭 방지 |
| 7. 완료 | — | "확인 메일을 보냈어요" + 3단계(메일 열기 → 신청 확인하기 → 끝) + 스팸함 안내 | 다음 행동을 명확히 |
| 8. 확인 | 메일의 "신청 확인하기" | 확인 페이지 "신청이 완료됐어요" (POST로 확정, 스캐너가 눌러도 확정되지 않음) | 48시간 유효 |

## 4. 예외 처리
| 상황 | 반응 |
|---|---|
| 이메일 형식 오류 | 칸 아래 "이메일 주소 형식을 확인해 주세요", 제출 비활성 |
| 동의 미체크 | 제출 비활성, 이메일이 유효하면 "수신 동의에 체크해 주세요" |
| 이미 구독 중인 주소 | 같은 완료 화면(가입 여부를 알리지 않음) |
| 수신거부·반송 이력 주소 | 같은 완료 화면, 메일은 보내지 않음 |
| 10분 안에 같은 주소로 재신청 | 같은 완료 화면, 확인 메일은 다시 보내지 않음 |
| 서버 메일 설정 꺼짐 | "지금은 메일 신청을 받지 않고 있어요"(503) |
| 네트워크 오류 | "네트워크 연결을 확인하고 다시 시도해 주세요" |
| 확인 링크 만료(48시간) | 확인 페이지에서 다시 신청 안내 |

## 5. 수신 이후
- 발송: 겹치는 레터가 있을 때만, 한 통에 한 편, 이미 보낸 레터 제외, 선택한 시각(8~20시)
- 수신거부: 모든 메일의 링크 → 수신거부 페이지에서 즉시 처리(로그인 불필요)
- 재구독: 같은 경로로 다시 신청 가능

## 6. 측정 이벤트 (GA4 커스텀)
| 이벤트 | 시점 | 파라미터 |
|---|---|---|
| letter_sub_open | 대화상자 열림 | source(editor:{id} / bar) |
| letter_sub_submit | 제출 클릭 | source, frequency, hour |
| letter_sub_requested | 서버 접수 성공 | source |
- 퍼널: open → submit → requested → (메일 확인 완료는 서버 구독 상태 active 수로 측정)
- 가설: open 대비 requested 비율 15% 이상이면 입력 단계 마찰이 낮은 것으로 봄(현재 값 없음, 첫 2주 측정 후 보정)

## 7. 화면 규칙 (디자인)
- 주 버튼 색은 사이트 파랑(#2f5fcf)으로 통일(레터 상세의 "받아보기" 버튼과 동일). 검정 버튼 사용 안 함
- 선택 상태: 선택 버튼 파랑 채움, 미선택은 흰색 + 옅은 테두리
- 대화상자: 화면 중앙 정렬(flex), 폭 최대 500px, 모바일은 좌우 16px 여백

## 8. 미확정·확인 필요
- 동의 문구의 법적 검토(수집 항목·목적·보관 기간·거부권 고지)와 개인정보처리방침 레터 메일 항목 — 법무 또는 서울경제 담당 확인 필요
- 반송·신고 자동 수집(SNS → email_suppressions) — 미구현
- 자동 발송 스케줄 — 미구현(수동 실행만)
