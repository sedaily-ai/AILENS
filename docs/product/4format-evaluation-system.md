# AI LENS — 4포맷 품질 평가 시스템

> `letter-evaluation-system.md`가 레터 하나에 대해 하던 것 — N 가상 독자 ×
> rubric → 점수 + 코멘트 — 을 웹툰·팟캐스트·영상에도 각자의 페르소나·rubric으로
> 확장한다. 근거(왜 이 페르소나·왜 이 rubric인가)는 `4format-persona-system.md`를
> 그대로 따른다 — 이 문서는 그 근거를 "측정 가능한 형태"로 바꾼 것이다.

---

## 0. 레터와 다르게 설계한 지점

레터는 5명의 서로 다른 독자가 **같은 텍스트**를 각자 다르게 느끼는지 검증한다.
웹툰·팟캐스트·영상은 애초에 **소비 맥락이 이미 좁게 정의**돼 있어서(이동 중,
스와이프 중, 스크롤 중) 5명씩 넓게 벌릴 필요가 적다. 대신 두 종류를 섞는다:

- **핵심 독자 2명** — 같은 소비 맥락 안에서의 하위 변주(예: 팟캐스트는 "운전
  중"과 "집안일 중"이 둘 다 손이 묶여 있지만 집중도가 다름)
- **이물감 체크 1명** — 그 포맷과 안 맞는 독자를 하나 넣어서 "이 포맷이
  과하게 가볍거나 신뢰를 깎아먹지 않는가"를 검증(레터의 장태원 같은 역할)

그리고 웹툰·영상은 **텍스트가 아니라 이미지/영상**이 실제 산출물이므로, 대본
단계 텍스트만 넣고 평가하면 "스크립트 검수"에 그친다 — 진짜 평가가 되려면
**멀티모달로 실제 생성물(이미지 URL, 영상 프레임)을 직접 보여줘야** 한다.
팟캐스트는 반대로 오디오 자체를 입력할 수 있는 모델이 마땅치 않아 **대본
텍스트 기준 평가로 한계를 인정**한다(§5 한계 참조).

## 1. 웹툰 평가

### 1.1 가상 독자 3명

**재이 — 웹툰 코어 타겟 (핵심)**
```
나이: 29 / 직업: 마케터 / 맥락: 인스타그램 스와이프, 하루 여러 번 자투리 시간
반응: 캐릭터 감정 이입, 대사의 자연스러움 / 약함: 설명충 대사, 정보 나열
"좋다"의 기준: 마지막 컷에서 마음에 한 장면 남고, 캡처해서 보내고 싶음
```

**도현 — 웹툰 비선호 독자 (이물감 체크)**
```
나이: 44 / 직업: 공무원 / 맥락: 뉴스는 텍스트로만 읽어온 사람, 웹툰 형식엔 낯섦
반응: "이게 뉴스야 만화야" 하는 회의 / 약함: 유치해 보이는 연출, 과한 이모지 톤
"좋다"의 기준: 형식은 낯설어도 정보 자체는 신뢰가 감
```

**하은 — 밈 센서 (톤 과잉 체크)**
```
나이: 22 / 직업: 대학생 / 맥락: 밈·유행어에 익숙, 오글거림 감지 민감
반응: 자연스러운 요즘 말투 / 약함: 뉴스가 억지로 웹툰체 흉내내는 어색함
"좋다"의 기준: "이거 진짜 요즘 애들 말투처럼 자연스럽다"
```

### 1.2 Rubric (10항목 × 0~5점)

| # | 항목 | 0점 | 5점 |
|---|---|---|---|
| 1 | 첫 컷 훅 | 그냥 제목 나열 | 스와이프 멈추게 하는 장면 |
| 2 | 대사 자연스러움 | 설명충, 로봇톤 | 실제 대화처럼 들림 |
| 3 | 감정 이입 | 캐릭터가 정보 전달 도구로만 느껴짐 | 캐릭터에 공감됨 |
| 4 | 컷 수·리듬 적정성 | 늘어지거나 급함 | 6~8컷이 딱 맞게 흐름 |
| 5 | 정보 정확성 | 원문 왜곡·과장 | 사실관계 그대로 |
| 6 | 시각적 임팩트 | 밋밋한 구도 | 한 컷이라도 눈에 박힘 |
| 7 | 결말 여운 | 그냥 요약하고 끝 | 마지막 컷이 기억에 남음 |
| 8 | 공유 욕구 | 안 보낼 듯 | 캡처해서 보낼 사람 떠오름 |
| 9 | 신뢰 유지 | 유치해서 뉴스로 안 느껴짐 | 형식은 가벼워도 정보는 신뢰감 |
| 10 | 완독 예상 | 중간에 스와이프 멈출 듯 | 끝까지 넘길 듯 |

### 1.3 입력 방식 — 반드시 멀티모달

```
[각 컷 이미지를 실제 이미지로 첨부] + [컷별 대사 텍스트]
```
스크립트(대사 JSON)만 텍스트로 주고 평가하면 "이미지에 실존 상호명이 그대로
렌더됐다"(라운드1에서 실제 발생) 같은 문제를 절대 못 잡는다 — 이미지 자체를
봐야 하는 평가라 텍스트 전용 모델로는 §5 한계에 해당.

### 1.4 출력 JSON
```json
{
  "reader_id": "jaei",
  "post_slug": "2026-08-11-빵지순례",
  "scores": {"hook":0,"dialogue":0,"empathy":0,"pacing":0,"accuracy":0,
             "visual_impact":0,"ending":0,"shareability":0,"trust":0,"completion":0},
  "total": 0,
  "qual": {
    "did_finish": true,
    "finish_reason": "",
    "most_resonant_cut": "컷 번호 + 대사 인용",
    "awkward_cut": "컷 번호 + 왜 어색한지, 없으면 null",
    "brand_name_leak": "이미지에 실존 상호명이 그대로 보이면 어디에, 없으면 null",
    "would_share": true,
    "verdict_one_line": ""
  }
}
```

## 2. 팟캐스트 평가

### 2.1 가상 독자 3명

**민규 — 운전 중 (핵심)**
```
나이: 38 / 직업: 영업직, 차로 이동 많음 / 맥락: 운전하며 흘려들음, 화면 볼 수 없음
반응: 수치 적고 흐름 명확하면 좋음 / 약함: 숫자 여러 개 연달아 나오면 놓침
"좋다"의 기준: 신호 대기 중 딴생각해도 흐름을 놓치지 않음
```

**소영 — 집안일 중 (핵심, 더 낮은 집중도)**
```
나이: 34 / 직업: 육아휴직 중 / 맥락: 설거지·빨래하며 배경음처럼 들음
반응: 목소리 톤이 편안하면 계속 틀어둠 / 약함: 정보 밀도 높으면 그냥 흘려보냄
"좋다"의 기준: 중간에 놓쳐도 다시 집중했을 때 이어 듣기 쉬움
```

**태호 — 팟캐스트 마니아 (눈높이 체크)**
```
나이: 41 / 직업: 프리랜서, 팟캐스트 다수 구독 / 맥락: 산책하며 진지하게 청취
반응: 자연스러운 진행자 톤 / 약함: 상투적 멘트("여러분", "오늘도 시작해볼까요")
"좋다"의 기준: 실제 방송처럼 자연스럽고 상투적이지 않음
```

### 2.2 Rubric (10항목 × 0~5점)

| # | 항목 | 0점 | 5점 |
|---|---|---|---|
| 1 | 도입 훅 | 첫 10초에 계속 들을 이유 없음 | 바로 궁금해짐 |
| 2 | 청취 편의 | 수치·표가 많아 놓침 | 듣기만 해도 이해됨 |
| 3 | 흐름 유지 | 중간에 놓치면 못 따라옴 | 잠깐 놓쳐도 다시 따라잡기 쉬움 |
| 4 | 톤·친밀감 | "여러분" 등 어색한 직접 호칭 | 자연스러운 대화체 |
| 5 | 길이 적정성 | 너무 길거나 급하게 끝남 | 이동 시간에 딱 맞음 |
| 6 | 정보 정확성 | 원문에 없는 수치·사실 | 원문 그대로 |
| 7 | 리듬·발음(TTS) | 어색한 끊어읽기 | 자연스러운 억양 |
| 8 | 기억에 남는 한 줄 | 다 듣고 뭘 들었는지 기억 안 남 | 한 문장 남음 |
| 9 | 재청취 의향 | 다시 안 들을 듯 | 다시 들을 만함 |
| 10 | 완청 예상 | 중간에 끌 듯 | 끝까지 들을 듯 |

### 2.3 출력 JSON
```json
{
  "reader_id": "minkyu",
  "post_slug": "2026-08-11-빵지순례",
  "scores": {"hook":0,"listenability":0,"flow_recovery":0,"tone":0,"length":0,
             "accuracy":0,"tts_rhythm":0,"memorable_line":0,"relisten":0,"completion":0},
  "total": 0,
  "qual": {
    "did_finish": true,
    "finish_reason": "",
    "lost_track_at": "놓친 지점, 없으면 null",
    "most_resonant_line": "",
    "awkward_part": "",
    "verdict_one_line": ""
  }
}
```

## 3. 영상 평가

### 3.1 가상 독자 3명

**유나 — 숏폼 스크롤 중 (핵심)**
```
나이: 26 / 직업: 콘텐츠 에디터 / 맥락: 릴스 스크롤, 60~120초 소비, 3초 안에 이탈 가능
반응: 임팩트 있는 첫 컷 / 약함: 텍스트 밀도 높은 슬라이드
"좋다"의 기준: 끝까지 보고 "오 신기하네" 하고 다음으로 넘어감
```

**성민 — 무음 시청 (핵심, 다른 소비 조건)**
```
나이: 30 / 직업: 회사원 / 맥락: 지하철·사무실에서 소리 없이 봄, 자막만 의존
반응: 자막·그래픽만으로 이해되면 좋음 / 약함: 나레이션에만 의존하는 정보
"좋다"의 기준: 소리 꺼도 무슨 내용인지 다 이해됨
```

**경아 — 데이터 신뢰 검증형 (이물감/신뢰 체크)**
```
나이: 47 / 직업: 애널리스트 / 맥락: 숫자를 보면 출처부터 의심하는 습관
반응: 수치에 출처 표기 있으면 신뢰 / 약함: 근거 없어 보이는 그래프
"좋다"의 기준: 이 숫자가 어디서 나온 건지 바로 납득됨
```
→ 라운드1의 "지어낸 통계" 문제를 잡아내기 위해 넣은 페르소나. 다른 2명은
   놓칠 수 있는 "이 수치 진짜야?" 반응을 의도적으로 유도한다.

### 3.2 Rubric (10항목 × 0~5점)

| # | 항목 | 0점 | 5점 |
|---|---|---|---|
| 1 | 3초 훅 | 스크롤 멈출 이유 없음 | 바로 시선 붙잡음 |
| 2 | 무음 이해도 | 나레이션 없인 이해 불가 | 자막·그래픽만으로 이해됨 |
| 3 | 데이터 신뢰성 | 근거 없어 보이는 수치 | 원문 근거와 일치, 출처 명확 |
| 4 | 컷 전환 리듬 | 어지럽거나 늘어짐 | 빠르되 자연스러움 |
| 5 | 정보 밀도 | 컷 하나에 정보 과다 | 컷당 메시지 하나 |
| 6 | 비주얼 임팩트 | 밋밋한 그래픽 | 눈에 띄는 시각 표현 |
| 7 | 나레이션 톤 | 기계적, 부자연스러움 | 자연스러운 설명체 |
| 8 | 엔딩·브랜드 각인 | 그냥 끝남 | AILENS가 기억에 남음 |
| 9 | 공유 욕구 | 안 보낼 듯 | 보내고 싶어짐 |
| 10 | 완주 예상 | 중간 이탈할 듯 | 끝까지 볼 듯 |

### 3.3 입력 방식 — 멀티모달(프레임 캡처) 권장

각 컷의 렌더된 프레임 이미지(또는 최소 컷별 스크린샷)를 함께 넣어야 "3번
데이터 신뢰성", "6번 비주얼 임팩트"가 실제로 평가된다. 각본 JSON 텍스트만
주면 "이 수치가 원문에 있었는지"만 기계적으로 대조 가능하고(그 자체로도
유용 — 라운드1 버그는 이 방식만으로도 잡을 수 있었다), 시각 품질은 평가
불가.

### 3.4 출력 JSON
```json
{
  "reader_id": "yuna",
  "post_slug": "2026-08-11-빵지순례",
  "scores": {"hook":0,"muted_clarity":0,"data_trust":0,"pacing":0,"density":0,
             "visual_impact":0,"narration_tone":0,"ending_brand":0,"shareability":0,"completion":0},
  "total": 0,
  "qual": {
    "did_finish": true,
    "muted_understandable": true,
    "stat_trust_flag": "의심되는 컷·수치, 없으면 null",
    "most_resonant_cut": "",
    "awkward_cut": "",
    "verdict_one_line": ""
  }
}
```

## 4. 평가 프롬프트 템플릿 (공통 골격)

```
당신은 [PERSONA_CONTEXT]인 [PERSONA_NAME]입니다.

지금 이 [포맷명]을 봤습니다(또는 들었습니다).

[CONTENT — 텍스트/이미지/프레임을 포맷에 맞게 첨부]

솔직히 반응해주세요. 평가자처럼 객관적으로 점수 주되, 점수보다 "왜 그렇게
느꼈는지"의 한 줄이 더 중요합니다.

다음 JSON으로만 응답: [해당 포맷의 §1.4/2.3/3.4 스키마]
```

레터 문서(§4)와 동일하게, Bedrock Claude Sonnet 계열로 호출한다. 웹툰·영상은
이미지/프레임을 함께 첨부하는 멀티모달 호출이 되므로 호출 비용이 텍스트
전용보다 높다(§5).

## 5. 한계

- **팟캐스트**: 오디오 자체를 입력할 수 있는 평가 모델이 지금 파이프라인에
  없어 **대본 텍스트 기준 평가**로 한정한다. TTS 리듬(항목 7)은 사람이 직접
  들어보고 채점하거나, 향후 오디오 입력 지원 모델로 넘어가야 한다.
- **웹툰·영상**: 멀티모달 호출이라 레터보다 토큰(이미지) 비용이 크다. 라운드마다
  전수 평가하기보다, 프롬프트를 크게 고친 직후에만 돌리는 식으로 아껴 써야 한다.
- 레터와 마찬가지로 **가상 독자는 실제 독자의 근사치일 뿐**이다. 특히 "공유
  욕구", "감정 이입" 같은 항목은 합성 반응이라 표면적일 수 있음 — 실제
  발행 후 GA 지표(웹툰 캡처/공유 클릭, 팟캐스트 완청률, 영상 완주율)와
  주기적으로 대조해야 한다.
- 이 문서는 **설계**다. 레터 쪽 `letter-evaluation-system.md` §6이 설명하는
  `scripts/eval_letters.py`도 실제로는 이 저장소에 커밋된 적이 없다(baseline
  리포트만 남아있음) — 즉 레터도 아직 "매번 자동으로 도는 스크립트"는
  없는 상태다. 이번 라운드에서 3포맷 rubric까지 설계는 끝났으니, 다음은
  4포맷 전체를 한 번에 도는 평가 스크립트를 실제로 만들지 결정하는 것.
