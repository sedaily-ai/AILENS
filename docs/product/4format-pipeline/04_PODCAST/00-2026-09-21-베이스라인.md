# PODCAST — 현재 구조 베이스라인 (2026-09-21)

작성: 문영광 + Claude Code. 코드 직접 대조로 확인 — 갱신 시 이 문서도
같이 고칠 것.

## A to Z — 실제 코드 흐름

```
frontpage_auto/run.py, mustknow_auto/run.py
  └─ publish_utils.publish_article()
       └─ podcast_mod.run_article(name, article_path, out_dir)
            1단계 — 대본
            └─ ddb_prompt.load_prompt("podcast")
            └─ bedrock_client.call_text(guide, "...기사 원문...",
                 model=lens-podcast-sonnet-46) → 대본.md 저장
            2단계 — 음성 합성
            └─ strip_code_fence(대본)
            └─ AWS Polly로 TTS → 팟캐스트.mp3 저장
       └─ podcast_url = S3 업로드
       └─ 청각장애인 접근성용 transcript는 대본.md를 그대로 재사용
```

- 파일: `pipelines/podcast/pipeline.py` (`run_article()`, 95~126행)
- 모델(대본): `arn:...application-inference-profile/kmkagk616y1c`
  (`lens-podcast-sonnet-46`)
- 프롬프트: `podcast/published` — Postgres(lens-cms-api)
- 음성 엔진: **AWS Polly**(2026-08-27 이후 확정). 2026-08-21에
  ElevenLabs로 한 번 바꿨다가, 실사용량(월 565K자) 기준 Polly
  generative 엔진이 약 82% 저렴(월 ~$17 vs ElevenLabs)해서 되돌림. 별도
  API 키 관리도 불필요(Fargate 태스크 IAM 롤 권한만으로 호출) — 부수
  이점(`pipeline.py:8-19`)
- **resume 지원** — `run_article(resume=True)`가 기본값. `대본.md`나
  `팟캐스트.mp3`가 이미 있으면 그 단계는 재실행 없이 재사용(재시도 시
  중복 과금 방지)
- 출력: 별도 파서 없음 — 대본 텍스트를 코드펜스만 벗겨서(`strip_code_fence`)
  그대로 Polly에 넘기고, 그대로 접근성 transcript로도 쓴다. 레터처럼
  `[제목]`/소제목 마커 파싱이 없다 — 팟캐스트는 애초에 소제목 구조가
  아니라 1인 화자 낭독체라 파싱할 대상 자체가 다르다.

## 스펙과의 관계

`README.md`(팟캐스트 스펙)가 요구하는 "수치 3개 이하" 같은 규칙은
프롬프트(`podcast/published`) 안에 있고, 코드 쪽에서 별도로 강제하는
로직은 없다 — 레터의 `[제목]` 파싱처럼 코드가 형식을 검증하는 지점이
없으므로, 프롬프트가 그 규칙을 못 지켜도 코드가 잡아내지 못한다(레터의
`parse_letter_title()` 실패 폴백 같은 안전망이 이 단계엔 없음).
