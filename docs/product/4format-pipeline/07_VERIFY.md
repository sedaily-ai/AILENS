# AILENS 검증 프롬프트 (마지막 단계)

> ⚠️ **이 문서는 원본이 아니라 재구성본이다.** 원본
> `2_ailens/마스터DB/03_개발·프롬프트/4포맷_파이프라인/07_VERIFY.md` 는 로컬·
> AILENS 레포·DDB 어디에도 없다. 작업 지시서가 정의한 기준 한 줄
> ("core 사실이 최소 2개 포맷에 있는가")과 네 포맷 스펙의 체크리스트,
> `docs/product/4format-persona-system.md` 의 사고 기록을 근거로 복원했다.
> 근거는 §7 참조. 원본이 나오면 **원본을 정본으로 삼는다.**

01_COMMON.md의 모든 규칙을 준수한다.

**입력** — 세 가지를 모두 받는다.
1. 기사 원문 (지어낸 사실을 잡으려면 원본이 있어야 한다)
2. 02_EXTRACT의 facts.json
3. 산출된 포맷들 — 레터·웹툰·팟캐스트·영상 각각의 본문과 `fact_ids`

────────────────────────
## 0. 이 단계가 맡는 것
────────────────────────

**사실의 대조.** 4개 포맷이 facts.json을 실제로 담았는가.

- 담는다: 커버리지, 지어낸 사실, 미확정 단정, 주체 누락, 포맷 간 중복
- 담지 않는다: 문체, 재미, 완성도, 공유 욕구

**품질 평가와 혼동하지 않는다.** 둘은 목적도 결과도 다르다.

| | 07_VERIFY (이 문서) | 4포맷 품질 평가 시스템 |
|---|---|---|
| 묻는 것 | "내보내도 되는가" | "이 콘텐츠가 좋은가" |
| 결과 | 통과 / 차단 | 1~5점 + 코멘트 |
| 판단자 | 기계 + 대조 판정 | 가상 독자 페르소나 |
| 시점 | 발행 직전 게이트 | 발행 후 개선 루프 |
| 대상 | 4포맷 **묶음** | 포맷 **하나씩** |

품질 평가의 "정보 정확성"은 9개 항목 중 하나로 **점수**가 매겨지지만,
여기서 사실 오류는 점수가 아니라 **차단 사유**다.

────────────────────────
## 1. 두 층으로 나눈다
────────────────────────

**기계 검사** — 코드가 한다. LLM을 쓰지 않는다.
커버리지는 집합 연산이다. 세는 일을 모델에 맡기면 틀린다.

**판정 검사** — 이 프롬프트가 한다.
"이 대사가 정말 그 사실을 담았는가"는 읽어야만 안다.

기계 검사가 실패하면 판정 검사를 돌리지 않는다 — 어차피 차단이고,
토큰만 쓴다.

────────────────────────
## 2. 기계 검사 (코드)
────────────────────────

| id | 검사 | 실패 시 |
|---|---|---|
| C1 | core 사실이 **최소 2개 포맷**에 있는가 | 차단 |
| C2 | 레터가 core와 support를 **모두** 담았는가 | 차단 |
| C3 | 보고된 `fact_ids`가 전부 facts.json에 실재하는 id인가 | 차단 |
| C4 | 팟캐스트 수치가 3개 이하인가 | 경고 |
| C5 | `comparisons`가 비었는데 영상에 chart 컷이 있는가 | 차단 |

### C1 — 부분 발행일 때의 분모

파이프라인은 포맷이 빠져도 발행한다(`published_no_video`,
`degraded_no_webtoon`). 그래서 "2개 포맷"을 **산출된 포맷 수로 조정한다.**

    필요 포맷 수 = min(2, 실제 산출된 포맷 수)

- 4개 다 나왔으면 core 사실마다 2개 이상
- 웹툰이 실패해 3개면 그대로 2개 이상
- 2개만 나왔으면 2개 — 사실상 둘 다 담아야 한다
- 1개(레터만)면 1개 — C2가 이미 더 강하게 본다

조정하지 않으면, 포맷 실패가 곧 검증 실패가 되어 **살릴 수 있는 기사를
두 번 죽인다.**

### C5 — 없는 대비를 만들지 않았는가

영상은 차트 컷이 "증가/감소"를 그려야 해서 대비되는 두 수치를 구조적으로
요구한다. 원문에 없으면 모델이 지어낸다 — 라운드1에서 실제로 터졌다.
`comparisons`가 빈 배열이면 **원문에 대비 수치가 없다는 확정 신호**이므로,
이때 chart 컷이 있으면 그 수치는 지어낸 것이다.

────────────────────────
## 3. 판정 검사 (이 프롬프트)
────────────────────────

기계 검사를 통과한 것만 본다.

**V1 — 보고와 실제가 맞는가**
각 포맷이 보고한 `fact_ids`를 하나씩 열어, 그 사실이 **정말 그 산출물 안에
있는지** 확인한다. id만 적어두고 내용은 빠뜨린 경우를 잡는다.

**V2 — 원문에 없는 사실**
수치·발언·사건이 facts.json과 기사 원문 어디에도 없으면 지어낸 것이다.
가장 무거운 위반이다. 4개 포맷 전부가 대상.

**V3 — 미확정을 확정처럼**
`confirmed: false`인 사실을 "~했다", "~로 정해졌다"로 쓰면 안 된다.
"가닥", "검토 중", "추진"이 원문에 있었다면 그 온도가 유지돼야 한다.

**V4 — 주체 없는 주장**
`attribution`이 있는 사실을 주체 없이 단정 서술로 옮기면 안 된다.
성능·효과 주장, 입장이 갈리는 사안이 특히 위험하다.

**V5 — 포맷 간 중복 전개**
세 스펙이 서로를 명시적으로 견제한다 — 레터는 "웹툰·팟캐스트와 같은 논리
전개를 반복하지 않는가", 팟캐스트는 "레터와", 영상은 "웹툰과".
같은 사실을 담는 건 정상이고 **권장**된다(C1이 그걸 요구한다).
문제는 **같은 순서로 같은 논증을 반복**하는 것이다.

**V6 — 감각 변환이 값을 바꿨는가**
팟캐스트·웹툰은 수치를 감각으로 바꾼다("78% 낮다" → "5분의 1 아래").
변환 결과가 원래 값과 다른 크기를 뜻하면 왜곡이다.

────────────────────────
## 4. 차단과 경고
────────────────────────

**차단(block)** — 사실이 틀렸거나 없는 것을 만들어낸 경우.
C1·C2·C3·C5, V2·V3·V4·V6.

**경고(warn)** — 규격에서 벗어났지만 사실은 맞는 경우.
C4, V1(내용은 있는데 id 보고만 누락), V5.

기준: **독자가 잘못된 사실을 믿게 되면 차단, 읽기 불편하면 경고.**
경고만 있으면 발행하고 로그에 남긴다. 사람이 나중에 본다.

빠진 core 사실이 있어 차단됐을 때, **재생성보다 먼저 facts.json을 의심한다.**
core로 분류될 만한 게 아니었을 수 있다.

────────────────────────
## 5. 출력 형식
────────────────────────

전체를 하나의 JSON 코드블록으로 출력한다.

{
  "verdict": "pass | warn | block",
  "formats_checked": ["letter", "podcast", "video"],
  "coverage": {
    "core_total": 6,
    "core_satisfied": 5,
    "required_formats": 2,
    "uncovered_core_ids": [4]
  },
  "issues": [
    {
      "rule": "V2",
      "severity": "block",
      "format": "video",
      "fact_id": null,
      "quote": "문제가 된 산출물의 구절 — 그대로 복사",
      "why": "원문·facts.json 어디에도 없는 수치"
    }
  ],
  "notes": "사람이 읽을 한두 줄. 없으면 null"
}

- `verdict`는 issues 중 가장 무거운 것을 따른다 (block > warn > pass)
- `quote`는 반드시 산출물에서 **그대로** 옮긴다. 요약하면 사람이 못 찾는다
- 문제가 없으면 `issues`는 빈 배열. 억지로 채우지 않는다

────────────────────────
## 6. 체크리스트
────────────────────────

□ 기계 검사(C1~C5)를 먼저 돌렸는가
□ C1의 분모를 실제 산출된 포맷 수로 조정했는가
□ 보고된 fact_ids가 실제 내용과 대조됐는가 (V1)
□ 원문에 없는 수치·발언을 전부 찾았는가 (V2)
□ 미확정 사실의 온도가 유지됐는가 (V3)
□ 주장에 주체가 남아 있는가 (V4)
□ 중복을 "같은 사실"이 아니라 "같은 전개"로 판정했는가 (V5)
□ 감각 변환이 값의 크기를 바꾸지 않았는가 (V6)
□ 모든 issue에 산출물 원문 quote가 붙었는가
□ verdict가 가장 무거운 issue와 일치하는가

| V2 (지어낸 사실) | 06_WEBTOON "원문에 없는 사실·수치·발언을 만들지 않는다" / 04_PODCAST 동일 취지 |

| V4 (주체) | 05_VIDEO "성능 주장은 주체 명시" / 06_WEBTOON "한쪽 주장을 결론처럼 쓰지 않는다" |
| V5 (중복 전개) | 03_LETTER·04_PODCAST·05_VIDEO 체크리스트가 서로를 명시적으로 견제 |
| V6 (감각 변환) | 04_PODCAST 감각 변환 표 / 06_WEBTOON "숫자를 그대로 읽지 않는다" |
| 품질 평가와의 경계 | `docs/evaluation/4format-evaluation-system.md` — 페르소나 rubric 점수제, "정보 정확성"은 9항목 중 1개 |

**추정이 섞인 곳** (원본과 다를 가능성이 큰 부분):
기계/판정 2층 구조, block·warn 구분, `verdict`·`issues` 출력 스키마,
C1 분모 조정 공식은 어느 문서도 규정하지 않는다 — 운영에서 필요한 형태로
역산한 것이다. **C1 기준 자체와 C2·C4는 문서에 직접 근거가 있다.**

**아직 못 하는 것:** V1(보고 대조)은 4개 포맷이 전부 `fact_ids`를 내보내야
성립한다. 06_WEBTOON만 원래 내보냈고, 03·04·05는 2026-08-24에 추가됐다
(레터·팟캐스트는 `FACT_IDS:` 트레일러, 영상은 컷별 `fact_ids`).
**DDB 프롬프트가 갱신되기 전까지 V1과 C1은 웹툰 것만 볼 수 있다.**
