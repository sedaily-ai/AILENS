> 03_LETTER·04_PODCAST·05_VIDEO·06_WEBTOON 네 스펙이 facts.json 에 대해
> 요구하는 것과, `docs/product/4format-persona-system.md` 의 교차표·사고 기록을
> 역으로 짜맞춰 복원했다. 원본이 나오면 **원본을 정본으로 삼는다.**
> 각 필드의 근거는 §7 에 출처를 달아뒀다.

01_COMMON.md의 모든 규칙을 준수한다.
출력 facts.json은 레터·웹툰·팟캐스트·영상 4개 포맷과 07_VERIFY의 **공통 입력**이다.

────────────────────────
## 0. 이 단계가 맡는 것
────────────────────────

**사실의 확정.** 무엇이 원문에 실제로 있었는가.

- 담는다: 원문에서 검증 가능한 사실, 수치, 발언, 구조
- 담지 않는다: 해석, 감상, 포맷별 표현, 원문에 없는 배경지식

**이 단계는 글을 쓰지 않는다.** 4개 포맷이 각자 다른 얼굴로 같은 사실을
말하려면, 그 "같은 사실"이 먼저 하나의 목록으로 고정돼야 한다.
여기서 지어낸 사실은 4개 포맷 전부로 퍼진다.

**포맷별로 뽑는 것이 다르다** — 그래서 한쪽만 보고 추출하면 안 된다.

| 포맷 | 원문에서 뽑는 것 | 버리는 것 |
|---|---|---|
| 레터 | 인과·함의 | 장식적 서사 |
| 웹툰 | 감정 이입 가능한 장면 | 추상적 통계 |
| 팟캐스트 | 흐름·서사 축 하나 | 수치·표 |
| 영상 | 대비되는 수치 | 서술적 디테일 |

────────────────────────
## 1. core / support
────────────────────────

**core** — 이 기사가 사라지면 독자가 놓치는 것. 보통 4~8개.
**support** — core를 뒷받침하거나 맥락을 주는 것. 보통 6~15개.

- 레터는 core와 support를 **모두** 담는다
- 웹툰·팟캐스트·영상은 core를 담고 support는 선택
- **core는 최소 2개 포맷에 담겨야 한다** (07_VERIFY 기준)

core를 고르는 기준: "이걸 빼고 기사를 요약하면 말이 되는가."
말이 되면 support다.

────────────────────────
## 2. 수치 — 조건까지 같이 뽑는다
────────────────────────

수치는 값만 뽑으면 4개 포맷 전부에서 오용된다.

- `value` / `unit` — 영상 stat 컷이 그대로 쓴다
- `basis` — 조건. "1t당", "전년 동기 대비", "서울 기준"
- `as_of` — 기준 시점. 영상은 수치 컷에 출처·시점을 반드시 표기한다
- `meaning` — 이 숫자가 크다는 건지 작다는 건지. 레터가 숫자 뒤에 붙인다
- `sensory` — 귀로 듣고 남는 형태. 팟캐스트·웹툰이 쓴다

`meaning`과 `sensory`는 **해석이 아니라 원문이 이미 제공하는 비교 기준**만
쓴다. 원문에 "보통 3g만 나와도 캘 만하다"가 있으면 그걸 쓰고, 없으면 null.

### 대비 수치 — 없으면 없다고 명시한다

영상은 차트 컷이 "증가/감소"를 그려야 해서 **대비되는 두 수치를 구조적으로
요구한다.** 원문에 그런 쌍이 없으면 모델이 숫자를 지어낸다 — 라운드1에서
실제로 터졌다(원문에 없는 "2025: 100 → 2026: 150" 생성).

그래서 `comparisons`를 **명시적으로 비운다.** 빈 배열은 "아직 안 찾았다"가
아니라 **"원문에 대비할 수치가 없다"**는 확정 신호이고, 영상은 이때 차트 컷을
스킵하고 highlight·diagram으로 대체한다.

────────────────────────
## 3. 확정 / 미확정 / 주장
────────────────────────

- `confirmed: true` — 일어난 일, 발표된 수치
- `confirmed: false` — 검토 중, 가닥, 전망, 추진
- `attribution` — 발언·주장이면 그 주체. 순수 사실이면 null

세 포맷이 이걸 직접 요구한다. 웹툰은 "확정된 사실과 검토 단계 내용을
구분한다", 영상은 "미확정 사항을 명시했는가", 레터는 "미확정 전망 단정" 금지.

입장이 갈리는 사안은 **양쪽을 각각 별도 fact로 뽑는다.** 한쪽만 뽑으면
그 뒤 어느 포맷도 균형을 복구할 수 없다.

────────────────────────
## 4. 소재 유형과 인물
────────────────────────

`topic_type`은 웹툰의 인물 처리와 팟캐스트의 진입 장면을 결정한다.

| topic_type | 웹툰 인물 처리 |
|---|---|
| 생활밀착 | 익명 일반인 2명 |
| 산업거시 | 익명 실무자 2명 |
| 사건사고 | **인물 없음** — 상황·사물 중심 |
| 인물정치 | **인물 없음** — 실존 인물 묘사 금지 |

`people`에는 원문에 실제로 등장하는 당사자만 적는다(실명·직책·처지).
웹툰이 익명 캐릭터를 만들 때 참고만 하고 그대로 그리지 않는다.

당사자가 없는 소재면 `people: []` 로 두고, 팟캐스트는 독자의 일상에서
접점을 찾는다 — **원문에 없는 사례를 지어내지 않는다.**

────────────────────────
## 5. 출력 형식
────────────────────────

전체를 하나의 JSON 코드블록으로 출력한다.

{
  "article": {
    "title": "원문 제목",
    "source": "서울경제",
    "published_at": "2026-08-24",
    "topic_type": "생활밀착|산업거시|사건사고|인물정치",
    "one_line": "이 기사가 말하는 것 한 문장",
    "axis_question": "이 사안의 축이 되는 질문 (웹툰 core_question 후보)"
  },
  "facts": [
    {
      "id": 1,
      "tier": "core",
      "kind": "number|event|statement|structure|context",
      "text": "사실 한 줄",
      "quote": "근거가 되는 원문 문장 — 그대로 복사",
      "number": {
        "value": 46.1, "unit": "g", "basis": "1t당",
        "as_of": "2026-08", "source_note": "한국지질자원연구원",
        "meaning": "보통 3g만 나와도 캘 만한 수준",
        "sensory": "보통의 열다섯 배쯤 됩니다"
      },
      "attribution": null,
      "confirmed": true,
      "visualizable": "stat|chart|diagram|none"
    }
  ],
  "comparisons": [
    { "kind": "before_after|ranking|share",
      "fact_ids": [1, 2], "label": "공제 기준 변화" }
  ],
  "people": [
    { "name": "", "role": "", "situation": "" }
  ],
  "unresolved": ["아직 정해지지 않은 것 — 레터의 '남은 변수', 영상의 '미확정 사항'"],
  "cautions": ["표현 주의 사항 — 실명 비난 금지, 목표주가 금지 등"]
}

- 수치가 아닌 fact는 `number: null`
- `id`는 1부터. **한 번 붙인 id는 바꾸지 않는다** — 웹툰이 `fact_ids`로,
  07_VERIFY가 커버리지 대조로 이 id를 참조한다
- `comparisons`가 비면 영상은 차트 컷을 만들지 않는다 (§2)

────────────────────────
## 6. 체크리스트
────────────────────────

□ 모든 fact에 원문 `quote`가 붙었는가
□ 원문에 없는 사실·수치·발언이 섞이지 않았는가
□ core가 4~8개이고, 빼면 기사가 성립하지 않는 것들인가
□ 수치에 조건(`basis`)과 기준 시점(`as_of`)이 붙었는가
□ `meaning`·`sensory`가 원문이 준 비교 기준만 쓰는가
□ 검토 단계 내용이 `confirmed: false`로 구분됐는가
□ 주장·발언에 `attribution`이 있는가
□ 입장이 갈리는 사안의 양쪽이 각각 fact로 있는가
□ `comparisons`가 원문에 실제 있는 대비만 담았는가 (없으면 빈 배열)
□ `topic_type`이 웹툰 인물 처리와 맞는가
□ id가 1부터 연속이고 중복이 없는가

────────────────────────
## 7. 각 필드의 근거 (재구성 출처)
────────────────────────

| 필드 | 근거 |
|---|---|
| `id` (정수) | 06_WEBTOON 출력 스키마 `"fact_ids": [8]` — "이 컷이 담은 facts.json의 id 배열" |
| `tier: core/support` | 03_LETTER "facts.json의 core와 support를 **모두** 담아야 한다" |
| core 최소 2포맷 | 작업 지시서 — 07_VERIFY "core 사실이 최소 2개 포맷에 있는가" |
| `quote` | 06_WEBTOON "원문에 없는 사실·수치·발언을 만들지 않는다" / 04_PODCAST "원문에 없는 사례를 지어내지 않는다" |
| `number.value/unit` | 05_VIDEO stat 스키마 `{value, unit, label, sourceNote}` |
| `number.basis` | 03_LETTER "조건이 붙은 수치는 조건을 함께" |
| `number.as_of`·`source_note` | 05_VIDEO "수치 컷에 출처·기준 시점 표기" |
| `number.meaning` | 03_LETTER "숫자 뒤에 반드시 의미를 붙인다" |
| `number.sensory` | 04_PODCAST 감각 변환 표 / 06_WEBTOON "숫자를 그대로 읽지 않는다" |
| `comparisons` | 05_VIDEO chart 스키마 + `4format-persona-system.md` §4 라운드1 수치 조작 사고 |
| `confirmed` | 06_WEBTOON "확정된 사실과 검토 단계 내용을 구분한다" / 05_VIDEO "미확정 사항 명시" |
| `attribution` | 05_VIDEO "성능 주장은 주체 명시" / 06_WEBTOON "한쪽 주장을 결론처럼 쓰지 않는다" |
| `visualizable` | 05_VIDEO "이 정보를 눈으로 보면 더 잘 이해되는가" |
| `topic_type` | 06_WEBTOON 소재 유형 4종 표 (인물 처리 결정) |
| `people` | 04_PODCAST 소재별 진입 표 / 06_WEBTOON 인물 설정 |
| `unresolved` | 03_LETTER "남은 변수" / 05_VIDEO "미확정 사항" |
| `cautions` | 05_VIDEO "목표주가 표시 금지" / 06_WEBTOON "실명 개인을 조롱하거나 단정 비난하지 않는다" |
| 포맷별 분담 교차표 | `docs/product/4format-persona-system.md` §5 |

**추정이 섞인 곳** (원본과 다를 가능성이 가장 큰 부분):
`kind` 분류값, `axis_question`, `one_line`, `people` 구조, core/support 권장
개수는 네 스펙이 직접 규정하지 않는다. 필요에서 역산한 것이라 원본과
이름·형태가 다를 수 있다. `id`·`core`/`support`·`comparisons`·`confirmed`는
스펙에 직접 근거가 있어 상대적으로 안전하다.
