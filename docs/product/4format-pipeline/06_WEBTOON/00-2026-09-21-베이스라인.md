작성: 문영광 + Claude Code. 다른 5개 포맷과 형식을 맞추기 위한 요약본 —
**상세 정본은 `docs/architecture/webtoon_custom/`**(01-현재구조·
02-정리후보·03-모델선정근거·04-작업기록·05-라운드기록)다. 웹툰은 4개

문서 세트를 이미 갖고 있다 — 이 파일은 그 세트로 들어가는 입구 역할만.

## A to Z — 요약(3단계)

```
frontpage_auto/run.py, mustknow_auto/run.py
  └─ publish_utils.publish_article()
       └─ webtoon_mod.run_article(name, article_path, out_dir, manage_gpu)
            1단계 — 스크립트+장면 연출 (한 번의 Bedrock 호출로 통합, 2026-09-20)
            └─ ddb_prompt.load_prompt("webtoon")
            └─ 8컷 narration + image_prompt 생성(카메라/장면 분리 폐기,
               v3 리디자인 — 자세한 경위는 architecture/webtoon_custom/)
            2단계 — 컷 이미지 생성 (모델은 CMS에서 fresh 조회, 재배포 불필요)
            └─ webtoon_image.get_active_image_model() ← webtoon-image/published
            └─ webtoon_image.generate_cut_image_to_file() × 8컷
               (admin 실험 패널과 발행 파이프라인이 이 함수 하나를 공유 —
               2026-09-20 "정리후보 A+D" 통합)
            3단계 — 스티칭
            └─ stitch.py가 8컷을 세로 한 장으로 합성
       └─ 실패해도(이미지 생성 실패 등) 웹툰만 빼고 3포맷은 발행(webtoon만
          있는 예외 — 05_VIDEO와 반대로 "재시도 없이 그냥 스킵")
```

- 모델(텍스트): `lens-webtoon-script-sonnet-46`(스크립트+장면연출)
- 모델(이미지): 코드 상수 없음 — `webtoon-image/published` CMS 문서의
  `IMAGE_MODEL` 값을 매 컷 생성 직전 fresh 조회(2026-09-20부터, 그
  전엔 코드 상수라 재배포 필요했음). 현재 admin 기본값/폴백 둘 다
  `sd_ultra`(Stable Image Ultra) — 선정 근거는
  `architecture/webtoon_custom/03-모델선정근거/`
- QA(생성 후 비전 모델 재검증) — **2026-09-20 완전 제거**. "CMS에서만
  제어돼야 한다"는 원칙과 안 맞아서(admin은 기본 off, 발행은 하드코딩
  on) 토글을 새로 만드는 대신 기능 자체를 없앰
