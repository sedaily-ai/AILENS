# 4포맷 파이프라인 프롬프트 스펙

기사 원문 1건 → 레터·웹툰·팟캐스트·영상 4개 포맷을 자동 생성하고 사실
커버리지를 검증하는 파이프라인의 **프롬프트 정의**. 각 포맷이 무엇을 담고
무엇을 담지 않는지, 출력이 어떤 형태여야 하는지가 여기에 있다.

**왜 이 4개 포맷인가**는 `../4format-persona-system.md`.
**품질을 어떻게 재는가**는 `../../evaluation/4format-evaluation-system.md`.

## 단계

```
기사 원문
  └─ 02_EXTRACT  사실 추출 → facts.json
       ├─ 03_LETTER    구조와 인과      (core + support 전부)
       ├─ 06_WEBTOON   감정 이입 가능한 장면
       ├─ 04_PODCAST   의미와 감각      (수치 3개 이하)
       └─ 05_VIDEO     변화와 대비      (대비 수치 없으면 chart 컷 스킵)
  └─ 07_VERIFY   facts.json 대비 커버리지 검증 → 발행 게이트
```

| 폴더 | 다루는 것 | 상태 |
|---|---|---|
| `02_EXTRACT/` | 원문 → facts.json(→ 실제로는 프로즈 팩트시트, 아래 베이스라인 참고) | ⚠️ **재구성본**, 스펙-코드 괴리 확인됨 |
| `03_LETTER/` | 레터 — 시계열·구조·메커니즘 | 원본, 2026-09-21 헤드라인 규칙 v10까지 갱신 |
| `04_PODCAST/` | 팟캐스트 — 1인 화자, 감각 변환 | 원본 |
| `05_VIDEO/` | 영상 — 컷 6종, 렌더용 JSON | 원본 |
| `06_WEBTOON/` | 웹툰 — 스크립트 → 연출 → 이미지 3단계 | ⚠️ 정본은 `../../architecture/webtoon_custom/` |
| `07_VERIFY/` | 커버리지·사실 검증 게이트 | ⚠️ **재구성본**, **미구현 확인됨**(아래 베이스라인 참고) |
| `08_BUNDLE_LETTER/` | 지면특별코너 다건 통합 레터(기사 1건=레터 1건이 아니라 여러 건=레터 1건) | 🚧 **설계 중**, 미구현. 다른 폴더와 달리 `vX.Y-` 시맨틱 버전 파일명 사용 |

각 폴더의 `00-2026-09-21-베이스라인.md`가 "지금 실제 코드가 A~Z
어떻게 동작하는가"를 코드 직접 대조로 확인한 스냅샷이다 — `README.md`
(스펙)와 실제 코드가 갈라진 지점(02·07이 특히 큼)은 그 파일에 명시돼
있다. 앞으로 이 스펙을 고칠 일이 있으면 베이스라인 먼저 확인할 것.

## 폴더 구조 (2026-09-21 — 파일에서 폴더로 전환)

각 포맷 폴더는 세 종류의 파일을 담는다:

- **`README.md`** — 살아있는 참고 문서. "지금 실제로 뭘 요구하는가"의 정본.
  프로덕션 DDB 프롬프트를 바꾸면 **같은 커밋에서 여기도 같이 갱신**한다
  (아래 "실제 운영 프롬프트는 DDB에 있다" 참고).
- **`00-YYYY-MM-DD-베이스라인.md`** — 그 포맷의 A~Z 로직·파이프라인을
  코드 직접 대조로 확인한 스냅샷. 이후 쌓이는 의사결정 기록들의
  "As-Is" 출발점 — 새 결정 기록을 쓸 때 "무엇이 바뀌었는가"를 이
  문서 대비로 서술한다. 폴더당 하나면 충분하고, 코드가 크게 달라지면
  새 번호(예: `08-...-베이스라인-재정립.md`)로 다시 잡는다(덮어쓰지
  않음 — ADR 관행).
- **`NN-YYYY-MM-DD-주제.md`** — 의사결정 기록. append-only — 왜 그
  규칙이 이렇게 바뀌었는지 시간순으로 쌓는다. 번호는 그 포맷 폴더 안에서
  날짜순으로 이어붙이고, 하위 폴더는 더 만들지 않는다. 이미 있는 결정을
  다시 쓰지 않는다 — 관련 있으면 새 번호로 후속 기록을 남기고 이전
  파일과 상호 링크.

**문서 틀**(의사결정 기록 파일 전부에 적용): 문제 발견 → 문제 정의 →
왜 그렇게 했는지 → 어떻게 달라졌는지, 4단 구성. 필요하면 끝에 "검증"
(테스트·확인 결과)·"성격"(이 작업이 어떤 종류였는지) 코다 섹션을 붙인다.

## 아직 없는 것

`00_CONTEXT.md` · `01_COMMON.md` 는 이 레포에도, 로컬에도, DDB 에도 없다.
**네 포맷 스펙이 전부 "01_COMMON.md의 모든 규칙을 준수한다"로 시작하므로,
지금은 모든 포맷이 읽을 수 없는 공통 규칙을 전제하고 있는 상태다.**
02·07 과 달리 내용을 추정할 근거가 없어 복원하지 않았다 — 마스터DB 에서
원본을 회수하는 게 맞다.

## 실제 운영 프롬프트는 Postgres(lens-cms-api)에 있다

이 문서들은 **정의**고, 프로덕션이 읽는 건 `pipelines/common/ddb_prompt.py`
가 `GET /api/v2/prompts/{category}/{name}`(lens-cms-api, Postgres
`prompt_versions` 테이블)에서 매번 fresh하게 fetch하는 content다 —
2026-09-21 확인, 이름(`ddb_prompt.py`)과 달리 실제로는 DynamoDB가 아니다
(과거 DynamoDB `PROMPT#<category>/<scope>` 스키마에서 마이그레이션됐고
모듈명만 남았다). lens-cms-api 접근이 실패하면
`service/backend/prompts/<category>/published.md` 파일시스템 사본으로
폴백한다. admin 콘솔 "프롬프트 실험"/"이미지 실험" 화면에서 편집·발행.

**여기를 고쳐도 프로덕션은 안 바뀐다.** 반영하려면 admin 콘솔에서 발행해
Postgres 버전을 같이 올려야 한다. 반대로 admin만 고치고 여기를 안 고치면
정의와 운영이 갈라진다 — 실제로 2026-09-21 레터 헤드라인 규칙이 이렇게
갈라졌다가 발견됨(`03_LETTER/` 의사결정 기록 참고).

### 커버리지 트레일러 — 순서 주의

`03_LETTER`·`04_PODCAST` 는 코드블록 **바깥** 마지막 줄에
`FACT_IDS: [1, 3, 4]` 를, `05_VIDEO` 는 컷마다 `"fact_ids": []` 를
내보낸다(`06_WEBTOON` 은 원래부터 냈다). `07_VERIFY` 가 이 값으로
커버리지를 대조한다.

🛑 **코드가 먼저 나가야 한다.** 이 트레일러를 떼어내는 처리가 없으면
레터는 그 줄이 발행 본문 문단이 되고(`_parse_letters` 에 종료 조건이 없다),
팟캐스트는 Polly 가 소리 내어 읽는다. 처리는 PR #26
(`common/text_utils.py` 의 `extract_fact_ids`)에 있다.
**PR #26 머지 → DDB 프롬프트 갱신** 순서를 지킬 것.
