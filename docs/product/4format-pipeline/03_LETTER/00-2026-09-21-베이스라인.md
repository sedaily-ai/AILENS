# LETTER — 현재 구조 베이스라인 (2026-09-21)

작성: 문영광 + Claude Code. 코드 직접 대조로 확인 — 갱신 시 이 문서도
같이 고칠 것. 오늘 헤드라인 톤 개편 경위는 `01-...md`(의사결정 기록),
이 문서는 "지금 A~Z가 어떻게 동작하는가" 스냅샷.

## A to Z — 실제 코드 흐름

```
frontpage_auto/run.py, mustknow_auto/run.py (EventBridge 스케줄)
  └─ publish_utils.publish_article()
       └─ letters_mod.run_article(name, article_path, out_dir)
            └─ ddb_prompt.load_prompt("letters")  ← admin "프롬프트 실험"에서 발행
            └─ bedrock_client.call_text(guide, "...기사 원문(+팩트시트)...",
                 model=lens-letters-opus-5, max_tokens=12000)
            └─ 결과 텍스트를 그대로 `레터.md`로 저장(파싱 없음, 이 단계에선)
       └─ letters_raw = 레터.md 읽기
       └─ paragraphs = parse_letters(letters_raw)          ← 본문 문단
       └─ letter_summary_bullets = parse_letter_summary_bullets(letters_raw) ← "30초 핵심"
       └─ letter_terms = parse_letter_terms(letters_raw)    ← 용어 설명
       └─ letter_title = parse_letter_title(letters_raw)
              or extract_title_from_lead(paragraphs)         ← 2026-09-21 신설 방어선
              or article["title"]                            ← 최후 폴백(원문 뉴스 제목)
       └─ lenses[] 배열의 "레터" 항목으로 조립 → lens-cms-api(Postgres) 발행
```

  가른다.

## 2026-09-21 발견·수정한 버그 (코드는 이미 반영, 검증 진행 중)

- **`[리드]` 마커 불일치**: `parse_letters()`/`parse_letter_title()`
  둘 다 `line.startswith("[리드]")`로 매칭했는데, 실제 프롬프트 헤더는
  `[리드 3~5문장]`이라 5번째 글자가 공백이라 불일치 — `[제목]` 블록이
  올바른 지점에서 안 끊겼다. `line.startswith("[리드")`로 느슨하게
  수정(`publish_utils.py`).
- **모델이 `[제목]` 줄 자체를 안 쓰는 경우**: 실제 발행 레터 다수를
  직접 열어보니, 모델이 제목을 별도 줄로 안 떼고 리드 문단에 섞어 쓴
  경우가 흔했다 — 이 경우 위 마커 수정과 무관하게 `parse_letter_title()`
  이 애초에 `in_block`을 못 켠다(None 반환). 방어선으로
  `extract_title_from_lead()`를 신설 — 첫 문단에서 첫 이모지까지를
  잘라 제목으로 복구한다(프롬프트 규칙상 제목은 항상 이모지 1개로
  끝남). 실사용 데이터 36건으로 이 발상 자체는 수동 검증 완료, 코드
  배포(ECS 이미지 재빌드·`sedaily-lens-frontpage-auto` 리비전 54)까지
  끝냈고, mustknow_auto 수동 실행으로 실제 파이프라인에서도 맞는지
  검증 중(이 문서 작성 시점 기준 진행 중).
- 두 수정 다 실패해야(첫 문단에 이모지조차 없는 극단적 경우만) 원문
  뉴스 제목(`article["title"]`)으로 최종 폴백한다.
