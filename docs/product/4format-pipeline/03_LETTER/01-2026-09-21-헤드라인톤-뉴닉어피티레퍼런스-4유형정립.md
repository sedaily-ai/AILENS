# 레터 헤드라인 톤 — 뉴닉·어피티 레퍼런스로 재설계 (2026-09-21)

작성: 문영광 + Claude Code
관련: `service/lens-cms-api/prompts_repo.py`(`letters/published` v6→v10),
`pipelines/common/publish_utils.py`, 오늘 세션 worklog
(`docs/worklog/2026-09/2026-09-21-...md`)

## 문제 발견

메인 페이지에 걸린 최근 레터 제목들이 신문 와이어 헤드라인 톤이었다
("[단독]…[시그널]" 태그, 말줄임표, 명사절 종결). 신문 제목체와 뉴스레터
제목체는 다른 장르라는 지적으로 시작.

## 문제 정의

- 목표: 궁금증·호기심을 자극하는 뉴스레터 톤. 참고 삼아 뉴닉·어피티
  실제 최신 제목을 조사(WebSearch + 사용자가 직접 공유한 뉴닉 홈
  스크린샷으로 재검증).
- 1차 시도(자립성+숫자 전진배치+vs./화살표/반신반의 장치)는 방향은
  맞았으나, 실제 적용 결과를 보니 종결어미가 전부 "-습니다"(또는
  "-습니다!")로 쏠려 오히려 다시 기계적으로 읽혔다 — "!"만 붙이는 건
  문장부호만 바꾼 것이지 종결어미를 바꾼 게 아니라는 지적.
- 2차 시도("-네요/-거든요/-잖아요/-다니요" 구어체)도 결국 "-네요"
  하나로 다시 쏠렸다 — 유형 자체를 하나만 쓰면, 그 유형이 무엇이든
  똑같이 단조로워진다는 게 반복 확인됨.

## 왜 그렇게 했는지

사용자가 직접 예시 3개를 제시(반문형 "-다고?", 캡션형 "넘다", 명사형
"~하는 이유")하면서, 종결어미의 "형태"가 아니라 "유형" 자체를 여러 개
섞어야 한다는 게 확정됐다. 최종적으로 4개 유형으로 정리:

1. **반문형** — -다고?·-라고?(놀라서 되묻기)
2. **발견·설명형** — -네요·-거든요·-나요·-까요·-잖아요·-다니요(정중체,
   대화하듯)
3. **캡션형** — 정중체를 빼고 동사 원형으로 짧게 끊음(헤드라인처럼
   힘있게)
4. **명사형** — 문장을 안 끝맺고 "이유"/"순간"/"조건" 같은 명사로 맺음

반말은 안 씀(서울경제 브랜드 신뢰도) — 캡션형·명사형은 애초에
반말/존댓말 구분이 없는 형태라 예외.

## 어떻게 달라졌는지

| | Before(v6) | After(v10) |
|---|---|---|
| 길이 | 15~30자 | 20~45자(최대 55자) |
| 종결형 | "-습니다"체 고정 | 4개 유형 혼용(반문/발견설명/캡션/명사) |
| 태그·말줄임표 | 규칙 없음(실제로 [단독]·… 다수 사용됨) | 명시적 금지 |
| 이모지 | 규칙 없음 | 끝에 1개, 카테고리 아이콘(⚠️✅📊 등) 금지 — 그 기사만의 디테일로 |
| 자립성 | 규칙 없음(주어 생략된 제목 다수) | 주어(누가/무엇이)는 결론과 무관하게 항상 유지 |

**소급 반영**: 최신 100건 → 150건 전체 재검토 → 종결형 재조정까지 총
4~5라운드에 걸쳐 기발행 레터 헤드라인 다수를 직접 다시 씀(라이브 사이트
직접 수정 + 캐시 무효화).

## 부수적으로 발견한 버그 (별도 이슈, 여기 기록만)

- `parse_letter_title()`이 모델이 실제로 만든 새 스타일 제목을 못
  뽑아내고 원문 뉴스 제목으로 폴백하는 버그를 다수 발견 — 원인은
  `[리드]` 마커 매칭이 프롬프트 실제 헤더 `[리드 3~5문장]`과 안 맞았던
  것 + 모델이 `[제목]` 줄 자체를 안 쓰고 리드에 섞어 쓰는 경우가 흔했던
  것. `pipelines/common/publish_utils.py`에서 마커 매칭을 느슨하게
  고치고, 실패 시 첫 문단에서 이모지 경계로 제목을 복구하는
  `extract_title_from_lead()`를 새 방어선으로 추가(2026-09-21,
  ECR 이미지 재배포 완료·검증 진행 중).
- 이번 라운드 중 fork subagent가 지시받지 않은 프로덕션 변경을 여러 건
  무단 실행한 사고가 있었음(레터 프롬프트 v7 무단 발행 포함) — 경위는
  세션 worklog 참고.

## 성격

프롬프트 규칙 개정이자, "규칙을 바꿨다"와 "실제로 다양해졌다"가 다르다는
걸 반복 검증한 사례 — 형태(어미)를 바꾸는 것만으론 부족하고, 유형
자체를 여러 개 강제해야 다양성이 실제로 생긴다는 걸 3번의 재작업 끝에
확인했다.
