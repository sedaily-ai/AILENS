# AILENS 레터 제작 프롬프트

01_COMMON.md의 모든 규칙을 준수한다.
`../02_EXTRACT/`의 facts.json을 입력으로 받는다.

실제 운영 버전은 v10(2026-09-21) — 변천사는 이 폴더의 번호 파일 참고.

────────────────────────
## 0. 이 포맷이 맡는 것
────────────────────────

**구조와 인과.** 왜 이 일이 벌어졌고, 어떤 흐름 위에 있는가.

- 담는다: 시계열 추이, 배경 구조, 메커니즘, 상반된 시각, 남은 변수
- 담지 않는다: 단순 수치 나열, 정서적 해석, 시각적 대비

**레터는 4개 포맷 중 사실 커버리지가 가장 넓다.**
facts.json의 core와 support를 **모두** 담아야 한다.

────────────────────────
## 1. 분량과 구조
────────────────────────

- 전체 2000~2800자
- 소제목 5~7개
- 각 섹션 200~450자

**골격**

[제목]
독자 시선 진입형. 20~45자(최대 55자 — 이 상한을 넘기지 않는다).

종결어미는 뉴스 기사체("-습니다")가 아니라 사람이 실제로 말하듯 쓴다.
"-습니다"에 느낌표만 붙이는 건 여전히 기사체다 — 문장부호만 바꾼 것이지
종결어미를 바꾼 게 아니다. "-네요"만 반복하는 것도 같은 함정 — 아래
서로 다른 "유형"을 실제로 섞어야 다양해진다(자세한 이유는 01번 결정
기록 참고):

- [반문형] -다고?·-라고?(놀라서 되묻기)
  ✓ 인천 1,949가구는 미달인데, 서울 31가구는 282대 1이었다고?
- [발견·설명형] -네요·-거든요·-나요·-까요·-잖아요·-다니요(정중체 유지, 대화하듯)
  ✓ 어깨 MRI 조영제, 아직 허가받은 게 하나도 없다니요
- [캡션형] 정중체를 빼고 동사 원형으로 짧게 끊는다(헤드라인처럼 힘있게)
  ✓ 고려아연 74억 달러 미국 제련소, 첫 관문을 넘다
- [명사형] 문장을 끝맺지 않고 "이유"/"순간"/"조건" 같은 명사로 맺어
  궁금증을 남긴다
  ✓ 밀가루 담합 과징금 6,710억, 법원이 줄줄이 멈춰 세우는 이유

이 네 유형을 오늘 발행되는 여러 제목에 걸쳐 섞어 쓴다 — 한 유형만
반복하면 그 자체로 기계적으로 보인다. 반말은 쓰지 않는다(신문 브랜드
신뢰도 때문) — 캡션형·명사형은 애초에 반말/존댓말 구분이 없는 형태라
예외.

또한:
- 결론을 다 말하지 않는다. 궁금증이 남게 쓰되, 주어(누가/무엇이)는
  반드시 남긴다 — 주체를 지우면 궁금증이 아니라 그냥 안 읽힌다.
- 본문에서 가장 구체적인 숫자 하나를 제목에 넣는다.
- 완결된 구어체 문장으로 끝낸다. 말줄임표(…)나 대괄호 태그([단독],
  [시그널] 등)로 얼버무리지 않는다.
- 끝에 이모지 1개만 붙인다. 그 기사만의 구체적인 디테일 하나를 골라
  붙이고, 주제를 그대로 나타내는 뻔한 아이콘(⚠️✅📊📈📉🔄🎯✨❌ 등)은
  쓰지 않는다.

[리드 3~5문장]
구체적 장면 또는 수치 하나로 시작.
설명 없이 상황만 제시한 뒤, 그것이 예외가 아님을 밝힌다.

◾ [소제목 1] — 사실 확인
무슨 일이 있었는지. 핵심 수치 제시.

◾ [소제목 2] — 흐름 속에 놓기
시계열, 추이, 이전과의 비교.

◾ [소제목 3] — 구조 설명
왜 이렇게 됐나. 메커니즘, 제도, 시장 구조.

◾ [소제목 4] — 반대편 사실
예상과 다른 지점. 대책이 있었는데도 왜.

◾ [소제목 5] — 시각 제시
전문가·당사자 발언. 다른 관점이 있으면 병치.

◾ 한 가지만 기억한다면
독자가 실제로 쓸 수 있는 정보 하나.
필요 시 상담·문의처 안내.
리드의 장면으로 되돌아오며 마무리.

## 2. 소제목
────────────────────────

**독자 시선으로 쓴다.**

| 발행자 시선 | 독자 시선 |
|---|---|
| 법은 강화됐습니다 | 무효인 계약인데도 갚고 있다 |
| 검거율은 반대로 갑니다 | 절반은 잡히지 않는다 |
| 시장 반응은 미미했다 | 발표 당일, 주가는 움직이지 않았다 |

- 10~20자
- 종결형 통일하지 않음
- 리포트 소제목("현황", "전망", "시사점") 금지

────────────────────────
## 3. 문체
────────────────────────

- "~습니다"체
- 한 문장 60자 이내 권장
- 한 문단 3~4문장
- 전문용어는 첫 등장 시 괄호 없이 풀어 설명
  ✓ "CXL은 AI 칩과 메모리를 고속으로 연결하는 기술입니다."
  ✗ "CXL(컴퓨트익스프레스링크)을 활용하면"

**금지**
- 감탄·과장 ("놀랍게도", "충격적인")
- 독자 훈계 ("~해야 합니다")
- 미확정 전망 단정
- 수사적 질문 남발 (섹션당 1회 이하)

────────────────────────
## 4. 숫자
────────────────────────

- 숫자 뒤에 반드시 의미를 붙인다
  ✗ "원가는 5400달러입니다."
  ✓ "원가는 5400달러입니다. 기존 방식보다 78% 낮은 수준입니다."
- 큰 수는 환산 또는 비교 대상 제시
- 조건이 붙은 수치는 조건을 함께
- 한 섹션에 수치 4개 이하

────────────────────────
## 5. 출력
────────────────────────

전체를 하나의 코드블록으로 감싸 출력한다.

**마지막 줄에 커버리지를 남긴다.**

코드블록을 닫은 **뒤**, 아래 한 줄만 덧붙인다.

FACT_IDS: [1, 3, 4, 7]

- 이 산출물이 실제로 담은 facts.json의 `id` 배열
- 07_VERIFY가 "core 사실이 최소 2개 포맷에 있는가"를 이 줄로 대조한다
- **반드시 코드블록 바깥, 맨 마지막 한 줄.** 본문 안에 넣지 않는다 —
  파이프라인이 이 줄을 지우고 본문만 쓴다
- 담지 못한 core 사실이 있으면 억지로 넣지 말고, 그 id를 빼고 정직하게 적는다

────────────────────────
## 6. 체크리스트
────────────────────────

□ 제목이 독자 시선이고, 주어가 살아있고, 숫자가 구체적인가
□ 제목 종결형이 다른 발행분과 같은 유형(반문형/발견설명형/캡션형/명사형)으로 쏠리지 않았는가
□ 제목 끝 이모지가 이 기사만의 디테일을 담고 있는가(뻔한 아이콘 아님)
□ 리드가 구체적 장면·수치로 시작하는가
□ 소제목이 리포트체가 아닌가
□ 웹툰·팟캐스트와 같은 논리 전개를 반복하지 않는가
□ 시계열·구조 설명이 들어갔는가
□ 전문용어를 풀어 썼는가
□ 수치에 의미·조건이 붙었는가
□ 마지막에 독자가 쓸 정보가 있는가
□ facts.json의 core와 support를 모두 담았는가
□ 코드블록 바깥 마지막 줄에 FACT_IDS를 적었는가
