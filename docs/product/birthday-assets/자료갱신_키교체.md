# 내 생일 타임머신 자료 — ECOS 키 교체와 월 갱신

확인: 2026-10-22(코드와 SSM 메타데이터만 조회, 키 값은 읽지 않았고 ECOS·KOSIS·BigKinds는 호출하지 않음) · 기준: 이 파일만 읽고 키 교체와 매달 자료 갱신을 끝낼 수 있게 쓴다.
관련: 출처 이용 근거 [`출처_이용조건.md`](출처_이용조건.md), 작업 기록 [`2026-10-21-생일자산-공식통계-연결.md`](../../worklog/2026-10/2026-10-21-생일자산-공식통계-연결.md), 코드 `service/backend/scripts/build_birthday_assets.py`·`build_birthday_item_prices.py`

명령은 모두 저장소 루트에서 시작한다. AWS CLI(us-east-1 SSM 읽기·쓰기 권한)와 `uv`가 필요하다. 시스템 python에는 boto3가 없어 스크립트는 `uv run --no-project`로 돌린다.

## 1. 현재 상태 (2026-10-22 기준)

- ECOS 키는 SSM `us-east-1 /sedaily-mbti/ecos-api-key`(SecureString)에 있다. 지금 값(버전 1)은 비영리로 신청한 키였고 사용자가 ECOS에서 폐기했다. 이 값으로 부르면 ECOS가 `INFO-100`(인증키가 유효하지 않습니다)을 돌려준다.
- 영리(상업 이용) 키를 새로 신청해 받았다. 회사 내부 사용 승인이 남아 있고, **승인 전에는 SSM에 넣지 않는다.**
- 영리 키여야 하는 이유: AI LENS는 영리법인 서울경제신문의 서비스라 상업 이용으로 본다. ECOS 약관은 상업 이용을 허용하고(제5조①), 인증키 신청서에 이용형태(비영리/영리) 칸이 있어 실제 용도인 영리로 받은 키를 쓴다. 근거는 [ECOS 약관](출처_이용조건.md#ecos-약관-2026-10-21-원문-확인)·[상업 이용 판단](출처_이용조건.md#ai-lens가-상업-이용에-해당하는가).

## 2. 키 위치

값은 어디에도 적지 않는다. 버전·수정 시각은 2026-10-22 `aws ssm describe-parameters` 조회 결과다(셋 다 Standard, KMS `alias/aws/ssm`).

| 키 | SSM 이름(us-east-1) | 버전·마지막 수정(KST) | 쓰는 곳 |
|---|---|---|---|
| ECOS | `/sedaily-mbti/ecos-api-key` | v1 · 2026-10-20 23:31 | `service/backend/scripts/build_birthday_assets.py`(로컬 수동 실행) |
| KOSIS | `/sedaily-mbti/kosis-api-key` | v1 · 2026-10-21 23:27 | `service/backend/scripts/build_birthday_item_prices.py`(로컬 수동 실행) |
| BigKinds | `/sedaily-mbti/bigkinds-api-key` | v2 · 2026-08-17 13:46 | Lambda `sedaily-mbti-time-machine-dev`(`handlers/timeline/time_machine.py` → `services/timeline/bigkinds_search.py`), 스크립트 `build_timeline_attention.py`·`build_front_page_calendar.py` |

- 위 스크립트와 Lambda는 모두 `common/secrets.py`의 `get_secret`으로 SSM에서 직접 읽는다. 키를 환경변수·명령줄·파일로 넘기지 않는다.
- ECOS·KOSIS 파라미터에는 태그 5개(`Project`·`Environment`·`Service=lens`·`CostCenter`·`ServiceName`)가 있다.
- 출처 문서의 남은 확인에 나오는 `/sedaily/apikeys/bok_ecos`는 이 저장소 코드가 읽지 않는다(`git grep` 0건).

## 3. 키 교체 (회사 승인 뒤 1회)

1. 새 키를 붙여 넣는다. `read -rs`는 입력을 화면에 보이지 않고, 셸 기록에는 변수 이름만 남는다. 명령을 실행한 뒤 키를 붙여 넣고 Enter를 누른다.

   ```sh
   read -rs ECOS_KEY && aws ssm put-parameter --region us-east-1 --name /sedaily-mbti/ecos-api-key --type SecureString --value "$ECOS_KEY" --overwrite && unset ECOS_KEY
   ```

2. 버전이 2로 올랐는지 본다(값은 나오지 않는다). `Version`이 2, `LastModifiedDate`가 교체 시각, `KeyId`가 `alias/aws/ssm`이면 된다.

   ```sh
   aws ssm describe-parameters --region us-east-1 --parameter-filters Key=Name,Values=/sedaily-mbti/ecos-api-key --query 'Parameters[].[Name,Version,LastModifiedDate,KeyId]' --output text
   aws ssm list-tags-for-resource --region us-east-1 --resource-type Parameter --resource-id /sedaily-mbti/ecos-api-key
   ```

3. ECOS 호출이 되는지는 4절 실행으로 확인한다(스크립트 1회 = ECOS 호출 6번).

- 태그: `--overwrite`는 값만 새 버전으로 바꾸고 기존 태그 5개는 그대로 둔다. `--tags`는 `--overwrite`와 함께 쓸 수 없다(ValidationException). 위 `list-tags-for-resource`로 5개가 남았는지만 확인한다.
- 비용 태그: 기존 파라미터의 값만 바꾸는 일이라 새 리소스가 아니다. [`비용태깅_규칙.md`](../../architecture/비용태깅_규칙.md)의 생성 전 태그 작업 대상이 아니고, 추가로 할 일은 없다.
- 키 값을 확인하려고 `get-parameter --with-decryption`을 쓰지 않는다. 값이 화면과 터미널 기록에 남는다.

## 4. 교체 직후 검증

키 교체만 확인하는 단계라 커밋하지 않는다. 생일 자료가 있는 최신 `main`(PR #158 병합 전이면 `feat/birthday-assets-official`)에서, `git status`가 깨끗한 상태로 한다.

```sh
(cd service/backend && AWS_DEFAULT_REGION=us-east-1 uv run --no-project --with boto3==1.35.0 --with requests==2.32.3 python scripts/build_birthday_assets.py --until 2026-10-20)
git diff --stat -- service/frontend/public/data/birthday-assets/
git diff --word-diff=plain --word-diff-regex='\["[0-9-]+",[^]]*\]' -- 'service/frontend/public/data/birthday-assets/[0-9]*.json' | grep -o -e '\[-\[[^]]*\]-\]' -e '{+\[[^]]*\]+}'
git diff -- service/frontend/public/data/birthday-assets/latest.json
```

- 셋째 명령은 연도 파일(한 줄 JSON)을 `[시점, 값]` 점 단위로 비교한다. `{+[…]+}`는 새로 생긴 점, `[-[…]-]`는 없어지거나 값이 바뀐 점이다.
- `--until`은 일별 계열의 끝 날짜이고, 월별 계열은 그달(2026-10)까지 받는다. 그래서 그 사이 ECOS가 2026-10 이하의 새 달을 발표했으면 그 달이 더해진다.
- `latest.json`의 `generatedAt`은 실행할 때마다 바뀐다.

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 셋째 명령 출력 없음, `latest.json`은 `generatedAt`만 바뀜 | 커밋된 값과 같다 | 키 교체 끝. `git restore -- service/frontend/public/data/birthday-assets/`로 되돌린다 |
| `{+…+}`만 있고 모두 1절 표의 마지막 시점 뒤 달(2026-10 이하) | 키는 정상이고 ECOS에 새 달이 있다 | 되돌리고 5절 월 갱신으로 넘어간다 |
| `[-…-]`가 하나라도 있음 | 커밋된 값이 달라졌다 | 커밋하지 않는다. ECOS 화면 값과 대조해 원인을 확인한다 |
| 끝줄 `EcosError: ECOS 901Y009 오류: INFO-100` | 키가 아직 유효하지 않다 | 파일은 쓰이지 않는다(받기를 마친 뒤에 쓴다). SSM 버전과 ECOS 마이페이지의 키 상태를 본다 |

## 5. 매달 자료 갱신 (수동)

자동 실행은 없다. 저장소에 `.github/`가 없고, Lambda 목록(`service/backend/lambda_handlers.txt`)·배포 스크립트·EventBridge 설정 코드 어디에서도 두 스크립트를 부르지 않는다(2026-10-22 `git grep`). 예약 실행(EventBridge·Lambda)이나 별도 저장소(S3 등)로 옮기면 만들기 전에 [`비용태깅_규칙.md`](../../architecture/비용태깅_규칙.md)를 읽고 `Service=lens` 태그를 붙인 뒤 재조회한다.

시점: ECOS에 서울 아파트 실거래가격지수(901Y089) 새 달이 올라온 뒤 한 번 한다(기존 절차). 키 교체 전에는 하지 않는다.

1. 최신 `main`에서 새 브랜치를 만든다.

   ```sh
   git switch main && git pull && git switch -c chore/birthday-assets-YYYY-MM
   ```

2. 수집한다. `--until`을 주지 않으면 어제(KST)까지 받는다.

   ```sh
   (cd service/backend && AWS_DEFAULT_REGION=us-east-1 uv run --no-project --with boto3==1.35.0 --with requests==2.32.3 python scripts/build_birthday_assets.py)
   ```

   마지막 출력 줄의 `files=`가 연도 파일 수 + 1(2026년 64)이고, 계열별 마지막 시점이 지난번보다 앞으로 갔는지 본다. 1월에 돌리면 그해 연도 파일이 새로 생긴다.

3. 기존 달 값이 바뀌지 않았는지 본다. 4절의 `git diff --stat`·점 비교·`latest.json` 명령을 그대로 쓴다. `{+…+}`(새 달)만 있어야 한다. `[-…-]`가 있으면 원인을 확인하기 전에는 커밋하지 않고, ECOS가 과거 값을 고친 것으로 확인되면 그 사실을 PR 본문에 적는다.

4. 프런트 테스트를 돌린다. 테스트는 이 JSON을 읽지 않으므로 값 확인은 3단계가 맡는다.

   ```sh
   (cd service/frontend && npx tsc --noEmit && npm test)
   ```

5. 바뀐 파일만 이름으로 스테이징하고 확인한 뒤 커밋한다(`git add -A`·`.`·`-u`, `commit -a` 금지). 아래는 2026년 예이고, 1월이면 새 연도 파일과 지난해 파일도 이름으로 더한다.

   ```sh
   git add service/frontend/public/data/birthday-assets/2026.json service/frontend/public/data/birthday-assets/latest.json
   git diff --cached --name-only
   ```

6. PR(`main` 대상)을 올리고 병합한다.
7. 병합된 최신 `main`에서 웹을 배포한다(`cd service/frontend && ./deploy.sh`, 사용자 확인 뒤). 배포는 작업 트리 내용을 그대로 올리므로 먼저 `git status`·`git log`를 본다.

### 1억 원 장면 품목 배수(KOSIS)

정해진 주기가 없다. 품목 자료의 지금 달은 1억 원 장면 `CPI_LATEST.period`(`birthdayCatalog.ts`, 지금 2026-09)와 같아야 하고(`birthdayItemPrices.test.ts`가 확인), `CPI_LATEST`를 갱신하는 스크립트는 저장소에 없다. `CPI_LATEST`를 새 달로 바꿀 때만 같은 달로 다시 받는다.

```sh
(cd service/backend && AWS_DEFAULT_REGION=us-east-1 uv run --no-project --with boto3==1.35.0 --with requests==2.32.3 python scripts/build_birthday_item_prices.py --now YYYY-MM)
```

- 연평균은 12달이 모두 있는 해만 들어간다. 2026년 연평균은 `--now 2026-12` 이후에 생기고, 그때 `birthdayItemPrices.test.ts`의 마지막 연도 확인('2025')도 함께 고친다.
- 그달 KOSIS 값이 없는 품목이 있으면 스크립트가 파일을 쓰지 않고 멈춘다.
- `git diff --stat`으로 `birthdayItemPrices.json` 하나만 바뀌었는지 보고, 지난 해 연평균이 바뀌었으면 커밋 전에 원인을 본다.

## 6. 하지 말 것

- 비영리로 신청한 키로 상업 서비스 자료를 받지 않는다. 승인 전에 새 키를 SSM에 넣지 않는다.
- 키 값을 코드·문서·로그·커밋 메시지·PR·채팅에 붙여 넣지 않는다. `--with-decryption`으로 값을 띄우지 않는다.
- 수집이 실패하면 값을 손으로 채우지 않는다. 생성 JSON을 손으로 고치지 않고, 수기 입력 값·추정치·AI가 만든 값을 쓰지 않는다. 실패하면 커밋된 파일을 그대로 둔다(화면은 그 값으로 계속 동작한다).
