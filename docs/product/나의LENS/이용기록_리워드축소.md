# 이용 기록 중심으로 리워드 축소

2026-10-16 사용자 승인에 따른 변경이다. 이전 완료·리워드 문서의 신규 보상 지급·주간 배지·목표 설명보다 이 문서를 우선한다.

## 사용자 화면

- ‘이용 기록·리워드’를 ‘이용 기록’으로 표시한다.
- 주·월·연 조회, 완료한 날·완료 콘텐츠 수·분야별 집계를 유지한다.
- 주간 요일 체크와 월간 달력의 도장 표시는 `days[].completed_contents > 0`을 기준으로 한다. 신규 콘텐츠인지, 저장했는지와 관계없이 다시 완료한 날도 표시한다.
- 배지 3종·주간 3일 목표·신규 스탬프 지급 안내·보상 대기 안내는 제거한다.
- 단순히 글을 열었다는 이유로 완료 표시하지 않는다. 기존 읽기·웹툰·미디어의 유효 완료 기준과 KST 일자 판정을 유지한다.

## 서버와 호환성

- 완료 원장·최초 완료·열람 신호·저장·추천·형식 통계는 유지한다. 동일 세션의 완료 중복을 막고 계정 잠금과 트랜잭션을 유지한다.
- 스탬프·주간 배지의 INSERT와 재열람 보상 자격 평가를 제거한다. 별도 기존 프로필 배지 7종도 신규 지급을 중단한다.
- 보상 그룹 매핑이 없는 콘텐츠도 안정 콘텐츠 키를 기준으로 완료 기록을 남긴다. 편집 확인한 기존 그룹은 동일 콘텐츠 집계에 계속 활용한다.
- 완료 응답은 `completed`를 유지하며 `reward_evaluation_enabled=false`, `awards=[]`, `reward.status=disabled`, `stamp_awarded=false`를 반환한다. 과거 이벤트 재전송은 저장된 당시 응답을 반환하며 다시 지급하지 않는다.
- 대시보드는 `weekly_activity`에 `/activity?period=week` 결과를 제공한다. `weekly_rewards`는 unavailable로 유지한다. 현재 프론트는 `/rewards`를 호출하지 않는다.
- `/rewards`는 과거 획득 원장의 호환 조회로 보존한다. 진행 수치를 새로 집계하지 않으며 획득 배지는 target, 미획득은 0을 반환한다. 과거의 실제 진행 수치 보존을 의미하지 않는다.
- 기존 스탬프·배지·읽기 이력과 테이블은 삭제하지 않는다. DDL·새 의존성·환경변수 추가는 없다.

## 적용 순서와 검증

서비스 백엔드·CMS·프론트를 함께 반영한다. 서버 반영 후 프론트가 이용 기록 요약을 읽도록 한다. 임시 loopback PostgreSQL에서 완료 기준·동시 요청·재열람·KST·윤년·과거 획득 원장 보존과 계정 통합 흐름을 검증한다. 프론트는 날짜 체크 렌더링·목표 미노출·기존 기간 계산과 API 테스트, 타입·ESLint·빌드를 검증한다.
