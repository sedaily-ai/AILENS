## 이미 구현한 범위와 구조

웹 프론트는 Next.js/React/FSD다. 계정 API는 기존 공개 Python Lambda(handler/service/repository) → 내부 FastAPI/CMS → psycopg2/PostgreSQL 구조를 사용한다. 새로운 Fastify/Nest 서버나 별도 사용자 DB를 만들지 않는다.

로그인 필수 대시보드, 계정 관심사·읽을 시간·문장 서랍·레터 북마크·팔로우·명시적 브라우저 북마크 가져오기, 이용 세션·신호, 관심사/문장 단어 일치 기반 뉴스·레터 추천, 홈 집계, 읽기/웹툰/듣기/영상 선호, 완료 판정·KST 주/월/년 기록·스탬프/배지, 알림 설정·별도 동의·암호화 기기 구독·후보/전달 원장·모의/실제 발송 분기를 구현했다.

레터 저장·해제 안내는 목록·상세·대시보드 공통으로 성공 확정 후 3초 표시하고 공통 북마크 아이콘을 사용한다. 이 보완은 PR #109에 포함됐다. 기존 브라우저 원본은 보존하고 자동 계정 병합은 하지 않는다.

운영 DB 적용·Gateway 등록·서비스 배포·worker 정기 실행·실제 발송은 아직 수행하지 않았다. 알림 기본 모드는 dry_run이다. 의미 유사도 모델은 현재 구현 범위가 아니다.

## 이번 미커밋 보완의 중요한 계약

- 실제 `issue_letter_categories.category_slug`는 VARCHAR(32)다. `content_metadata.py`의 카테고리 배열 비교는 양쪽을 TEXT[]로 맞췄다. 최소 테스트의 TEXT 컬럼만 보면 놓치는 오류였다.
- `content_followup_links`는 앱 역할에 SELECT만 부여한다. 발송 직전 `FOR SHARE`에 UPDATE 권한이 필요했던 문제를 **v1.55의 잠금 전용 함수**로 보완했다.
- `public.lock_notification_followup_sources(TEXT[])`는 마이그레이션 역할 소유의 SECURITY DEFINER다. 고정 search_path, public 테이블 명시, PUBLIC EXECUTE 회수, 앱 역할 EXECUTE만 허용한다. 관련 행 잠금은 발송 재검사 트랜잭션 동안 유지한다. 앱 역할의 후속 관계 쓰기 권한을 확대하지 않는다.
- DB 적용 순서는 **v1.48 →49 →50 →51 →52 →53 →54 →55**. v1.55와 권한 확인이 CMS 새 알림 코드 적용보다 먼저다.

## 로컬 환경 재사용과 검증 경계

별도 스테이징은 없다. 운영 DB 접속·자료 복사 없이 원본 DDL과 변경 기록으로 로컬 기준 스키마를 재구성했다. PostgreSQL 16의 마이그레이션·권한·재실행·자료 보존·롤백·백업 복원과 앱 역할의 계정 처리/모의 알림을 확인했다. 실제 운영 스키마·권한·자료량, vector/pg_bigm/pg_partman, 실제 Cognito와 기기 수신은 별도 확인 사항이다.

- 로컬 컨테이너 `ailens-account-local-pg`는 현재 중지돼 있다. 검증용 DB는 `lens_local`, `lens_dashboard_rehearsal_20261015`, `lens_dashboard_restore_20261015`. 운영 환경변수를 테스트 연결에 사용하지 않는다.
- Python 런타임은 `/tmp/ailens-account-pinned-venv/bin/python`. `/tmp/lens-pytest-offline.py`는 외부 소켓을 차단한다.
- 기존 CMS SQL fixture는 `LENS_ACCOUNT_TEST_DB=loopback`일 때만 localhost의 전용 `lens_local` public 스키마를 재생성한다. 사용자 DB로 연결을 바꾸지 않는다. 리허설 DB와 동시에 실행해도 서로 다른 DB인지 먼저 확인한다.
- 프론트는 `service/frontend`에서 타입·lint·vitest를 실행한다. 기존 사용자가 실행한 3000 서버를 끄거나 해당 .next 위에 빌드하지 않는다. 프로덕션 빌드는 `/tmp` 격리 복사에서 실행한다.
- 합성 JWT·시드·검증 로그·캡처·백업·임시 서버는 `/tmp`에만 둔다. Git/PR에 검증 기록을 넣지 않는다. 실행한 새 임시 서버·컨테이너는 작업 후 정리한다.

## 남은 개발 묶음 — 순서대로 진행

### 1. 배포 패키징·계정 API 경로 연결 준비

- `service/backend/deploy.sh`, `lambda_handlers.txt`, `handlers/user/dashboard.py`, `service/lens-cms-api/deploy.sh`, `service/frontend/deploy.sh`를 실제 코드로 다시 조사한다.
- 현재 dashboard 함수는 Lambda 대응표에 없고 기존 backend 스크립트는 새 함수를 자동 생성하지 않는다. Gateway의 `/api/v2/me/*`와 기존 `/api/archive` 인증·CORS·개인 응답 private/no-store를 배포 시 일관되게 구성할 수 있도록 스크립트/설정 준비가 필요하다.
- top-level `notification_worker.py`가 기존 zip 복사 방식에서 누락되지 않도록 별도 실행 패키지와 정기 실행 설정을 준비한다. 기본 dry_run을 유지하고 실제 발송을 자동 활성화하지 않는다.
- CMS 패키지에 v1.48~55 적용 자료와 안전한 마이그레이션 경로를 제공한다. 현재 deploy.sh가 복사하는 기존 SQL 목록은 v1.47까지다. 복사와 실제 SQL 실행은 구분한다.
- 로컬에서 AWS CLI/SSM/DB 호출을 대체해 패키지·경로·실행 순서·실패 시 중단을 검증한다. 배포 스크립트를 실제 실행하지 않는다.

### 2. 콘텐츠 메타데이터 공급 준비

- 직접 재생 URL·정확한 `media_assets.duration_seconds` 공급 경로, 이슈 레터 `content_reward_groups`, 편집 승인 `content_followup_links`, 실제 `issue_letter_editors` 관계 입력/관리 경로를 마련한다.
- 원문 유사성으로 보상 그룹·작성자·승인 관계를 임의 추정하지 않는다. iframe 완료를 실제 재생 신호처럼 처리하지 않는다.
- 관리자와 파이프라인의 기존 구조를 재사용한다. 준비되지 않은 자료는 완료/보상 대기나 추천 빈 결과로 정확히 표시한다.

### 3. 검증용 UI·문구 정리

- 알림 화면의 로컬 검증 기기 연결, 서버 후보 미리보기, 모의 구독 목록/발송 시각과 개발용 서버 상태 조작을 일반 사용자 화면에서 제외한다. 개발 검증 수단은 별도 테스트나 개발 전용 접근에 남긴다.
- 고정 ‘운영 푸시 발송 준비 중’ 안내와 ‘로컬 검증’ 문구를 서버 상태 기준으로 정리한다. 실발송 비활성 시 ‘알림 발송은 아직 활성화되지 않았어요.’처럼 정확히 안내한다. 합성 구독을 실제 연결로 표시하지 않는다.
- 이미 제거한 브라우저 저장·동기화 준비 중 안내를 다시 넣지 않는다. 계정 저장·수신 동의·실제 권한/기기 연결·오류 안내는 유지한다.
- 사이트의 밝은 화면·LENS 톤과 기능 아이콘·리워드 표시는 유지한다.

### 4. 배포 전 통합 인수·최종 명령 안내

- 계정 A/B, 계정 전환/만료, 다른 기기·탭, 관심 revision 충돌, 가져오기 재생/해제 보존, 부분 형식 기사, 완료 중복 보상, 실제 타입/역할, 알림 모드 변경·철회·lease·unknown·암호화·구독 해제, 전체 프론트 연결을 로컬에서 점검한다.
- 배포 산출물에 테스트 자료·비밀값이 포함되지 않고 신규 함수/worker/SQL/의존성이 누락되지 않는지 확인한다. 쉘 구문 검사와 격리 빌드, 실패/재실행/롤백 경로를 확인한다.
- 마지막에는 사용자가 복사해 실행할 정확한 명령과 실행 디렉터리를 제공한다. 프론트, CMS API, 공개 Lambda API의 세 적용 단위와 DB 선행 단계·worker 후행 단계를 빠뜨리지 않는다.
- DB 백업·버전·실제 자격증명·권한처럼 운영에서만 확인 가능한 항목은 실행 전 preflight로 확인하고 실패하면 배포를 중단하도록 준비한다. 누락된 실제 입력을 임의 성공 처리하지 않는다.
- 배포 스크립트 준비 완료와 실제 운영 인수 완료를 구분한다. 실행하지 않은 운영 검사·배포·실제 발송을 완료라고 보고하지 않는다.
