기준: 2026-10-14, 첫 계정 저장 묶음 위의 두 번째 로컬 구현. 운영 DB·API Gateway·배포 미반영. 이후 완료·리워드 변경은 [세 번째 구현 상태](완료·리워드_구현상태.md)를 따른다.

## 구현한 연결

뉴스/레터 상세 → 실제 제공 형식으로 세션 생성 → visible 시간 보고 → 계정의 약한 열람 신호 → 최근 90일 분야/등록 키워드 집계 → 직접 고른 관심·저장 문장과 함께 추천 → 홈/근거 필터/문장별 관련 뉴스 표시.

- 공개 개인 API는 기존 dashboard Lambda handler의 인증·no-store·오류 계약을 사용한다. 업무 규칙은 services/user/activity.py, recommendations.py, dashboard_summary.py에 분리한다.
- 내부 FastAPI의 `/internal/personal/lens/*`는 내부 토큰 필수이며 activity_repo/recommendation_repo가 PostgreSQL에 접근한다.
- frontend 상세는 검증된 콘텐츠 resolver를 통해 stable key를 받은 뒤 세션을 만든다. 제목·분야·키워드·점수를 보고 payload에 넣지 않는다.
- CMS 상세의 rendition `format`을 추가 제공하므로 포맷 배열에서 일부 항목이 빠져도 실제 형식으로 신호를 보낼 수 있다. 이전 응답에는 기존 인덱스 매핑을 하위 호환으로 사용하고 서버가 제공 형식을 다시 검증한다.
- 공개 상태와 ready rendition의 실제 본문 블록/웹툰 컷/미디어 URL을 확인한다. 이슈 레터는 읽기 형식만 지원한다.

## 이번 신호의 의미

약한 추천용 열람이다. visible 누적 10초 이상 및 서버 세션 경과 10초 이상일 때 views를 갱신한다. 브라우저 숨김 상태와 형식 전환 시 누적을 분리하고 계정 변경·이동 시 요청을 취소한다. visible 값은 클라이언트 보고이므로 사람의 독해·재생을 증명하지 않는다.

- event_id와 payload hash, 세션 seq를 확인하고 동일 요청은 저장한 결과를 재반환한다. 같은 ID의 다른 내용·역순은409, 타인 세션은404, 비공개화한 콘텐츠는404다.
- 이벤트와 세션 진행, view 갱신을 같은 트랜잭션으로 처리한다. 같은 글을 반복 열어도 계정 views는 한 행이고 관심 집계는 서로 다른 content_key 단위다.
- 서버 경과보다 과도한 누적·감소를 거부한다. 초기 시계 여유는 2초, 보고 최소 간격은5초, 세션 만료는24시간이다.
- 초기 한도: 계정 세션 생성 500개/24시간, 새 이벤트 120개/분. 계정 lock으로 동시에 검사하고 재송신은 새 이벤트로 세지 않는다. 이 값은 초기 보호 한도이며 운영에서 별도 조정할 수 있다.
- 응답 completed=false, awards=[], reward_evaluation_enabled=false. 완료·리워드·포맷 선호 순위는 만들지 않는다.

## 집계와 추천 근거

- 뉴스: 공개 publication의 현재 분야 및 admin_extra.body_inline.lenses에 등록된 term/explain 용어를 경량 SQL로 추출한다. 레터: 실제 issue_letter_categories와 issue_letter_topics의 주제 이름을 사용한다. 본문/미디어 대본 전체를 Lambda에 보내거나 후보별 상세 API를 N+1 호출하지 않는다.
- 집계는 최근 90일의 서로 다른 콘텐츠 기준이다. publication_id로 연결 가능한 기존 user_readings를 합치되 같은 콘텐츠를 중복 집계하지 않는다. 기존 article_no를 publication 숫자로 추정하지 않으며 미해결/비공개 자료 수는 coverage로 표시한다.
- 분야/키워드는 현재 공개 등록 메타데이터를 재조회한다. 과거 열람 당시 메타데이터 버전의 스냅샷 분석이 아니다.
- 저장 문장은 본인의 전체 user_archives에서 SQL로 단어를 집계한 뒤 NFKC/소문자·조사/불용어 정리로 상위8개를 선택한다. 원문 문장 전체는 추천 후보 요청·URL·외부 모델·일반 로그로 전달하지 않는다. 홈 요약의 본인 최근 문장3개 반환과는 별도다.
- 추천 이유는 직접 선택(selected), 관찰(observed), 저장 문장(saved_sentence), 명시적인 최신 fallback으로 구분한다. method=exact이며 의미 유사도·품질 확률이 아니다.
- 공개 후보 전체에서 관심 조건을 먼저 적용한 뒤 최근 최대200개를 채점한다. 뉴스는 문장4점/키워드3점/분야2점의 초기 규칙과 발행일 정렬을 사용한다. 등록 용어에만 일치하는 글도 후보에 들어온다. 미지원/비공개/삭제 후보는 반환하지 않는다.
- 뉴스는 계정의 이미 열람한 자료와 모든 저장 원문을 제외한다. 전체 뉴스에만 근거가 없을 때 최근 공개 뉴스 fallback을 명시한다. 근거별 필터·문장 관련 글에는 무관한 최신 글을 채우지 않는다.
- 레터는 동일 근거의 규칙 순위에 미열람을 우선하며 실제 read_minutes의 합계로 5/10분 예산을 적용한다. 길이를 모르면 시간 제한 묶음에서 제외하고, 무제한에서는 길이 미확인으로 표시한다. 관심과 맞는 레터가 없으면 빈 결과다.
- 확인된 작성 에디터 메타데이터가 없는 대시보드 카드에 주제만으로 작성자를 만들어 표시하지 않는다. 에디터 팔로우 계정 저장은 이번 범위 밖이다.

## 공개 API

| 경로 | 이번 구현 |
|---|---|
| POST `/api/v2/me/activity/sessions` | `{content_key,format}` →201 세션·rule_version·reward_evaluation_enabled=false |
| POST `/api/v2/me/activity/events` | event_id/session_id/seq/progress 또는 ended/누적 visible_ms →200 accepted/viewed/중복 결과 |
| GET `/api/v2/me/recommendations` | kind=news/letter, 뉴스 reason=all/category/keyword/sentence, limit, 레터 minutes |
| GET `/api/v2/me/sentences/{id}/recommendations` | 본인 문장 관련 뉴스 최대3개, 기본3, 미일치 빈 배열 |
| GET `/api/v2/me/dashboard` | 뉴스4/레터3/최근 문장3, 계정 설정·관심 집계·저장 총수 및 상태 |

이벤트의 active_ms는0만, 컷/소비 구간 배열은 빈 값만 지원한다. client_occurred_at은 집계 날짜로 쓰지 않는다. scroll_ratio는 범위를 확인하지만 완료 판단에 쓰지 않는다. 서버 완료·미디어 소비 검증을 이번 기능에 포함한 것으로 해석하지 않는다.

홈 집계는 전체 의존성 실패를503으로 반환하고, 일부 추천/저장 영역 실패는 status=error와 data=null로 구분한다. weekly_rewards/notifications/followed_editors는 unavailable이다. 아직 없는 리워드를0일로 채우지 않는다.

## 프론트 연결

- 홈·뉴스 근거 필터·추천 레터·관심 흐름은 서버 응답을 사용하며 프론트 점수로 다시 정렬하지 않는다. 홈 최근 문장과 저장 총수도 집계 응답에 연결한다.
- 관련 글은 문장 ID로 별도 서버 추천을 조회한다. 문장 삭제 뒤 선택 상태를 안내하고 홈/문장 추천 근거를 다시 조회한다.
- 관심·읽을 시간 변경, 서랍/북마크 변경, 계정 view 수락, 브라우저 포커스 복귀에 다시 조회한다. 계정 설정도 포커스 복귀 시 재조회한다.
- 계정/요청 키를 분리하고 늦은 응답을 취소한다. 신규 개인 API의401과 세션 없음은 개인 화면을 내리고 로그인으로 이동한다. 정상 빈 추천과 조회 실패를 구분한다.
- 비로그인 브라우저 신호는 기존 로컬 기록만 남기며 로그인 계정에 자동 합치지 않는다.
- 레터의 기존 브라우저70% 읽음 표시·저장 목록의 ‘아직 안 읽은’ 필터는 보존한다. 추천 카드의 서버 viewed 및 90일 관심 집계는10초 약한 신호로 구분한다. 서버 완료 기반 기간/리워드와 저장 목록의 계정 열람 필터 전환은 후속이다.

## SQL과 로컬 실행

- v1.48 이후 `docs/architecture/lens-erd-src/lens_schema_v1.49_2026-10-14.sql`: user_content_views, user_content_sessions, user_content_events 및 owner/time 인덱스·FK·unique·권한. 아직 운영 미적용.
- 사용한 로컬 진입은 첫 묶음의 `local_account_api.py`다. POST 전달도 추가했다. 제품 코드에 인증 우회나 테스트 JWT를 추가하지 않았다.
- 로컬 DB 테스트는 `LENS_ACCOUNT_TEST_DB=loopback`을 명시하고 전용 lens_local DB를 사용한다. fixture는 최소 기존 스키마를 재현해 격리 schema를 초기화하므로 개인 작업 DB에 실행하지 않는다.
- 신규 테스트는 tests/test_activity_recommendations.py, backend tests/test_lens_recommendations.py 및 프론트 dashboardApi/activityApi 어댑터 테스트다. 검증 로그/화면/합성 JWT는 저장소 밖 임시 파일로만 둔다.
