# 개인화 알림·동의·푸시 구독·발송 실행 계획

목표: 계정 설정 저장 → 별도 동의 → 기기 연결 → 하루 최대1묶음 후보/발송 원장 → 서버 상태 UI.
구조: 기존 공개 Lambda/service/repository → 내부 CMS FastAPI → PostgreSQL. 별도 일회 실행 worker와 provider adapter를 사용한다.
운영 DB·AWS·배포·실제 외부 발송·커밋·push는 제외한다. 기본 mode=dry_run, 로컬 합성 구독/receipt로 검증한다.

## 설계

- settings revision·동의 policy_version·브라우저 permission·구독 active·발송 상태를 분리한다. 기본 유형 꺼짐, sentenceSource=false. 동의 철회는 구독과 대기 작업을 비활성화한다.
- endpoint는 제공자 허용 목록·HTTPS·키 길이/P-256 유효성을 검사하고 Fernet로 암호화한다. 임의 endpoint를 조회하지 않는다. 같은 endpoint의 계정 전환은 키 소유 확인 후 이전 대상 작업을 취소한다.
- SQL owner/date/mode unique·target lease로 중복을 제한한다. 전송 직전 조건을 재검사하며 timeout/중단의 결과 미확정은 자동 재전송하지 않는다.404/410은 구독 종료,429/5xx는 최대3회 제한 재시도한다.
- schedule은 선택한 IANA zone,08:00~20:59,threeDays 월수금,weekly 선택요일. 하루1묶음과 전송/미확정 이후24시간 보호를 함께 적용한다. DST/시간대 변경도 동일 원장으로 제한한다.
- briefing은 선택한 source만 읽고 정확한 개인 추천 후보를 사용한다. 무관한 최신 fallback은 없다. followups는 현재 저장 원문/레터와 편집 승인된 관계만 사용한다. weekly는 KST 지난주 읽은 날/현재 저장 수를 사용한다.
- payload는 콘텐츠 key·유형·집계 기간만 저장하며 문장 원문·endpoint·키는 응답/로그/알림에 노출하지 않는다. 실제 전송 승인과 기기 수신은 별개이며 dry_run을 sent로 기록하지 않는다.
- live용 service worker/브라우저 subscribe/provider 경로를 만들되 로컬 검증에서 Notification 권한이나 외부 PushManager 등록을 호출하지 않는다. 화면에서 로컬 검증 기기임을 구분한다.
