# 콘텐츠 완료·기간 기록·리워드 — 세 번째 개발 묶음

> 2026-10-14 추가 구현: 계정별 형식 선호·추천/알림 연결, 에디터 팔로우, 서버 완료 읽음 필터, 사용자 선택 북마크 가져오기를 로컬 구현했다. 현재 계약은 [형식 선호·계정 연결](형식선호·계정연결_구현상태.md)의 v1.53·API를 따른다. 아래 이전 단계의 미구현 표시는 해당 구현으로 대체하며 운영은 미반영이다.

> 이후 [백엔드 리뷰 보완](백엔드_리뷰_보완.md)을 적용했다. 콘텐츠 조건·서랍 검사·알림 metadata/lease·worker 회전은 해당 계약을 우선한다. 운영은 미반영이다.

2026-10-14 로컬 구현. 앞선 계정 저장·추천 묶음 위에 추가했으며 운영 DB·API Gateway·배포는 반영하지 않았다. 기존 Python Lambda → 내부 FastAPI → psycopg2/PostgreSQL 구조를 유지한다.

## 규칙 completion-v1

기획의 권장 초기안을 개발 규칙으로 사용한다. 현금성 포인트나 교환 혜택은 없다. 출시 전에는 이 임계값과 동일 이슈 매핑 정책을 제품 담당자가 확정해야 한다.

| 형식 | 완료 조건 | 부족한 자료 |
|---|---|---|
| 읽기 | 등록된 실제 본문 영역 도달80% 이상, visible 누적30초 및 서버 경과30초 | 본문이 짧아도30초. 읽기를 증명하는 시험이 아닌 진행 기준 |
| 웹툰 | 실제 서버 컷 ID80% 이상, visible10초 및 서버 경과10초 | 컷이 없는 목업은 제외. 프론트는 로드된 컷의 충분한 화면 노출을1초 이상 관찰 |
| 팟캐스트·영상 | 등록된 길이의 소비 구간 합집합80%, 이에 맞는 active 시간 | 서버 길이 없음은 MEDIA_METADATA_REQUIRED. YouTube/네이버TV iframe은 DIRECT_MEDIA_REQUIRED |

- 클라이언트 visible/active는 비음수·증가·서버 시간 및 visible 범위로 제한한다. 구간은 유한수·길이 범위·최대100개, 이전 소비 구간 유지와 최대2배속 증가를 검사한다. 겹친 재생은 한 번만 센다. 위치를 끝으로 이동하거나 ended 선언만 보내도 완료되지 않는다.
- 프론트는 활성 형식의 실제 본문/컷/미디어를 측정한다. 숨긴 화면·비활성 형식·seek 점프·조작 없는 자동 재생·미디어 원본 URL 불일치는 제외한다. 완료 보고가 서버에 확인될 때까지 누적을 잠시 멈춰 지연 응답 후의 과도한 증가를 방지한다.
- 세션은 생성 당시 실제 공개 콘텐츠의 본문 fingerprint·컷·길이·URL·주 분야·보상 그룹을 snapshot한다. 빈 본문은 새 이용 세션에서400으로 거부하고 메타데이터에는 BODY_REQUIRED를 표시한다. 완료 시 현재 메타데이터와 다르면409 CONTENT_CHANGED, 비공개화하면404다. 새 세션에서 다시 확인해야 한다.
- 세션/이벤트 소유권·hash·seq·24시간 만료·5초 최소 간격·기존 계정 한도를 유지한다. 동일 이벤트는 이전 결과를 반환한다. 규칙이 없는 과거 visible-v1 세션은 완료/보상을 만들지 않는다.
- 클라이언트 보고는 위조 불가능한 증명이 아니다. 서버는 실제 콘텐츠·시간·순서·중복·범위를 검사하지만 사람의 독해나 물리적 재생을 보증하지 않는다.

## 원장과 지급

완료·최초 그룹 완료·하루 스탬프·주간 배지·이벤트 결과를 같은 cursor/트랜잭션에서 저장한다. 계정 row lock과 DB unique로 동시 기기에서도 한 번만 지급한다. 실패하면 모두 rollback한다.

- 동일 publication의4형식은 `publication:ID` 한 보상 그룹이다. `content_reward_groups`의 명시적 그룹으로 재게시/이슈 레터와 원문을 묶을 수 있다. 명시적 NULL은 대기다.
- 이슈 레터는 기본 보상 그룹을 임의 추정하지 않는다. 매핑 전에도 유효 완료 원장은 남기되 reward.status=pending, pending_reason=REWARD_GROUP_REQUIRED, stamp_awarded=false다. 매핑 후 새 세션에서 완료해야 보상하며 과거 기록을 소급 지급하지 않는다.
- 새 보상 그룹 최초 완료의 KST 날짜에 하루 최대1스탬프를 지급한다. 같은 글 반복·형식 변경·북마크·알림 설정·과거 브라우저70% 표시는 스탬프를 만들지 않는다.
- steady_week/꾸준한 시선: 월~일의 스탬프3일. discovery_week/새로운 발견: 그 주 최초 완료의 주 카테고리3개. 보조 분야·재열람으로 분야 수를 부풀리지 않는다.
- revisit_week/다시 보는 깊이: 이미 완료하고 저장해 둔 서로 다른2그룹을 별도 세션에서 다시 완료. 같은 그룹의 직전 완료 후 최소30분이 지나 세션을 시작해야 하며, 현재 북마크 또는 서랍 저장 시각이 재열람 세션보다 앞서야 한다. 뉴스는 저장 문장 원문의 slug/rendition, 레터는 bookmark로 확인한다. 삭제된 저장의 과거 이력은 새 재열람 평가에 사용하지 않는다.
- 배지는 `(user_id,week_start,badge_id)` unique이며 버전 변경/재조회로 재지급하지 않는다. 휴식·저장 삭제·메타데이터 변경으로 기존 획득 원장을 삭제하지 않는다.
- 보상 날짜는 서버 수신 시각을 Asia/Seoul로 변환한다. 클라이언트 날짜는 사용하지 않는다.

## SQL / API

v1.48/49 다음에 `docs/architecture/lens-erd-src/lens_schema_v1.50_2026-10-14.sql`을 적용하는 설계다. 파일만 추가했으며 운영 적용은 하지 않았다.

- 기존 user_content_sessions: completion_rules JSONB, active_ms, scroll_ratio, viewed_panel_ids, consumed_ranges 추가. 기존 행은 빈 규칙으로 남는다.
- media_assets: nullable duration_seconds 추가. 공개 개인 API에서 길이를 받지 않는다. 기존 내부/admin CMS의 body_inline 또는 lenses 항목에 측정한 duration_seconds를 전달하면 `_write_format_body`가 저장한다. 잘못된 타입/길이는 거부하고 파일 URL을 바꾸면 이전 길이를 초기화한다. 기존 모든 파일을 다운로드/측정하는 backfill과 파이프라인 길이 공급은 별도 운영 인수 사항이다.
- content_reward_groups: 편집 확인한 content_key→group_key 매핑. 서비스 계정은 읽기 전용이다. 매핑 관리 API/관리자 UI를 새로 만든 것은 아니다.
- user_content_completions: 세션별 완료, 그룹·주 분야·KST 일자·규칙·최초/재열람 snapshot.
- user_content_first_completions: owner/group 최초 원장. user_daily_stamps: owner/day unique. user_weekly_badges: owner/week/badge unique.
- content_completion_coverage: 실제 수집 시작 서버 시각. 운영 적용 시 새로 기록되며 예전 사용자 기록을 완료로 변환하지 않는다.

| 공개 경로 | 응답 |
|---|---|
| POST `/api/v2/me/activity/sessions` | 기존201에 completion 규칙 snapshot, rule_version=completion-v1, reward_evaluation_enabled 추가 |
| POST `/api/v2/me/activity/events` | completed/reward/awards/rule_version. not_eligible/pending/awarded/already_awarded 구분 |
| GET `/api/v2/me/activity?period=week\|month\|year&anchor=YYYY-MM-DD` | 영역 wrapper `{status,data,error}`. anchor 생략은 서버 KST 오늘 |
| GET `/api/v2/me/rewards?week=YYYY-MM-DD` | 월요일 시작 주의 스탬프·실제 배지·진행값. 생략은 현재 주 |
| GET `/api/v2/me/dashboard` | weekly_rewards를 unavailable 대신 실제 주간 영역으로 집계 |

개인 JWT sub/no-store/내부 토큰 가드를 유지한다. 신규 내부 GET은 `/internal/personal/lens/activity`와 `/rewards`다. 공개 API Gateway 연결과 Lambda 설정은 별도다.

기간은 주7일·월28~31일·연365~366일을 원장 전체 SQL로 집계한다. completed_contents는 기간 내 서로 다른 확인된 그룹(미확인 자료는 content_key), read_days는 완료가 있었던 날짜, stamp_days는 지급 날짜다. 월별 집계도 전체 SQL이며 최신200개 목록으로 계산하지 않는다. 미확인 그룹이 이후 매핑되더라도 과거 snapshot은 소급 수정하지 않으므로 pending 자료와 확인 그룹이 각각 집계될 수 있다.

미래 anchor·잘못된 날짜/기간·수집 시작 연도 밖의 요청은400이다. 연도 경계의 주는 인접한 이전 연도 날짜를 허용한다. days에 future/covered를 표시하고 연간 months에도 수집 전/미래를 구분한다. 조회는 완료나 배지를 생성하지 않는다.

## 프론트 연결

- 상세 useNewsReadingSignal이10초마다 누적 진행을 순서대로 보고한다. 동일 event_id/payload로 한 번 재시도하며 확인되지 않은 저장을 성공 처리하거나 다음 seq로 건너뛰지 않는다. 계정/형식/이동 시 취소한다.
- 홈 오른쪽 주간 스탬프, records의 주/월/연 이동·월 달력·연 월별 집계·주별 실제 배지를 서버에 연결했다. 달성 화면 예시와 연동 대기 표시는 제거했다.
- 로딩/재시도/빈0건/수집 전/미래/보상 그룹 대기를 구분한다.401은 기존 중앙 로그인 만료 처리로 연결한다. 계정 키와 요청 키로 늦은 응답을 차단한다.
- 추천 레터 카드의 읽음 표시는 서버 completed를 사용한다. 기존 상세70% 로컬 열람 표시 및 저장 레터 목록의 브라우저 unread 필터는 하위 호환으로 남아 있으며 완료 원장/리워드와 별개다.
- 계정 완료 수락·포커스 복귀 시 대시보드와 기간 기록을 재조회한다. 배지는 선택한 주의 실제 획득·진행값을 보여주고 월/년은 기간 조회만 확장한다.

## 후속/운영 인수

운영 SQL·권한·Gateway 연결·공개/내부 API 및 프론트 배포는 미실행이다. 미디어 길이 측정 공급/기존 파일 backfill·같은 이슈의 편집 매핑과 정책 확정이 필요하다. raw 이벤트 정리 작업은 없으며 완료가 연결된 세션/원장은 과거 보상 보존을 위해 임의 삭제하면 안 된다. 실제 인코딩 영상의 브라우저 재생 점검과 iframe 공급자 SDK 연동은 운영 인수에서 추가한다. 푸시 설정·동의·발송은 후속 [네 번째 묶음](알림·푸시_구현상태.md)으로 로컬 구현했다. 완료/배지 지급 자체는 알림을 생성하지 않는다.
