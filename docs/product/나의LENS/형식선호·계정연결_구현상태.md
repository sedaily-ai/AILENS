# 형식 선호와 계정 연결 보완

2026-10-14 로컬 구현. 이후 [전체 리뷰 보완](백엔드_리뷰_보완.md)의 v1.54·알림 후보/순서·실제 작성자·이관 재시도 계약을 함께 적용한다. 기존 공개 Python Lambda → service/repository → 내부 FastAPI → PostgreSQL 구조를 확장했다. 운영 DB·API Gateway·배포·외부 푸시 발송은 수행하지 않았다.

## 계정별 형식 선호

- GET `/api/v2/me/format-preference` 및 dashboard의 `format_preference` 영역으로 제공한다. Cognito ID token의 검증된 sub만 owner로 사용하며 개인 응답은 no-store다.
- `format-v1`, 최근 90일의 뉴스(publication) 이용을 사용한다. 읽기만 제공하는 이슈 레터는 4형식 비교에서 제외한다.
- 읽기는 visible 10초, 웹툰은 visible 10초와 실제 컷 노출, 팟캐스트·영상은 visible/active 10초 또는 서버 완료를 확인한다. 실제 제공 형식으로 생성된 서버 세션과 완료 원장만 사용한다. 클라이언트의 분석 결과·점수·선호 형식을 저장 요청으로 받지 않는다.
- 같은 content_key/format의 여러 세션은 한 근거로 합친다. 완료가 있으면 3점, 유효 열람만 있으면 1점이다. 반복 이용·장시간 재생이 무한 가점을 만들지 않는다. 원문이 현재 비공개·삭제·미래 발행 상태면 제외한다.
- 서로 다른 뉴스 3편 미만이면 `status=insufficient_data`, 대표 형식과 순위를 표시하지 않는다. 3편 이상은 `ready`이며 동률은 같은 순위다. 1위가 동률이면 `preferred_format=null`이다.
- distribution은 letter/webtoon/podcast/video 4행이다. 각 행은 viewed_contents/completed_contents/score/share/rank를 반환한다. share는 가중치 비율이며 취향 확률·완독률이 아니다.
- 분석 결과를 별도 테이블에 복사하지 않고 기존 세션·완료 원장에서 조회한다. 과거 브라우저 읽음·날짜 없는 이력은 분석 근거로 변환하지 않는다.

프론트 홈의 ‘내가 자주 고른 시선’에서 실제 계정 기록·비율·순위·표본 부족·분석 기준을 표시한다. 사이트의 밝은 배경과 파란 강조색을 사용하며 장식 이모지는 추가하지 않았다.

## 추천·알림 연결

추천 버전은 `exact-format-v2`다. 기존 분야·등록 키워드·저장 문장 일치와 미열람 우선 정책을 유지한다. 관심 점수가 같은 후보에서 실제 제공 형식과 선호 가중치를 비교한다. 관심이 맞지 않는 글을 형식만으로 개인화 추천하지 않는다.

- 카드의 `preferred_format`은 해당 콘텐츠에서 실제 제공하는 형식 중 가장 높은 근거가 있는 형식이다. 제공하지 않는 최상위 형식을 강제로 열지 않는다. 지원 형식 내 최고 점수가 동률이거나 표본이 부족하면 강제 선택을 하지 않는다.
- publication의 선호 형식 링크는 `/{분야}/{KST연}/{월}/{일}/{slug}?format=webtoon`처럼 정본 주소를 사용한다. 공개 CMS와 같은 발행일·원문 category 규칙을 사용한다. `admin_extra.body_inline.category`가 사전의 분류명이 아니면 `news`다.
- 옛 `/lens/{slug}` 리다이렉트는 쿼리를 버리므로 선호 형식 링크에 사용하지 않는다. 정본 기사 화면에서 format 키로 실제 lenses 배열의 형식을 찾는다. 기존 `?v=N` 지정은 우선하며 모르는 형식은 기본 화면을 유지한다.
- 뉴스 추천 카드에는 이어볼 형식을 표시하고, 이슈 레터는 기존 읽기 주소를 유지한다.
- 알림 후보도 같은 선호 분석을 사용하며 관심 점수를 먼저 유지한 뒤 형식 가중치로 정렬한다. 편집 승인 후속 글의 지원 형식도 확인한다. 주간 기록·별도 수신 동의·기기 구독·발송 일정은 기존 정책을 유지한다.
- 계획 원천 fingerprint에 형식 선호 결과를 포함한다. 전송 전에 근거가 바뀌면 기존 계획을 취소한다. 실제 푸시 클릭은 `/my-lens#ml-news`로 이동해 개인화 링크로 이어진다.
- 에디터 팔로우만으로 브리핑 알림의 활용 기록을 자동 확대하지 않는다. 기존 사용자가 선택한 category/keyword/sentence source를 유지한다. 기본 dry_run과 실제 발송 차단을 유지한다.

## 계정 에디터 팔로우

GET `/api/v2/me/followed-editors`, PUT/DELETE `/api/v2/me/followed-editors/{editor_slug}`를 제공한다. slug는 기존 letter_editors 사전을 사용하며 저장 FK는 안정적인 editor ID다.

- 직접 고른 관심을 팔로우로 덮어쓰지 않는다. 서로 다른 로그인 계정과 다른 기기의 조회는 서버 저장을 기준으로 한다.
- 반복 PUT/DELETE는 멱등이며 비활성 에디터는 신규 팔로우를 거부한다. 기존 비활성 팔로우는 상태를 표시하고 해제할 수 있다.
- 레터 추천에는 실제 `issue_letter_editors`의 작성자 관계만 사용한다. 주제 유사성으로 작성자를 만들어 넣지 않는다. 비활성 작성자는 팔로우 추천 근거에서 제외한다.
- 기존 `lens-letter-editors`는 삭제·변경·자동 계정 가져오기하지 않는다. 공용 키를 현재 계정의 팔로우 상태로 읽지 않는다.
- 계정별 로딩·실패·중복 클릭·로그아웃·늦은 응답을 처리한다. 같은 화면 이벤트·다른 탭 revision·포커스 복귀에서 다시 조회한다.

## 서버 읽음 필터

GET `/api/v2/me/letter-bookmarks?read=all|unread|completed`를 지원한다. 읽음은 해당 계정의 `user_content_completions` 존재 여부다. 보상 그룹이 대기여도 완료 원장이 있으면 완료한 레터다.

- content.completed를 계정 목록에 반환하고 같은 완료 조건으로 목록·total을 계산한다.
- cursor를 owner/q/read에 묶는다. 다른 계정이나 읽음 필터의 cursor 재사용은 400이다.
- 홈과 내 서랍의 ‘아직 안 읽은 레터’는 서버 unread API를 호출한다. 목록은 최근 저장순이며 완료 표시도 서버 기록을 사용한다.
- 기존 브라우저 70% 열람 표시로 서버 완료를 추정하지 않는다. 공개 레터 목록·상세의 하위 호환 읽음 표시는 별도로 유지한다.

## 사용자 선택 브라우저 북마크 가져오기

POST `/api/v2/me/imports/bookmarks`:

```json
{"source":"browser-bookmarks-v1","import_id":"6e4639eb-4239-4415-82ab-c8ea3e6a9d19","slugs":["example-letter"]}
```

현재 범위는 레터 북마크만이다. 에디터·관심·읽음·알림 동의를 자동 가져오지 않는다. 기존 포괄 `/imports`·Idempotency-Key 헤더 제안과 구분하며 이 API는 body의 UUID와 계정별 선택 목록 hash를 사용한다.

- 내 서랍 위에서 브라우저 원본 목록을 설명하고 체크한 항목만 현재 계정에 가져온다. 1~200개, 정규화·중복 제거 후 검증한다. user_id 같은 추가 입력을 허용하지 않는다.
- 현재 공개·미삭제·발행 시각 도래 레터만 수락한다. 비공개/없는 slug는 원문 정보를 노출하지 않고 rejected에 남긴다.
- 사용자 row lock, 북마크 복합 PK와 가져오기 unique로 같은 계정의 동시 호출을 직렬화한다. 정상 자료와 처리 영수증을 같은 transaction으로 저장한다.
- 같은 import_id의 다른 선택은 409다. 같은 선택 목록을 새 UUID로 재전송하면 이전 수락 항목은 재생성하지 않고 거부 항목만 재검사한다. 새로 수락할 항목이 없으면 `replayed=true`다. 같은 UUID의 재시도는 최초 결과를 재생하며 다른 선택은409다. 이후 사용자가 해제한 북마크는 같은 목록의 재생 요청으로 재생성하지 않는다.
- 기존 북마크의 saved_at은 바꾸지 않는다. 가져오는 항목은 서버 반영 시각을 사용하며 과거 저장일을 지어내지 않는다. 빈 목록을 서버 전체 삭제로 해석하지 않는다.
- 처리 성공·재시도·일부 거부·장애 모두 `lens-letter-saved` 원본을 삭제하거나 덮어쓰지 않는다. 실패 항목만 따로 선택하면 별도 선택 목록으로 검토할 수 있다. 최근24시간의 새 UUID 요청은 재생 요청을 포함해 계정당 최대20회다. 동일 UUID 재시도는 추가 횟수를 쓰지 않는다.
- 응답은 import_id/replayed/accepted[{slug,content_key}]/rejected[{slug,code}]다. 가져오기로 열람·완료·스탬프·푸시 동의를 생성하지 않는다.

## SQL·파일과 운영 인수

v1.48~52 다음에 **lens_schema_v1.53_2026-10-14.sql**, **lens_schema_v1.54_2026-10-14.sql**을 순서대로 적용한다. 파일로 추가했으며 운영에는 적용하지 않았다.

- user_followed_editors: user/editor FK CASCADE, 복합 PK, followed_at.
- user_lens_imports: 계정/import UUID PK, 계정/snapshot_hash/처리시각 조회 인덱스, 처리 result JSONB·imported_at. v1.54에서 snapshot UNIQUE를 제거해 새 UUID 재생도 입력에 묶는다. 해제 보존을 위한 영수증을 임의 삭제하면 과거 가져오기가 북마크를 복원할 수 있으므로 보존 정책을 별도 확정한다.
- completions_owner_content_idx: 서버 읽음 필터의 계정/content_key 조회 인덱스.
- CMS format_preference_repo.py/account_connections_repo.py 및 기존 추천·알림·계정 router 확장.
- 공개 dashboard service, recommendations, notifications, dashboard_summary 확장.
- 프론트 계정 API·저장/팔로우 훅, FormatPreference·BrowserBookmarksImport·내 서랍 필터·기사 형식 이동 연결.

운영 반영에는 실제 스키마·DB 역할 권한, 개인 API Gateway 경로, CMS/공개 API/프론트 배포, 실제 Cognito 계정과 기기 인수가 남아 있다. 푸시 정기 worker·키 공급·실제 수신 인수도 기존대로 남아 있다. 의미 유사도 추천·품질 평가 모델은 이번 범위가 아니다.
