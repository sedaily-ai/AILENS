# 나의 LENS 두 번째 개발 묶음

정본: 백엔드_개발_인수인계.md, ../../architecture/나의LENS_백엔드_API계약.md.
목표: 계정 이용 신호 → 90일 분야/등록 키워드 집계 → 직접 관심/저장 문장과 함께 뉴스·레터 추천 → 홈 집계와 프론트 연결.
기존 Python Lambda service/repository → 내부 FastAPI → PostgreSQL 구조를 유지한다.
운영 DB·AWS·배포·Git 커밋/push는 수행하지 않는다. 이전 미커밋 첫 묶음 위에서 이어 구현한다.

## 작업

- [x] v1.49 SQL: user_content_views, user_content_sessions, user_content_events. 계정 FK, 세션 소유권, event/seq unique와 payload hash, 트랜잭션.
- [x] 공개 activity sessions/events: 안정 콘텐츠 키와 실제 제공 형식 검사. 서버 시간 기준 10초 유효 visible 약한 신호만 집계. 반복/역순/만료/과도한 증가 거부. 완료·스탬프 지급 없음.
- [x] CMS recommendation_repo: 서버 메타데이터 경량 일괄 조회. 90일 서로 다른 콘텐츠 집계, legacy publication ID만 안전하게 병합. 저장 문장 입력은 본인 DB에서만 조회.
- [x] Lambda recommendations service: 정확한 문자열 일치와 직접 관심/관찰/저장 문장 이유 분리. 읽은 뉴스와 저장 원문 제외, 문장별 추천 3개에 최신 fallback 금지. 레터는 실제 read_minutes 합계로 예산 적용.
- [x] dashboard API: 뉴스4/레터3/최근 문장3, 계정 설정·관심 집계·저장 총수. 정상 빈 값/장애/미지원 리워드·알림 구분.
- [x] 프론트 상세의 visible 신호와 활성 포맷을 activity에 연결. 숨긴 탭·브라우저 백그라운드는 시간에 포함하지 않음. 제목/분야/키워드는 서버가 조회.
- [x] 홈/근거별 추천/문장 관련 뉴스에 서버 응답 사용. 서버 순위를 프론트에서 다시 계산하지 않음. 설정·서랍·북마크 변경 후 재조회, 401·오류·계정 전환 처리.
- [x] 격리 PostgreSQL·로컬 JWT·외부 연결 차단 검증 및 기존 첫 묶음 회귀. 근거가 등록 키워드에만 있는 후보, 과거 기록, 중복, 타인 세션/문장, 예산 합계와 빈 추천을 확인.

## 범위

visible 시간은 클라이언트 보고에 기반한 추천용 약한 신호이며 실제 사람의 독해/재생/완료 증명이 아니다. 미디어 소비·컷 완료·리워드 원장은 다음 묶음. 의미 모델·벡터 DB·추론 호출·푸시 발송은 추가하지 않는다. 기존 브라우저 자료 자동 가져오기는 없다.
