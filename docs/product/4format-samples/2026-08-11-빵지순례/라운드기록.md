## 라운드 2 (2026-08-20)

**계기**: 14F(SBS 디지털 뉴스 채널로 보이는 곳) 영상 4편의 스크립트를
같이 분석해봄 — 오프닝 훅 유형, 비교 수치를 기준값과 함께 제시하는 방식,
전환 브릿지 문구, 여운형 클로징 같은 패턴을 확인. 이걸 영상 프롬프트에
반영해서 라운드1의 지어낸 수치 문제를 근본적으로 고쳐보기로 함
(`docs/product/4format-persona-system.md` §4의 "구조적 위험" 참고).

**문제** (이슈 트래커 #4, R1에서 발견): chart 컷이 원문에 없는 비교 수치를
지어냄("빵트레일런 참여 100→150"). 원인은 chart라는 형식 자체가 "두
지점"을 요구하는 구조라, 없으면 만들어서라도 채우려는 경향.

**솔루션**: video v2→v3 — chart는 원문에 실제 비교 수치가 있을 때만 쓰고
없으면 highlight/diagram으로 대체하라는 규칙 신설(아래 "v3에서 추가한
것" 참고).

**검증**: 재생성 결과 chart 컷에 원문 실수치(고양 22%·대전 18%)만 사용 —
지어낸 수치 재현 안 됨. 이슈 트래커 #4 해결로 표시.

**프롬프트 버전**: video v2→v3

**v3에서 추가한 것**
- "비교 수치(chart 컷 전용)" 절 신설 — chart는 원문에 실제 비교 가능한
  수치가 있을 때만 쓰고, 없으면 highlight/diagram으로 대체(대비할 숫자가
  없다고 지어내지 않는다)를 명시. 비교 수치는 기준값을 먼저 제시하고 이번
  값을 얹는 순서로 쓰라고 지시(14F 거제 폭우 영상의 "평소엔 50mm만 와도"
  패턴 참고)
- "전환 브릿지" 절 신설 — 컷 간 나레이션이 사실 나열이 아니라 앞 컷과
  이어지는 접속·전환 표현으로 시작하게 지시
- [컷9] 클로징 지침 변경 — 요약이 아니라 여운 또는 질문으로 마무리
- "절대 하면 안 되는 것"에 "chart 컷을 채우려고 대비 수치를 지어냄"을
  별도 항목으로 명시(기존 "원문에 없는 수치 생성 금지"만으로는 라운드1에서
  안 지켜졌음)
- 체크리스트 3항목 추가(chart 수치 원문 대조 여부, 전환 표현 여부, closing
  여운/질문 여부)

**한 것**
- 새 프롬프트로 영상 각본 재생성(GPT-4o) → 스키마 오류 2건 발견해서
  수동으로 고침(§산출물의 라운드2_산출물/영상_각본.md 상단 참고)
- 로컬 Remotion 프로젝트(`콘텐츠/프로젝트/ailens/video`)로 실제 TTS(Google
  Cloud TTS, ko-KR-Chirp3-HD-Kore) + 렌더까지 완결 — 라운드1은 별도 세션에서
  만들어둔 영상을 그냥 재사용했지만, 라운드2는 이번에 고친 각본이 실제로

  파일은 지우지 않고 S3에 남겨둠 — `lens-bread-video.mp4`)

v3 프롬프트엔 "구어체 ~요체"라고만 적어놔서 모델이 제일 만만한
"-습니다"로 도망간 것 — TTS로 실제로 들어보면 기계가 읽는 것처럼
딱딱하게 들리는 원인.

**솔루션**: video v3→v4 — "문장 어미" 절 신설(같은 어미 연속 2컷

체크리스트에 어미 다양성 항목 추가.

**한 것**: 9개 나레이션을 손으로 다시 씀(GPT 재호출 대신 — 이미 검증된
차트 수치·전환 브릿지는 그대로 두고 어미만 교체하는 게 더 빠르고
확실해서). 최종 어미: -거든요/-더라고요/-던데요/-죠/-어요/-고요/-였어요/
-죠/-겠어요(질문) — 7종류, 연속 반복 없음. 재렌더 후 라이브 반영.

**검증**: 재렌더된 round2b 각본에서 "-습니다" 사용 0회, 어미 7종류 확인
(§영상_각본.md "어미 확인" 참고). 다만 이건 사람이 손으로 고친 결과에 대한

## 라운드 3 (2026-08-20) — 웹툰

**계기**: 네이버 웹툰 "복학왕" 2화를 사용자가 PDF로 제공, 실제 컷을 보며
말풍선 작법을 분석. 복학왕은 발화(말풍선)와 내레이션/독백(말풍선 없는
텍스트)을 명확히 구분하고, 평범한 대사는 둥근 말풍선, 흥분·놀람한 대사는
삐죽삐죽한 폭발형 말풍선으로 톤을 시각적으로 구분해서 그린다는 걸 확인.

**문제** (이슈 트래커 #10, #12): AILENS 웹툰 프롬프트는 말풍선/내레이션/
캡션 구분은 이미 있었지만(이 부분은 복학왕과 비교해도 이미 잘 돼 있었음),
①말풍선이 대사 내용의 감정 강도와 무관하게 항상 같은 모양(둥근 타원)
으로만 렌더되고, ②A·B 두 화자가 하는 "일"(사실 vs 의미)은 구분해도
말투 격식(리액션형 vs 단정형) 차이는 지시가 없었다.

**솔루션**: webtoon v3→v4 —
- 1단계 dialogue 스키마에 `tone`("보통"|"격앙") 필드 추가, 격앙 남발 금지
  규칙(한 컷에 둘 다 격앙 금지, 8컷 중 1~2개 이내)
- 3단계 이미지 스타일(BUBBLE_RULES)에 tone별 말풍선 모양 분기 — 보통은
  기존과 동일한 둥근 말풍선, 격앙은 삐죽삐죽한 폭발형
- 대사 규칙에 "A·B 말투 격식 대비" 항목 추가(리액션형 vs 단정형)
- 체크리스트에 tone 남발 여부, 말투 대비 여부 항목 추가
- **같은 내용을 실제 프로덕션 코드에도 반영**: 마스터DB
  `03_개발·프롬프트/뉴스웹툰_파이프라인/prompts.py`의 `bubbles()` 함수가
  이제 tone별로 다른 영문 지시문을 생성한다(하위 호환 유지 — tone 없이
  2-tuple로 불러도 "보통"으로 처리). `pipeline.py`의 호출부도 1단계 JSON의
  tone 값을 그대로 넘기도록 수정.

### 라운드3 추가 수정 — DDB 프롬프트와 실제 생성 코드가 따로 놀던 문제

**문제** (이슈 트래커 #11): 라운드3 작업 중 발견 — DDB의 webtoon 프롬프트
(관리자 화면이 읽고 쓰는 정본)와 마스터DB `뉴스웹툰_파이프라인/pipeline.py`
+`prompts.py`(라운드1 실제 이미지 생성에 쓴 코드)가 완전히 다른 대사
규칙을 하드코딩해서 갖고 있었다 — 예를 들어 DDB는 "소재 유형에 맞게
인물을 매번 새로 정한다"인데 코드는 "인물 A/B 역할이 모든 편에서 고정".
즉 지금까지 admin 드로어에서 프롬프트를 아무리 고쳐도 실제 웹툰 생성
결과엔 전혀 반영이 안 됐다 — 두 곳이 애초에 연결돼 있지 않았다.

**솔루션**: "코드가 DDB를 맞춰서 읽게" 방향으로 근본 수정(사용자 지시:
"근본적으로 해결... 맞춰서 하시면 좋겠네요"). `video-pipeline/`와 같은
이유로 파이프라인 자체를 `webtoon-pipeline/`로 dev2에 이관(이슈 트래커 #8과
같은 홈 디렉터리 git 루트 문제도 같이 해소). `ddb_prompt.py` 신설 —
`service/backend/services/prompt_loader.py`와 같은 DDB 스키마·같은
fallback 순서(DDB 실패 시 `service/backend/prompts/webtoon/published.md`)로
`PROMPT#webtoon/published`를 읽어온다. `pipeline.py`의 1·2단계가 이제
이 함수로 매 실행마다 admin 프롬프트를 가져와 그 자리에서 "지금은
1단계만 출력해" / "지금은 2단계만 출력해"라는 작업 지시를 붙여 호출한다.
`prompts.py`에 하드코딩돼 있던 옛 1·2단계 템플릿(SCRIPT_PROMPT_TEMPLATE,
SCENE_PROMPT_TEMPLATE)은 완전히 삭제 — 다시 여기 하드코딩하면 같은 문제가
반복되므로 파일 docstring에 그렇게 하지 말라고 명시해뒀다.

3단계(이미지 생성 API 호출)는 그대로 코드로 남겨뒀다 — DB에 저장된 임의
텍스트를 코드처럼 실행하는 건 안전하지 않은 패턴이라, 대신 DDB 프롬프트
문서 안의 "3단계 — 이미지 생성 스타일" 섹션과 이 코드를 사람이 수동으로
동기화하는 쪽을 택했다(`prompts.py` docstring에 "여기 고치면 그 섹션도
같이 고칠 것"이라고 명시).

**검증**: 이관 후 `ddb_prompt.load_prompt("webtoon")`이 DDB에서
`v#4`(이번 라운드에서 올린 최신 버전)를 실제로 가져오는 것 확인. 이어서
빵지순례 원문으로 `pipeline.py`의 1단계 전체를 실제로 돌려서(GPT-4o
호출) 8컷 스크립트가 정상 생성되고 `tone` 필드도 자연스럽게 섞여
나오는 것 확인(격앙 2개, 서로 다른 컷에 분산 — 한 컷에 둘 다 격앙인
경우 없음). 즉 "admin에서 프롬프트를 고치면 실제 생성에 반영된다"는
것이 격리 테스트가 아니라 실제 코드 경로로 검증됨.
