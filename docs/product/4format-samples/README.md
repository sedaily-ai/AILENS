# 4포맷 샘플 개발 — 기사 1건 고정, 라운드 반복

기사 하나를 정해두고 레터/웹툰/팟캐스트/영상 4포맷을 반복 생성·발행·리뷰하며
"괜찮다" 싶은 품질까지 끌어올리는 작업 로그. 목적은 완성된 샘플 하나를
갖는 것 — 그 과정에서 프롬프트가 얼마나, 왜 좋아졌는지를 남긴다.

## 왜 두 종류로 나눠서 기록하나

- **프롬프트가 뭘로 바뀌었는지**는 이미 자동으로 남는다 — admin 프롬프트
  드로어가 저장할 때마다 v1→v2→v3로 버전을 쌓고(`sedaily-mbti-admin-prompts-dev`),
  드로어 히스토리 탭에서 언제·누가 저장했는지 바로 보인다. 여기서 또 안 적는다.
- **결과물이 실제로 나아지고 있는지**는 사람이 읽고 판단해야 하는 부분이라
  자동으로 안 남는다 — 그래서 이 폴더가 그걸 담당한다.

## 폴더 하나 = 기사 하나

```
{기사슬러그}/
├── 원문.txt        — 고정, 라운드 내내 안 바뀐다
└── 라운드기록.md    — 매 라운드 이어서 기록
```

`라운드기록.md` 맨 위에는 **이슈 트래커 표**를 둔다 — 이슈 | 포맷 | 발견
라운드 | 상태 | 해결 라운드. 새 문제를 찾으면 행을 추가하고, 고치면
상태를 바꾼다. 라운드가 몇 개든 이 표 하나만 보면 "지금 뭐가 살아있는
문제인지"가 한눈에 보여야 한다 — 라운드 수가 늘어날수록 이 표의 값어치가
커진다.

각 라운드는(레터/웹툰/팟캐스트/영상 어느 포맷이든 동일하게):
- **문제** — 이슈 트래커의 몇 번 항목을 다루는지, 왜 생겼는지
- **솔루션** — 프롬프트를 몇 v → 몇 v로, 뭘 바꿨는지
- **검증** — 재생성/재렌더해서 실제로 고쳐졌는지 확인한 결과. "고쳤다고
  주장"이 아니라 "다시 만들어서 확인했다"까지가 한 세트다. 사람이 손으로
  고친 거면(GPT가 프롬프트만으로 재현 못한 경우) 그것도 명시한다 — 다음
  라운드에서 "프롬프트만으로 되는지" 검증이 필요하다는 뜻이므로

이 3개가 그 라운드 항목의 첫머리에 온다. 그 아래엔 기존처럼:
- 프롬프트 버전, 한 것, 산출물(실제 발행 링크 — 같은 CMS 글을 계속
  덮어쓴다), 읽어본 소감, 다음 라운드에서 손볼 것

## 흐름

1. `/lens/edit`에서 원문을 기준으로 4개 탭 각각 "AI로 생성"
2. 마음에 들면 그 텍스트를 실제 필드(문단/불릿/이미지/링크)로 옮겨 저장 → 발행
3. 발행된 라이브 URL을 독자처럼 읽어본다
4. 별로인 부분이 있으면 그 포맷의 프롬프트(드로어 "지침" 섹션)를 고쳐 저장
   — 새 버전이 자동으로 쌓인다
5. `라운드기록.md`에 이번 라운드 소감·다음 할 일 한 줄씩 추가
6. 1번으로 돌아가 반복
