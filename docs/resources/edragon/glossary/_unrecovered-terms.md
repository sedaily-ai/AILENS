# 복구 실패한 용어 목록

아래 2개 용어는 glossary 인덱스 페이지(https://edragon.oopy.io/2175659d-574a-81a7-b4f1-c0eb4309b3c2)에서
UUID를 추출하려는 시도에서 끝내 신뢰할 수 있는 URL을 찾지 못했다.

- **채권 ETF**
- **황제주**

## 시도 경위

이 사이트(oopy.io, Notion 기반)의 목록 페이지는 각 용어로 이동하는 링크가 정적 HTML에는 노출되지 않고
클라이언트 사이드 JS로 렌더링된다. WebFetch로 여러 차례 raw HTML/JS 안에 임베드된 UUID 패턴을 탐색해
25개 용어 중 23개의 UUID는 성공적으로 복구했다(각 파일의 실제 내용과 대조해 제목이 일치함을 확인).

그러나 "채권 ETF"와 "황제주" 두 용어에 대해 추가로 질의했을 때, WebFetch가 반환한 UUID가 각각
이미 확인된 "브라질 채권"(`2175659d-574a-81f7-987e-c5fd5ef72ab3`), "고정금리 변동금리"
(`2175659d-574a-8159-be0a-c7881c1b628b`)의 UUID와 **완전히 동일**했다 — 이는 실제 값이 아니라
모델이 이전 응답을 재사용(할루시네이션)한 것으로 판단해 신뢰하지 않기로 했다.

브라우저 확장(Claude in Chrome)을 통한 실제 JS 렌더링 + 네트워크 요청 검사도 시도했으나,
이 세션에서는 확장이 연결되어 있지 않아 사용할 수 없었다.

## 복구하려면

브라우저 자동화(예: Playwright, Claude in Chrome 확장 연결 후 재시도)로 목록 페이지를 렌더링한 뒤
개발자 도구 네트워크 탭 또는 DOM에서 두 항목의 실제 링크를 확인하는 것을 권장한다.
