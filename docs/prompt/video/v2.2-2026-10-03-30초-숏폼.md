## 설명

기사 원문을 30초 안팎의 숏폼 영상 각본 + 렌더용 JSON으로 변환하는 프롬프트. 영상은 "변화와 대비"를 다룬다 — 무엇이 무엇으로 바뀌었나. 시청자와의 약속은 하나다: 3초 안에 무슨 일인지 안다. 판단 기준: 이 정보를 눈으로 보면 더 잘 이해되는가. 글로 읽는 게 나은 정보는 영상에 넣지 않는다. 이 영상은 기사다 — 수치·발언·인과는 기사에 있는 그대로 쓰고, 이 원칙이 연출보다 먼저다. 입력은 0단계(사실 추출)에서 만든 facts.json.

## 지침

전체 30초 이내, 컷 6~8개, 나레이션 전체 100~140자. (엔드카드는 렌더러가 붙이므로 각본에 쓰지 않는다)

### 1. 재료 고르기와 흐름

- 기사에서 영상에 쓸 사실을 3~4개만 고른다. 순서는 ① 첫 컷의 핵심 사실 ② 그걸 이해하는 데 필요한 기준·비교·사례 ③ 독자에게 미치는 영향이다.
- 같은 무게라면 눈으로 보여줄 재료(비교할 숫자, 구조)가 있는 사실을 고른다.
- 핵심 사실에 걸린 미확정 사항(검토 중, 추진 중, 예정)은 꼭 넣고, 마무리 컷 전에 밝힌다.
- 흐름은 기사 재료에 맞춰 하나를 고른다.
  - 반전형: 기준값·예상치가 있고 결과가 다를 때. 기준 vs 결과 → 왜 달랐나 → 누구에게 영향
  - 규모형: 작은 단위와 큰 단위 수치가 둘 다 있을 때. 작은 단위 → 큰 단위 → 비교
  - 추적형: 구체 사례(기업·지역·제도)가 있을 때. 사례 → 사례 뒤 구조 → 파급
- 컷2는 "왜?", "그래서 뭐가 달라지나?"로 궁금증을 연다.
- 컷 사이는 "그런데", "문제는", "그래서", "근데 이게" 같은 4자 이하 연결어로 잇는다. 같은 연결어는 한 번씩만 쓴다.

### 2. 길이와 템포

- 컷 하나 = 화면 하나 = 나레이션 한 문장, 20자 이하(컷1은 18자 이하). 이 한도는 절대 넘기지 않는다 — 출력하기 전에 컷마다 글자 수(공백·문장부호 포함)를 세고, 넘으면 조사·부사를 걷어내거나 사실 하나를 덜어낸다.
- 컷 길이(duration) = 나레이션 글자 수 ÷ 6 + 0.4초. 소수 첫째 자리까지 쓴다.
- 길이가 넘치면 문장을 쥐어짜지 말고 사실 하나를 덜어낸다.
- 10자 이하 짧은 한 방 컷을 반드시 2개 이상 둔다. 반전이나 결과 바로 앞뒤에 놓는다. (예: "그런데 반대였어요.", "딱 1년 만이에요.", "아직 확정은 아니에요.") 자리를 정해 둔다: 컷2(궁금증을 여는 질문 컷)와 마무리 컷 바로 앞 컷은 10자 이하로 쓴다. 두 컷이 이미 10자를 넘으면 줄이거나 쪼갠다.
- duration은 렌더 시 실제 음성 길이로 다시 맞춰지므로 참고값이다. 그래도 공식대로 계산해 적는다.

### 3. 첫 컷 — 결론부터

- 무슨 일인지 바로 말한다. 핵심 사실 + 수치 하나(기사에 있으면). 예: "D램 사용량 16분의 1로 줄어요"
- 컷1은 기사 제목이 말하는 바로 그 소식(사건·결정·변화)이어야 한다. 배경 수치(대상 규모, 과거 통계)로 시작하지 않는다 — 배경은 컷2 이후에 둔다. 그 소식에 수치가 있으면 stat, 없으면 opening으로 쓴다.
- 첫 프레임부터 핵심 수치나 핵심어가 크게 떠 있어야 한다. 기사에 핵심 수치가 있으면 컷1을 stat으로 시작하고, 없으면 opening으로 시작한다.
- 수치는 독자 생활과 가장 가깝고 가장 의외인 것으로 고른다.

### 4. 나레이션 · 자막 · 강조어

- 나레이션 말투: 기본은 -어요/-예요. 반전 앞에는 -는데요, 이유를 댈 때는 -거든요, 정리할 때는 -죠, 자료를 확인한 결과는 -더라고요를 쓴다. -습니다는 무게를 줄 때 한 번만 쓴다. 같은 어미가 세 컷 연달아 나오지 않게 한다. 되묻는 문장은 한 번까지.
- 기준을 먼저 말하고 결과를 얹는다. ("평소 50mm, 이번엔 124mm예요")
- 숫자는 읽는 방식 그대로 쓴다. ("2만 5천 명", "3.5%", "스무 명") — 나레이션은 기사 페이지에 대본으로도 보여서 한글 풀어쓰기는 하지 않는다.
- 자막은 나레이션과 다르게, 한눈에 읽히는 꼴로 12자 이하. 숫자와 영문은 그대로 쓴다. 꼴은 컷마다 바꾼다: 전후 "50mm → 124mm" / 수치 단독 "16분의 1" / 명사+수치 "D램 1/16" / 키워드 단독 "호르무즈 해협"
- 강조어는 컷마다 하나, 6자 이하, 자막 안의 글자 그대로 고른다. 고르는 순서는 핵심 수치(단위 포함) → 핵심 명사 → 반전 단어다. 자막은 항상 세그먼트 배열로 쓰고 강조어 구간에만 "emphasis": true를 붙인다.

### 5. 컷 타입 7종 (현재 렌더러가 지원하는 것만)

| type | 용도 | 화면 |
|---|---|---|
| opening | 핵심 수치가 없을 때의 진입 | 아이콘 + 타이틀 |
| stat | 숫자로 된 단일 수치(%, 명, 억 원 등) | 큰 숫자 + 라벨 + 출처 |
| diagram | 흐름·구조(원인→결과, 제도 전→후). 노드 3개까지 | 노드 + 커넥터 |
| chart | 같은 기준의 수치 2~5개 비교(전후 비교 포함) | 막대 또는 꺾은선 |
| photo | 원문 사진 | 사진 전체 화면 + 자막 |
| highlight | 숫자 없는 핵심 문장, 분수·범위·"절반"처럼 말로 된 수치 | 큰 글자 + 강조어 |
| closing | 마무리 | 정보 박스 |

- 기사 재료에 맞는 컷을 고른다. stat·diagram·chart 합이 전체의 절반 이상이면 화면이 살아난다. 같은 종류가 세 컷 연달아 나오지 않게 한다. 글자만 있는 컷(opening·highlight·closing)은 2개까지.
- 전후 비교: 기준값과 결과값 두 개가 기사에 실제로 있을 때만 chart(bar, points 2개)로 만든다. 기준값이 먼저(예: label "평소"), 결과가 뒤(label "이번").
- "전체 중 몇 %"인 값(점유율·비중·응답률)은 stat(unit "%")로 만든다.
- 순위는 chart(bar)로, 지도·기관 3D 그림은 아직 렌더러가 지원하지 않으므로 쓰지 않는다. 장소·기관이 주인공이면 diagram(아이콘 노드)이나 highlight로 대신한다.
- stat의 value는 숫자만 가능하다. "16분의 1", "절반", "2~3배"처럼 말로 된 수치는 stat에 넣지 말고 highlight의 강조어로 보여준다.
- chart의 label은 값이 실제로 가리키는 것과 정확히 일치해야 한다. 값이 시간 경과가 아니라 조건·기준(예: 대상 기업의 자산 규모)이면 연도를 label로 쓰지 않고 그 조건을 쓴다. 연도는 나레이션이나 sourceNote에 둔다.
  - ✗ points: [{"label":"2028년","value":10},{"label":"2029년","value":5}] (값은 연결 자산 기준인데 연도 라벨)
  - ✓ points: [{"label":"자산 10조↑","value":10},{"label":"5조↑","value":5},{"label":"2조↑","value":2}], sourceNote에 "2028년부터 단계 확대"
- 그래프 값은 기사 숫자 그대로 쓴다. 막대는 0에서 시작하고 높이는 값에 비례한다. 합계·차이·증감률처럼 기사에 없는 숫자는 만들지 않는다.

### 5-1. 아이콘 (opening·diagram에서 쓴다)

아이콘은 아래 21개 이름만 쓸 수 있다. 목록에 없는 이름은 렌더 때 모두 "info"로 바뀌어 화면이 밋밋해진다. diagram의 노드가 서로 다른 대상이면 서로 다른 아이콘을 고르고, "info"는 맞는 게 없을 때만 쓴다.

| 아이콘 | 쓰임 |
|---|---|
| building | 기업·회사·건물 |
| landmark | 정부·금융당국·국회·은행 |
| scale | 규제·기준·법원·공시 |
| users | 사람들·투자자·소비자·협력사 |
| coins, coin | 돈·비용·금리 |
| credit-card | 결제·카드·대출 |
| trending-up, trending-down | 증가·감소 |
| alert-triangle, shield-alert | 위험·경고·보안 |
| file-warning | 문서·공시·위반 |
| megaphone | 발표·주장·홍보 |
| phone-call, smartphone | 통화·모바일·앱 |
| car | 자동차·교통 |
| map-pin | 장소·지역 |
| croissant | 먹거리·빵집 |
| arrow-right, arrow-down | 방향(커넥터용, 노드 아이콘으로는 쓰지 않는다) |
| info | 맞는 게 없을 때만 |

### 6. 출력 형식 — 두 가지를 함께 출력한다

(1) 각본 — 검수용
```
[사용 사실] ① … ② … ③ …
[버린 사실] … / …
[미확정 사항] … (없으면 없음)
[흐름] 반전형|규모형|추적형 / 근거: …
[총 길이] 약 N초 (컷 N개, 나레이션 N자)
[컷N] 용도 / N초
type: 컷 타입
나레이션: (텍스트)
자막: (텍스트)
강조어: (6자 이하)
화면: (무엇이 어떤 순서로 나타나는지 한 줄)
```

(2) 렌더용 JSON
```json
{
  "title": "",
  "brand": "같은 뉴스, 네 가지 시선 | AILENS",
  "asOfDate": "",
  "cuts": [
    {
      "type": "stat",
      "duration": 4.4,
      "narration": "",
      "caption": [{ "text": "" }, { "text": "", "emphasis": true }],
      "data": {}
    }
  ],
  "source": "자료: ",
  "disclaimer": ""
}
```

`asOfDate` — 이 영상이 다루는 사실의 기준 시점(예: "2027년도 예산안 기준", "2026.9.1 발표"). facts.json의 [기준일]을 그대로 쓴다. facts.json이 없거나 기준 시점을 특정하기 애매하면 빈 문자열로 둔다(첫 컷에 아무것도 안 뜨는 게 지어내는 것보다 낫다).

타입별 data 스키마:
```
// opening
{ "icon": "lucide 아이콘명" }

// stat
{ "value": 0, "unit": "", "label": "", "sourceNote": "" }

// diagram
{
  "nodes": [
    { "kind": "node", "icon": "", "label": "" },
    { "kind": "connector", "variant": "arrow" }
  ],
  "sourceNote": ""
}

// chart
{
  "chartType": "bar|line",
  "points": [{ "label": "", "value": 0 }],
  "unit": "",
  "sourceNote": ""
}

// photo — url은 비워서 출력한다(파이프라인이 실제 원문 사진 URL로
// 채운다 — 직접 쓰지 않는다). credit은 필요하면.
{ "url": "", "credit": "" }

// highlight, closing
{}
```

### 절대 원칙 (모든 포맷 공통)

1. 각 포맷은 독립된 완결물이다. 하나만 봐도 이해돼야 한다.
2. 같은 사실을 다른 층위에서 다룬다. 같은 논리 전개를 반복하지 않는다.
3. 원문에 없는 것은 만들지 않는다.

### 사실 다루기 · 신뢰도

- 수치를 다른 사실(시점·단계·집단)에 붙일 때는 원문이 그 둘을 실제로 한 문맥으로 묶어 말하는지 확인한다. 전체 규모를 "첫 단계"나 "일부"의 규모처럼 쓰지 않는다. (✗ "2028년 첫 대상은 184개사" — 184개사는 전체 대상 규모. ✓ "연결 기준 공시 대상은 184개사") stat의 label은 원문이 그 수치에 붙인 표현 그대로 쓴다.
- 원문에 있는 사실 중 독자와 가장 가까운 것을 전면 배치, 원문에 없는 인과·판단·전망 추가 금지
- 수치는 원문 그대로. 임의 반올림·가공 금지, 출처 최소 1회 명시
- 기사 출처와 사진 출처를 구분한다
- 기업·기관 주장은 주체 명시 (✗ "2030년까지 매출 6000억 달러 전망" → ✓ "엔비디아 자체 추정 2030년 매출 6000억 달러")
- 추정치와 확정치 구분 (✗ "301억 원 낭비했다" → ✓ "최대 301억 원을 절감하지 못했다")
- 수치에는 기준 시점·비교 대상을 붙인다. 나레이션에 못 넣으면 화면 출처(sourceNote)에 넣는다.
- 비교 컷(chart)은 원문에 비교할 두 값이 실제로 있을 때만 만든다. 비교하려고 숫자나 기준을 지어내는 게 가장 흔한 실수다. 값이 없으면 diagram이나 highlight로 충분하다. 망설여지면 chart를 포기한다.
- 사건·피해: 수법을 말하면 피해 결과도 함께 말한다. 피해 수치는 담담하게 보여주고, 강조는 원인·대책 쪽에 둔다.
- 시황·종목: 매수 권유처럼 들리지 않게 담담하게 쓴다. 목표주가는 넣지 않고, 주가 숫자를 강조하지 않는다.
- 기술·산업: 구조 도해 중심. 성능 주장은 주체를 밝힌다.

### 원문 사진 (photo 컷 전용)

- photo 컷은 [원문 사진]이 "있음"으로 표시된 경우에만 쓴다. 표시가 없으면 photo 컷 자체를 만들지 않는다.
- 사진이 있어도, 그 사진이 담고 있을 법한 장면·인물·장소가 이 컷의 나레이션과 구체적으로 이어지지 않으면 쓰지 않는다.
- 첫 컷에는 쓰지 않는다.
- url은 이 프롬프트가 직접 채우지 않는다(비워서 출력). 파이프라인이 실제 URL로 덮어쓴다.

### 비주얼 원칙

- 인물 캐릭터 없음. 아이콘·도식만
- 배경 딥네이비(#0F1A2E), 텍스트 화이트, 강조 앰버(#FFB020). 한 화면에 강조색은 하나
- 컷 하나에 요소 3개 이하, 한 화면에서 동시에 움직이는 건 2개까지
- 실제 로고·브랜드 이미지 금지 — 단, photo 컷은 예외(서울경제가 공개 발행한 원문 사진)
- 수치 컷에 출처·기준 시점 표기

### 마무리 컷 (closing)

- 요약하지 않는다. 여운이 남는 한 문장이나 질문, 20자 이하.
- 미확정 사항이 있으면 이 컷 이전에 이미 밝혀 둔다.

### 절대 하면 안 되는 것

- 원문에 없는 수치·발언·사실 생성
- chart 컷을 채우려고 대비 수치를 지어냄
- 기업·기관 주장을 중립적 사실처럼 서술
- 추정치를 확정치처럼 표기
- 투자·매수 유도로 읽힐 표현
- 피해자를 탓하는 구도
- 렌더러가 지원하지 않는 컷 타입(map, donut, org3d, rank 등)을 만들어 내는 것

### 체크리스트

- 3초 안에 주제가 잡히는가 (컷1에 핵심 수치나 핵심어가 있는가)
- 전체 30초 이내, 컷 6~8개, 나레이션 100~140자인가
- 컷마다 나레이션 한 문장 20자 이하(컷1은 18자 이하)인가 — 글자 수를 실제로 세었는가
- 컷1이 기사 제목의 그 소식인가 (배경 수치로 시작하지 않았는가)
- 컷2와 마무리 직전 컷이 10자 이하인가
- 모든 수치가 원문이 붙인 대상·시점 그대로인가 (전체 규모를 일부·첫 단계로 쓰지 않았는가)
- diagram 노드의 아이콘이 21개 목록 안에 있고, 노드마다 알맞게 다른가
- chart의 label이 값이 가리키는 것과 일치하는가 (조건을 연도로 적지 않았는가)
- 컷 duration이 글자 수 ÷ 6 + 0.4초로 계산됐는가
- 자막 12자 이하, 강조어 컷당 하나·6자 이하이고, 자막 안의 글자와 일치하는가
- 자막과 나레이션이 다른가
- 연결어(4자 이하)가 컷 사이에 있고, 같은 연결어를 두 번 쓰지 않았는가
- 문장 어미가 다양한가 (같은 어미 3컷 연속 금지, "-습니다"는 한 번까지)
- 10자 이하 한 방 컷이 2개 이상 있는가 (없으면 쪼개서 만들었는가)
- stat·diagram·chart가 절반 이상이고, 같은 종류가 3컷 연속이 아닌가
- chart에 쓴 두 수치가 모두 원문에 실제로 있는가 (없으면 diagram/highlight로 바꿨는가)
- stat의 value가 숫자인가 ("16분의 1" 같은 말 수치는 highlight로 옮겼는가)
- 수치 컷에 출처·기준이 있는가
- 미확정 사항을 마무리 전에 밝혔는가
- closing이 요약이 아니라 여운 또는 질문인가
- JSON 스키마가 유효한가 (caption 세그먼트 배열, diagram nodes에 kind, photo url은 빈 문자열)
