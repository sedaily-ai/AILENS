## v2.0 — 무엇을 가져오고 무엇을 뺐나

사용자가 가져온 Remotion 에이전트용 프롬프트(2026-10-03)에서 **각본(편집) 규칙만** 옮겼다. 그 프롬프트는 "Remotion 프로젝트를 새로 만들고 mp4까지 뽑는 개발 에이전트"용이라, 현재 파이프라인(AI는 각본 JSON만 쓰고 고정 컷 7종이 렌더)에 그대로 넣을 수 없다.

옮긴 것: 30초·6~8컷·100~140자, 흐름 3종(반전·규모·추적), 연결어, 컷당 20자 한 문장, 첫 컷 결론부터, 어미 규칙, 자막 12자·강조어 1개, 10자 이하 한 방 컷, 사실 다루기, 마무리 컷.

옮기지 못한 것(렌더러 개발 필요 — 2단계): 전후 비교 전용 컷, 도넛, 순위, 지도, 기관 3D 그림, 숫자 굴리기 외 연출, 전면 타이포 전용 컷, 키워드 라벨 고정 요소, 소리 없을 때 하단 자막 줄, 엔드카드(렌더러가 `brand`로 대신), 배경 음악·효과음. 전후 비교는 chart(bar 2점), 도넛은 stat(%), 전면 타이포는 highlight로 대체한다.

옮기되 바꾼 것: 나레이션 한글 풀어쓰기(백이십삼억)는 하지 않는다 — 나레이션이 기사 페이지에 대본으로 보여서. 세로 1080×1920은 프롬프트가 아니라 렌더 설정(`--format vertical`)과 웹 플레이어(현재 16:9 프레임)의 문제라 3단계로 미뤘다.

## 반영 전에 확인할 것

- 컷 수·길이가 줄어 TTS 호출 수가 줄어든다 — 비용은 늘지 않는 방향. 실측은 반영 후 기사 1건으로.
- `pipelines/video/generate_script.py`의 검증은 컷 수·길이 상한이 없어 새 길이로도 통과한다(확인 완료). 다만 `max_tokens=4000`이라 각본(검수용)+JSON을 둘 다 내는 출력이 길어지면 잘릴 수 있는지 첫 실행에서 본다.
- 반영 후 첫 기사에서: 컷 6~8개인가 / 컷 한 문장 20자 이하인가 / chart 값이 기사에 있는가 / 말 수치가 stat으로 들어가지 않았는가.

## v3.0 — 원문 프롬프트 그대로 + 틀만 맞춤 (같은 기사 시험)

원문의 §1~12를 거의 그대로 두고 역할 문장·작업 순서·구현 메모만 각본/JSON 출력용으로 바꿨다. 지도·3D·도넛·순위 등 렌더러에 없는 장면은 §14 대응표로 JSON 컷 종류에 옮기게 했다.

시험 결과(스코프3 기사): 렌더 성공(14.6초, 자동 수정 0건). v2.2보다 규칙 위반이 늘었다.
- 글자만 있는 장면(highlight)이 컷1~3 연속 3개 — 원문 §6의 "같은 종류 3연속 금지, 글자만 2개까지" 위반
- 한 방 컷(10자 이하) 1개뿐(컷2 9자), 컷7 12자
- 자막 12자 초과(컷5 20자), chart 라벨에 연도 사용
- "첫 대상은 백여든네 곳" — 184개사는 전체 공시 대상 규모인데 첫 적용 대상으로 서술(수치 귀속 오류 재발)
- 나레이션이 한글 풀어쓰기라 기사 페이지 대본에 "이천이십팔년 십조 원부터요"처럼 노출된다
