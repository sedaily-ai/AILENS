# 웹툰 생성 프롬프트 — 버전 이력

CMS 프롬프트 화면(웹툰 → 생성 프롬프트)의 내용을 버전별로 보관한다. **정본은 CMS(DB)이고 이 폴더는 이력용 사본이다.**
파일명 규칙: `v<CMS 버전>-YYYY-MM-DD-<변화 한 줄>.md`

| 파일 | 상태 | 요약 |
|---|---|---|
| `v0-2026-09-24-이전-스냅샷.md` | 옛 스냅샷 | 이전 `published.md`(인스타·웹·AILens용, 후식자 이전 구조) |
| `v31-2026-10-02-현재-라이브.md` | **현재 CMS 라이브(v31)** | A 왼쪽·B 오른쪽, 컷당 두 대사(speaker만), 고정 문자열 5종, 컷1·8만 제목, JSON `negative_prompt` 출력 |
| `v32-2026-10-02-말풍선-tone-추가.md` | CMS 적용(사용자 확인) | v31 + 말풍선 tone(보통/격앙/속삭임/생각) 규칙·출력 필드·자체검수 |
| `v33-2026-10-02-나레이션-복원.md` | 이력 | v32 + 컷마다 한 줄 나레이션(32자 이내, 그림 아래 검은 띠) — 대사만으로 빈약해 보이는 정보량을 보강. 하단 자막 바 금지 문구는 "한 줄 띠만 허용"으로 교체 |
| `v34-2026-10-02-구성-정보충족.md` | **CMS 적용 대기** | v33 + 컷별 독자 마음·역할표, 숫자 표기 규칙, 마지막 "핵심 정리" 카드용 `key_numbers`·`card_title` 출력 |

`published.md`는 v31(라이브)과 같은 내용이다.

## v31 → v32 변경 (3곳, 기존 내용 삭제 없음)
1. `<bubble_rules>`: tone 규칙 추가(격앙 최대 2, 속삭임 최대 2, 생각 최대 1, 의심스러우면 보통).
2. `<output_format>`: dialogue 각 항목에 `"tone"` 추가, 허용 값 4종 명시.
3. `<step_4_self_check>`: 17-1 tone 점검 추가.

## v32 → v33 변경
1. `<narration_rules>` 추가(32자·사실 요약·대사 되풀이 금지·컷8은 서술문 마무리).
2. `<output_format>` cuts에 `narration` 필드 추가.
3. `<must_not>`의 "하단 전체를 덮는 자막 바 금지"를 "나레이션은 한 줄 띠만"으로 교체.
4. 자체검수 20-1 추가.

## v33 → v34 변경
1. `<step_2_structure>`: 컷별 독자 마음·대사·나레이션·톤 표, 질문 컷/답 컷 구조, 특수 톤 총량 5개 이하.
2. `<narration_rules>`: 핵심 숫자는 아라비아 숫자+단위, 컷1 나레이션은 기사 핵심 한 문장.
3. `<key_numbers_rules>` 신설, `<output_format>`에 `card_title`·`key_numbers` 추가.
4. 자체검수 20-2~20-4 추가.

## 코드 쪽 연동 (2026-10-02)
- `pipelines/webtoon/compose_text.py`가 tone별 말풍선을 그린다: 보통(손으로 그은 둥근 선) / 격앙(삐죽) / 속삭임(점선·회색 글자) / 생각(구름). 모르는 값은 보통.
- 프롬프트가 내는 `negative_prompt`를 `pipelines/common/webtoon_image.py`가 공통 금지어 뒤에 덧붙여 Ultra에 보낸다.
- 나레이션은 웹툰식 말풍선 모드에서 그림 아래 검은 띠(핵심 숫자만 파랑 강조)로, `key_numbers`는 마지막 "핵심 정리" 카드(컷9, 코드로 그림·비용 0)로 합성된다.
- 말풍선 얼굴 회피(Rekognition)는 프롬프트가 아니라 CMS "이미지 설정"의 토글이다.

## 적용 방법 (v32)
CMS 프롬프트 화면에서 v31을 열어 위 3곳을 반영하거나 `v32-…md` 전체를 붙여 넣어 저장 → 테스트 카드에서 tone이 나오는지 확인 → "프로덕션에 적용".
