# v1.5 (2026-09-28) — "맥락 파악"과 "선정 후보"를 별개 입력으로 분리

작성: 문영광 + Claude Code
관련: `v1.4-2026-09-28-실제-호출-검증-json-버그-발견.md`(직전 버전),
`pipelines/mustknow_auto/classify.py`, `pipelines/mustknow_auto/run.py`

## 문제 발견

코드 구현·커밋까지 마친 뒤, 사용자 질문("제가 방향을 잡은 것에서 문제점이나
개선할 부분은 없으려나요")에 답하며 재검토하다가 발견한 구조적 결함.

v1.4까지의 "1단계: 오늘의 흐름 파악"은 **선정 후보 목록 자체**를 보고
트렌드를 판단하도록 설계돼 있었다. 그런데 실제 운영은 `mustknow_auto`가
하루 4~8회 도는데, 매 회차 이미 평가한 후보는 `seen` 처리돼 다음 회차
후보 풀에서 빠진다(`run.py`의 `fresh = [a for a in all_articles if ...
not _is_seen(...)]`). 즉 **이번 회차의 "선정 후보"는 그날 전체가 아니라,
지난 회차 이후 새로 들어온 델타일 뿐**이다.

v1.4 검증(9/27 하루치 147건을 한 번에 넣고 확인)은 이 실제 운영 패턴을
반영하지 못했다 — "하루 전체를 한 번에 보는" 이상적인 상황만 검증했지,
"회차마다 쪼개진 작은 델타만 보는" 실제 상황은 검증하지 않았다. 늦은
회차(예: 23시)일수록 델타가 작고 편중돼 "오늘의 흐름 파악"이 부정확해질
위험이 있었다.

## 문제 정의

"오늘의 흐름 파악"(맥락 이해)과 "20건 선정"(실제 고르기)은 서로 다른
입력이 필요하다 — 맥락 파악은 넓은 표본(그날 전체)이 필요하고, 선정은
좁은 대상(이번 회차에 아직 안 본 것)만 필요하다. 지금까지는 같은 목록
하나로 두 역할을 다 시키고 있었다.

## 왜 이렇게 풀었는가

`run.py::main()`은 이미 `all_articles = discovery.fetch_articles(today)`로
그날 게재된 전체 기사(seen 여부 무관)를 매 회차 가져오고 있었다 — 새
데이터 소스가 필요한 게 아니라, **이미 있는 걸 안 쓰고 있었을 뿐**이다.
이 전체 목록을 "맥락 파악 전용"(제목+카테고리만, 선정 대상 아님)으로
프롬프트에 별도 섹션으로 추가하고, 기존 "선정 후보"(제목·카테고리·부제·
리드, 이번 회차 델타)는 그대로 둬서 2단계 선정 대상으로만 쓰게 분리했다.

제목만 넘기므로 비용 부담도 크지 않다(리드 200자까지 포함하는 선정
후보보다 훨씬 가벼움).

## 가설

선정 후보(회차별 델타)와 별개로 전체 맥락(`context_articles`)을 주면,
델타가 작아도 `today_context` 품질이 하루 전체를 봤을 때와 동등하게
유지될 것이다.

- 위험/역효과 가능성: 맥락 목록이 추가되면 입력 토큰·비용이 늘 수
  있다(아래 "미해결"에서 순영향 불명으로 남김).

## 프롬프트 변경분

**시스템 프롬프트 도입부**에 입력이 두 목록으로 나뉜다는 설명 추가,
**1단계**는 "오늘 지금까지 게재된 전체 기사 목록"을 보고 판단하도록
명시(전체 프롬프트는 아래 참고).

## 코드 변경

- `classify.py::_build_general_prompt(candidates, context_articles)` —
  `context_articles`(전체 목록, 제목+카테고리만) 섹션을 선정 후보 목록
  앞에 추가
- `classify.py::select_general_articles(guide, candidates,
  context_articles=None)` — 새 파라미터, 하위호환(None이면 이전 동작과

- `run.py` 호출부: `classify.select_general_articles(selection_guide,
  general_pool, context_articles=all_articles)` — 이미 있던 `all_articles`
  그대로 전달

## 검증

9/27 실데이터로 "늦은 회차" 시뮬레이션: 전체 맥락(221건)은 그대로 두고
**선정 후보만 마지막 12건**(사건사고·인사 단신 위주 저품질 샘플)으로
줄여서 실제 Bedrock 호출.

- `today_context`가 여전히 정확했다: "추석 연휴 직후... 아시안게임...
  DMZ 지뢰 폭발사고... 서울 전세난·부동산" — 하루 전체(147건)로 봤을 때
  (v1.4)와 실질적으로 동일한 맥락을 잡아냄. 스스로 "선정 후보는... 협소한
  편"이라고 표본 한계까지 인지.
- 12건짜리 부실한 후보군에서도 가짜 신호에 안 휘둘리고 진짜 괜찮은
  4건(전셋값 역대 최고, 신축인데도 전세 안 내리는 이례적 현상, 중수청
  개청 리스크, DMZ 조사 쟁점)만 정확히 골라냄. 사건사고·인사·건강
  라이프 단신은 배제 규칙대로 걸러짐.

## 판정: 채택

"델타 12건 + 전체 맥락 221건" 시뮬레이션에서 `today_context`가 하루
전체(147건)로 봤을 때(v1.4)와 실질적으로 동등했다 — 가설대로 작동함을
확인해 **채택**. 단 n=1(하루 전체) + n=1(늦은 회차 시뮬레이션)뿐이라
표본은 여전히 작다(아래 "미해결" 참고).

## 미해결 (다음 버전)

- **다양성 규칙은 여전히 회차 단위**다 — 하루 누적으로 "카테고리당
  5건"을 강제하진 못한다(이전 worklog의 "하루 36건 누적 캡 미구현"과
  같은 근본 원인 — lens-cms-api COUNT 경로 필요).
- 아직 n=1(하루 전체) + n=1(늦은 회차 시뮬레이션) — 여러 날짜·여러
  회차 패턴으로 반복 검증 안 됨.
- 비용 실측 안 됨(맥락 목록 추가로 입력 토큰이 더 늘었다 — 이번 건은
  회차별 델타가 작을수록 오히려 입력이 줄어들 수도 있어 순영향 불명).
- 코드는 커밋됐지만 배포는 안 됨 — 라이브는 여전히 옛 로직.

```
당신은 서울경제신문 AI LENS의 수석 에디터입니다.
입력엔 두 개의 목록이 있습니다 — "오늘 지금까지 게재된 전체 기사 목록"
(맥락 파악 전용, 선정 대상 아님)과 "선정 후보"(이번 회차에 실제로 고를 수

알아야 하는 뉴스"를 기준으로 **선정 후보 중에서만** 최대 20건을 직접
골라주세요.

## 1단계: 오늘의 흐름 파악
선정에 들어가기 전, **"오늘 지금까지 게재된 전체 기사 목록"**(제목만 있음,
선정 대상 아님)을 한 번 훑고 다음을 파악한다:
- 오늘 유독 여러 기사에서 반복되는 주제·사건·이슈가 있는가(예: 특정
  정책 발표, 특정 기업 이슈, 연휴 전후 특수성 등)
이 파악 결과를 2단계 선정 시 참고한다 — 특히 "시의성" 판단은 "선정 후보"
목록 하나만 보고 추측하지 않고, 오늘 전체 맥락에 비춰 판단한다. 하루에
같은 파이프라인이 여러 번 도는데, 이번 회차의 "선정 후보"는 그중 이번에
새로 검토하는 일부일 뿐이다 — 표본이 작을 수 있으니 "오늘의 흐름"은
반드시 전체 목록 기준으로 판단한다.

같은 사안이 "선정 후보"에 여러 건 있다면, 가장 정보량이 많고 구체적인
기사 하나만 남기고 나머지는 아래 "배제" 규칙의 반복 게재로 처리한다.

단, 화제(트렌드) 자체를 고르는 게 아니다. 추석 연휴·스포츠 이벤트·유명인
소식처럼 사람들 입에 오르내리는 화제라도, 그 화제를 있는 그대로 보도한
기사(메달 획득 소식, 연휴 인파 숫자, 귀경길 정체 등)는 우선 대상이
아니다. 그 화제가 경제·소비·산업·생활과 만나는 지점을 다룬 기사를
우선한다.
  ✗ (화제 자체) 한국, 아시안게임 e스포츠 첫 금메달
  ✓ (화제×경제 교차점) 아시안게임 특수로 이 유통업체 매출이 20% 늘었다
  ✗ (화제 자체) 추석 연휴 이틀간 23만명 방문
  ✓ (화제×경제 교차점) 추석 지나면 주식 오른다는 징크스, 22번 중 15번 통했다

## 2단계: 선정

### 우선 고려 (이런 기사를 우선한다)
- 파급력: 전 국민 또는 대규모 경제주체에 영향(단, 화제 자체의 크기가
  아니라 그 화제가 경제·생활에 미친 구체적 영향의 크기로 판단한다)
- 시의성: 오늘 지나면 의미가 옅어지는 속보성 사안(1단계에서 파악한 오늘의 맥락 참고)
- 사실·데이터 밀도: 정성적 홍보가 아니라 구체적 수치·사실
- 정책·제도 변화: 법·제도·정책의 실제 변경
- 이례성: 예상 밖의 전개("역대 최대" 등 근거가 리드에 있을 때)

### 배제 (아무리 여유가 있어도 고르지 않는다)
- 기업 홍보/IR/신제품 출시
- 단순 인사이동·부고·사건사고 단신·동정
- 같은 사안을 다른 각도로 반복 게재한 기사(있으면 리드가 더 구체적인 1건만 — 1단계에서 파악한 오늘의 흐름과 연동)

### 다양성 규칙 (반드시 지킨다)
- 한 카테고리에서 5건을 초과해 고르지 않는다
- 최소 6개 이상의 서로 다른 카테고리가 포함되도록 한다
- 20건을 못 채워도(후보 자체가 부족하면) 억지로 채우지 않는다 — 기준 미달 기사보다는 적게 뽑는 게 낫다

### 선정 전 자체 검증 (고른 기사마다 스스로 점검한다)
각 후보에 대해 다음 5개 질문에 "예/아니오"로 답하고, 하나라도 "아니오"면
그 기사는 최종 목록에서 뺀다:
1. 파급력·시의성·사실데이터밀도·정책제도변화·이례성 중 최소 하나를
   명확히 충족하는가?
2. 표면적 정보 나열이 아니라 구체적 사실·수치에 근거하는가?
3. 위 "배제" 기준(홍보·인사·부고·단신)에 해당하지 않는가?
4. 이미 고른 다른 기사와 같은 사안을 다루지 않는가(반복 게재가 아닌가)?
5. 지금까지 고른 기사들의 카테고리 구성이 다양성 규칙(카테고리당 5건
   이하, 최소 6개 카테고리)을 지키고 있는가?
```
