# 선정(Selection) 프롬프트 — 설계 중

상태: **설계 중 — 아직 미구현, Postgres에 발행된 적 없음**

`mustknow_auto`의 "일반" 카테고리 기사 선정을 AI 채점(1~10점, 7.0 임계값)
방식에서 "LLM이 후보 전체를 보고 직접 고르는" 방식으로 바꾸는 프롬프트.

## 형제 폴더(`letters/`·`webtoon/`·`podcast/`·`video/`)와 다른 점

그 4개는 **지금 라이브로 쓰이는 프롬프트의 단일 스냅샷**이다(버전 이력 없이
Postgres에서 그때그때 다시 받아와 덮어씀 — `../README.md` 참고). 이 폴더는
아직 라이브가 아니라 **설계 중인 초안**이라, `docs/product/4format-pipeline/
08_BUNDLE_LETTER/`와 같은 방식으로 `vX.Y-YYYY-MM-DD-주제.md` 버전 이력을
쌓는다. 실제로 Postgres에 발행되는 시점이 오면 이 폴더도 `published.md`
단일 스냅샷 체계로 전환한다.

**규칙**: 모든 버전 파일은 프롬프트 내용이 이번 버전에서 안 바뀌었어도
(예: 검증만 진행한 버전) 파일 맨 하단에 "## 전체 프롬프트 (vX.Y — ...)"
섹션으로 그 시점 기준 완성된 프롬프트 전체를 반드시 포함한다 — 위쪽은
변경 이유, 맨 아래만 보면 바로 실사용 가능한 프롬프트가 나오게.

## 배경

`service/backend/prompts/mustknow/published.md`(지면특별코너 4탭+일반
공용 채점 프롬프트)의 문제: 5지표 평균 점수가 7.0~7.4 구간에 68.5% 쏠려
있어(2026-09-28 seen 테이블 769건 실측) 사실상 통과/미통과 이진 신호에
가깝고, 애초에 "7.0"이라는 임계값 자체가 검증된 기준이 아니었다.

같은 사내 프로덕트 AI 프리즘(`1_ai_link/prism`)의 선별 방식을 참고 —
원본은 `docs/resources/prism-selection-reference/`에 저장해뒀다. 다만
평가 지표 내용(투자자 페르소나 전용)은 안 맞고, **다양성 메커니즘**(관심사
쏠림 방지) 구조만 참고 가치가 있다는 게 2026-09-28 결론.

## 🛑 실제 런타임 파일은 여기가 아니다 (2026-09-28, 배포 직전 발견)

당초 계획은 `service/backend/prompts/selection/published.md`를
`ddb_prompt.load_prompt("selection")`이 읽는 것이었는데, 배포 직전
Dockerfile을 확인하니 **이미지 빌드 컨텍스트가 `pipelines/`로 한정돼
있어** `service/`가 컨테이너 안에 없다는 걸 발견했다. "selection"은
admin CMS(Postgres)에도 등록 안 돼 있어 API 호출이 항상 실패하고, 그러면
반드시 파일시스템 폴백을 타는데 그 파일이 컨테이너에 없어
`FileNotFoundError`로 `main()` 전체가 죽는 문제였다.

**실제 런타임이 읽는 파일은 `pipelines/mustknow_auto/selection_prompt.md`
다**(`run.py`가 `ddb_prompt` 안 거치고 직접 읽음). `service/backend/
prompts/selection/published.md`는 사람이 보는 문서 사본으로만 유지 —
내용 바꿀 땐 **두 파일 다** 갱신할 것.
