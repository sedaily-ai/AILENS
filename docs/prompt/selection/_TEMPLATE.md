# vX.Y (YYYY-MM-DD) — 한 줄 요약

작성: 이름 (+ Claude Code)
직전 버전: vX.(Y-1) — 링크 (최초 버전이면 "없음, v1.0")

## 문제 발견

직전 버전(또는 현재 상태)에서 관찰된 문제. 가능하면 실측 데이터·사용자
피드백·로그 등 **원본 근거**를 남긴다. "느낌"이 아니라 "무엇을 보고 알았나".

## 가설

이번 버전이 "무엇을 어떻게 바꾸면 어떤 결과가 나올 것"이라고 예상하는지,
**반증 가능한 형태**로 쓴다. 위험·역효과 가능성도 같이 적는다.

- 가설: (예) "선정 후보만 보고 판단하면 회차별 표본이 작을 때 '오늘의
  흐름 파악'이 부정확해질 것이다 — context_articles를 별도로 주면 표본
  크기와 무관하게 today_context 품질이 유지될 것이다."
- 위험/역효과 가능성: (예) "맥락 목록이 커지면 입력 토큰·비용이 늘 수 있다."

## 변경

실제로 무엇을 바꿨는지 — 프롬프트 diff, 코드 diff. 이유(Why)는 위 "문제
발견"·"가설"에서 이미 나왔으니 여기는 **What**만 간결하게.

## 검증

가설을 실제로 어떻게 테스트했는지 — 입력 데이터, 조건, 방법. **정량
실험만**(추측이나 "될 것 같다"가 아니라 실제로 돌려본 결과).

## 결과 및 판정

- **판정**: 가설 채택 / 기각 / 부분채택
- 직전 버전 대비 구체적으로 뭐가 좋아졌는지 — 가능하면 **before/after
  수치 비교**
- 남은 위험·부작용(위 "가설"에서 예상했던 것이 실제로 나타났는지 포함)
