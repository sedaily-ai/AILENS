# v1.1 (2026-09-28) — 자체검증 게이트 + 검증 결과 로깅 추가

작성: 문영광 + Claude Code
관련: `v1.0-2026-09-28-초안.md`(원본), `docs/resources/prism-selection-reference/`

## 이번 버전에서 바뀐 것

v1.0의 "알려진 한계 2"(Prism의 5개 자체검증 질문 누락)와, Prism 전수 확인
후 발견한 "검증 결과 로깅"(desc.txt `quality_verification` 참고)을
반영했다. v1.0에서 그대로 가져간 것(우선 고려·배제·다양성 규칙)은
안 바꿨다 — v1.0의 "알려진 한계 1"(top3 자동+나머지 다양성보정 2단계
구조)은 이번에도 아직 반영 안 함, v1.2 이후로 미룸.

## 가설

Prism의 5개 자체검증 질문을 더하면 선정 품질이 오르고, 검증 결과
로깅(candidates_total/excluded_count/excluded_reasons)으로 사후 감사가
가능해질 것이다.

- 위험/역효과 가능성: 자체검증은 LLM이 스스로 고른 걸 스스로 재검증하는
  구조라 실질적 필터링 강도가 약할 수 있다(자기일관성 편향). 이번
  버전에선 이 위험을 검증하지 않고 다음으로 미룬다.

## 프롬프트 (v1.0 대비 변경분만 표시, 전체는 아래 "전체 프롬프트" 참고)

**우선 고려 / 배제 / 다양성 규칙 섹션 뒤에 추가**:

```
## 선정 전 자체 검증 (고른 기사마다 스스로 점검한다)
각 후보에 대해 다음 5개 질문에 "예/아니오"로 답하고, 하나라도 "아니오"면
그 기사는 최종 목록에서 뺀다:
1. 파급력·시의성·사실데이터밀도·정책제도변화·이례성 중 최소 하나를
   명확히 충족하는가?
2. 표면적 정보 나열이 아니라 구체적 사실·수치에 근거하는가?
3. 위 "배제" 기준(홍보·인사·부고·단신)에 해당하지 않는가?
4. 이미 고른 다른 기사와 같은 사안을 다루지 않는가(반복 게재가 아닌가)?
5. 지금까지 고른 기사들의 카테고리 구성이 다양성 규칙(카테고리당 5건
   이하, 최소 6개 카테고리)을 지키고 있는가?
```

**출력 형식 변경**:

```
## 출력
JSON 객체 하나로 출력한다:
{
  "candidates_total": N,           # 이번 회차 소거 후 검토한 후보 총 수
  "excluded_count": M,             # 자체검증에서 탈락한 후보 수
  "excluded_reasons": ["...", ...],# 탈락 사유 요약(질문 1~5 중 어떤 것에 걸렸는지, 상위 몇 개만)
  "selected": [
    {"key": "...", "category": "...", "reason": "한 문장"}
  ]
}
```

## 왜 이렇게 했는가

- 5개 질문은 Prism의 investor 전용 질문(포트폴리오 적용 가능성 등)을
  AI LENS "일반 독자" 기준(published.md의 5지표·배제·다양성 규칙)으로
  1:1 재작성한 것 — Prism 문구를 그대로 쓰지 않고 우리 기준으로 바꿨다.
- `candidates_total`/`excluded_count`/`excluded_reasons`는 desc.txt의
  "검증 결과 문서화"(총 검증 수·제외 수·제외 사유) 아이디어를 그대로
  채택 — 무인 자동 실행이라 사람이 실시간으로 "확인"은 못 하지만, 이
  요약을 CloudWatch 로그에 남기면 나중에 "오늘 왜 이 기사들이 빠졌는지"
  사람이 사후 검토할 수 있다.

## 판정: 부분채택

이번 버전 시점엔 아직 실제 Bedrock 호출이 없어 정량 검증은 못 했다
(아래 "미해결" 참고). 이후 v1.4에서 같은 프롬프트 계열을 실제로 돌려본
결과 `excluded_reasons`가 실제로 유의미한 내용을 출력하는 것을
확인했고, 그걸 근거로 이 가설은 **부분채택**으로 판정한다 — "선정
품질이 올랐는가"는 별도로 검증된 적 없지만, "사후 감사가 가능해졌는가"
쪽은 확인됨.

## 미해결 (v1.2 이후)

- Prism의 "top N 자동 선정 + 나머지 다양성 보정" 2단계 구조는 여전히
  미반영 — 지금은 평면적 규칙(카테고리당 상한)뿐
- 실제 Bedrock 호출로 토큰/비용 실측 안 됨
- 코드 반영 미착수(`classify.py::select_general_articles()` 신설 필요)

## 우선 고려 (이런 기사를 우선한다)
- 파급력: 전 국민 또는 대규모 경제주체에 영향
- 시의성: 오늘 지나면 의미가 옅어지는 속보성 사안
- 사실·데이터 밀도: 정성적 홍보가 아니라 구체적 수치·사실
- 정책·제도 변화: 법·제도·정책의 실제 변경
- 이례성: 예상 밖의 전개("역대 최대" 등 근거가 리드에 있을 때)

## 배제 (아무리 여유가 있어도 고르지 않는다)
- 기업 홍보/IR/신제품 출시
- 단순 인사이동·부고·사건사고 단신·동정
- 같은 사안을 다른 각도로 반복 게재한 기사(있으면 리드가 더 구체적인 1건만)

## 다양성 규칙 (반드시 지킨다)
- 한 카테고리에서 5건을 초과해 고르지 않는다

- 20건을 못 채워도(후보 자체가 부족하면) 억지로 채우지 않는다 — 기준 미달 기사보다는 적게 뽑는 게 낫다
